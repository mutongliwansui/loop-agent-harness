## 一、目标与边界

### 1.1 一句话目标

把「技能 / MCP / 工具启停 / 模型 / 通用配置」五类配置的**唯一事实源收敛到全局层**（`~/.loop-agent/`），删除工作空间级配置层，并清理随之失效的脚手架、前端 scope 选择器与 REST `scope` 参数。

### 1.2 明确落地的六条决策（用户已确认）

| 编号 | 决策 | 结论 |
|---|---|---|
| Q1 | CLI 是否同口径 | **同口径全局化**，CLI 不再有 workspace 层 |
| Q2 | 存量 541B 迁移 | **自动并入 global**，以 workspace 值为准，原文件备份 `.bak` |
| Q3 | `scope` 参数 | **传 `workspace` 返回 400**，不静默落全局 |
| Q4 | runtime 单例化 | **纳入**（P1），ConfigLoader/ConfigWriter/SkillLoader/MCP 收敛为进程级 |
| Q5 | `memory.dreaming.*` | **随全局化** |
| Q6 | 与 defaultRoot 收敛同批 | **同批但 008 先做**，skill 全局化是 defaultRoot 移除的前置 |

### 1.3 非目标

- 会话 / 文件 / 记忆**内容**的空间隔离（`/fs`、`/terminal`、`/memory?ws=` 的 `ws` 语义保持不变）
- 模型 provider 实现、MCP 传输协议、工具执行逻辑
- 移除 CLI 的「工作空间目录」概念（CLI 仍以 cwd 作为会话归属，只是不再分层配置）
- 桌面端（20261112-007）改动

## 三、🍃 归并后的目标结构

```
                 ┌─────────────────────────────────────────┐
                 │  进程级单例（P1，Q4）                     │
                 │  configLoader / configWriter            │
                 │  skillLoader（只扫全局目录）              │
                 │  mcpManager + mcpMonitor                │
                 └───────────────┬─────────────────────────┘
                                 │ 全局唯一事实源
                 ┌───────────────▼─────────────────────────┐
                 │  ~/.loop-agent/                          │
                 │    config.json      ← 唯一配置           │
                 │    skills/          ← 唯一 skill 目录    │
                 └─────────────────────────────────────────┘

                 ┌─────────────────────────────────────────┐
                 │  每空间 runtime（不受影响）                │
                 │  SessionStore / AgentPool / memory kit   │
                 │  （会话、文件、记忆内容仍按空间隔离）      │
                 └─────────────────────────────────────────┘
```

**关键点**：配置与技能「去空间化」，运行内容「保留空间化」。`WorkspaceRuntime` 仍以 `root` 构造 `SessionStore` 与 `AgentPool`，只是不再持有 ConfigLoader/ConfigWriter/SkillLoader。

## 四、关键设计决策

### D1：config 层从五层降为四层，workspace 层整层删除

`load()` 合并顺序改为 `default < env < global < cli`；`resolveSources` 的 `ConfigSource` 去掉 `'workspace'`。

**取舍**：保留「读兼容」不做——即不继续读取 workspace 层再忽略。理由是忽略式兼容会让「文件明明写着却生效不了」成为长期困惑源；一次性迁移 + 备份更干净。被否决项：保留 workspace 层但在 serve 下强制 global（两套语义并存，正是当前 bug 的来源）。

### D2：`ConfigLoader` 不再接收 `workspacePath`

构造签名收敛为 `constructor(globalDir = loopAgentHome())`；删除 `workspaceConfigPath` getter。`src/config/loader.ts:290` 的单例 `new ConfigLoader()` 与 serve 侧 `new ConfigLoader(root)` 统一。

**取舍**：不做「保留参数但忽略」——保留会让调用方误以为仍可分层。被否决项：加 `mode: 'cli' | 'serve'` 枚举（Q1 已定为同口径，枚举是多余复杂度）。

### D3：`ConfigScope` 类型收敛为单值，`updateScope` 改名为 `update`

`ConfigScope` 直接删除（不再有第二个值）；`updateScope(scope, partial)` → `update(partial)`，`deleteScopeKey(scope, key)` → `deleteKey(key)`。写盘一律走 `writeGlobal`。

**取舍**：保留旧方法名做兼容别名会让「scope 概念」在代码里阴魂不散。被否决项：仅删除 `'workspace'` 联合值但保留 `scope` 形参（形参恒为 `'global'`，是噪声）。

### D4：REST `scope` 参数保留解析位置但传 `workspace` 显式报 400

`parseScope(raw)` 改为：`undefined/null/''` → 全局；`'global'` → 全局；其余（含 `'workspace'`）→ `400 bad_request`，错误文案明确「工作空间级配置已移除，请使用全局配置」。

**取舍**：这是 Q3 的落地。对旧前端/裸 curl 立刻暴露，而不是「写成功了但其实写到了别处」。被否决项：静默忽略（最危险）、静默落 global（用户以为分了层）。

### D5：skill 只保留全局目录，`SkillScope` 收敛为 `'global'`

`SkillLoader.scan(cwd)` → `scan()`（只扫 `globalDir`）；`getWorkspaceDir()` 删除；`SkillMetadata.scope` 恒为 `'global'`（保留字段以减小协议/前端改动面，但不参与分支）。REST `?scope=workspace` 同理报 400。

**取舍**：保留 `scope` 字段（恒 `'global'`）而非从协议中删除，是为了让 `/skills` 响应与前端 `SkillMetadata` 类型不产生连带破坏；P2 再考虑彻底移除。被否决项：同时删除字段（会把前端筛选、单测夹具一并推翻，收益不足）。

### D6：存量迁移在启动时执行一次，幂等，按「workspace 值优先」深合并

新增 `src/config/migrate.ts`：`migrateWorkspaceConfigToGlobal({ globalDir, candidateRoots })`。

- 枚举候选：`~/.loop-agent/sessions/*/meta.json` 的 `workspacePath` + `process.cwd()`
- 对每个存在 `{ws}/.loop-agent/.agent-config.json` 的根：读 JSON → `deepMerge(global, workspaceCfg)`（**workspace 值胜出**，因为改造前它就是生效值）→ 写 global
- 原文件 `rename` 为 `.agent-config.json.bak-<ts>`（幂等：已备份则跳过）
- 记录一条启动日志：迁移了哪些键、来自哪个空间
- 全程 `try/catch`，失败只告警不阻断启动

**取舍**：Q2 已定「自动并入」。**用 workspace 值胜出**而非 global 胜出，是关键——global 胜出会让用户当前生效的 `tools.enabled` 白名单**静默失效**（工具突然全开/全关）。被否决项：仅告警不迁移（用户升级后行为突变，且要手工搬 6 个键）。

### D7：`ensureScaffold` 不再创建 workspace 配置与 workspace skills 目录

`defaultBootstrapPaths()` 去掉 `workspaceConfigPath` / `skillsWorkspaceDir`；`ensureScaffold` 只建 `skillsGlobalDir`。`checkBootstrap` 的对应检查项删除。

**取舍**：必须同步改，否则每个新空间仍会被写入 `{}` 空配置，全局化形同虚设。被否决项：保留目录但不用（磁盘残留 + 体检报告永久告警）。

### D8：`WorkspaceRuntime` 不再持有 Config/Skill 组件（Q4）

`build()` 中删除 `new ConfigLoader(root)`、`new ConfigWriter(root)`、`new SkillLoader()` 与 `skillLoader.scan(root)`；`resolveWorkspaceRuntime` 不再改写 `ctx.configLoader` / `ctx.configWriter` / `ctx.skillLoader` / `ctx.deps.getConfig`。

**保留**：`SessionStore(root)`、`AgentPool`、`memory kit`、`runWithWorkspace`——即「内容」仍按空间。

**取舍**：这是本次最大的架构收益（MCP 连接数与 skill 扫描次数从 O(空间数) 降为 O(1)）。风险是 `ctx` 改写面较广，需确认所有 handler 都不再依赖「按空间读配置」。被否决项：只做配置读路径收敛、保留 per-space 实例（N 份 MCP 连接仍在）。

### D9：MCP 侧 `scope` 字段保留但恒 `'global'`，删除跨层匹配分支

`GET /mcp/servers` 每项 `scope: 'global'` 常量；`DELETE /mcp/servers/:name?scope=workspace` → 400；删除 `mcp.ts:154` 的 `layer` 双分支。

**取舍**：与 D5 同理，保字段降破坏面。被否决项：删除字段。

### D10：CLI 命令的 `--workspace\|--global` 参数保留但 `--workspace` 报错

`/config set|delete`、`/mcp add|remove`、`/model use`、`/skill upload|remove` 的 `--workspace` 一律给出明确错误提示与替代写法（去掉该参数即可），不静默降级。

**取舍**：保留参数名是为了让习惯旧语法的用户得到「已移除」的明确反馈，而不是「未知参数」的误导。被否决项：直接删除解析逻辑（用户会以为命令坏了）。

### D11：`memory.dreaming.*` 随全局化，Dreaming 配置只读全局

`bootstrap.ts:85,104` 与 `dream-scheduler.ts:390,507,832` 改为读进程级 `configLoader`；`DreamScheduleCard.vue` 去掉 `scope:'workspace'`。

**取舍**：Q5 已定。Dreaming 已是全空间三段式运行，按空间配开关本就自相矛盾。

## 六、验收

- 全局 `~/.loop-agent/config.json` 是唯一配置读写的落点；`{ws}/.loop-agent/` 不再生成配置与 skills
- 旧 541B 内容（`tools.enabled` 12 项等）迁移后行为不变
- `?scope=workspace` 在 `/config`、`/tools`、`/models`、`/mcp`、`/skills` 一律 400
- 前端五个管理页面无 scope 选择器、无「工作空间/全局」文案
- 多空间并存时 MCP 连接数恒为 1 份、skill 扫描 1 次
- `npx tsc --noEmit`、`npx vitest run`、`npm run build:webui` 全绿
