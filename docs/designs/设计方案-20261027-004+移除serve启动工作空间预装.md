# 设计方案：移除 serve 启动工作空间预装（最近空间缺省 + 全空间 Dreaming + 全盘自愈）

> 需求编号：20261027-004 ｜ 日期：2026-10-27 ｜ 状态：待确认
> 前置分析：2026-10-27 三轮影响面核实（会话记录见 L2 记忆），关键事实均带源码行号复核

## 1. 背景与现状

### 1.1 启动预装的四重角色（bootstrap.ts）

`src/api/bootstrap.ts:24` 的 `const rt = await registry.get(process.cwd())` 装载的启动空间 runtime 被解构注入 `createApiServer`，承担四重角色：

| 角色 | 依赖点 | 移除后后果 |
|---|---|---|
| deps 装配根 | `runAgent: rt.runAgent`、`sessionStore: store`、`sessions: rt.sessions`、`runtime.configLoader/configWriter/skillLoader/createMemoryKit: rt.*` | deps 对象无着落，handler 编译期即挂 |
| handler 缺省空间 | fs.ts:192、memory.ts:207/260、memory-dream.ts:73/75/164、sessions.ts:52/220 共 9 处「缺省回落 `ctx.deps.sessionStore.path`」 | 打开记忆页（不带 ?ws=）等操作 500 |
| Dreaming 保底遍历对象 | dream-scheduler.ts:274/386/686 遍历 `registry.list()`（只含已装载空间） | 无人访问时全部空间定时晋升静默停摆 |
| 启动自愈扫描范围 | bootstrap.ts:33 `reconcileInterruptedOnBoot(store)` 仅扫启动空间 | 兄弟空间中断 run 永不被标记 interrupted |

### 1.2 已核实不依赖启动空间的部分（无需改动）

- **会话归属定位**：`session-locator.ts` 三级策略（wsId8 前缀 O(1) → 老 id 缓存 → 磁盘全扫），纯磁盘定位 + 懒装载，零依赖启动空间
- **MCP stdio cwd**：`mcp-manager.ts:17` 独立捕获 `process.cwd()`（模块加载期），语义为「进程启动目录」，保留不动
- **静态资源 webui/dist**：`static.ts` cwd 兜底是应用部署目录语义，非工作空间
- **上传目录**：全局 `~/.loop-agent/uploads`
- **CLI 单空间模式**：`src/cli/start.ts` 不经过 bootstrap.ts，零改动

### 1.3 既有缺陷（顺带修复）

`WorkspaceRegistry.evictIdle()`（workspace-runtime.ts:225）有完整实现但**全库无生产调用点**——runtime 只增不降，LRU 上限（默认 4）从未生效。按需装载后此缺陷被放大，本需求必须顺带接上。

### 1.4 用户已确认的方向（2026-10-27）

1. 新建会话 ws 必选（前端已保证），后端缺省按「最近一次工作空间」；
2. 文件面板进入会话后展示会话所在空间目录（现状即如此），不需要额外缺省；
3. Dreaming 应全空间参与；空转空间不调 LLM，可按磁盘状态预判谁需要跑；
4. 启动自愈就应全盘扫描（或按最近使用筛选）；
5. 不受影响的部分（MCP/静态资源/上传/定位器）不再展开。

## 2. 总体思路

```
启动（bootstrap.ts）
  ├─ registry = new WorkspaceRegistry()            （不预装任何 runtime）
  ├─ recentRoot = await resolveRecentRoot()         ← D2：磁盘推导最近空间（不建 runtime）
  ├─ void reconcileAllInterruptedOnBoot()           ← D5：全盘扫描 journals（fire-and-forget）
  ├─ deps 装配：defaultRoot() 动态解析              ← D1/D3：缺省 = 最近使用空间（运行期动态）
  └─ dreamScheduler.start()                         ← D4：tick 前磁盘枚举全空间
                                  │
                 ┌────────────────┴────────────────┐
                 ▼                                  ▼
        API 请求（缺省场景）                  Dreaming tick（每轮）
        defaultRoot()                         enumerateCandidateRoots()
        = 进程内 MRU 指针                       = sessions/* ∪ memory/*
        = 冷启动时 recentRoot                   → 逐空间磁盘预判（D4）
                                                → 需要跑才 getCanonical 懒装载
```

## 3. 关键设计决策

| # | 决策 | 结论（推荐） | 理由与被否决项 |
|---|---|---|---|
| D1 | 缺省空间语义 | 新增进程级「最近使用空间」指针（MRU root），语义替换原 `sessionStore.path` 的缺省地位；handler 缺省回落一律改为 `defaultRoot()` | 9 处回落点统一收敛到一个函数，杜绝再散落；被否决：保留 cwd 常量缺省（违背需求本意） |
| D2 | 冷启动最近空间推导 | 新模块 `src/api/recent-workspace.ts`：扫 `~/.loop-agent/sessions/*/`，取「最近会话文件 mtime」最大的空间的 canonical root；无任何会话目录时兜底 `canonicalWorkspacePath(process.cwd())` 并跳过 ensureRoot | mtime 一次 readdir+stat 即得，成本可控（~180 目录）；被否决：读最近会话 meta.json 的 updatedAt（需 JSON.parse 全部目录，更贵且格式兼容负担）；cwd 目录不存在时不报错（延后到真正使用时） |
| D3 | defaultRoot 解析顺序 | ①进程内 MRU 指针（任意空间 API 活动即更新）→ ②冷启动 D2 推导值 → ③cwd 兜底；返回 root 字符串（不 build runtime），调用方需要 rt 时自行 `registry.getCanonical` | 指针更新点收口在 resolveWorkspaceRuntime 成功路径与会话创建处（已有代码位），不加埋点面 |
| D4 | Dreaming 全空间参与 | `tick()`/`runAllForShutdown` 改为：磁盘枚举候选 roots（`{userDir}/sessions/*` 目录名 → meta.json 的 workspacePath ∪ `{memoryDir}/*/` 目录名反查）→ 逐空间磁盘预判（读 `.agent-config.json` 开关 + `.dreaming-state.json` 的 lastProcessedDay 是否落后于昨日 + `lastRunAt` 距今是否已过 minGap）→ 预判通过才 `registry.getCanonical(root)` 懒装载执行 | 空转空间每 tick 仅 2 个小文件读取，零 LLM 零 runtime；被否决：只遍历已装载 runtime（现状，正是要修的问题）；被否决：全部懒装载再判（浪费 runtime 构建） |
| D5 | 启动自愈全盘扫描 | `reconcileInterruptedOnBoot` 扩展：遍历 `~/.loop-agent/sessions/*/runs/*.json`，bootId ≠ 当前进程即标 interrupted；可加 mtime > 7 天直接标（无需读内容）的快路径 | journal 文件随会话删除联动，量级=历史会话数，异步不阻塞启动；被否决：仍只扫启动空间（漏兄弟空间） |
| D6 | evictIdle 接线 | registry 构造时 `setInterval(evictIdle, 5min).unref()`；boot 后首跑延迟 10min；输出「已释放 N 个空闲空间」日志 | 有 in-flight run 的空间既有逻辑自动跳过；间隔 5min 粒度足够，不追求精确 TTL |
| D7 | DreamScheduleCard「当前空间」语义 | 前端「当前空间」改显式化：数据源加 `defaultRoot`（`GET /status` 或 `/memory/workspaces` 附带），展示名改为「缺省空间（最近使用）」 | 避免用户误以为是浏览器当前会话空间；被否决：维持「当前空间」文案（语义已失真） |
| D8 | deps 装配结构 | **保留** deps 装配链不动（server.ts 构造签名不变），仅把「启动 rt 解构注入」改为「sessionStore 等依赖按需经 defaultRoot()+registry 动态解析」的最小改造：deps.sessionStore 改为 getter 式解析或默认空间 store 的惰性代理 | 被否决：deps 全惰性化/上下文对象重构（改动面大、超出本需求）；折中方案见 3.1 |
| D9 | 单测夹具 | 新增测试用临时 userDir（LOOP_AGENT_USER_DIR 已支持）夹具，断言：冷启动推导、MRU 更新、tick 磁盘预判跳过/执行分支、全盘 reconcile、evict 触发 | 不依赖真实 ~/.loop-agent |

## 6. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| 冷启动推导的「最近空间」与用户预期不符（如测试目录会话最新） | 兜底链路保证永远有合法 root；D7 文案明示「最近使用」；MRU 一旦有真实活动立即覆盖 |
| 磁盘预判与真实增量判定口径不一致（预判放行但实际无新增） | 预判只做粗筛（lastProcessedDay < 昨天 或 lastRunAt 超过 1 个周期即放行），放行后仍走原增量判定兜底，不产生 LLM 浪费 |
| 全盘 reconcile 误标正在其他进程运行的 journal | 沿用 bootId 双因子判定（跨进程必然 bootId 不匹配），与现状同一语义，仅扫描范围扩大 |
| evictIdle 误释放频繁使用的空间 | 既有 busy 检查 + lastUsedAt 刷新逻辑保留；5min 低频触发 |
