原型 20261025-001 · 对话输入区重设计 Input Dock（输入坞）· 一体卡片 + 图标化主操作 + 自增高 + 会话级模型选择
问题不是「不好看」，是三层结构错位：主操作（发送）与低频开关（附件 / 流式 / 通知）挤在同一行且权重相同；输入框被钉死 44px，长 prompt 只能框内滚动；描边三层叠加（容器上沿 + 输入框 + chip）在窄区里显脏。模型只能在 #/models 页全局切换，无法为「这一次对话」单独指定。 改版只动 ChatView.vue 的 .composer 一节 CSS 与模板结构（外加删除流式/通知、新增模型选择），SSE 协议、消息数据、上传通通不动。
实测：FilesView 展开时对话区仅 462px，输入内容宽 422px textarea 固定 44px，6 行文本时 scrollHeight 146px 内部滚动 输入区内 svg 数 0，emoji 命中 U+1F4CE / U+1F514 发送文字按钮占宽 66px（窄区 15%）

一诊断（实测取证，不是观感）

1图标体系割裂：输入区内 svg 数为 0，靠 📎 / 🔔 emoji 与 ■ / ✕ 字符撑场，与 FilesView、ToolCard 已落地的内联 SVG 体系正面冲突；深色主题下 emoji 固定彩色，与品牌绿抢色。
2一行三按钮三套权重：附件（灰边白底 48px）、发送（绿底白字 66px）、停止（红边描边）并列，主操作不突出；窄区 422px 里文字按钮吃掉 15% 宽度，textarea 只剩 288px。
3高度钉死：height:44px + resize:none，写入 6 行后仍是 44px、scrollHeight 146px 内部滚动——写长需求（本产品主场景）时只能看见两行。
4底栏信息同权重：「流式」是技术开关、「发送后自动附带…」是开发期说明、「🔔声音开」是设置入口，三者并列占住主视线；12px --muted 对比偏低。
5描边三层叠加：容器上沿 1px + textarea 1px 边框，chip 自身再 1px，并且 chip 浮在输入框之外，附件与「我要发的内容」在视觉上没有归属关系。

二决策点（待确认）

D1去 .composer 上沿分隔线，底改 --bg，分界交给卡片阴影。否决：保留 border-top（线中套线、与卡片描边重复）
D2输入坞做成一体卡片（--panel 底 + --line-soft 描边 + --shadow-card），聚焦转品牌描边 + 3px 光晕；深色下卡底提亮为 --panel-2、描边提亮为 --line（深色 --line-soft 与 --panel 明度差不足，描边近乎消失）。否决：整块铺满的输入条（无层级，与消息流糊在一起）
D3textarea 无边框、自增高 44→200px，超出后内部滚动；上限 200px ≈ 8 行。否决：field-sizing:content（Chromium 123+ 才有，项目还需覆盖老终端）
D4主操作与上下文设置分层：工具行只放「附件 + 模型选择」，主位只留发送按钮。否决：多按钮平铺（权重问题未解）
D5发送按钮图标化 32×32（↑），空态灰底不可点，生成中同位置变 ■。否决：保留「发送」文字（窄区吃宽）；否决：停止另起一个按钮（位置跳动）
D6全部 emoji / 字符图标换内联 SVG（paperclip / chip / chevron / check / arrow / square / x），走同一 stroke 1.8 线性风格。否决：引第三方图标库（零新增依赖约束）
D7「流式」「通知」两个控件直接删除（按你的决定）。流式恒为默认开启（stream 缺省 true），完成提醒不再可配。代价：stream:false 的降级通道与提示音/系统通知开关在 WebUI 不再可达；若仍需保留，只能放进设置页而非输入区
D8占位符缩短为「发消息给 Loop Agent…」，快捷键说明改右下角 Enter 发送 · Shift+Enter 换行 常驻小字；原「发送后自动附带…」移入上传浮层。否决：全塞占位符（输入后即消失，等于没有）
D9容器查询两档：≤440px 隐快捷键提示、≤380px 收内边距并把模型 pill 收到 112px（名字省略而不隐藏，模型名始终可见）。否决：靠 flex-wrap 换行（工具行折两行，高度跳动）；阈值定 440 而非 520，是为让默认 462px 下提示仍可见
D10浮层挂 .dock 内、与卡片同宽；零新增设计令牌，全部复用既有 --line-soft / --hover / --radius-card / --shadow-card。否决：新增 --dock-* 令牌组（会出现第三套视觉语言）
D11模型选择器放工具行、用 pill + 向上展开列表，不占输入区高度（与流式/通知腾出的位置正好抵换）；pill 只显示当前 alias，完整信息留在列表里。否决：<select>（无法渲染 alias / 模型名 / 主机三行信息与「全局」徽标）；否决：放输入框上方独立行（吃掉长 prompt 空间，重犯现状 3 行的错）
D12作用域是「本次对话」，不是全局切换——不调 PUT /model（那个会写盘并同步 model.*，影响所有会话）。落地须：POST /sessions/:id/messages 增加 modelAlias；后端按 alias 取 profile 的 name/baseUrl/apiKey；AgentOptions 目前只有 model?: string，没有 baseUrl/apiKey 透传，需扩展（否则换到 tokenhub.haizhi.com 的 glm 会仍打 deepseek 域名）。会话元数据记 modelAlias，重进会话能还原。否决：前端直接改全局激活（会污染其它会话与 CLI）
D13状态约束：生成中禁用模型切换（opacity:.5 + pointer-events:none，与附件按钮同档）——已发出的请求改不了模型，允许点只会让人误以为本条会换模型；同一时刻只开一个浮层（模型下拉与上传浮层互斥，Esc 或点外部关闭）。否决：生成中仍可切换（语义误导，且下一轮的上下文归属会含混）
D14语义防混淆与降级：与全局激活同名的项标「全局」徽标、其余不标，pill 未覆盖时不加 pinned；一旦覆盖则 pill 图标转品牌色并露出「跟随全局」复位项，让「我现在到底跟没跟全局」一眼可判。窄区（≤380px）只省略 alias 文本、不隐藏控件；列表超高时面板内部滚动，不外溢卡片。否决：只在 pill 上换颜色不显式标注（颜色无标签，切过一次后无法判断是覆盖还是默认）
待确认后可进入落地：前端改 webui/src/views/ChatView.vue（模板 .composer 段 + 样式「输入区」一节），模型列表复用 GET /models；后端改 src/api/handlers/messages.ts（收 modelAlias）与 src/types.ts 的 AgentOptions（支持 baseUrl/apiKey 覆盖）。自增高逻辑抽 webui/src/autogrow.ts 以便单测。
