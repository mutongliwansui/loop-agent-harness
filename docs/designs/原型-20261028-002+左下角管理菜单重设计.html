侧边栏左下角「管理」菜单重设计

需求 20261028-002 · 入口 + 向上浮层面板 · 三组分层 · 自绘线性图标 · 宽窄屏均可达

一、空间占用（实测）

337.3px
改造前常驻高度（占 900px 视口 37.5%）
45px
改造后常驻高度（含 1px 分隔线 + 8px 间距，入口按钮本身 36px）
−87%

—
浮层面板高度（覆盖式，不占布局）

改造前面板与菜单**同处文档流**，8 行（7 管理项 + 主题）全部常驻；改造后只有一行入口常驻， 面板 position:absolute 覆盖在会话列表之上，内容增删不再影响布局。

二、现状诊断（2026-10-28 CDP 实测）

问题实测证据性质
P1 空间侵占.nav-bottom 展开态 337.3px，会话列表被压到不足 200px布局
P2 图标撕裂9 个平台彩色 emoji，饱和度/视觉重量不一，跨平台渲染不同视觉
P3 无层次7 个管理项 + 主题同层平铺，零分组信息架构
P4 主从同权入口行与子项同为 13.5px、7px 10px、同款 hover；箭头仅 11px视觉层级
P5 发现性差收起态只剩「管理」二字，看不出内含 7 项可用性
P6 展开突变display:none ↔ block 硬切，无过渡动效
P7 窄屏不可达@media(max-width:900px) 同时隐藏 .grp-body 与 .grp.open .grp-body，管理菜单完全无法进入功能缺陷

三、关键决策（推荐值，待确认）

编号决策取舍
D1入口 + 向上弹出浮层，非常驻内联展开否决「分组竖排压缩」（≈320px，省不下来）与「横向图标条」（纯图标发现性差）
D2自绘 16px 线性 SVG，复用 gear/wrench/puzzle，新增 chip/link/stack/pulse/sliders否决保留 emoji、否决引入图标库（零新依赖）
D32 列网格，每格 34px，横排「图标 + 标签」否决单列（7 项 7 行，失去压缩意义）
D4「MCP 服务器」渲染为「MCP」，全称进 title2 列格宽约 92px，6 字放不下；label 原值保留
D5三组：运行 / 扩展 / 数据与排查按「改参数 / 装能力 / 看数据与排障」切分
D6外观改三段控件（跟随 / 浅色 / 深色）三态可见优于循环盲切；localStorage 语义不变
D7入口常驻显示当前页名「我在哪」可见；否决不显示
D8常驻高度 ≤40px（实测 36px）与「新建对话」同高，形成底栏节奏
D9120ms 淡入 + 6px 上移；prefers-reduced-motion 禁用否决无动画与 >150ms 长动画
D10窄屏入口缩为图标按钮，面板向右弹出修 P7；否决窄屏隐藏与全屏抽屉
D11WAI-ARIA menu：↑↓/Home/End、ESC 关闭并焦点回归、点外部关闭否决仅鼠标可用

四、验证方法

  • 点击「设置与管理」→ 面板上浮；点击面板外部 → 关闭
  • 键盘：焦点在面板内按 ↑ ↓ 循环移动项，Home End 跳首尾，ESC 关闭且焦点回到入口
  • 点「窄屏 ≤900」→ 入口缩为齿轮图标，面板改向右弹出（现状此场景管理菜单完全不可见）
  • 点「改造前」→ 侧边栏底部变回 8 行 emoji 平铺，对照高度徽标数值
  • 外观三段可切：跟随系统 / 浅色 / 深色，整页令牌同步
