症状（按影响排序）
  1. 一行挤 6 个元素且权重相同：箭头 / 徽章 / emoji / 名称 / 摘要 / 耗时视觉重量接近，扫视时抓不到「用了哪个工具、动了哪个文件」。

  3. 状态胶囊最抢眼：.tc-badge 用 11.5px 等宽加粗 + 三色底，比工具名更醒目；⟳ / ✓ / ✗ 字形尺寸不一，切换时行高抖动。
  4. 摘要与参数值同为等宽字体：折叠态摘要（等宽）和展开后参数值（等宽）没有主次，层级靠颜色硬撑。
  5. 参数表像 Excel：.ptable 每个单元格都有 1px 边框 + 首列底色，与产品通篇的浅分隔线（--line-soft）风格冲突。
  6. 结果区三套机制并存：.clamped 120px 遮罩 + max-height 260px 内滚 + 「展开全部结果」按钮，展开后大小屏都可能出现内外双滚动条。
  7. 同构边框随调用次数堆叠：连续 5 次 fileRead 就是 5 张一模一样的描边卡片，纵向空间与视觉噪音成倍增长。
  8. 缺「已中断」语义：chat-stream.ts 的 ToolSeg 只有 done/elapsedMs，未透传 message.aborted，停止后未完成的工具会永远显示 ⟳ 执行中。

D1 = B

定稿规则
  • 合并阈值：连续 ≥3 次同一工具才合并（「连续」= 中间没有文本段、也没有其他工具）；单张卡的副标题列出各次参数的首段，超出省略。
  • 任一失败不合并：组内含失败时整卡左条转红、pill 显示 有失败，并默认展开——失败必须一眼可见。
  • pill 语义：完成=绿、失败=红、执行中=琥珀 + 转圈、已中断=灰、跳过/未知=灰底。
  • icon 来源：6 个内置工具用线性 SVG（与 chart-box 的 kind-ico 同一套 16×16 描边）；MCP / 未知工具用拼图图标并直接显示原名，不做翻译。

5 · 交互与边界（方案 B 下必须覆盖）

交互
  • 整行可点展开/收起；Enter/Space 同效，Esc 收起；aria-expanded 同步。
  • 展开状态按 msgId:idx 记忆（沿用现有 expandedTools Set），重新渲染不丢。
  • 结果块与命令均提供「复制」（navigator.clipboard，失败回退「长按选中」提示）。
  • 失败态首次出现自动展开一次，用户手动收起后不再自动展开。
长内容
  • 值超长：路径单行省略（title 给全文），命令与输出 pre-wrap 换行不横滚。
  • 输出默认 190px 内滚，>12 行给「展开全部 N 行」，展开后 420px 内滚——只保留一套机制。
  • 结果超 64 KB 时前端再截断并提示「已截断，完整内容见日志」。
流式与中断
  • 流式中新工具行出现时，若用户已在底部则跟随滚动；否则不动（沿用现有 nearBottom 逻辑）。
  • 执行中计时用 elapsedMs 心跳，本地 requestAnimationFrame 兜底，切页回来立即对齐。
  • 停止后：未完成工具转「已中断」，不再有 ⟳；已展开的失败态保留。
  • 暗色主题下状态色用 --ok/--warn/--danger 的暗色值，圆点不加描边即可分辨。
