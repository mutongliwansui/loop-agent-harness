现状问题

诊断

当前容器（.mermaid-block + .mmd-bar）功能齐备但「装饰层」缺位：它是把功能按钮直接裸露在标题栏上的结果，视觉上像 PDF 阅读器 / 浏览器缩放条，与 Markdown 正文的排版质感脱节。核心症状 5 条 →

症状成因（对应代码）本原型对策
调试遗留感 .mmd-cap 用等宽字体渲染字面量 echarts / mermaid，读起来像日志标签 改为「图标 + 中文类型名」的 .chart-kind（图表 / 流程图），语义化且本地化
控件像阅读器 ＋ － 100% ⛶ 四个全角字符裸按钮，无容器、无 hover 层次 换 SVG 线性图标 + 26×26 圆角热区 + hover/active/focus-visible 三态，分组间加细分隔线
外框平面化 仅 1px --line 描边、8px 圆角、无阴影，卡片与正文同一平面 12px 圆角 + 双层阴影（1px 贴边 + 大范围柔光），hover 时阴影与描边同步加深
工具栏抢戏 .mmd-bar 底色 --bg 与外框对比过强，分隔线用 --line 偏重 工具栏底色改 --bar-bg（≈面板色 +2%），分隔线换 --line-soft，弱化存在感
读数歧义 「100%」在同一个裸按钮上既表示档位又表示动作（适应宽度），点击行为不明确 拆成「读数（可点复位 100%）」+「适应宽度（图标按钮）」两个独立控件

方案 A · 常驻工具栏

推荐默认

工具栏常驻、轻量存在：左侧类型标识回答「这是什么图」，右侧图标组回答「能做什么」。适合 mermaid 流程图这类需要频繁缩放阅读的内容。 结构保留 button[data-act=in|out|fit|fs] 并新增 data-act="src" 源码开关，JS 改动为「文案 → 图标」「百分比节点独立」「预览/源码切换」。

为什么把类型名放在左、控件放右？ 阅读路径是「先认图、再操作」，左侧定位标签、右侧聚拢动作，中间留弹性空白； 这也让超长标题（echarts 内嵌标题）不会与按钮争夺同一行空间。

方案 B · 悬停悬浮工具条

内容优先

工具栏脱离文档流，默认隐藏为右上角悬浮胶囊，悬停 / 键盘聚焦时淡入。适合对话流里图表密集、希望「正文不被打断」的场景； 代价是控件可发现性略降（因此保留 :focus-within 与 tooltip）。

落地映射

改动清单

目标文件两个：webui/src/mermaid.css（样式，主体）+ webui/src/chart-box.ts（模板字符串与 caption 语义）。 建议保留旧类名做别名一个版本，避免 dist 旧产物与缓存页白屏。 末尾新增的「预览 ⇄ 源代码」除了模板与 CSS，还要求 chart-box.ts 把原始源码留存下来。

现状重设计动作
.mermaid-block .chart-block（别名保留） 圆角 8 → 12；加双层阴影 + hover 描边/阴影过渡
.mmd-bar .chart-bar 底色 --bg → --bar-bg；分隔线 → --line-soft；min-height:34px；padding:4px 8px 4px 11px
.mmd-cap（等宽 "echarts"） .chart-kind + .kind-ico + .kind-sub caption 参数由字符串改为 'chart' | 'diagram'，渲染「图标 + 中文名」；副标题可选（echarts 可显示系列类型）
.mmd-spring .chart-tools（margin-left:auto） 弹簧 span 由「占位」升级为「控件容器」，少一层节点
button[data-act=in|out|fit|fs] 字符按钮 .tbtn + 内联 SVG 26×26 热区、stroke-width:1.6、hover/active/focus-visible 三态；补 aria-label
图标语义（易踩坑） in/out = 放大镜±；fit = 左右边界竖线 + 水平双向箭头；fs = 四角外扩括号 fit 与 fs 必须视觉可区分：勿给「适应宽度」用四角括号（那是「全屏/展开」语义，会与 fs 撞脸成两个全屏按钮）
fit 按钮既显示百分比又是动作 .zoom-val（读数，点击复位 100%）+ 独立 fit 图标 apply() 里写 zoomVal.textContent；fit 不再改名文本
.mmd-view / .mmd-stage .chart-view / .chart-stage padding 10/12 → 14/16；细滚动条（hover 才显形）；overscroll-behavior:contain；新增 .chart-hint 拖拽提示
无（源码渲染完即丢弃） .chart-src + [data-act="src"] 开关 + .src-on 新增「预览 ⇄ 源代码」：chart-box.ts 需把原始代码块字符串存到实例上（不要只留渲染结果），模板里输出 <pre class="src-code">；切换只改 .src-on 一个类，缩放/适应按钮随之置灰，全屏保留
pre.echarts-err 整圈红框 pre.chart-err 左侧 3px 重边框 + 错误标签 chip，与代码块风格解耦；配合源码视图可直接看到出错的 option
无 方案 B：.chart-block.floating 工具栏绝对定位 + backdrop-filter，hover/focus-within 淡入；一行 class 即可切换
主题令牌 新增 --line-soft --line-strong --hover --active --bar-bg --view-bg --chart-bar --chart-line --chart-grid --chart-axis --node-bg --node-line --shadow-card --shadow-card-hover --shadow-pop --panel-glass --radius-card --radius-ctl 亮/暗两套都要补齐（暗色下阴影改纯黑低透明度，描边提亮）
不改的部分：缩放算法（0.2×~5×、按钮 1.25×、滚轮 1.15×、视口中心锚定）、拖拽平移判定、全屏行为、remeasure() 时机、echarts 主题重建逻辑 —— 全部保持 chart-box.ts 现实现，本次只动「模板字符串 + CSS」。

唯一需要跟着改的数值：fit() 里的 (view.clientWidth - 24) —— 24 是旧内边距合计（padding:10px 12px）；新内边距为 14px 16px（合计 32），常数需同步改为 32，否则会多出横向滚动条。
