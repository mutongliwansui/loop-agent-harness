0 · 目标与边界

只改展示层

现状把技能当成一张后台表格：描述与长路径挤在同一行、名称列被压窄、危险按钮常驻每一行、安装区游离在列表之外。 本次重设计不改任何接口与 Agent 侧技能加载逻辑，只重排 SkillsView 的信息层级与交互，让「技能」更像一个可浏览、可安装、可检查的能力库。

8 个可感知问题
  • 列宽失衡：描述与长路径同处一行级别，路径换行把行高撑乱，扫读节奏被打断。
  • 名称最窄：py-pptx 折行、task-driven-development 折三行；第一识别项反而最拥挤。
  • 来源无层级：只有一行绿色 / 灰色小字，工作空间与全局没有可筛选的视觉区分。
  • 危险操作常驻：每一行都有红色「卸载」，误触风险高，也拉高整页视觉噪音。
  • 正文不可读：展开后直接倾倒 <pre>，frontmatter 与章节混在一起，长文档无法阅读。
  • 没有检索：无搜索、无来源筛选、无总数统计，技能一多只能逐行扫。
  • 安装被割裂：主操作藏在列表下方；不支持拖拽、没有上传进度，409 只靠 toast 一闪而过。
  • 接口语义抢戏：「GET /skills」与「重载 / 刷新」同权重，产品页读起来像调试面板。

2 · 设计方向

定为方案 B

技能是「少量、高价值、带说明文档」的对象，天然适合卡片而不是数据表。三条路径对比后选 B：卡片承担识别与浏览，抽屉承担阅读，安装升级为页头主入口。

A · 表格增强改动最小

保留 5 列表格，加搜索、筛选、路径折叠、操作收进 ⋯。路径与描述仍挤在同一行，整体仍是后台表格观感。

B · 卡片流 + 详情抽屉推荐

名称 / 来源 / 描述分三层，路径降为辅助行；详情用右侧抽屉阅读，列表不被打断；安装是页头主 CTA。

C · 双栏 List-Detail信息最全

左列表右常驻正文。技能数量少时右栏长期空白，窄屏需要折叠，交互与布局成本都更高。

信息层级（从上到下）
  1. 页头：标题 + 一句用途说明 + 刷新 / 重载 / 安装技能接口标签只在开发模式出现
  2. 统计条：技能总数 / 工作空间 / 全局 / 最近重载让「现在有什么」一眼可见
  3. 工具条：搜索 + 来源分段筛选 + 排序 + 结果计数检索先于浏览
  4. 技能卡片：图标 · 名称 · 来源 · 描述 · 路径 · 查看两列网格，窄屏单列
  5. 按需浮层：详情抽屉（阅读）/ 安装模态（写入）不占常驻版面，关闭即回到列表
