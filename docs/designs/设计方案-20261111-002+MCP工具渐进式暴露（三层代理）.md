## 一、背景与目标

### 1.1 问题

MCP server 接入后，工具数量随 server 数量线性增长。当前实现把**全部工具的完整 `inputSchema` 每轮发进 `tools` 数组**：

- 上下文固定开销变大，压缩阈值被工具定义挤占，可用的对话历史变短；
- 工具数量到几十个后，模型在长工具列表中选错/漏选的概率上升；
- 工具越多，`tools` 前缀越不稳定（server 重连、配置变更都会改变数组），缓存收益越差。

用户方案提出按规模分三层渐进暴露。本设计在其基础上，按本仓库的真实调用链修正了缓存边界、阈值口径与代理层的集成点。

### 1.3 实测基线（2026-11-11，本仓库直连注册表测量）

| 指标 | 实测值 |
| --- | --- |
| 内置工具数 | 10（`vision.enabled=true` 时 14） |
| `tools` 数组序列化长度 | 6 197 字符 |
| 估算 token（字符/4） | ≈ 1 549 |
| 占工作记忆预算 | ≈ 1.5%（分母 102 400） |
| 单工具 schema 最大者 | `editFile` 756 字符；`fileRead` 658 字符 |

**推论**：工具数阈值只统计 MCP 工具（用户已确认，内置工具不计入），因此 MCP 少于 10 个时仍留在 L1。内置工具实测仅占 1.5%，占比阈值主要由 MCP schema 决定——要触发 5% 需再增加约 3 600 token 的 MCP 定义（约 1 个大型 server）。两个口径并行，任一越线即升级，见 D4。

### 1.4 目标

1. 工具定义 token 占比在 L2/L3 下显著下降（L2 目标 ≤ 全量的 40%，L3 ≤ 25%）；
2. 工具选择准确率不下降：代理调用参数一次通过率 ≥95%，漏调可通过纠错恢复；
3. 前缀缓存不退化：同会话第 2 轮起命中率不低于开启前基线；
4. 全链路可观测、可回滚：任意时刻可强制回 L1。

### 1.5 非目标

- 不改 MCP 协议与传输层，不改 `MCPClient`；
- 不做用户自定义工具别名/分组编辑；
- 不做基于向量的工具检索（见 D10）；
- 不替模型自动规划工具调用链。

### 1.6 设计约束

- `toOpenAITools()` 在层内必须字节级稳定（排序 + `canonicalize` 不变）；
- 目录块只作用于本次 LLM 调用的视图消息，**不落盘、不进 `transcript`**；
- 代理层不得绕过 `excludeTools`、`tools.disabled` 与子 Agent 防递归约束；
- 新增配置全部可选，缺省值保持现有行为可回退；
- 新增代码不引入 npm 依赖（校验器自实现子集）。

## 二、总体设计

### 2.1 三层定义

| 层 | 进入条件（默认值，均可配） | `tools` 数组 | 工具信息呈现 | 执行路径 |
| --- | --- | --- | --- | --- |
| **L1 全量** | MCP 工具数 < 10 **且** 定义占比 < 5% | 全部工具的原生 schema | `tools` 数组 | 模型直接调目标工具 |
| **L2 目录 + 代理** | MCP 工具数 10–50 **或** 占比 5%–20% | 内置工具 + `mcp_call` | 尾部注入的目录块 | `mcp_call(tool_name, arguments)` → 路由到 `tools/call` |
| **L3 搜索 + 代理** | MCP 工具数 > 50 **或** 占比 > 20% | 内置工具 + `mcp_search` + `mcp_call` | 分类概览块 + 搜索结果 | `mcp_search` → `mcp_call` |

口径说明：

- **工具数只统计 MCP 工具**（注册名含 `__`），内置工具不计入（用户已确认）；
- **占比 = 全量 `tools` 数组估算 token ÷ `memory.working.maxTokens`**，内置与 MCP 一并计入分子（它们共享同一预算）；
- 两个条件「或」关系；降级需同时低于下一层两条阈值。

### 2.2 数据流

```
 MCPClient.tools/list
        │
        ▼
 ToolRegistry（内置 10 + server__tool）── mcpMeta（中文名/描述侧表，已有）
        │                                        │
        ├─▶ 统计：mcpToolCount / toolsTokens / ratio（D4/D5）
        │                                        │
        ▼                                        ▼
 decideTier() ── 会话级冻结（D2）        目录/搜索索引（D10）
        │
   ┌────┴─────────────┬──────────────────┐
   ▼                  ▼                  ▼
  L1                 L2                 L3
 全量 schema      目录块 + mcp_call   分类块 + mcp_search + mcp_call
   │                  │                  │
   └──────────┬───────┴──────────────────┘
              ▼
      openaiTools（run 内字节稳定）──▶ LLM
              │
        tool_calls
              │
              ▼
      resolveCall()（D6/D8）── schema 校验（D7）──▶ MCPClient.tools/call
              │
              └─▶ 事件/展示解包（D9）──▶ SSE / 前端 / 记忆回调
```

### 2.3 缓存边界模型（本方案的核心约束）

前缀缓存从 token 0 起逐字节匹配，而 `tools` 位于请求最前。因此：

| 变化 | 缓存影响 | 本方案策略 |
| --- | --- | --- |
| 层内、工具集不变、目录不变 | 无 | 每轮只在尾部追加新消息，前缀持续命中 |
| 层位切换（L1↔L2↔L3） | `tools` 变化 → 整条历史全量重算 | **只在「工具集本身已变化」或「压缩点」或「新会话」时切换**（D2） |
| 目录块内容变化（翻译异步回填） | 目录块在尾部 → 仅尾部重算 | 会话内冻结目录快照；翻译结果只影响新会话（D3） |
| 搜索/代理结果 | 作为 tool result 追加 | 不影响前缀 |

> 修正点：用户方案中「升级可即时、降级只在压缩点」仍会产生一次全量重算。实际应统一为「**层位与工具集同生命周期**」——工具集没变就不动层位；工具集变了，缓存本来就会 miss，此时换层才是零额外成本。

## 三、关键设计决策

| 编号 | 决策（一句可确认的判断） | 推荐 | 被否决项与理由 |
| --- | --- | --- | --- |
| **D1** | 采用三层模型，但层级判断只对 **MCP 工具**计数，内置工具始终原生暴露 | ✅ 采纳 | 否决「全量工具一起计数」：用户已明确阈值按 MCP 工具统计，内置工具恒定存在会稀释层级含义；也否决「把内置工具也塞进代理」：会破坏子 Agent 排除、UI 定制与 `delegate` 递归防护 |
| **D2** | 层位按**会话级冻结**：工具集未变时沿用上次层位；仅在工具集指纹变化、压缩完成、新会话三种边界重算 | ✅ 采纳 | 否决「每轮重算、越线即升」：`tools` 一变整条历史全量 miss，长会话代价远大于省下的 schema 开销 |
| **D3** | 目录/分类块注入**最后一条真实 user 消息**（视图态、不落盘、每 run 重建、按工具名排序），并在会话内冻结文本快照 | ✅ 采纳 | 否决「独立 system 消息」：部分 OpenAI 兼容服务要求 system 只能在首条；否决「写进 system 主体」：工具增删会改变 system 前缀；否决「写进历史」：每轮累积且污染前端展示 |
| **D4** | 工具数阈值**只统计 MCP 工具**；默认 **L2：MCP ≥10 或占比 ≥5%；L3：MCP >50 或占比 >20%**，全部可配置，并提供 `tier: 'l1'` 强制回退 | ✅ 采纳 | 否决「全量工具一起计数」：内置工具会稀释阈值，且用户已明确按 MCP 口径；否决「只按数量」：单个 server 的 schema 可能很轻，数量到 50 也未必占 20%；否决「只按占比」：小预算或极简 schema 下占比抖动大 |
| **D5** | 分层判断用 `JSON.stringify(toOpenAITools()).length / 4` 估算；真实 `prompt_tokens` 只用于观测校准，不参与判定 | ✅ 采纳 | 否决「用 `_promptOverheadTokens` 当工具开销」：它含 system 与 L2 注入，会把记忆误算成工具；否决「为精确值引入 tokenizer」：模型各异、增加依赖且判定并不需要那么精确 |
| **D6** | 代理工具固定命名 `mcp_call` / `mcp_search`，**只允许代理 MCP 工具**；`tool_name` 必须命中注册表中的 `server__tool` | ✅ 采纳 | 否决「统一 `tool_call` 代理全部工具」：内置工具的排除、审批、展示与递归防护都以工具名为键，统一代理会全部失效 |
| **D7** | 调用前按目标 `inputSchema` 做 JSON Schema **子集校验**（`type/required/properties/items/enum/const/anyOf/oneOf/allOf/$ref`），不认识的关键字跳过而非拒绝 | ✅ 采纳 | 否决引入 `ajv`（违反零新依赖）；否决「只校验 required」（嵌套参数错误率会显著上升）；否决「严格全量校验」（MCP schema 生态复杂，误拒比漏拒更伤可用性） |
| **D8** | 代理执行前二次检查 `excludeTools`、内置工具名与未知工具名；违规返回可纠正文本而不是抛错 | ✅ 采纳 | 否决「只在外层 `openaiTools` 过滤」：模型仍可能手写被排除的工具名，代理是最后一道闸 |
| **D9** | 事件与历史**双侧解包**：服务端 `tool_start/tool_end` 发真实工具名与真实参数；前端历史解析同样解包；记忆回调记真实名 | ✅ 采纳 | 否决「只在执行层拆」：UI 会显示「调用了 mcp_call」、审计丢失真实工具、L2 记忆检索质量下降 |
| **D10** | L3 检索用**关键词 + 既有 `mcpMeta` 中文名/描述**做索引，分类按 server 聚合；结果只回 `name + 一句话 + 必填参数` | ✅ 采纳 | 否决向量检索：需索引与依赖，当前工具规模用不上；否决新建分类体系：MCP 无 category 字段，短期只能按 server |
| **D11** | 压缩完成后允许重算层位并切换 `tools`；同时清空 L3 候选缓存，保留分类概览 | ✅ 采纳 | 否决「压缩后沿用旧层」：压缩已重写历史，是唯一低代价切换点；否决「保留候选缓存」：候选引用的工具集可能已变化 |
| **D12** | 默认 `enabled=true + tier=auto`，但保留 `tools.exposure.enabled=false` 与 `tier='l1'` 两级逃生门 | ✅ 采纳 | 否决「默认关闭」：默认关闭等于功能不生效；否决「无开关」：缓存类故障必须能一键回滚 |

## 四、详细设计

### 4.1 分层判定（纯函数，可单测）

新增 `src/tools/exposure/types.ts`：

```ts
export type ExposureTier = 'l1' | 'l2' | 'l3';

export interface ExposureConfig {
  enabled: boolean;
  /** auto = 按阈值；其余为强制层 */
  tier: 'auto' | ExposureTier;
  l2: { minMcpTools: number; minRatio: number };
  l3: { minMcpTools: number; minRatio: number };
  catalog: { maxEntries: number; maxDescChars: number };
  search: { defaultLimit: number; maxResults: number };
}

export interface ToolFootprint {
  mcpToolCount: number;
  /** 全量 tools 数组估算 token（含内置） */
  toolsTokens: number;
  /** toolsTokens / working.maxTokens */
  ratio: number;
}
```

新增 `src/tools/exposure/tier.ts`：

```ts
export function decideTier(fp: ToolFootprint, cfg: ExposureConfig): ExposureTier {
  if (!cfg.enabled || cfg.tier === 'l1') return 'l1';
  if (cfg.tier !== 'auto') return cfg.tier;
  // L3：MCP > 50 或占比 > 20%
  if (fp.mcpToolCount > cfg.l3.minMcpTools || fp.ratio >= cfg.l3.minRatio) return 'l3';
  // L2：MCP ≥ 10 或占比 ≥ 5%
  if (fp.mcpToolCount >= cfg.l2.minMcpTools || fp.ratio >= cfg.l2.minRatio) return 'l2';
  return 'l1';
}
```

默认值（`src/config/schema.ts`）：

```ts
tools: {
  // ...既有字段
  exposure: {
    enabled: true,
    tier: 'auto',
    l2: { minMcpTools: 10, minRatio: 0.05 },
    l3: { minMcpTools: 50, minRatio: 0.20 },
    catalog: { maxEntries: 60, maxDescChars: 40 },
    search: { defaultLimit: 5, maxResults: 8 },
  },
}
```

判定输入获取：

- `mcpToolCount = registry.list().filter(t => t.name.includes('__')).length`；
- `toolsTokens = JSON.stringify(registry.toOpenAITools()).length / 4`；
- `ratio = toolsTokens / cfg.memory.working.maxTokens`。

### 4.2 会话级层位状态

新增 `src/tools/exposure/state.ts`（进程内 Map，不落盘）：

```ts
interface TierState {
  tier: ExposureTier;
  /** 工具集指纹：排序后的 name + schema 的 sha256 */
  fingerprint: string;
  /** 目录快照（L2/L3），会话内冻结 */
  catalogText: string;
}

const states = new Map<string, TierState>(); // key: `${wsId}:${sessionId ?? 'cli'}`
```

run 开始时：

```
fingerprint = sha256(排序后的 tool name + canonicalize(parameters))
prev = states.get(key)
if (!prev)                                   → decideTier() 并保存
else if (prev.fingerprint !== fingerprint)   → decideTier()（工具集已变，缓存本来就会 miss）
else                                         → 沿用 prev.tier 与 prev.catalogText
```

压缩完成后（`react-agent.ts` 压缩分支尾部）：删除该会话的 `TierState`，下一次迭代按新工具集重新判定（D11）。进程重启后状态丢失，重新判定；由于工具集未变，结果通常一致，可接受。

### 4.3 目录块与分类块

新增 `src/tools/exposure/catalog.ts`：

L2 目录（每条 ≤ `maxDescChars`，总条数 ≤ `maxEntries`）：

```

- atlasGraphMcp__shortestPath: 查询两个节点之间的最短路径（必填: graph, from, to）
- lark__sendMessage: 发送消息到指定会话（必填: receiveId, content）
...
```

L3 分类概览（按 server 名排序，仅列数量）：

```
[MCP 工具分类]
- atlasGraphMcp: 24 个（图数据库）
- lark: 18 个（协作）
- 其他: 6 个
```

规则：

1. 文字优先取 `mcpToolMeta()` 的 `zhName` / 描述首句；缺失时回退注册表 `description` 首句；再回退 `tool` 名分词美化；
2. 排序固定为 `fullName` 升序；同一会话内文本冻结，翻译异步回填**不修改已有快照**（D3）；
3. 若条目数 > `maxEntries` 或估算 token > 1 700，直接强制 L3；
4. 目录块使用独立哨兵（如 `<<<LOOP_AGENT_TOOL_CATALOG_END_1c7f>>>`），与记忆块互不干扰；剥离函数循环剥离，保证幂等。

### 4.4 `mcp_call` 代理

新增 `src/tools/exposure/proxy-tools.ts`，构造**不注册进全局 registry** 的工具定义与执行器，仅在构建 `openaiTools` 时追加：

```ts
export function buildProxyTools(tier: ExposureTier): {
  defs: OpenAIToolDef[];
  resolve(name: string, args: Record<string, unknown>): ProxyResolution;
};
```

`mcp_call` 定义：

```json
{
  "type": "function",
  "function": {
    "name": "mcp_call",
    "description": "调用一个 MCP 工具。tool_name 必须取自 [MCP 工具目录] 或 mcp_search 的结果，arguments 是该工具的参数对象。内置工具请直接调用，不要走这里。",
    "parameters": {
      "type": "object",
      "properties": {
        "tool_name": { "type": "string", "description": "完整工具名，如 atlasGraphMcp__shortestPath" },
        "arguments": { "type": "object", "description": "目标工具的参数对象" }
      },
      "required": ["tool_name", "arguments"]
    }
  }
}
```

执行流程：

1. 解析 `tool_name` / `arguments`；若 `arguments` 是 JSON 字符串，先尝试 `JSON.parse`；
2. 查注册表：不存在 → 返回「工具不存在，是否想调 `<最接近的名字>`」；
3. 命中内置工具（不含 `__`）→ 返回「该工具不是 MCP 工具，请直接调用」；
4. 命中 `excludeTools` → 返回「工具在当前上下文不可用」；
5. schema 校验失败 → 返回「参数校验失败 + 期望摘要 + 实际参数」；
6. 通过 → `runner.run(target, args, ctx)`，沿用输出治理、锁与取消信号；
7. 结果原样回填为 `mcp_call` 的 tool result。

`ProxyResolution` 同时返回 `displayName` / `displayArgs` 供事件解包使用。

### 4.5 参数校验（子集实现）

新增 `src/tools/exposure/validate.ts`：

```ts
export interface ValidateResult {
  ok: boolean;
  /** 面向模型的简短错误：路径 + 期望 + 实际；最多 5 条 */
  message?: string;
  /** 期望摘要：仅必填键与类型，控制在 30 token 内 */
  schemaHint?: string;
}

export function validateArgs(
  schema: Record<string, unknown> | undefined,
  args: unknown,
): ValidateResult;
```

支持关键字：`type`（含类型数组）、`required`、`properties`、`additionalProperties: false`、`items`、`enum`、`const`、`anyOf`、`oneOf`、`allOf`、`$ref`（仅 `#/$defs/*` 与 `#/definitions/*`）。其余关键字（`format`、`pattern`、数值边界等）忽略，避免误拒。

错误示例（作为 tool result 返回，模型可自我纠正）：

```
参数校验失败（atlasGraphMcp__shortestPath）：
- 缺少必需参数：graph
- to 期望 string，实际 number
期望参数：{ graph: string, from: string, to: string }
```

### 4.11 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| `mcp_call` 的 `arguments` 是字符串 | 尝试 `JSON.parse`，失败返回解析错误与示例 |
| `tool_name` 不存在 | 返回最接近的 3 个候选（编辑距离 + 前缀匹配） |
| `tool_name` 是内置工具 | 返回「请直接调用内置工具」 |
| 目标工具被 `excludeTools` 排除 | 返回「当前上下文不可用」，不执行 |
| 目标工具 schema 含不支持关键字 | 跳过该关键字校验，仅校验可识别部分 |
| 目录条目超上限 | 强制 L3；L3 仍超限时按 server 分组截断并提示 |
| 翻译异步回填 | 不修改当前会话目录快照 |
| 工具集在 run 中途变化（server 断连） | 本 run 沿用冻结快照；执行时目标不存在则返回可纠正错误 |
| 压缩后层位重算 | 允许升/降层；目录同步重建，搜索候选清空 |
| 配置 `enabled=false` 或 `tier='l1'` | 完全等价于现状：全量 schema，无目录、无代理 |

## 八、风险与回滚

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 模型不按目录选工具或写错 `tool_name` | 多一次往返 | 目录写「何时用」、名字纠错、L3 兜底；统计一次通过率 |
| 校验器误拒复杂 schema | 工具不可用 | 只校验可识别关键字；失败信息带 schema 摘要；可临时 `tier='l1'` |
| 目录翻译异步回填导致前缀漂移 | 缓存 miss | 会话内冻结快照，只影响新会话 |
| 层位切换造成全量 miss | 费用与 TTFT 上升 | 只在工具集/压缩/新会话边界切换；上线前后对比命中率 |
| 事件解包遗漏 | UI/审计失真 | 代理路径与原生路径共用同一 `displayName/displayArgs` |
| 子 Agent 绕过排除 | 递归或越权 | 代理内二次校验 + 单测 |

回滚方式（按代价从低到高）：

1. `tools.exposure.tier = 'l1'`：立即回到全量 schema；
2. `tools.exposure.enabled = false`：关闭目录注入与代理；
3. 代码回退：删除 `exposure` 目录与 `react-agent` 三处接线。
