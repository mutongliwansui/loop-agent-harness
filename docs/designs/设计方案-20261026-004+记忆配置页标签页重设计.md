# 设计方案：记忆配置页标签页重设计（全局定时 / L2 / L3 / 检索）

> 需求编号：20261026-004 ｜ 原型：[原型-20261026-004+记忆配置页标签页重设计.html](原型-20261026-004+记忆配置页标签页重设计.html)
> 日期：2026-10-26 ｜ 状态：已实施（2026-10-26）

## 1. 背景与目标

MemoryView（`webui/src/views/MemoryView.vue`）现为单页纵排 7 张卡片，本需求将其重组为四个标签页，并补齐跨空间维度的数据通路：

| 标签页 | 内容 | 数据源 |
|---|---|---|
| 定时任务 | 进程级 cron 配置 + 最近触发记录（跨空间聚合） | `GET /memory/status`、`PUT /memory/dream/schedule`、`GET /memory/dream/preview`、`GET|DELETE /memory/dream/history` |
| L2 情景 | 空间 → 会话 → scope/tag 三级筛选，按天分组 | `GET /memory/episodic?ws=&limit=`（本期加 `ws`）+ `GET /workspaces` |
| L3 长期 | 全局共享（SOUL/USER）与工作空间级分组 | `GET /memory/curated?ws=`（本期加 `ws`） |
| 检索 | L2 语义检索（当前空间） | `GET /memory/search`（不改） |

## 2. 已核实的现状（2026-10-26）

1. **触发记录读取失真**：定时轮每 tick 遍历 `registry.list()` 全部已装载空间、每空间各写一份 `.dreaming-runs.json`；但 `GET /memory/dream/history` 恒读启动空间（`ctx.deps.sessionStore.path`），页面只见 1 条。
2. **目录哈希能对上**：`memory` 与 `sessions` 的目录哈希交集 18 个（memory 25 个、sessions 172 个，155 个为测试临时目录）；存在「有 memory 无 session」的孤儿空间 7 个。
3. **L2 条目头带元数据**：`episodic.ts` 写入格式 `## [ts] [sessionId: x] [scope: session|global] [tag: tool|...]`，读取侧 `readRecentDays` 返回 `{day, content}` 原文。
4. **`GET /workspaces` 已够用**：`listAllWorkspaces()` 返回 `{id, name, path, createdAt, lastAccessedAt, sessions:[{id,title,updatedAt,...}]}`——L2 的空间与会话两级下拉数据源现成，**后端零改动**。
5. **配置承载**：`DreamScheduler.getConfig` 读启动空间 configLoader（进程级语义），现有 `PUT /memory/dream/schedule` 校验即热重排，写入路径正确，不需要 scope 选择。
6. **WebUI 路由**：hash 路由（router.ts，D4 决策不引 vue-router），已有 `#/chat?session=` 先例。

## 3. 决策点（默认按推荐项执行）

| # | 决策 | 结论（推荐） | 理由 |
|---|---|---|---|
| D1 | 标签页载体 | MemoryView 内部四段式 tabs，状态写入 hash query（`#/memory?tab=l2&ws=<id>&sid=<sessionId>`），不新增路由页 | 刷新/分享可还原视图；沿用 `#/chat?session=` 先例；router.ts 零改动 |
| D2 | L2 空间下拉数据源 | `GET /workspaces`（有会话空间）∪ 扫描 `{memoryDir}/*/` 目录哈希（有记忆空间），条目带 `有记忆/有会话` 徽标；孤儿空间（仅有记忆）也列出 | 后端新增一个轻量端点 `GET /memory/workspaces`（聚合两来源，返回 `{id,name,path,hasMemory,hasSession}`），避免前端两次请求自行合并 |
| D3 | 会话/范围/标签筛选位置 | **前端**解析条目头（按行解析 `## [ts] [sessionId: …] [scope: …] [tag: …]`），后端不加这三个参数 | 数据量 ≤90 天纯文本，前端筛选零延迟；后端只做空间路由一件事，改动面最小 |
| D4 | L2/L3 按空间读取 | `/memory/episodic` 与 `/memory/curated` 支持 `?ws=<id 或绝对路径>`：`registry.ensureRoot` → `getCanonical` → `rt.getMemoryKit()`，canonical 校验与 404/forbidden 语义对齐 `fs.ts resolveFsRoot`；缺省回落启动空间（现有行为不变） | 复用跨空间并行（20261021-010）既有机制；不 chdir、不动全局指针 |
| D5 | 触发记录聚合 | `GET /memory/dream/history?scope=all|ws`：`all` 时**文件扫描** `{memoryDir}/*/.dreaming-runs.json` 聚合（不要求空间已装载），每条附 `workspaceName/workspacePath`（映射来自 sessions 索引扫描，查不到显示 wsId）；`ws`（缺省）行为=现启动空间单文件读取。**顺带修复读取恒为启动空间的问题** | 纯文件聚合不依赖 runtime 装载状态，进程重启后未访问过的空间记录也能看到 |
| D6 | 清空记录语义 | `DELETE /memory/dream/history?scope=all|ws&ws=<id>`，缺省跟随当前筛选范围；`all` 时遍历删除各空间文件内记录（文件保留、内容清空，保持幂等） | 与列表视图的操作对象一致，避免「看着全部、删的却是启动空间」 |
| D7 | 定时配置写入 | 沿用现有 `PUT /memory/dream/schedule`，不做 scope 选择（启动空间配置承载＝进程级，语义不变） | 调度器本就只读启动空间配置；引入 scope 反而制造「写了 global 却不生效」的假问题 |
| D8 | 触发记录表列 | 时间（含错误行内红字）/ 工作空间（名 + wsId 副行）/ 来源（定时·手动·关停·补跑徽标）/ 结果（成功·部分失败·跳过·错过）/ 窗口 / 晋升·跳过·错误三数 / 耗时 | 对齐原型；数字三列等宽右对齐 |
| D9 | L3 空间切换 | L3 页右上角空间下拉（数据源同 D2），`GET /memory/curated?ws=` 拉取；SOUL/USER 全局共享区不随 ws 变化（后端 `getFilePaths` 的 globalDir 语义天然如此） | 全局区一次拉取缓存，切空间只重取工作空间级两文件 |
| D10 | 检索页范围 | 本期仅当前空间（`episodic.search` 无跨空间能力），不做「全部空间」档；跨空间检索列入演进项 | 避免本期引入跨空间检索的聚合排序复杂度 |

## 4. 改动清单

### 后端（P0）
1. `src/api/handlers/memory.ts`：
   - `requireMemoryKit` 扩展可选 `ws` 参数（`episodic`/`curated` 两处传入），走 `registry.ensureRoot + getCanonical + getMemoryKit`；
   - `GET /memory/dream/history` 加 `?scope=&ws=`：`all` 走 `{memoryDir}/*/.dreaming-runs.json` 文件扫描聚合 + sessions 索引扫描补空间名；
   - `DELETE /memory/dream/history` 同步支持 `?scope=&ws=`。
2. 新增 `GET /memory/workspaces`：`GET /workspaces` ∪ `{memoryDir}` 目录扫描，输出 `{id,name,path,hasMemory,hasSession}[]`（检索路由注册于 `/memory/dream/*` 静态段之后，无路径冲突）。
3. `dreaming.ts`：导出 run-log 读取/清空的纯函数（按 memory 根聚合），供 handler 复用；`.dreaming-runs.json` 结构不变。

### 前端（P1）
4. `MemoryView.vue` 重构为四标签页（tab 状态进 hash query）；现有 7 张卡片按归属迁移，不删能力：
   - 定时任务 = 自动晋升卡 + 触发记录卡（新表格：工作空间列 + 范围切换）；
   - L2 = 空间/会话/scope/tag/天数筛选链 + 按天分组列表（前端解析条目头）+ 加载更多；
   - L3 = 全局共享 / 工作空间级两栏折叠卡 + 空间切换；
   - 检索 = 现有搜索能力平移。
5. 新增 `memory-entries.ts`（纯函数：条目头解析 + 会话/范围/标签过滤），配 Vitest 单测。
6. 图标沿内联 SVG 体系，样式复用既有令牌，零新增色值。

### 测试与验证（P2）
7. 单测：memory-entries 解析/过滤、history 聚合函数（临时目录夹具）、`?ws=` 路由 404/回落语义。
8. 真机验证：`npx tsx src/index.ts --serve` 测试端口副本 + headless Edge DOM 断言 + 双主题像素采样（沿用 20261026-004 原型验证链路）；文档中英双语文档同步（docs/readme/zh、en）。
