## 一、背景与现状

### 1.1 症状

内置工具（13 个）在 WebUI 对话流里有完整定制展示：中文名 + 16px 线性 SVG 图标 + 语义摘要 + 中文参数标签 + 失败原因直写。
MCP 工具（本机 2 个 server 共 26 个工具）全部退化为：英文原名 `server__tool`、图标恒为齿轮、摘要为紧凑 JSON、参数表为英文键。

### 1.2 现状链路（已逐行核实）

| 环节 | 现状 | 结论 |
| --- | --- | --- |
| `src/tools/mcp/adapter.ts` `adaptMCPTool()` | 只取 `name` / `description` / `inputSchema` 三字段 | MCP 的 `title`、`annotations`、`icons`、`properties[*].description` 全被丢弃 |
| `src/types.ts` `Tool` | 仅 `name` / `description` / `parameters` / `execute` | 元信息无处承载 |
| `src/tools/registry.ts` `toOpenAITools()` | `list()` 排序后只映射 `name/description/parameters` | 前缀缓存友好，**不可改** |
| `src/api/handlers/mcp.ts` `viewServer` | 返回 `tools`（名字列表级） | 无展示元信息端点 |
| `webui/src/tool-meta.ts` `TOOL_META` | 静态白名单 13 项 | MCP 工具落到 `FALLBACK_META` |
| `ToolCard.vue` / `LiveStatus.vue` | 共用 `toolDisplay/toolParamRows/toolSummary` 纯函数 | 改动点集中，接线成本低 |

### 1.3 实测证据（2026-11-04，SDK 直连 `tools/list` 只读探测）

| server | 工具数 | 顶层 `title` | `annotations.title` | 其他字段 | 描述语言 |
| --- | --- | --- | --- | --- | --- |
| `parallel-search` | 2 | **0/2** | **2/2** | `icons`（明/暗各 2 套远程 URL）、`outputSchema` | 英文长文（`Purpose: … Ideal Use Cases: …`） |
| `atlasGraphMcp` | 24 | **0/24** | **0/24** | 仅 `name`/`description`/`inputSchema` | **中文**（`"在指定的图实例下，查询两个节点之间的最短路径"`、`graph→"图实例"`） |

**结论**：`title` 在真实生态覆盖率极低（26 个工具里顶层 title 命中 0 个）。这正是用户「取不到就走 LLM 翻译」这一方向的现实依据——翻译不是锦上添花，而是主力路径。

### 1.4 协议依据（联网检索结论）

- MCP 规范 `Tool` 的展示优先级为 **`title` → `annotations.title` → `name`**。
- 顶层 `title` 于 **2025-06-18**（PR #663）引入，目的是让 `name` 回归纯程序标识；`annotations.title` 自 2025-03-26 起可用。
- `ToolAnnotations` 全部字段（含 `title`）在规范中被定性为 **hint、不可信**——仅用于展示是安全的，不可用于安全决策。
- `icons` 于 2025-11-25 引入，本机 `parallel-search` 已提供，但形式是**远程 URL**。

## 三、展示名解析优先级（核心链路）

```
zhName 解析（后端一次算好并固化进 McpToolMeta.zhName）
  1. annotations/title 存在且非空 ─────────────▶ 直接用它，nameSource = 'title'
  2. 描述已是中文（CJK 检测）──▶ 本地提炼短名 ──▶ nameSource = 'cjk'   （D3，省一次 LLM）
  3. 以上皆无 ──▶ LLM 翻译（批量） ────────────▶ nameSource = 'translate'
  4. 翻译失败/关闭 ──▶ 空串 ───────────────────▶ nameSource = 'none'
                                                 └─▶ 前端兜底：名字分词美化 `shortestPath` → `Shortest Path`
```

参数标签 `zhParams[key]` 同构：`properties[k].description` → CJK 提炼/LLM 翻译 → 缺省用美化后的键名。

## 四、关键设计决策（D1–D15）

| 编号 | 决策（一句可确认的判断） | 推荐 | 被否决项与理由 |
| --- | --- | --- | --- |
| **D1** | 展示名优先级固定为 **`title` → `annotations.title` → LLM 翻译 → 名字分词美化 → 原名**，解析在后端一次完成并固化进 `McpToolMeta.zhName`，前端只做末位兜底 | ✅ 采纳 | 否决「前端拿到原始 title/description 自己解析」：解析逻辑（含 CJK 检测、缓存查表）放前端会与翻译缓存分裂，且 LiveStatus 流式态拿不到异步结果 |
| **D2** | 顶层 `title` 与 `annotations.title` **都认**，顶层优先，严格遵循规范 2025-11-25 的 precedence | ✅ 采纳 | 否决「只认顶层 title」（实测本机 2/26 只有 annotations.title，会漏掉 parallel-search 全部工具）；也否决「只认 annotations.title」（旧实现习惯，非规范主路径） |
| **D3** | 描述**已是中文**时本地提炼短名（按标点/长度截断），**不调 LLM**；配置项 `mode: 'auto' \| 'always'` 可强制全走 LLM | ✅ `auto` | 否决「无脑全翻译」：`atlasGraphMcp` 24 个工具描述本就是中文，翻译纯烧钱且可能改写原意，实测该 server 可省掉 100% 调用 |
| **D4** | 翻译在 **MCP server 连接成功后后台异步**触发（`void run()`），不 `await`、不阻塞 server 注册、不阻塞对话 | ✅ 采纳 | 否决「注册时同步等翻译」（首个对话被拖慢数秒）；否决「前端首次渲染时按需触发」（同一工具会被多端重复触发，且流式渲染路径无法等待） |
| **D5** | 翻译**按 server 批量**：一个 server 一次 LLM 调用返回 JSON map；单批工具数上限 60、单批估算字符上限 12000，超出切批串行 | ✅ 采纳 | 否决「一工具一次调用」（26 次往返，耗时与限速风险高）；否决「全 server 合并一次」（单点失败全灭、单批过大易超时） |
| **D6** | 翻译复用**当前激活模型 profile**（`models.active` 的 `baseUrl/apiKey/name`），不新增独立模型配置项 | ✅ 采纳 | 否决「新增 `tools.mcpTranslate.model`」（配置面膨胀，且用户已有多模型管理）；复用后翻译质量随用户所选模型自然变化 |
| **D7** | 翻译结果持久化到 **`~/.loop-agent/mcp-meta.json`**，键为内容指纹 `sha256(server\0tool\0title\0description\0JSON(paramDesc))`；指纹变化自动重译，server 升级零配置失效 | ✅ 采纳 | 否决「键用 `server__tool`」（server 改了描述不会重译，展示名永久过期）；否决「不落盘纯内存」（每次启动重复烧钱） |
| **D8** | **不做**用户自定义工具别名（`atlasGraphMcp__shortestPath → 最短路径查询`） | ⏸ 演进项 | 别名需新增 MCP 页编辑 UI + 写配置 + 冲突处理，与本期「自动解析」目标正交；先看自动结果够不够好 |
| **D9** | 元信息**不注入** `Tool` 接口、**不进** `toOpenAITools()`；改走 `Registry.mcpMeta` 侧表 + `GET /mcp/tool-meta` | ✅ 采纳 | 否决「扩展 `Tool` 接口加 `title?`」：虽 `toOpenAITools()` 是白名单映射不会漏，但类型放宽后任何未来 `...tool` 展开都可能污染 tools 数组，**前缀缓存失效是无法回滚的线上事故**（每轮多付全量 prompt 费用） |
| **D10** | 前端将 MCP 元信息存于 `webui/src/mcp-tool-meta.ts` 的**纯注册表**（零 DOM、零 vue 依赖），拉取与响应式 bump 放独立 `mcp-tool-meta-loader.ts`（`shallowRef`）；`ChatView` 的 cards computed 依赖 `metaRev.value` | ✅ 采纳 | 否决「注册表直接放 vue ref」（`tool-meta.ts` 是 root vitest 的纯函数测试目标，引入 vue 会污染其可测性与依赖面） |
| **D11** | MCP 工具图标按**关键词词典**匹配（工具名 + 参数名 → 复用内置 `ToolIconKey`），未命中回落 `gear` | ✅ 采纳 | 否决「引入图标库」（项目规范：16×16 内联线性 SVG，`stroke-width:1.6`，零新依赖）；否决「只用 server 一级图标」（同 server 下 24 个工具全同图标，区分度为 0） |
| **D12** | 工具卡片标题区显示 **来源 server 徽标**（灰底小字），工具中文名过长按 14 字截断并保留 `title` 原文 | ✅ 采纳 | 否决「不显示 server」：`parallel-search__web_search` 与将来其它 server 的同名工具会撞名 |
| **D13** | 新增配置 `tools.mcpTranslate = { enabled: true, mode: 'auto', timeoutMs: 20000, maxToolsPerBatch: 60 }`，**默认开启**；关闭后退回名字美化，功能不坏 | ✅ 采纳 | 否决「默认关闭」（用户诉求正是要中文化，默认关闭等于没做）；但必须可关——离线/限流环境要给逃生门 |
| **D14** | 翻译**失败必须可观测**：`GET /mcp/tool-meta` 回传 `translate` 状态与 `translateError`，MCP 页展示「已翻译 N/M」与失败原因，日志统一打点 | ✅ 采纳 | 否决「失败静默回落英文名」（用户看到半中半英却查不到原因，违背项目「兜底也要可观测」原则） |
| **D15** | **不预翻译**未连接 server 的工具；元信息随 server 断开而清理 | ✅ 采纳 | 否决「启动时按配置文件全量预翻译」（为未使用的 server 烧钱；配置里的 server 可能连不上） |

## 五、数据结构

### 5.1 后端 `McpToolMeta`（`src/tools/mcp/meta.ts`）

```ts
/** MCP 工具展示元信息：只服务 UI，永不进入 toOpenAITools()（D9） */
export interface McpToolMeta {
  /** 完整工具名 server__tool（与 registry 注册名一致） */
  fullName: string;
  server: string;
  tool: string;
  /** 规范展示名：title → annotations.title → ''（D2） */
  title: string;
  /** 服务端 description 原文（可能数百字符，前端自行截断） */
  description: string;
  /** inputSchema.properties[k].description 原文 */
  paramDesc: Record<string, string>;
  /** inputSchema.required（用于摘要挑选参数） */
  required: string[];
  /** 已解析的中文展示名；空串 = 未取到（D1） */
  zhName: string;
  /** 参数中文标签（缺项前端用美化键名） */
  zhParams: Record<string, string>;
  /** 展示名来源，用于 MCP 页可观测（D14） */
  nameSource: 'title' | 'cjk' | 'translate' | 'none';
  /** 翻译状态机（D14） */
  translate: 'idle' | 'pending' | 'done' | 'failed' | 'skipped';
  translateError?: string;
}
```

**状态机**：

```
idle ──(有 title / 描述是中文 / enabled=false)──▶ skipped
  └──(需翻译)──▶ pending ──成功──▶ done
                     └──失败──▶ failed（保留 error，下次连接重试）
```

### 5.2 缓存文件 `~/.loop-agent/mcp-meta.json`

```json
{
  "version": 1,
  "translations": {
    "<sha256 前 32 位>": {
      "server": "parallel-search",
      "tool": "web_search",
      "zhName": "网页搜索",
      "zhParams": { "objective": "检索目标", "search_queries": "关键词" },
      "model": "deepseek-flash",
      "at": "2026-11-04T19:10:00.000Z"
    }
  }
}
```

- 写盘：`tmp` + `rename` 原子替换；读盘容错（缺字段/损坏 → 空表，不抛错）。
- 上限：保留最近 500 条（按 `at` LRU），防无界增长。

### 5.3 端点 `GET /mcp/tool-meta`

```jsonc
{
  "tools": [ /* McpToolMeta[] */ ],
  "summary": { "total": 26, "titled": 2, "translated": 24, "failed": 0 }
}
```

### 5.4 前端注册表（`webui/src/mcp-tool-meta.ts`）

```ts
export function setMcpToolMeta(list: McpToolMeta[]): void;
export function mcpMetaOf(tool: string): McpToolMeta | undefined;
/** 名字分词美化：shortestPath → Shortest Path、get_edge_label → Get Edge Label */
export function prettifyName(raw: string): string;
/** 关键词词典：工具名 + 参数名 → ToolIconKey（D11） */
```

## 六、翻译调用设计

### 6.1 Prompt（单 server 一批）

```
你是 MCP 工具的中文展示名翻译器。下面是一个服务器提供的工具清单（JSON 数组）。
为每个工具给出：
- zh：简洁中文展示名，4~10 字，动词短语或名词短语，不加引号与书名号
- params：参数名 → 中文标签，2~6 字，只翻译给定的参数，不要编造
只输出 JSON，不要任何解释文字。无法判断的项直接省略。
输出格式：{"<工具名>":{"zh":"<中文名>","params":{"<参数名>":"<标签>"}}}

输入：
[{"name":"web_search","description":"Purpose: Perform web searches …","params":{"objective":"Natural-language description …"}}]
```

### 6.2 输入裁剪（控成本）

| 字段 | 上限 | 说明 |
| --- | --- | --- |
| `description` | 240 字符 | 取前 2 句，实测 `parallel-search` 描述约 800 字符，截断后信息足够 |
| `paramDesc[k]` | 80 字符 | 实测 atlasGraphMcp 参数描述短（< 20 字），parallel-search 长 |
| 每批工具数 | 60 | 超出切批串行（D5） |

### 6.3 失败与并发

- **单飞锁**：进程内 `translating: boolean`，重入直接跳过（不排队）。
- **超时**：`AbortSignal.timeout(tools.mcpTranslate.timeoutMs)`（默认 20s），超时记 `failed`。
- **JSON 解析容错**：先尝试直接 `JSON.parse`；失败则剥离 ```` ```json ```` 围栏与前后噪声后重试一次；仍失败记 `failed` 并保留原文前 200 字符进 `translateError`。
- **不重试网络错误**：交给 `LLMClient.chat()` 既有退避逻辑，翻译层不做二次重试（避免放大限流）。
- **部分成功**：返回的 map 缺哪个工具就只让哪个回落美化名，不用整批失败覆盖。

## 七、成本与性能
