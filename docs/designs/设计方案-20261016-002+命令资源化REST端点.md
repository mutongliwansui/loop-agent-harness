## 二、设计原则

1. **资源化直调**：API handler 直调底层业务模块，返回结构化 JSON；不经过 CLI 命令层（渲染/交互/彩色输出），命令层零改动。两层平行：

   ```
   CLI command（渲染 + askConfirm 交互）──┐
                                          ├──► 底层业务模块（manager / writer / loader）──► 存储
   API handler（参数校验 + JSON 序列化）──┘
   ```

2. **一命令组一文件**：每个命令对应一个 handler 文件，导出路由工厂（如 `uploadRoutes(ctx): Route[]`，含 upload/list/clean 三端点）；`server.ts` 汇总路由表时每组一行。
3. **HTTP 动词即确认**：`DELETE`/`PUT`/`PATCH` 语义天然显式，不做 y/N 两段式确认。
4. **延续既有风格**：无 `/api` 前缀、统一错误格式（001 已定）、鉴权三态（token 空→仅本机 / token 非空→Bearer）全端点生效，无新增鉴权面。

## 四、关键设计决策

- **D1 资源化直调，否决通用命令转发**（用户已定）：无 `POST /commands/:name` 之类的转发端点；每命令组按资源建端点、直调底层模块。否决理由：转发端点返回人类可读文本行，无结构化契约；资源化才能演进为稳定 API。
- **D2 一命令组一文件 + 路由工厂**：每文件导出 `xxxRoutes(ctx): Route[]`；`server.ts` 路由表按组汇总一行一组。新增资源组 = 新文件 + 一行，扩展面收敛。
- **D3 复用层次二分**：业务在独立模块的（upload/skill/memory/config）直调；逻辑内联在命令文件的（model 的 `buildUsePartial`、doctor 的诊断项）**补 export 后复用**，纯函数导出不改 CLI 行为。禁止 API handler 复制实现（双源漂移）。
- **D4 作用域参数统一**：写配置类端点一律 `scope: 'workspace' | 'global'`，默认 workspace，与 CLI flag 语义对齐（`configWriter.updateScope/deleteScopeKey` 原生支持）。
- **D5 uploads 显式会话绑定**：`sessionId` 必填且必须已存在（否则 404），不隐式建会话（与 CLI 的 `ensureSessionKey` 按需创建不同——API 显式性优先，避免隐式副作用）；`contextNote` 返回不注入共享 agent，由客户端决定随下轮 `/messages` 发送（延续 001 D5 隔离哲学）。
- **D6 HTTP 动词即确认**：无 y/N 两段式。CLI `askConfirm` 场景映射：upload clean→`DELETE`、skill remove→`DELETE`、skill 同名覆盖→`overwrite: true`、model 删当前使用中→直接 409 拒绝（比确认更严格）。
- **D7 不资源化清单**：`/session` 组（`/sessions` 已覆盖，load/save/current 为 CLI 共享单例语义）；`/setup` 交互向导（其产物写配置已由 `PUT /config` 覆盖）；REPL 内联 `/help /reset /clear`。
- **D8 HandlerContext 扩展**：新增 `configLoader / configWriter / mcpManager / skillLoader / uploadsRoot` 等字段，`bootstrap.ts` 一次组装；001 D9 依赖注入 seam 不变，单测继续注入 fake + 临时目录。
- **D9 零新依赖**：延续 `node:http`；二进制上传、批量操作、OpenAPI schema 文档为演进项（见 §6）。

## 五、边界与错误处理

| 场景 | 行为 |
|---|---|
| sessionId 不存在（uploads） | `404 not_found` |
| paths 含不存在/不可读路径 | 不失败整批：`entries` 收成功项，`failed: [{path, reason}]` 收失败项，201 返回（与 CLI 逐项报告一致）；全部失败 → `400` |
| `GET /config/:key` 键不存在 | `404 not_found` |
| `PUT /config/:key` 值类型与 schema 不符 | `400 bad_request`（复用 zod-ish 校验链） |
| 删除当前使用中的 model profile | `409 conflict` |
| `POST /models` 同名 alias 已存在 | `409 conflict` |
| skill 同名且未 overwrite | `409 conflict`（message 附提示） |
| skill sourcePath 校验失败（无 SKILL.md 等） | `400 bad_request`（message 带原因） |
| mcp add 同名 / 连接失败 | 同名 409；连接失败 502（配置已落盘，响应附 status） |
| memory search 缺 q | `400 bad_request` |
| vision/doctor 检测项失败 | 不失败端点：`ok: false` + `error` 明细（诊断语义） |
| scope 非法值 | `400 bad_request` |
| 全部端点 | 继承 001 鉴权三态、2MB body 限长、统一错误格式 |
