看点：悬停到「readme」这一行时，行尾凭空出现 4 个字符按钮（↑ ✎ ⤓ ✕）， 名称可用宽度瞬间少 ~68px，长名称的省略号位置跳变；同时 📄 与 ✕ 的字形基线在不同系统字体下高度不一致。

症状（按影响排序）
  1. 悬停行宽突变：.ops 由 display:none 切 inline-flex，名称与省略号位置横向抖动；4 个按钮热区仅 ~14px 宽，⤓ 与 ✕ 相邻易误删。
  2. 图标体系割裂：📁/📄 emoji 与字符按钮，和刚落地的工具卡 / 图表容器 16×16 线性 SVG 不同源，跨平台字形与行高也不稳。
  3. 文件大小常驻抢位：.sz 每行都占 ~46px，面板 300px 时深层长文件名几乎只剩省略号；而大小是低频信息。
  4. 无层级引导线：缩进只有 paddingLeft，depth ≥ 3 后父子关系只能靠数像素，深目录回溯困难。
  5. 目录与文件无视觉层级：同字号同色重，仅靠 emoji 区分；展开目录与子项之间没有连线呼应。
  6. 选中态无位置指示：仅 --brand-weak 底色 + 绿色文字，长列表滚动后难以定位「正在预览的是哪一行」，且绿色文字与「状态色只用于语义」的约定冲突。
  7. 无文件类型语义：所有文件同一 📄，md / ts / png / pdf 同脸，扫视无法分辨。
  8. 无键盘导航：无 role="tree"/treeitem"、无 ↑↓←→ / Home / End / F2 / Delete，鼠标是唯一路径。
  9. 加载态粗糙：展开等待是 8.5px 的 … 挤在箭头槽位里，无骨架感，易被误认为空目录。
  10. 树与预览不呼应：预览头部只有路径文字，没有「在目录中定位」的入口，跳转后难确认文件在树中的位置。

1 · 三套方案对比

D1 已选 B

面板常态宽度 300px（对话区占 2/3 时更窄，实测窄态 232px）。方案选型的硬约束是：窄容器下名称优先、 悬停不得改变行内布局、图标必须与工具卡同源。检索参考：VS Code Explorer（紧凑单行 + 引导线 + workbench.tree.indent）、WAI-ARIA APG Treeview（键盘与 role 规范）、PatternFly Tree view （行内动作 hover 出现且「每项最多 1 个动作」）、HeroUI FileTree（缩进引导线 hover 提亮）、Carbon/Spectrum 的 缩进实现对比（层数决定 padding，末层不折叠占位）。

A · 详细信息列表资源管理器式

名称 / 大小 / 修改时间三列 + 表头可排序，图标放大到 20px，靠列宽分配信息。

问题：三列最少需要 380px，300px 面板必出横向滚动条；表头常驻又吃掉 24px 纵向空间。与「右侧窄栏常驻」的定位冲突。

结论：否决（窄容器不可行）
B · IDE Explorer 紧凑式已选定

单行 26px：chevron + 类型图标 + 名称，左侧缩进引导线，右侧固定 24px 操作槽（⋯），选中态为整行弱底 + 2px 指示条。

全部信息按「名称 > 类型 > 操作 > 大小」分层，大小让位到标题属性与底部汇总。

结论：采用（与工具卡、图表容器同一套图标与状态语言）
C · 分栏卡片式Finder 分栏

每进入一层目录向右追加一栏，栏内是磁贴卡片，靠横向滚动回溯层级。

问题：纵向空间利用率低（每栏都要重复头部），深层定位需横向滚动 2~3 屏，且与「预览区在左、树在右」的既有布局冲突。

结论：否决（层级回溯成本高）

关键改动点
  • 顶部面包屑 + 工具条：workspace / docs 常驻说明当前根，右侧四个 24px 图标按钮（定位当前文件 / 新建目录 / 上传 / 自动刷新开关）。自动刷新开启时按钮用 --brand 着色（.on），关闭时回归 muted —— 不再靠文字「开/关」。
  • 搜索框独立成行：现有搜索与树共用一个滚动区，滚动时输入框会跟着走；改为固定行，树在下方独立滚动（.ft-body { overflow:auto }）。
  • 缩进引导线：每级 14px，用 repeating-linear-gradient 按 --d 铺 1px var(--line-soft) 竖线；悬停整行时该行所有祖先线提升为 --line-strong，等于「点亮当前路径」。不新增 DOM。
  • 图标按类型分工：目录 --brand（展开/收起两态），文件 --muted；md / 代码 / json / 图片 / 表格 / pdf 各有 15×15 线性图标，与 tool-meta.ts 的 TOOL_ICON_PATHS 同一套描边参数（1.4 描边、round 端点）。
  • 名称优先：.ft-name { flex:1; min-width:0 }，单行省略 + title 全路径；目录名 500 权重、文件 400，仅靠字重与图标色区分层级，不靠字号。
  • 右侧固定操作槽：24px，内含 ⋯（20×20 热区，是原 4 个字符按钮单体的 4 倍以上）；默认 opacity:0，悬停/选中/聚焦时浮出，点击弹菜单，右键仍出同一组操作。
  • 选中态两级表达：整行 --brand-weak 底 + 左端 2px --brand 指示条（::after，top/bottom:4px 圆角），名称转 600 但不变色 —— 绿色只留给品牌控件与语义状态，延续 20261024-001 的约定。
  • 底部汇总条：5 个目录 · 9 个文件 · 共 3.4 MB，接管被移除的行内文件大小信息，同时给出当前层规模（原先完全没有）。

与旧实现的关系：类名全部重写为 .ft-*（file tree），旧 .tree-row/.tw/.nm/.sz/.ops 保留一版别名指向新样式，避免旧缓存页错乱（与 20261024-001 的处理一致）。
