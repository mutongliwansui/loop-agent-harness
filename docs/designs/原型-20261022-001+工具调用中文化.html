06关键决策点（请逐条确认）

D1映射层放前端，不动后端与 SSE 协议
新增 webui/src/tool-meta.ts 纯前端常量映射（工具名→中文名+图标、参数名→中文标签、每工具摘要函数）。会话数据、SSE 事件、历史消息均不动，历史会话回放天然兼容。
在后端工具 description / SSE 事件里加中文字段——侵入协议层，历史数据不兼容，且 MCP 工具名后端同样不可控。
D2summary 形态：「徽章 + 图标中文名 + 摘要短语 + 耗时」，未知工具回退英文
10 个内置工具走白名单摘要函数（见 05 目录表）；MCP / 未登记工具回退「⚙️ 英文名 + 紧凑 JSON 截断」，保证永不出现空白或报错。
把完整参数全部平铺在 summary 行——回到「一行挤满 JSON」的老问题。
D3展开详情 = 中文参数表 + 原始 JSON 折叠
参数表两列（中文标签 + 值，英文参数名以小字附注，方便与后端 schema 对照）；「原始 JSON」保留为折叠块，排查问题/复制参数时用。
只留中文参数表——丢失与后端字段对照能力，报错排查（错误信息常引用英文参数名）会不便。
D4结果区默认限高截断 + 一键展开
结果默认限高约 120px（渐隐 + 「展开全部」按钮），展开后也限 260px 内滚动，避免数万行日志把消息流撑到不可用。
完全不限制高度——dict.txt 这类 34 万行文件会直接撑爆消息流。
D5失败徽章用启发式判定（前端仅见结果文本）
SSE 的 tool_end 无 status 字段，前端按结果文本启发式判定：[exit=非0] 开头、Error/错误/异常 开头、含 Traceback → 红色 ✗ 徽章；其余为绿 ✓。
改 SSE 协议增加 status 字段——更准确但要动后端与 chat-stream，超出「仅展示层」范围，可作为后续需求。
D6LiveStatus 三态文案同步中文化，机制不动
「思考中… / 生成参数：写入文件 xxx… / 执行中：执行命令 xxx…」；摘要复用 D2 的白名单函数；未知工具保留英文原名。旋转动画、500ms 时钟、停滞提示逻辑全部不动。
LiveStatus 显示完整摘要短语——状态行空间有限，只放「中文名 + 短对象」即可，详情留给工具卡片。
