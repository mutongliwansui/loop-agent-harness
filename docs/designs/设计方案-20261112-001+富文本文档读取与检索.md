## 一、背景与目标

### 1.1 问题

`fileRead` 与 `grep` 的现有实现都以「可直接按 UTF-8 逐行读取」为前提：

- 读取前用前 8000 字节是否含 NUL 判定二进制，直接拒绝或跳过；
- 参数 `startLine/endLine`、`encoding`、`lineNumbers` 与输出 `path:line: content` 都按「文件真实行」设计；
- 结果因此完全无法触达 doc/docx/pdf 这类富文本，模型只能靠 `commandRun` 调外部命令（多数环境没有 `pdftotext`/Office），或者干脆读不到。

WebUI 的文件预览早已另起一套（docx 用 mammoth、xlsx 用 SheetJS、pdf 用 iframe 原生渲染、doc 走后端 `/fs/doc2md`），但**工具层没有对应能力**，Agent 与用户看到的能力不一致。

### 1.3 目标

1. `fileRead` 能直接读取 doc/docx/pdf，返回带行号的提取文本，并保留 `startLine/endLine/maxBytes/lineNumbers` 语义；
2. `grep` 能在单个文档与目录（混合文本/文档）中检索，结果仍为 `path:line: content`，PDF 结果附带页码；
3. 文本文件路径**字节级行为不变**（现有 `tests/file-read.test.ts`、`tests/grep.test.ts` 零改动通过）；
4. 扫描件、加密 PDF、损坏文件、超大文件给出**可纠正的中文提示**，目录检索不因单个文档失败而中断；
5. 零新增 npm 依赖，三平台可用，SEA 单文件打包不受影响；
6. 工具描述总预算不超标（新增参数后仍 ≤ 调整后的预算，且单条 ≤200 字符）。

### 1.4 非目标

- 不做 OCR，不处理扫描件/纯图片 PDF；
- 不做版面还原、字体样式、图片/图表提取；只保留可读文本与必要的分页/分段边界；
- 不支持带密码的加密 PDF/Office 文档（明确提示，不尝试破解）；
- 不支持旧版 `.xls` / `.ppt`（OLE 二进制表格/演示格式），提示另存为 xlsx/pptx 或转 PDF；
- 不改 `fileWrite` / `editFile`（文档只读，不支持回写）；
- 不改 WebUI 文件预览、`/fs/file`、`/fs/search`、`/fs/raw`；
- 不引入向量索引或文档 RAG。

### 1.5 设计约束

- 纯文本路径必须零行为变化：检测只多读一次文件头（可与现有 NUL 嗅探共用缓冲区）；
- 提取层不得依赖 `process.cwd()`，路径由调用方传入绝对路径；
- 提取过程必须有明确上限（源文件大小、页数、提取字符数、时间预算），防止一次工具调用吃满内存或撞 30s 超时；
- 不新增工具名、不改 `ToolContext`、不改 SSE/前端协议；
- docx/xlsx/pptx 的 zip 解析复用 `readZipEntries()` 的既有安全上限（≤2000 条目、解压总量 ≤50MB）。

## 二、总体设计

### 2.1 核心思路：识别 → 提取 → 复用既有行管线

新增一个独立的「文档层」，只负责把二进制文档变成 UTF-8 纯文本；`fileRead`/`grep` 只增加一个前置分支，后续的行号、区间、截断、落盘、匹配逻辑全部复用现有实现。

```
fileRead(path) / grep(path)
        │
        ▼
  readHead(fh, ≤8KB)  ──────────────┐
        │                            │（文本路径：原 NUL 嗅探，行为不变）
        ▼                            ▼
  detectDocumentKind()  ── text ──▶ 现有 readFull/readRange/逐行搜索
        │
      doc/docx/pdf/...
        ▼
  extractDocument(abs, kind, limits)
        │  { text, pages[], pageCount, warnings, truncated }
        ▼
  splitLines + 行渲染（行号/startLine/endLine/maxBytes）
        │
        ├─ fileRead：输出文本 + 截断提示 + 超限时提取文本落盘
        └─ grep：逐行正则 → path:line: content（PDF 加 [p.N]）+ 跳过汇总
```

### 2.2 格式能力矩阵

| 格式 | 识别依据 | 提取实现 | 阶段 | 质量与边界 |
| --- | --- | --- | --- | --- |
| `.txt/.md/.java/...` | 非文档魔数 | **走现有逻辑，零改动** | — | 保持字节级行为 |
| `.docx` | ZIP 魔数 `PK\x03\x04` + 扩展名 | 复用 `word-extractor`（已支持 docx，`getBody()`） | **P0** | 正文与表格文字按段落扁平输出；标题层级/表格列对齐不保留 |
| `.doc` | OLE 魔数 `D0 CF 11 E0 A1 B1 1A E1` + 扩展名 | `word-extractor`（现有依赖） | **P0** | 正文文本；页眉页脚可按需附加 |
| `.pdf` | `%PDF-` | 零依赖自研最小解析器 | **P0 基础 / P1 完整** | 仅文本层 PDF；扫描件、加密、CID 无 ToUnicode 时明确降级 |
| `.rtf` | `{\rtf` | 控制字剥离 + 转义解码 | P2 | 纯文本，样式丢弃 |
| `.odt` | ZIP + `mimetype=application/vnd.oasis.opendocument.text` | zip + `content.xml` 文本节点 | P2 | 正文段落 |
| `.xlsx` | ZIP + `xl/workbook.xml` | zip + sharedStrings/sheet XML | P2 | 单元格文本按行输出，公式只取值 |
| `.pptx` | ZIP + `ppt/presentation.xml` | zip + 每页 `<a:t>` 文本 | P2 | 每页一个分段，不保留版式 |
| `.xls/.ppt` | OLE + 扩展名 | 不支持 | P2 提示 | 明确提示另存为 xlsx/pptx 或 PDF |

> 「P0 基础 / P1 完整」指：P0 先覆盖 FlateDecode + 简单字体（英文/数字为主）；P1 补对象流（ObjStm）、ToUnicode CMap（中文 CID 字体）、加密/扫描件识别与 `pages` 参数。需求验收以 P1 为准。

### 2.3 输出语义

| 工具 | 文本文件（不变） | 文档 |
| --- | --- | --- |
| `fileRead` 全文 | `1: alpha` | 首行加 `[docx 文档，已提取为文本，共 128 行]`，后续仍 `1: …` |
| `fileRead` 区间 | `文件 p 第 3-4 行（共 5 行）:` | `文件 p（docx 文档，共 128 行，已提取为文本）第 3-4 行:` |
| `fileRead` PDF | — | 文本中插入 `=== 第 N 页 ===` 独立行；可选用 `pages: "3-7"` 只读指定页 |
| `grep` | `p:12: content` | `p:12: content`；PDF 为 `p:12: [p.3] content` |
| 行号含义 | 文件真实行号 | **提取文本行号**（同一文件重复提取结果确定，可用于后续 `startLine` 续读） |

> 文档行号不是原文件的行号：docx/xml、pdf 内容流本就没有「行」的概念。工具会在输出里显式说明「行号为提取文本行号」，避免模型误以为能回到原文件对照。

## 四、详细设计

### 4.1 模块与接口

新增目录 `src/documents/`：

```ts
// types.ts
export type DocumentKind = 'doc' | 'docx' | 'pdf' | 'rtf' | 'odt' | 'xlsx' | 'pptx';

export interface DetectResult {
  /** text = 非文档，继续走现有文本路径 */
  kind: DocumentKind | 'text';
  /** 仅当扩展名与魔数不一致时给出（如 .doc 实际是 PDF） */
  warning?: string;
}

export interface PageRange {
  /** 1-based 页号/幻灯片号 */
  page: number;
  /** 该页文本在整体提取文本中的起止行（1-based，含） */
  startLine: number;
  endLine: number;
}

export interface ExtractResult {
  kind: DocumentKind;
  /** 规范化文本：LF 换行；段落/页之间空行分隔 */
  text: string;
  /** 分页文档才有 */
  pages?: PageRange[];
  pageCount?: number;
  /** 可读告警，如「第 3 页未提取到文本（可能是扫描页）」 */
  warnings: string[];
  /** 是否因页数/字符数/时间预算而提前结束 */
  truncated: boolean;
}

export interface ExtractOptions {
  maxBytes: number;
  pdfMaxPages?: number;
  timeBudgetMs?: number;
  signal?: AbortSignal;
}
```

```ts
// detect.ts
export function detectDocumentKind(absPath: string, head: Buffer): DetectResult;

// extract.ts
export function extractDocument(
  absPath: string,
  kind: DocumentKind,
  opts: ExtractOptions,
): Promise<ExtractResult>;

// word.ts
export function extractWordBody(absPath: string): Promise<string>;
```

错误统一用带 `code` 的 `DocumentExtractError`（`unsupported | corrupt | encrypted | too_large | scanned | timeout | empty`），消息为中文、面向模型可纠正。

### 4.2 格式识别

只读文件头 ≤64 字节（与现有 8000 字节 NUL 嗅探共用同一缓冲区，不增加 I/O）：

| 魔数 | 判定 |
| --- | --- |
| `%PDF-` | pdf |
| `D0 CF 11 E0 A1 B1 1A E1` | OLE：扩展名 doc → doc；xls/ppt → 不支持提示；其他 → 不支持 |
| `PK\x03\x04` | 扩展名 docx/xlsx/pptx/odt → 对应 kind；其他 → 按普通二进制处理 |
| `{\rtf` | rtf |
| 其他 | text（继续现有 NUL 嗅探） |

扩展名与魔数冲突时以魔数为准，并写入 `warning`（例如「扩展名 .doc 实际为 PDF，已按 PDF 解析」）。

### 4.3 doc / docx 提取（P0）

- 直接 `new WordExtractor().extract(absPath)` → `getBody()`；与 [`fs.ts L306-L312`](file:///d:/trae_workspace/loop-agent-command/src/api/handlers/fs.ts#L306-L312) 同一 API。
- 规范化：
  - CRLF/CR → LF；
  - 连续 3 个以上空行折叠为 1 个空行；
  - 去除行尾空白（避免 PDF/Word 的排版空格污染 grep 结果）。
- 不保留标题层级与表格列结构（word-extractor 只能取文本）；在输出首行提示「已提取为文本」。
- `.doc` 解析失败（OLE 不是 Word、文件损坏）→ `corrupt`，提示「不是 Word 97-2003 文档或文件已损坏」。
- P1 顺手把 `/fs/doc2md` 改为调用 `extractWordBody()`，`textToMd()` 与响应结构保持原样。

### 4.4 PDF 提取（P0 基础 / P1 完整）

`src/documents/pdf.ts` 的解析流程：

1. **读取与总上限**：整文件入内存（≤50MB，超过直接 `too_large`）。
2. **对象扫描**：不依赖 xref（兼容损坏的交叉引用表），用 `/(\d+)\s+(\d+)\s+obj/` 扫描所有间接对象；同时识别 `ObjStm`（PDF 1.5+ 对象流），解压后把内部对象并入对象表。
3. **加密检测**：trailer 含 `/Encrypt` → `encrypted`，提示「PDF 已加密，无法提取文本」。
4. **页树**：从 `/Root` → `/Pages` 递归 `/Kids` 得到页序；处理 `/Resources` 继承；`/Contents` 支持单引用与数组。
5. **流解码**：`FlateDecode`（`zlib.inflateSync`，带 `maxOutputLength` 防解压炸弹）、`ASCIIHexDecode`、`ASCII85Decode`；不支持 `LZW`/`RunLength` 时跳过该流并告警。`/Length` 优先用声明值，缺失或越界时回退扫描 `endstream`。
6. **内容流解析**：跟踪 `BT/ET`、`Tf/Td/TD/T*/Tm`、`Tj/TJ/'/"`：
   - Y 坐标明显变化或 `T*`/`'`/`"` → 换行；
   - `TJ` 中负 kerning（< -100）或 X 间距过大 → 补空格；
   - 忽略图形状态、路径绘制、图片 XObject。
7. **字体解码**：
   - 优先 `/ToUnicode` CMap：解析 `beginbfchar/endbfchar` 与 `beginbfrange/endbfrange`；
   - 无 ToUnicode 时：简单字体按 WinAnsi/StandardEncoding 单字节映射；`Type0 + Identity-H` 按 2 字节码输出，未映射字符用 `�`；
   - 替换字符（`�`）占比 >20% 时追加告警「字体编码未完全解析，文本可能乱码」。
8. **页聚合**：每页前插入 `=== 第 N 页 ===` 独立行，页间空行；记录 `PageRange` 供 grep 标注与 `pages` 参数使用。
9. **扫描件判定**：去除空白后全文可读字符 < 每页 10 个的均值 → `scanned`，提示「该 PDF 没有可提取的文本层（可能是扫描件）；可用 analyzeImage 或先转成图片/OCR」。
10. **预算**：页数 >500、提取字符 >5M、耗时 >15s（每页检查一次）→ 停止并标记 `truncated`，输出末尾说明。

> 实现规模预估 600–900 行（含注释与测试辅助），是本方案风险最高的部分；通过 D3 的零依赖路径换取 SEA 可打包与部署零负担。若后续真实样本暴露出无法接受的解析缺口，再评估 P2 外部 `pdftotext` 增强（自动探测，失败回退自研）。

### 4.5 fileRead 接入

```ts
// execute 内，stat 之后
const fh = await open(path, 'r');
try {
  const head = await readHead(fh, st.size);          // 复用现有嗅探缓冲区
  const det = detectDocumentKind(path, head);
  if (det.kind !== 'text') {
    return await readDocument(fh, path, st.size, det, {
      encoding, lineNumbers, startLine, endLine, maxBytes, pages,
    }, ctx);
  }
  await assertTextFile(head, path);                  // 原逻辑，入参改为已读缓冲区
  return explicit ? await readRange(...) : await readFull(...);
} finally {
  await fh.close();
}
```

`readDocument()` 负责：

1. 源文件大小 > `MAX_DOC_SOURCE_BYTES`（50MB）→ 抛 `too_large`，提示用 `commandRun` 或转小文件；
2. `extractDocument()`；
3. `pages` 与 `startLine/endLine` 互斥校验；`pages` 仅对 `pdf` 生效（其他分页格式 P2 再扩展）；
4. 用 `text.split('\n')` 得到行数组，复用 `clipLine()`、`withLineNumbers()`、`DEFAULT_MAX_LINES`、`DEFAULT_MAX_BYTES`；
5. 截断时用 `TmpFileWriter` 写入**完整提取文本**，提示文案改为「该文件为提取出的全文文本（非原始二进制文档）」；
6. 返回首行文档说明 + 正文 + 截断/警告提示。

文本路径的 `readFull/readRange/scanLines` 不改逻辑，仅把 `assertTextFile` 的入参从 `FileHandle` 改为已读的 `Buffer`（避免二次读盘）。

### 4.6 grep 接入

`searchFile(filePath)`：

```
head = readHead(fh, size)
det = detectDocumentKind(filePath, head)
if (det.kind !== 'text') {
  if (size > MAX_DOC_GREP_BYTES) { skipped.push(...); return; }
  const ex = await extractDocument(...)   // 受目录总预算约束
  for (i, line of ex.text.split('\n')) {
    const m = regex.exec(line)
    if (m) matches.push(`${filePath}:${i+1}: ${pdf ? `[p.${pageOf(i+1)}] ` : ''}${clipMatchLine(...)}`)
  }
  return
}
// 原 NUL 嗅探 + 流式逐行（不变）
```

- 页号映射：按 `PageRange` 维护移动指针，逐行递增，O(1) 摊销；
- 目录场景新增局部变量 `skippedDocs: Array<{ path, reason }>`，结束时若非空：
  ```
  [跳过 2 个文档] 
  - a.pdf：已加密
  - b.docx：文件损坏
  ```
  最多列 5 条，其余折叠为「等 N 个」；
- 目录文档提取合计超过 20s：剩余文档跳过并计入汇总（原因「超出本次文档提取预算」）；
- 匹配条数硬上限、`maxResults` 落盘治理、超长行窗口截取全部沿用现有实现。

### 4.8 资源与安全

| 风险 | 防护 |
| --- | --- |
| zip 压缩炸弹（docx/xlsx/pptx） | 复用 `readZipEntries()`：≤2000 条目、解压总量 ≤50MB、拒绝 ZIP64/加密条目 |
| PDF Flate 炸弹 | `inflateSync(buf, { maxOutputLength: 64MB })`，超限跳过该流并告警 |
| 超大文件/超长文本 | 源文件 50MB、提取 5M 字符、PDF 500 页、单文档 15s、目录 20s |
| XML 实体膨胀 | 不使用通用 XML 解析器；P2 解析 xlsx/pptx 时只做标签级文本抽取，不展开自定义实体、不处理 DTD |
| 路径越界 | 工具层继续用 `resolveToolPath`；文档层只接收绝对路径，不解析相对路径 |
| 内存峰值 | 一次只提取一个文档；目录场景串行提取，结果逐文件释放（不缓存全文） |
