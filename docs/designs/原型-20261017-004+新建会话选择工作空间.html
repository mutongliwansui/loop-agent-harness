GET /workspaces 原型 20261017-004
原型说明：新建会话时支持选择工作空间目录——优先从已知工作空间一键选择，也可「浏览磁盘」挑选任意目录。
  • 为什么不是操作系统原生选择框：浏览器安全限制拿不到目录的绝对路径（showDirectoryPicker() 只给目录名、webkitdirectory 只有相对路径），而工作空间必须是服务端可访问的绝对路径。因此采用业界同款方案（code-server / Jupyter）：服务端提供目录浏览接口 GET /fs/dirs，WebUI 内置目录浏览器（面包屑 + 目录列表 + 盘符快捷入口）
  • 交互路径：点「＋ 新建会话」→ 弹窗上半是 已知工作空间（GET /workspaces，当前置顶，一键切换）→ 点「📁 浏览磁盘…」打开目录浏览器逐级进入，最后「在此新建会话」
  • 可演示的边界：D:\secure-vault → 403 无权限；跳转输入 D:\nope → 404 目录不存在；D:\data → 空目录提示
  • 切换语义：serve 当前工作空间随之切换（旧空间会话转为只读，与现有跨空间只读模型一致）；新空间自动创建 .loop-agent 配置并置顶展示

接口契约（设计稿）新增 GET /fs/dirs扩展 POST /sessions
GET /fs/dirs?path=D:\trae_workspace          （path 缺省 → 服务端默认目录；Windows 盘根自动列盘符）
→ 200 {
    "path":   "D:\\trae_workspace",        // 规范化后的绝对路径
    "parent": "D:\\",                       // 根目录时为 null（隐藏「上级」）
    "dirs":   [ { "name": "loop-agent-command" }, { "name": "demo-blog" } ]   // 仅子目录，不含文件
  }
错误：400 路径非法（相对路径 / 含 .. 等） · 404 目录不存在 · 403 无权限 / 非目录
实现：fs.promises.readdir(path, { withFileTypes: true }) 过滤.isDirectory()，逐项 try/catch 忽略无权限子项
POST /sessions    { "title": "", "workspacePath": "D:\\new\\proj" }     （workspacePath 省略 → 行为同现状，用当前空间）
→ 校验目录存在且可访问 → 与当前空间相同：直接建会话
                    不同：切换当前工作空间（SessionStore 重绑 workspacePath，写 <userDir>/sessions/<wsId>/meta.json）
→ 201 { "session": {…}, "workspace": { "id", "name", "path", "current": true } }
错误：400 非法路径 · 404 目录不存在 · 403 无权限
切换语义与只读模型
  • 进程级单空间：SessionStore 构造时绑定一个 workspacePath；切换 = 重绑当前空间，不并行多空间执行（agent 的 cwd、.loop-agent 配置、memory 分桶均随空间走）
  • 旧空间会话只读：切换后原空间会话保留完整历史可查看，但输入框禁用（与现有跨空间只读徽标一致）；切回即恢复可写
  • 已知空间聚合：列表来自现有 listAllWorkspaces()（扫描 <userDir>/sessions/* 的 meta.json），无需新增存储
  • 备选增强（不在本期）：目录浏览器记忆最近使用位置；新空间检测到非空 .agent-config.json 时提示复用
