1待发送区（composer 附件区）

52px 高度带：图片走 52×52 缩略图砖，文档走 「折角图标 + 文件名 + 扩展名字标 + 大小」卡，两者同高以保证整行上下沿齐平。 顶部一行汇总（数量 + 总量 + 清空），删除按钮悬停浮出于卡片右上角，不再常驻占位。悬停任一卡片可看到删除按钮与抬升反馈。

现状是 await uploadRaw() 完成后才出现 chip，上传期间零反馈、失败只有 toast 一闪。改为先占位再上传：虚线品牌描边 + 进度条 / 图片砖 spinner，失败就地转红并给「重试」按钮。

2已发送气泡（刷新后同样如此）

图片走 88×88 缩略图（真实缩略图，来源 /uploads/view?disp=raw，已有端点、无新增），与文档胶囊分两行排列： 图片一行、文档一行。分组的原因见下方注释——图片要够大才看得清，胶囊要够扁才不臃肿，硬凑同高两边都会变形。

这三张照片拍的是同一台区吗？
缩略图为什么不新增端点：气泡里的 attachments[].path 是上传后的绝对路径， GET /uploads/view?path=&disp=raw（需求 20261028-006）已支持受控只读取原始字节， 前端 fetch 带 Bearer 后用 URL.createObjectURL 显示，卸载时 revokeObjectURL 释放， 与 FilesView 既有的图片预览同一套写法。失败（404/403）降级为文档胶囊，不出现破图。

3文件类型图标体系

延续项目「16px 内联线性 SVG、stroke-width:1.6、currentColor、圆头圆角」规范（tool-meta.ts / chart-box.ts 同源写法）。 不使用文件类型彩色——避免与品牌绿体系和暗色主题抢色；靠「折角形状 + 内部标识线」区分大类，扩展名交给字标文本。

分四族即可覆盖上传场景：图片（山形 + 太阳）、文档（折角页 + 文本线）、表格（折角页 + 网格）、代码/文本（折角页 + </>）。 PDF 复用文档族但在页内加 PDF 竖条语义线，ZIP 用拉链页形。

顺带修掉的既有缺陷：.msg-file-chip:hover 用了 var(--fg)、:focus-visible 用了 var(--accent)， 这两个令牌在 style.css 中都不存在（全仓检索 0 处定义），所以现在的悬停变色与键盘聚焦描边实际都不生效。本设计全部改用真实令牌（--text / --brand）。
