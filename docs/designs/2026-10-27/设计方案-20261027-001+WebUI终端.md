# 设计方案-20261027-001 · WebUI 文件预览区终端

> 原型：`docs/prototypes/2026-10-27/原型-20261027-001+文件预览区终端.html`（自包含、可交互、亮暗双主题）
> 渲染验证：`webui/verify-term-proto.shot.mjs` → `docs/designs/原型-20261027-001-预览-*.png`（11 张，全部断言通过）

## 1. 需求与范围

在 WebUI **文件预览区**内提供终端，可运行 cmd 与 PowerShell 命令，工作目录默认落在当前会话的工作空间。

范围内：

- 终端以「标签页」形式与文件预览共存于预览区顶部（文件/终端可切换、终端可多开）
- shell 选择（PowerShell 7 / Windows PowerShell 5.1 / cmd）、工作目录、清屏、复制、最大化、重启、关闭
- 会话状态机：运行中 / 执行中 / 已退出 / 断连重连 / 未启动 / 缺 PTY 降级

范围外（本期不做）：分屏（多终端并排）、SSH 远端、文件拖拽进终端路径补全、命令历史持久化。

## 2. 联网调研结论

业界实现高度一致，几乎是唯一成熟解：

```
浏览器 (xterm.js) ⇄ WebSocket ⇄ Node 服务 ⇄ 伪终端 PTY (node-pty / ConPTY) ⇄ shell
```

| 参考实现 | 关键做法 |
| --- | --- |
| [Coder Web Terminal](https://coder.com/docs/user-guides/workspace-access/web-terminal.md) | xterm.js + WebSocket + PTY 五段式；渲染器可选 `canvas`（默认，兼容优先）与 `webgl`（高频刷新/复杂场景） |
| [Cloudflare Sandbox](https://developers.cloudflare.com/sandbox/sdk/concepts/terminal) | 强调「持久双向字节流」而非 `exec()` 逐条执行；客户端自带重连退避 |
| [ttyd](https://github.com/tsl0922/ttyd) | libuv + WebGL2；有 `--check-origin`、`--max-clients` 等安全开关、`-T` 指定 `xterm-256color` |
| [xterm.js 官方](https://github.com/xtermjs/xterm.js) | `pty.onData → term.write`、`term.onData → pty.write`；`@xterm/addon-fit` 负责跟随容器尺寸 |
| [node-pty](https://github.com/microsoft/node-pty) | Windows 走 ConPTY（要求 Win10 1809 / build 18309+，winpty 已移除） |

按官方 README 的范式，核心就是两行数据管道：

```ts
pty.onData((d) => term.write(d));
term.onData((d) => pty.write(d));
```

### 2.1 三个必须提前决策的坑

**① Windows 安装 node-pty 需要原生编译（最大落地风险）**

官方 `node-pty` 的 `npm install` 需要 Python + C++ 编译器 + Windows SDK（node-gyp 链路），普通前端/本机用户几乎不可能具备。社区免编译替代：

- [`@lydell/node-pty`](https://www.npmjs.com/package/@lydell/node-pty)：只装当前平台的预编译二进制，**永不调用 node-gyp**，体积也小得多 → **推荐作为默认依赖**
- `@karinjs/node-pty` / `@homebridge/node-pty-prebuilt-multiarch`：预编译 + 国内镜像，仅 Windows 已充分测试

**② ConPTY 的进程级副作用**

- 每次 spawn 会附带 `conhost.exe`，`windowsHide: true` 对其无效（不走 `child_process`），可能闪黑窗
- [`kill()` 后 ConoutConnection 工作线程未 unref](https://github.com/microsoft/node-pty/issues/887)，会让 Node 进程无法退出（需 `process.exit` 兜底）
- [conout/conin socket 无 error 监听且重抛](https://github.com/microsoft/node-pty/issues/960)，异常管道会直接杀掉宿主进程

→ 对策：PTY 生命周期集中封装、`uncaughtException` 兜底、退出后强制清理进程树、空闲超时回收、限制并发终端数。

**③ 中文/CJK 与编码**

xterm.js 本身支持 CJK，乱码多来自宿主环境。Windows 上需：`cmd` 会话启动后自动 `chcp 65001`；PowerShell 设置 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`；`env` 中补 `LANG`/`LC_ALL`（跨平台同源代码时）。渲染字体需带中文回退（`'Microsoft YaHei UI'`）。

## 3. 交互设计（见原型）

### 3.1 入口：预览区顶部标签行

复用 VSCode 的「编辑器标签」心智，把终端当作预览区的一等公民，而不是另开浮层：

| 元素 | 说明 |
| --- | --- |
| `📄 README.md` | 文件预览页签（沿用现有 `fv-head` 内容，页签只在文件名层面） |
| `● PowerShell` | 终端页签，左侧圆点表示会话状态（绿=运行、灰=已退出、红色=异常）；执行中替换为旋转圈 |
| `＋` | 新建终端（快捷键 `Ctrl + `` `） |
| 悬停 `✕` | 关闭该会话（二次确认仅在进程仍存活时出现） |

选中态用 2px brand 下划线（与现有 `.fv-head`/`.md-mode` 的克制风格一致），不改动既有面板外框与分割条。

### 3.2 终端工具条（38px）

`shell 选择（带版本徽标）` → `工作目录（等宽、可点击复制、中间省略）` → 弹性空白 → `清屏 / 复制全部 / 最大化 / 重启 / 关闭`。

窄面板下：工作目录自动收起为图标，按钮组只保留「清屏 + 关闭」，其余进「更多」浮层。

### 3.3 状态机与覆盖态

| 状态 | 表现 | 关键设计点 |
| --- | --- | --- |
| 运行中 | 正常输出 + 闪烁光标 | 底部状态条：`● 已连接 · 96×27 · UTF-8 · PID · xterm-256color · cwd` |
| 执行中 | 页签转圈 + 右下浮条「正在执行 xx · Ctrl+C · 12.4s」 | 浮条不遮文字，落在终端空白区 |
| 已退出 | 覆盖层「会话已结束 · 退出码 0 · 运行时长」+ 重新启动 / 关闭 | **输出保留可滚动**，不是清屏 |
| 断连 | 顶部黄色横幅「正在重连…（2/5）」+ 立即重连 | 不遮画面；明确告知「终端进程仍在后台运行」 |
| 未启动 | 居中 CTA + 三种 shell 卡片，附「具备当前用户完整权限」提示 | 主动降级：清屏/复制按钮置灰，状态条显示「未连接 / PID —」 |
| 缺 PTY | 「交互式终端不可用」+ 复制安装命令 + 使用命令执行模式 | 直接给出 `npm i @lydell/node-pty`，不让用户去查文档 |
| 已被禁用 | 「当前配置 webui.terminal = false」 | 默认关闭时的解释，而非静默失败 |

一致性约束（已在探针中断言）：**状态条不得在非存活态谎报「● 已连接」**；空态下清屏/复制不可点。

### 3.4 安全交互

危险命令（`del /f`、`del /s`、`rmdir /s`、`rm -rf`、`format`、`shutdown`）提交前弹确认浮层，展示完整命令 + 红色「仍然执行」。**前端确认只是防手滑，不是安全边界**——真正的边界在服务端（见 §5）。

### 3.5 主题

终端配色新增一组 `--term-*` 令牌（浅色 One-Half-Light 取向、深色低饱和），与现有 `--panel`/`--line-soft` 同族；`data-theme` 切换时需同步更新 `term.options.theme`（xterm 是 canvas 绘制，不吃 CSS 变量）。

## 4. 技术实现

### 4.1 前端

```
webui/src/components/TerminalPanel.vue   新增：终端视图（工具条 + xterm 容器 + 状态条 + 覆盖态）
webui/src/terminal.ts                    新增：xterm 实例封装（fit / webgl 回退 / 主题 / 尺寸防抖）
webui/src/views/FilesView.vue            改造：预览区顶部插入 viewer-tabs，按 activeTab 条件渲染
```

- **FilesView.vue 已 2472 行，终端必须独立组件**，只通过 props（`wsPath`）与事件（`close`）交互
- 渲染器：默认 `canvas`（兼容优先）；检测到 `WebglAddon` 可用则启用，并监听 `webglcontextlost` 自动回退 canvas
- 尺寸：`ResizeObserver` → `FitAddon.fit()` → 防抖 120ms 后发 `resize` 消息；面板分割条拖拽时同样走这条链
- 字体：`ui-monospace, 'Cascadia Mono', Consolas, 'Microsoft YaHei UI', monospace`，`fontSize: 12.5`，`lineHeight: 1.62`（原型实测窄面板不横向溢出）
- 渲染节流：xterm 输出侧合并写入，避免大日志把主线程打满

### 4.2 后端

新增 `src/api/terminal.ts`（WS 路由 + 会话表），挂到既有 `server.ts` 的 upgrade 分支。**不复用** `POST /commands` 的资源化端点（那是逐条执行语义，无 TTY、无交互）。

```
GET /ws/terminal?cols=96&rows=27&shell=ps
Upgrade: websocket
Sec-WebSocket-Protocol: loop-agent.token.<TOKEN>
```

浏览器 WebSocket 无法自定义请求头，因此 token 走**子协议**而非 query（query 会进访问日志）。握手时复用现有 `http-utils.ts` 的令牌校验逻辑。

消息协议（JSON 文本帧；大数据用二进制帧直通）：

| 方向 | 消息 |
| --- | --- |
| C→S | `{"t":"in","d":"ls\r"}` / `{"t":"resize","cols":120,"rows":32}` / `{"t":"signal","sig":"INT"}` / `{"t":"close"}` |
| S→C | `{"t":"ready","pid":18364,"shell":"pwsh.exe"}` / `{"t":"out","d":"..."}` / `{"t":"exit","code":0}` / `{"t":"err","code":"pty_missing","message":"..."}` |

- **输出合并**：16ms 内累积后批量下发；单帧上限 64 KB，超出截断并下发 `{"t":"truncated":n}`
- **回放缓冲**：每会话保留最近 256 KB 环形缓冲，重连后先回放再续流（断连不丢输出）
- **心跳**：30s ping/pong；前端指数退避重连（1s→2s→4s→8s，上限 5 次后转手动）
- **生命周期**：会话绑定 `(workspacePath, sessionId)`；空闲 30min 回收；单用户并发上限 4；关闭时 Windows 用 `taskkill /T /F /PID` 保证子进程树清理

## 5. 安全设计

终端 = 任意命令执行，必须按「远程代码执行」级别对待。

1. **默认关闭**：配置项 `webui.terminal`（默认 `false`），首次开启需在配置里显式打开
2. **只允许回环**：非 `127.0.0.1`/`localhost` 绑定且未设 token 时，拒绝开启终端（复用 `server.ts` 现有启动校验口径）
3. **强制鉴权**：WS 握手校验 Bearer token（子协议通道），失败直接 `401` 断连
4. **Origin 校验**：握手校验 `Origin` 白名单，防 CSRF 式跨站连接（参考 ttyd `--check-origin`）
5. **命令审计**：每条回车提交的命令（前端上报 + 服务端记录）写入会话日志，便于回溯
6. **可选黑名单**：`webui.terminalDeny`（如 `shutdown`、`format`、`diskpart`），命中即拒绝并提示
7. **并发与超时**：单用户并发上限 + 空闲回收，避免进程泄漏把机器拖死
