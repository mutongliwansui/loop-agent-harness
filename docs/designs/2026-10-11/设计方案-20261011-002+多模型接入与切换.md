# 设计方案：多模型接入与切换

> 优化建议编号：20261011-002
> 提出时间：2026-10-11
> 方案状态：待评审

---

## 一、背景与目标

当前模型的配置接入只支持单个模型（`model.baseUrl/apiKey/name` 单组配置），要更换模型必须重新走一遍配置流程（手改 JSON 或 `/config set` 逐键修改，或重跑向导），旧配置被覆盖、切换成本高。

目标：**支持接入多个模型配置（登记簿），配套切换命令一键换模型，切换只改激活项、不动各模型已有配置。**

核心原则：

- 接入（登记）与生效（激活）分离：登记簿长期保存各模型三元组，激活项决定当前用谁
- 切换零重启：沿用运行时动态读配置的既有机制，写盘后下一次调用即生效
- 向后兼容：存量用户只有 `model.*` 单组配置时行为完全不变，不强制迁移
- apiKey 安全待遇与 `model.apiKey` 一致：遮蔽显示、不进日志

## 二、现状梳理（结合当前代码）

| 本方案需要的能力 | 当前框架现状 | 结论 |
|---|---|---|
| 模型配置结构 | `ModelConfig`（[schema.ts](../../../src/config/schema.ts)：`name/baseUrl/apiKey/temperature/maxIterations`），单组 | 需扩展，见 5.1 |
| 运行时热读取 | `agent.run()` 每次跑前 `configLoader.load()` 重新读 `cfg.model.*`（[react-agent.ts](../../../src/agent/react-agent.ts) L352-356）；`LLMClient.getClient()` 每次调用动态比对 apiKey/baseUrl，变化即重建 OpenAI 客户端（[client.ts](../../../src/llm/client.ts) L61-72） | **切换天然热生效，运行时零改动** |
| 配置分层合并 | 五层 deepMerge：default < env < global < workspace < cli；**数组整体替换、对象递归合并**（[merge.ts](../../../src/config/merge.ts) L37-46） | models 清单必须用 `Record`（对象）而非数组，否则跨层无法叠加 |
| 配置写入 | `ConfigWriter.updateScope` 读-合并-写回，支持 `--workspace/--global`（[writer.ts](../../../src/config/writer.ts)）；`parseScope/parseValue` 工具（[utils.ts](../../../src/commands/utils.ts)） | 直接复用 |
| 命令范式 | `/vision`（[vision-command.ts](../../../src/commands/vision-command.ts)）展示了 subcommands + Tab 补全 + 来源标注 + key 尾 4 位遮蔽的完整范式 | 直接复用 |
| 连通性测试 | 向导内 `defaultCheckConnectivity`（[wizard.ts](../../../src/bootstrap/wizard.ts)）、`/vision test` 先例 | 抽出共享，见 5.3 |
| 视觉回退 | `vision.*` 为空时回退主模型三元组（`resolveVisionTargets`） | 主模型切换后视觉自动跟随（vision 未独立配置时），**天然联动，无需改动** |
| 引导向导 | 向导收集三元组写 `model.*`（wizard.ts `collectInput`），blocker 判定基于合并后 `model.apiKey/name`（[doctor.ts](../../../src/bootstrap/doctor.ts) L74-81） | 向导不改，兼容联动见 5.6 |
| 既有单次覆盖 | `agent.run(input, { model })` 已支持单次调用级模型覆盖（react-agent.ts L347），不落盘 | 与本方案的持久切换互补，不冲突 |

### 关键结论

1. **运行时零改动**：热生效机制已存在（每次 run/每次调用动态读配置），`/model use` 只需写盘，无需向 Agent/LLMClient 传任何新参数。
2. **唯一的结构性扩展**是配置 schema 新增 `models` 组；其余全部是命令层与展示层的增量。
3. 两个必须正视的坑：
   - deepMerge 数组整体替换 → profiles 若用数组，workspace 清单会整体覆盖 global 清单；**用 `Record<别名, profile>` 递归合并天然跨层叠加**。
   - 跨层覆盖：workspace 层若有 `model.*`，`--global` 切换会被它盖住 → 需要冲突检测（见 5.4）。

## 三、总体架构

```
┌────────────────────── 配置存储（五层合并，沿用） ──────────────────────┐
│  global ~/.loop-agent/config.json   workspace .loop-agent/.agent-config.json │
│                                                                 │
│  models: {                       models: {                      │
│    active: "deepseek",             active: "glm",               │
│    profiles: {                     profiles: {                  │
│      deepseek: {...},  ──deepMerge──>  glm: {...}   ← 对象递归合并，跨层叠加 │
│      kimi: {...}                 }                              │
│    }                           }                                │
│  }                                                              │
│  model:  { name/baseUrl/apiKey }  ← "当前生效"快照（运行时唯一读取点）  │
└──────────────────────────────┬──────────────────────────────┘
                               │
              /model use <别名> = 写 active + 同步 model.* 快照
                               │
                               ▼
        agent.run() 每次跑前 load() 读 model.*  ←─ 无改动
        LLMClient.getClient() 比对 key/url 重建  ←─ 无改动
```

**角色划分：**

| 角色 | 职责 | 对应代码 |
|---|---|---|
| `models.profiles` | 模型登记簿：长期保存各模型三元组，不参与运行时 | `ModelsConfig`（新增） |
| `models.active` | 激活指针：标记当前生效模型来自哪个 profile | `ModelsConfig`（新增） |
| `model.*` | 当前生效快照：Agent/LLMClient 运行时唯一读取点（现状不变） | `ModelConfig`（不改） |
| `/model` 命令 | 登记(list/add/remove)、切换(use)、验证(test)；use 同时写 active + 快照 | `model-command.ts`（新增） |

## 四、关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | profiles 用 `Record<别名, ModelProfile>` 而非数组 | deepMerge 对对象递归合并（global 与 workspace 的 profiles 叠加共存）、对数组整体替换（互相覆盖）；别名同时天然作为切换标识，免做名字唯一性检查 |
| D2 | 顶层新增 `models` 配置组，不塞进 `model.*` | 单数 `model` 语义是"当前生效"，复数 `models` 是"登记簿+激活指针"，职责分离；不动 `model.*` 结构则 loader/merge/bootstrap/vision 回退全部零改动 |
| D3 | **激活即同步写快照**：`/model use` 同时写 `models.active` 与 `model.name/baseUrl/apiKey`（profile 定义了 temperature 时连带写） | 运行时只认 `model.*`，写快照即全链路生效，Agent/LLMClient/doctor/banner 零改动；代价是数据双份（登记簿 + 快照），由命令保证一致性 |
| D4 | 漂移检测而非强制同步：用户手改 `model.*` 后 active 指针不自动失效，`/model list` 比对 name+baseUrl 不一致时警示 | 手改配置是合法操作（如临时换 key 调试），不应被命令层悄悄覆盖；只比结构字段，apiKey 轮换不算漂移 |
| D5 | `/model use` 默认写 workspace，`--global` 写全局（与 `/config set` 惯例一致）；`--global` 时检测 workspace 层 `model.*`/`models.active` 冲突并警示 | 项目级用不同模型是主场景；跨层覆盖是 deepMerge 标量语义的必然结果，必须显式提示（P0 警示，P1 交互确认后清理） |
| D6 | profile 结构 `{ name, baseUrl, apiKey, temperature? }`，**不含 maxIterations** | 前三项+温度是"模型身份"属性；maxIterations 是任务级行为参数，与换哪个模型无关，留在 `model.*` |
| D7 | `models.active` 为空 = 未纳入多模型管理（存量用户状态），一切展示与 blocker 判定按现状 | 向后兼容：不强制迁移，`/model list` 给出引导提示 |
| D8 | apiKey 全链路遮蔽：`/model list`/`/config list` 只显示尾 4 位 | 本方案使 apiKey 副本增多（每个 profile 一份），`printConfigLayer` 现状明文打印 `model.apiKey` 必须一并修复，否则 profiles 全量明文暴露 |
| D9 | 切换不改会话历史 | OpenAI 协议消息与模型无关，同一会话中途换模型即"无缝接续"；token 统计/上下文压缩按会话口径不变 |

## 五、详细设计

### 5.1 配置组 `ModelsConfig`

[schema.ts](../../../src/config/schema.ts) 新增：

```typescript
/** 单个已接入模型的登记信息 */
export interface ModelProfile {
  /** 模型名（如 deepseek-chat） */
  name: string;
  /** 服务地址 */
  baseUrl: string;
  /** API Key（遮蔽展示，尾 4 位） */
  apiKey: string;
  /** 采样温度（可选；未设置时沿用 model.temperature 现值） */
  temperature?: number;
}

/** 多模型接入配置（20261011-002） */
export interface ModelsConfig {
  /** 当前激活的 profile 别名；空串 = 未纳入多模型管理（兼容存量单模型配置） */
  active: string;
  /** 模型登记簿：别名 → 三元组（Record 便于 deepMerge 跨层叠加） */
  profiles: Record<string, ModelProfile>;
}
```

- `AgentConfig` 增加 `models: ModelsConfig`；`PartialAgentConfig` 增加 `models?: Partial<ModelsConfig>`
- `DEFAULT_CONFIG.models = { active: '', profiles: {} }`
- 不新增环境变量（env 层维持主模型三变量，避免与登记簿语义打架）
- 五层合并无需改：`deepMerge` 对 `profiles` 递归合并、对 `active` 标量取高层

### 5.2 激活机制与热生效

`/model use <别名>` 的写入动作（一次 `updateScope` 调用）：

```typescript
const profile = cfg.models.profiles[alias];
const partial: PartialAgentConfig = {
  models: { active: alias },
  model: {
    name: profile.name,
    baseUrl: profile.baseUrl,
    apiKey: profile.apiKey,
    ...(profile.temperature !== undefined ? { temperature: profile.temperature } : {}),
  },
};
await ctx.configWriter.updateScope(scope, partial);
```

- `updateScope` 内部 deepMerge 时 `temperature` 未定义则跳过（merge.ts L33 `undefined: 跳过`），恰好满足"未设置沿用现值"
- **热生效链路（全部既有机制，零代码改动）**：
  1. 下一次 `agent.run()` → `configLoader.load()` 读到新 `model.*`
  2. 下一次 LLM 调用 → `getClient()` 比对 apiKey/baseUrl 变化，重建 OpenAI 客户端；`model` 参数每次从 `config.modelName` 取
  3. 视觉工具（vision 未独立配置时）→ `resolveVisionTargets` 回退新主模型三元组
- 两处启动期捕获的遗留（P1 处理）：`_dreamingModel`（react-agent.ts L220）与 DreamingPipeline 的 llmAdapter（L251）在 `initMemory` 时固化，切换后 Dreaming 仍用旧模型直至重启。改法：`runDreaming` 时动态 `createLLMAdapter(cfg.model.name, ...)`（与 CuratedMemory 压缩回调同款写法），改动约 5 行。

### 5.3 `/model` 命令：`src/commands/model-command.ts`

```
/model list              列出已接入模型（默认子命令）：别名、模型名、baseUrl、key 尾4位、
                         来源标注；激活项打 →；active 与生效快照漂移时警示
/model use <别名> [--workspace|--global]
                         切换激活模型（写 active + 同步 model.* 快照）；未知别名报错并列候选
/model add <别名>        交互式登记新模型：baseUrl → apiKey（遮蔽输入）→ 模型名 →
                         可选连通性测试（y/N）→ 写入 profiles；别名已存在则中止
/model remove <别名> [--workspace|--global]
                         移除登记；激活中的别名拒绝移除（提示先切换）；
                         两层都存在同名 profile 时提示显式指定 scope
/model test <别名>       对指定 profile 发起连通性测试（不改变激活状态）
```

实现要点：

- 命令骨架复用 `/vision` 范式：`subcommands: ['list', 'use', 'add', 'remove', 'test']`、`match: /^\/model(?:\s|$)/i`
- `add` 的交互输入复用向导基建：`askSecret` 遮蔽回显思路（[wizard.ts](../../../src/bootstrap/wizard.ts) `createMaskedAsk`）；连通性测试将 wizard 的 `defaultCheckConnectivity` 抽到 `src/llm/connectivity.ts` 共享（wizard 改为 re-export，行为不变）
- Tab 补全：`src/index.ts` 的 `argProvider` 增加分支——`/model use|remove|test` 返回 `Object.keys(cfg.models.profiles)` 前缀过滤结果；`/model` 走注册器自动进入一级补全，无需动 `BUILTIN_SLASH_COMMANDS`
- `list` 展示存量兼容态（`active === ''`）：

```
模型登记簿（未激活多模型管理）:
  当前生效: deepseek-v4-flash @ https://api.deepseek.com/v1（来源: workspace）
  提示: /model add <别名> 可登记当前模型为 profile，之后 /model use <别名> 一键切换
```

### 5.4 作用域与跨层冲突（D5 展开）

切换写哪一层遵循 `/config set` 惯例（默认 workspace，`--global` 写全局）。跨层覆盖场景必须处理：

| 场景 | 行为 |
|---|---|
| `--global` 切换，但 workspace 层定义了 `model.*` 或 `models.active` | P0：打印警示「workspace 层的 model.*/models.active 将覆盖全局切换（键列表），可用 /model use <别名>（默认写工作空间）或 /config delete 清理」；P1：交互 y/N 确认后自动清理 workspace 的这两个冲突键（二者本就是生效快照，由 /model 接管） |
| `remove` 时两层同名 profile | 提示显式指定 `--workspace/--global`，不猜 |
| `use` 的别名只存在于 global，workspace 未定义 | 正常：global profiles 合并对所有层可见 |

### 5.5 展示接线与 apiKey 遮蔽（D8）

- [config-command.ts](../../../src/commands/config-command.ts) `printConfigLayer`：键名以 `apiKey` 结尾时值渲染为 `****<尾4位>`。此改动同时修复既有 `model.apiKey` 明文打印问题（属安全改进，验收单独立项）
- [renderer.ts](../../../src/ui/renderer.ts) Banner（P1）：`models.active` 非空且未漂移时，模型行追加 `(profile: <别名>)`；漂移时追加 `(profile: <别名>·未同步)`
- `/model list` 中 `sources` 标注读 `sources['models.profiles.<别名>.name']` 与 `sources['models.active']`（resolveSources 已天然支持深层键）

### 5.6 兼容性与向导联动

| 状态 | 行为 |
|---|---|
| 存量用户（只有 `model.*`，`active=''`） | 一切按现状；`/model list` 给登记引导（见 5.3）；bootstrap blocker 判定不变 |
| P1：向导完成后 profiles 为空 | 摘要步骤追加一句「已将当前模型登记为 profile `default`，可 /model add 接入更多模型后 /model use 切换」并写入（失败不阻断向导） |
| P1：首次 `/model add` 且当前生效模型未登记 | 交互询问「是否将当前生效模型（name@baseUrl）也登记为 profile？(y/N)」，避免用户补录旧模型 |
| 删除 active 指向的 profile | 拒绝并提示先切换；`model.*` 快照任何情况下不被 remove 触碰 |
