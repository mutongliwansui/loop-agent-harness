## 二、设计目标与非目标

### 2.1 目标

1. **信息层级**：一屏先读到「哪个模型在生效」，再读「其它模型是什么状态」，最后才是操作。
2. **一事实一处**：生效状态只在置顶行出现一次（左侧 3px 品牌色条 + `生效中` pill）。
3. **颜色克制**：中性态用 `--code-bg`/`--muted`，绿色只给「生效 / 连通成功」，红色只给「真的失败」。
4. **长串可控**：主机域名替代完整 `baseUrl`，全部带 `title` 全文，`text-overflow: ellipsis`。
5. **表单可用**：显式 `label` + 必填星标 + 行内校验 + Key 显隐 + 写入位置就地可见。
6. **零新增依赖与令牌**：只用 `style.css` 既有令牌与既有 `.seg` / `.badge` / `.empty-box` / `.notice` 语汇。

### 2.2 非目标

- 后端端点语义与响应结构变更（`/models`、`/model`、`/models/:alias/test`、`/models/bench/*`）。
- 模型编辑（改名 / 改 Key / 改 Base URL）——列演进项。
- profile 来源 scope 行内展示——`GET /models` 不返回 scope，需后端补字段，列演进项。
- 密钥明文查看（后端已遮蔽，不可逆）。
- `BenchDrawer.vue` 内部重做、CLI 侧 `/model` 命令、ChatView 的模型 pill。

## 四、关键设计决策（D1–D13）

> 以下均为推荐值，已按此执行；如需纠偏请指出编号。

| 编号 | 决策 | 取舍与被否决项 |
| --- | --- | --- |
| **D1** | 列表由**表格改行卡**（`.mv-row`），每模型一行卡 | 否决「保留表格只调列宽」：7 类信息里 3 类是长串（型号 / host / key）+ 4 个操作，表格在 800px 以下必然溢出；行卡可换行堆叠，窄屏天然适配 |
| **D2** | 删除独立「当前生效」卡片，生效信息**合并为置顶高亮行** | 否决「卡片 + 列表双处展示」：同一事实两处出现，且卡片那行是 5 个元素的 mono 平铺，可读性最差。`active=null`（无激活、走 `model.*` 快照）时改用 `.notice.info` 提示，不再占一张卡 |
| **D3** | **移除全部 HTTP 端点徽标**（`GET /models` 等 3 处） | 否决「降级为 dim 小字保留」：开发者在 `/doctor` 与 HTTP API 文档里已有端点信息，管理页放端点属于噪声。若排障需要，`说明` 展开区给一句「对应端点见 HTTP API 文档」 |
| **D4** | 状态色三档收口：**中性 = 未测试 / 未测速**，`--ok` = 连通成功 / TTFT 良好，`--danger` = 连通失败 / 测速全败，`--warn` 只留给 TTFT 偏慢 | 否决「未测试保持 warn 黄」：黄是告警色，用于「没做过」会让正常态看起来有问题。TTFT 沿用既有 `ttftTone()` 阈值（good/warn/bad） |
| **D5** | 操作区 = 3 个 30×30 **图标按钮**（测试 / 测速 / 删除）+ 非生效行的**胶囊文字按钮「设为生效」** | 否决「4 个文字按钮等宽平铺」：4 个同权重按钮让主操作（切换生效）淹没；否决「全图标化」：`设为生效` 是低频高危操作，需要文字明确语义 |
| **D6** | 删除确认沿用既有 `ConfirmButton`（动词即确认），但**收进图标按钮形态**（`.icon-btn.confirm-btn`） | 否决「⋯ 菜单收纳删除」：需新增浮层组件与外部点击管理，收益低于成本，而 `ConfirmButton` 已是项目既有交互语汇（Tools / MCP 页在用） |
| **D7** | 登记表单从内联卡片改**右侧抽屉浮层 420px**（`.mv-drawer`），显式 `label` + 必填星标 + 行内校验 | 否决「保留内联卡片只加 label」：内联表单常驻吃掉首屏 200px，而登记是低频操作；抽屉还能承载「写入位置」与提交按钮的因果绑定 |
| **D8** | 写入位置 = 页头 `.seg` 分段控件 + **抽屉内重复呈现**（同 `v-model`） | 否决「只留页头 select」：作用域决定写到哪个配置文件，必须在「点提交的那一刻」可见；两处共用同一状态，不引入第二份真相 |
| **D9** | 窄屏 ≤720px：行卡 `flex-wrap` 两行堆叠（主信息占满首行，状态区与操作区下沉） | 否决「横向滚动」：横向滚动在管理页会让「设为生效」按钮滚出视野 |
| **D10** | 版尾技术说明折叠为 `<details class="mv-note">`，摘要一行 | 否决「直接删除」：409 限制与计费差异是真实用户会踩的坑，需要可查但不常驻 |
| **D11** | 新增**关键字过滤**（别名 / 型号 / baseUrl 子串，大小写不敏感）+ 计数行（`N 个模型 · M 个生效`） | 否决「不做过滤」：profile 数量增长后只能滚动查找；过滤是纯前端 `Array.filter`，零成本 |
| **D12** | 纯逻辑下沉 `webui/src/models-ui.ts`（图标表、`hostOf`、`modelPills`、`filterProfiles`、`sortActiveFirst`、`validateModelForm`），配 vitest 单测 | 沿用 `chart-labels.ts` / `nav-menu.ts` 先例：`.vue` 无法在 Node 下直测，纯函数可测才守得住不变量（如「生效行恒排第一」「主机名去掉协议与路径」） |
| **D13** | profile **来源 scope 不在行内展示**（本期） | `GET /models` 响应无 scope 字段，前端无法区分「工作空间登记」与「全局登记」。需后端补字段，列为演进项；本期以页头「写入位置」表达用户可控的那一半语义 |
| **D16**（20261103-001 修复） | 图标 SVG **内联 `width`/`height` 兜底**（presentation attribute，CSS 仍可覆盖）；`.mv-filter` 的尺寸与定位挂 `v-html` 产出的 `<span>` 而非直接子 `svg` | `v-html` 使真实 DOM 为 `.mv-filter > span > svg`，`>` 直接子选择器落空；SVG 只有 `viewBox` 无声明尺寸时退化为浏览器默认 **300×150**，过滤图标撑爆整行。根因②是共性缺陷，故从生成侧兜底，任何后续 CSS 失配都只退化为图标大小。详见 8.5 |

## 七、交互细节

1. **过滤**：`input` 事件即时过滤，命中为 `alias|name|baseUrl` 子串（小写比较）；计数行追加「（过滤「q」）」。过滤结果为空但 `profiles.length > 0` 时显示「没有匹配的模型」提示（不显示「还没有登记」空态）。
2. **抽屉校验**（`validateModelForm`）：别名 / 型号 / Base URL / API Key 必填；`baseUrl` 必须 `http://` 或 `https://` 开头；`temperature` 若填必须是 `0~2` 的数字。校验失败时字段加 `.bad`（红边 + 光晕）并在字段下显示 `.field .err`，提交按钮不发起请求。
3. **Key 显隐**：抽屉内 `显示/隐藏` 切换 `type=password|text`，纯前端行为，不回显已存密钥（登记是新增，输入框始终为空）。
4. **写入位置**：页头与抽屉共用 `scope` ref；切换即时生效，登记/切换/删除请求体带同一 `scope`。
5. **删除**：`ConfirmButton` 两段确认（第一段图标态，第二段红底「确认删除」）；当前生效行的删除按钮 `disabled` 并带 `title="先切换生效模型后才能删除"`（与后端 409 语义一致，前端提前拦，减少无效往返）。
6. **切换生效**：成功后 `refresh()`，行卡重排（生效行置顶）。
7. **抽屉关闭**：`✕` / 取消 / 点击遮罩 / `ESC`；关闭时重置表单与校验态。

### 8.5 线上样式事故与修复（20261103-001）

**现象**：用户重打包后反馈「模型配置页面样式不对」，截图显示页头下方出现巨大黑色放大镜，工具行被撑到约 150px。行卡、胶囊、按钮均正常。

**根因（两层叠加）**：

1. **CSS 直接子选择器落空**：模板 `<span v-html="icon('search')"></span>` 的真实 DOM 是 `.mv-filter > span > svg`，而样式写的是 `.mv-filter > svg`（`>` 直接子级），中间那层 `<span>` 让规则完全不匹配。
2. **SVG 尺寸无内联兜底（共性缺陷）**：`modelIconSvg()` 生成的 `<svg>` 只有 `viewBox`、没有 `width`/`height`，尺寸 100% 依赖 CSS。规则一旦失配，SVG 作为替换元素退化为浏览器默认 **300×150**，这就是巨图来源。

**为何只有这一处爆发**：`style.css` 中其余 17 处 SVG 规则（`.pill svg`、`.mv-ico svg`、`.icon-btn svg`、`.mv-empty-ico svg` 等）都是**后代选择器**，能穿透 `<span>`，所以只有用了 `>` 的过滤图标出问题。但根因②是共性缺陷——任何一处后续改动再度失配都会重演。

**修复**：

- `models-ui.ts`：`modelIconSvg()` 输出内联 `width="16" height="16"`（presentation attribute，优先级低于 CSS，既有各处 CSS 覆盖尺寸的行为完全不变），并新增第三参数 `size` 供大图标场合显式指定。
- `style.css`：`.mv-filter > svg` → `.mv-filter > span`（挂定位与 14×14）+ `.mv-filter > span svg { display:block; width/height:100% }`。
- 单测 +2 例：每个图标恒带内联宽高、第三参数可覆盖。

**验证**（CDP，临时端口 3099）：13/13 通过——全页 28 个 SVG 全部 ≤64px（最大 16px）、过滤图标精确 14×14 / `absolute` / 落在输入框内 / 不遮挡占位文字、工具行 32px、抽屉内 SVG 受控、深色主题取色正常、375 窄屏同样通过；视觉模型复核确认巨图消失。

**验证教训（已固化为常设检查）**：上一轮 CDP 34/34 之所以漏掉，是因为几何不变量只覆盖 `.mv-row` 内部子块，**没覆盖工具行**，也没有「全页 SVG 尺寸上限」这条通用断言。本轮起把「扫描全页 `svg`，任一超出 64px 即失败」作为模型页验证的固定项——它不依赖具体类名，能兜住同类事故。
