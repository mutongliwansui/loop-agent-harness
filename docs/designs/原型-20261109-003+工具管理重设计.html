A. 现状问题

先问为什么改

当前工具管理页（ToolsView）是一张扁平表格 + 页头 scope 下拉 + 行内 JsonViewer 展开。按 20261109-001 / 20261109-002 已经确立的「卡片流 + 抽屉」新范式，对照 MCP 与技能页，这里有 6 个具体问题：

1
表格信息密度不均

内置工具 20+ 行全部挤进一张表，行内描述被挤窄无法换行，视觉四件套（describe_image/ask_image/extract_json/ocr_image）直接消失（vision.enabled=false 时），用户不知道有这能力。

2
启用/禁用视觉语义弱

一个 toggle 开关直接决定 prompt schema 是否注入，属于「影响 Agent 核心能力」的高影响操作，但旧版只有一行文字说明，没有禁用态提醒。

3
MCP 工具从这里消失

GET /tools 同时返回 builtin + mcp 两类，旧版只展示 builtin，让用户误以为 MCP 工具只是「不在」而不是「归 MCP 页管」，信息割裂。

4
Schema 查看是行内展开

JSON schema 可能上百行，展开后把整个表格撑得面目全非，且跟在所属工具行紧挨着，视觉无法区分是哪个工具的 schema。

5
scope 写在页头影响面模糊

所有开关共用一个 scope 下拉。用户禁用 fileRead（workspace）后，可能忘记切回 global 就去禁用 commandRun，导致多个工具在两个层被拆解得支离破碎。

6
没有分类 / 搜索 / 筛选

20 个内置工具分属文件 / 命令 / 会话 / 记忆 / 视觉 / HTTP / 技能 7 个家族，旧版不展示家族，用户要找 editFile 或 grep 只能盯着表格扫。

B. 设计决策

D1–D9

沿用 20261109-001（技能）和 20261109-002（MCP）已经建立的「卡片流 + 统计条 + 工具条 + 抽屉 + 弹层」范式，避免每一页重新发明一套。后端接口保持不变，无需改动。

D1
卡片流两列，桌面优先，窄屏自动单列

每卡：工具名（等宽） + 分组图标 tile（按家族染色：文件蓝、命令紫、会话青、记忆玫红、视觉琥珀、HTTP 橙、技能绿） + 简述（2 行截断） + 启用 pill + toggle + ⋯ 菜单 + scope 默认写入下拉（工具条）。

D2
来源分段：内置 / MCP 各自成组

工具条第一分段「全部 / 内置 / MCP / 仅禁用」，MCP 工具卡不显示 toggle（PATCH 会 400），改用「跳 MCP 页」按钮；内置禁用卡灰色底 + 红色斜条 + 标题删除线，突出「不出现在 prompt schema」。

D3
视觉四件套单独提醒

vision.enabled=false 时，describe_image / ask_image / extract_json / ocr_image 仍在卡片流里，tile 灰化 + 右上角「视觉未启用」徽标 + toggle 禁用 + 简述前加「vision.enabled=false，打开后即可调用」，让用户一眼知道「能力存在但被配置挡住」。

D4
详情抽屉替代行内 JsonViewer

点卡片或「Schema」菜单项打开右侧抽屉：名称 + 来源 + 分组 + 启用 pill + 简短说明 + 参数明细表（name / type / required / description）+ 原始 Schema JSON（折叠）+ 示例调用（从描述里提取第一行代码片段）+ scope 信息 + 底部「禁用 / 关闭」按钮。

D5
切换开关直接生效 + 可选重载

点 toggle 直接 PATCH /tools/:name，落盘 + registry 同步 + toast「已禁用 fileRead（workspace），运行中的会话继续可用；重载后新会话生效」。不弹确认模态（同技能页 uninstall 的「一次确认」思路：禁用后果可逆且可见，但需提示影响面）。

D6
搜索 / 来源分段 / 状态分段 / 排序

搜索按名称 + 简述匹配（含 server__tool 的 server 前缀命中）；第二分段「启用 / 禁用 / MCP 失败」；排序「名称 A→Z / 家族优先（文件 → 命令 → 会话 → 记忆 → 视觉 → HTTP → 技能 → 其他）/ 禁用优先（禁用顶到最上）」。

D7
统计条：总工具 / 内置 / MCP / 已禁用 / MCP 失败

五项统计，禁用计数红色，MCP 失败计数红色；分段 Tab 右侧的「N 个」实时同步统计。

D8
后端零改动

沿用 GET /tools + GET /tools/:name + PATCH /tools/:name + POST /tools/reload。唯一约束：MCP 工具卡不调用 PATCH（后端会 400），改为引导去 MCP 页。

D9
键盘 & 无障碍

Esc 关闭抽屉与菜单；`/` 聚焦搜索；菜单 `role=menu` / `role=menuitem`；Toggle 可键盘触发；抽屉 `aria-modal`。骨架 / 空态 / 无匹配态与 MCP / 技能页同构。

E. 接口映射

后端零改动
GET /tools → { tools: [{name, description, enabled, source}] }（内置 + MCP 快照，原样使用；前端按 source 分两组；MCP 失败判定从 GET /mcp/servers 合并）
PATCH /tools/:name { enabled, scope } → 内置工具 toggle（前端按 D5 直接调用；MCP 工具卡不调用，后端会 400）
GET /tools/:name → { name, description, enabled, source, schema }（抽屉正文，参数表 + 原始 JSON 都来自 schema）
POST /tools/reload → { reloaded }（页头「重载」按钮；抽屉底部也可调用）
GET /mcp/servers（合并读取）→ 决定 MCP 工具的 server 来源 + 失败态，用于 MCP 工具卡的 tile 灰化 + 红色条

后端没有工具登记/删除/改名端点（静态注册），所以原型不设计「新建」「删除」「改名」等模态。视觉四件套的门控由 vision.enabled 决定，不是 tools.disabled，前端渲染时要额外读取 GET /config 判断是否灰化。

F. 响应式

三个断点
≥ 980
桌面 · 双列

卡片两列；统计条 5 项均分；搜索 max-width 330px；scope 下拉在工具条最右侧。

860–980
平板 · 单列

卡片变单列；统计条变 3+2 两行；搜索保持 max-width；分段 Tab 折行。

≤ 700
手机 · 堆叠

页头纵排，主按钮 flex:1；搜索、scope 下拉、排序各占一行；toggle 文字说明隐藏，只留开关图形。
