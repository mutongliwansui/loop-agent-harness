| 20261019-001 | 会话上下文三视图统一 | 当前会话内容实际是「内存 1 份 + 磁盘 3 类字段」，与期望的「全量历史 / 压缩视图 / 内存 messages」三视图并不对齐：内存 messages 在 L1 压缩后只剩 system + 最近 3 轮且无摘要占位（LLM 失忆）；磁盘恢复视图 `getRestoreMessages` 另用 lastSummary + 12 条滑窗，与压缩结果形态、参数均不一致；恢复注入的摘要 user 消息还会被写盘污染全量历史。建议抽出唯一生成器 `buildCompactedView()`，让内存压缩与磁盘恢复共用同一逻辑/参数/形态，并给摘要占位加 `ephemeral` 标记（LLM 可见、写盘过滤），全量历史保持干净供前台展示；同时针对「L1 占位与 L2 语义检索注入」的交互补三处防护（flush 笔记 scope 由 global 改 session、检索过滤 `tag: compaction` 条目、查询增强拼接检索词时过滤 `ephemeral`），避免同一份信息被两条通道重复注入（2026-10-20 修订：移除 `ephemeral`，摘要占位统一由 `is_show=false` 承载；废弃 `lastSummary`/`recentMessages`，磁盘收敛为单一 `messages` 真源，恢复按 `is_compact!==true` 过滤） | 2026-10-19 | 是 | 2026-10-19 |
| 20261021-001 | WebUI 对话后台运行与跨页面保持 | 当前 WebUI 在对话进行中无法切换到其他会话（`selectSession` 在 `streaming` 时直接提示「正在生成回复，请先停止」），切到配置等页面会因 ChatView 卸载丢失流式状态，用户感知为「直接断连」，正在生成的回复看不到后续输出。建议：1）把对话流从视图组件抽离为按 sessionId 管理的全局 stream manager（单例/store），ChatView 只订阅当前会话的显示数据，路由切换或切换会话都不中止 SSE 连接，仅「停止」按钮显式中止；2）去掉流式期间禁止切换会话的限制，streaming 状态与 AbortController 按会话维度记录，会话列表对运行中的会话显示「运行中」标记，非当前会话完成时给出提醒（列表红点/toast）；3）补齐重连与恢复能力：服务端为运行中的 run 维护可 attach 的标识与事件序号（或支持 SSE `Last-Event-ID` 续传），页面刷新或重新进入会话时可续接增量，服务端在客户端断开后继续执行并落盘（保持现有行为），完成后重进会话能看到完整结果 | 2026-10-21 | 是 | 2026-10-21 |
| 20261021-002 | WebUI 对话运行态增强（P2：服务端取消 / 同空间并发 / 多标签页同步 / 通知提醒 / 运行态持久化） | 承接 20261021-001（其 P0 后台保活、P1 体验补全已实施，本项为方案原 P2 五项可选增强的展开），建议按 1→2→3→4→5 推进。1）服务端真正取消（优先，独立可用且是并发运行的安全前提）：当前 `stop(sessionId)` 只 abort 前端 fetch，服务端 run 照常执行、继续消耗 token 并可能继续写文件；`AgentOptions`（`src/types.ts`）没有 `signal`，`ToolRunner.withTimeout` 超时后原 Promise 仍在执行。建议新增 `POST /sessions/:id/stop`（幂等：无运行返回 204，有运行触发取消并返回 runId），RunHub 为每个 run 持有 AbortController 并提供 `abort(sessionId)`；新增 `AgentOptions.signal` 贯穿 ReAct 循环——每轮迭代入口检查 `signal.aborted`、LLM 调用透传 signal（OpenAI SDK `create(..., { signal })`，MCP `callTool(params, schema, { signal })`）、工具执行新增 `ToolContext{signal}` 由 `ToolRunner.run` 与 abort 竞争、`commandRun` 把 signal 交给 `exec`（Windows 用 `taskkill /T` 兜底子进程树）、压缩与记忆写入前检查；取消时强制 `persistSnapshot` 落盘已产生消息，Hub 发布终态 `aborted`（与 `failed` 区分），handler 持久化部分结果并追加「已被用户停止」，前端「停止」按钮改为调用该端点（失败再回退本地 detach），刷新后仍能看到部分结果。2）同工作空间多会话并发：`deps.runAgent` 固定绑定 `src/agent/react-agent.ts` 末尾的 `agent` 单例，其 `_chatHistory`/`_workingMemory`/`_episodicMemory`/`_currentSessionId` 会被多会话互相覆盖，因此现在用 `entry.inFlight` 做会话级互斥、`hasInFlight()` 做全局互斥；建议先只解除同工作空间内的并发——新增 `createAgent()` 工厂或按 sessionId 的实例池（LRU 2~4，空闲释放），每个 run 独占 agent 与记忆 kit（`src/api/memory-kit.ts` 的 `cachedKit` 需按 workspace 取而非全局单例），`events`/`onSnapshot` 本就按次注入可直接复用，前端去掉「另一会话正在生成」的发送拦截即可。跨工作空间并发还受 `process.chdir`（`switchWorkspace`）这一进程级状态限制（`skillLoader`/`configLoader`/`SessionStore`/工具相对路径均基于 `process.cwd()`），建议单列 2b：把工作空间根显式化（`ToolContext.workspaceRoot` + 路径解析、`commandRun` 默认 cwd 用根目录、store/skillLoader 按根实例化），彻底移除 `process.chdir` 后再放开；完成前保留「有运行中会话禁止切换工作空间」的限制。3）多标签页状态同步：RunHub 已支持多订阅者，但 `chat-stream` 是各标签页独立的模块单例，A 页停止查看/清未读/完成后 B 页的未读点、标题栏计数、侧栏运行态不会同步；建议新增 `BroadcastChannel('loop-agent')`，只同步 `run-started`/`run-finished`/`run-aborted`/`unread-cleared` 等派生状态与 `lastSeq`（不传消息体），收到后复用 P1 的 `reconcile` 做一次历史对齐，无 BroadcastChannel 时退回 `storage` 事件。4）系统通知与声音提醒：后台完成目前只有页内 toast，用户切到其他应用时无感知；建议在 `document.hidden` 且非当前会话完成时调用 Web Notification（标题 + 会话名 + 耗时，点击 `focus()` 并切到该会话），权限在用户显式开关或首次后台完成时请求、不自动弹窗；并用 WebAudio 生成短提示音（无需音频资源），通知与声音各设一个开关并持久化到 localStorage，`document.hasFocus()` 时不发以免重复打扰。5）运行态持久化与中断诊断：RunHub 全在内存、终态仅保留 60s，服务重启或崩溃后无法判断上次是否运行到一半，`running` 标记消失、用户只看到半截回答易误判；建议在会话目录写轻量 `run.json`（`{runId,status,startedAt,pid,lastSeq,finishedAt}`，start/finish 时更新，写失败不影响主流程），启动时扫描：状态为 `running` 但 pid 已不存在 → 记为 `interrupted`，`GET /sessions/:id` 与 `/workspaces` 暴露 `lastRun`，前端在消息末尾渲染「上次运行被中断（服务已重启），以下是已保存的部分输出」并在侧栏加断点标记，终态与耗时同步写入现有 llm 日志便于诊断。验收建议：同一空间两会话同时流式且消息不串；停止后无新事件、token 停止增长、部分结果落盘且刷新可见；两标签页未读/运行态一致；已授权时后台完成能收到系统通知；重启后中断会话有明确提示 | 2026-10-21 | 否 |  |
