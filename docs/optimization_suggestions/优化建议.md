| 20261015-001 | MCP Streamable HTTP 传输支持 | 当前 MCP 接入只支持 stdio 与 sse 两种传输（`src/tools/mcp/client.ts` 的 `MCPServerConfig` 仅 `StdioConfig \| SSEConfig`，`/mcp add` 交互与 `/mcp list` 详情同样只认 stdio/sse），无法接入仅提供 Streamable HTTP 端点的远程 MCP Server；而 MCP 规范自 2025-03-26 起已用 Streamable HTTP 取代 HTTP+SSE，并在 2026-07-28 规范中将 HTTP+SSE 标记为 Deprecated（SEP-2596），继续只支持 sse 会逐步失去生态兼容性。建议新增 streamableHttp 传输：配置项 `{ type: 'streamableHttp', url, headers? }`（`headers` 用于 Bearer Token / API Key 等认证头），底层复用 SDK 已内置的 `StreamableHTTPClientTransport`（`@modelcontextprotocol/sdk` 1.30.0 已提供，零新增依赖）；同步支持 `/mcp add` 交互选择与 `/mcp list` 详情展示，并保留 sse 传输以兼容存量配置 | 2026-10-15 | 是 | 2026-10-15 |
| 20261019-001 | 会话上下文三视图统一 | 当前会话内容实际是「内存 1 份 + 磁盘 3 类字段」，与期望的「全量历史 / 压缩视图 / 内存 messages」三视图并不对齐：内存 messages 在 L1 压缩后只剩 system + 最近 3 轮且无摘要占位（LLM 失忆）；磁盘恢复视图 `getRestoreMessages` 另用 lastSummary + 12 条滑窗，与压缩结果形态、参数均不一致；恢复注入的摘要 user 消息还会被写盘污染全量历史。建议抽出唯一生成器 `buildCompactedView()`，让内存压缩与磁盘恢复共用同一逻辑/参数/形态，并给摘要占位加 `ephemeral` 标记（LLM 可见、写盘过滤），全量历史保持干净供前台展示；同时针对「L1 占位与 L2 语义检索注入」的交互补三处防护（flush 笔记 scope 由 global 改 session、检索过滤 `tag: compaction` 条目、查询增强拼接检索词时过滤 `ephemeral`），避免同一份信息被两条通道重复注入（2026-10-20 修订：移除 `ephemeral`，摘要占位统一由 `is_show=false` 承载；废弃 `lastSummary`/`recentMessages`，磁盘收敛为单一 `messages` 真源，恢复按 `is_compact!==true` 过滤） | 2026-10-19 | 是 | 2026-10-19 |
