# 需求 20261108-003：后台子任务结果卡片 kind 丢失修复

> 对应需求编号：**20261108-003** ｜ 状态：**已实施（2026-11-09）** ｜ 创建：2026-11-08
> 前置任务：[task-20261107-002-子Agent过程可见与并行后台执行](./task-20261107-002-子Agent过程可见与并行后台执行.md)、[task-20261107-009-P2后台子任务过程可见性增强](./task-20261107-009-P2后台子任务过程可见性增强.md)
> 涉及：`src/session/store.ts`、`src/api/session-manager.ts`、`webui/src/chat-stream.ts`、`tests/subagent-card-kind.test.ts`（新增）、`tests/webui-subagent-card-fallback.test.ts`（新增）

## 一、背景（缺陷）

后台子任务结果卡片是**展示专用消息**（`kind='subagent_result'`，内容为 `<subagent_result>…</subagent_result>` 报文），不进入 LLM 历史。两处判据不一致导致两个可观察缺陷：

1. **卡片 kind 被压缩重写抹掉**：旧版 `toStoredMessage` 对非 summary 消息无条件 `delete out.kind`。压缩轮次把磁盘全量历史重新 `map(toStoredMessage)`（轨迹重建 / legacy 回退两条路径）时，卡片的 `kind` 被清掉。后端仍按内容特征（`isSubAgentResultContent`）正确过滤 LLM 上下文——**模型看不见，但前端只认 `kind`**，进不了卡片分支，`<subagent_result>` 原文被当普通文本裸渲到界面上。
2. **`show_content` 缺失时记忆前缀裸渲**：普通 user 消息的展示依赖后端写入的 `show_content`。存量数据或特殊落盘路径缺该字段时，前端回退到 `content`，把 L2 记忆注入前缀（`## 相关历史记忆 … <<<LOOP_AGENT_MEMORY_END_7f3a9c2e>>>`）原样渲染出来。

## 二、方案与决策点

| # | 决策 | 结论与理由 |
|---|---|---|
| D1 | 写入侧补回 kind | `toStoredMessage` 在 summary 分支之后增加 `else if (role==='user' && isSubAgentResultContent(content)) out.kind='subagent_result'`。与后端判据同源，天然幂等；不用「保留原 kind」方案——全量重写的输入不含旧 kind，无从保留 |
| D2 | 存量脏数据修复 | 新增 `SessionStore.repairSubAgentCardKinds(id)`：内容命中且缺 kind 的补回，有改动才 `writeSession`，返回修复条数。与 `markRunningSubAgentsInterrupted` 同模式，**仅在 `SessionManager.ensureEntry` 冷启动（缓存 miss）调用一次**，避免与运行中写入竞争 |
| D3 | 前端内容兜底 | `chat-stream.ts` 识别卡片时加内容判据兜底，覆盖两个入口：时间线重建 `rebuildChatMsgs` 与运行中轨迹同步 `syncRunningCardTraces`（判据必须同形，否则刷新前后卡片状态不一致） |
| D4 | 判据各自独立实现 | 前端不跨端 import 后端 `isSubAgentResultContent`（webui 独立构建、不引入 `src/` 依赖），前端自带同形实现（`trim` 后 `endsWith('</subagent_result>')` 且 `includes('<subagent_result>')`），注释标注「与后端同形」 |
| D5 | 记忆前缀展示兜底 | `stripMemorySection` 在渲染前剥离 L2 记忆前缀，**循环剥离**嵌套前缀（同一消息可能被多轮注入包裹）；未命中原样返回，零副作用 |
| D6 | 不做批量迁移脚本 | 存量修复挂在冷启动路径，会话被打开时自然收敛；一次性批量改写全部会话文件的收益不抵风险（并发写、备份） |

## 三、改动

| 文件 | 改动 |
|---|---|
| `src/session/store.ts` | `toStoredMessage` 按内容特征补回卡片 kind；新增 `repairSubAgentCardKinds(id)` |
