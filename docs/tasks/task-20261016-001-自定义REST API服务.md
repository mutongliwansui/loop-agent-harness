### 1.3 任务目标

- `loop-agent --serve`（或 `npm run serve`）以 HTTP API 服务进程启动，不开 REPL；共用既有初始化链路（bootstrap / 配置 / 工具 / MCP / Skill / 记忆）。
- REST 端点：健康探针、会话创建 / 列表 / 详情 / 删除、按会话发消息。
- 发消息支持流式（SSE，默认）与非流式（`stream: false`，JSON 一次返回）两种模式。
- SSE 事件全量透传 `AgentEvents` 15 钩子（snake_case 命名）+ API 层合成终态 `done` / `fatal`。
- 鉴权：未配 token 时仅接受本机请求；配置 `api.token` 后强制 Bearer 校验；绑定非回环地址且未配 token 时拒绝启动。
- 会话持久化与 CLI 共用同一 SessionStore 存储（同工作空间会话池），服务重启后历史可恢复。
- `/config` 对新增 `api` 段自动支持查看 / 设置 / Tab 补全；`api.token` 展示遮蔽。

### 1.4 设计约束

- **零新依赖**：仅用 `node:http`，不引入 Web 框架。
- **共享 agent 单例**：不per-session 实例化 ReActAgent（记忆模块初始化成本高），多会话经显式 `messages` 隔离。
- **不破坏 CLI**：REPL 路径行为零变化；serve 模式不注入 agent 的 sessionStore / currentSessionId。
- **可单元测试**：Server 构造与依赖解耦（注入 fake agent.run 与临时目录 SessionStore），单测起真实 http server（port 0）用 `fetch` 断言。
- **安全默认**：默认绑定 `127.0.0.1`；token 脱敏展示；请求体大小限制。

## 二、方案设计

### 2.1 总体思路

```
外部客户端 (Web / IDE / 脚本)
   │  HTTP  D8: node:http, --serve 进程
   ▼
src/api/server.ts  createApiServer(deps)
   │  路由 → 鉴权 D6 → JSON 解析/限长 → 会话锁 D5
   │
   ├─ GET  /health                    ──► 直接返回 {status, version, model}
   ├─ POST /sessions                  ──► SessionStore.createSession（空会话）
   ├─ GET  /sessions                  ──► SessionStore.listSessions            (P1)
   ├─ GET  /sessions/:id              ──► loadSession + meta + recentMessages  (P1)
   ├─ DELETE /sessions/:id            ──► SessionStore.deleteSession           (P1)
   └─ POST /sessions/:id/messages     ──► 会话管理器
            │  history 缓存 miss → loadSession + getRestoreMessages   D5
            ▼
      agent.run(input, { messages | resetHistory, verbose:false, events:[SseForwarder] })  D5
            │        AgentEvents 15 钩子全量透传（D4：onXxx ─► snake_case 事件名）
            │        start / iteration_start / llm_stream / llm_end / llm_stats
            │        llm_stats_summary / tool_start / tool_end / tool_progress
            │        tool_call_delta / compaction / final / error / warning / end
            ▼
      持久化（API 层 SessionStore.createSession/updateSession）
      合成终态（D4）：done（正常）│ fatal（异常）──► 关流
```

### 2.2 关键设计决策

#### D1 用 `node:http` 内置模块实现，零新依赖

- 端点数量少（6 个）、无中间件生态诉求，`node:http` + 手写极简路由（方法 + 路径正则匹配）完全够用。
- **被否决项**：express / fastify（新增依赖，违背工程默认约束）；@modelcontextprotocol/sdk 复用为 server（那是 MCP 协议，用户已明确不走）。

#### D2 资源式 REST 端点，会话为一等资源

- `POST /sessions` 创建、`GET /sessions` 列表、`GET /sessions/:id` 详情、`DELETE /sessions/:id` 删除、`POST /sessions/:id/messages` 发消息、`GET /health` 探针。
- **被否决项**：单端点 `POST /chat`（无会话管理，Web/IDE 场景必需多会话，已在 Q1 确认）；OpenAI 兼容 `/v1/chat/completions` 形态（用户已选自定义协议，且无状态补全语义与本 Agent 的会话型多步推理不匹配）。

#### D3 流式走 SSE，`stream` 参数切非流式

- 发消息默认 `stream: true`：响应 `200 + Content-Type: text/event-stream`，事件流式推送；`stream: false` 时等 `run()` 结束一次性返回 JSON。SSE 是 A2A 协议与业界 Agent 流式的主流传输（见 2.3 检索），`node:http` 原生支持。
- 非流式作为参数附赠（同一处理管线，仅响应封装不同），供 curl / 脚本等简单场景使用。
- **被否决项**：WebSocket（双向通道对本「单请求-多事件」模型过度设计，且引入升级握手复杂度）；轮询任务态（实现复杂度最高、延迟最差）。

#### D4 SSE 事件：AgentEvents 全量透传 + 合成终态

- **透传规则**：`AgentEvents` 全部 15 个钩子按「去 on 前缀 + camelCase 转 snake_case」映射为同名事件，参数原样序列化为 data：`start` / `iteration_start` / `llm_stream` / `llm_end` / `llm_stats` / `llm_stats_summary` / `tool_start` / `tool_end` / `tool_progress` / `tool_call_delta` / `compaction` / `final` / `error` / `warning` / `end`。客户端可完整还原 REPL 观感（迭代进度、token 统计、上下文压缩、长工具心跳、工具参数生成进度）。
- **序列化特例**：`Error` → `{name, message}`（Error 原生不可 JSON 序列化）；`end` 事件携带完整 `AgentResult`（answer/steps/messages，体量大但透传语义如此，客户端可选择性消费）。
- **终态契约**：API 层合成两个终态事件，流必以其一收尾——正常结束 → `done{sessionId,durationMs,iterations,steps}`（在 `end` 之后）；`run()` 抛异常 → `fatal{message}`。透传的 `error` 是 Agent 内部非致命上报（如达到 maxIterations），可在流中正常出现，不承担终态语义。
- **被否决项**：白名单式 7 事件子集（用户明确要求全量透传，观测类事件对 Web/IDE 进度渲染有价值）；保留 onXxx 原始命名（统一 snake_case 更符合 SSE/JSON 惯例）。

#### D5 会话引擎：共享 agent 单例 + 显式 messages + API 层自持 SessionStore + 会话级互斥

- 复用全局 `agent` 单例：`run()` 支持 `options.messages` 显式传历史、`resetHistory` 重开（[react-agent.ts L379-L397](file:///d:/trae_workspace/loop-agent-command/src/agent/react-agent.ts#L379-L397)），多会话经调用参数隔离，不依赖实例 `_chatHistory`。
- **规则**：缓存历史为空 → `resetHistory: true`（全新会话，忽略实例内部可能存在的残留 `_chatHistory`）；非空 → `messages: history`（`run()` 自动补 system）。
- serve 模式**不**执行 `agent.setSessionStore()`、不恢复会话到 agent（index.ts 分支改造）：否则两次并发 run 的自动保存会按共享 `_currentSessionId` 互相串写。持久化由 API 层在 `run()` 返回后用自持 SessionStore `createSession`（首次）/`updateSession`（续写）完成。
- 历史缓存：`Map<sessionId, ChatMessage[]>`（不含 system）；miss（服务重启）时 `loadSession(id)` + 静态 `SessionStore.getRestoreMessages(data)`（含 lastSummary 注入与 recentMessages，不含 system）。
- 会话级互斥：同会话已有 in-flight run 时新请求返回 `409 busy`；不同会话可并行（registry/runner/llm 调用均为无共享可变状态）。
- **被否决项**：per-session ReActAgent 实例（`initMemory` 等初始化成本高且记忆模块按目录共享，多实例无收益）；依赖 agent 自动保存（共享 `_currentSessionId` 必然串话）。

#### D6 鉴权：token 未配置仅本机 + 配置后强制 Bearer；非回环绑定无 token 拒绝启动

- `api.token` 为空：校验 `req.socket.remoteAddress` 属本机（`127.0.0.1` / `::1` / `::ffff:127.0.0.1`），否则 `403 forbidden`。
- `api.token` 非空：所有请求校验 `Authorization: Bearer <token>`，失败 `401 unauthorized`。
- 启动校验：host 绑定非回环地址（如 `0.0.0.0`）且 token 为空 → 直接报错退出（防裸奔暴露局域网）。
- **被否决项**：HTTPS/TLS（本机服务，由反向代理场景自行解决，属演进项）；CORS 头（同机使用为主，属演进项）。

#### D7 配置新增顶层 `api` 段，token 展示遮蔽

- `api: { port: 3000, host: '127.0.0.1', token: '' }`：`AgentConfig` / `PartialAgentConfig` / `DEFAULT_CONFIG` 三处同步；[ConfigWriter](file:///d:/trae_workspace/loop-agent-command/src/config/writer.ts) 按点路径泛型读写，`/config get api.port`、`/config set api.token xxx` 零改动即生效；`flattenConfigKeys` 自动补全新段。
- [maskSecretsDeep](file:///d:/trae_workspace/loop-agent-command/src/commands/config-command.ts#L44) 遮蔽键从 `apiKey` 扩展到 `apiKey|token`（`/config` 展示 `****尾4位`）。
- **被否决项**：配置项挂在 `agent.api.*`（既有惯例均为顶层段，如 session/vision）；环境变量优先级（`PORT` env 已有 `env` 来源机制覆盖，不专项处理）。

#### D8 启动方式：`--serve` argv 开关，共用初始化跳过 REPL

- [index.ts](file:///d:/trae_workspace/loop-agent-command/src/index.ts#L95) `main()` 在记忆初始化（step 5）后判断 `process.argv.includes('--serve')`：构建 API 专用 SessionStore（init 但不恢复、不注入 agent）→ 打印服务信息 → `await startApiServer()` 常驻；SIGINT/SIGINT 时关停 server + `mcpManager.disconnectAll()`。
- `package.json` 增加 `"serve": "tsx src/index.ts --serve"`；SEA/构建产物天然继承 argv 行为。
- **被否决项**：REPL 内 `/api start|stop`（同进程双入口状态复杂，留作演进项）；配置常开自动起服务（隐式行为不利排障）。

#### D9 可测试性：`createApiServer(deps)` 依赖注入，单测起真实服务

- 导出 `createApiServer(deps: ApiServerDeps)`，`deps` 含 `runAgent`（`agent.run` 的函数签名）、`sessionStore`、`getConfig`、`version`；`startApiServer()` 负责真实组装（读配置、建 SessionStore、绑单例 agent）。
- 单测：`SessionStore` 指向临时目录（`encryptionEnabled: false`），`runAgent` 为 fake（按脚本回调 `events` 钩子并返回 AgentResult），server 监听 port 0 取实际端口，`fetch` 断言状态码 / JSON / SSE 事件序列。
- **被否决项**：仅集成测试（依赖真实 LLM，CI 不稳定）；supertest 类工具（新依赖）。

### 2.3 检索结论（同类实现与已知坑）

| 结论 | 来源 |
|---|---|
| A2A 协议流式：`200 OK + Content-Type: text/event-stream`，body 为 SSE 事件流；`message/stream` 一次请求同时发送消息并订阅更新 | [A2A Spec — Streaming Transport](https://a2a-protocol.org/v0.2.5/specification/)、[Streaming & Async](https://a2a-protocol.org/dev/topics/streaming-and-async/) |
| 业界 Agent 流式推荐「SSE + 类型化事件」（`text_delta` / `tool_start` / `tool_end` / `done` / `error`），客户端按 type 路由渲染；SSE 适合 server→client 单向推送，WebSocket 适合双向 | [Streaming Typed Events 模式](https://agentpatternscatalog.github.io/patterns/patterns/streaming-typed-events.html)、[Streaming AI Agent Responses in Production](https://niteagent.com/blog/2026-07-09-streaming-agent-responses-production-guide/) |
| SSE 帧格式：`event: <type>\n` + `data: <JSON>\n` + 空行边界 | [IETF draft-spk-agentproto-llm-stream](https://datatracker.ietf.org/doc/html/draft-spk-agentproto-llm-stream) |
| 工具执行期间文本流会暂停，需 tool_start/tool_end 事件维持「进行中」感知（本设计 D4 已覆盖） | [Streaming Responses Implementation](https://www.ai-agentsplus.com/blog/streaming-responses-ai-agents-implementation-2026) |

**路由与处理器**（极简分发：先按 `method+path` 精确匹配，`:id` 用正则 `^/sessions/([^/]+)$` 提取）：

| Method | Path | 请求体 | 成功响应 | 阶段 |
|---|---|---|---|---|
| GET | `/health` | — | `200 {status:'ok', version, model}` | P0 |
| POST | `/sessions` | `{}`（可空体） | `201 {id, title, createdAt, updatedAt, messageCount:0}` | P0 |
| POST | `/sessions/:id/messages` | `{message: string, stream?: boolean=true}` | 流式：`200 text/event-stream`；非流式：`200 {sessionId, answer, iterations, steps, durationMs}` | P0 |
| GET | `/sessions` | — | `200 {sessions: SessionMeta[]}` | P1 |
| GET | `/sessions/:id` | — | `200 {meta, messages}`（`getRestoreMessages` 视图，不含 system） | P1 |
| DELETE | `/sessions/:id` | — | `200 {deleted: true}`（同时清历史缓存） | P1 |

**SSE 事件**（`event: <type>\n` + `data: <JSON>\n\n`）：15 个透传事件 + 2 个合成终态（D4）

| 事件 | data 载荷 | 来源 |
|---|---|---|
| start | `{input}` | onStart |
| iteration_start | `{iteration, maxIterations}` | onIterationStart |
| llm_stream | `{text}` | onLLMStream |
| llm_end | `{response, iteration}`（LLMResponse 全量） | onLLMEnd |
| llm_stats | `{stats}`（tokens / 耗时） | onLLMStats |
| llm_stats_summary | `{summary}` | onLLMStatsSummary |
| tool_start | `{tool, args}` | onToolStart |
| tool_end | `{tool, result}` | onToolEnd |
| tool_progress | `{tool, elapsedMs}` | onToolProgress |
| tool_call_delta | `{tool, accumulatedBytes, elapsedMs}` | onToolCallDelta |
| compaction | `{info}`（压缩前后 token 等） | onCompaction |
| final | `{answer}` | onFinal |
| error | `{name, message}` | onError（非致命上报，可多次） |
| warning | `{level, message, context?}` | onWarning |
| end | `{result}`（完整 AgentResult 或 null） | onEnd |
| **done** | `{sessionId, durationMs, iterations, steps}` | **合成终态**（正常结束，关流） |
| **fatal** | `{message}` | **合成终态**（run 抛异常，关流） |

**统一错误格式**：`{ "error": { "code": string, "message": string } }`，code → HTTP 状态：`unauthorized`(401) / `forbidden`(403) / `not_found`(404) / `method_not_allowed`(405) / `bad_request`(400，含 JSON 解析失败、message 缺失) / `busy`(409) / `payload_too_large`(413) / `internal`(500)。

**会话管理器**（server.ts 内部）：

```typescript
interface SessionEntry { history: ChatMessage[]; inFlight: Promise<unknown> | null; }
const sessions = new Map<string, SessionEntry>();
```

- 发消息流程：鉴权 → 取 entry（不存在→404；`inFlight` 非空→409）→ history 缓存 miss 则 `loadSession` + `getRestoreMessages`（过滤 system）→ 构造 `events`（SSE 转发器或无事件收集器）→ `runAgent(input, history空 ? {resetHistory:true, ...} : {messages: history, ...})`，`verbose: false`、不传 spinner → 返回后：空历史→`createSession`（以 input 为 firstMessage）否则 `updateSession`；写回缓存与 `result.messages` → 推送 done / 返回 JSON。
- 持久化失败不失败整个请求：以 `event: error`/JSON warning 语义降级（对齐 agent 内 onWarning 处理哲学），HTTP 仍成功返回回答。

**服务器杂项**：`server.requestTimeout = 0`（长流式不被 Node 默认 300s 掐断）；请求体累计超 2MB → 413 并销毁连接；未知路径 → 404 JSON；路径匹配但方法不符 → 405；客户端中途断开（`res.on('close')`）→ 停止写流但 run 照常完成并持久化。

### 3.4 边界与错误处理

| 场景 | 行为 |
|---|---|
| 未配 token 且请求来自非本机 | `403 forbidden` |
| 已配 token 且缺失/错误 Bearer | `401 unauthorized` |
| host 绑非回环且未配 token | 启动即报错退出（进程 exit 1，打印修复指引） |
| 会话不存在 | `404 not_found` |
| 同会话并发第二条消息 | `409 busy`（附 in-flight 提示） |
| body 非 JSON / message 缺失或非字符串 | `400 bad_request` |
| body 超 2MB | `413 payload_too_large` |
| agent.run 抛错（LLM 网络错、异常） | 流式：先推已发生事件再合成 `event: fatal` 关流；非流式：`500 internal`（run 抛错不持久化本次失败轮，保留原历史）。注：达到 maxIterations 不抛错，照常走 `final` + `done` |
| 会话持久化失败 | 回答照常返回，附 warning 字段/事件（不静默丢） |
| `POST /sessions` 同秒并发 id 冲突 | ~~createSession 返回重复 id 时重试追加 `-2` 后缀（最多 3 次）~~ 实施偏差：store 内部生成秒级 id 不可自定义，改为 createSessionSafe——Promise 链串行化创建请求 + 两次创建间隔 ≥1050ms（最多等待 3 次），从源头规避同秒撞 id |
| 客户端中断 SSE 连接 | 停止写流，run 完成并持久化（下次可续） |
| 端口被占用 | 启动报错退出，提示 `api.port` 配置项 |
| `/config set api.token` 后 | 已运行实例不热生效（鉴权配置启动时定），README 注明需重启 |

#### 实施偏差与补充说明

1. **createSessionSafe**：原方案「同秒冲突重试追加 `-2` 后缀」不可实现——`SessionStore.createSession` 内部生成秒级 id 且不可自定义。改为 Promise 链串行化创建请求 + 两次创建间隔 ≥1050ms（最多等待 3 次），从源头规避同秒撞 id。
2. **readBody 413 排空策略**：超 2MB 时置 `overLimit` 标志后 `removeAllListeners('data')` + `resume()` 排空请求体再 reject，保证客户端能收到 413 响应而非连接重置。
3. **长流式保护**：`server.requestTimeout = 0`，避免 Node 默认 300s 掐断长 SSE 流。
4. **startApiServer 动态 import**：agent/config/session 模块在函数体内动态加载，避免非 serve 路径的启动开销与循环依赖。
5. **配置热读**：`getConfig()` 每请求调用（health/model/token 均取活值）；鉴权三态中的 token 于启动时校验并缓存，`/config set api.token` 后需重启生效（README 已注明）。
