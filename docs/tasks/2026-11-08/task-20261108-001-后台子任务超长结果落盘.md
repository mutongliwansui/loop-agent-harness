# 需求 20261108-001：后台子任务超长结果落盘（告别「结果过长已截断」）

## 背景

后台子任务（delegate）完成时，`buildSubAgentWakeNotice`（原 `src/api/handlers/messages.ts`）把结果注入会话前硬截 2000 字符。长报告（如 README 中英文比对报告）尾部（明细 + 总体结论）天然丢失，主 Agent 只能靠人工复核补齐。

## 方案

复用 output-governor 的 tmp 落盘基础设施（`buildTmpFilePath` / `pruneTmp` 7 天 TTL），与工具超长输出治理（20261106-001）同构：

- **≤2000 字符**：维持原行为，结果直接进通知。
- **>2000 字符**：完整落盘 `~/.loop-agent/tmp/<sessionId>/subagent-<taskId>-<ts>.txt`，通知里带「路径 + 大小 + 开头 400 字符预览 + fileRead 分段读取建议」；文件即真相源，无截断。
- **落盘失败**：降级回 2000 字符截断，并如实声明「完整内容落盘失败」。
- **error 优先于 answer**、状态文案（已完成/已取消/失败）、`SUBAGENT_WAKE_PREFIX` 前缀文本均保持不变——会话落盘剥离逻辑（`stripWakeInput`）不受影响。
