## 一、任务目标需求

### 1.1 背景

`--serve` 模式（Task-20261016-001 已交付）目前只暴露 `/health`、`/sessions` 系、`/sessions/:id/messages` 会话与对话端点。CLI 内置命令沉淀的运维能力——文件上传、配置读写、工具开关、模型增删切换、MCP 服务器管理、Skill 安装卸载、记忆检索与整理、视觉链路状态、环境诊断——外部客户端（Web / IDE 插件 / 自动化脚本）无法程序化调用，只能绕道 CLI 人工操作。

### 1.2 现状梳理

| 所需能力 | 现状 | 结论 |
|---|---|---|
| API 骨架 | [router.ts](file:///d:/trae_workspace/loop-agent-command/src/api/router.ts) 声明式路由表 + `matchRoute`（`:param` 单段提取 / 405 / 404）；[server.ts](file:///d:/trae_workspace/loop-agent-command/src/api/server.ts) 只做组装（鉴权 → 路由 → handler → 错误转 JSON） | **骨架可直接扩展**；`createRoutes()` 改为按组汇总 |
| HandlerContext | 现为 `{deps, sessions, log, version}`（[router.ts L15](file:///d:/trae_workspace/loop-agent-command/src/api/router.ts#L15)） | **需扩展**（D8）：新增 configLoader / configWriter / mcpManager / skillLoader / uploadsRoot |
| 业务单例 | [mcp-manager.ts L135](file:///d:/trae_workspace/loop-agent-command/src/config/mcp-manager.ts#L135) `mcpManager`、[skill/loader.ts L76](file:///d:/trae_workspace/loop-agent-command/src/skill/loader.ts#L76) `skillLoader`、[tools/registry.ts L167](file:///d:/trae_workspace/loop-agent-command/src/tools/registry.ts#L167) `registry` 均为模块级单例 | **直调/import 即可**；与 index.ts main() serve 分支共享同一实例 |

| 交互依赖 | `askConfirm`（upload clean / skill 同名覆盖）、`rl.question`（mcp/model 交互选择） | **REST 语义替代**：HTTP 动词 + 请求体参数（D6） |

### 1.3 任务目标

- 新增 10 组 handler 文件、33 个端点（uploads / config / tools / models / mcp / skills / memory / vision / doctor / status），端点表见设计文档 §3。
- API handler 直调底层业务模块，返回结构化 JSON；CLI 命令层零改动（含渲染与交互行为）。
- 鉴权、错误格式、body 限长、统一入口全端点继承 001 契约，无新增鉴权面。
- 单测覆盖每组核心路径与边界（404 / 400 / 409 / 201 部分成功），注入 fake 依赖 + 临时目录。

### 1.4 设计约束

- **零新依赖**：延续 `node:http`，无路由/校验框架。
- **CLI 零改动**：命令层文件除 doctor 补 export 外不动；禁止 API handler 复制命令内联实现（双源漂移）。
- **两层平行架构**：CLI command（渲染 + askConfirm）∥ API handler（参数校验 + JSON）→ 同一底层业务模块。
- **可单元测试**：HandlerContext 依赖注入 seam 不变（001 D9），单测起真实 http server（port 0）+ `fetch` 断言。

## 三、任务详细设计

### 3.1 HandlerContext 扩展（D8）

```typescript
// src/api/router.ts（扩展既有接口）
export interface HandlerContext {
  deps: ApiServerDeps;
  sessions: SessionManager;
  log: (msg: string) => void;
  version?: string;
  // ── 002 新增 ──
  configLoader: ConfigLoader;      // getByKey / path 逻辑（deps.getConfig 已覆盖合成配置读取）
  configWriter: ConfigWriter;
  mcpManager: MCPManager;
  skillLoader: SkillLoader;
  uploadsRoot: string;             // defaultUploadsRoot()
}
```

- `createApiServer(deps)` 签名不变；新增字段由 `bootstrap.ts` 组装（`ApiServerDeps` 不膨胀——这些是与真实单例绑定的运行时依赖，单测在构造 HandlerContext 时注入 fake）。
- 组装来源：`configWriter = new ConfigWriter(...)`（与 CLI 同参）、`mcpManager` / `skillLoader` 直接 import 单例（与 index.ts main() serve 分支共享同一实例，MCP 已在初始化链路连接）。
- tools 组直调 `import { registry } from '../../tools/registry.js'` 单例（读快照 + reload，无注入需求）。

### 3.2 路由工厂约定（D2）

```typescript
// src/api/handlers/uploads.ts（用户点名形态）
export function uploadRoutes(ctx: HandlerContext): Route[] {
  return [
    { method: 'POST',   path: '/uploads',          handler: handleUpload },
    { method: 'GET',    path: '/uploads',          handler: handleListUploads },
    { method: 'DELETE', path: '/uploads',          handler: handleCleanUploads },
  ];
}
```

```typescript
// src/api/router.ts createRoutes() 汇总：每组一行
export function createRoutes(): Route[] {
  return [
    { method: 'GET', path: '/health', handler: handleHealth },
    // ...001 既有 sessions 系
    ...sessionRoutes(),   // 若迁移则迁，否则保留内联
    ...uploadRoutes(ctxFactory),
    // ...10 组各一行
  ];
}
```

> 实施注意：`createRoutes()` 当前无参，路由工厂若需 HandlerContext（如闭包 deps），采用工厂函数惰性取 ctx 或工厂仅导出静态 Route[]（handler 从 `ctx` 参数拿依赖，工厂本身无参）——优先后者，保持 `Route[]` 静态可组合。

### 3.3 端点实现要点（细则以设计文档 §3 / §5 为准）

- **uploads**：`copyToUploads` 逐项收集成功/失败，部分成功 201；`contextNote` 返回不注入；sessionId 校验经 `deps.sessionStore`（不存在 404）。
- **config**：读走 loader 合成配置 + `maskSecretsDeep` 遮蔽；写走 `setByKey`+`updateScope` / `deleteScopeKey`；`api.*` 键变更响应附 `restartRequired: true`。
- **tools**：registry 快照直读；`PATCH /tools/:name` 落盘写法与 [tools-command L110](file:///d:/trae_workspace/loop-agent-command/src/commands/tools-command.ts#L110) 同（`configWriter.updateScope` 写 `tools.disabled`）+ 运行时 registry 同步。
- **models**：`buildUsePartial`（已导出）+ `updateScope`；同名 409、删当前使用中 409；`test` 端点发最小补全。
- **mcp**：先 `updateScope` 落盘再 `mcpManager.connect`；删除先 disconnect 再 `deleteScopeKey`；连接失败 502（配置已落盘，响应附 status）；`reload` 返回 `{reconnected, failed}`。
- **skills**：直调 skill upload/remove 独立模块（校验/复制/防穿越复用）；同名未 `overwrite` 409；`reload` 走 `skillLoader`。
- **memory**：各 manager 直调；`dream` 返回 202 异步；`init` 幂等。
- **vision / doctor / status**：轻量快照；doctor 诊断项从 [doctor-command.ts](file:///d:/trae_workspace/loop-agent-command/src/commands/doctor-command.ts) 补 export 复用；检测项失败不失败端点（诊断语义）。
