## 一、任务目标需求

### 1.1 背景（痛点）

内置工具在 WebUI 对话流中已具备完整定制展示（20261022-001 中文化、20261024-001 卡片内聚式重设计）：中文工具名 + 16px 线性 SVG 图标 + 语义摘要 + 中文参数标签 + 失败原因直写副标题。

MCP 工具则完全没有：卡片标题是 `server__tool` 英文原名、图标恒为齿轮、参数表列英文键、副标题退化为紧凑 JSON。在同一会话里内置工具与 MCP 工具并列出现时观感割裂，且用户无法从卡片读懂「这次到底调了什么」。

根因不在前端——前端 `tool-meta.ts` 是合理设计的静态白名单；**真正的问题是后端在适配 MCP 工具时把协议里的展示元信息全丢了**，前端拿不到任何可用的中文素材（详见 1.2）。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| MCP 展示名 `title` | `adapter.ts` `adaptMCPTool()` 只取 `name/description/inputSchema`，`title` 未读 | **缺失** |
| `annotations.title` | 同上，`annotations` 整体未读 | **缺失** |
| 参数中文说明 | `inputSchema` 原样透传为 `parameters`，但前端 `toolParamRows()` 只按内置 `TOOL_META.params` 查中文，MCP 工具查不到 | **后端有数据、前端没用** |
| `Tool` 接口承载元信息 | [file:///D:/trae_workspace/loop-agent-command/src/types.ts](file:///D:/trae_workspace/loop-agent-command/src/types.ts) `Tool` 仅 `name/description/parameters/execute` | **无位可放**（决定走侧表，D9） |
| 元信息出口端点 | [file:///D:/trae_workspace/loop-agent-command/src/api/handlers/mcp.ts](file:///D:/trae_workspace/loop-agent-command/src/api/handlers/mcp.ts) 仅 `viewServer` 返回工具名级信息 | **缺失** |
| 前端 MCP 展示分支 | [file:///D:/trae_workspace/loop-agent-command/webui/src/tool-meta.ts](file:///D:/trae_workspace/loop-agent-command/webui/src/tool-meta.ts) `TOOL_META` 13 项白名单，未命中落 `FALLBACK_META`（gear + 英文名 + 空摘要） | **缺失** |
| 服务端中文素材可用性 | 实测 `atlasGraphMcp` 24 个工具 `description` 与参数描述**已是中文**；`parallel-search` 为英文长文 | **一半可直接用，一半需翻译** |
| 前缀缓存稳定性 | [file:///D:/trae_workspace/loop-agent-command/src/tools/registry.ts](file:///D:/trae_workspace/loop-agent-command/src/tools/registry.ts) `toOpenAITools()` 白名单映射 + `canonicalize()` | **必须逐字节保持** |
| 内置工具单测基线 | `tests/` 内 `toolDisplay/toolParamRows/toolSummary` 相关约 36 例 | **必须全部保持通过且行为不变** |

### 1.3 任务目标

1. **后端采集**：新增 MCP 展示元信息采集，完整读取 `title`、`annotations.title`、`inputSchema.properties[*].description`、`required`，产出 `McpToolMeta`。
2. **展示名解析**：按 `title` → `annotations.title` → LLM 翻译 → 名字分词美化 → 原名 的顺序解析中文展示名，解析在后端一次完成并固化（D1/D2）。
3. **LLM 翻译兜底**：MCP 连接成功后**后台异步批量**翻译缺失项，不阻塞注册与对话；结果按内容指纹持久化缓存（D4–D7）。
4. **元信息出口**：新增 `GET /mcp/tool-meta`，回传元信息 + 翻译状态汇总，失败可观测（D14）。
5. **前端展示**：`tool-meta.ts` 增加 MCP 分支，使 ToolCard/LiveStatus 上的 MCP 工具获得中文名 + 语义图标 + 来源 server 徽标 + 中文参数标签 + 语义摘要（D10–D12）。
6. **成本与缓存护栏**：`tools.mcpTranslate` 配置段默认开启但可关；描述已是中文时跳过 LLM（D3/D13）。
7. **零回归**：`toOpenAITools()` 输出逐字节不变；内置 13 工具展示行为逐字节不变。

### 1.4 设计约束

| 约束 | 说明 |
| --- | --- |
| **前缀缓存不可破** | 元信息绝不进入 `Tool` 接口与 `toOpenAITools()`；本任务所有新增字段走旁路（D9） |
| **不阻塞主链路** | 翻译全程异步；MCP 连接、对话流式渲染、首屏挂载均不等翻译 |
| **零新依赖** | 复用 `LLMClient.chat()`、`node:crypto`、`node:fs`；前端复用既有 `ToolIconKey` 与内联 SVG |
| **纯函数可测** | `webui/src/mcp-tool-meta.ts` 零 DOM、零 vue 依赖，便于 root vitest 直接断言（D10） |
| **失败可观测** | 翻译失败不得静默；状态与原因回传并在 MCP 页可见（D14） |
| **命名规则不动** | `server__tool` 生成规则不变（影响 `tool_calls` 回传与存量会话） |
| **三平台兼容** | 缓存路径用 `node:path`/`os.homedir()`，不硬编码分隔符 |

### 2.2 关键设计决策

> 完整取舍说明见 [设计方案第四节](../designs/设计方案-20261104-001+MCP工具展示元信息与翻译.md)。此处列可确认判断项。

- **D1 展示名优先级**：`title` → `annotations.title` → LLM 翻译 → 名字分词美化 → 原名；解析在后端一次完成并固化进 `McpToolMeta.zhName`，前端只做末位兜底。
- **D2 title 双源**：顶层 `title` 与 `annotations.title` 都认、顶层优先（实测 26 个工具顶层命中 0、annotations 命中 2，只认任一方都会漏）。
- **D3 中文描述不翻译**：描述含 CJK 时本地提炼短名，不调 LLM；`mode: 'always'` 可强制全翻。
- **D4 异步触发**：连接成功后 `void` 后台跑，不 `await`、不阻塞注册与对话。
- **D5 按 server 批量**：一次 LLM 调用返回整个 server 的 JSON map；单批 ≤60 工具、≤12000 字符，超出切批串行。
- **D6 复用激活模型**：用 `models.active` 的 profile 三元组，不新增模型配置项。
- **D7 内容指纹缓存**：`sha256(server\0tool\0title\0description\0JSON(paramDesc))` 前 32 位为键，落 `~/.loop-agent/mcp-meta.json`，LRU 500 条。
- **D8 不做用户别名**：列演进项，本期不做编辑 UI。
- **D9 元信息走侧表**：不扩 `Tool` 接口、不进 `toOpenAITools()`，前缀缓存逐字节不变。
- **D10 前端分层**：纯注册表 `mcp-tool-meta.ts`（零 vue/DOM）+ 拉取层 `mcp-tool-meta-loader.ts`（`shallowRef` bump `metaRev`）。
- **D11 图标关键词词典**：工具名 + 参数名匹配 → 复用内置 `ToolIconKey`，未命中 `gear`。
- **D12 来源徽标 + 截断**：标题区显示 server 名小徽标；中文名超 14 字截断并保留原文 `title`。
- **D13 配置段**：`tools.mcpTranslate = { enabled: true, mode: 'auto', timeoutMs: 20000, maxToolsPerBatch: 60 }`，默认开启、可关。
- **D14 失败可观测**：端点回传 `translate` 状态与 `translateError`，MCP 页显示「已翻译 N/M」，日志统一打点。
- **D15 不预翻译**：只为**已连接** server 采集与翻译，断开即清理。

## 三、任务详细设计

### 3.1 后端 `src/tools/mcp/meta.ts`（新增）

```ts
/** MCP 工具展示元信息：只服务 UI，永不进入 toOpenAITools()（D9） */
export interface McpToolMeta {
  fullName: string;              // server__tool
  server: string;
  tool: string;
  title: string;                 // title → annotations.title → ''（D2）
  description: string;
  paramDesc: Record<string, string>;
  required: string[];
  zhName: string;                // '' = 未取到（D1）
  zhParams: Record<string, string>;
  nameSource: 'title' | 'cjk' | 'translate' | 'none';
  translate: 'idle' | 'pending' | 'done' | 'failed' | 'skipped';
  translateError?: string;
}

/** 从原始 MCP tool 采集元信息（纯函数，零 LLM） */
export function collectMcpMeta(
  serverName: string,
  tools: Array<{ name: string; title?: string; description?: string;
                 annotations?: { title?: string }; inputSchema?: Record<string, unknown> }>,
): McpToolMeta[];

/** CJK 检测：命中任一 CJK 区间即判定为中文描述（D3） */
export function hasCjk(text: string): boolean;

/** 从中文描述本地提炼短名：按标点/长度截断（D3） */
export function distillZhName(desc: string): string;

/** 指纹：sha256(server\0tool\0title\0description\0JSON(paramDesc)) 前 32 位（D7） */
export function metaFingerprint(m: McpToolMeta): string;
```

**边界与错误处理**

| 场景 | 行为 |
| --- | --- |
| `inputSchema` 缺失/非对象 | `paramDesc = {}` / `required = []`，不抛错 |
| `properties[k]` 无 `description` | 该键不进 `paramDesc`（前端用美化键名） |
| `description` 为空 | `distillZhName` 返回 `''` → 走翻译或美化 |
| `title` 为空白串 | 视为无 title（`trim()` 后判空） |

### 3.3 后端 `src/tools/mcp/translator.ts`（新增）

```ts
export interface TranslateOptions {
  timeoutMs?: number;        // 默认 20000
  maxToolsPerBatch?: number; // 默认 60
  model?: string;            // 默认取激活 profile 的 name
}
export interface TranslateOutcome {
  translated: number; failed: number;
  errors: string[];
}

/**
 * 批量翻译一个 server 的缺失展示名（D5）。
 * 内部单飞：translating 为真时直接返回 {translated:0,...}（D4）。
 * 不抛错：任何异常进 errors，由调用方写入 meta.translate='failed'（D14）。
 */
export async function translateServerMeta(
  llm: LLMClient,
  metas: McpToolMeta[],          // 仅含 translate==='pending' 的项
  cacheFile?: string,
  opts?: TranslateOptions,
): Promise<TranslateOutcome>;
```

**输入构造与裁剪**（§6.2 of 设计方案）：`description` 截 240 字符、`paramDesc[k]` 截 80 字符、每批 ≤60 工具。

**输出解析容错顺序**
1. 直接 `JSON.parse(content)`
2. 剥离 ```` ```json ```` / ```` ``` ```` 围栏后重试
3. 截取首个 `{` 到末个 `}` 后重试
4. 全失败 → 该批记 `failed`，`translateError` 保留原文前 200 字符

**部分成功**：map 缺哪个工具就只让哪个保持 `zhName=''`，不整批覆盖。

### 五-2、实施与方案的差异（2026-11-04 真机验证时发现并已修复）

| 差异 | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| **响应式依赖缺失** | 元信息端点已返回 24 条中文名，但浏览器里 MCP 卡片仍显示英文原名、无徽标（`.tsrc` 数 = 0） | `ToolCard`/`LiveStatus` 的 `display`/`iconSvg`/`subtitle`/`rows` 四个 computed 只依赖 `props.card.tool`，而 `toolDisplay()` 读的是模块级注册表（非响应式）。`metaRev` 变化只会让 `ChatView` 的 cards 重算，子组件的 computed 缓存不失效 → 首帧早于元信息到达时永久停留英文名 | 四个 computed 内显式 `void metaRev.value` 建立依赖（组件是 vue 环境，注册表本身仍保持零 vue 依赖） |
| **冷启动时序** | 页面比 MCP 连接更快打开时，首拉得到空表且永不刷新 | `loadMcpToolMeta()` 只在 `main.ts` 挂载时拉一次 | 改为「空表自动重试」：`tools.length === 0` 时按 3s 间隔最多重试 5 次（拿到非空即停，`timer.unref()` 不阻止进程退出），`force=true` 会重置计数 |
| **测试文件合并** | 计划中的 `mcp-meta-store.test.ts` / `mcp-translator.test.ts` 未单独建 | 三模块共用同一批夹具与临时目录，拆开会产生重复 setup | 合并进 `tests/mcp-tool-meta.test.ts`，用例数不减（含缓存/翻译全部分支） |
