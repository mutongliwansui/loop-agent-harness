## 一、任务目标需求

### 1.1 背景（痛点）

对话区底部输入坞 `.composer` 功能齐备，但视觉与交互仍是功能直出。原型阶段已用 headless Chrome 真实渲染取证（1600×1000，FilesView 展开时对话区仅 462px），确认 6 条症状：

| # | 症状 | 实测证据 |
|---|---|---|
| ① | 图标体系割裂 | composer 内嵌 SVG 数量为 **0**；📎（U+1F4CE）、🔔（U+1F514）、`■`、`✕` 全为 emoji/字符，与 FilesView、ToolCard 已统一的内联 SVG 体系冲突；深色下 emoji 彩色与品牌绿抢色 |
| ② | 同行三按钮三套权重 | attach（灰边白底 48px 承载 emoji）、发送（绿底白字 66px）、停止（红边描边）并列无主次；窄容器下文字按钮吃掉约 15% 宽度，textarea 仅剩 288px |
| ③ | 输入框不增高 | `height:44px` + `resize:none`，写入 6 行后高度仍 44px、内部 `scrollHeight` 146px 滚动，与「发长需求」主场景冲突 |
| ④ | 底栏三类信息等权平铺 | 「流式」（技术开关）+「发送后自动附带 📎 文件的 contextNote」（说明文字）+「🔔声音开·通知开」（设置入口）并列；`--muted` 11.5px 对比偏低 |
| ⑤ | 描边线中套线 | `.composer` 上沿 1px 与 textarea 自身 1px 叠加；附件 chip 浮于输入框之外无归属 |
| ⑥ | **模型无法按会话指定** | 现状只能在 `#/models` 页全局切换（`PUT /model` 写盘并同步 `model.*`，影响所有会话与 CLI）；对话中想「这一次换 glm」无入口 |

**检索结论（2026-10-25）**：查 openai-node 文档与源码确认，`RequestOptions` 内只有 `defaultBaseURL` 且位于 `src/internal/`，由客户端自身注入，**没有公开的按次 `apiKey` 覆盖**；官方 per-request 选项仅 `timeout`/`maxRetries`/`headers`/`query`/`signal` 等。故「一个客户端 + 按次换凭据」不可行走 SDK 内部字段，必须按 `(apiKey, baseUrl)` 维护客户端缓存。来源：[openai-node configuration.md](https://github.com/openai/openai-node/blob/main/docs/configuration.md)、[request-options.ts](https://github.com/openai/openai-node/blob/master/src/internal/request-options.ts)。

## 二、方案设计

### 2.1 总体思路

```
前端 ChatView.vue
  ├─ 工具行 model pill ──click──> 向上面板（数据源 GET /models）
  │        │ 选择 alias（或「跟随全局」复位）
  │        ▼
  │   modelAlias（本地 ref，随会话切换重载）
  │        │
  └─ send() ──POST /sessions/:id/messages { message, stream:true, modelAlias }──┐
                                                                              │
后端 handleMessage (src/api/handlers/messages.ts)                              │
  ├─ modelAlias 缺省/空 ──────────────────────> 不注入，走全局 config           │
  └─ 有值 ──> 校验 alias 存在 & apiKey 非空（D11）                             │
              └─> profile {name, baseUrl, apiKey}                             │
                   └─> runOptions.model / baseUrl / apiKey  (D4)              │
                                                                              │
ReActAgent.run() (react-agent.ts)                                             │
  ├─ 主对话调用：chat/chatStream 传 { model, temperature, baseUrl, apiKey }(D6)│
  └─ 辅助调用（记忆去重/压缩/摘要）：仅 { model: 全局, temperature: 全局 }      │
                                                                              │
LLMClient (src/llm/client.ts)                                                 │
  getClient(apiKey?, baseURL?)                                                │
    ├─ 未传 ──> 全局 config 单例（行为不变）                                   │
    └─ 传入 ──> Map<`${apiKey}\0${baseURL}` 缓存，命中复用，超限淘汰 (D5)      │
                                                                              │
会话元数据：SessionMeta.modelAlias（切换时单独写，GET /sessions/:id 回读）(D7)  │
```

### 2.2 关键设计决策

**D1 落地范围＝前端输入坞 + 后端最小透传，不做「大而全」重构**
改动收敛在 `ChatView.vue` 的 composer 段、`chat-stream.ts` 的发送入参、`types.ts`/`llm/client.ts`/`react-agent.ts`/`api/handlers/messages.ts` 的凭据链路、`session` 的一个可选字段。不动 ToolCard / FilesView / SSE 事件定义。
*否决*：顺手把模型选择做成全局能力（会牵动 `#/models` 与 CLI，超出本需求）。

**D2 「流式」复选框删除，`stream` 恒为 `true`**
前端删 `streamChk`，`send()` 固定传 `stream: true`；头部「SSE 流式/非流式」提示改为固定文案（或直接移除该提示）。`sendMessage` 保留 `stream` 入参与非流式分支——协议与测试仍需要。
*否决*：把复选框藏进「更多」菜单（仍是技术开关暴露，没解决症状④）。

**D3 「通知」按钮删除，两开关迁入设置页 `ConfigView` 的「界面偏好」卡片（用户 2026-10-25 选定 B）**
删除 composer 内的 `notifyPopOpen` 浮层与 🔔 按钮；保留 `notify.ts` 不动（`chat-stream.ts` 的完成提醒调用零改动）；在 [`ConfigView.vue`](file:///D:/trae_workspace/loop-agent-command/webui/src/views/ConfigView.vue) 的 sections 卡片前新增「界面偏好」卡片，复用 `getNotifySettings/setNotifySettings` 与权限申请逻辑，承载「系统通知」「提示音」两个开关。
*否决*：只删 UI 不搬（开过的用户改不了，只能清 localStorage）；*否决*：直接删 `notify.ts`（会让已配置用户静默失去提醒，且 `chat-stream` 要改，风险大于收益）。
*实现注意*：通知偏好存 localStorage、不属于 `GET /config` 的 section 体系，故该卡片必须与配置表格分离、不参与 scope 写入；`notifySecure()`（https/localhost 判定）的降级文案随卡片一起搬走。

**D4 模型覆盖走请求级入参，绝不改全局激活**
`POST /sessions/:id/messages` 新增可选 `modelAlias`；后端从 `configLoader.load().config.models.profiles[alias]` 取 `{name, baseUrl, apiKey}` 注入 `AgentOptions`。
*否决*：前端调 `PUT /model`（写盘并同步 `model.*`，污染其它会话与 CLI）。

**D5 LLM 客户端按 `(apiKey, baseUrl)` 键控缓存**
`ChatOptions`/`AgentOptions` 增可选 `baseUrl`/`apiKey`；`getClient(apiKey?, baseURL?)`：未传→现有全局单例逻辑原样保留；传入→`Map` 缓存，key 为 `apiKey + '\0' + baseURL`，上限 8 条，超限清空最旧。**这是本任务唯一必须动 LLM 层的点**。
*否决*：复用 SDK 内部 `defaultBaseURL`（非公开契约，升级即碎）；*否决*：继续单槽缓存（WebUI 多会话并行选不同模型会互相踢缓存，每次调用都重建 client）。

**D6 模型覆盖只作用于主对话调用，辅助调用仍用全局模型**
`react-agent.ts` 中 `streamLLM`/主 `llm.chat` 传会话凭据；`createLLMAdapter`（记忆去重、压缩、摘要）继续用全局 `cfg.model`。
*否决*：全部跟随会话模型——一次选择会把后台记忆任务也切到另一供应商，成本与可用性风险不可控，且这类调用对模型能力要求低。

**D7 `modelAlias` 存会话元数据，且只在切换时单独写**
`SessionMeta` 与 `SessionData` 增可选 `modelAlias`；新增最小写入方法（如 `setSessionModelAlias(id, alias)`），**不**把它塞进每轮 `updateSession`。理由：`updateSession` 已含压缩归档重建逻辑，且已知存在并发写盘竞态，减少写入口径可降低风险。
*否决*：仅存前端 localStorage（换浏览器/设备即丢，CLI 也读不到）。

**D8 模型列表复用 `GET /models`，进入会话时懒加载一次**
不新增端点；`apiKey` 已遮蔽，前端无需也不应拿到明文。请求失败时 pill 降级为「模型」文案并禁用，toast 提示，不阻塞发消息。
*否决*：新增 `/models/lite`（重复端点）。

**D9 状态约束与浮层互斥**
生成中（`streaming`）pill 置灰不可点（`opacity:.5` + `pointer-events:none`）；模型面板与上传浮层互斥；Esc / 点外部关闭；外部点击监听需忽略控制条自身点击。
*教训直接入档*：原型调试时面板「点开即关」——`document` 点击监听与触发按钮在同一次事件冒泡里互相抵消，落地必须避开（已有回归断言）。

**D10 令牌映射按应用真实令牌，零新增**
原型 `--r-lg`→`--radius-card`(12px)、`--shadow-1`→`--shadow-card`、`--panel-2`→`--bar-bg`（浅色 #fbfcfd／深色 #1f242b，与原型取值一致）、浮层阴影 `--shadow-pop`、深色卡描边用 `--line`。容器查询两档：≤440px 隐快捷键提示、≤380px 收内边距且只省略 alias 文本。
*否决*：为对齐原型而新增 `--r-lg` 等令牌（会出现第三套视觉语言）。

**D11 非法 alias 明确报错，不静默回落**
`modelAlias` 有值但 profile 不存在 / `apiKey` 为空 → 返回 `bad_request` 并列出可用别名。理由：静默回落会让用户「以为换了其实没换」，比报错更糟。
*否决*：回落全局 + warning（流式下 warning 易被忽略）。

**D12 验收以真实渲染为准，断言口径与原型探针一致**
后端用 vitest 覆盖凭据缓存、handler 解析、meta 持久化；前端用 headless Chrome + CDP 打 vite dev 的真实组件，沿用原型 65 条断言的分类（结构/自增高/交互/状态/模型/宽度/深色/矩阵），并额外断言「模型 pill 显示的 alias 与后端实际收到的 modelAlias 一致」。
*否决*：只跑单测（本任务一半是视觉与交互，单测覆盖不到）。

### 3.5 边界与错误处理

| 场景 | 行为 |
|---|---|
| `modelAlias` 省略 / 空串 | 不注入，走全局 config（旧行为，CLI 等价） |
| `modelAlias` 不存在 | 400 `bad_request`，消息列出已登记别名 |
| profile `apiKey` 为空 | 400，提示用 `PUT /config/models.profiles.<alias>.apiKey` 补 |
| `GET /models` 失败 | pill 降级为「模型」、禁用、toast；发消息不受影响 |
| 生成中点击 pill | 无响应（`pointer-events:none`），不弹 toast（避免干扰） |
| 会话中途换模型 | 只影响后续消息，已产生的上下文保留（面板脚注已声明） |
| 深色主题 | 卡底 `--bar-bg`、描边 `--line`、面板不透明（不穿透消息流） |

**测试结果**

**探针调试中修掉的 4 类问题（记录以备复用）**

1. **Esc 未关面板导致级联失败**：面板开着时按 Esc 未生效，后续 4 条断言全部连带失败。根因是外部点击监听与 Esc 监听的关闭顺序，修正后单点收敛。
2. **hex 与 rgb 直接比较造成 4 条假失败**：`getComputedStyle` 返回 `rgb(31, 36, 43)`，令牌是 `#1f242b`，字符串不等但颜色相同。新增 `normColor()` 归一化后比较。
3. **SVG 阈值未考虑「无附件」态**：断言写死 ≥5，但无附件时附件 pill 的图标不存在，实际只有 4 个（paperclip/chip/chevron/arrow）。阈值改为 ≥4 并在名称中说明。
4. **容器查询按「容器宽度」而非「视口宽度」生效**：1600 视口下 FilesView 展开把对话区挤到 **462px**，1024 视口下仅 **270px**。原断言用视口宽度推期望档位，冤枉了正确的 CSS（误报 2 条）。改为按实测容器宽度判定档位，并把 `compW/innerW` 写进断言详情便于排查。

**探针过程中发现并修复的真实缺陷（1 个）**

- `persistModelAlias()` 只发 `PUT /sessions/:id/model`，**未同步内存中的 `workspaces` 列表**。后果：同页内「切到别的会话再切回」时，`selectSession` 仍从旧 meta 取值，pill 退回全局——用户会以为选择丢了（服务端其实已存，刷新才恢复）。已在 PUT 成功后同步 `s.modelAlias`，并新增 3 条断言（会话一选 glm → 切会话二不串味 → 切回还原 glm）锁住该回归。
