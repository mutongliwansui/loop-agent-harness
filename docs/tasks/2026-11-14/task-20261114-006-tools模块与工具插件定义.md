## 一、任务目标需求

### 1.1 背景（痛点）

`core` 解决「插件长什么样、怎么挂、怎么撤」，`main` 解决「挂哪些、什么顺序、存哪、重启怎么还原」，`llm` 解决「一个大模型服务商该长什么样」。**但「一个工具」在这套体系里还没有契约**，具体表现为五处硬耦合：

1. **契约是纯 interface，不可继承**：`src/types.ts:161` 的 `Tool` 只有 `name`/`description`/`parameters`/`execute`/`timeoutMs` 五个字段，实现方式只能是对象字面量。想加一个「所有工具都该有」的公共能力（参数校验、结果归一、耗时统计、错误包装），没有任何可复写的落点——只能每个工具各写一遍，或在 runner 里 if/else。

2. **注册中心是模块级单例**：`src/tools/registry.ts:229` 是 `export const registry = new ToolRegistry()`，内部一个 `Map<string, Tool>`（`:27`）。**没有归属追踪、没有成组撤销**：某个来源的工具想整批摘掉，只能自己遍历 name 逐个 `unregister()`；`diagnose()` 这类能力对它完全不可见（这正是需求 20261114-003 登记的「17 处 `export const x = new X()`」同源问题）。

3. **重复注册直接抛裸 Error**：`registry.ts:42` 是 `throw new Error('工具 X 已注册，不可重复注册')`——无稳定 `code`、无归属信息，宿主既无法程序化识别「是冲突还是别的错」，也无法在诊断报告里定位是谁抢注的。

4. **超时与错误归一写死在执行器**：`src/tools/runner.ts:65` 的 `options.timeout ?? tool.timeoutMs ?? 30000`、`:107` 的 `工具执行失败: ${msg}` 都固化在 `ToolRunner` 里。契约层无法声明「我这个工具默认给多久」「我的失败长什么样」，第三方工具只能被动接受宿主口径。

5. **装配靠人肉编排**：`src/tools/index.ts` 逐个 `registry.register(...)` 12 个内置工具，再按 `shouldRegisterOcrTools()` / 视觉开关条件注册，MCP 工具由 `registry.registerMCPServer()` 在运行期动态适配。**新增一个工具 = 改主工程代码并改装配代码**，无法以「加一个插件」的方式扩展，「默认实现」与「用户自定义实现」都没有位置。

用户原话：「新建 tools 子模块，tools 依赖 core 模块，tools 模块基于插件基础上定义工具插件定义，供后续默认实现和用户自定义实现继承。」

关键信息拆解：

- 「新建 tools 子模块」→ 与 `core/`、`main/`、`llm/` 平级的独立包；
- 「tools 依赖 core 模块」→ `dependencies` 只允许 `@loop-agent/core`；
- 「基于插件基础上定义」→ 产物必须是 **core 可识别的插件**，能交给 `main` 的 `PersistentPluginRegistry` 挂载；
- 「供后续默认实现和用户自定义实现**继承**」→ 契约形态是**可继承的抽象基类**，不是纯 interface；「默认实现」属后续工作，**本期不做**。

### 1.2 现状梳理

### 1.3 任务目标

1. **新建独立子包 `tools/`**（`@loop-agent/tools`），与 `core/`、`main/`、`llm/` 平级；`dependencies` 只允许 `@loop-agent/core`，零三方运行时依赖。
2. **自持领域类型**：工具规格、参数 JSON Schema、执行上下文、执行结果、行为声明、展示元信息，全部定义在 tools 包内，命名与 `src/types.ts` 解耦。
3. **定义可继承的双层契约**：
   - `ToolBase`（单个工具）：抽象 `execute()` + 模板方法 `invoke()` 统一「参数校验 → 执行 → 结果归一」；
   - `ToolProvider`（一个插件提供多个工具）：覆盖 MCP server 这类集合式注册。
   默认实现与用户自定义实现都通过 `extends` 落地。
4. **把提供者编译成 core 插件**：`defineTools(def)` 返回 `PluginObject`；`defineToolsFactory(def)` 返回接 `options` 的工厂；`installTools()` 提供目录服务 `tools:registry`；每个提供者以 `tools:provider:<id>` 占一个服务 key；挂载/卸载由 core Fiber 自动托管与成组撤销。
5. **注册期前置校验**：工具名（`^[A-Za-z0-9_-]{1,64}$`）、必填字段、`parameters` 必为 `object` 型 JSON Schema、同目录内重名、同 id 提供者重复挂载——全部在挂载期同步炸掉，不留给模型 API 返回 400。
6. **保住输出确定性**：`toToolDefs()` 按 name 排序 + 参数键序规范化，继承 `toOpenAITools()` 已实证的前缀缓存不变量。
7. **错误族与事件表齐备**：`ToolsError` 继承 `CoreError`；事件 `tools/registered`、`tools/unregistered`、`tools/invoke`、`tools/result`、`tools/error` 供宿主观测。
8. **装配期与执行期分离**：core `Context`（装配期）与 `ToolInvokeContext`（执行期：workspaceRoot / sessionId / callId / signal）严格分开，插件对象**不持有任何执行期状态**。

### 1.4 设计约束

| 约束 | 来源 | 落地要求 |
|---|---|---|
| **只依赖 core** | 用户原话「tools 依赖 core 模块」 | `tools/package.json` 的 `dependencies` 只有 `@loop-agent/core` |
| **零反向依赖** | 沿用 core/main/llm 的边界范式 | `tools/src/**` 不 import `src/`、`webui/`、`desktop/`、`main/`、`llm/` 任何代码；`boundary.test.ts` 断言锁死 |
| **本期零接入 `src/`** | 沿用「先搭骨架、渐进迁移」 | 不改 `src/` 任一行；不替换 `src/tools/registry.ts`；不接 `initRuntime`；不声称已替代现有工具层 |
| **只收 ESM，单产物** | 沿用 core 的 Q12 定案 | `tsup` 只 `format:['esm']`；`exports` 单分支 `types`+`import`+`default`；产物恰好 3 文件 |
| **strict 无 `any`** | 项目规范 | 上游未知报文用 `unknown` + 显式收窄 |
| **不引入三方校验库** | 工程默认约束 | JSON Schema 校验手写，不引 zod/ajv |
| **跨平台** | 工程默认约束 | 本包无路径解析、无外部命令，天然跨平台；测试不写死路径分隔符 |
| **契约一次写对** | 教训（20261114-003 的 Q12 反复三轮） | 接口签名在 P0 定稿，P1/P2 只允许「加法式」演进 |
| **不破坏模型前缀缓存** | `src/tools/registry.ts:108-123` 注释已明示的既有不变量 | `toToolDefs()` 必须排序 + `canonicalize`，见 D12 |

一句话分层：**core 管机制，main 管装配，llm 管模型契约，tools 管工具契约，实现管具体**。

### 2.2 关键设计决策（D1–D14 摘要）

| 编号 | 决策 | 硬理由 / 否决项 |
|---|---|---|
| D1 | 本包只做「工具契约 + 插件编译器 + 目录服务」，**不做任何工具实现** | 用户明确「供**后续**默认实现…继承」；先搬 12 个内置工具会让契约被具体实现反向塑造。否决「本期顺带迁移 `src/tools/`」 |
| D2 | 领域类型在包内自持，**不依赖 llm**；与 `LlmToolDef` 结构对齐、由适配函数衔接 | tools 与 llm 是平级领域包，依赖会形成 `tools → llm → core` 三层链；否决「让 llm 反向依赖 tools」 |
| D3 | 服务 key：一个目录服务 + 每提供者一个 key | `core/src/service.ts:47` 重复 key 抛 `ServiceConflictError`；否决「单 key 存 Map」（丢归属追踪与成组撤销） |
| D4 | 双层契约：`ToolBase` + `ToolProvider`，两者都可 `extends` | 只有单工具契约时 MCP/成组场景只能用户手写循环与撤销；抽象类才能承载模板方法与只读访问器 |
| D5 | 双导出 `defineTools()` + `defineToolsFactory()` | `main` 的 `defaultLoadPlugin` 里 **`options` 唯一通道是外层工厂函数**，只给 A 会让清单 `options` 被静默丢弃 |
| D6 | `invoke()` 模板方法固化「校验→执行→归一」，`execute()` 唯一抽象方法（`protected`） | 现状校验与失败文案散在 runner 与各工具；`protected` 防宿主绕过校验 |
| D7 | 参数校验手写 JSON Schema 子集，不引三方库 | 零新依赖；超出子集的关键字**跳过而非报错** |
| D8 | 工具名约束 `^[A-Za-z0-9_-]{1,64}$`、禁 `__` 前缀，**注册期同步校验** | 三大厂商 function name 最低公共上限为 64 且不容 `.`；`. `会每轮请求 400 而根因在注册处 |
| D9 | 行为声明对齐 MCP `ToolAnnotations` 四 hint（**悲观默认**）+ 可选 `display` 段 | 已有事实标准；MCP 明示 annotations 只是 hint，**不是权限** |
| D10 | 结果结构化 `ToolResult{text,isError?,structured?}`，兼容纯字符串 | 前端现状靠正则猜失败；`text` 不叫 `content` 以免与 llm 消息内容混淆 |
| D11 | 目录内重名 → 显式冲突错误（带双方 `providerId`），不覆盖 | 静默覆盖会导致「注册了新工具却调到旧实现」，比崩溃更难查 |
| D12 | `toToolDefs()` 按 `name.localeCompare` 排序 + `canonicalize()` | 工具定义是请求前缀，键序抖动会让 provider 前缀缓存整体失效（成本/延迟上升且无报错） |
| D13 | MCP 类集合工具用 `ToolProvider` 承载，命名空间前缀由**适配器**负责 | 前缀策略属装配决策；否决「在 tools 包内置 MCP 适配器」（会把协议依赖拉进契约包） |
| D14 | 错误族继承 `CoreError`；事件用目录自带 emitter，不用 core 总线 | core `Context` 只暴露 `on()` **无 `emit()`**，插件拿不到 host |

### 3.2 领域类型（`src/types.ts`）

- `JsonSchema`：`Record<string, unknown>`（手写子集）
- `ToolSpec`：`name` / `description` / `parameters` / `annotations?` / `display?` / `timeoutMs?`（缺省 `DEFAULT_TOOL_TIMEOUT_MS = 30_000`，对齐 `runner.ts:65`）
- `ToolInvokeContext`：`signal?` / `workspaceRoot?` / `sessionId?` / `callId?` / `metadata?`（**插件不得持有**）
- `ToolResult`：`text` / `isError?` / `structured?`
- `ToolDefView`：`name` / `description` / `parameters`（与 `LlmToolDef` 结构等价、类型自持）

### 3.3 `ToolBase` 与 `invoke()` 边界

| 场景 | 行为 | `isError` |
|---|---|---|
| `rawArgs` 为 `null`/数组/原始值 | 不调 `execute()`，返回「参数必须是对象」 | `true` |
| 必填缺失 / 类型不符 / enum 越界 | 不调 `execute()`，返回逐条问题清单（最多 10 条） | `true` |
| `parameters` 含不支持的 schema 关键字 | 跳过该关键字，继续校验其余部分 | 不触发 |
| `execute()` 返回 `string` | 包成 `{ text, isError: false }` | `false` |
| `execute()` 返回 `ToolResult` | 原样透传（`isError` 缺省 `false`） | 依实现 |
| `execute()` 抛异常 | 归一为 `{ text: '工具执行失败: <msg>', isError: true }` | `true` |
| `ctx.signal` 已 abort | 返回「工具已取消」，**不调** `execute()` | `true` |

### 3.4 `ToolProvider` 约定

提供者**不做**命名空间前缀（归适配器 D13）、**不做**去重（归 registry D11）、**不做**排序（归 `toToolDefs()` D12）。`create(options)` 允许异步（MCP 握手、读磁盘清单）；`dispose?()` 异常被吞，不阻断撤销链。

### 3.5 `ToolRegistry` 与 `installTools`

`list()` / `get()` / `require()` / `count()` / `register(tool, opts?): Disposer` / `invoke(name, rawArgs, ctx?)` / `toToolDefs()` / `on(event, listener): Disposer`。

`installTools()` → `ctx.provide('tools:registry', createToolRegistry())`，重复安装把 `ServiceConflictError` 翻译为 `TOOLS_REGISTRY_EXISTS`（与 `installLlm()` 同构）。

### 3.6 错误族与事件

| `code` | 触发时机 |
|---|---|
| `TOOLS_INVALID_NAME` | 工具名不合 `^[A-Za-z0-9_-]{1,64}$` 或含 `__` 前缀 |
| `TOOLS_CONFIG_INVALID` | `description` 为空、`parameters` 非 object schema、`id` 含 `:` |
| `TOOLS_DUPLICATE` | 目录内重名（带双方 `providerId`） |
| `TOOLS_PROVIDER_EXISTS` | 同 id 提供者重复挂载 |
| `TOOLS_NOT_FOUND` | `require(name)` 未注册 |
| `TOOLS_ARGS_INVALID` | 参数校验失败（仅 `invoke()` 内部构造，不外抛） |
| `TOOLS_REGISTRY_MISSING` | `getToolRegistry()` 时未安装 |
| `TOOLS_REGISTRY_EXISTS` | 重复 `installTools()` |
| `TOOLS_EXEC_FAILED` | `execute()` 抛错的 cause 包装 |

事件 5 个：`tools/registered`、`tools/unregistered`、`tools/invoke`、`tools/result`、`tools/error`。

### 3.7 `defineTools` / `defineToolsFactory` 的 apply 流程

1. `getToolRegistry(ctx)` 取目录；
2. 解析 `tools`（数组 / `provider.create(merged)` / 工厂调用）；
3. 逐个工具同步校验——**任一个不合法即整批失败**（`apply` 抛错 → Fiber `FAILED`），不留半挂载状态；
4. `ctx.provide('tools:provider:<id>', providerFacade)`；
5. `ctx.effect(() => batchRegister(tools, id), 'tools:provider:<id>')` 批量登记，卸载逆序撤销；
6. 若有 `dispose`，`ctx.effect(() => () => provider.dispose?.(), ...)` 兜资源释放。

### 3.8 边界与错误处理

| 边界 | 处理 |
|---|---|
| `create()` 返回空数组 | 允许（挂载成功但 0 工具），记诊断信息，不视为错误 |
| `create()` 抛错 | `apply` 抛错 → Fiber `FAILED`，`diagnose()` 可见 |
| 批量注册中途某工具重名 | 整批失败并回滚已注册项（先收集校验，全通过后落登记） |
| 卸载期 `dispose()` 抛错 | 吞掉并记 `disposeErrors`（core 不变量 3） |
| `toToolDefs()` 时并发注销 | 基于快照遍历，不抛错 |
| 工具名大小写差异（`FileRead` vs `fileRead`） | 视为不同名（大小写敏感，与 MCP/OpenAI 一致） |
| `additionalProperties` 未声明 | 允许多余参数并原样透传给 `execute()` |
