## 一、任务目标需求

### 1.1 背景

后台命令任务与后台子 Agent 任务是两套独立机制：模型查询工具 `commandStatus` 只读命令任务；WebUI 输入区上方的常驻指示器只轮询子任务；两套状态词、会话过滤与停止能力不一致，导致「查不到、看不见、口径不一」。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| 命令任务读模型 | [`background-tasks.ts`](file:///d:/trae_workspace/loop-agent-command/src/tools/background-tasks.ts) `list/get` | 保留，作为聚合数据源 |
| 子任务读模型 | [`subagent-registry.ts`](file:///d:/trae_workspace/loop-agent-command/src/agent/subagent-registry.ts) `list/get` | 保留，补终态淘汰 |
| 模型查询 | [`command-status.ts`](file:///d:/trae_workspace/loop-agent-command/src/tools/command-status.ts) 只查命令任务 | 扩展返回内容 |
| HTTP 查询 | `/background/:id` 与 `/sessions/:id/subagents` 分治 | 新增会话级 `/jobs` |
| 常驻指示器 | [`BackgroundDock.vue`](file:///d:/trae_workspace/loop-agent-command/webui/src/components/BackgroundDock.vue)（原 SubAgentDock）只订阅子任务 | 合并为统一 `BackgroundDock` |
| CLI 查询 | 仅 `/subagent` | 新增 `/jobs` |

### 1.3 任务目标

1. 模型一次 `commandStatus` 能查到当前会话的命令任务与子任务；
2. Dock 同时展示两类任务，命令任务可停止；
3. 统一状态词与会话过滤（当前会话 + 无归属）；
4. 不改两套 registry 的写入、持久化与通知路径。

### 1.4 设计约束

- 只读聚合，不修改 `backgroundTasks` / `subAgentRegistry` 的状态机；
- 原 HTTP 端点、`commandLogs/commandStop`、`/subagent` 命令保持兼容；
- 不新增模型工具，避免 `tools` 数组额外变化；
- 子任务本期不提供单任务停止。

## 三、任务详细设计

### 3.1 `src/background/jobs.ts`

```ts
export type JobKind = 'command' | 'subagent';
export type JobStatus = 'running' | 'done' | 'failed' | 'stopped' | 'lost';

export interface JobSummary { /* 见设计方案 5.1 */ }

export function toCommandJob(t: BackgroundTask): JobSummary;
export function toSubAgentJob(t: SubAgentTaskRecord): JobSummary;
export function listJobs(opts?: ListJobsOptions): JobSummary[];
export function getJob(id: string): JobSummary | undefined;
```

### 3.2 接口

`GET /sessions/:id/jobs?kind=&status=&limit=` → `{ items, run }`；会话不存在返回 404。

### 3.3 工具

`commandStatus`：

- 参数保持 `taskId` 不变（不加 kind，避免工具 schema 预算增长）；
- 不带 `taskId`：返回本会话 + 无归属的最近 5 条；
- 带 `taskId`：命令任务走原详细分支，子任务返回状态/轮次/错误与完成通知提示；
- `commandLogs/commandStop` 对 `sub_` 前缀返回「子任务不支持」提示。

### 3.4 WebUI

- `chat-stream.ts`：新增 `JobTaskVM` 与 `jobsOf()`；轮询 `/jobs`，保留 `run` 状态接管逻辑；
- `BackgroundDock.vue`：两类任务统一列表，kind 徽标，命令任务停止按钮；
- `ChatView.vue`：`SubAgentDock` → `BackgroundDock`。

### 3.5 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| 命令任务 `exitCode=null` | `failed`（信号终止/未知） |
| 命令任务 `orphaned-*` | `lost`，仍允许 stop |
| 子任务进程重启丢失 | 不出现在列表（registry 无记录） |
| `sessionId` 为空的任务 | 作为无归属任务出现在当前会话 Dock |
| `/jobs` 会话不存在 | 404，不返回其他会话数据 |
| 子任务 taskId 传给 commandLogs/Stop | 返回「子任务不支持」而非「任务不存在」 |

### 3.6 演进项（本任务不做）

- 子任务单任务停止 API；
- 统一完成通知注入与卡片；
- 全局任务中心（跨会话视图）；
- 命令任务日志在 Dock 内直接展开。
