## 一、任务目标需求

### 1.1 背景（痛点）

20261107-002 让子 Agent 过程「可见」，但前端只做了最小可用渲染：

1. 工具调用只显示 `tool.name`（英文原名，如 `fileRead`、`grep`）和 `JSON.stringify(args)` 截断 80 字符的原始报文，与对话区既有工具卡片（图标 + 中文名 + 语义摘要）视觉割裂；
2. 思考内容用等宽字体整段铺开，长思考会占据大量纵向空间；
3. 没有成功/失败状态点、没有结果查看入口，用户无法判断某一步是否失败、失败原因是什么；
4. 后台结果卡片（`SubAgentResultCard.vue`）完全没有过程区，只有任务描述和结论；刷新后即使 `m.sub` 已落盘也不会恢复。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| 过程区渲染 | [ToolCard.vue](../../webui/src/components/ToolCard.vue#L208-L241) 内联 `toolArgOf` 直接 `JSON.stringify`；模板 [L417-L445](../../webui/src/components/ToolCard.vue#L417-L445) 只有名称 + 原始参数行 | 抽取独立组件并复用工具元信息 |
| 工具展示映射 | [tool-meta.ts](../../webui/src/tool-meta.ts#L347-L368) 提供 `toolDisplay` / `toolIconSvg` / `toolSummary`，未知工具回退英文名 + 紧凑 JSON | 直接复用，无需后端改动 |
| 思考/结论样式 | `.tsub-think` / `.tsub-final` 均为等宽原文 | 改为弱化引用块 + 结论块 |
| 状态表达 | 只有工具行之前的圆点，失败红/成功绿，无运行中状态 | 增加 running 脉冲点、failed/aborted/interrupted 语义 |
| 后台结果卡片 | [SubAgentResultCard.vue](../../webui/src/components/SubAgentResultCard.vue) 无过程区；[chat-stream.ts](../../webui/src/chat-stream.ts#L388-L412) `parseSubAgentResultCard` 不读 `m.sub` | 卡片补过程区 + 解析恢复轨迹 |
| 落盘轨迹 | `SubAgentTrace` 已随 tool 消息 `m.sub` 与后台卡片 `sub` 落盘 | 数据齐全，纯前端改造 |

### 1.3 任务目标

1. 过程区视觉与对话区工具卡片一致：图标徽标 + 中文工具名 + 语义摘要 + 状态点 + 耗时；
2. 工具结果默认收起，点击工具行展开查看（限高滚动），未知工具回退紧凑 JSON；
3. 思考改为「引用条 + 弱化文本」，默认 3 行截断、可展开；最终结论独立成「结论」块；
4. `running / done / failed / aborted / interrupted` 五种状态都有明确视觉表达，中断保留中断前轨迹；
5. 后台结果卡片补齐同一套过程区，刷新/重进会话后从 `m.sub` 恢复；
6. 默认收起，不增加对话流初始纵向高度。

### 1.4 设计约束

- 零新依赖、零后端协议改动；只消费既有 `SubAgentTrace` 与 `tool-meta.ts` 纯函数；
- 复用现有 CSS 令牌（`--panel/-2`、`--code-bg`、`--line*`、`--text-2`、`--muted`、`--brand/-weak`、`--danger/-weak`、`--mono` 等），不新增颜色令牌；
- 过程区不进入 LLM 历史（既有 `isDisplayOnlyContent` 约束不变）；
- 不引入 Markdown 富文本渲染，结论按纯文本 + 自动换行展示（避免嵌套渲染器复杂度）；
- 移动端窄屏下文本必须可换行、不出现横向滚动。

## 二、方案设计

### 2.1 总体思路

```
SubAgentTrace（内存/落盘）
   │
   ├─ ToolCard（同步 delegate）──┐
   │                              ├─▶ SubAgentProcess.vue（新，共用）
   └─ SubAgentResultCard（后台）──┘        │
                                          ├─ 头部：过程 · N 轮 · N 步 · 耗时（默认收起）
                                          ├─ 迭代分组（第 N 轮）
                                          │   ├─ 思考：引用条 + 3 行 clamp（可展开）
                                          │   └─ 工具行：icon + 中文名 + toolSummary + 状态点 + 耗时
                                          │        └─ 点击展开 result（限高 168px）
                                          └─ 结论 / 错误 / 中断说明
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍 / 被否决项 |
| --- | --- | --- |
| D1 | 抽取独立组件 `SubAgentProcess.vue`，`ToolCard` 与 `SubAgentResultCard` 共用 | 否决继续写在 `ToolCard.vue` 内：后台卡片无法复用，且 `ToolCard` 已 800+ 行 |
| D2 | 工具行复用 `toolDisplay(name)` / `toolIconSvg(name)` / `toolSummary(name, JSON.stringify(args))` | 否决自造中文映射：会与主对话逐渐漂移；未知工具自动回退紧凑 JSON，与既有约定一致 |
| D3 | 工具结果默认收起、点击行展开，限高 168px；工具行保留状态点与耗时 | 否决常驻结果区：7 步过程会变成数千像素长 |
| D4 | 思考用引用条 + 弱化正文，`-webkit-line-clamp:3`，超出显示「展开」 | 否决等宽整段：与正文视觉割裂且占纵向空间；否决折叠每条思考：操作成本高 |
| D5 | 结论统一用「结论」块（`trace.final` 优先，后台卡片回退 `info.answer`）；失败显示错误块，中断显示灰虚线说明块 | 否决复用 `error` 块展示中断：中断不是错误，需要独立语义 |
| D6 | `parseSubAgentResultCard(content, sub?)` 增加可选轨迹参数，`rebuildChatMsgs` 传入落盘消息的 `m.sub` 填充 `SubAgentResultVM.trace` | 否决把轨迹序列化进卡片文本：会破坏 `<subagent_result>` 字段格式与 LLM 过滤规则 |
| D7 | 运行中耗时直接使用 `trace.startedAt` 现算，不额外起定时器 | 否决 1s 定时器刷新：会增加大量组件重渲染；过程事件本身高频，足以刷新 |

## 三、任务详细设计

### 3.1 组件接口

```ts
// webui/src/components/SubAgentProcess.vue
interface Props {
  trace: SubAgentTraceVM;
  /** 卡片级状态（后台卡片可能与 trace.status 不同，例如 interrupted） */
  status?: 'running' | 'done' | 'failed' | 'aborted' | 'interrupted';
  /** 默认是否展开（过程区默认 false） */
  defaultOpen?: boolean;
}
```

- 组件内部状态：`open`（过程区）、`openThink`（思考展开集合，按 `iteration-index` 键）、`openTools`（工具结果展开集合，按步骤下标键）；
- 无 props 变更副作用；`trace` 更新时只追加新行，不重置展开态。

### 3.2 工具行数据映射

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| 图标 | `toolIconSvg(step.name)` | 与主对话 ToolCard 完全一致 |
| 名称 | `toolDisplay(step.name).name` | 中文名；未知工具回退英文 |
| 摘要 | `toolSummary(step.name, JSON.stringify(step.args ?? {}))` | 替代原始报文 |
| 状态点 | `step.ok === false` → danger；`step.result === undefined && running` → 脉冲 accent；否则 ok |
| 耗时 | `step.elapsedMs` | `0.0s` 格式，与 `fmtSecs` 一致 |
| 结果 | `step.result` | 点击后展开，`max-height:168px` |

### 3.3 迭代分组

复用 `ToolCard` 现有 `subIterations` 逻辑（`iteration` 缺失时归到当前轮），抽到组件内部；空轮次不渲染标题。

### 3.4 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| `trace.tools` 为空、仅 think | 只渲染思考与结论，不显示「0 步」空态 |
| `args` 非对象/含循环引用 | `JSON.stringify` try/catch，失败回退空串，仅显示工具名 |
| `result` 超长（>4000 字已由后端截断） | 前端结果区限高滚动，不二次截断文本 |
| 历史卡片无 `m.sub` | 不渲染过程区（保持现状），不报错 |
| `status='interrupted'` | 过程区照常可展开；底部显示「进程重启，后台子任务未完成」 |
| 窄屏 | `.st-brief` 单行省略；思考与结论自动换行 |

### 3.5 演进项（本任务不做）

- 子 Agent 内部嵌套完整 `ToolCard`（含 `{ }` 浮层、键值表、结果复制）；
- 思考逐字流式；
- 结论 Markdown 富文本；
- 过程区搜索/过滤。
