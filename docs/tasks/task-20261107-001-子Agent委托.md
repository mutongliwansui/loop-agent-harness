## 一、任务目标需求

### 1.1 背景（痛点）

当前所有任务都在主 Agent 的单条 ReAct 循环内串行完成。对于**可封装、可独立思考**的子任务（如「调研 X 库的 API 并给出选型建议」「把这段日志按错误类型归类」），主 Agent 必须亲自跑完全部工具链，存在两个问题：

1. **上下文污染**：子任务的工具调用/中间观察会拉长主对话，挤占主任务上下文窗口；
2. **思考链不可复用**：子任务若需独立的多步推理，与主任务的推理混在一起，主 Agent 难以聚焦。

期望形态：主 Agent 调用一个 `delegate` 工具，把任务描述丢给一个**独立子 Agent**，子 Agent 用自己的上下文跑完整条 ReAct 链，完成后只把最终结论作为 observation 返回主 Agent。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| Agent 执行循环 | `ReActAgent.run()` 单 agent ReAct，工具来自全局 `registry`，`AgentEvents` 透传 SSE | 子 Agent 可复用同一条 run 链路，无需另造执行器 |
| 工具注入能力 | `Tool.execute(args, ctx)` 的 `ctx` 只有 `signal/workspaceRoot/sessionId` | **缺**：工具拿不到 agent 实例/记忆 kit，无法自行起子 Agent → 需扩展 ctx |
| 实例池化 | `AgentPool` 按 sessionId 复用，`_chatHistory` 实例态不共享 | 子 Agent **不占池**（父已占槽，嵌套占槽可能死锁）→ 新建临时实例，用完 `dispose` |
| 记忆共享 | `attachMemory(kit)` 共享 L2/L3（episodic/curated 单例），每实例独立 L1 | 子 Agent `attachMemory(同 kit)` → 共享长期记忆、独立短期，正确 |
| 工具来源 | `run()` 直接 `registry.toOpenAITools()`，无 `options.tools` 覆盖 | 要排除 `delegate` 防递归 → 需给 `run()` 加 `excludeTools` 过滤 |
| 进度展示 | `tool_start/end/progress` 已有心跳 | 委托可复用 tool 心跳；嵌套流式属演进项 |

### 1.3 任务目标

1. 新增 `delegate` 工具：主 Agent 可将一个自包含子任务委托给独立子 Agent。
2. 子 Agent：独立消息历史、共享 L2/L3 记忆、独立 L1 工作记忆、工具集排除 `delegate`。
3. 子 Agent 结果作为 observation 返回主 Agent；子任务本身不落盘（主对话为真相源）。
4. 取消信号透传：主 Agent 停止 → 子 Agent 同步中止。
5. MVP：进度以单个工具卡片 + `tool_progress` 心跳展示；前端零改动。

### 1.4 设计约束

- **不改主 Agent 既有行为**：`delegate` 是普通工具，不改变 run 循环、工具调用、SSE 协议。
- **防无限递归**：子 Agent 工具集必须不含 `delegate`（MVP 一刀切排除）。
- **零新依赖**。
- 子任务不持久化到独立会话（避免会话爆炸）；L2 记忆写入仍带 `sessionId` 归属。
- 可测：`delegate` 工具通过 mock `ctx.runSubAgent` 单测，不依赖真实 LLM。

## 二、方案设计

### 2.1 总体思路

```
主 Agent run()
  ├─ 构造 runSubAgent 闭包（持 configLoader / 共享记忆 kit / wsRoot / signal）
  ├─ 注入 ToolContext.runSubAgent
  └─ LLM 决定调用 delegate(task, context?)
        └─ delegate.execute → ctx.runSubAgent(task)
              ├─ new ReActAgent(configLoader)
              ├─ setWorkspaceRoot(wsRoot)
              ├─ attachMemory(共享 kit)      ← 共享 L2/L3，独立 L1
              ├─ sub.run(task, {
              │     model, maxIterations, signal,
              │     excludeTools: ['delegate']   ← 防递归
              │   })
              ├─ 结果 { answer, iterations }
              └─ sub.dispose()
        ← 返回 answer 作为 observation
```

**为什么用 ToolContext 注入而非全局 registry 查找**：工具层零全局依赖、可测（mock `runSubAgent`）、CLI 不注入即自然降级报错、不破坏现有工具契约。

### 2.2 关键设计决策

| 编号 | 决策 | 取舍 / 被否决项 |
| --- | --- | --- |
| D1 | 子 Agent 执行器通过 `ToolContext.runSubAgent` 注入 | 否决全局 registry 查找：工具层耦合 api 层、不可测 |
| D2 | 子 Agent 工具集 = 全量工具扣除 `delegate` | 否决白名单：子 Agent 能力应与主 Agent 对等，仅防递归 |
| D3 | 子任务不落盘，结果作为主对话的 observation | 否决落子会话：会话爆炸、主对话不再是真相源 |
| D4 | 防递归 = `excludeTools: ['delegate']`（MVP 一刀切） | 否决 `maxDepth`：MVP 先跑通，多级委托列演进项 |
| D5 | 进度展示 = 单个 ToolCard + `tool_progress` 心跳（MVP） | 否决嵌套流式：协议未定、前端改动大，列演进项 |
| D6 | `delegate` 默认开启，可在 tools 配置 disable | 否决默认关闭：工具已存在即应可用 |

### 2.3 子 Agent 的隔离与共享

| 项 | 策略 | 理由 |
| --- | --- | --- |
| 消息历史 | 全新空 `_chatHistory`，仅含 task 一条 user | 子任务独立，不污染主对话 |
| L2/L3 记忆 | 共享父 Agent 的 episodic/curated/gate/dream | 子 Agent 有项目背景与用户偏好 |
| L1 工作记忆 | 独立 `WorkingMemory`（`attachMemory` 新建） | 子任务上下文不串入主 Agent 压缩窗口 |
| 工具集 | 全部工具扣除 `delegate`（`excludeTools`） | 防无限递归 |
| 会话存储 | 不 `setSessionStore`（不落盘） | 子任务是主对话的 observation，主会话才是真相源；L2 写入仍带 sessionId |
| 模型 | 继承父 Agent 的 `options.model` | 一致性；后续可加 per-task 模型参数 |
| 取消 | 透传父 Agent 的 `signal` | 主 Agent 停止 → 子 Agent 同步中止 |

## 三、任务详细设计

### 3.1 类型扩展（types.ts）

```ts
/** 子 Agent 委托选项（需求 20261107-001） */
export interface SubAgentOptions {
  /** 补充给子 Agent 的背景信息 */
  context?: string;
  /** 指定模型（缺省继承主 Agent） */
  model?: string;
  /** 最大迭代数（缺省继承主 Agent） */
  maxIterations?: number;
}

/** 子 Agent 执行结果 */
export interface SubAgentResult {
  /** 子 Agent 的最终回答 */
  answer: string;
  /** 实际迭代次数 */
  iterations: number;
}

export interface ToolContext {
  signal?: AbortSignal;
  workspaceRoot?: string;
  sessionId?: string;
  /** 子 Agent 委托执行器（需求 20261107-001）：由主 Agent 在 run() 内注入；CLI/缺省为 undefined，工具据此降级 */
  runSubAgent?: (task: string, opts?: SubAgentOptions) => Promise<SubAgentResult>;
}
```

### 3.2 react-agent.ts：runSubAgent 闭包 + excludeTools

**`AgentOptions` 新增**：

```ts
/** 子 Agent 委托时排除的工具名（需求 20261107-001 D4）；主 Agent run 一般不传 */
excludeTools?: string[];
```

**`run()` 内两处改动**：

1. 构造工具列表时过滤：
   ```ts
   let openaiTools = registry.toOpenAITools();
   if (options.excludeTools?.length) {
     const ex = new Set(options.excludeTools);
     openaiTools = openaiTools.filter((t) => !ex.has(t.function.name));
   }
   ```

2. 工具执行阶段拦截（防 LLM 幻觉调用被排除的工具）：
   ```ts
   if (options.excludeTools?.includes(toolName)) {
     return { ...c, result: `工具 ${toolName} 在此上下文中不可用` };
   }
   ```

3. 构造 `runSubAgent` 闭包（在拿到 wsRoot/signal/memory 后），注入 runner：
   ```ts
   const runSubAgent = async (task, opts) => {
     const sub = new ReActAgent(this._configLoader);
     sub.setWorkspaceRoot(wsRoot);
     // 共享 L2/L3，独立 L1
     const kit = this._episodicMemory
       ? { episodic: this._episodicMemory, curated: this._curatedMemory,
           gate: this._promotionGate, dream: this._dreamingPipeline }
       : null;
     await sub.attachMemory(kit, wsRoot);
     try {
       const result = await sub.run(
         opts?.context ? `${opts.context}\n\n任务：${task}` : task,
         {
           model: opts?.model ?? options.model,
           maxIterations: opts?.maxIterations ?? options.maxIterations,
           signal: options.signal,
           excludeTools: ['delegate'],
           sessionId: sessionId ?? undefined,
         },
       );
       return { answer: result.answer, iterations: result.iterations };
     } finally {
       sub.dispose();
     }
   };
   ```
   并在 `runner.run(c.tool, c.args, { signal, workspaceRoot, sessionId, runSubAgent })` 中传入。

### 3.3 runner.ts：透传 runSubAgent

`run()` 的 options 接口增加 `runSubAgent`，原样透传到 `ToolContext`。

### 3.4 tools/delegate.ts（新增）

```ts
export const delegate: Tool = {
  name: 'delegate',
  description:
    '委托一个独立子 Agent 完成一个原子子任务。子 Agent 拥有独立上下文、共享项目记忆，' +
    '完成后返回最终结论。适用于可封装/可独立思考链的子任务。',
  parameters: {
    type: 'object',
    properties: {
      task: { type: 'string', description: '子任务描述，应自包含、可独立执行' },
      context: { type: 'string', description: '可选：补充给子 Agent 的背景信息' },
    },
    required: ['task'],
  },
  execute: async (args, ctx) => {
    if (!ctx.runSubAgent) return '错误：当前环境不支持子 Agent 委托';
    const r = await ctx.runSubAgent(String(args.task), {
      context: args.context ? String(args.context) : undefined,
    });
    return r.answer;
  },
};
```

### 3.7 演进（非本期）

- **多级委托**：`maxDepth` 参数，子 Agent `excludeTools` 仅在 `depth<=1` 时含 delegate。
- **嵌套流式进度**：子 Agent 的 `AgentEvents` 以 `sub_` 前缀回灌主 SSE，前端渲染嵌套工具流（需先定 schema 再联调）。
- **子任务独立持久化**：落子会话 + 在主对话中引用（可召回子任务完整轨迹）。
- **子 Agent 专用模型**：`delegate.model` 参数路由到更便宜/更快的模型。

### 6.2 与方案偏差（均已确认合理）

1. **新增 `delegate.timeoutMs = 600000`**：`runner` 默认 30s 超时对「完整 ReAct 链」的子任务过短，会误报超时；超时后主 Agent 放弃等待，子 Agent Promise 自然结束后结果丢弃。
2. **子 Agent `verbose: false`**：避免 ConsoleLogger 把子 Agent 的思考流打进主进程日志/终端，污染主对话观感。
3. **`BUILTIN_TOOL_NAMES` 同步加入 `delegate`**（D6「默认开启」的落地配套）：否则 `/tools list` 看不到、也无法通过 `tools.disabled` 关闭。
4. **`tests/vision-registry.test.ts` 计数更新**：内置工具 9→10、含视觉 13→14、禁用单视觉 12→13。
