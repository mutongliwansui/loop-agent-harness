## 一、任务目标需求

### 1.1 背景（痛点）

当前 `delegate` 的超时是一刀切的固定值：

- [delegate.ts](../../src/tools/delegate.ts#L14) 硬编码 `timeoutMs: 600000`（10 分钟）；
- [runner.ts](../../src/tools/runner.ts#L65) 以 `tool.timeoutMs` 交给 `withTimeout`（[L135-L151](../../src/tools/runner.ts#L135-L151)），到点直接返回「工具执行超时 (600000ms)」；
- 超时后子 Agent 的 Promise 仍在后台继续跑，但结果被丢弃（注释已明说），且不会落盘、不会通知——长任务必然「白跑」；
- 反过来，后台子任务（`background: true`）没有任何总时长/无进展保护，若子 Agent 卡在某个工具或模型请求上，会永久停留在 `running`，前端 2s 轮询永不停止；
- 短任务与长任务使用同一阈值，既无法保护短任务的卡死，也无法容纳合理的长任务。

后台命令的成熟方案是：**提交即返回 taskId、不设固定硬超时、结束由完成通知驱动**（见 [background-notice.ts](../../src/agent/background-notice.ts)、[task-20261104-004](./task-20261104-004-后台任务完成事件通知.md)）。本任务把同一思路用于子 Agent。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| 工具层超时 | `ToolRunner.withTimeout` 到点 reject，结果丢弃 | 需要支持「不限时」语义 |
| 子 Agent 生命周期 | `runSubAgentOnce` 只受父 `signal` 控制 | 需要新增 `AbortController` 级联 |
| 后台进度 | `subagent_event`（iteration/think/tool_*/tool_progress）可作心跳 | 可复用作「无进展」判定 |
| 后台完成通知 | `onSubAgentComplete` 落盘卡片 + SSE；CLI 走 `pushCliNotice` | 可直接复用，不改协议 |
| 配置 | [schema.ts](../../src/config/schema.ts#L172-L177) `SubAgentConfig` 仅 `background`/`maxConcurrent` | 需新增超时三参数 |
| 父级阻塞 | 同步 `delegate` 会一直等到结论或工具超时 | 需软阈值转后台，避免主 Agent 被长任务锁死 |

### 1.3 任务目标

1. **工具层不再硬杀**：`delegate` 工具超时设为「不限时」，生命周期由子 Agent 自身的超时策略管理；
2. **无进展超时**（核心保护）：以子 Agent 的 LLM 流式/工具进度事件为心跳，超过 `idleTimeoutMs`（默认 10 分钟）无任何活动才中止，避免「长任务有进展却被杀」；
3. **可选总时长上限**：`maxRuntimeMs`（默认 `0` = 不限），供运维按需设置硬上限；
4. **软超时自动转后台**：同步委托运行超过 `foregroundSoftTimeoutMs`（默认 120s）时，不再阻塞主 Agent，转为后台任务并返回 `taskId`，完成走既有结果卡片 + 通知链路；
5. **全部阈值可配**，并有单测覆盖（含定时器替代、假 LLM）。

### 1.4 设计约束

- 不改变 `delegate` 工具的参数语义（`task/context/background` 不变）；
- 不改变后台完成通知与结果卡片的协议（`subagent_result` 字段不变）；
- 取消语义不变：父 `run` 的 `signal` 仍会级联中止子 Agent；
- 子 Agent 仍不落盘独立会话，主对话为唯一真相源；
- 零新依赖；阈值有合理默认值，且默认行为对短任务无感知（软阈值 120s 内完全不变）。

## 二、方案设计

### 2.1 总体思路

```
delegate(task)
   │
   ├─ background=true ──▶ registry.create(taskId) ──▶ 立即返回 taskId
   │                              │
   │                              └─ 子 Agent 运行（idle/maxRuntime 看护）
   │                                     └─ 完成/失败 ──▶ onSubAgentComplete（卡片+通知）
   │
   └─ 同步 ──▶ registry.create(taskId)（不立刻落盘运行卡片）
                   │
                   ├─ race(子 Agent, 软阈值 120s)
                   │     ├─ 子 Agent 先完成 ──▶ 返回结论（不落额外结果卡片，避免与 tool 卡片重复）
                   │     └─ 软阈值先到 ──▶ 落盘 running 卡片 + 返回「已转后台 taskId」
                   │                              └─ 后台继续，完成走 onSubAgentComplete
                   │
                   └─ 看护：idleTimeout / maxRuntime → controller.abort(原因)
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍 / 被否决项 |
| --- | --- | --- |
| D1 | `ToolRunner` 约定 `timeoutMs <= 0` 表示**不限时**；`delegate` 改为 `timeoutMs: 0` | 否决继续给一个更大的固定值（如 60 分钟）：仍是任意阈值；否决新增 `'none'` 联合类型：会扩散到所有工具签名 |
| D2 | 主保护改为**无进展超时** `agent.subAgent.idleTimeoutMs`（默认 600000），心跳源为 `onLLMStream`/`onToolCallDelta`/`onToolProgress`/迭代事件 | 否决仅总时长：长任务有进展也会被杀；否决仅工具超时：模型请求卡住无法覆盖 |
| D3 | 保留可选总上限 `agent.subAgent.maxRuntimeMs`（默认 0＝不限），仅在运维显式配置时生效 | 否决删除总上限：异常任务仍需要兜底；否决强制默认值：与「不硬杀」目标冲突 |
| D4 | 同步委托软阈值 `agent.subAgent.foregroundSoftTimeoutMs`（默认 120000）到点后**不中止**，转后台并返回 `已转后台 taskId` | 否决软超时即中止：会丢掉已完成部分；否决永远后台：短任务拿不到即时结论，且每次多一次卡片 |
| D5 | 转后台时写 running 卡片并触发 `onSubAgentStart`；完成时复用 `onSubAgentComplete` | 否决另造通知协议：与 20261107-002 的卡片/轮询链路重复 |
| D6 | 无进展/总时长超时统一走 `controller.abort(原因)`，完成回调 `status='failed'` 且 `error=原因`；SSE 发 `aborted` 事件 | 否决标记 `aborted`：`aborted` 语义留给用户/父级取消，超时属于失败 |
| D7 | 完成通知不自动触发新一轮模型推理，仍在下一轮 LLM 调用前按现有队列投递 | 否决主动起 run：会与用户输入抢跑、产生并发与额外成本（与 20261104-004 D2 一致） |
| D8 | 软转后台后，原 `delegate` 工具卡片以「已转后台」结束；后续过程/结论由后台卡片承载 | 否决继续复用原工具卡片：工具消息已落盘，无法在后续轮次改写其结果 |

### 2.3 配置项

```ts
export interface SubAgentConfig {
  background: boolean;             // 既有
  maxConcurrent: number;           // 既有
  /** 无进展超时（ms），0=关闭；默认 600000 */
  idleTimeoutMs: number;
  /** 总时长上限（ms），0=不限；默认 0 */
  maxRuntimeMs: number;
  /** 同步委托软阈值（ms），0=不转后台；默认 120000 */
  foregroundSoftTimeoutMs: number;
}
```

默认值：

```ts
subAgent: {
  background: true,
  maxConcurrent: 3,
  idleTimeoutMs: 600_000,
  maxRuntimeMs: 0,
  foregroundSoftTimeoutMs: 120_000,
}
```

## 三、任务详细设计

### 3.1 ToolRunner 不限时

```ts
// src/tools/runner.ts
const timeout = options.timeout ?? tool.timeoutMs ?? 30000;
const result = timeout > 0 ? await this.withTimeout(raced, timeout) : await raced;
```

- `0` 与负数都视为不限时；`commandRun` 的 `timeout` 参数不经过该分支（工具内部自管），行为不变。

### 3.2 看护器（新增 `src/agent/subagent-watchdog.ts`）

```ts
interface SubAgentWatchdogOptions {
  idleTimeoutMs: number;   // 0 关闭
  maxRuntimeMs: number;    // 0 关闭
  onTimeout: (reason: 'idle' | 'max-runtime', elapsedMs: number) => void;
}
class SubAgentWatchdog {
  touch(): void;    // 重置 idle 计时
  start(): void;
  stop(): void;
}
```

- `touch()` 由 bridge 的 `onLLMStream`（仅心跳，不转 SSE）、`onToolCallDelta`、`onToolStart/End`、`onToolProgress`、`onIterationStart` 调用；
- 内部 `setInterval` 30s 检查一次（或每次 touch 重设定时器，二选一，实施时以「30s 轮询 + lastActivityAt」实现，避免高频 clearTimeout）；
- 超时调用 `controller.abort(reason)`；注册表 `finish(status='failed', error=...)`。

### 3.3 同步 → 后台提升

```ts
const taskId = makeTaskId();
const controller = new AbortController();  // 与父 signal 级联
registry.create({ taskId, sessionId, task, controller });

const running = runSubAgentOnce(task, subOpts, callId, controller.signal, ...);
const winner = await Promise.race([
  running.then((r) => ({ kind: 'done' as const, r })),
  delay(softTimeoutMs, controller.signal).then(() => ({ kind: 'promote' as const })),
]);

if (winner.kind === 'done') {
  registry.finish(taskId, { status: 'done', ... });
  return winner.r;                       // 不落结果卡片
}
// 转后台：落 running 卡片，返回 taskId；running 继续
void running.then(...).catch(...).finally(...);   // 完成走 onSubAgentComplete
return { answer: `⏳ 已转后台子任务 ${taskId}：${task}`, iterations: 0, taskId, background: true };
```

- `softTimeoutMs === 0` 时跳过 race，保持纯同步等待；
- 同步阶段产生的 `subagent_event` 仍带原 `callId`；转后台后的事件改用 `taskId` 作为 `callId`，并补发一次 `phase:'start'`，让前端启动 2s 轮询（与既有后台逻辑一致）。

### 3.4 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| 父 `signal` 取消 | 级联 `controller.abort`，状态 `aborted`，错误「父 run 已取消」 |
| 无进展超时 | 状态 `failed`，错误「子任务无进展超时（N 分钟）」，结果卡片置失败 |
| 总时长超时 | 状态 `failed`，错误「子任务超过最大运行时长（N 分钟）」 |
| 软转后台后用户删除会话 | 既有 `abortSession` 中止，状态 `aborted` |
| 软转后台后进程重启 | 既有 running 卡片被标记 `interrupted`（20261107-002 已实现） |
| `idleTimeoutMs=0` 且 `maxRuntimeMs=0` | 无看护，仅受父 signal 与模型/工具自身超时约束（需在文档提示风险） |
| 定时器与真实时钟 | 单测使用 `vi.useFakeTimers()`，避免真实等待 |

### 3.5 演进项（本任务不做）

- 跨进程任务恢复/接管；
- 基于任务的 token 预算超时；
- 动态阈值（按任务类型/模型自动调整）；
- 超时后自动重试或拆分任务。
