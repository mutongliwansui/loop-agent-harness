## 一、任务目标需求

### 1.1 背景（痛点）

记忆管理页（`#/memory`）分四个标签页：定时任务 / L2 情景 / L3 长期 / 检索。用户反馈这四个页面里仍有「启动空间」的内容，要求去掉。

用户看到的「启动空间」不是一个孤立文案，而是**一条隐式作用域暗线的界面投影**：前端多处把「不传 `ws`」当作「看启动空间」，于是必须给这个"不选"的状态起个名字，就叫「启动空间（缺省）」。名字背后是用户无法回答的问题——「我到底是哪个空间？」。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| 定时任务页只读单空间历史时不暴露「启动空间」 | `DreamHistoryList.vue:63` 分段按钮文案写死「启动空间」；选中即 `?history?limit=20`（不带 `ws`），后端 `memory-dream.ts:76` 的 `resolveHistoryTargetRoot` 缺省取 `ctx.deps.sessionStore.path` | ❌ 真语义但名字是暗线 |
| 历史表格每行都有可读的空间标识 | `DreamHistoryList.vue:94-102`：`r.workspaceName` 存在则显示名+id，否则兜底渲染「启动空间」 | ❌ 兜底文案即暗线 |
| L2 只看显式选中的空间 | `MemoryView.vue:509-512` 下拉首项 `<option value="">启动空间（缺省）</option>`；`:189` 不带 `ws` → `memory.ts:140` `requireMemoryKit(ctx)` 落 `ctx` 空间 | ❌ 隐式缺省可视化 |
| L3 只看显式选中的空间 | `MemoryView.vue:587-590` 同样首项；`:247` 不带 `ws` → 同上 | ❌ 隐式缺省可视化 |
| 检索能明确「在哪个空间搜」 | `MemoryView.vue:635` 徽章写「启动空间」；`memory.ts:175-184` 的 `handleMemorySearch` **没有 `ws` 参数**，恒搜 `ctx` 那一个空间 | ❌ 最严重：既不可选也不可知 |
| 空间清单能支撑「自动选第一个有记忆的空间」 | `GET /memory/workspaces` 已返回 `{id,name,path,hasMemory,hasSession}`（`memory-workspaces.ts:21-28`、`memory.ts:100-107`） | ✅ 能力已就绪，仅缺前端使用 |
| 跨空间直读 L2 记忆 | `resolveWsTarget()`（`memory.ts:66-98`）已支持 `?ws=<id|绝对路径>`，`readEpisodicDirect()` 复用 `EpisodicMemory` 直读 | ✅ 检索可复用同一基座 |
| 跨空间直读 L3 记忆 | `handleCurated` 的 `?ws=` 分支已实现（`memory.ts:113-139`） | ✅ 已就绪 |
| 单空间历史可按 `ws` 读取/清空 | `handleHistory` / `handleClearHistory` 的 `scope=ws&ws=` 分支已实现（`memory-dream.ts:238-260/289-311`） | ✅ 已就绪，仅前端未用 |
| 标签页状态进 hash | `MemoryView.vue:344-368` 已把 `tab` / `ws` / `histScope` 写进 hash query | ✅ 复用即可 |

**关键结论**：后端**跨空间能力齐备**（`?ws=` 早在 20261026-004 就做完了），缺的是**前端愿不愿意显式传**。本次改动主战场在前端，后端只补一个 `GET /memory/search?ws=`。

### 1.3 任务目标

1. **四个标签页零「启动空间」字样**：用户可见文案里不再出现该词（含注释同步修订）。
2. **L2 / L3 下拉删除隐含项**：不再有「（缺省）」选项，改为进页面自动选中清单里第一个 `hasMemory=true` 的空间；清单为空时显示空态引导，数据区在未选中前**不发任何缺省请求**。
3. **检索页补空间选择器**：后端 `GET /memory/search` 新增 `?ws=<id|绝对路径>`，复用 `resolveWsTarget` + `EpisodicMemory`；前端徽章改为显示所选空间名，未选空间不允许检索。
4. **定时任务页范围语义显式化**：分段按钮改「全部空间 / 指定空间」，选「指定空间」时必须显式选一个空间（带 `?ws=`）；表格空间列无数据时兜底改「—」。
5. **hash 状态化延续**：所选空间仍写入 hash `?ws=`，刷新/分享可还原。

### 1.4 设计约束

- **不改后端缺省语义**：`20261113-001` D5 已决定「记忆端点缺省=进程启动空间」，本次**只让前端不再触发缺省**，后端 `resolveWsTarget` 缺 `ws` 返回 null 的行为原样保留（单测/嵌入用法仍依赖它）。
- **`/memory/dream*` 全空间语义不变**：`POST /memory/dream` 仍全空间整理，`scope=all` 仍文件扫描聚合。
- **零新依赖**：只用既有 `node:` 模块与 Vue 组合式 API。
- **`wsLabel()` 命名不变**：`MemoryView.vue:173-176` 的「名称（记忆·会话）」标注继续用于区分孤儿空间。
- **不自启用户服务**：现场 `loop-agent.exe --serve` 占 3000 端口，验证另起端口。
- **文档双语同步**：`docs/readme/zh|en` 的 `http-api.md`、`memory-management.md` 涉及 `?ws=` 语义处需同步。

## 二、方案设计

### 2.1 总体思路

```
                    ┌──────────────────────────────────┐
                    │  GET /memory/workspaces          │
                    │  {id,name,path,hasMemory,...}    │
                    └──────────────┬───────────────────┘
                                   │ 进页面加载一次
                    ┌──────────────▼───────────────────┐
                    │ 前端 activeWs（显式选择）         │  ← D1：单一事实源
                    │ hash ?ws= 双向同步               │
                    │ 初值 = 第一个 hasMemory 空间      │
                    └──┬────────┬────────┬────────┬────┘
                       │        │        │        │
              ┌────────▼─┐ ┌───▼────┐ ┌─▼─────┐ ┌▼──────────┐
              │ L2 情景  │ │ L3 长期│ │ 检索  │ │ 定时任务  │
              │?ws=必带  │ │?ws=必带│ │?ws=必带│ │scope=ws  │
              │无 ws 不请求│ │        │ │       │ │+ws 必带   │
              └──────────┘ └────────┘ └───────┘ └───────────┘
                                          │
                              ┌───────────▼────────────┐
                              │ 后端新增 ?ws=（D4）    │
                              │ GET /memory/search     │
                              │ resolveWsTarget +      │
                              │ readEpisodicDirect 同构│
                              └────────────────────────┘
```

**数据流要点**：所有标签页共享同一个 `activeWs`（D1），任何标签页切换空间都写 hash，其它标签页同步跟随。这与现有 `MemoryView.vue:351-356`「一个 ws 参数两个标签页共用」的约定一致，只需从「可为空」变为「必填」。

### 2.2 关键设计决策 D1…D7

| 编号 | 决策 | 取舍与被否决项 |
| --- | --- | --- |
| **D1** | **前端单一 `activeWs` 事实源，替代 `l2Ws`/`l3Ws` 两个可空 ref**。初值 = `workspaces` 中第一个 `hasMemory=true` 的 id；没有一个有记忆则取第一个存在的空间；清单为空则 `activeWs=''` 并渲染空态 | 现状 `l2Ws`/`l3Ws` 两个 ref 由 hash watch 强行对齐（`MemoryView.vue:351-356`），改单 ref 后逻辑更短且不可能漂移。**否决**「保留两个 ref 各自可空」：那就是暗线本身。**否决**「初值取最近使用空间」：记忆端点缺省不是 MRU，前端再造一个 MRU 会让"界面显示"与"后端行为"再次脱钩 |
| **D2** | **下拉删除 `value=""` 的隐含项**，选项只来自 `workspaces`；选中项必非空。未选中（空清单）时 `<select>` 显示占位「无可用空间」且 `disabled` | 直接删掉选项就有"不选"的空窗期，故用 auto-select 兜住。**否决**「保留一个叫『默认』的选项」：这就是把「启动空间」改个名字，用户明确要去掉的是这个概念本身 |
| **D3** | **L2 标签页计数改为跟随 `activeWs`**（`l2TotalAll` 由当前空间 7 天条目数决定），不再走无 `ws` 的 `preloadEpisodicCount()` | 现状 `preloadEpisodicCount()`（`MemoryView.vue:202-209`）拉的是启动空间，与页面实际展示的空间可能不是同一个 → 计数会撒谎。**否决**「删掉计数徽章」：信息本身有用，只是错在数据源 |
| **D4** | **后端 `GET /memory/search` 新增 `?ws=`**：有 `ws` 时用 `resolveWsTarget()` 定位记忆目录 → `readEpisodicDirect`-同构方式 `new EpisodicMemory(dir)` + `init()` + `search(q,topK,{scope:'all'})`；无 `ws` 时保持现有 `requireMemoryKit(ctx)` 行为 | 复用 `resolveWsTarget` 可白拿 canonical 校验与 404/forbidden 语义（与 episodic/curated 完全一致）。**否决**「前端自己挑空间、后端不动」：做不到，`handleMemorySearch` 现在没有任何空间入参。**否决**「改成全空间聚合检索」：要给每个空间建/开索引，成本与本次目标无关，另立需求 |
| **D5** | **定时任务页 `scope` 分段改「全部空间 / 指定空间」**，选「指定空间」时下方出现空间下拉且必选，请求带 `?ws=`；hash 用 `histScope=ws` + 共享 `ws` | `scope=ws` 的后端语义本来就是"一个具体空间"，只是界面上把它叫成了「启动空间」。**否决**「直接只剩『全部空间』」：那会丢失"只看某个空间的历史"这个真实需求，且删除已有能力属于功能退步。**否决**「`scope=ws` 时复用 L2/L3 的 `activeWs` 隐式带入」：用户切到"指定空间"却没选空间时行为不可预期，必须显式 |
| **D6** | **历史表格空间列兜底文案由「启动空间」改「—」**；`scope=ws` 单空间读取时后端回填该空间三维（可选增强，P1） | 兜底文案是被删词的最后一处。**P1 可选**：让 `handleHistory` 的 `scope=ws` 分支也附 `workspaceId/Name/Path`，表格就永远有名字可显示，`—` 只是极端兜底。若 P1 不做，`—` 语义也正确（"这条记录无可归属空间信息"） |
| **D7** | **注释同步修订**（`MemoryView.vue:13/161/201/264`、`DreamHistoryList.vue:6/24`）：把「启动空间」改为「指定空间」/「进程启动空间（后端缺省，前端不再触发）」 | 注释留着旧词会让下一个人重新引入。**否决**「只改 UI 文案不改注释」：评审时会被问"到底还存不存在启动空间"，注释必须给出准确答案 |

### 2.3 联网检索结论

本次为**内部界面语义收敛**，实现路径完全由本仓库既有能力决定，不涉及外部协议或第三方方案选型。可借鉴的通用结论（与 20261113-001 台账同源）：

- Eclipse Theia 的 `WorkspaceServer` 把 `getMostRecentlyUsedWorkspace()` 与 `getRecentWorkspaces()` 分离，**MRU 只作推荐不作隐式默认**——支持 D1 否决「初值取 MRU」。
- NVIDIA OpenShell #3048 把「空字符串代表默认空间」列为需重构的反模式（`replace implicit workspace selection with typed scope selectors`），要求「省略 / 默认 / 全空间」三种意图可显式区分——正是本任务 `全部空间 / 指定空间` 分段（D5）与「必选空间」（D2）的理论依据。

> 说明：本轮未新增外网检索（无可验证的新外部依赖），结论沿用台账 20261113-001 已核实来源。

## 三、任务详细设计

### 3.1 后端：`src/api/handlers/memory.ts`

```
GET /memory/search?q=<必填>&limit=&ws=<id|绝对路径>
```

- `q` 缺失/空白 → 400（保持现状）。
- `limit` 走 `queryInt(url,'limit',5,50)`（保持现状）。
- `ws` 存在 → `resolveWsTarget(ctx, url)` 得 `{memoryDir}`；`new EpisodicMemory(memoryDir)` → `await init()` → `search(q, topK, { scope:'all' })`；结果附 `ws: { id, path }`（与 `/memory/episodic` 响应同构）。
- `ws` 不存在 → 走现有 `requireMemoryKit(ctx)` 分支（不改）。
- 错误映射：`resolveWsTarget` 内 `registry.ensureRoot` 抛 `not_found`/`forbidden`；非法形态抛 `bad_request`；未知空间 `not_found`——全部沿用，无需新增。

**签名**：`handleMemorySearch` 不变（已收 `req`，无需改路由表）。

### 3.2 前端：`webui/src/views/MemoryView.vue`

| 项 | 改动 |
| --- | --- |
| 状态 | 删 `l2Ws`/`l3Ws`，新增 `const activeWs = ref('')`；`l2TotalAll` 由 `activeWs` 驱动；删 `preloadEpisodicCount()` 的无 `ws` 调用 |
| 初值 | `refresh()` 中 `workspaces` 到手后：`activeWs = hashWs ?? 第一个 hasMemory ?? 第一个 ?? ''`，随后按 `activeWs` 加载各页 |
| 空态 | `activeWs === ''` 时 L2/L3/检索三页显示「暂无可用工作空间（需先有会话或记忆数据）」引导；`<select disabled>` |
| L2 | 下拉选项仅 `workspaces`；`loadEpisodic()` 强制带 `&ws=`；`l2WsName` 改名 `activeWsName`，缺省分支删「启动空间」 |
| L3 | 同上；`loadCurated()` 强制带 `?ws=` |
| 检索 | 新增空间下拉 + `search()` 带 `&ws=`；徽章改 `<StatusBadge>{{ activeWsName }}</StatusBadge>`；未选空间时搜索按钮 disabled |
| 定时 | `setHistScope` 增加「指定空间」分支：先要求 `activeWs` 非空，`loadHistory()` 带 `?scope=ws&ws=<activeWs>`；`clearHistory()` 同步 |
| hash | `replaceHashQuery({ ws: activeWs || undefined })` 保留 |

### 3.3 前端：`webui/src/components/DreamHistoryList.vue`

| 项 | 改动 |
| --- | --- |
| 分段按钮 | `全部空间` / `指定空间`（文案），props/emit 不变（`scope: 'all' \| 'ws'`） |
| 空间列兜底 | `:100` 的 `<span class="muted">启动空间</span>` → `<span class="muted">—</span>` |
| 注释 | `:6`/`:24` 的「启动空间」→「指定空间（scope=ws，由父组件显式给定）」 |

### 3.4 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| 空间清单为空（全新安装、无任何会话/记忆） | 三页空态引导，不发缺省请求；定时页「指定空间」不可选 |
| hash 里的 `ws` 已失效（空间被删） | 回落 auto-select 第一个可用空间并覆写 hash |
| 空间仅「有记忆无会话」（孤儿空间） | 可选中；L3 走 `?ws=` 会 `not_found`（`memory.ts:121-123` 既有语义），前端 toast 提示而非白屏 |
| 检索时空间无索引 | `EpisodicMemory.search` 自动降级文件检索（`episodic.ts:284-295`），无需特殊处理 |
| 记忆未启用（`enabled=false`） | 保持现有「未启用」卡片；空间下拉不渲染 |

### 3.5 演进项（本任务不做）

- `/memory/search` 全空间聚合检索（跨空间合并打分）。
- 记忆页记住「上次看的空间」到服务端磁盘（现只用 hash，刷新级持久）。
- 定时任务页「指定空间」的历史清空二次确认。
