## 一、任务目标需求

### 1.1 背景

`bootstrap.ts:24` 以 `registry.get(process.cwd())` 预装启动目录为工作空间，该 runtime 承担四重角色：deps 装配根、9 处 handler 缺省回落、Dreaming 保底遍历对象（registry.list() 只含已装载）、启动自愈扫描范围。后果：服务绑定启动目录、无人访问时其他空间记忆晋升停摆、兄弟空间中断 journal 永不标记。另核实 `WorkspaceRegistry.evictIdle()` 为无调用点死代码（runtime 只增不降）。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| 缺省空间解析 | 15 处 handler 直接读 `ctx.deps.sessionStore.path`（缺省回落+指针残留） | 需收敛到单一事实源 |
| 跨空间定位 | `session-locator.ts` 三级策略纯磁盘懒装载，不依赖启动空间 | 已具备，无需改 |
| wsId↔path 映射 | `memory-workspaces.ts` `listMemoryWorkspaces()`（sessions meta ∪ memory 目录，孤儿 path=''） | D2/D4 直接复用 |
| 增量预判素材 | `{memory}/{wsId}/.dreaming-state.json`：`lastProcessedDay`/`lastRunAt`；workspaceId 为纯哈希可离线算 | 预判可行 |
| Dreaming 入口 | `runFor(root)` 首行 `registry.peek(root)` 无 runtime 即 skip | 懒装载改动点唯一 |
| journal 自愈 | `reconcileInterruptedOnBoot(store)` 仅扫单空间 `runs/`；bootId 双因子判定 | 扩全盘 |
| LRU 回收 | `evictIdle()` 实现完整、busy 跳过、LRU 淘汰，但无生产调用点 | 定时接线 |

### 1.3 任务目标

①「以 cwd 为工作空间」→「最近使用空间」缺省（冷启动磁盘推导，无会话兜底 cwd）；②Dreaming 定时轮与关停兜底全空间参与（磁盘枚举+预判+懒装载）；③启动自愈全盘扫描；④evictIdle 接线。

### 1.4 设计约束

- CLI 单空间模式零改动；MCP stdio cwd、静态资源、上传目录语义不变
- `ApiServerDeps` 构造签名不变（既有单测零改动为第一优先）
- 零新依赖；`ctx.deps.sessionStore` 保留为合法 store 实例（同步 getter 消费点不破坏）

## 二、方案设计

### 2.1 总体思路（含 D8' 修订）

```
启动（bootstrap.ts）
  ├─ recentRoot = await resolveRecentRoot()      ← D2：扫 sessions/*/ 推导最近空间（canonical）
  ├─ rt = await registry.get(recentRoot)         ← 仍装 1 个 runtime＝缺省空间（非 cwd！）
  ├─ deps.sessionStore = rt.store                ← D8'：保留为「冷启动缺省空间 store」
  ├─ void reconcileAllInterruptedOnBoot()        ← D5：全盘扫 sessions/*/runs/
  └─ dreamScheduler.start()                      ← D4：tick 枚举全空间→预判→懒装载

请求（handler 缺省场景）
  ctx.defaultRoot()                              ← D1/D3：同步返回 MRU 指针（冷启动=recentRoot）
  ctx.resolveDefaultRuntime()                    ← 需要/store 时经 registry 懒取 + 改写指针 + touch MRU
```

**D8'（方案修订，替代原「惰性代理/getter 化」）**：实施前核实发现 `handlers/sessions.ts` 的 `resolveWorkspaceRuntime()` 本就**原地改写 `ctx.deps.sessionStore` 等指针**——「缺省回落」的真实语义已是「最近被 resolve 的空间」（MRU）。因此：

- **保留** bootstrap 预装 1 个 runtime，但其身份从 `process.cwd()` 换成 `resolveRecentRoot()`（最近使用空间）——满足「移除 cwd 绑定」的需求本质，且 `ApiServerDeps`/同步 getter/既有单测全部零破坏；
- `deps.sessionStore` 重定位为「冷启动缺省空间的 store 实例」：仅承担**跨空间无空间语义**的读操作（/workspaces 聚合、journal 读取、定位兜底）与单测 seam，**不再承担缺省空间语义**；
- 缺省空间语义的真实来源 = `ctx.defaultRoot()`（进程内 MRU 指针，单一事实源）；
- 被否决：Proxy 惰性代理（`.path`/`.id` 同步 getter 无法经 async 解析返回字符串，会破坏 15 处同步消费点）。

MRU touch 点（仅 2 处，用户可感知的活动）：`resolveWorkspaceRuntime()` 成功路径（显式跨空间操作/创建会话）+ `handleMessage` locateSession 成功后（活跃对话）。

## 三、任务详细设计

### 3.1 recent-workspace.ts（新模块）

```ts
/** 扫 <userDir>/sessions/*/: 返回 canonical 化的「最近使用空间」；无任何可用映射 → canonical(cwd) */
export async function resolveRecentRoot(userDir?: string): Promise<string>;
/** 进程内 MRU 指针（模块级） */
export function markWorkspaceUsed(root: string): void;   // touch（canonical 化后写入）
export function defaultRoot(): string;                    // 同步读（进程启动后恒有值，初始为 cwd）
```

- recency 计算：对每个 ws 目录 `stat` 目录与 `readdir(withFileTypes)` 后取子文件最大 mtime（会话文件更新必改文件 mtime）
- meta.json 的 `workspacePath` 缺失（孤儿）→ 该目录跳过
- `canonicalWorkspacePath` 失败（目录已删）→ 跳过该目录；全跳过 → cwd

### 3.2 HandlerContext 扩展（router.ts 类型 + server.ts 实现）

```ts
defaultRoot(): string;
resolveDefaultRuntime(): Promise<WorkspaceRuntime>;  // registry 缺失时回落 deps.sessionStore 对应 rt? — 无 registry 场景（纯单测）抛 internal
```

- server.ts 闭包实现：`defaultRoot` 引 recent-workspace 模块；`resolveDefaultRuntime` = `resolveWorkspaceRuntime(ctx, defaultRoot())`（import 自 handlers/sessions.js，已导出；该函数完成指针改写 + ensureScaffold + touch）
- bootstrap 在 server 构造后调用 `markWorkspaceUsed(recentRoot)` 一次（初始指针与冷启动值一致，幂等）

### 3.3 dream-scheduler 改造

```ts
private async enumerateCandidateRoots(): Promise<string[]>;   // D4 第一步
private shouldAttempt(root: string): Promise<boolean>;        // D4 第二步（磁盘预判）
// tick() / runAllForShutdown：for (root of 枚举∩预判) out.push(await this.runFor(root, ...))
// runFor：peek 未中 → try getCanonical(root)（懒装载）；失败 → skipSummary(root,'','runtime-unavailable')
```

- 预判规则：state 缺失 → true；`lastProcessedDay < 昨日(UTC)` → true；`lastRunAt` 距今 > intervalHours 小时 → true；否则 false（reason `no-new-content`）
- memoryDir/sessionsDir 口径与 handlers/memory.ts 一致（getConfig().memory.episodic.dir 绝对路径优先，否则 userDir/memory）；wsId = workspaceId(root) 纯哈希
- touch MRU：dream 不 touch（缺省指针保持用户视角）

### 3.5 边界与错误处理

| 场景 | 行为 |
|---|---|
| 冷启动 sessions 目录不存在/全孤儿 | 兜底 cwd（canonical 失败也返回原值，延后到 ensureRoot 才报错） |
| defaultRoot 空间目录被外部删除 | resolveDefaultRuntime → ensureRoot 抛 not_found（与显式 ws 同语义） |
| evict 后旧 ctx 指针（deps.sessionStore/configLoader） | 实例闭包仍可用（纯对象），读操作透明；写路径走 registry 重建 |
| dream 长跑中被 evict | kit 按根缓存不受 dispose 影响，run 正常完成（已核实 getMemoryKit 模块级缓存） |
| 全盘 reconcile 单文件损坏 | 跳过计数，不中断 |
| 预判误放行 | 真实增量判定兜底（0 LLM 成本空跑）；误拦截由 lastRunAt 超周期规则覆盖 |
