## 一、任务目标需求

### 1.1 背景

工具调用展示自 20261022-001 中文化后，结构仍是 `<details class="tool-call">` 折叠块：emoji 图标 + `✓/✗` 徽章 + 中文名 + 摘要，展开后是**全边框参数表 + 原始 JSON 折叠块 + 三重折叠的结果区**。原型诊断出 5 条症状：

| # | 症状 | 现状取值 |
| --- | --- | --- |
| 1 | 图标体系与图表容器割裂 | 工具用 emoji（📖 ✏️ ⚡），`chart-box` 用 16×16 线性 SVG；同屏两种图标语言 |
| 2 | 状态表达弱 | `✓ / ✗ / ⟳` 单字符徽章 + 12px 圆点，失败要靠展开读结果才知道原因 |
| 3 | 折叠层次过多 | 结果区同时有「>400 字符判定」「`max-height:120px` 截断 + 渐变遮罩」「`max-height:260px` 自身滚动」三套口径（详见 1.2） |
| 4 | 参数表过重 | `.ptable` 每格 1px 全边框 + 灰底首列，视觉上像调试面板 |
| 5 | 原始 JSON 占位 | `<details class="jv">` 常显在参数与结果之间，纵向挤占；而它的信息量最低 |

### 1.3 任务目标

1. 按原型方案 B 落地**卡片内聚式**外框：图标徽标 + 中文名 + 等宽副标题，右侧只有 `{ }` / 状态 pill / 耗时 / caret。
2. 图标从 emoji 换成 16×16 线性 SVG（与 `chart-box.ts` 的 `kind-ico` 同一体系：`fill:none`、`stroke:currentColor`、`stroke-width:1.5`、圆头圆角）。
3. 补「已中断」态：数据层 `ToolSeg.aborted` + 展示层灰色 pill「已中断」+ 副标题「用户停止，结果未返回」。
4. 原始 JSON 降级为头部 `{ }` 图标按钮，点开为**绝对定位浮层**，默认不占纵向空间。
5. 连续 ≥3 次同工具调用合并成组：折叠态一行（`读取文件 ×4`），展开为逐次调用行（序号 + 状态 + 副标题 + 耗时）；组内含失败则不合并且默认展开。
6. 结果区统一为行数口径（190px / 420px / >12 行才出「展开全部 N 行」），并把 `stripAnsi` 接进渲染路径。
7. 旧类名 `.tool-call` 保留一版别名，旧缓存页不至于裸奔。

### 1.4 设计约束

- **只动展示层**：SSE 协议、会话落盘结构、后端工具定义零改动；`ToolSeg` 仅新增可选字段。
- 纯逻辑（分组 / 失败原因 / 行数口径 / 图标表）放 [tool-meta.ts](file:///D:/trae_workspace/loop-agent-command/webui/src/tool-meta.ts)，保持「无 DOM 依赖」以便 root vitest 直测。
- 零新增依赖：图标为内联 SVG，不引图标库；不引 UI 框架。
- 未知工具 / MCP 工具（`server__tool`）永不空白或报错：拼图/齿轮图标 + 英文原名 + 紧凑 JSON 摘要（沿用现状语义）。
- 无障碍：卡片头 `role="button"` + `aria-expanded`，图标按钮带 `aria-label`，`{ }` 浮层按钮带 `aria-pressed`，`:focus-visible` 可见描边。
- 令牌化：新增样式只用 [style.css](file:///D:/trae_workspace/loop-agent-command/webui/src/style.css) 已有变量（`--bar-bg / --line-soft / --radius-card / --shadow-card / --ok-weak …`），亮色、跟随系统暗色、强制暗色三套主题自动一致。
- 交付前必须**实际渲染截图 + 像素级验证**，不得凭想象；临时产物用完清理。

### 2.2 关键设计决策

| # | 决策点 | 结论 | 理由 / 否决项 |
| --- | --- | --- | --- |
| D1 | 整体方案 | **方案 B 卡片内聚式**（2026-10-24 定稿） | 与 `chart-box` 同源外框语言，学一次通用；副标题承载参数摘要与失败原因，不展开即可读懂。否决 A 时间轴（无卡片时失败条无处安放）、C 极简 pill（信息量不足） |
| D2 | 图标体系 | 工具图标改 16×16 线性 SVG，path 表放 `tool-meta.ts`，`toolDisplay().icon` 返回 **icon key** 而非 emoji | 与 `chart-box.ts` 的 `kind-ico` 同体系；否决继续用 emoji——跨平台字形不一致、无法跟随 `currentColor` |
| D3 | 中断态 | `ToolSeg.aborted?: boolean`；`aborted` 事件时把**未完成**的同轮工具段标中断；展示为中性灰 pill「已中断」+ 无彩色左条 | 现状中断的工具段永远停在「执行中」转圈，误导为仍在跑。否决「用 done+空结果推断」——正常空结果与中断无法区分 |
| D4 | 原始 JSON | 降级为头部 `{ }` 按钮 → 绝对定位浮层（`top:38px; right:10px; max-height:240px` 自身滚动），点外部 / Esc / 再点关闭 | 默认不占纵向空间；参数已在键值表中文呈现，JSON 只服务调试 |
| D5 | 合并组 | 连续 **≥3 次同一工具**（中间无文本段、无其他工具）合并；**含失败不合并**（保持单卡 + 红条，失败必须一眼可见）；组内含执行中也整体按执行中展示 | 缓解同构卡片连续堆叠；否决「≥2 次就合并」——两次调用信息密度低，合并收益不如直接读 |
| D6 | 结果区口径 | 默认 `max-height:190px`（≈12 行）单滚动；`>12 行` 或（行数 ≤12 且字符 >1200）显示「展开全部 N 行」；展开 420px | 单一滚动机制取代「字符阈值 + clamp + 遮罩 + 按钮」三套并存；1200 字符兜底防止「单行超长被 190px 裁掉却无展开入口」 |
| D7 | 组件归属 | 新建 [ToolCard.vue](file:///D:/trae_workspace/loop-agent-command/webui/src/components/ToolCard.vue)，ChatView 只做分组 + `v-for` | ChatView 已 1421 行；卡片需独立预览页做真实渲染验证，抽组件后预览的就是**真实组件**而非复刻副本。否决「模板内联改造」——预览只能靠复刻，易与实现漂移 |
| D8 | 展开状态归属 | 由 `ToolCard` 实例自持 `ref`（不再用 ChatView 的 `expandedTools` Set） | 卡片自治，少一层 `msgId:segIdx` 字符串 key 传递；代价：切换会话后重挂载会丢展开态（可接受，原型未承诺记忆） |
| D9 | 旧类名 | `.tool-call` 保留为 `.tcard` 的**最小别名**（外框 + 标题栏可读），只保一版 | 沿用 20261023-003 惯例；dist 带内容散列、`index.html` 不缓存，旧页只会短暂共存 |
| D10 | 未知工具图标 | 齿轮（`gear`）对未知工具；拼图（`puzzle`）对 `activateSkill` | 原型 ⑤ 用拼图表示 MCP 工具，但拼图在中文语境更像「技能」，故 MCP/未知改用齿轮 |

### 2.3 借鉴与已知坑

| 来源 | 结论 |
| --- | --- |
| 本仓 `chart-box.ts`（20261023-003） | `inset box-shadow` 画的左侧色条会被**不透明子元素背景**覆盖（子元素绘制在内阴影之上），必须用 `::before` + `z-index`；本次状态条同理 |
| 本仓 `chart-box.ts` | `overflow:hidden` 的卡片会裁掉绝对定位浮层，`{ }` 浮层要求卡片 `overflow: visible` 而内层 `border-radius` 自行收敛 |
| 20261022-001 用户反馈 | `[exit=N]` 只在 `commandRun` 行首锚定判定，否则 `fileRead` 读到测试正文会误判失败；失败原因提取必须沿用该判定，不得放宽 |
| Vue 3 模板 | `<details>` 的 open 状态与响应式数据双写会打架（现实现靠 DOM 状态）；改 `div` + `aria-expanded` 后展开态完全受控，SSE 更新不会意外收起 |

## 三、任务详细设计

### 3.1 `tool-meta.ts`（纯函数层）

```ts
/** 图标 key（与 TOOL_ICON_PATHS 对应） */
export type ToolIconKey = 'book' | 'pencil' | 'wrench' | 'search' | 'terminal' | 'clock'
  | 'lines' | 'stop' | 'puzzle' | 'image' | 'help' | 'table' | 'text' | 'gear';

/** 16×16 线性图标的 inner SVG（stroke 由外层 svg 统一给） */
export const TOOL_ICON_PATHS: Record<ToolIconKey, string>;

/** 完整 <svg> 串（宽高由 CSS 控制），供 v-html 渲染 */
export function toolIconSvg(tool: string): string;

/** 工具显示名：icon 现为 icon key */
export function toolDisplay(tool: string): { icon: ToolIconKey; name: string; known: boolean };

/** 失败原因一句话（副标题直写）：剥 [exit=N]、取首个非空行、截 60 字；无内容 → '执行失败' */
export function toolFailReason(result: string, tool?: string): string;

/** 结果区行数口径（D6）：clamp 后行数；needsExpand 依据它 */
export const RESULT_PREVIEW_LINES = 12;
export const RESULT_PREVIEW_CHARS = 1200;
export function resultLines(result: string): number;
export function resultNeedsExpand(result: string): boolean;
/** 结果区头部meta：`60 行 · 1.8 KB` */
export function resultMetaText(result: string): string;

/** 连续同工具分组（D5）：返回顺序渲染项，tool 项 items 长度 1 时为单卡 */
export interface ToolSegLike {
  tool: string; args: string; result: string; done: boolean;
  elapsedMs?: number; aborted?: boolean;
}
export interface ToolSegItem<T> { seg: T; index: number }
export interface ToolCardVM<T> {
  kind: 'single' | 'group';
  tool: string;
  items: ToolSegItem<T>[];      // single 时长度恒为 1
  index: number;                // 首段下标（渲染 key / 展开状态 key）
  failed: boolean;              // 任一失败
  running: boolean;             // 任一未完成且未中断
  aborted: boolean;             // 全部已中断（且无完成）
  totalMs?: number;             // 各组员耗时之和（全有值才给）
}
export type RenderItem<T> =
  | { kind: 'seg'; seg: T; index: number }
  | { kind: 'tool'; card: ToolCardVM<T> };
export function groupToolSegs<T extends { type: string }>(segs: readonly T[], minCount?: number): RenderItem<T>[];
```

分组规则（`minCount` 默认 3）：
1. 非 `type === 'tool'` 的段原样输出 `{ kind:'seg' }`，并**打断**当前候选组。
2. 连续的 `type === 'tool'` 且 `tool` 相同的段累积为候选；遇到不同工具或文本段即结算。
3. 候选长度 ≥ `minCount` **且** 组内无失败（`toolResultLooksFailed` 对 `done && result` 判定）→ 输出 `kind:'group'`；否则拆成逐个 `kind:'single'`。

### 3.2 `ToolCard.vue`（展示层）

| 区域 | 结构 | 说明 |
| --- | --- | --- |
| 卡片根 | `div.tcard` `:data-state="state"`（`ok/fail/run/aborted`）+ `div.is-open` 控制展开 | 状态条 `.tcard::before`（3px，`z-index:2`） |
| 头部 | `div.tcard-h[role=button][aria-expanded]` → 图标徽标 `.tcard-ico` + `.tcard-txt`（`.tcard-name` + `.tcard-sub`）+ `.tcard-side`（`{ }` / pill / 耗时 / caret） | 组卡名称后缀 `<span class="ttimes">×N</span>` |
| `{ }` 浮层 | `div.tjson`（默认 `display:none`，`.json-open` 时 block） | 头部 `{ } 原始参数` + 复制 + `<pre>` 自滚动 |
| 单卡主体 | `.tl-kv` 键值表（无边框两列 68px）+ `.tl-out`（`out-h` + `pre` + `tl-more`） | 参数来自 `toolParamRows` |
| 组卡主体 | `.tgroup-rows` → `.tgroup-row`（序号 / 状态符 / 副标题 / 耗时） | 含失败默认展开 |

状态优先级：`running`（有未完成且未中断）> `fail`（任一失败）> `aborted`（全部中断）> `ok`。
pill 文案：`执行中` / `失败`（组卡 `有失败`）/ `已中断` / `完成`（组卡 `全部完成`）。

### 3.3 `chat-stream.ts`（数据层）

| 改动点 | 说明 |
| --- | --- |
| `ToolSeg.aborted?: boolean` | 新可选字段，默认缺省 |
| `case 'aborted'` | 遍历本轮 `segments`，把 `type==='tool' && !done` 的段置 `aborted = true`（保留 `done=false`，结果区显示「已中断」） |
| `fetchDetail` 的 `run.status==='aborted'` 分支 | 末尾 assistant 消息里 `result` 为空的工具段补 `aborted = true`，刷新后同样显示中断态而非「完成（空）」 |

### 3.4 边界与错误处理

| 场景 | 处理 |
| --- | --- |
| `args` 非法 JSON | 键值表为空数组；`{ }` 按钮不渲染（无法格式化）；摘要回落紧凑 JSON |
| 结果为空 | 完成态结果区显示「（空）」；执行中显示「执行中…」；中断态显示「用户停止，结果未返回」 |
| 结果超长 | `>20000` 字符硬截断并注明原文长度；否则 `pre` 自身滚动 + 可展开 |
| 单行超长（无换行） | 行数 1 但字符 >1200 也出「展开全部 1 行」入口 |
| 未知工具 | 齿轮图标 + 英文原名 + 紧凑 JSON 摘要（`known:false`） |
| 组内混有执行中 | 整卡 pill「执行中」，不合并不影响；执行完成后若含失败则**下次渲染自动拆组**（纯函数重算，无缓存） |
| 复制失败 | 静默失败（非安全上下文 `document.execCommand` 兜底已在 `chart-box` 验证过，但工具卡不引该依赖，仅 `navigator.clipboard`，失败提示 toast） |

### 3.5 演进项（本任务不做）

- 组卡内单行点击展开该次详情（原型未设计，避免层级再嵌套）。
- 结果区语法高亮 / 折叠（需引依赖，违背零依赖约束）。
- 工具卡「重新执行」按钮（涉及 API 与会话写入，超出展示层范围）。
