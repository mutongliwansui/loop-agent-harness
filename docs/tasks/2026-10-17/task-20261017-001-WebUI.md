## 一、任务目标需求

### 1.1 背景

`--serve` 已提供 46 个 REST 端点（20261016-001/002），但使用门槛仍是 curl/脚本，非技术用户无法便捷使用 Agent 的聊天与运维能力。需要在 API 之上提供浏览器图形界面，让「打开网址即用」成为可能。

### 1.2 现状梳理

| 所需能力 | 现状 | 结论 |
|---|---|---|
| API 面 | 46 端点全覆盖（[http-api.md](file:///d:/trae_workspace/loop-agent-command/docs/readme/zh/http-api.md)） | **直接消费，不新增业务面** |
| 服务骨架 | [server.ts](file:///d:/trae_workspace/loop-agent-command/src/api/server.ts) 统一入口：鉴权 → 路由 → handler → 错误 JSON | **静态托管挂在路由未命中之后**（新增一层，API 行为零变化） |
| SSE | POST /sessions/:id/messages 默认 `text/event-stream`，16 种事件帧 | 浏览器 `EventSource` 无法带 Bearer header → **fetch + ReadableStream 自行解析**（设计文档 §3.4） |
| 鉴权 | 三态：token 空 → 仅本机 / 非空 → Bearer / 非回环无 token 拒启 | WebUI 沿用，静态页不鉴权、API 全 Bearer（D6） |
| 上传 | POST /uploads 收 `{sessionId, paths}`——**服务器本地路径** | 浏览器拿不到文件本地完整路径 → WebUI 用文件选择框 + **新增 `POST /uploads/raw` 二进制端点**（D7）；路径模式端点保留给 CLI/脚本 |
| 构建链 | 仓库无前端工程 | 新建 `webui/` 独立 Vite 工程（D1），产物提交 git（D2） |

### 1.3 任务目标

- 浏览器打开 `http://127.0.0.1:3000/` 即得完整 UI：聊天（多会话 + SSE 流式 + 停止生成 + 对话内上传：文件选择框）+ 管理台（配置/模型/工具/MCP/Skill/记忆/诊断）。
- 46 端点行为零变化；新增「静态文件托管」一层 + `POST /uploads/raw` 一个端点（46 → 47）；运行时零新依赖。
- token 模式：首次进入输入 token（localStorage 记忆），401 自动弹出；无 token 本机模式零感。

### 1.4 设计约束

- **运行时零新依赖**：托管仍 `node:http` 手写；Vue/Vite/marked 等仅在 webui/ 工程内。
- **API 零改动**：既有 46 端点 handler 不动；server.ts 仅追加静态回落层；uploads 组仅**新增** raw 端点（不改既有三路由）。
- **跨平台**：路径穿越防护、MIME 表、缓存头三平台一致。
- **可单元测试**：静态托管层走真实 http server（port 0）+ fetch 断言（沿用 api-endpoints.test.ts 模式）；前端组件不做单测（人工验证清单覆盖）。

## 三、任务详细设计

### 3.1 后端：静态托管层（src/api/static.ts）

```typescript
/** 返回 true = 已响应；false = 放行（保持 404 行为或继续后续层） */
export function serveStatic(root: string): (req: IncomingMessage, res: ServerResponse) => Promise<boolean>
```

- 接入点：[server.ts](file:///d:/trae_workspace/loop-agent-command/src/api/server.ts) `handleRequest` 中 `matchRoute` 未命中且 `req.method === 'GET'` 时调用；`api.webRoot` 配置托管根（默认 `webui/dist`，schema 增加可选字段）。
- 安全：`path.resolve(root, '.' + decodeURIComponent(url.pathname))` 后强制 `startsWith(resolve(root))`，否则 403。
- `/` 与未命中且 Accept 含 text/html → index.html（SPA 兜底）；其余未命中 → false（404）。
- 缓存：`/assets/` 前缀 immutable 一年；index.html no-cache。

### 3.1b 后端：raw 上传端点（新增，端点 46 → 47）

- [src/upload/manager.ts](file:///d:/trae_workspace/loop-agent-command/src/upload/manager.ts) 新增 `writeUpload(sessionKey, fileName, bytes, opts)`：复用既有时间戳命名 / 同名冲突（毫秒段）/ `MAX_UPLOAD_BYTES`（100MB）上限逻辑，落盘到会话隔离上传目录。
- [src/api/handlers/uploads.ts](file:///d:/trae_workspace/loop-agent-command/src/api/handlers/uploads.ts) 新增 `POST /uploads/raw?sessionId=`：请求体 = 文件原始字节，`X-File-Name`（encodeURIComponent）传文件名；会话不存在 404 / 文件名缺失 400 / 超限 413 / 成功 201（响应结构与 POST /uploads 同构：entries + contextNote）。既有三路由（POST/GET/DELETE /uploads）不动。
- 单测：`tests/api-uploads-raw.test.ts`（沿用 api-endpoints.test.ts 模式，port 0 + fetch）：正常落盘 / 404 / 400 / 413 / contextNote 格式。

### 3.3 前端：视图与路由

- 复用组件：StatusBadge（enabled/active/connected…）、JsonViewer（折叠）、ConfirmButton（红字二次点击确认，对应「动词即确认」语义）、UploadPanel（对话内上传 📎 面板 + chip）、Toast。

### 3.4 边界与错误处理表

| 场景 | 处理 |
|---|---|
| webui/dist 不存在 | 静态层跳过；启动日志提示构建命令；纯 API 不受影响 |
| 静态路径穿越（../） | 403 |
| API 4xx/5xx | toast 显示后端 message；409 busy 特殊文案；上传 413 提示「超过单文件上限 100MB」 |
| 401 | 清 token → token 门弹出 |
| SSE fatal/中断 | 消息流终止条 + 保留已收内容 |
| PUT /config api.* | restartRequired 徽标提示「重启生效」 |
