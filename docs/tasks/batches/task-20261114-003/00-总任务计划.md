## 一、需求背景

当前工程的能力单元全部是「模块级单例 + 直接 import」，装配靠人肉编排：

- `src/**` 共 17 处 `export const x = new X()`（16 个自有类实例 + 1 个 `new Set`）
- `src/runtime/init.ts:37` 的 `initRuntime()` 串行 6 个编号阶段
- `src/api/bootstrap.ts:20` 的 `startApiServer()` 195 行、含 9 处 `await import()` 动态装配
- `AgentEvents`（`src/types.ts:596`）16 个回调、`createRoutes()` 返回 `Route[]`——注册后无法成组撤销
- `WorkspaceRuntime`（`src/api/workspace-runtime.ts:41`）硬编码 8 个字段，加第 9 个组件要改 4 个文件

用户长期方向是接入插件生态，借鉴 Cordis 的插件/依赖注入机制，但**不直接引入 npm 包**（`cordis` 仍 `4.0.0-rc.12`；SEA 单文件打包与其运行期磁盘 `import()` 冲突；`deepseek-harness` 是 vendor 源码 + 27 处补丁）。

**本期只做内核定义，不做任何接入**：`core/` 是一个零依赖、零反向依赖的独立库，本期不被本项目任何代码引用。但包契约必须一次写对——用户已明确 core 后续作为基础模块被其他模块引用，契约写错会导致 P3 返工。

## 二、总体设计

```
                    ┌──────────────────────────────┐
                    │  第三方插件（只收 ESM，P3）    │
                    └───────────────┬──────────────┘
                                    │ import（同进程）
┌───────────────┐    P3 接入    ┌────▼─────────────────┐
│ 主工程 src/    │──────────────▶│  @loop-agent/core    │
│ （ESM，SEA）   │   import       │  零依赖 / 零反向依赖  │
└───────────────┘               └──────────────────────┘
        ▲                                 ▲
        │ spawn + HTTP（跨进程）           │ workspaces 链接（单份物理副本）
┌───────────────┐               ┌────────┴─────────────┐
│ desktop/ 外壳  │               │ 根 node_modules       │
│ （CJS，不引用）│               │ @loop-agent/core→core │
└───────────────┘               └──────────────────────┘

内核四件事（全部与业务无关）：
  1. 插件定义      apply(ctx) + inject 依赖声明
  2. Context 容器  ctx.get<T>(key) 按 key 寻址
  3. 类型化事件    emit / serial / parallel / waterfall
  4. 可逆副作用    effect + Fiber 六态生命周期（逆序撤销）
```

设计决策 D1–D17 详见设计方案第四章，本计划按**任务归属**重新组织。

## 五、关键风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| `npm install` 触发 lockfile 大面积变动 | 主工程依赖解析被扰动 | 任务 01 实施后立即 `git diff package-lock.json` 核对，实测预期 +2 条、0 删除；超预期则回滚重来 |
| `tsup` 的 `outDir` 解析基准是 cwd | 从根带 `--config core/tsup.config.ts` 调用会把产物写到根目录 | build 脚本一律在 `core/` 内执行（`npm run build -w`），并在任务 01 验收项中显式检查产物落点 |
| `core/tests` 被主工程 vitest 误收集 | 全量回归混入 core 测试、计数变化 | 根 `vitest.config.ts:18` 的 `include` 仅 `tests/**/*.test.ts`，不加 core；任务 01 验收项核对文件数仍为 213 |
| 根 `tsconfig.json` 把 core 纳入检查 | 主工程 typecheck 报 core 的错误 | 根 `include` 仅 `src/**`+`examples/**`，天然不含 core；任务 01 验收项显式核对 |
| 包契约（`exports`）写错 | P3 接入返工，或双副本静默错误 | 任务 01 就把契约写全并在 P1 做最小冒烟（早暴露），任务 04 再做完整回归 |
| 忘记 `default` 条件 | CJS 侧 `require` 抛 `ERR_PACKAGE_PATH_NOT_EXPORTED` | 任务 01 验收项含「去掉 `default` 必须能复现该错误」的反向验证 |
