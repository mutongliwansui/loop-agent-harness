## 二、方案设计

### 2.1 为什么这些核验必须**分开**做

单看「`npm test` 全绿」是不够的，四个核验各自能挡住不同性质的破坏：

| 核验 | 能挡住什么 | 挡不住什么 |
|---|---|---|
| `tsc --noEmit` | core 的类型改动泄漏进主工程检查范围、`@types` 提升引起的类型冲突 | 运行期行为变化 |
| 全量 vitest | 依赖解析变化、单例被意外共享 | 构建期问题、产物污染 |
| `build` + 产物内容检查 | core 被误当作主工程依赖打进 `dist/` | 运行期问题 |
| `build:sea` | SEA 的 CJS 打包与 core 的纯 ESM 冲突（这正是当初拒绝引入 `cordis` 的理由） | 磁盘版行为 |

其中 `build:sea` 是最有信息量的一项：SEA 走 `tsup --format cjs` 单文件打包，若 core 被误引入，纯 ESM 的 core 会在 CJS 打包链上出问题，或被打成第二份副本。

### 2.2 产物内容检查的做法

不依赖「体积没变」这种脆弱判据（主工程代码本身就随改动变大变小），而是**在产物里搜 core 的独有标识符**：

```
CORE_SERVICE_CONFLICT   ← 只在 core 的错误族里出现
TypedEventBus           ← 只在 core 的事件总线里出现
PluginRegistry          ← 只在 core 的清单挂载里出现
```

三者都搜不到，才说明 core 确实没进包。这比比对文件大小更准确：即便主工程代码量变化，core 的标识符一旦出现就是确定的污染。

### 2.3 独立性核验为何也查 `desktop`

设计文档里 `desktop/` 是**纯 CJS 外壳，不引用 core**（它与主进程走 spawn + HTTP 跨进程通信，不共享进程内实例）。若它开始引用 core，就会出现两份副本、`instanceof` 失效，恰好踩中 README 里写的那条铁律。所以扫描 `desktop/` 与 `webui/` 的源码与配置，是对该结论的持续校验。

## 三、任务详细设计

### 3.1 执行顺序

四项核验的耗时差异很大，串行会白等：

| 步骤 | 命令 | 典型耗时 | 执行方式 |
|---|---|---|---|
| ① 类型检查 | `npx tsc --noEmit` | 10–20s | 前台 |
| ② SEA 构建 | `npm run build:sea` | 30–60s | 前台（与③并行） |
| ③ 全量回归 | `npx vitest run` | 60–70s | **后台**，轮询日志 |
| ④ 主工程构建 | `npm run build` | 5–10s | 前台 |
| ⑤ webui 构建 | `npm run build:webui` | 40–60s | **后台** |

③⑤ 放后台的原因：都超过前台 30s 超时，且与 ②④ 互不干扰（不改同一批文件）。

### 3.2 全量回归的基线口径

改造前的基线为 **213 个测试文件**（`unit` 205 + `integration` 8）。核验时看三个数：

- 文件数必须**仍为 213**（core/tests 不得被根 vitest 收集）
- `passed` 数不得低于改造前
- `failed` 必须为 **0**

`skipped` 允许存在（部分集成用例依赖外部环境，改造前即有 skip）。

### 3.3 `git status` 的期望形态

改动应只出现在「新增」与「包的元数据」上：

```
 M .gitignore                                  ← 忽略 core/dist 等产物
 M docs/requirements/需求.md                    ← 需求台账登记
 M package-lock.json                           ← workspaces 带来的 lock 变动
 M package.json                                ← 新增 workspaces 字段
?? core/                                       ← 新子包
?? docs/designs/…/设计方案-20261114-003+…md     ← 设计文档
?? docs/tasks/batches/task-20261114-003/       ← 任务文档
```

`src/`、`tests/`、`tsconfig.json`、`vitest.config.ts` **必须**不出现在列表中。
