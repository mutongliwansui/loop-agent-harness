## 一、需求背景

WebUI 与 `--serve` 模式下，技能 / MCP / 工具启停 / 模型 / 通用配置长期存在「工作空间级」与「全局」两份可选写入层。实测本机数据分布表明：

- 模型、MCP、skill **本已只存在于全局**
- 真正滞留工作空间层的只有 541B：`tools.enabled`（12 项白名单）、`tools.disabled`、`memory.working`、`agent.debug/maxIterations`、`webui.terminal`、`vision.enabled`

用户决策：**五类配置一律只保留全局一份，WebUI 与 serve 均不再保留工作空间级配置，CLI 同口径。**

## 二、总体设计

```
default < env < global < cli        ← 五层降为四层（删 workspace）
~/.loop-agent/config.json          ← 唯一配置事实源
~/.loop-agent/skills/              ← 唯一 skill 目录
{ws}/.loop-agent/                  ← 不再生成配置与 skills

进程级单例：configLoader / configWriter / skillLoader / mcpManager / mcpMonitor
每空间保留：SessionStore / AgentPool / memory kit（内容仍按空间隔离）
```

设计决策 D1–D11 详见设计方案第四章，本计划按任务归属重新组织。
