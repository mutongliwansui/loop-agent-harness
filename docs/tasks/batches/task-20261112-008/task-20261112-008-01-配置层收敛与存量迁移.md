## 一、任务目标需求

### 1.1 背景（痛点）

`src/config/loader.ts` 当前是五层合并（`default < env < global < workspace < cli`），`src/config/writer.ts` 的 `ConfigScope = 'workspace' | 'global'`，两者共同构成「配置可按工作空间覆盖全局」的能力。用户已决策该能力整体移除，以免：

- 前端不传 scope 时静默写入工作空间层，用户以为改了全局
- `--global` 切换模型被工作空间同键静默盖住（`src/commands/model-command.ts:164-175` 已为此写了一段冲突清理向导）
- serve 下 N 个空间各持一份 ConfigLoader，MCP/skill 扫描与配置读取都按空间重复

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| 分层合并 | `loader.ts:87-93` deepMerge 五层；`resolveSources:212-217` 五层溯源 | 需降为四层 |
| 工作空间配置路径 | `loader.ts:62-65`、`writer.ts:25-27` | 需删除 |
| 写入分层 | `writer.ts:47-65` `updateScope` 双分支；`68-80` `deleteScopeKey` 双分支 | 需单值化 |
| 单例 | `loader.ts:290` `new ConfigLoader()`（cwd 兜底）；`writer.ts:143` `new ConfigWriter()` | 统一为全局目录 |
| 存量数据 | 本机 541B `.agent-config.json` 含 `tools.enabled` 等 6 键 | 需一次性迁移 |

### 1.3 任务目标

- `load()`/`loadAsync()` 只合并 `default < env < global < cli`
- `ConfigLoader` 构造只接 `globalDir`；删除 `workspaceConfigPath`
- `ConfigScope` 类型删除；`updateScope`→`update`、`deleteScopeKey`→`deleteKey`
- 新增 `migrateWorkspaceConfigToGlobal()`：把存量工作空间配置按「workspace 值优先」并入全局，原文件备份 `.bak-<ts>`，幂等
- `loadWorkspace()`/`loadWorkspaceSync()` 保留为**迁移专用**读函数（或移入 migrate.ts），不再参与合并

### 1.4 设计约束

- 零新依赖；三平台路径兼容
- 迁移失败只告警，绝不阻断启动
- 不改变 `DEFAULT_CONFIG` 与 `schema.ts` 的 `ConfigSource` 之外的结构
- `maskSecretsDeep`、`ConfigWriter.parseKey`/`getByKey`/`setByKey` 行为不变

## 二、方案设计

### 2.1 总体思路

```
读取路径（改造后）
  DEFAULT_CONFIG ─┐
  process.env     ├─► deepMerge ─► ResolvedConfig
  config.json     │   （global）
  cliOverrides    ┘

写入路径（改造后）
  update(partial) ──► deepMerge(config.json 现值, partial) ──► 写 config.json
  deleteKey(key)  ──► 删 config.json 中的键 ──► 写回

启动迁移（一次性，D6）
  {ws}/.agent-config.json ──┐
                            ├─► deepMerge(global, ws)  ← ws 值胜出
  ~/.loop-agent/config.json ┘        │
                                     └─► 写 config.json + ws 文件改名 .bak-<ts>
```

### 2.2 关键设计决策

- **D1（对应设计方案 D1）**：五层降四层，整层删除 workspace，不做「读但忽略」的兼容。
  - 被否决：继续读 workspace 再忽略（会产生「文件写着却不生效」的长期困惑）
  - 被否决：serve 下强制 global 而 CLI 保留 workspace（正是当前 bug 的来源）
- **D2**：`ConfigLoader` 构造签名 `constructor(globalDir = loopAgentHome())`，删除 `workspacePath` 字段。
  - 被否决：保留参数但忽略（调用方误以为仍可分层）
  - 被否决：加 `mode: 'cli' | 'serve'`（Q1 已定同口径，枚举是多余复杂度）
- **D3**：`ConfigScope` 类型删除，方法改名 `update(partial)` / `deleteKey(key)`。
  - 被否决：保留 `scope` 形参恒传 `'global'`（噪声）
  - 被否决：保留旧方法名做别名（scope 概念阴魂不散）
- **D6**：迁移**以 workspace 值为准**（`deepMerge(global, ws)`），源文件改名为 `.bak-<ts>`。
  - 理由：改造前 workspace 覆盖 global，它才是当前生效值；若 global 胜出，用户 `tools.enabled` 白名单会静默失效
  - 被否决：仅告警不迁移（升级后行为突变）
  - 幂等：`.bak-` 已存在则跳过该空间

### 2.3 联网检索结论

本次为仓库内部配置体系收敛，无外部同类实现可借鉴；已核对 Node `fs.rename` 在同卷内为原子操作，跨卷会 `EXDEV` 失败——迁移改用「先写 global 再 rename 源文件」，两者都在各自卷内，不跨卷。

## 三、任务详细设计

### 3.1 `src/config/loader.ts`

```ts
export class ConfigLoader {
  private globalDir: string;
  constructor(globalDir = loopAgentHome());

  get globalConfigPath(): string;          // 保留
  // get workspaceConfigPath 删除

  load(cliOverrides?: PartialAgentConfig): ResolvedConfig;       // 四层
  async loadAsync(cliOverrides?: PartialAgentConfig): Promise<ResolvedConfig>;
  loadGlobal(): Promise<PartialAgentConfig>;                     // 保留
  loadGlobalSync(): PartialAgentConfig;                          // 保留
  // loadWorkspace / loadWorkspaceSync 移入 migrate.ts（仅供迁移读取）
}
```

`resolveSources` 中 `orderedLayers` 删除 `{ name: 'workspace', ... }` 项；`ConfigSource` 联合类型删除 `'workspace'`。

**边界与错误**：

| 情形 | 行为 |
|---|---|
| `config.json` 不存在 | 与现状一致：按 default/env/cli 合成 |
| `config.json` JSON 损坏 | 与现状一致：捕获后按空对象处理（不新增行为） |
| 迁移时 `{ws}/.agent-config.json` 损坏 | 跳过该空间，日志告警，不阻断 |
| 迁移时 `rename` 失败 | 捕获告警，global 已写入不回滚（幂等可重跑） |

### 3.2 `src/config/writer.ts`

```ts
export class ConfigWriter {
  constructor(globalDir?: string, opts?: ..., loader?: ConfigLoader);
  get globalConfigPath(): string;
  async writeGlobal(config: PartialAgentConfig): Promise<void>;   // 保留
  async update(partial: PartialAgentConfig): Promise<void>;       // 原 updateScope('global')
  async deleteKey(keyPath: string[]): Promise<void>;              // 原 deleteScopeKey('global')
  // writeWorkspace 删除
  static parseKey(key: string): string[];
  static getByKey(...); static setByKey(...);                     // 不变
}
```

### 3.3 `src/config/migrate.ts`（新增）

```ts
export interface MigrateResult {
  scanned: number;
  migrated: Array<{ root: string; keys: string[]; backupPath: string }>;
  skipped: Array<{ root: string; reason: string }>;
}

export async function migrateWorkspaceConfigToGlobal(opts: {
  globalDir: string;
  candidateRoots: string[];
  log?: (msg: string) => void;
}): Promise<MigrateResult>;
```

- 候选根：`~/.loop-agent/sessions/*/meta.json` 的 `workspacePath` ∪ 传入的 `candidateRoots`
- 每个根：存在 `.agent-config.json` → 读 → `deepMerge(global现値, ws值)` → `writeGlobal` → `rename` 源文件为 `.bak-<ts>`
- 空对象 `{}` 视为无内容，直接备份不合并
- 全程 try/catch

### 3.4 演进项（本任务不做）

- 自动清理历史 `.bak-*` 文件
- 迁移进度的可中断/续跑（幂等已足够）
