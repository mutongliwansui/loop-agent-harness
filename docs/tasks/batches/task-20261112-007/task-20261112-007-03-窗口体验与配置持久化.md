## 一、任务目标需求

### 1.1 背景（痛点）

任务 01/02 之后「能用」但「不好用」：窗口每次都是默认大小位置（用户调过的尺寸丢失）；启动到界面出现之间是空白，用户不知道后端在干什么；应用的图标还是默认 Electron 图标。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| 窗口尺寸/位置记忆 | 无 | 需自实现，Electron 无内置持久化 |
| 首选端口来源 | `ApiConfig.port`（`src/config/schema.ts:343-345`），全局配置在 `~/.loop-agent/config.json`（`src/config/loader.ts:67-68`） | 壳可零依赖读 JSON 取 `api.port` |
| 配置加载器 | 主工程 `ConfigLoader` 支持 CLI/env/workspace/global 分层（`src/config/loader.ts:55-68`） | **壳不应复用**：壳打包后只有自己的代码，且窗口状态不是业务配置 |
| 应用图标 | 前端图标规范为 16×16 内联 SVG（`webui/src/tool-meta.ts`），无 `.ico` | 壳/安装器需单独提供 PNG→ico |
| 加载态 | 后端启动约 2.5s（实测） | 需加载页，否则用户以为卡死 |

### 1.3 任务目标

1. 记住窗口尺寸/位置，下次启动恢复；显示器变化时**不跑到屏幕外**
2. 启动期显示加载页（含阶段文案），失败显示错误页并可重试
3. 提供应用图标（窗口 + 任务栏 + 安装器）
4. 首选端口能跟随用户在 `config.json` 里的 `api.port` 设置

### 1.4 设计约束

- **不修改主工程 `config.json` 结构**（不加 `desktop.*` 节）
- 不改前端代码
- 不引入第三方窗口状态库（零依赖优先）

## 二、方案设计

### 2.1 总体思路

```text
首次启动                              后续启动
   │                                    │
   ├─ 读 userData/window-state.json ────┤ 有则用，校验是否在可见屏幕内
   │   （无 → 默认 1440×900 居中）        │
   ├─ 读 ~/.loop-agent/config.json 的 api.port → 首选端口
   ├─ 显示加载页（BrowserWindow 自带 html，不走网络）
   ├─ 任务01 的编排：spawn → health → 就绪
   ├─ 就绪 → loadURL → ready-to-show 后再 show
   └─ 窗口 move/resize（防抖 500ms）→ 写回 state
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与理由 |
|---|---|---|
| **D3-1** | **窗口状态与首选端口不进主工程 `config.json`；窗口状态存 `app.getPath('userData')/window-state.json`** | 对设计方案 D9 的**实施级修正**：D9 原设想加 `desktop.*` 配置节，但壳打包后**只有自己的代码**，无法（也不该）复用主工程的分层 `ConfigLoader`；而窗口宽高位置本质是 UI 状态，不是业务配置。放 `userData` 是 Electron 标准位置（Win 下 `%APPDATA%\LoopAgent`），`--serve` 完全不受影响。**否决写进 `config.json`**（会让壳依赖主工程配置体系，且把 UI 状态混进业务配置）。 |
| **D3-2** | **首选端口读 `~/.loop-agent/config.json` 的 `api.port`，读不到/非法则 3000** | 用户若把 `api.port` 改成 8080，桌面版与浏览器版端口一致，排障时不会「两个地址」。只读一个 JSON 字段，零依赖、不引入配置分层。 |
| **D3-3** | **恢复窗口位置前做可见性校验：必须与任一显示器 workArea 有足够交集（≥100×100 像素），否则回退默认居中** | 典型坑：用户拔掉第二显示器后，保存的位置落在不存在的屏幕上，窗口「消失」。这是窗口状态持久化最常见的 bug。 |
| **D3-4** | **加载页用 `loadURL('data:text/html,...')` 或本地临时 html，就绪后才 `loadURL(后端地址)`** | 若直接 loadURL 后端地址，后端未就绪时 Electron 显示 `ERR_CONNECTION_REFUSED` 错误页，观感极差。加载页自带阶段文案（「正在启动服务…」→「正在准备记忆…」）。**否决「先开窗口让页面自己重试」**（同 D1-4）。 |
| **D3-5** | **加载页与错误页文案用中文，错误页提供「重试」「查看日志」「退出」三个动作** | 现场用户是中文非技术用户；「查看日志」打开壳捕获的后端日志尾部，避免让用户自己去翻文件。 |
| **D3-6** | **图标：提供 1024×1024 PNG 作为唯一源，`.ico` 在任务 04 由构建流程生成** | 单一源避免多份图标不一致；P0 阶段窗口图标可用 PNG 占位，不阻塞功能。 |
| **D3-7** | **窗口 `minWidth/minHeight` 限制为 1024×700** | WebUI 在 ≤900px 会切窄屏管理菜单（既有实现），限制最小宽度避免用户拖到不可用尺寸。 |

### 2.3 检索依据

- Electron `screen.getDisplayMatching` / `workArea` 用于多显示器校验（官方 API）
- 窗口状态文件属 UI 状态，放 `app.getPath('userData')` 为 Electron 惯例

### 3.3 边界与错误处理

| 场景 | 现象 | 处理 |
|---|---|---|
| 状态文件损坏/非法 JSON | 启动异常 | 忽略并使用默认值，记录日志，不阻塞启动 |
| 状态文件只读/磁盘满 | 写入失败 | 静默忽略（仅日志），不影响使用 |
| 保存的位置在已断开显示器 | 窗口不可见 | D3-3 校验回退居中 |
| 保存尺寸小于最小限制 | 窗口过小 | 夹到 `minWidth/minHeight` |
| 最大化状态保存/恢复 | 恢复后没最大化 | 单独存 `maximized` 标志，恢复顺序：先 setBounds 再 maximize |
| 加载阶段后端失败 | 白屏 | 切错误页，含日志尾部与重试 |
| 后端迟迟不就绪 | 加载页停住 | 加载页显示已耗时，超时转错误页（复用任务 01 的 60s 上限） |
| 用户点「查看日志」 | 无 UI | 打开新窗口渲染日志尾部文本（只读，等宽字体） |

关键结论：

1. **`getNormalBounds()` 而非 `getBounds()` 是最大化恢复正确的关键**：最大化时 `getBounds` 返回屏幕尺寸，直接存会让下次启动得到一个「假最大化」（还原后铺满全屏且无法变小）。实测最大化为 true 时存回 `1100×800` 还原尺寸，重启后 `STATE=maximized` 且还原尺寸未污染。
2. **高 DPI（本机 150%）下 setBounds 与 getNormalBounds 存在一次性 +2px 取整偏移，但不累积**：三轮往返中仅有第一轮 `1180→1182`，之后稳定在 1182，证明不是逐次增长——这是 DPI 1.5 的物理像素取整，属正常行为，无需修正。真机验证容差取 ±4px。
3. **越界位置回退必须用「交集面积」而非「左上角在屏内」**：只露 1px 边缘的窗口左上角可能仍在屏内，但用户实际找不到。`isStateVisible` 要求交集 ≥100×100，伪造 `x=99999,y=99999` 后窗口回退到 `RECT=253,99,1200,820`（主屏工作区 1707×1019 内完整可见）。
4. **小于最小限制的旧状态会被夹到下限**：预置 `600×400` 启动后存回 `1026×702`（1024×700 + 边框），说明夹取在「读到即夹」阶段生效，而非仅靠窗口 `minWidth`。
5. **错误页路径已验证但触发方式需注意**：把 `dist-sea/loop-agent.exe` 改名并不能造出 `BackendNotFoundError`——`resolveBackend` 会回落到 `tsx src/index.ts`（开发期回落，见 `backend-path.ts:64-69`），此时因配置里的模型地址不可用而表现为健康检查超时，错误页文案为「后端启动超时」，与实际原因一致。若要真实验证 `BackendNotFoundError`，需同时移除 `src/index.ts` 或直接以 `isPackaged` 形态测试。

验证环境提示（供后续任务复用）：

- **Electron 未实现 CDP 的 `Browser.getWindowForTarget` / `setWindowBounds`**：调用返回错误、无 `windowId`，不能用它读取或搬动窗口。改用 Win32 `GetWindowRect` / `GetWindowPlacement` / `MoveWindow`（经同名 `.ps1` 调用），`GetWindowPlacement.showCmd` 可区分 `normal`/`minimized`/`maximized`。
- **PowerShell 变量名大小写不敏感**：脚本里窗口句柄变量若命名为 `$h`，会覆盖 `param([int]$H)`（高度），导致 `MoveWindow` 把句柄当高度传入、窗口高度变成 32767。句柄一律命名 `$hwnd`，高度参数命名 `$Hgt`。
- 验证脚本里内嵌 PowerShell here-string 会被 JS 模板字符串的 `${}` 插值破坏，且 `powershell -File` 按 GBK 解析脚本 → 含 `Add-Type` 的脚本一律独立成纯 ASCII `.ps1` 文件，用 `execFileSync` 传参调用。
- 前台命令 30s 即超时，涉及 90s 等待的验证脚本须用后台任务运行并轮询日志。
