## 一、任务目标需求

### 1.1 背景（痛点）

任务 01 之后，「名称 + 日期」已能同行，但仍是**一行文本**（`xxx.ps1 2026/11/12 17:19`）。当模型需要「逐行逐列对齐」或「按列筛选」时，纯文本仍要靠猜空格边界。同时用户辨认小字必须在 `temp/` 手写放大与裁剪脚本，能力缺口外溢成手工成本。

### 1.2 现状梳理

| 需求 | 现状 | 结论 |
| --- | --- | --- |
| 表格输出 | 无；`OcrResult` 只有 `text` | 新增 `layout=table`（x 投影列聚类 → markdown） |
| 词级坐标 | 无（`out.json` 里有了，但不对外） | 新增 `layout=words`（TSV） |
| 放大 | 无参数，用户手写 PS 脚本 | 新增 `scale`（1–4 整数，`BitmapTransform` + `HighQualityCubic`） |
| 裁剪 | 无参数，用户手写 PS 脚本 | 新增 `crop`（`[x,y,w,h]`，`BitmapBounds`） |
| 缓存 | `cache.ts` 存 `string`，key 含 `OCR_CACHE_VERSION`（手工常量）+ engine + lang + 图片哈希 | 改存结构化快照；key 加 `scale`/`crop`；版本升 `v2` |
| `maxChars` | `ocrImage.ts:54` `Math.min(入参, cfg.maxChars)` → **只能缩小不能放大**；`:63` `slice` 会把行切一半 | 配置改默认值、入参可上浮到硬顶；截断改按行 |
| 耗时 | `elapsedMs` 只含 `RecognizeAsync`，不含进程启动与解码 | 分段计时并如实展示 |
| 工具预算 | 4400 字符、实测 4379，且**不含 `ocrImage`**（需引擎探测才注册） | 重定基线 5000 并把 `ocrImage` 纳入口径 |

### 1.3 任务目标

1. `layout` 参数三档：`text`（默认，任务 01 已实现）/ `table`（markdown 表格）/ `words`（TSV 坐标）；
2. 表格列聚类用 **x 投影空白带**（不用词起点聚类），阈值 `median(h) × 1.5`，列数 ≥2 且行数 ≥3 才输出表格，否则回落 `text`；
3. `scale`（1–4 整数）与 `crop`（`[x,y,w,h]`）在 PowerShell 内用 `BitmapTransform` 完成，**不引入图像库**；放大后超 `MaxImageDimension` 时明确报错并提示降 scale；
4. 缓存改存结构化快照，使同一张图在不同 `layout` 下复用同一份缓存（避免切 layout 就重跑 1s OCR）；
5. `maxChars` 语义修正：`ocr.maxChars` 变默认值，入参可上浮至硬顶 `200000`；截断按行进行；
6. 耗时改为分段展示（识别 / 进程与解码），缓存命中显示 `0s（缓存）`；
7. 工具描述预算基线重定为 5000（含 `ocrImage`），并压缩既有描述对冲。

### 1.4 设计约束

- 工具描述与参数 schema 受 `tests/tool-description-budget.test.ts` 约束，新增参数**必须**同步该测试口径与中英双语文档；
- `scale`/`crop` 只影响引擎输入，不得改变 `OcrResult.text` 的语义；
- 无 bbox 的引擎（http）在 `layout !== 'text'` 时**降级 + 告警**，不抛错；
- 非 Windows 平台行为与当前完全一致（工具不注册）；
- 零新增依赖；幂等约束继续成立。

## 二、方案设计

详 [设计方案 §四 D4/D5/D6/D7/D8/D9/D11/D12](../../../designs/2026-11-12/设计方案-20261112-003+OCR行结构与版面还原.md)。

### 2.1 列聚类：为什么必须用投影法

任务 01 的原型用「词起点一维聚类」，实测切出 **7 个碎簇**：

```
列起点簇： 20~465 | 501 | 537~751 | 787 | 805 | 842~900 | 1116 | 1159~1262
```

碎的原因是**日期内部也有空格**（`2026` / `/` / `11` / `/` / `12`）。

投影法改为看「整列空白」：把该视觉行所有词投到 x 轴，**所有词都未覆盖**的区间才是列边界。日期内部的空格在别的行被数字覆盖，因此不会成为列边界。这正是 OCR 版面分析的通行做法。

### 2.2 三档输出

| layout | 输出 | 判定 |
| --- | --- | --- |
| `text` | 视觉行文本，1 行 1 条 | 默认 |
| `table` | `\| 名称 \| 修改日期 \|` + 分隔行 + 21 行数据 | 列数 ≥2 且行数 ≥3 |
| `words` | `x\ty\tw\th\ttext` 逐词 | 供精确几何推理 |

表格单元格文本先过 `mergeCjkSpaces`（否则格内是「小 智 前 后 台」）；空单元格输出空串。

### 2.3 预处理链

```
原图 Bytes → BitmapDecoder
   → BitmapTransform { ScaledWidth/Height = round(w*scale), InterpolationMode = HighQualityCubic,
                       Bounds = crop }   ← 新增
   → GetSoftwareBitmapAsync(transform, ExifOrientationMode, ColorManagementMode)
   → RecognizeAsync
```

`scale=1` 且无 `crop` 时**跳过** transform，保持现行路径（零额外开销）。

## 三、实施计划

1. **脚本侧**：加 `-Scale` / `-Crop` 参数；`scale≠1` 或 `crop` 非空时构造 `BitmapTransform` 并走 `GetSoftwareBitmapAsync(transform, …)` 重载；放大后尺寸校验；`Stopwatch` 分 `transform`/`recognize` 两段，stdout 增 `T_*` 键。
2. **类型侧**：`OcrOptions` 增 `layout/scale/crop`；新增 `OcrLayout` 联合类型；`OcrImageSize`。
3. **布局层**：`clusterColumns()`（x 投影）、`renderTableLayout()`、`renderWordsLayout()`；`renderLayout(lines, layout)` 统一入口，含回落逻辑。
4. **编排侧**：`runOcr` 接受 layout/scale/crop；缓存存 `{text, lines, imageSize}` 快照；`truncateOcrText` 改按行截断并返回被丢弃行数。
5. **工具侧**：`ocrImage.ts` 增 `layout`（enum）/`scale`（integer 1–4）/`crop`（number[]），description 各 ≤30 字符；`maxChars` 改可上浮；结果头补 `布局: table`。
6. **配置**：`schema.ts` 增 `ocr.layout`（默认 `text`）、`ocr.maxCharsHardLimit`（默认 200000）；`maxChars` 注释改「默认值」。
7. **缓存**：`OCR_CACHE_VERSION` → `v2`；key 加 `scale`/`crop`；值类型放宽。
8. **预算测试**：`tool-description-budget.test.ts` 增加「模拟引擎可用」分支纳入 `ocrImage`；`BUDGET_CHARS` 4400→5000、`BUDGET_TOKENS` 1100→1250，注释写明口径变更。
9. **前端**：`webui/src/tool-meta.ts` 的 `ocrImage` 参数标签补 `layout`/`scale`/`crop` 中文名。
10. **文档**：`docs/readme/{zh,en}/built-in-tools.md` 增三参数说明 + 表格/坐标示例；`configuration.md` 增 `ocr.layout`、`maxCharsHardLimit`。
11. **单测**：投影聚类（含 7 碎簇反例必须聚成 2 列）、三档渲染、回落、scale/crop 参数透传、按行截断、缓存 key 与快照、预算测试。

## 六、风险与回滚

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 投影法在正文段落上误判成多列 | 表格化后语义破碎 | 设「列数 ≥2 且行数 ≥3」门槛；不满足回落 `text`；默认 `text` 不自动触发 |
| `BitmapTransform` 在 PS 5.1 不可用 | 内网机 scale/crop 失效 | 属 WinRT 投影 API 非 PS 语言特性，5.1 可用；本地 `powershell.exe` 实测把关 |
| 预算抬高 600 字符 | 每轮多约 150 token | 同步压缩既有描述对冲；基线变更写入测试注释 |
| 缓存结构升级致首轮全 miss | 冷启动多 1s | 一次性代价，可接受 |
| `crop` 坐标越界 | 脚本异常 | 参数校验：`x+w ≤ width`、`y+h ≤ height`，越界报 `bad_input` |

**回滚**：`layout` 默认 `text`、`scale` 默认 1、`crop` 缺省整图 → 不传新参数时行为与任务 01 完全一致；如需整体回退，去掉工具 schema 三参数即可，引擎与缓存改动向后兼容（`out.txt` 仍在）。
