## 一、任务目标需求

### 1.1 背景（痛点）

`fileRead` 与 `grep` 以「可直接按 UTF-8 逐行读取」为前提：读取前用前 8000 字节是否含 NUL 判定二进制，直接拒绝或跳过。doc/docx 因此完全不可达，Agent 只能靠 `commandRun` 调用本机不一定存在的 Office/转换工具。

### 1.3 任务目标

1. 新增 `src/documents/` 文档层骨架：类型、格式识别、提取调度、Word 提取；
2. `fileRead` 能读取 doc/docx，返回带行号的提取文本，`startLine/endLine`、`maxBytes`、`lineNumbers` 语义与文本路径一致；
3. `grep` 能在单个 doc/docx 与混合目录中检索，输出仍为 `path:line: content`；
4. 不支持的二进制、损坏 Word、过大文件给出可纠正的中文提示；目录检索跳过失败文档并汇总；
5. 原有 `tests/file-read.test.ts`、`tests/grep.test.ts` 零改动通过；
6. 中英双语文档补充支持格式与行号语义。

### 1.4 设计约束

- 零新增 npm 依赖；doc/docx 统一走 `word-extractor`；
- 文本文件路径字节级行为不变；文件头只读一次，与现有 NUL 嗅探共用缓冲区；
- 文档提取结果统一规范化：CRLF/CR → LF、连续空行折叠、去行尾空白；
- 文档行号为**提取文本行号**，输出首行必须显式说明；
- 不新增工具名、不改 `ToolContext`、不改 runner 超时；
- 本期不实现 PDF 提取与 `pages` 参数（由任务 02 提供）；PDF 被识别后返回明确的「暂不支持/待启用」提示，而不是 NUL 二进制错误。

## 二、方案设计

### 2.1 总体思路

```
fileRead(path) / grep(path)
        │
        ▼
  readHead(fh, ≤8KB) ───────────────┐
        │                          │（text：原 NUL 判定，行为不变）
        ▼                          ▼
  detectDocumentKind()  ── text ──▶ 现有 readFull / readRange / 逐行搜索
        │
     doc/docx
        │
        ▼
  extractDocument()  ──▶  normalizeText()  ──▶ 行数组
        │                                      │
        │                                      ├─ fileRead：行号/区间/maxBytes/截断提示
        │                                      └─ grep：逐行正则 + 失败汇总
        └─ 其他 kind → DocumentExtractError(unsupported)
```

图中 D 编号对应设计方案 D2/D5/D8/D9。

### 2.2 关键设计决策

| 编号 | 决策 | 推荐 | 被否决项与理由 |
| --- | --- | --- | --- |
| **T1-D1** | 文档层独立为 `src/documents/`，工具层只加识别分支与行渲染 | ✅ | 否决在工具内直接写解析：两处重复且与 `/fs/doc2md` 漂移 |
| **T1-D2** | 识别用魔数 + 扩展名双校验；魔数优先，冲突附警告 | ✅ | 否决只看扩展名：改名文件会误走文本路径 |
| **T1-D3** | doc/docx 复用 `word-extractor.getBody()`，只取正文文本 | ✅ | 否决新增 mammoth：新增根依赖，本期只需要可读文本 |
| **T1-D4** | 提取文本统一规范化后再交给行管线 | ✅ | 否决原样输出：Word 的 CRLF/多余空行会污染行号与 grep 结果 |
| **T1-D5** | 文件头只读一次：识别与 NUL 嗅探共用 8KB 缓冲 | ✅ | 否决两次读盘：增加所有文本读取的 I/O |
| **T1-D6** | 单文件调用失败抛错（由 runner 归一化）；目录检索内部捕获并汇总 | ✅ | 否决目录遇错即停：一个坏文件毁掉整次搜索 |
| **T1-D7** | 文档行号为提取文本行号，首行声明；PDF 暂不提供页语义 | ✅ | 否决伪装成原文件行号：模型无法对照，后续 `startLine` 也会误导 |
| **T1-D8** | 资源上限写死常量：源文件 50MB、提取文本 5M 字符、目录提取合计 20s | ✅ | 否决新增配置：本期无差异化需求，配置面越大越易漂移 |
| **T1-D9** | 本期 PDF/xlsx/pptx 等被识别但提取抛 `unsupported`，提示等待对应任务启用 | ✅ | 否决不识别：会退回 NUL 报错，用户无法判断是格式不支持还是文件损坏 |

## 三、任务详细设计

### 3.1 模块与接口

```ts
// src/documents/types.ts
export type DocumentKind = 'doc' | 'docx' | 'pdf' | 'rtf' | 'odt' | 'xlsx' | 'pptx';

export interface DetectResult {
  kind: DocumentKind | 'text';
  /** 扩展名与魔数冲突时的说明 */
  warning?: string;
}

export interface ExtractOptions {
  /** 源文件大小上限（字节） */
  maxBytes: number;
  /** 单文档时间预算（毫秒） */
  timeBudgetMs?: number;
  signal?: AbortSignal;
}

export interface ExtractResult {
  kind: DocumentKind;
  /** 规范化后的提取文本（LF 换行） */
  text: string;
  /** P1 起用于 PDF/PPTX；本期恒为 undefined */
  pages?: Array<{ page: number; startLine: number; endLine: number }>;
  pageCount?: number;
  warnings: string[];
  truncated: boolean;
}

export type ExtractErrorCode =
  | 'unsupported' | 'corrupt' | 'encrypted' | 'too_large' | 'scanned' | 'timeout' | 'empty';

export class DocumentExtractError extends Error {
  constructor(readonly code: ExtractErrorCode, message: string);
}
```

```ts
// src/documents/detect.ts
export function detectDocumentKind(absPath: string, head: Buffer): DetectResult;

// src/documents/extract.ts
export function normalizeText(raw: string): string;
export function extractDocument(
  absPath: string,
  kind: DocumentKind,
  opts: ExtractOptions,
): Promise<ExtractResult>;

// src/documents/word.ts
export function extractWordBody(absPath: string): Promise<string>;
```

### 3.2 格式识别规则

| 头部特征 | 判定 |
| --- | --- |
| `%PDF-` | `pdf` |
| `D0 CF 11 E0 A1 B1 1A E1` | 扩展名 `doc` → `doc`；`xls`/`ppt` → 对应 kind（提取时提示不支持）；其他 → `text`（仍走 NUL 判定） |
| `PK\x03\x04` | 扩展名 `docx`/`xlsx`/`pptx`/`odt` → 对应 kind；其他 → `text` |
| `{\rtf` | `rtf` |
| 其他 | `text` |

`head` 取 `min(size, 8000)` 字节，由工具层传入；识别函数不读盘。

### 3.3 文本规范化

`normalizeText(raw)`：

1. `\r\n` / `\r` → `\n`；
2. 每行 `trimEnd()`；
3. 连续 ≥3 个空行折叠为 1 个空行；
4. 首尾空行去除（保留正文内部空行）。

### 3.4 `fileRead` 接入

```
stat → 目录拒绝
open
head = readHead(fh, size)
det  = detectDocumentKind(path, head)
if (det.kind !== 'text') return readDocument(...)
assertTextFile(head, path)            // 入参改为 Buffer，消息不变
explicit ? readRange(...) : readFull(...)
```

`readDocument()`：

1. `size > 50MB` → `too_large`；
2. `extractDocument(path, kind, { maxBytes, timeBudgetMs: 15000 })`；
3. `text.split('\n')` 得到行数组；
4. 全文模式：超过 2000 行或 256KB（`maxBytes` 可覆盖）截断；区间模式：按提取文本行号切片；
5. 复用 `clipLine()`、`withLineNumbers()`、`fmtSize()`；
6. 输出首行：`[docx 文档，已提取为文本，共 128 行；行号为提取文本行号]`；
7. 区间模式头部：`文件 p（docx 文档，共 128 行，已提取为文本）第 3-4 行:`；
8. 截断提示追加「继续读取请用 startLine/endLine（提取文本行号）」；
9. 本期不落盘完整提取文本（任务 02 补齐）。

### 3.5 `grep` 接入

`searchFile(filePath)`：

```
head = readHead(fh, size)
det  = detectDocumentKind(filePath, head)
if (det.kind !== 'text') {
  if (size > MAX_DOC_GREP_BYTES) { skipped.push({ path, reason: '超过 50MB' }); return; }
  const ex = await extractDocument(...)       // 受全局 20s 预算约束
  ex.text.split('\n').forEach((line, i) => { 匹配 → `${filePath}:${i+1}: ${clipMatchLine(...)}` })
  return
}
// 原逻辑不变
```

- 目录场景新增 `skippedDocs`，结束时若非空追加：

  ```
  [跳过 2 个文档]
  - a.docx：文件损坏
  - b.pdf：暂不支持（任务 02 启用）
  ```

  最多列 5 条，其余折叠为「等 N 个」；
- 目录文档提取累计耗时 >20s：剩余文档跳过，计入汇总；
- `maxResults` 截断与落盘治理保持原实现。

### 3.6 错误与边界

| 场景 | code | 提示要点 |
| --- | --- | --- |
| 不支持的二进制 | `unsupported` | 当前支持 doc/docx；PDF 等由后续任务启用 |
| 非 Word 的 OLE / 损坏 doc | `corrupt` | 不是 Word 97-2003 文档或文件已损坏 |
| Word 解析抛错 | `corrupt` | 附原始错误摘要，便于用户换文件 |
| 源文件 >50MB | `too_large` | 报实际大小与 50MB 上限 |
| 提取后文本为空 | `empty` | 文档没有可提取文本 |
| 目录单个文档失败 | — | 不抛错，跳过并汇总 |

### 3.7 演进项（本任务不做）

- PDF/页语义（任务 02）；
- xlsx/pptx/rtf/odt（任务 03）；
- 提取结果缓存；
- 文档结构（标题/表格）还原。
