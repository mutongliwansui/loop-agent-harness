## 一、任务目标需求

### 1.1 背景（痛点）

任务 01/02 打通了 doc/docx/pdf。真实工作区里还常见 xlsx、pptx、rtf、odt；此外部分扫描件/字体异常 PDF 在零依赖解析器下只能降级。用户明确「pdf 等文件」，需要在成本可控的前提下扩大覆盖，并给旧版 `.xls/.ppt` 明确出路。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| zip 容器解析 | [`zip.ts L68-L138`](file:///d:/trae_workspace/loop-agent-command/src/skill/zip.ts#L68-L138) `readZipEntries()` 已具备安全上限 | xlsx/pptx/odt 直接复用 |
| 格式识别 | 任务 01 的 `detectDocumentKind()` 已按扩展名识别 xlsx/pptx/odt/rtf | 提取器补齐即可 |
| 提取调度 | 任务 01 的 `extractDocument()` 对未实现 kind 抛 `unsupported` | 逐个接入新提取器 |
| PDF 降级 | 任务 02 返回 `scanned` / 乱码告警 | 本任务增加可选外部兜底 |
| 旧版格式提示 | OLE 魔数 + 扩展名 xls/ppt | 明确提示另存为或转 PDF |
| 双语文档 | `docs/readme/{zh,en}/built-in-tools.md` 已有工具说明结构 | 补齐支持矩阵、上限、错误语义 |

### 1.3 任务目标

1. `xlsx`：按工作表输出单元格文本（行内以制表符分隔），保留 sheet 边界；
2. `pptx`：按幻灯片输出文本，沿用 `=== 第 N 页 ===` 页标记；
3. `rtf`：剥离控制字并解码转义文本，保留段落；
4. `odt`：解析 `content.xml` 的段落/标题文本；
5. `.xls/.ppt`：返回「暂不支持，请另存为 xlsx/pptx 或 PDF」；
6. PDF 可选外部兜底：内置解析失败（扫描件/乱码）且系统存在 `pdftotext` 时重试；不存在则保持原降级结果；
7. 双语文档补齐格式矩阵、资源上限、错误语义与示例。

### 1.4 设计约束

- 继续零新增 npm 依赖；xlsx/pptx/odt 只做标签级文本抽取，不处理 DTD/自定义实体；
- 解析 zip 必须走 `readZipEntries()`，继承其条目数/解压总量/ZIP64/加密限制；
- 所有格式输出统一走 `normalizeText()`，行号语义与任务 01 一致；
- xlsx 日期单元格不做序列号转换（输出缓存值），在文档中声明；
- `pdftotext` 仅作兜底：不改变主路径、不新增配置、失败不掩盖内置结果；
- 外部命令必须 `spawn` 参数数组、无 shell、带超时与输出上限。

## 二、方案设计

### 2.1 总体思路

```
detectDocumentKind()
   ├─ xlsx  → readZipEntries → workbook.xml + rels + sharedStrings + sheetN.xml → 行文本
   ├─ pptx  → readZipEntries → ppt/slides/slideN.xml（按序号）→ 每页文本 + 页标记
   ├─ odt   → readZipEntries → content.xml → 段落/标题文本
   ├─ rtf   → 字节流 → 控制字/转义解码 → 段落文本
   └─ pdf   → extractPdf()
                └─ 失败(scanned/乱码) → tryPdftotext()（可用才重试）→ 成功则替换结果
        │
        ▼
   normalizeText() → ExtractResult
```

图中 D 编号对应设计方案 D2/D9 与本任务 T3-D1…D8。

### 2.2 关键设计决策

| 编号 | 决策 | 推荐 | 被否决项与理由 |
| --- | --- | --- | --- |
| **T3-D1** | xlsx 解析 `workbook.xml + rels + sharedStrings + sheetN.xml`，每行单元格以 `\t` 连接 | ✅ | 否决引入 SheetJS：新增依赖；否决只输出 sharedStrings：会丢失行列关系 |
| **T3-D2** | pptx 按 `slideN.xml` 数字序提取 `<a:t>`，每页加页标记 | ✅ | 否决按 zip 条目名字典序：slide10 会排在 slide2 前 |
| **T3-D3** | rtf 只做「控制字剥离 + `\'hh`/`\uN` 转义 + 段落还原」 | ✅ | 否决完整 RTF 排版解析：收益低、复杂度高 |
| **T3-D4** | odt 只解析 `content.xml` 的 `text:h/text:p` 文本节点 | ✅ | 否决解析样式/表格布局：超出「可读文本」目标 |
| **T3-D5** | `.xls/.ppt` 明确不支持，提示另存为 xlsx/pptx 或转 PDF | ✅ | 否决自研 BIFF 解析：工作量与风险远高于收益 |
| **T3-D6** | `pdftotext` 仅在「内置返回 scanned 或乱码告警」时兜底；进程内缓存可用性 | ✅ | 否决默认优先外部命令：不同机器结果不一致；否决完全不兜底：扫描件之外仍有字体异常 PDF 可救 |
| **T3-D7** | 不新增 OCR、不做提取缓存 | ✅ | 否决 OCR：依赖重、超出范围；否决缓存：内存与失效风险大于收益 |
| **T3-D8** | 新格式错误统一映射到既有 `ExtractErrorCode` | ✅ | 否决为每种格式新增错误码：工具层只关心可纠正提示 |

## 三、任务详细设计

### 3.1 模块接口

```ts
// src/documents/xlsx.ts
export function extractXlsx(absPath: string, opts: ExtractOptions): Promise<ExtractResult>;

// src/documents/pptx.ts
export function extractPptx(absPath: string, opts: ExtractOptions): Promise<ExtractResult>;

// src/documents/rtf.ts
export function extractRtf(absPath: string, opts: ExtractOptions): Promise<ExtractResult>;

// src/documents/odt.ts
export function extractOdt(absPath: string, opts: ExtractOptions): Promise<ExtractResult>;

// src/documents/external.ts
export function pdftotextAvailable(): boolean;
export function runPdftotext(absPath: string, timeoutMs: number): Promise<string | null>;
```

`extractDocument()` 的 switch 增加四个分支；PDF 分支在返回前执行兜底判断。

### 3.2 xlsx 输出格式

```
=== Sheet: 销售数据 ===
产品	一月	二月
A	100	120
B	80	95

=== Sheet: 汇总 ===
合计	200	215
```

规则：

- sheet 顺序取 `xl/workbook.xml` 的 `<sheet>` 顺序；
- `r:id` 经 `xl/_rels/workbook.xml.rels` 映射到实际 XML 路径；
- 单元格类型：`t="s"` 查 sharedStrings；`inlineStr` 取 `<is><t>`；`b` 输出 `TRUE/FALSE`；其余取 `<v>`；
- 空行跳过；单 sheet 行数上限 20 万、单元格总字符受 5M 总上限约束；
- 日期/百分比等格式化值输出缓存值（可能为序列号），文档中声明。

### 3.3 pptx 输出格式

```
=== 第 1 页 ===
年度总结
2026 年业务回顾

=== 第 2 页 ===
关键指标
收入增长 20%
```

规则：只取 `ppt/slides/slideN.xml` 的 `<a:t>`；按 `N` 数字升序；备注页不读；页数计入 `PageRange`，`fileRead.pages` 可复用。

### 3.4 rtf 解析

1. 识别 `\ansicpgN`，建立 `TextDecoder`（如 `windows-1252`、`gbk`）；
2. 跳过多媒体/字体表等目标组：`\*`、`fonttbl`、`colortbl`、`stylesheet`、`info`、`pict`；
3. `\par`/`\line` → `\n`；`\tab` → `\t`；`\'hh` 按代码页解码；`\uN?` → Unicode；
4. `\\`、`\{`、`\}` 转义还原；未知控制字丢弃；
5. 输出经 `normalizeText()`。

### 3.5 odt 解析

- `readZipEntries()` 找 `content.xml`；
- 提取 `<text:h>…</text:h>` 与 `<text:p>…</text:p>`；
- 内部 `<text:tab/>` → `\t`，`<text:line-break/>` → `\n`，`<text:s/>` → 空格；
- 去标签、解码 XML 实体（`&lt;`/`&gt;`/`&amp;`/`&quot;`/`&apos;` 与数字实体），不展开自定义实体。

### 3.6 PDF 外部兜底

触发条件：`extractPdf()` 抛 `scanned`，或返回结果带乱码告警。

流程：

1. `pdftotextAvailable()`：`spawnSync('pdftotext', ['-v'], { timeout: 2000 })`，进程内缓存布尔值；
2. 可用则 `spawn('pdftotext', ['-layout', '-enc', 'UTF-8', absPath, '-'])`，超时 15s、输出上限 6MB；
3. 成功且非空 → 用其结果替换内置文本，追加告警「由系统 pdftotext 提取」；
4. 失败/超时/为空 → 返回内置降级结果，不抛新错误；
5. 安全：无 shell、参数固定、路径由调用方传入绝对路径。

### 3.7 错误与边界

| 场景 | code | 提示要点 |
| --- | --- | --- |
| xlsx/pptx/odt 不是合法 zip 或缺核心条目 | `corrupt` | 指定缺少的条目名 |
| zip 超限（条目/解压量） | `too_large` | 复用 `readZipEntries()` 的中文错误 |
| `.xls/.ppt` | `unsupported` | 请另存为 xlsx/pptx 或 PDF |
| rtf 编码无法识别 | — | 按 latin-1 解码并告警 |
| xlsx 无可读单元格 | `empty` | 工作表为空或只有公式无缓存值 |
| pdftotext 不存在 | — | 静默回退，不提示安装（避免噪音） |

### 3.8 演进项（本任务不做）

- 旧版 xls/ppt 解析；
- 文档版面/表格样式还原；
- OCR；
- 文档提取缓存；
- `/fs/search` 与 WebUI 搜索同步支持文档内容。
