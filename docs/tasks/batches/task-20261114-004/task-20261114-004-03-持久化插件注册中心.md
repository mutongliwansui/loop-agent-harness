## 一、任务目标需求

### 1.1 背景（痛点）

用户要求「在 main 中实现支持持久化的 PluginRegistry」。被删掉的 core `PluginRegistry` 是**纯内存**的（设计 5.10 明确「无磁盘 IO」），进程一重启，挂载什么插件全靠调用方硬编码。

真实痛点：

- 用户装了插件、调了顺序、停用了某个，**重启后全部丢失**。
- 没有清单文件，就没有「已安装但停用」这个状态——只能靠删条目，删了配置也没了。
- 插件加载失败（文件被删、依赖缺）时，若直接抛错会**一个坏插件锁死整个启动**。

### 1.2 现状梳理

| 所需能力 | 框架现状（链接） | 结论 |
|---|---|---|
| 建装能力 | `core/src/context.ts:457` `createRootContext()` + `ctx.plugin()` | **复用** |
| Fiber 生命周期 | `core/src/fiber.ts` 六态 + disposer 栈 | **复用**，不重复实现 |
| 诊断 | `core/src/context.ts` `diagnose()` 返回 `DiagnosticReport` | **复用并合并** |
| 插件清单文件 | **仓库内完全不存在**（无 `plugins/` 目录、无 `registry.json`、无清单读写代码） | **新增** |
| 原子写 | 主工程各模块自行 `writeFileSync`，**无统一原子写工具** | **新增**（tmp + rename） |
| 插件动态加载 | core 只收 ESM，但**无加载器**（core 边界禁裸包 import） | **新增**（`import()` 在 main 层） |
| 清单容错 | 无任何容错代码 | **新增**（坏档备份 + 降级空清单） |

### 1.3 任务目标

1. `PluginStore`：清单读写，落 `~/.loop-agent/plugins/registry.json`，原子写，坏档容错。
2. `PersistentPluginRegistry`：`restore` / `mount` / `unmount` / `enable` / `disable` / `reorder` / `fiberOf` / `diagnose` / `dispose`。
3. 5 个写操作（`mount` / `enable` / `disable` / `unmount` / `reorder`）**均立即原子落盘**；写失败只记录不打断。
4. 插件加载走动态 `import()`，失败进诊断，不中断其余。
5. `createMainHost().start()` / `stop()` 接线到 `registry.restore()` / `dispose()`。

### 1.4 设计约束

| 约束 | 落地要求 |
|---|---|
| **D3（用户拍板）** 全局 `~/.loop-agent/plugins/registry.json` | 路径经 `loopAgentHome()` 派生，`LOOP_AGENT_HOME` 可重定向 |
| **D4（用户拍板）** 写后立即原子写，失败只记录 | 每个写方法末尾 `persist()`；失败进 `lastError()` + `diagnose().persistError` |
| **D6** 只存清单，不存服务快照 | 清单条目只含 `id` / `specifier` / `enabled` / `options` |
| **D7** `enabled` 为一等状态 | `disable` 卸 Fiber 留条目；`enable` 重挂载 |
| **D8** Windows rename 语义 | 目标存在时先 `rm` 再 `rename` |
| **D9** `schemaVersion` + 坏档容错 | 不识别/损坏 → 备份 `.bad.<ts>` + 空清单，不抛错 |
| **D10** 只收 ESM，加载失败不抛 | `import()`；`loadError` 进诊断 |
| 零新依赖 | 只用 `node:fs` / `node:path` / `node:os` + `@loop-agent/core` |
| 单进程内并发写安全 | 内部写队列串行化；多进程锁为非目标 |

## 二、方案设计

### 2.1 总体思路

```
PersistentPluginRegistry
├── entries: PluginManifestEntry[]   内存镜像（顺序 == 挂载顺序）
├── mounted: Map<id, Fiber>          运行期 Fiber
├── loadErrors: Map<id, Error>       加载失败记录
│
├─ restore()    read() → 逐条挂载 enabled → settle
├─ mount(e)     import() → ctx.plugin() → push 条目 → persist()
├─ unmount(id)  fiber.dispose() → 删条目 → persist()
├─ disable(id)  fiber.dispose() → enabled=false → persist()
├─ enable(id)   import() → ctx.plugin() → enabled=true → persist()
├─ reorder(ids) 重排 entries → persist()
├─ fiberOf(id)  读 mounted
├─ diagnose()   core 诊断 + 条目状态 + persistError
└─ dispose()    逆序卸载全部（幂等）

persist()
  └─ store.write(manifest) ──▶ tmp 文件 ──▶ rename ──▶ registry.json
                                  │
                                  └─ 失败：lastError 记录，内存照常更新（D4）
```

### 2.2 关键设计决策

| 编号 | 决策 | 理由 | 被否决项 |
|---|---|---|---|
| **D5** | 类名 `PersistentPluginRegistry`，**组合** `Context` 而非继承 | 名字点明新增职责；core 侧零耦合，core 演进不牵动 main | 复用 `PluginRegistry` 同名（迁移期指代不清） |
| **D17**（本任务新增） | 顺序**用数组下标表达**，不存冗余 `order` 字段 | 冗余字段会与数组顺序不一致，是经典的双写不一致源；`reorder` 只重排数组即可 | 存 `order: number`（需额外一致性校验） |
| **D18**（本任务新增） | `persist()` 内部维护**串行写队列**（`writeChain: Promise`），同一进程内写操作按调用序落盘 | 避免并发 `mount` 交叉写导致 tmp 文件互相覆盖、最终落盘内容错乱 | 无队列（并发写竞态，测试偶发失败，线上难复现） |
| **D19**（本任务新增） | `diagnose()` **扩展**而非替换 core 的 `DiagnosticReport`：返回 `{ core, entries, file, persistError? }` | core 的诊断回答「Fiber 服务为什么没生效」，main 需再回答「清单里登记了什么、哪个加载失败了、落盘有没有问题」，两者是并列关系 | 直接返回 core 报告（丢失清单视角）；展开合并（字段名冲突） |

import type { DiagnosticReport, FiberState } from '@loop-agent/core';

/** 清单结构版本；不识别时降级为空清单并备份坏档（D9） */
export const MANIFEST_SCHEMA_VERSION = 1 as const;

/** 单条插件清单条目 */
export interface PluginManifestEntry {
  /** 稳定标识（用户可读），同时作为清单主键；重复即冲突 */
  id: string;
  /** 模块说明符：相对路径 / 绝对路径 / 包名（只收 ESM，D10） */
  specifier: string;
  /** 是否启用；false 表示「已登记但未挂载」（D7） */
  enabled: boolean;
  /** 传给插件工厂的选项；仅 JSON 可序列化值 */
  options?: Record<string, unknown>;
}

/** 清单文件（落盘结构） */
export interface PluginManifest {
  schemaVersion: typeof MANIFEST_SCHEMA_VERSION;
  /** 数组顺序 == 挂载顺序（D17） */
  entries: PluginManifestEntry[];
  /** 最后写入时间（ISO），仅供诊断 */
  updatedAt: string;
}

/** 注册中心诊断（D19） */
export interface RegistryDiagnostic {
  /** core 原始诊断 */
  core: DiagnosticReport;
  entries: Array<{
    id: string;
    specifier: string;
    enabled: boolean;
    /** 运行期状态；未挂载为 undefined */
    state?: FiberState;
    /** 加载失败原因（D10） */
    loadError?: { code: string; message: string };
  }>;
  /** 清单文件绝对路径 */
  file: string;
  /** 最近一次落盘失败（D4） */
  persistError?: { message: string };
}

/** 空清单工厂（首次启动 / 坏档降级共用） */
export function emptyManifest(): PluginManifest {
  return { schemaVersion: MANIFEST_SCHEMA_VERSION, entries: [], updatedAt: new Date().toISOString() };
}

### 3.2 `main/src/store.ts`

```ts
import { mkdirSync, readFileSync, renameSync, rmSync, writeFileSync, existsSync } from 'node:fs';
import { dirname, join } from 'node:path';
import { pluginsDir } from './home.js';
import {
  MANIFEST_SCHEMA_VERSION,
  emptyManifest,
  type PluginManifest,
  type PluginManifestEntry,
} from './types.js';

export interface PluginStoreOptions {
  /** 清单文件绝对路径；缺省 ~/.loop-agent/plugins/registry.json（D3） */
  file?: string;
}

export interface PluginStore {
  readonly file: string;
  read(): PluginManifest;
  write(manifest: PluginManifest): { ok: true } | { ok: false; error: Error };
  lastError(): Error | undefined;
}

export function createPluginStore(options: PluginStoreOptions = {}): PluginStore {
  const file = options.file ?? join(pluginsDir(), 'registry.json');
  let lastError: Error | undefined;
  // tmp 文件名序号（同进程多次写不重名）
  let seq = 0;

  return {
    file,

    read() {
      if (!existsSync(file)) return emptyManifest();
      let raw: string;
      try {
        raw = readFileSync(file, 'utf8');
      } catch (error) {
        return degrade(file, error instanceof Error ? error : new Error(String(error)));
      }
      let parsed: unknown;
      try {
        parsed = JSON.parse(raw);
      } catch (error) {
        return degrade(file, error instanceof Error ? error : new Error(String(error)));
      }
      const normalized = normalizeManifest(parsed);
      if (!normalized) return degrade(file, new Error('清单结构不识别'));
      return normalized;
    },

    write(manifest) {
      // D8：写 tmp → 删目标 → rename；Windows 上目标存在时 rename 会 EPERM
      const tmp = `${file}.tmp.${process.pid}.${++seq}`;
      try {
        mkdirSync(dirname(file), { recursive: true });
        writeFileSync(tmp, JSON.stringify(manifest, null, 2) + '\n', 'utf8');
        if (existsSync(file)) rmSync(file, { force: true });
        renameSync(tmp, file);
        lastError = undefined;
        return { ok: true };
      } catch (error) {
        const err = error instanceof Error ? error : new Error(String(error));
        lastError = err;
        // 清理残留 tmp，避免同目录堆积
        try {
          if (existsSync(tmp)) rmSync(tmp, { force: true });
        } catch {
          /* 清理失败不影响主流程 */
        }
        return { ok: false, error: err };
      }
    },

    lastError() {
      return lastError;
    },
  };

  /** 坏档处理：备份为 .bad.<ts> 后返回空清单，不抛错（D9） */
  function degrade(target: string, error: Error): PluginManifest {
    lastError = error;
    try {
      if (existsSync(target)) {
        renameSync(target, `${target}.bad.${Date.now()}`);
      }
    } catch {
      /* 备份失败不阻断，原文件仍在原地 */
    }
    return emptyManifest();
  }
}

/** 结构校验：字段类型不符即视为不可用，返回 undefined */
function normalizeManifest(value: unknown): PluginManifest | undefined {
  if (typeof value !== 'object' || value === null) return undefined;
  const obj = value as Record<string, unknown>;
  if (obj.schemaVersion !== MANIFEST_SCHEMA_VERSION) return undefined;
  if (!Array.isArray(obj.entries)) return undefined;

  const seen = new Set<string>();
  const entries: PluginManifestEntry[] = [];
  for (const item of obj.entries) {
    if (typeof item !== 'object' || item === null) continue;
    const e = item as Record<string, unknown>;
    if (typeof e.id !== 'string' || e.id === '') continue;
    if (typeof e.specifier !== 'string' || e.specifier === '') continue;
    if (seen.has(e.id)) continue; // 重复 id 保留首个
    seen.add(e.id);
    entries.push({
      id: e.id,
      specifier: e.specifier,
      enabled: e.enabled !== false, // 缺省视为启用
      ...(isPlainObject(e.options) ? { options: e.options } : {}),
    });
  }
  return {
    schemaVersion: MANIFEST_SCHEMA_VERSION,
    entries,
    updatedAt: typeof obj.updatedAt === 'string' ? obj.updatedAt : new Date().toISOString(),
  };
}

function isPlainObject(v: unknown): v is Record<string, unknown> {
  return typeof v === 'object' && v !== null && !Array.isArray(v);
}
```

### 3.3 `main/src/registry.ts`

```ts
import type { Context, CoreHost, EventMapBase, Fiber, FiberState, Plugin } from '@loop-agent/core';
import { createPluginStore, type PluginStore } from './store.js';
import {
  MANIFEST_SCHEMA_VERSION,
  emptyManifest,
  type PluginManifestEntry,
  type RegistryDiagnostic,
} from './types.js';

export interface PersistentPluginRegistryOptions<E extends EventMapBase = EventMapBase> {
  /** 根 Context（由 createMainHost 提供） */
  context: Context<E>;
  /** core 宿主；提供后可在 restore 末尾用 host.settle() 等链式依赖收敛 */
  host?: CoreHost<E>;
  /** 清单存储；缺省用默认路径（D3） */
  store?: PluginStore;
  /** specifier → Plugin 工厂；缺省动态 import()（D10） */
  loadPlugin?: (specifier: string, options?: Record<string, unknown>) => Promise<Plugin<E>>;
}

/** 缺省加载器：只收 ESM（D10） */
export const defaultLoadPlugin = async <E extends EventMapBase>(
  specifier: string,
  options?: Record<string, unknown>,
): Promise<Plugin<E>> => {
  const mod = (await import(specifier)) as Record<string, unknown>;
  const factory = (mod.default ?? mod.plugin ?? mod) as unknown;
  if (typeof factory === 'function') {
    // 形如 export default (options) => PluginObject | export default PluginFunction
    return (factory as (o?: unknown) => Plugin<E> | Promise<Plugin<E>>)(options) as Plugin<E>;
  }
  if (typeof factory === 'object' && factory !== null) return factory as Plugin<E>;
  throw new TypeError(`插件模块未导出可用的 Plugin：${specifier}`);
};

export class PersistentPluginRegistry<E extends EventMapBase = EventMapBase> {
  private readonly context: Context<E>;
  private readonly host?: CoreHost<E>;
  private readonly store: PluginStore;
  private readonly loadPlugin: NonNullable<PersistentPluginRegistryOptions<E>['loadPlugin']>;

  /** 内存镜像；顺序 == 挂载顺序（D17） */
  private entries: PluginManifestEntry[] = [];
  private readonly mounted = new Map<string, Fiber>();
  private readonly loadErrors = new Map<string, Error>();
  /** 串行写队列（D18） */
  private writeChain: Promise<void> = Promise.resolve();
  private disposePromise?: Promise<void>;

  constructor(options: PersistentPluginRegistryOptions<E>) {
    this.context = options.context;
    this.host = options.host;
    this.store = options.store ?? createPluginStore();
    this.loadPlugin = options.loadPlugin ?? defaultLoadPlugin;
  }

  /** 已登记清单（只读副本） */
  entries(): readonly PluginManifestEntry[] {
    return this.entries.map((e) => ({ ...e }));
  }

  /** 启动还原：读清单 → 逐条挂载 enabled（D6） */
  async restore(): Promise<void> {
    const manifest = this.store.read();
    this.entries = manifest.entries.map((e) => ({ ...e }));
    for (const id of [...this.mounted.keys()]) await this.stopFiber(id);
    this.loadErrors.clear();

    for (const entry of this.entries) {
      if (!entry.enabled) continue;
      // D10：单条加载失败不中断其余
      try {
        await this.start(entry);
      } catch {
        /* 已记入 loadErrors，继续下一条 */
      }
    }
    await this.settle();
  }

  /** 新增并挂载；id 重复抛错 */
  async mount(entry: PluginManifestEntry): Promise<Fiber> {
    if (this.entries.some((e) => e.id === entry.id)) {
      const err = new Error(`插件 id 重复：${entry.id}`);
      (err as Error & { code?: string }).code = 'PLUGIN_ID_CONFLICT';
      throw err;
    }
    this.entries.push({ ...entry });
    const fiber = await this.start({ ...entry, enabled: true });
    await this.persist();
    return fiber;
  }

  /** 彻底移除：卸载 Fiber + 删条目 */
  async unmount(id: string): Promise<void> {
    const index = this.entries.findIndex((e) => e.id === id);
    if (index < 0) return; // 幂等
    await this.stopFiber(id);
    this.entries.splice(index, 1);
    this.loadErrors.delete(id);
    await this.persist();
  }

  /** 停用：卸 Fiber，保留条目（D7）；幂等 */
  async disable(id: string): Promise<void> {
    const entry = this.entries.find((e) => e.id === id);
    if (!entry || !entry.enabled) return;
    await this.stopFiber(id);
    entry.enabled = false;
    await this.persist();
  }

  /** 启用：重新挂载，保持条目位置（D7） */
  async enable(id: string): Promise<Fiber> {
    const entry = this.entries.find((e) => e.id === id);
    if (!entry) throw notFound(id);
    if (entry.enabled && this.mounted.has(id)) return this.mounted.get(id)!;
    entry.enabled = true;
    const fiber = await this.start(entry);
    await this.persist();
    return fiber;
  }

  /** 排序：按给定 id 顺序重排（D17）；未列出的按原相对序追加尾部 */
  async reorder(ids: readonly string[]): Promise<void> {
    const known = new Set(this.entries.map((e) => e.id));
    for (const id of ids) {
      if (!known.has(id)) throw notFound(id);
    }
    const rank = new Map(ids.map((id, i) => [id, i]));
    this.entries = [...this.entries].sort((a, b) => {
      const ra = rank.get(a.id) ?? Number.MAX_SAFE_INTEGER;
      const rb = rank.get(b.id) ?? Number.MAX_SAFE_INTEGER;
      return ra === rb ? 0 : ra - rb; // 未列出者保持原相对顺序（sort 稳定）
    });
    await this.persist();
  }

  /** 按 id 取运行期 Fiber */
  fiberOf(id: string): Fiber | undefined {
    return this.mounted.get(id);
  }

  /** core 诊断 + 清单/落盘状态合并（D19） */
  diagnose(): RegistryDiagnostic {
    const core = this.context.diagnose();
    const persistError = this.store.lastError();
    return {
      core,
      entries: this.entries.map((e) => {
        const state = this.mounted.get(e.id)?.state as FiberState | undefined;
        const err = this.loadErrors.get(e.id);
        return {
          id: e.id,
          specifier: e.specifier,
          enabled: e.enabled,
          ...(state ? { state } : {}),
          ...(err ? { loadError: { code: (err as Error & { code?: string }).code ?? 'PLUGIN_LOAD_ERROR', message: err.message } } : {}),
        };
      }),
      file: this.store.file,
      ...(persistError ? { persistError: { message: persistError.message } } : {}),
    };
  }

  /** 逆序卸载全部；幂等（与 core dispose 语义一致） */
  dispose(): Promise<void> {
    if (!this.disposePromise) this.disposePromise = this.doDispose();
    return this.disposePromise;
  }

  // ── 内部 ──

  private async doDispose(): Promise<void> {
    for (const id of [...this.mounted.keys()].reverse()) {
      await this.stopFiber(id);
    }
    this.mounted.clear();
  }

  private async start(entry: PluginManifestEntry): Promise<Fiber> {
    this.loadErrors.delete(entry.id);
    let plugin: Plugin<E>;
    try {
      plugin = await this.loadPlugin(entry.specifier, entry.options);
    } catch (error) {
      const err = error instanceof Error ? error : new Error(String(error));
      this.loadErrors.set(entry.id, err);
      throw err; // 由调用方决定吞掉（restore）或抛出（mount/enable）
    }
    const fiber = this.context.plugin(plugin);
    this.mounted.set(entry.id, fiber);
    await fiber.ready();
    return fiber;
  }

  /** 等依赖收敛静止：有 host 时走 host.settle()，否则逐条 ready 已够 */
  private async settle(): Promise<void> {
    if (this.host) await this.host.settle();
  }

  private async stopFiber(id: string): Promise<void> {
    const fiber = this.mounted.get(id);
    if (!fiber) return;
    this.mounted.delete(id);
    await fiber.dispose();
  }

  /** 串行落盘：失败只记录（D4） */
  private persist(): Promise<void> {
    this.writeChain = this.writeChain.then(() => {
      this.store.write({
        schemaVersion: MANIFEST_SCHEMA_VERSION,
        entries: this.entries.map((e) => ({ ...e })),
        updatedAt: new Date().toISOString(),
      });
    });
    return this.writeChain;
  }
}

function notFound(id: string): Error {
  const err = new Error(`插件不存在：${id}`);
  (err as Error & { code?: string }).code = 'PLUGIN_NOT_FOUND';
  return err;
}
```

> **实施时需修正的两处实现细节**（设计层面已定，编码时按此收敛）：
> 1. `restore()` 里「等依赖收敛」要用 `host.settle()`。`Context` 接口不暴露 host，故 `PersistentPluginRegistryOptions` 需**增加 `host?: CoreHost<E>`**，由 `createMainHost` 一并传入；缺省时以「逐条 `await fiber.ready()`」兜底（与 core 旧 `PluginRegistry.mount` 同策略）。
> 2. `start()` 遇加载失败：**不能** `throw`（D10 明确「不中断」）。正确做法是 `restore()` 循环内 `try/catch` 吞掉并记录；`mount()` / `enable()` 这类**用户显式操作**允许把错误抛给调用方（用户需要知道「我装失败了」），但**清单条目保留**，`loadError` 已记录，便于 `diagnose()` 排查。

### 3.4 `createMainHost` 接线（修订任务 02 的 `start`/`stop`）

```ts
export interface MainHostOptions<E extends EventMapBase = EventMapBase> {
  host?: CoreHost<E>;
  logger?: Logger;
  home?: string;
  /** 清单文件路径覆盖（测试注入临时目录） */
  manifestFile?: string;
  /** 插件加载器覆盖（测试注入内存插件） */
  loadPlugin?: PersistentPluginRegistryOptions<E>['loadPlugin'];

```

- `start()` → `await registry.restore()`
- `stop()` → `await registry.dispose()`
- `registry` 通过 `MainHost.registry` 暴露，供上层查询 `entries()` / `diagnose()`

### 3.5 边界与错误处理

| 场景 | 行为 |
|---|---|
| 清单文件不存在 | `read()` 返回空清单，`restore()` 成空操作 |
| JSON 损坏 / `schemaVersion` 不识别 / `entries` 非数组 | 备份 `.bad.<ts>` → 空清单 → `lastError` 记录；**不阻断启动**（D9） |
| 条目字段类型不符（`id` 非串/空串） | 跳过该条，其余保留 |
| 文件内 `id` 重复 | 保留首个，其余忽略 |
| `enabled` 字段缺失 | 视为 `true`（宽松向后兼容） |
| `mount` 的 id 已存在 | 抛 `PLUGIN_ID_CONFLICT` |
| `enable` / `reorder` 传未知 id | 抛 `PLUGIN_NOT_FOUND` |
| `unmount` / `disable` 未知 id | 幂等空操作，不写盘 |
| `import()` 失败（文件不存在/语法错/非 ESM） | `restore` 内吞掉并记 `loadError`；`mount`/`enable` 抛给调用方但条目保留 |
| 插件 `apply` 抛错 | core 置 `FAILED`，`diagnose().entries[].state === 'FAILED'`，不中断其余 |
| 落盘失败（磁盘满/只读） | `write()` 返回 `{ok:false}`，`lastError` 记录，内存清单照常更新，操作不抛（D4） |
| 同进程并发写 | `writeChain` 串行，last-write-wins，不交叉（D18） |
| `dispose()` 重复调用 | 返回同一 Promise |
| `restore()` 重复调用 | 先清空 `mounted` 与 `loadErrors` 再重挂（幂等） |

### 3.6 打包与动态 import（tsup 注意事项）

`defaultLoadPlugin` 用的是 `import(specifier)`——**变量说明符**。tsup/rollup 遇到变量 `import()` 会：

- 打包时告警 `The above dynamic import cannot be analyzed by bundler`；
- 在 ESM 产物中原样保留，运行时由 Node 解析（行为正确）。

处置：`tsup.config.ts` 里把该告警显式关掉并加注释说明「插件说明符是运行期值，不可静态分析」：

```ts
export default defineConfig({
  // …其他配置
  esbuildOptions(options) {
    // 插件 specifier 是运行期值，变量 import() 无法静态分析属预期
    options.logOverride = { 'unsupported-dynamic-import': 'silent' };
  },
});
```

同时 `main/tests/boundary.test.ts` 不必断言产物内容（动态 import 在 ESM 中合法），但要在验收里核验「build 无 error、只有该类 warning 已被静音」。

#### 二、关键语义实测

| 语义 | 实现要点 | 验证 |
|---|---|---|
| 五写操作立即落盘 | `mount`/`unmount`/`disable`/`enable`/`reorder` 后均 `await persist()` | registry 测试逐项断言**文件内容**一致（按 D21，不用 mtime） |

#### 三、偏差

1. **`mainHost.start()` / `stop()` 的行为定义比方案更具体**：`start()` 走 `registry.restore()` 且**不因单插件失败而失败**；`stop()` 走 `registry.dispose()` 且**幂等**，语义定为「会话结束」而非「进程退出」。方案原文只说「走 restore / 走 dispose」，未明确失败与幂等语义，实施时补齐并写进 README。
2. **`RegistryDiagnostic` 的字段名**：方案草稿里叫 `core` / `entries` / `file`，实测落地为 `{ core, entries, file, persistError }`——多出 `persistError`（D4 的「落盘失败只记录」需要一个可观测出口，否则该决策无法验收）。
