### 3.3 `main/README.md`（新增）

```markdown
# @loop-agent/main

主工程宿主层：**持久化插件注册中心**、基础服务与启停骨架。

## 定位（先读这段）

`main` 是**新的主工程入口**，但当前处于**骨架阶段**：

- ✅ 已交付：`createMainHost()`（host + 根 Context + 基础服务 + 启停骨架）、
  `PersistentPluginRegistry`（清单落盘、增删启停排序、重启还原）
- ❌ 未交付：`src/` 现有业务代码的插件化迁移、CLI 入口、HTTP 服务

> **`src/` 尚未迁移，仍是当前实际运行的入口。** `main` 本轮不替代 `src/`。
> 后续按「包装不启用 → 双写对照 → 切换删旧」逐步推进。

## 分层判据

- `@loop-agent/core` 回答「插件怎么被定义、怎么被挂载、怎么被撤销」
- `@loop-agent/main` 回答「挂载哪些插件、按什么顺序、启停状态、清单存哪、重启怎么还原」

## 插件清单

落盘位置：`~/.loop-agent/plugins/registry.json`（跨工作空间共享一套）

- 路径经 `LOOP_AGENT_HOME` 环境变量可重定向（测试隔离 / 多实例）
- `schemaVersion: 1`，数组顺序即挂载顺序
- 条目字段：`id` / `specifier` / `enabled` / `options?`

```json
{
  "schemaVersion": 1,
  "entries": [
    { "id": "logger", "specifier": "./plugins/logger.js", "enabled": true },
    { "id": "metrics", "specifier": "@acme/metrics", "enabled": false }
  ],
  "updatedAt": "2026-11-14T00:00:00.000Z"
}
```

## 持久化语义

- **写即落盘**：`mount` / `enable` / `disable` / `unmount` / `reorder` 后立即原子写
- **原子写**：写 `<file>.tmp.<pid>.<seq>` → 删目标 → `rename`（Windows 上目标存在必须先去）
- **写失败不打断**：落盘失败只记入 `diagnose().persistError`，内存清单照常更新，挂载继续
- **坏档不阻断启动**：JSON 损坏 / `schemaVersion` 不识别 → 备份为 `registry.json.bad.<ts>` → 降级空清单
- **只存清单，不存服务快照**：服务是运行时对象，每次启动由插件 `apply` 重新建立

## 插件形态

沿用 core 约定：**只收 ESM**。`specifier` 支持相对路径 / 绝对路径 / 包名。

```js
// plugins/logger.js
export default {
  name: 'logger',
  apply(ctx) {
    ctx.effect(() => () => { /* 清理逻辑 */ });
  },
};
```

加载失败（文件不存在、语法错、非 ESM）**不会**让宿主起不来：该条目记 `loadError`，其余照常挂载。

## 快速开始

```ts
import { createMainHost } from '@loop-agent/main';

const main = createMainHost();
await main.start();          // 读清单并挂载 enabled 插件
console.log(main.registry.diagnose());  // 清单 + Fiber 状态 + 落盘状态

await main.stop();           // 逆序卸载全部
```

## 非目标

- 多进程并发写锁
- 插件市场 / 远程安装
- 插件 semver 版本约束
- 热重载（文件监听）
- 按工作空间覆盖清单
```
