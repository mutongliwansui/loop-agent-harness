## 一、任务目标需求

### 1.1 背景（痛点）

用户要「main 作为新的主工程入口」。现有主工程 `src/` 的问题：

- `src/runtime/init.ts:37` `initRuntime()` 串行 6 个编号阶段，装配靠人肉编排。
- `src/api/bootstrap.ts:20` `startApiServer()` 195 行，含 9 处 `await import()` 动态装配。
- 17 处 `export const x = new X()` 模块级单例，无撤销、无整体关停。

但这些是**业务装配**，需要逐个改造成插件才能迁移。用户明确 D1：**本轮只搭基础主工程框架，不迁移 `src/`**。

### 1.2 现状梳理

| 所需能力 | 框架现状（链接） | 结论 |
|---|---|---|
| 独立子包先例 | `core/` 已有完整四件套（`package.json` / `tsconfig.json` / `tsup.config.ts` / `vitest.config.ts`），`node_modules/@loop-agent/core` 实测为 Junction | **照抄结构** |
| workspaces 声明 | 根 `package.json` 现为 `workspaces: ["core"]` | 追加 `"main"` |
| dist 忽略规则 | `.gitignore` 含 core 的 `dist` 忽略 | 追加 `/main/dist/` |
| 用户目录解析 | `src/user-home.ts:18` `loopAgentHome()`（读 `LOOP_AGENT_HOME`） | **main 内自查实现同语义**，不 import（D12） |
| 宿主与根 Context | `core/src/context.ts:375` `createHost()`、`:457` `createRootContext()` | **直接复用**，core 零改动 |
| 基础服务清单 | 仓库无宿主层基础服务定义 | 新增最小集（logger + home） |
| 主工程入口进程 | `src/index.ts`（CLI / `--serve`） | **本轮不动**；main 只交付可编程入口 |

### 1.3 任务目标

1. 新建 `main/` 子包，四件套与 core 同构，`dependencies` 只有 `@loop-agent/core`（workspace 内）。
2. 根 `workspaces` 追加 `"main"`，`.gitignore` 追加 `/main/dist/`。
3. 实现 `createMainHost()`：建 core host + 根 Context + 注册基础服务，返回 `{ host, context, start, stop }`。
4. `main/src/index.ts` 建立导出面。
5. 边界保证：`main/src/**` 零 import 主工程 `src/`。

### 1.4 设计约束

| 约束 | 落地要求 |
|---|---|
| **D1（用户拍板）** 只搭基础框架，不迁移 `src/` | `src/` 零改动；不实现 CLI / HTTP / 业务服务 |
| **D11** `external: ['@loop-agent/core']` | `tsup.config.ts` 必须配；`main/tests/boundary.test.ts` 断言单副本 |
| **D12** 用户目录自查 | `main/src/home.ts` 自己读 `LOOP_AGENT_HOME`，**不 import `src/`** |
| 零新依赖 | 除 `@loop-agent/core` 外只用 `node:` |
| 与 core 同构 | 包契约（`exports` / `files` / `sideEffects` / `engines` / `type: module`）与 core 保持一致 |

## 二、方案设计

### 2.1 总体思路

```
main/
├── package.json        @loop-agent/main，deps 只有 @loop-agent/core
├── tsconfig.json       与 core 同构
├── tsup.config.ts      external: ['@loop-agent/core']（D11）
├── vitest.config.ts    cacheDir: dist/.vitest
├── src/
│   ├── home.ts         loopAgentHome()（D12，自查实现）
│   ├── host.ts         createMainHost()
│   └── index.ts        导出面
└── tests/              （任务 04 填）

createMainHost()
   ├─ createHost<E>()           ← core
   ├─ createRootContext<E>(host)← core
   ├─ context.provide('main:logger', ...)
   ├─ context.provide('main:home', ...)
   └─ return { host, context, start, stop }
```

### 2.2 关键设计决策

| 编号 | 决策 | 理由 | 被否决项 |
|---|---|---|---|
| **D1**（用户已拍板） | 新建独立子包，只搭基础框架，不迁 `src/` | 迁移需先把 17 个模块级单例改造成插件，属渐进工程；本轮先立骨架，后续「包装不启用 → 双写对照 → 切换删旧」 | main 取代 `src/` 本轮全量迁移（数千行、与「P3 再逐步包装」定案冲突、无收益） |
| **D14**（本任务新增） | 基础服务只放 **2 个**：`main:logger`、`main:home`；不预置 config / session / db / http | 基础框架要「薄」。业务服务应各自做成插件，预置进 main 会让 main 变成又一个 `initRuntime()` | 预置全套服务（立刻复现「硬编码装配」旧问题） |
| **D15**（本任务新增） | `createMainHost()` **必返回 `stop()`**，且 `stop()` 内委托注册中心 `dispose()`（任务 03 接线）；本轮 `stop()` 先只做「卸载全部 Fiber + 清空服务」 | 用户痛点之一是「注册后无法成组撤销」；骨架期就把关停路径定死，避免后续补丁 | 不提供 `stop()`（骨架期偷懒，后续必返工） |
| **D16**（本任务新增） | `start()` 本轮**只做空实现 + TODO**，真正「还原清单并挂载」在任务 03 注入 | 任务 02 尚无注册中心，硬塞会造临时接口再拆 | 在任务 02 就实现 `start()`（需先有 store/registry，顺序颠倒） |

### 3.5 `main/src/home.ts`（D12）

```ts
/**
 * 用户级数据根目录（~/.loop-agent）。
 *
 * 与主工程 src/user-home.ts 同语义，但**独立实现**：
 * main 要能作为独立包演进，import 主工程会破坏「零反向依赖」边界。
 * 优先级：LOOP_AGENT_HOME（测试隔离/多实例）> 真实用户主目录。
 */
import { homedir } from 'node:os';
import { join } from 'node:path';

export function loopAgentHome(): string {
  const override = process.env.LOOP_AGENT_HOME;
  if (override !== undefined && override.trim() !== '') return override.trim();
  return join(homedir(), '.loop-agent');
}

/** 插件目录（~/.loop-agent/plugins） */
export function pluginsDir(): string {
  return join(loopAgentHome(), 'plugins');
}
```

### 3.6 `main/src/host.ts`

```ts
import { createHost, createRootContext, type Context, type CoreHost } from '@loop-agent/core';
import type { EventMapBase } from '@loop-agent/core';
import { join } from 'node:path';
import { loopAgentHome } from './home.js';

export interface Logger {
  info(msg: string, meta?: unknown): void;
  warn(msg: string, meta?: unknown): void;
  error(msg: string, meta?: unknown): void;
}

export interface MainHostOptions<E extends EventMapBase = EventMapBase> {
  /** 复用已有 host（测试/多宿主场景）；缺省自建 */
  host?: CoreHost<E>;
  /** 覆盖日志实现；缺省 console */
  logger?: Logger;
  /** 覆盖用户目录；缺省 loopAgentHome() */
  home?: string;
}

export interface MainHost<E extends EventMapBase = EventMapBase> {
  readonly host: CoreHost<E>;
  /** 根 Context；在其上 provide 的服务对所有插件可见 */
  readonly context: Context<E>;
  readonly logger: Logger;
  readonly home: string;
  /** 启动：还原清单并挂载（任务 03 接线；本轮空实现） */
  start(): Promise<void>;
  /** 优雅关停：逆序卸载全部 + 清空服务 */
  stop(): Promise<void>;
}

export function createMainHost<E extends EventMapBase = EventMapBase>(
  options: MainHostOptions<E> = {},
): MainHost<E> {
  const host = options.host ?? createHost<E>();
  const context = createRootContext<E>(host);
  const logger: Logger = options.logger ?? {
    info: (m, meta) => console.info(`[main] ${m}`, meta ?? ''),
    warn: (m, meta) => console.warn(`[main] ${m}`, meta ?? ''),
    error: (m, meta) => console.error(`[main] ${m}`, meta ?? ''),
  };
  const home = options.home ?? loopAgentHome();

  context.provide('main:logger', logger);
  // pluginsDir 必须随 home override 联动，否则测试注入 home 后仍写真实目录
  context.provide('main:home', { dir: home, pluginsDir: join(home, 'plugins') });

  return {
    host,
    context,
    logger,
    home,
    async start() {
      // TODO(任务 03)：registry.restore() —— 读清单并挂载 enabled 插件
    },
    async stop() {
      // TODO(任务 03)：registry.dispose() —— 逆序卸载（当前先兜底清空服务）
      await host.settle();
    },
  };
}
```

> `main:home` 的 `pluginsDir` 应随 `home` override 联动（`join(home, 'plugins')`），不以环境变量为准，避免测试注入 `home` 后仍写真实目录。实现时以 `join(home, 'plugins')` 计算。

### 3.9 边界与错误处理

| 场景 | 行为 |
|---|---|
| `main/node_modules` 被 npm 建出 | `vitest cacheDir` 指 `dist/.vitest`，且 `materials` 走根 hoist；`boundary.test.ts`（任务 04）断言不存在 |
| `main` 未 build 时被 import | `exports` 指向 `dist/index.js`，未 build 会报模块找不到。开发期用 `npm run build -w @loop-agent/main` 或 tsx 直跑 |
| `options.home` 传入相对路径 | 不做规范化（调用方负责传绝对路径）；测试一律传 `mkdtempSync` 的绝对路径 |
| `stop()` 重复调用 | 幂等（内部用 Promise 缓存），与 core `dispose` 语义一致 |

1. **`stop()` 初版不符合 D15**：只撤销服务，Fiber 停在 `PENDING` 而非 `DISPOSED`。改为逆序 `dispose` `host.rootFibers` 后实测 Fiber 变 `DISPOSED`。此修正落在 P1 阶段，但语义属本任务的启停骨架范畴。
