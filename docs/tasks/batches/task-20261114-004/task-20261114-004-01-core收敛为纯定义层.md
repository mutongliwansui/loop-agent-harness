## 一、任务目标需求

### 1.1 背景（痛点）

`core/src/registry.ts` 里的 `PluginRegistry` 是宿主层职责被错放进内核的产物：

- 它只组合 `createHost()` + `createRootContext()`，**未侵入** `context.ts` / `fiber.ts` / `service.ts` / `events.ts` 一行——说明它与内核实现无耦合，天然可外移。
- core 设计 5.10 明确写「纯内存，无磁盘 IO（磁盘动态加载是明确非目标）」，与用户要的「注册中心支持持久化」直接冲突。
- 留着它，`main` 再实现一个持久化版本，就会出现**两个注册中心**并存，语义歧义（`PluginRegistry` 到底指哪个）。

### 1.2 现状梳理

| 所需能力 | 框架现状（链接） | 结论 |
|---|---|---|
| 内核定义层 | `core/src/types.ts`、`context.ts`、`fiber.ts`、`events.ts`、`service.ts`、`errors.ts` | **保留，一字不改** |
| 清单挂载 | `core/src/registry.ts`（75 行，纯内存） | **删除** |
| 导出面 | `core/src/index.ts:29` | 删该行 |
| 上下文注释引用 | `core/src/context.ts:455` 提到 `PluginRegistry` | 中性化改写 |
| 单测引用 | `core/tests/diagnose.test.ts:3,154-284` | 删 describe 块 + import |
| 类型断言引用 | `core/tests/types.test-d.ts:25,282-288` | 删断言 + import |
| 外部消费冒烟引用 | `core/tests/external-consumer.test.ts:131,148-150,173` | 改 `createRootContext` 口径 |
| 文档引用 | `core/README.md:10,147-156`、`core/CHANGELOG.md:25` | 同步更新 |
| 版本号 | `core/package.json:3` `0.1.0` | → `0.2.0` |

### 1.3 任务目标

1. 删除 `core/src/registry.ts` 与 `PluginRegistry` 的全部导出、文档、测试引用。
2. 内核其余公开契约（`Plugin` / `Context` / `Fiber` / `FiberState` / `TypedEventBus` / `ServiceRegistry` / 6 类错误 / `createHost` / `createRootContext`）**一字不改**。
3. core 版本升 `0.2.0`，CHANGELOG 单列「移除（breaking）」。
4. 删除后 `npm run build` 仍恰好 3 个产物文件，`boundary` / `external-consumer` / `types` 测试全绿。

### 1.4 设计约束

- 不得降低测试覆盖率：「链式依赖追平」「单插件 FAILED 不中断」等**内核行为**必须仍有用例覆盖，只是换成 `createRootContext()` + `plugin()` + `host.settle()` 视角。
- `boundary.test.ts` 的六项断言（零三方依赖、零反向依赖、单副本、单 ESM 产物、无 TLA、`exports` 契约）必须继续通过。
- 只出单 ESM 产物的策略不变（`CHANGELOG` 的「已知约束」段落保留）。

### 2.2 关键设计决策

| 编号 | 决策 | 理由 | 被否决项 |
|---|---|---|---|
| **D2**（用户已拍板） | 直接删除，不留 `@deprecated` 壳 | 留下壳会让「两个注册中心」语义并存，且 core 的「纯内存」契约与持久化需求不可调和 | 保留 `@deprecated` 转发到 main（core 会反向依赖 main，彻底颠倒分层） |
| **D13**（本任务新增） | 删除后**不降低覆盖**：`diagnose.test.ts` 里属于**内核行为**的 3 个用例（链式依赖追平、FAILED 不中断、根 Context provide 全局可见）改写成 `createRootContext()` 视角保留，仅删掉「registry 包装层本身」的 3 个用例（`mount` 按序返回、`dispose` 逆序幂等、`registry.diagnose === context.diagnose`） | 前 3 个测的是内核能力（属 core 职责），后 3 个测的是包装层（已移走） | 整块删除（会让内核链式依赖、FAILED 隔离失去回归保护） |

#### 3.1.5 `core/tests/diagnose.test.ts`

- **补 3 个 `createRootContext` 视角的等效用例**（覆盖内核行为，不覆盖包装层）：

```ts
describe('根 Context 的清单式挂载语（内核视角）', () => {
  it('链式依赖可收敛到全 ACTIVE（等价于按清单顺序挂载）', async () => {
    const host = createHost();
    const ctx = createRootContext(host);
    ctx.plugin({ name: 'C', inject: ['b-svc'], apply: () => {} });
    ctx.plugin({ name: 'B', inject: ['a-svc'], apply: (c) => { c.provide('b-svc', 'b'); } });
    ctx.plugin({ name: 'A', apply: (c) => { c.provide('a-svc', 'a'); } });
    await host.settle();
    expect(ctx.diagnose().fibers.map((f) => f.state)).toEqual(['ACTIVE', 'ACTIVE', 'ACTIVE']);
  });

  it('单个插件 FAILED 不中断其余', async () => {
    const host = createHost();
    const ctx = createRootContext(host);
    ctx.plugin({ name: 'good1', apply: () => {} });
    ctx.plugin({ name: 'bad', apply: () => { throw new Error('boom'); } });
    ctx.plugin({ name: 'good2', apply: () => {} });
    await host.settle();
    const states = ctx.diagnose().fibers.map((f) => [f.name, f.state]);
    expect(states).toEqual([['good1', 'ACTIVE'], ['bad', 'FAILED'], ['good2', 'ACTIVE']]);
  });

  it('根 Context 上 provide 的服务对所有插件可见', async () => {
    const host = createHost();
    const ctx = createRootContext(host);
    ctx.provide('shared', 'v');
    let seen: unknown;
    ctx.plugin({ name: 'reader', inject: ['shared'], apply: (c) => { seen = c.get('shared'); } });
    await host.settle();
    expect(seen).toBe('v');
  });
});
```

> 注：v1 草案里写的 `createHost()` 无参数版本 —— 实际 `createHost<E>()` 支持缺省泛型，与 `diagnose.test.ts` 现有用法一致。
