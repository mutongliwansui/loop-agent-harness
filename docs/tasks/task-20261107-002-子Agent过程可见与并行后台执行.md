# task-20261107-002 · 子 Agent 过程可见 + 并行后台委托

> 对应需求编号：**20261107-002**（承接 20261107-001）

> 原型：[20261107-001-子Agent委托原型.html](../prototypes/20261107-001-子Agent委托原型.html)（第五节「过程可见」、第六节「并行后台委托」为本次新增）

## 一、现状与问题

20261107-001 已上线 `delegate` 工具：主 Agent 调 `delegate(task)` → 子 Agent 独立 ReAct 执行 → 结果作为 observation 回写。当前实现有两处体验缺口：

| # | 现象 | 根因（代码位置） |
| --- | --- | --- |
| 1 | delegate 卡片只有「运行中… Ns」心跳与最终结论，看不到子 Agent 在做什么 | `runSubAgent` 构造子 Agent 时**不传 `events`**（[react-agent.ts](../../src/agent/react-agent.ts)），子 Agent 的事件（迭代/工具/思考）全部丢失；`tool_progress` 只有耗时心跳 |
| 2 | 两个互不相干的子任务无法同时后台运行 | `delegate.execute` 内 `await ctx.runSubAgent(...)`（[delegate.ts](../../src/tools/delegate.ts)），工具必须返回才能继续；ReAct 循环等待本轮所有 tool_calls 完成才进入下一轮 |

补充事实：同一轮 LLM 返回的多个 `tool_calls` 确实**并发执行**（`callItems.map` + `Promise.all`），所以「同一轮发两个 delegate」已经能并发，但**整轮仍被阻塞**——主 Agent 无法在子任务运行期间继续推理/回复用户，长任务期间界面表现为「卡住」。

## 二、目标

1. **过程可见**：子 Agent 的迭代、思考摘要、工具调用、最终回答以 `subagent_event`（带 `callId`）转发到主 SSE；前端在 delegate 卡片内提供默认收起的「过程」区，展开即可查看完整执行轨迹。
2. **并行后台**：`delegate` 支持 `background: true`，立即返回任务 ID，主 Agent 继续推理；多个后台子任务并发执行（上限可配，默认 3）；完成后结果落盘为会话卡片并提示。
3. **可观测**：新增 `GET /sessions/:id/subagents` 返回该会话子任务状态（running / done / failed / aborted），前端在存在 running 时轮询并刷新。

### 非目标

- 子任务独立持久化为子会话、跨进程/分布式调度、子 Agent 专用模型路由、多级嵌套委托（仍排除 `delegate`）。
- 后台子任务在进程重启后恢复（不可能：Promise 在内存中；仅标记「已中断」）。

## 三、方案设计

### 3.1 事件转发（过程可见）

```
子 Agent ReActAgent.run({ events: bridgeEvents })
   │
   ├─ onIterationStart(n)      ─┐
   ├─ onLLMEnd(resp, n)        ─┤
   ├─ onToolStart(tool,args)   ─┼─▶ bridge(info) ──▶ 主 Agent onSubAgentEvent(info)
   ├─ onToolEnd(tool,result)   ─┤                        │
   ├─ onToolProgress(tool,ms)  ─┤                        ▼
   └─ onFinal(answer)          ─┘          messages.ts SSE forwarder
                                              write('subagent_event', { callId, ... })
                                                        │
                                                        ▼
                                      chat-stream: 挂到对应 ToolSeg.sub
                                                        │
                                                        ▼
                                  ToolCard: 「过程」折叠区（默认收起）
```

**粒度决策（D1）**：`llm_stream` **不逐字转发**（子任务长文本会造成 SSE 爆炸、前端渲染压力），改为在 `onLLMEnd` 时转发该迭代的完整文本**截断摘要**（默认 4000 字符）。实时性由 `onIterationStart` / `onToolStart` / `onToolProgress` 保障。

**归属决策（D2）**：需要 `callId` 把子事件挂到正确的 delegate 卡片。

```ts
// runner.ts：从 ToolCall 带下来
const ctx: ToolContext = { ..., callId: call.id, runSubAgent };
```

`runSubAgent(task, opts)` 的 `opts` 内含 `callId`（由 `delegate.execute` 从 `ctx.callId` 传入），避免闭包与具体调用耦合。

**类型（types.ts）**：

```ts
export type SubAgentPhase =
  | 'start' | 'iteration' | 'think' | 'tool_start' | 'tool_end' | 'tool_progress'
  | 'final' | 'error' | 'aborted';

export interface SubAgentEventInfo {
  callId: string;
  phase: SubAgentPhase;
  iteration?: number;
  /** phase='think' 时为该迭代文本摘要（截断后）；final 时为最终回答 */
  text?: string;
  /** phase='tool_*' 时 */
  tool?: string;
  args?: Record<string, unknown>;
  result?: string;
  elapsedMs?: number;
  error?: string;
}

/** AgentOptions 新增 */
onSubAgentEvent?: (info: SubAgentEventInfo) => void;

/** ToolContext 新增 */
callId?: string;
```

**SSE 事件（新增一条）**：

```ts
onSubAgentEvent: (info) => write('subagent_event', { info }),
```

payload 与 `SubAgentEventInfo` 同构，前端 `case 'subagent_event'` 按 `info.callId` 找到对应 ToolSeg 写入 `sub.trace`。

### 3.2 前端过程区（默认收起）

`chat-stream.ts`：

```ts
export interface SubAgentToolStep {
  name: string;
  args?: Record<string, unknown>;
  result?: string;
  elapsedMs?: number;
  ok?: boolean;
}
export interface SubAgentTrace {
  status: 'running' | 'done' | 'failed' | 'aborted';
  iterations: number;
  think: Array<{ iteration: number; text: string }>;
  tools: SubAgentToolStep[];
  final?: string;
  startedAt: number;
}
// ToolSeg 新增 sub?: SubAgentTrace
```

`ToolCard.vue`（delegate 专属区块，`toolName === 'delegate'` 时渲染）：

```
┌ 委托子任务 · delegate                        [运行中 00:42] ┐
│ 任务：调研记忆系统…                                          │
│ ▸ 展开过程   3 轮 · 7 次工具调用 · 用时 42s                  │  ← 默认收起
│ ─── 展开后 ───                                              │
│ 第 1 轮 · 思考  需要先确认记忆模块位置…                       │
│   grep  "class WorkingMemory"                    1.2s  ✓   │
│   fileRead  src/memory/working.ts                0.4s  ✓   │
│ 第 2 轮 · 思考  L1 压缩阈值来自 memory.working…               │
│   …                                                        │
│ 结论：L1 内存压缩 / L2 日文件 / L3 SOUL-USER-MEMORY          │
└─────────────────────────────────────────────────────────────┘
```

- **默认收起**（D3）：收起时只显示 meta 行（轮次/工具数/耗时），避免长会话视觉噪音。
- 运行中：meta 行显示当前阶段（「第 2 轮 · 执行 read_file」）+ 展开按钮；**不自动展开**。
- 失败/中断：meta 行转红并展示原因摘要（沿用 20261024-001 的失败态色条语义）。
- 历史回放：`sub.trace` 随 `ToolSeg` 由会话落盘恢复（delegate 工具结果已持久化在 assistant 消息的 tool_calls 中，但 trace 需要新增持久化字段，见 D4）。

**持久化决策（D4）**：trace 需在 **tool 消息**上落盘（新增 `SessionMessageFlags.sub?: SubAgentTrace`，`normalizeMessages` 剥离不进 LLM 请求，同 `usage` 的既有做法），否则刷新后展开过程为空。落盘时机：`onToolEnd` 时由 API 层写入（`tool` 角色消息），与现有 `usage` 挂载路径一致。

### 3.3 并行后台执行

**接口（D5：扩展现有工具而非新增工具）**：

```ts
delegate({ task, context?, background?: boolean })
// background=false（默认）：同步，返回子 Agent 最终回答
// background=true：立即返回 { taskId, status: 'running' } 文本
```

返回文本示例：

```
已提交后台子任务 sub_a1b2c3（任务：调研记忆系统）。完成后会以结果卡片通知，可用 subagent_status 查询状态。
```

**执行流**：

```
delegate(background=true)
  ├─ 生成 taskId：sub_<hex8>_<秒时间戳>
  ├─ 注册到 subAgentRegistry（sessionId, taskId, task, status='running', startedAt）
  ├─ 立即返回（不 await）
  └─ 后台：runSubAgent(task)（独立子 Agent，共享记忆 kit，signal 来自本次 run）
        ├─ 完成 → registry.finish(taskId, {answer}) 
        │          ├─ 落盘结果卡片消息（会话）
        │          └─ 入队后台通知（复用 background-notice 队列）
        └─ 失败/中断 → registry.finish(taskId, {error})
```

**为什么复用 `runSubAgent` 而不是另起通道**（D6）：后台只是「不等待」，执行体与同步完全一致（同样的隔离/共享/防递归语义），避免两套子 Agent 实现漂移。

**并发上限（D7）**：`agent.subAgent.maxConcurrent`，默认 3。超限时**立即返回错误文本**（不排队），由 LLM 决定改期或改同步：

```
错误：后台子任务已达并发上限 3，请等待已有任务完成或改为同步执行。
```

**结果回传（D8）**：完成后必须**主动落盘**，不能只靠「下一轮 run 前 drain」——主 Agent 的 run 已结束、用户可能不再发消息，通知将永远不出现。落盘形式：一条带 `SessionMessageFlags.kind='subagent_result'` 的用户侧展示消息（`isBackgroundNoticeContent` 兼容文本标记，不进 LLM 历史前缀），前端渲染为结果卡片（复用 `BackgroundNoticeCard` 结构，新增摘要字段）。

**查询接口（D9）**：

```ts
GET /sessions/:id/subagents
→ { items: [{ taskId, task, status, startedAt, finishedAt?, elapsedMs?, answerPreview?, error? }] }
```

前端策略：仅当 `messages` 中存在 `running` 后台卡片时启动 2s 轮询；完成后 `resync(id)` 拉取落盘消息并停止轮询。

**进程重启（D10）**：注册表纯内存，重启即丢。启动后首次查询时把历史遗留的 `running` 卡片标记为 `interrupted`（在会话消息上，前端显示「已中断」），不尝试恢复。

### 3.4 CLI 模式的运行与展示（D12–D14）

CLI 没有 SSE、没有可折叠卡片，展示通道不同，需要单独设计（与 WebUI「默认收起」等价的机制是 `verbose` 开关）。

**当前（20261107-001）CLI 实际表现**：

```
⏺ delegate({"task":"调研记忆系统"})
[Observation] 子 Agent 结论…（截断摘要）
✓ delegate (42s)
```

子 Agent 内部**完全静默**：`runSubAgent` 构造子 Agent时 `verbose: false` 且不传 `events`/`spinner`，父级只能看到一行工具开始/结束。（`src/cli/start.ts` 只传 `verbose`/`spinner`，没有事件桥接。）

**D12：CLI 走「控制台直出」而非事件桥接**

```
runSubAgent
  ├─ options.onSubAgentEvent 存在（WebUI）→ 纯事件模式，子 Agent ConsoleLogger 关闭
  └─ 不存在（CLI）→ 子 Agent 自带缩进 ConsoleLogger
        ConsoleLogger(verbose, showTokenStats, undefined, { indent: '  ┆ ' })
        ├─ verbose=false（默认）→ 只在结束时打印一行摘要
        │    ┆ 子 Agent 完成 · 3 轮 · 7 步 · 42s · 结论 120 字
        └─ verbose=true（--verbose / /verbose）→ 逐行缩进打印
        │    ┆ [Iteration 2/5] 思考：先定位记忆模块…
        │    ┆ ⏺ grep("class WorkingMemory")
        │    ┆ [Observation] src/memory/working.ts:59
```

- 子 Agent **不传父级 `spinner`**（共用实例会导致父子抢占、指示器闪行），只靠行输出。
- 「收起/展开」在 CLI 的等价物：默认一行摘要；`verbose` 打开即展开过程。**不做**终端内联折叠交互（破坏 REPL 输入体验）。
- WebUI 与 CLI 共用同一执行体（D6），只是展示适配不同。

**D13：后台子任务在 CLI 的展示**

CLI 是行式 REPL、无常驻事件循环，只能在两个时点打印：

1. **提交时立即打印**：`⏳ 后台子任务 sub_a1b2c3 已提交：调研记忆系统`
2. **下一次输入前 drain 打印**：`✅ 后台子任务 sub_a1b2c3 完成（42s）：结论摘要…`

MVP 不做「空闲即打印」的后台定时轮询（会与正在输入的行冲突）；`--verbose` 下可选启用 1s 空闲轮询（用 `readline` pause/resume 清理行）作为增强项。

**D14：CLI 查看子任务详情（P2 可选）**

`/subagent list`（读 `subAgentRegistry`，按会话列出 running/done/interrupted）与 `/subagent show <taskId>`（打印该任务的过程摘要：轮次、工具序列、最终结论）。这是 CLI 无折叠卡片时的「按需查看」入口。

**已知限制**：后台子 Agent 需要的交互式确认（如危险命令确认）在 CLI 后台模式下无人应答 → 后台模式**仅允许非交互工具**；`delegate(background)` 在 CLI 中遇到需要确认的工具应直接失败并回写错误（不挂起）。

### 3.5 兼容与降级

- `onSubAgentEvent` 未注入（CLI）：**不静默**——按 D12 走缩进 ConsoleLogger（默认一行摘要，verbose 展开）。
- `background` 未开启（配置 `agent.subAgent.background=false`）：忽略参数，按同步执行并返回说明。
- 子 Agent 仍 `excludeTools: ['delegate']`；后台模式同样不递归。
- 主 Agent 停止（`signal` abort）：同步子任务立即中止；**后台任务不随主 run 结束而中止**（这是后台的意义），但会话删除时由 API 层统一 abort（D11）。
- CLI 退出（`Ctrl+D`/进程结束）：所有后台子任务随进程终止，会话文件中未完成卡片标记「已中断」。

## 四、决策点汇总

| 编号 | 决策 | 被否决项 |
| --- | --- | --- |
| D1 | 思考文本按迭代摘要转发（截断 4000 字符），不逐字转发 | 逐字转发 llm_stream：SSE/渲染压力大，收益低 |
| D2 | `callId` 经 ToolContext 传入 `runSubAgent`，事件按 callId 归属卡片 | 按工具名归属：并发多个 delegate 时无法区分 |
| D3 | 过程区**默认收起**，运行中也不自动展开 | 自动展开：长任务会把主对话挤出视口 |
| D4 | trace 挂 tool 消息落盘（`SessionMessageFlags.sub`），`normalizeMessages` 剥离 | 只存内存：刷新/重启后过程丢失 |
| D5 | 扩展 `delegate({ background })`，不新增工具 | 新增 `delegate_background` 工具：LLM 选择成本更高 |
| D6 | 后台复用同一 `runSubAgent` 执行体 | 另写后台执行器：语义漂移风险 |
| D7 | 并发上限默认 3，超限立即报错不排队 | 排队：主 Agent 已拿到 taskId 但实际未运行，语义不清 |
| D8 | 完成时主动落盘结果卡片 + 通知 | 仅靠下一轮 drain：主 run 结束后通知永不出现 |
| D9 | 新增 `GET /sessions/:id/subagents`，前端仅在 running 时轮询 | 复用 `/stream` 续传：run 已结束，无事件可推 |
| D10 | 进程重启后标记 `interrupted`，不恢复 | 恢复：Promise 无法序列化，伪实现会误导用户 |
| D11 | 会话删除时 abort 该会话全部后台子任务 | 放任运行：资源泄漏 |
| D12 | CLI 走「缩进 ConsoleLogger 直出」：默认一行摘要，`verbose` 展开过程 | 在终端做内联折叠：破坏 REPL 输入体验 |
| D13 | CLI 后台任务在「提交时」与「下一次输入前」打印，不做空闲轮询 | 空闲定时轮询：与正在输入的行冲突 |
| D14 | 可选 `/subagent list` / `/subagent show` 作为 CLI 按需查看入口 | 无入口：后台任务状态在 CLI 不可查 |
