# 任务文档：Task-20261022-001 WebUI 工具调用展示中文化与参数友好化

> 对应需求：优化建议台账 `20261022-001`（docs/optimization_suggestions/优化建议.md）
> 交互式原型：docs/designs/原型-20261022-001+工具调用中文化.html（视觉与 D1-D6 已于 2026-10-22 经用户确认，按原型实施）

## 一、任务目标需求

### 1.1 背景（痛点）
WebUI 会话流中的工具调用展示对用户不友好：summary 显示英文工具名 + 行尾原始 JSON 参数串，难读；运行态 LiveStatus 同样显示英文名；展开后只有裸文本结果，长结果无限撑高。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| 工具段渲染 | `webui/src/views/ChatView.vue:517-525`：`✓ {{ seg.tool }}` + 行尾 `{{ seg.args }}`（原始 JSON） | 需重构为「徽章+图标中文名+摘要短语+耗时」 |
| 运行态文案 | `webui/src/components/LiveStatus.vue`：`生成参数：fileWrite…` / `执行中：commandRun…` | 需中文名映射；live 需补充 brief（chat-stream 已有 args 可算） |
| 参数结构 | 无（seg.args 为 JSON 字符串） | 需参数中文标签表 + 原始 JSON 折叠 |
| 结果展示 | `.tc-body` 直接渲染 `seg.result` 原文 | 需限高截断 + 一键展开 |
| 失败标识 | 无（SSE tool_end 无 status 字段） | 前端按结果文本启发式判定 |
| 元数据来源 | `GET /tools` 仅有 name/description/enabled，无中文名 | 前端自建映射常量 |

### 1.3 任务目标
新增前端工具元信息映射层 `webui/src/tool-meta.ts`（10 个内置工具全覆盖），工具卡片与 LiveStatus 中文化；展开详情改为参数表 + 原始 JSON 折叠 + 结果截断可展开；失败显示红 ✗。仅改 WebUI 渲染层，SSE 协议与会话数据结构不动，历史会话天然兼容。

### 1.4 设计约束
- 零新依赖；`tool-meta.ts` 保持纯函数/纯数据（无 DOM 依赖），可在 vitest（Node）下单测。
- webui 不强制 tsc 类型检查（无 vue-tsc），以 `vite build` + 单测 + 全量回归为准；根项目 `npx tsc --noEmit` 不受影响。
- 未知工具 / MCP 工具（`server__tool` 命名）永不空白或报错，回退英文名 + 紧凑 JSON。

## 二、方案设计

### 2.1 总体思路

```
SSE(tool_start/tool_end) ──► chat-stream.ts ──► segments{tool,args,result}
                                   │（新增：live.brief = 摘要短语）
                                   ▼
             ┌──────────── webui/src/tool-meta.ts（新增，纯前端）────────────┐
             │ TOOL_META：10 工具 → {zh, icon, params(中文标签), brief(args)} │
             │ toolSummary() / toolParamRows() / toolResultLooksFailed()     │
             └──────┬────────────────────────┬──────────────────────────────┘
                    ▼                        ▼
        ChatView.vue 工具卡片            LiveStatus.vue 运行态
        (徽章+图标中文名+摘要+耗时，      (生成参数/执行中：中文名[+短语]…)
         展开参数表+原始JSON+结果截断)
```

### 2.2 关键设计决策（原型已确认）

- **D1** 映射层放前端（`webui/src/tool-meta.ts`），不动后端与 SSE 协议，历史会话天然兼容。（被否决：后端加中文字段侵入协议层）
- **D2** summary = 状态徽章 + 图标 + 中文名 + 摘要短语（每工具白名单函数）+ 耗时；未知/MCP 工具回退「⚙️ 英文名 + 紧凑 JSON（80 字符截断）」。
- **D3** 展开详情 = 中文参数表（英文参数名小字附注）+「原始 JSON」折叠块（保留对照排查能力）。
- **D4** 结果区默认限高（约 120px，渐隐 + 展开按钮），展开后限 260px 内滚动；超 2 万字符再按字符截断兜底。
- **D5** 失败徽章启发式判定（结果文本：`[exit=非0]` 开头 / `Error`·`错误`·`异常` 开头 / 含 `Traceback` / `工具执行超时`）。（被否决：改 SSE 加 status 字段，超出仅展示层范围）
- **D6** LiveStatus 三态文案中文化，旋转动画 / 500ms 时钟 / 停滞提示机制不动；brief 由 chat-stream 在 tool_start/tool_progress 时算好放入 live（实现细节：原型示例含 brief，而 live 原结构无 args，故在 chat-stream 补一个 brief 字段，纯前端数据）。

## 三、任务详细设计

### 3.1 `webui/src/tool-meta.ts`（新增）

```ts
export interface ToolMeta { zh: string; icon: string; params: Record<string, string>; brief: (args: Record<string, unknown>) => string; }
export interface ParamRow { key: string; zh: string; text: string }
export function toolMeta(tool: string): ToolMeta            // 未知 → { zh: tool, icon: '⚙️', params: {}, brief: ()=>'' }
export function toolSummary(tool: string, argsJson: string): string   // 已知→brief；未知/解析失败→compactJson(80)
export function toolParamRows(tool: string, argsJson: string): ParamRow[] // 按 params 键序；值超长截 200；object→JSON；无效 JSON→[]
export function toolResultLooksFailed(result: string): boolean
export function compactJson(argsJson: string, max?: number): string
```

映射目录（10 工具）：fileRead 读取文件📖 / fileWrite 写入文件✏️ / editFile 编辑文件🔧 / grep 搜索内容🔍 / commandRun 执行命令⚡ / activateSkill 激活技能🧩 / describe_image 描述图片🖼️ / ask_image 图片问答❓ / extract_json 提取字段📋 / ocr_image 文字识别🔤。摘要示例：fileRead→`src/a.ts（430-500 行）`；commandRun→命令原文；ask_image→`error.png →「问题」`。

### 3.2 `ChatView.vue`
- 模板 517-525 工具段重构：徽章三态（未完成 `⟳` warn / 完成 `✓` ok / 失败 `✗` danger）+ 图标中文名 + 摘要（`title` 保留原始 JSON 悬停）+ 耗时；展开体 = 参数表 + 原始 JSON 折叠（未知工具不重复显示）+ 结果区（clamped 状态按 `msgId:segIdx` 记入 `Set`，默认截断）。
- 样式：`.tc-icon/.tc-name/.tc-sum/.ptable/.jv/.tc-result/.tc-expand/.tc-sec-title/.tc-badge.fail`，移除不再使用的 `.tc-args`。

### 3.3 `chat-stream.ts` + `LiveStatus.vue`
- chat-stream：`tool_start` / `tool_progress` 的 live 增加 `brief`（`toolSummary(tool, JSON.stringify(args))`，args 缺省时为空）；`LivePhase` 类型同步。
- LiveStatus：`生成参数：${中文名}…（N B / Xs）`、`执行中：${中文名}${brief ? ' ' + brief : ''}…（Xs）`；未知工具保留英文原名。

### 3.4 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| args 为无效 JSON（历史脏数据/中断） | summary 回退紧凑 JSON；参数表为空；不抛错 |
| result 为空 | 完成→「（空）」；未完成→「执行中…」 |
| 结果超 2 万字符 | 显示层字符截断 + 「…（已截断，原文共 N 字符）」 |
| 会话恢复（restore）后的旧消息 | 与新消息同构渲染，无需迁移 |
| 深浅色 | 全部走既有 CSS 变量（--ok/--warn/--danger/--line/--code-bg） |

### 3.5 演进项（本任务不做）
- SSE `tool_end` 增加 status 字段（D5 被否决项，可单列需求）；MCP 工具中文名登记机制；结果语法高亮。
