# task-20261028-007 自有数据目录路径点击预览放行（~/.loop-agent）

> 对应需求编号：20261028-007（需求台账同号条目）
> 承接：需求 20261028-006 对话流路径点击预览（D8「不读任意绝对路径」的规则收窄修订）

## 一、任务目标需求

### 1.1 背景（痛点）

20261028-006 上线后实测：工具卡片路径 chip 对「应用自有数据目录」内的路径误伤——

- fileWrite 写记忆：`C:\Users\muton\.loop-agent\memory\{wsId}\*.md`（L2 情景记忆）不可点；
- fileRead 读后台任务日志：`~\.loop-agent\runs\*.log`（commandLogs 日志文件）不可点；
- activate_skill 返回文本明确引导读取的全局技能：`~\.loop-agent\skills\**\SKILL.md` 不可点。

三者均因 D8「ws 外绝对路径不可点」渲染为纯文本（title「文件在工作空间之外」），点击无响应。而 `~/.loop-agent` 是本应用创建与管理的自有数据目录（记忆 / 会话 / runs / uploads / model-bench / skills），预览诉求合理；uploads 已在上次需求特批放行（`/uploads/view`），本次把同口径扩到 uploads 之外的其余自有目录。

### 1.2 现状梳理

| 所需能力 | 现状 | 结论 |
| --- | --- | --- |
| ws 内路径预览 | `/fs/file`、`/fs/raw`（resolveInWs 限定 ws） | 复用，不动 |
| uploads 预览 | `/uploads/view`（D5/D6，校验链同构 /fs） | 复用；顺带修 `~` 字面量缺口 |
| 其余自有目录（memory/runs/skills…） | 无端点；chip 判定 `isPathArgClickable` 拒绝 | **本次新增 `/userdir/view` + 放行判定** |
| `~` 字面量输入 | `resolveInWs` 不展开 `~`，`~/.loop-agent/...` 解析到 `<root>/~/...` 恒 404（上次 CDP 走查仅覆盖绝对路径未发现） | **本次修复（两端点一致）** |
| chip 通道 | ToolCard → ChatView(onOpenPath) → FilesView.openPath | 零改动（判定收敛在 tool-meta） |

### 1.3 任务目标

1. 新增受控只读端点 `GET /userdir/view?path=&disp=file|raw`，root = `~/.loop-agent`（`ctx.userDir` 可注入，单测不写真实目录）；
2. 顺带修既有缺口：`/uploads/view` 与 `/userdir/view` 对 `~` 开头输入先按 homedir 展开再校验；
3. 前端 tool-meta 新增 `/.loop-agent/` 段判定放行 chip；uploads 段仍优先走 `/uploads/view`；FilesView.openPath 分流 openUserDir（与 openUploads 参数化复用）；
4. `~/.claude` 等外部目录与系统路径仍不可点，安全边界不放宽。

### 1.4 设计约束

- 零新依赖；校验链与 /uploads/view 完全同构（词法防穿越 + realpath 防符号链接逃逸）；
- 只读，不做写操作端点；不做独立浮层预览组件；不改工具侧 `~` 解析语义（resolveToolPath 行为不变）；
- 历史会话回放天然生效（chip 判定在渲染层）。

## 二、方案设计

### 2.1 总体思路

```
ToolCard chip 点击 (row.path)
   │ emit open-path（判定：tool-meta.isPathArgClickable）
   ▼
ChatView onOpenPath ──► FilesView.openPath(p)
   │
   ├─ ws 内（含相对路径）──────────► openFile ──► GET /fs/file | /fs/raw
   ├─ uploads 段（/.loop-agent/uploads/）─► openUploads ─► GET /uploads/view  (disp=file|raw)
   ├─ 其余自有目录（/.loop-agent/ 段）──► openUserDir ─► GET /userdir/view  (disp=file|raw)   ← 本次新增
   └─ 其他 ws 外绝对路径 ──────────► 不可点（title 注明），不产生请求
```

### 2.2 关键设计决策

- **D1 放行口径仅 `~/.loop-agent`**：应用自有数据目录整体放行（含 uploads 之外部分），与上次 uploads 特批同口径；「任意绝对路径」（`~/.claude` 等外部应用目录、系统目录）维持拒绝。被否决：白名单枚举子目录（memory/runs/skills…）——目录清单会随版本演进，漏列即误伤，维护成本高且安全增益为零（root 内本来就该可读）。
- **D2 独立端点 `/userdir/view`**：root 固定 `~/.loop-agent`，不给 `/uploads/view` 加 root 参数。被否决：复用 /uploads/view 加 `?root=`——uploads 会话隔离语义被稀释，且等于变相开放任意目录参数。
- **D3 `~` 字面量 homedir 展开**：两端点一致，`~`/`~/`/`~\` 前缀按 `os.homedir()` 展开后走既有校验链（展开后不在 root 内即 403）。修复现状 404 缺口。
- **D4 openUploads 参数化复用**：抽 `openControlled(p, 'uploads'|'userdir')`，二进制/文本双分支渲染链零复制；`fetchRawUploads` 保留导出名，新增 `fetchRawUserDir`（同一底层函数）。
- **D5 file|raw 双档同构**：disp=file 与 /fs/file 同构（512KB 截断 + NUL 二进制拒绝）；disp=raw 原始字节上限 100MB、Content-Type 按扩展名——两常量表与 /uploads/view 共用（抽 shared 模块，不复制）。
- **D6 不做写操作**：userdir 仅 GET；写自有数据目录仍走工具链（fileWrite 已有能力）。

## 三、任务详细设计

### 3.1 后端：`src/api/handlers/controlled-view.ts`（新）

```ts
export const MAX_VIEW_TEXT_BYTES = 512 * 1024;   // 与 /fs/file 同构
export const MAX_VIEW_RAW_BYTES = 100 * 1024 * 1024;
export const VIEW_BINARY_SNIFF_BYTES = 8000;
export const VIEW_CONTENT_TYPES: Record<string, string>; // 自 uploads.ts 上移

/** ~ 开头输入按 homedir 展开（'~'/'~/'/'~\'；其余原样）。home 参数供单测注入 */
export function expandHomeInput(input: string, home?: string): string;

/** 受控只读视图共用体：resolveInWs 词法防穿越 → assertRealInside 防逃逸 → file/raw 双档 */
export async function serveControlledView(root: string, input: string, disp: 'file'|'raw', res: ServerResponse): Promise<void>;
```

错误码沿用：缺参 400 / 越界 403 / 缺失 404 / 超限 413 / 二进制 400 / 不可读 403。

### 3.2 后端：uploads.ts 与 userdir.ts

- `handleUploadView` 收缩为「解析 query → `serveControlledView(ctx.uploadsRoot, expandHomeInput(input), disp, res)`」；`VIEW_CONTENT_TYPES` 等常量上移 controlled-view.ts（uploads.ts 保留 re-export 以免影响既有 import）。
- `src/api/handlers/userdir.ts`（新）：`root = ctx.userDir ?? join(homedir(), '.loop-agent')`；`userdirRoutes(): [{ GET /userdir/view }]`；router.ts 注册（静态段，无冲突）。
- ctx.userDir 既有字段复用（需求 20261026-004 已注入通道），server.ts 零改动。

### 3.3 前端

- `webui/src/tool-meta.ts`：
  - `export function isUserDirPath(raw): boolean`——归一分隔符后含 `/.loop-agent/` 段（uploads 是其子集，分流时 uploads 优先）；
  - `isPathArgClickable` / `pathArgDisabledReason`：`~` 分支与绝对路径分支均加 isUserDirPath 放行（uploads 优先判定保持既有分流）。
- `webui/src/api/uploads-view.ts`：抽 `fetchRawControlled(base, path)`，`fetchRawUploads`/`fetchRawUserDir` 为具名包装（Bearer 注入与错误语义同现有）。
- `webui/src/views/FilesView.vue`：`openPath` 在 uploads 分流后加 `isUserDirPath → openUserDir`；`openUploads` 体抽 `openControlled(p, base)`（文本分支 URL 前缀与二进制分支取数函数按 base 分派），`openUploads`/`openUserDir` 为薄包装。

### 3.4 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| `~/.claude/skills/x/SKILL.md` | chip 不可点（title「文件在工作空间之外」），无请求 |
| `/etc/hosts`、`C:\Windows\...` | 同上 |
| `~` 展开后越出 root（如测试环境 tmp root） | 403 |
| `..` 穿越 / 符号链接逃逸 | 403（词法 + realpath 双重） |
| 文件不存在 | 404 → 前端既有 toast |
| 二进制 disp=file | 400 二进制拒绝 → toast |
| `~` 恰为 root 上层（`~/..`） | 词法 relative 已拦（.. 开头 → 403） |

### 3.5 演进项（本任务不做）

写操作端点、任意绝对路径放行、独立浮层预览、工具侧 `~` 解析语义、`~/.claude` 等外部应用目录放行。
