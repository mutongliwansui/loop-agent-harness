## 一、任务目标需求

### 1.1 背景

task-02 让工具层能显式拿到空间根之后，才轮到**真正的解耦**：把四个"靠 `process.chdir()` + 原地重绑"工作的子系统改为**按空间实例化、根路径构造期固定**，并删除 `chdir`。这是本需求"用户不可见但最关键"的一步——M2 完成时功能与今天一致，但内部已无全局态。

需要拆掉的"原地重绑"机制：

```ts
// src/api/handlers/sessions.ts:132-158 —— 一次切换六件事
process.chdir(target);                          // ① 全局 cwd
await ctx.deps.sessionStore.rebindWorkspace(target);  // ② store 原地改写
ctx.configLoader.setWorkspacePath(target);      // ③ 配置层原地改写
ctx.configWriter.setWorkspacePath(target);
resetMemoryKitCache();                          // ④ 清记忆缓存
await ensureScaffold(defaultBootstrapPaths());  // ⑤ 目录骨架
await ctx.reinitMemory?.(target);               // ⑥ 重置 AgentPool（整池）
```

### 1.3 任务目标

1. **删除 `process.chdir`**（sessions.ts 唯一处）。
2. `SessionStore` 构造期定根；`rebindWorkspace()` 标 `@deprecated`（P1 保留兼容、P2 删除）。
3. `ConfigLoader/ConfigWriter` 由 runtime 构造持有（构造传根），serve 侧**不再调用** `setWorkspacePath`。
4. `SkillLoader` 按 runtime 持有；serve 侧全部 `process.cwd()` → `rt.root`（D14，**不加 `*At` 方法**）。
5. 记忆 kit 由 runtime 持有并懒建（`getMemoryKit(rt.root)`），删除 `defaultMemoryKitFactory` 的 cwd 隐式依赖（改为接收 root）。
6. `AgentPool` 由 runtime 持有，`initAgent` 钩子使用 `rt.root`（含 `attachMemory(kit, rt.root)` 与 `setWorkspaceRoot(rt.root)`）。
7. `memory/vector.ts`、`memory/fts.ts` 改 `createRequire(import.meta.url)`（D16）。
8. `bootstrap/doctor.ts`、`runtime/init.ts` 增加可选 root 参数（默认 `process.cwd()`，CLI 零改动）。
9. 逐条复核 29 处空间资源 cwd，**每处补一行注释**说明"空间资源 → 已改 runtime 根 / CLI 保留"。

### 1.4 设计约束

- **P1 出口契约**：功能与改造前一致（`switchWorkspace` 仍"有运行中会话则拒绝"），但内部**零 chdir、零原地重绑**。
- `src/cli/**`、`src/commands/**` **零 diff**（A7.1）；这些文件里的 `process.cwd()` 保留。
- **不改 `workspaceId()` 公式**（D2）；`<userDir>/sessions/<wsId>` 目录名不变。
- 单例导出（`configLoader`、`configWriter`、`skillLoader`、`config`）**继续存在**（P2 才考虑收敛），保证 CLI 与既有单测零改动。

## 二、方案设计

### 2.1 总体思路

```
WorkspaceRuntime（task-01 建立，本任务填满）
  root / id
  store        = new SessionStore(root)               ← 构造定根，无 rebind
  configLoader = new ConfigLoader(root)               ← 构造定根，无 setWorkspacePath
  configWriter = new ConfigWriter(root)
  skillLoader  = new SkillLoader()  + scan(root)      ← 每 runtime 独立实例
  sessions     = new SessionManager(store)
  pool         = new AgentPool({...}, async a => {
                   await a.attachMemory(await rt.getMemoryKit(), rt.root);
                   a.setWorkspaceRoot(rt.root);       ← task-02 引入
                 })
  getMemoryKit = () => getMemoryKit(root)             ← 按 workspaceId 缓存

switchWorkspace（P1 退化）
  ensureRoot(target) → registry.get(target) → 记录"当前空间指针"
  ✗ chdir  ✗ rebind  ✗ setWorkspacePath  ✗ reset 整池
  ✓ ensureScaffold(target)（新空间缺骨架时补建）
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D7** | **每空间一个 `ConfigLoader`/`ConfigWriter` 实例（构造定根）**，serve 侧不再 `setWorkspacePath` | 继续用单例 + `setWorkspacePath`：两空间并发时后写者覆盖前者，**必错**；每次 `load()` 传 root：`loadWorkspaceSync` 内部大量读 `this.workspacePath`，改造面更大 |
| **D14** | 技能层**不加** `listAt/reloadAt/loadAt`：`scan(cwd)`/`reload(cwd)` 已是必填参数。因 `this.skills` 为实例级状态，**每 runtime 持一个 loader 实例** | 共享单例 + 传 cwd：两空间交替 `scan()` 会互相 `clear()` 覆盖，工具列表抖动 |
| **D11** | CLI 保持单空间：`cli/start.ts`、`commands/*` 中的 `process.cwd()` **不改**，`initAgentMemory()` 等保持无参调用（新增可选参数） | 让 CLI 也走 registry：违反 A7.1 零 diff 红线，且 CLI 本就单空间无收益 |
| **D16** | `vector.ts`/`fts.ts` 的 `createRequire(resolve(process.cwd(),'package.json'))` 改 `createRequire(import.meta.url)`（解析对象是 `node:sqlite` **内置模块**，与空间无关） | 传空间根：空间目录没有 `package.json` 时直接崩，且语义错误 |
| **L1** | `rebindWorkspace` P1 阶段**保留并标 `@deprecated`**，P2 删除 | P1 就删：`sessions.ts` 与其单测需同步大改，混进"解耦"任务难以定位回归 |

### 3.2 `switchWorkspace` 退化（`src/api/handlers/sessions.ts`）

```ts
export async function switchWorkspace(ctx: HandlerContext, target: string): Promise<void> {
  const root = await canonicalWorkspacePath(target);
  await ctx.registry.ensureRoot(root);      // stat + R|X
  const rt = await ctx.registry.get(root);  // 懒建（不 chdir、不 reset）
  await ensureScaffold(defaultBootstrapPaths(root));  // 只补新空间骨架
  ctx.currentRoot = rt.root;                // "当前空间"退化为指针（D9）
}
```

变化点：

- 删除 `process.chdir` 与回滚；
- 删除 `rebindWorkspace` / `setWorkspacePath` / `resetMemoryKitCache` / `reinitMemory` 调用（`reinitMemory` 入参改由 registry 承担，见 3.5）；
- `hasInFlight()` **P1 阶段保持全局语义**（跨空间并行禁止仍在，task-04 才放开）——这样 P1 可独立上线；
- `ensureScaffold` / `defaultBootstrapPaths` 需支持 root 参数（当前隐式 cwd）。

### 3.5 `reinitMemory` 的去留

- 旧语义：切换空间后"重置记忆 + 重置整池"（[bootstrap.ts:60-63](file:///d:/trae_workspace/loop-agent-command/src/api/bootstrap.ts#L60-L63)）；
- 新语义：**无需重置**——每空间独立的 pool/kit/store 各就各位；切回旧空间直接复用其 runtime（LRU 未淘汰时）；
- P1 阶段：`reinitMemory` 保留为可选依赖（`/config`、`/model` 变更仍可能用到），但 `switchWorkspace` **不再调用**；调用点收敛到"配置变更后重置**当前空间**的池"。

### 3.6 边界与错误处理

| 场景 | 行为 |
|---|---|
| 目标目录不存在 / 无权限 | `registry.ensureRoot` 抛 `not_found` / `forbidden`（与原 `ensureDirUsable` 一致） |
| 新空间缺 `.loop-agent` 骨架 | `ensureScaffold(root)` 幂等补齐；失败只记日志不阻断（沿用现状） |
| 新空间配置缺失 | `ConfigLoader(root).load()` 走 env/global/default 回退（现状行为） |
| `realpath` 失败（目录刚被删） | `canonicalWorkspacePath` 回退 `resolve`；后续 `ensureRoot` 抛 `not_found` |
| 切回已淘汰的空间 | runtime 重建（LRU miss）；会话历史从磁盘恢复（`ensureEntry` 已支持） |

### 3.7 演进项

- 删除 `rebindWorkspace` 与 `setWorkspacePath`（task-04）。
- 单例导出收敛（`configLoader` 等），避免 CLI 与 serve 语义混淆——本批次不动。
