# Task-20261012-001：文件上传（/upload 会话隔离上传目录）

> 目标：让用户能把本地文件"上传"（复制）进 Agent 的全局上传目录，按会话物理隔离存放；上传完成后将文件路径注入当前会话上下文，Agent 在后续对话中可直接用 fileRead / commandRun / 视觉工具处理该文件——打通"给 Agent 喂附件"的链路，无需用户口头转述路径。
>
> 对应优化建议编号：`20261012-001`（条目随本任务在 `docs/optimization_suggestions/优化建议.md` 登记）

---

## 一、任务目标需求

### 1.1 背景

当前用户想让 Agent 处理本地文件（文本、代码、Excel、图片等），只能自己在对话里手敲文件绝对路径。痛点：

1. 路径全靠手输，长路径/含空格路径易错；
2. Agent 工作空间目录（`process.cwd()`）会混入用户临时文件，污染 git 工作区；
3. 多会话场景下文件无归属，会话删除后残留孤儿文件。

Windows 终端天然支持把文件从资源管理器**拖进终端窗口**（自动插入带引号的完整路径，多文件拖入产生多段引号路径），这是"上传"的零成本入口，无需引入文件选择框或任何 GUI 依赖。注意各平台终端拖拽插入格式不同：Windows Terminal 为引号路径，Linux GNOME Terminal 为 `file://` URI，Konsole 为引号+转义路径——解析器统一归一（见 D5），不依赖单一终端行为。

### 1.2 现状梳理（框架契合度）

| 上传链路需要的能力 | 当前框架现状 | 结论 |
|---|---|---|
| 会话标识 | `SessionStore.currentSessionId`（[store.ts:85](file:///d:/trae_workspace/loop-agent-command/src/session/store.ts#L85)），autoSave 首轮对话后即有正式 id；会话存储于 `~/.loop-agent/sessions/{workspaceId}/` | 上传目录 sessionKey 直接取 `currentSessionId` |
| 上下文注入 | Agent 内存历史 `_chatHistory`（[react-agent.ts:386](file:///d:/trae_workspace/loop-agent-command/src/agent/react-agent.ts#L386)），run 时拼入 messages；autoSave 时随轮次落盘、`/session load` 恢复 | 注入历史即可随会话持久化，无需新存储 |
| 文件处理工具 | `fileRead` / `fileWrite` / `editFile`（文本）、`commandRun`（shell，可跑 Python 处理 Excel 等）、视觉工具（图片，[image.ts](file:///d:/trae_workspace/loop-agent-command/src/tools/vision/image.ts)） | 上传后 Agent 自主选择工具，无需新增执行工具 |
| 命令框架 | `CommandRegistry` + `CommandContext`，`BUILTIN_SLASH_COMMANDS` + Tab 补全 + argProvider 动态参数 | 新命令零框架改动 |
| REPL readline | 主 REPL 复用同一 `rl`（[index.ts:246](file:///d:/trae_workspace/loop-agent-command/src/index.ts#L246-L256)） | 命令在 line 事件内同步处理，不与 stdin 抢占 |
| 全局目录 | `~/.loop-agent/` 已有 config.json / sessions / logs / memory | 新增 `uploads/` 同级子目录，mkdir -p 即可 |

**关键结论**：

1. **上传 = 复制 + 注入**，纯文件操作，无协议/无新依赖（仅 `node:fs` / `node:path`）。
2. **会话隔离天然成立**：注入的上下文消息随 `_chatHistory` 只属于当前会话；物理目录按 `uploads/{sessionId}/` 分隔。
3. **拖拽即上传**：Windows Terminal / conhost 拖文件进窗口 = 输入带引号路径，`/upload` 解析即可，不需要文件选择框。

### 1.3 任务目标

- `/upload <路径...>`：把一个或多个本地**文件**复制到 `~/.loop-agent/uploads/{sessionId}/`，文件名加时间戳前缀防重名；打印上传清单；向当前会话注入带上传路径的上下文消息。
- 支持多选：一次传多个路径；终端拖拽多文件（多段引号路径）直接可用。
- `/upload`（无参数）：弹出**系统文件选择框**（跨平台探测链：Windows PowerShell + WinForms / macOS osascript / Linux zenity → kdialog → yad；支持多选），选中即上传；全部工具不可用时降级为拖拽 / 路径参数提示——拖拽之外的第二入口。
- `/upload list`：列出当前会话已上传文件（名称、大小、上传时间）。
- `/upload clean`：清理当前会话的上传目录（需 y/n 确认）。
- `/session delete <id>` 与 `/session delete-all`：**连带清理**对应会话的 uploads 子目录（已确认决策）。
- Agent 感知：下一轮对话自动"知道"文件路径与大小，可自主决定用 fileRead / commandRun / 视觉工具处理；**不自动触发回答**。
- 单文件大小上限 100MB（内置常量，不入配置）。
- 零新依赖；零配置项（不新增 config schema 字段）。

### 1.4 设计约束

- **不污染工作空间**：上传目录在全局 `~/.loop-agent/uploads/`，与工作空间 git 工作区物理隔离。
- **复制不移动**：源文件始终不动，上传是"拷贝进 Agent 领地"。
- **会话语义**（已确认决策，2026-10-14 修订为 D10）：sessionKey 恒取 `agent.currentSessionId`；**不设 default 回退**——为空时**按需创建会话**（`createSession('[文件上传]', [], [])`）再上传，仅当会话功能不可用（`sessionStore === null`）才拒绝并提示「会话功能未启用」。
- **仅文件**：路径指向目录时该项报错并提示（不支持递归目录上传，已确认决策）。
- **历史注入轻量**：注入消息 ≤ 数行，不携带文件内容，token 体积可忽略。
- **可独立验证**：manager 为纯逻辑模块（fs 通过 tmpdir 真实文件验证），命令壳薄，单测不依赖真实终端。

## 二、方案设计

### 2.1 总体思路

```
用户拖拽文件 / 手输路径 / `/upload` 无参弹框多选
        │  （终端拖拽自动插入路径，格式随终端而异：Windows 引号路径
        │    "D:\path\a.png"、Linux GNOME Terminal 为 file:///…、Konsole 为引号+转义；
        │    无参时先经 pickFilesViaDialog() 按平台探测链弹出系统选择框取得路径数组）
        ▼
/upload "D:\path\a.png" "D:\path\b.xlsx"
        │  parseUploadArgs()      跨平台归一为本地路径数组（D5）
        ▼
┌────────────────────────────────────────────┐
│ uploadManager.copyToUploads(paths, opts)   │
│  ① sessionKey = ensureSessionKey(ctx)      │ 无会话→按需创建（D10）；sessionStore=null→拒绝
│  ② 逐项校验：存在 / 是文件 / ≤100MB          │ 单项失败记录，其余继续
│  ③ copyFile → uploads/{sessionKey}/        │
│     {yyyymmdd-hhmmss}-{原文件名}            │ 同秒同名追加毫秒段
└────────────────────────────────────────────┘
        ▼
打印清单（✓ 原名 → 上传路径 / ✗ 原因）
        ▼
agent.appendContextNote()   → _chatHistory 注入：
  [文件上传] a.png
    上传路径: C:\Users\<user>\.loop-agent\uploads\{sessionId}\20261012-153001-a.png
    大小: 1.2MB
        ▼
（autoSave 随轮次落盘；用户继续提问 → Agent 用 fileRead/commandRun/视觉工具处理）
```

### 2.2 关键设计决策

1. **D1 物理目录按会话分隔**：`~/.loop-agent/uploads/{sessionId}/`——全局根目录跨 workspace 共享（会话本就按 workspaceId 分区存储，sessionId 全局唯一），子目录即隔离单元；`/session delete` / `delete-all` / `/upload clean` 三处删除入口对齐。
2. **D2 上下文注入而非工具**：不新增"上传"工具给模型（上传是用户侧动作）；上传完成后向 `_chatHistory` push 一条带 `[文件上传]` 标记的 user 消息。Agent 对文件的存在与路径的感知来自历史，恢复会话后依然有效。
3. **D3 时间戳前缀防重名**：`{yyyymmdd-hhmmss}-{原文件名}`——同会话内多次上传同名文件互不覆盖；同秒撞名（概率极低）追加 `-{毫秒}` 段。
4. **D4 上限内置常量**：`MAX_UPLOAD_BYTES = 100MB` 硬编码在 manager——避免为单一防线增加配置面；超限报错信息写明上限值。
5. **D5 参数解析与跨平台归一**：`parseUploadArgs(raw)` 统一处理各终端拖拽格式——① 引号段（`"..."` / `'...'`，Windows Terminal / Konsole）② `file://` URI（GNOME Terminal 等，`decodeURIComponent` + `fileURLToPath` 归一为本地路径，多 URI 以空白分隔）③ 转义空格（`a\ b.png`，Konsole）④ 无引号单路径。解析结果恒为本地绝对路径候选数组。
6. **D6 不自动触发 Agent**：上传只注入上下文不发起提问——上传可能是批量准备动作（一次喂 5 个文件再一起问），触发权留给用户下一条消息。
7. **D7 clean 与 delete 职责分离**：`/upload clean` 清当前会话目录（交互确认）；`/session delete/delete-all` 连带清理（无需确认，会话本体已删）。会话 load 切换后旧会话上传文件不迁移（历史里的路径仍有效）。
8. **D8 manager 纯逻辑 + 命令薄壳**：路径解析、校验、复制、列表、清理全部在 `src/upload/manager.ts`（fs/promises，tmpdir 可测）；upload-command 仅做 ctx 组装与输出渲染。
9. **D9 无参打开文件选择框（跨平台探测链）**：`/upload` 不带参数时按平台弹出系统文件选择框——**Windows**：`powershell -NoProfile -STA` + WinForms `OpenFileDialog`（`Multiselect=true`）；**macOS**：`osascript -e 'choose file with multiple selections allowed'`（POSIX path 输出）；**Linux**：依次探测 `zenity --file-selection --multiple` → `kdialog --getopenfilename --multiple` → `yad --file --multiple`（`which` 探测，命中即用）。选中路径逐行输出到 stdout 归一为路径数组；输出为空 = 用户取消；**全部工具不可用 / 命令执行失败 → 降级**：提示选择框不可用，改用拖拽或 `/upload <路径>`。弹窗期间 REPL 模态等待（期望行为，Spinner 提示中）。零 npm 新依赖。
10. **D10 无会话时按需创建（2026-10-14 追加）**：`currentSessionId` 置空有 5 条路径（`/session new`、`/reset`、`/session delete` 当前、`delete-all`、首次安装），原「无活动会话拒绝」不符合使用规范（用户反馈：`/session new` 后立即 `/upload` 报错）。改为在 `/upload` 咽喉处 `ensureSessionKey()`：agent 侧为空且有 sessionStore 时 `createSession('[文件上传]', [], [])` + `setCurrentSessionId(meta.id)`。**判定必须用 `agent.currentSessionId`**——`SessionStore.currentSessionId` 在 `agent.resetSession()` 后是陈旧值；`sessionStore === null`（会话功能未启用）才拒绝。备选方案 A（`/session new`/`/reset` 处 eager 建会话）会产生空目录，被否决。

## 三、任务详细设计

### 3.1 上传管理器 `src/upload/manager.ts`（P0）

```typescript
export const MAX_UPLOAD_BYTES = 100 * 1024 * 1024;

export interface UploadEntry {
  originalPath: string;   // 源路径（原样回显）
  targetPath: string;     // 上传后绝对路径
  fileName: string;       // 时间戳前缀后的文件名
  bytes: number;
  uploadedAt: string;     // ISO 时间
}

export interface UploadResult {
  succeeded: UploadEntry[];
  failed: { path: string; reason: string }[];
}

/** 拆分参数并跨平台归一：引号段（"…"/'…'）/ file:// URI（decodeURIComponent + fileURLToPath）/
 *  转义空格（a\ b.png）/ 无引号单路径；输出恒为本地绝对路径候选数组 */
export function parseUploadArgs(raw: string): string[];

/** 弹出系统文件选择框（跨平台探测链：win32 → PowerShell WinForms；darwin → osascript；
 *  Linux → zenity / kdialog / yad 依次探测。Multiselect 多选，选中路径逐行输出；
 *  取消/全部工具不可用/执行失败返回 []，降级原因随 stderr 分类） */
export async function pickFilesViaDialog(): Promise<string[]>;

/** 批量复制：单项失败不阻断其余；sessionKey 为空串时整体拒绝 */
export async function copyToUploads(
  paths: string[],
  opts: { sessionKey: string; uploadsRoot: string; now?: Date },
): Promise<UploadResult>;

/** 列出会话上传目录（目录不存在返回 []） */
export async function listUploads(uploadsRoot: string, sessionKey: string): Promise<UploadEntry[]>;

/** 清理会话上传目录，返回是否删除了内容 */
export async function cleanUploads(uploadsRoot: string, sessionKey: string): Promise<boolean>;
```

- 校验顺序：存在（`stat`）→ 是文件（`isFile()`）→ 大小 ≤ 上限；`copyFile` 落盘。
- 时间戳格式与 SessionStore 的 `formatDate` 对齐（`yyyymmdd_hhmmss` → 此处用 `yyyymmdd-hhmmss` 紧凑变体亦可，落地时统一）。

### 3.2 上下文注入 `src/agent/react-agent.ts`（P0）

```typescript
/** 向会话历史追加一条用户侧上下文备注（文件上传等），随 autoSave 持久化 */
appendContextNote(note: string): void {
  this._chatHistory.push({ role: 'user', content: note });
}
```

### 3.6 边界与错误处理

| 场景 | 处理 |
|---|---|
| 路径不存在 / 是目录 | 该项计入 failed（reason：文件不存在 / 仅支持文件），其余项继续 |
| 单文件 > 100MB | 该项计入 failed，reason 注明上限 |
| `currentSessionId === null` | 按需创建会话（D10：`createSession('[文件上传]')` + `setCurrentSessionId`）再继续；仅 `sessionStore === null` 时拒绝并提示「会话功能未启用」 |
| 同秒同名冲突 | 目标名追加 `-{毫秒}` 段，不覆盖 |
| uploads 目录不存在 | `mkdir -p` 幂等创建 |
| 磁盘不可写 / 空间不足 | copyFile 抛错计入该项 failed，原样透传 message |
| 拖拽路径含空格/中文 | 解析器归一（D5）：Windows 引号段、Linux `file://` URI、Konsole 转义空格均正确转本地路径 |
| `/upload` 无参且用户取消选择框 | 输出为空 → 提示「已取消」返回，不报错 |
| 无可用选择框工具（Windows PowerShell 失败 / Linux 无 zenity、kdialog、yad / 非 GUI 会话无 $DISPLAY） | 降级：提示选择框不可用，引导拖拽文件或 `/upload <路径>` |
| 弹窗期间 REPL 等待 | 模态期望行为：Spinner 提示「等待选择文件…」，关闭对话框后继续；exec 设长超时（10 分钟）防挂死 |
| `/session load` 切换会话 | 后续上传进入新会话目录；旧文件留在原目录（原历史路径仍有效） |
| `/upload clean` 无内容 | 提示「当前会话无上传文件」 |
| 非 TTY / 管道 | 上传与 list 正常工作（无交互）；clean 的 y/n 确认在非 TTY 下读 stdin 行，EOF 视为取消 |

### 3.7 演进项（本任务不做）

- 剪贴板截图直接上传（`/upload clip`）
