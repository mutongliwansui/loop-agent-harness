## 一、任务目标需求

### 1.1 背景

当前 CLI 从「用户回车」到「看到结果」的链路中，所有可见输出都来自事件监听器 `ConsoleLogger`（[logger.ts](file:///d:/trae_workspace/loop-agent-command/src/agent/logger.ts)），而这些输出**全是"边界事件"**（开始/结束各打一次），过程中没有任何"进行中"的心跳提示。一旦某个阶段耗时较长，界面就会长时间一片空白。

经代码梳理（见 1.2），空窗集中在模型生成与工具执行阶段，典型表现为：模型正在"憋"一个 `fileWrite` / `editFile` 的大 JSON 参数时，因 `streamLLM` 只把文本 `delta` 转发给 `onLLMStream`（[react-agent.ts:691-697](file:///d:/trae_workspace/loop-agent-command/src/agent/react-agent.ts#L691-L697)），**生成工具调用参数的全程没有任何输出**，直到生成完成才突然打印 `[Action]`。

### 1.3 任务目标

- 用户在等待期间**始终能看到**「正在做什么」的实时提示（转圈动画 + 阶段文案）。
- 覆盖 **A / D / E** 三个主要空窗；**B / C** 通过"轮次级"指示器覆盖。
- **不干扰正常输出**：日志、流式 Thought、最终答案照常打印，且与指示器**不混行**。
- **非交互场景自动禁用**：管道、重定向、CI、单元测试（非 TTY）下不输出任何动画字符，零污染。
- **零新依赖**：不引入 `ora` 等第三方包，纯 ANSI 自绘。

### 1.4 设计约束

- **不改动 ReAct 循环业务逻辑与事件语义**：不改变现有事件触发时机与参数。
- **指示器与 `verbose` 解耦**：即使 `verbose=false`（连边界日志都不打）也应显示 loading。
- **可单元测试**：指示器的输出目标（写函数）、开关、帧序列均可注入，便于断言。
- **不改变 readline 暂停语义**：不得通过 `rl.pause()` 造成"排队输入自动执行"。
- **跨终端兼容**：Windows 缺字形终端需可回落 ASCII 帧。
- **单次改动可独立验证**：不阻塞其他任务。

## 二、方案设计

### 2.1 总体思路

```
用户回车
  └─ agent.run()
       ├─ onStart        ──(print header)──▶ 【指示器 start：思考中…】
       └─ for 每轮迭代:
            ├─ onIterationStart ─(print)──▶ 【指示器 start：思考中…（第 N 轮）】
            │     ├─ L1 压缩（B）  ← 指示器已在转，覆盖
            │     ├─ Context Assembly（C） ← 指示器已在转，覆盖
            │     └─ streamLLM（A/E）
            │           ├─ onLLMStream(首个 delta，仅 verbose) ──▶ 【指示器 stop（内容开始流式输出）】
            │           └─ onLLMEnd ──▶ 【指示器 stop】
            ├─ onToolStart      ──▶ 【指示器 stop → 打印 [Action] → start：执行中：<tool>…】
            ├─ 工具执行（D）     ← 指示器在转，覆盖
            └─ onToolEnd        ──▶ 【指示器 stop → 打印 [Observation]】
       ├─ onFinal ──▶ 【指示器 stop】→ 打印 Final Answer
       └─ onEnd   ──▶ 【指示器 stop】→ 打印完成统计
```

核心：**指示器随事件"start / stop"，任何 `console.log` 之前先 `stop()` 清行，之后再按需 `start()`。**

### 2.2 关键设计决策

1. **Spinner 由 CLI 层创建、经 `AgentOptions` 注入（归属层）**
   Spinner 实例在 `index.ts` 创建，通过新增的 `AgentOptions.spinner` 传入 `run()`，再由 `run()` 转交给默认 `ConsoleLogger`（[react-agent.ts:363-366](file:///d:/trae_workspace/loop-agent-command/src/agent/react-agent.ts#L363-L366)）。原因是 **CLI 层自己也会直接 `console.log`**——`running` 守卫警告（[index.ts:238](file:///d:/trae_workspace/loop-agent-command/src/index.ts#L238)）与完成统计行（[index.ts:279](file:///d:/trae_workspace/loop-agent-command/src/index.ts#L279)）——只有 CLI 持有 Spinner 引用，才能在这些打印前先 `stop()` 清行。程序化调用（测试、集成）不传即无指示器。

2. **把起停逻辑收进 `ConsoleLogger`（打印前先清行）**
   运行期所有可见输出都由 `ConsoleLogger` 打印，且 `composeEvents` 中它排在用户监听器**之前**（[react-agent.ts:363-366](file:///d:/trae_workspace/loop-agent-command/src/agent/react-agent.ts#L363-L366)）。由它统一在每次打印前 `spinner.stop()`，才能保证**绝不与指示器行混行**；若改用独立 listener，其 `stop()` 会晚于打印，必然错位。

3. **复用现有事件，不新增 `AgentEvents` 钩子**
   `onStart / onIterationStart / onLLMStream / onLLMEnd / onLLMStats / onLLMStatsSummary / onToolStart / onToolEnd / onCompaction / onFinal / onError / onWarning / onEnd` 已能完整覆盖 A~F，避免扩大事件接口面。

4. **非 TTY 自动禁用 + 依赖注入**
   `enabled` 默认取 `process.stdout.isTTY === true`；`write` 默认 `process.stdout.write`；`intervalMs` 默认 80；`frames` 可配置。前三者在测试中可注入 mock，动画可关闭。

5. **指示器与 `verbose` 解耦，但"停"必须与"是否真的打印"对齐**
   起停逻辑写在 `verbose` 判断之外；但 `onLLMStream` **仅当 `verbose` 为真（内容确实会被打印）时才停**，否则 `verbose=false` 下会在无内容输出时提前停止、反而留下新空窗。

6. **跨终端兼容**
   Windows 部分终端/字体缺少 Braille 字形，默认帧需提供 **ASCII 兜底**（`frames` 可配置）。

### 2.3 事件 → 指示器动作 / 文案映射

| 事件 | 指示器动作 | 文案 | 备注 |
|------|-----------|------|------|
| `onStart` | start | `思考中…` | 覆盖启动到首轮之间 |
| `onIterationStart(i)` | stop → print → start | `思考中…（第 ${i+1} 轮）` | 覆盖 B / C / A / E |
| `onLLMStream(delta)` | **仅 `verbose` 时 stop** | — | 首个 delta 即停，让文本接管；`verbose=false` 时不停，避免提前留空窗 |
| `onLLMEnd` | stop | — | 兜底停止 |
| `onLLMStats` | stop → print | — | 打印 token 统计行（显式包裹，勿依赖"隐式已停"） |
| `onLLMStatsSummary` | stop → print | — | 打印汇总行 |
| `onCompaction` | stop → print → start | `思考中…` | 打印 `[记忆]` 后恢复 |
| `onToolStart(tool)` | stop → print → start | `执行中：${tool}…` | 覆盖 D |
| `onToolEnd` | stop → print | — | 打印 `[Observation]` |
| `onWarning(msg)` | stop → print | — | 打印告警（如会话保存失败），**防止混行** |
| `onFinal` | stop | — | 打印 Final Answer |
| `onError` | stop | — | 打印错误 |
| `onEnd` | stop | — | 打印完成统计（`result=null` 时**也必须** stop） |

### 2.4 与 readline 的协作

`index.ts` 的 REPL 使用 `readline`（[index.ts:188](file:///d:/trae_workspace/loop-agent-command/src/index.ts#L188)）。运行期间 `safePrompt()` 不会被调用，因此不存在"提示符被冲掉"的问题。**结论：不暂停/恢复 readline**，理由：

- 若 `rl.pause()`，运行期间用户键入的字符会被缓冲，`rl.resume()` 后作为完整行重新触发 `rl.on('line')`，**可能自动发起一次新对话**；且 `resume` 若早于 `running = false`，还会先命中守卫分支，产生意外行为。
- Spinner 每帧以 `\r\x1b[K` 重绘，会自然覆盖该行的误击字符（视觉自愈）；用户提交整行时仍由既有 `running` 守卫给出提示。

因此仅需：CLI 层持有 Spinner 引用，在自身打印（守卫警告、完成行）前 `spinner.stop()`；**不触碰 readline 的暂停语义**。

## 三、任务详细设计

### 3.1 新增 Spinner 组件 `src/ui/spinner.ts`

```typescript
// src/ui/spinner.ts — 零依赖的自绘 loading 指示器
// Braille 帧；Windows 部分终端/字体缺字形时，可传 ASCII 兜底：['|', '/', '-', '\\']
const FRAMES = ['⠋', '⠙', '⠹', '⠸', '⠼', '⠴', '⠦', '⠧', '⠇', '⠏'];

export interface SpinnerOptions {
  /** 是否启用动画，默认 process.stdout.isTTY === true */
  enabled?: boolean;
  /** 输出目标，默认 process.stdout.write（便于测试注入） */
  write?: (s: string) => void;
  /** 帧间隔，默认 80ms */
  intervalMs?: number;
  /** 动画帧序列，默认 Braille；可传 ASCII 以兼容缺字形终端 */
  frames?: string[];
}

export class Spinner {
  private timer: NodeJS.Timeout | null = null;
  private frame = 0;
  private text = '';
  private active = false;
  private readonly enabled: boolean;
  private readonly write: (s: string) => void;
  private readonly intervalMs: number;
  private readonly frames: string[];

  constructor(opts: SpinnerOptions = {}) {
    this.enabled = opts.enabled ?? process.stdout.isTTY === true;
    this.write = opts.write ?? ((s) => process.stdout.write(s));
    this.intervalMs = opts.intervalMs ?? 80;
    this.frames = opts.frames ?? FRAMES;
  }

  get isActive(): boolean { return this.active; }

  /** 启动/更新指示器（重复调用视为更新文案） */
  start(text: string): void {
    if (!this.enabled) return;
    this.text = text;
    if (this.active) { this.render(); return; }
    this.active = true;
    this.render();
    this.timer = setInterval(() => {
      this.frame = (this.frame + 1) % this.frames.length;
      this.render();
    }, this.intervalMs);
    this.timer.unref?.();
  }

  update(text: string): void {
    if (!this.enabled || !this.active) return;
    this.text = text;
    this.render();
  }

  /** 停止并清行；可传入收尾文案（会换行保留） */
  stop(finalText?: string): void {
    if (!this.active) return;
    this.active = false;
    if (this.timer) { clearInterval(this.timer); this.timer = null; }
    if (this.enabled) {
      this.write('\r\x1b[K');            // 回到行首 + 清除整行
      if (finalText) this.write(`${finalText}\n`);
    }
  }

  private render(): void {
    this.write(`\r\x1b[K\x1b[36m${this.frames[this.frame % this.frames.length]}\x1b[0m ${this.text}`);
  }
}
```

### 3.2 改造 `ConsoleLogger`（`src/agent/logger.ts`）

- 构造函数新增可选第三参 `spinner?: Spinner`。
- 新增私有 `emit(fn)`：先 `this.spinner?.stop()` 再执行打印，保证打印前先清行。
- 在各事件回调中按 2.3 注入"起停"逻辑，**起停写在 `verbose` 判断之外**，文字日志仍受 `verbose` 控制。

关键片段示意：

```typescript
export class ConsoleLogger implements AgentEvents {
  constructor(
    private verbose = true,
    private showTokenStats = true,
    private spinner?: Spinner,
  ) {}

  private emit(fn: () => void): void {
    this.spinner?.stop();   // 打印前先清掉指示器行，避免混行
    fn();
  }

  onIterationStart(i: number, max: number): void {
    this.emit(() => {
      if (this.verbose) console.log(`\n${COLORS.gray}━━━ 迭代 ${i + 1}/${max} ━━━${COLORS.reset}`);
    });
    this.spinner?.start(`思考中…（第 ${i + 1} 轮）`);   // 不受 verbose 影响
  }

  onLLMStream(delta: string): void {
    if (!this.verbose) return;   // verbose=false 时内容不打印，保持指示器运转，避免留空窗
    this.spinner?.stop();        // 内容即将输出，停止动画
    /* 原有 Thought 前缀 + 流式写入逻辑 */
  }

  onLLMEnd(response: LLMResponse): void {
    this.spinner?.stop();
    if (!this.verbose) return;
    /* 原有换行逻辑 */
  }

  onToolStart(tool: string, args: Record<string, unknown>): void {
    this.emit(() => {
      if (!this.verbose) return;
      /* 原有 [Action] 打印 */
    });
    this.spinner?.start(`执行中：${tool}…`);
  }

  onToolEnd(tool: string, result: string): void {
    this.emit(() => {
      if (!this.verbose) return;
      /* 原有 [Observation] 打印 */
    });
  }

  onCompaction(info: CompactionInfo): void {
    this.emit(() => {
      if (!this.verbose) return;
      /* 原有 [记忆] 打印 */
    });
    this.spinner?.start('思考中…');
  }

  onLLMStats(stats: LLMStats): void { this.emit(() => { if (this.verbose && this.showTokenStats) {/* 原有 */} }); }
  onLLMStatsSummary(): void { this.emit(() => { if (this.verbose && this.showTokenStats) {/* 原有 */} }); }
  onWarning(message: string): void { this.emit(() => { if (this.verbose) {/* 原有告警打印 */} }); }

  onFinal(answer: string): void { this.emit(() => { if (this.verbose) {/* 原有 */} }); }
  onError(error: Error): void { this.emit(() => { if (this.verbose) {/* 原有 */} }); }
  onEnd(result: AgentResult | null): void { this.emit(() => { if (this.verbose) {/* 原有 */} }); }
}
```

> 说明：`onToolStart` / `onCompaction` 等"打印后仍需继续等待"的事件，采用 `stop → 打印 → start` 三段式；`onToolEnd` / `onLLMStats` / `onLLMStatsSummary` / `onWarning` / `onFinal` / `onError` / `onEnd` 为"打印型/终止型"，只 `stop`（**不再依赖"上一步已隐式停"**）。
> 注意：`onEnd(result)` 在 `result=null`（如 `run` 抛出异常）时**也必须 `stop`**，`emit()` 已保证这一点（stop 不受 `if (this.verbose)` 与 `if (result)` 影响）。

### 阶段四：P2 补充 — 工具调用参数生成空窗（联调发现）

**问题**：实测「让 Agent 生成 README.en.md」时，`[Thought] …一一对应）。` 到 `[Action]fileWrite(...)` 之间存在长时间无 loading 的空窗。

**根因**（三处叠加）：
1. `chatStream` 对 `tool_calls.arguments` 增量会 `yield toolCallStart/toolCallDelta`（`client.ts`），但 `streamLLM` 原先只处理 `delta`/`done`，**参数增量被丢弃**；
2. `ConsoleLogger.onLLMStream` 在 Thought 首个文本分片时 `stop()` 让行，之后到 `onToolStart` 之前**无人重启**指示器；
3. `fileWrite` 的整个文件内容就是 `arguments.content`，逐 token 生成且完全不可见 → 空窗极长。

| 步骤 | 内容 | 类型 |
|------|------|------|
| 4.12 | 透传 `toolCallStart/toolCallDelta` 并新增事件 `onToolCallDelta`，在参数生成阶段显示「生成参数：<tool>…（体积 / 用时）」 | 修改/新建 |

> **实现状态（已完成，方案 1）**：
> - 新建 `src/agent/stream-forward.ts`：`dispatchStreamChunk(chunk, tracker, events)` + `createToolCallGenTracker()`，负责 chunk→事件派发与按 index 的参数字节/耗时累积（可独立单测，避免测试引入重量级依赖）。
> - `src/types.ts`：新增可选事件 `onToolCallDelta?(tool, accumulatedBytes, elapsedMs)`。
> - `src/agent/react-agent.ts`：`streamLLM` 改用派发器；`composeEvents` 转发 `onToolCallDelta`。
> - `src/agent/logger.ts`：`onToolCallDelta` 用 `spinner.start()`（活跃即等价 `update`）刷新文案，**绝不 `stop()`**，`verbose=false` 下同样连续运转。
