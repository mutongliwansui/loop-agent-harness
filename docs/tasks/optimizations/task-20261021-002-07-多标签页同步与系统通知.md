## 一、任务目标需求

### 1.1 背景

`chat-stream.ts` 的 `states` 是**模块级** `reactive(Map)`（[chat-stream.ts:85](file:///d:/trae_workspace/loop-agent-command/webui/src/chat-stream.ts#L85)），各标签页各有一套：A 页发起的 run，B 页看不到运行点；A 页看过的会话，B 页未读红点依旧。后台完成的提醒只有页内 toast（`finishRun` 里 `showToast`），用户切到别的应用完全无感。本任务补两条感知通道：**跨标签页广播**与**系统通知 + 提示音**。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| 跨标签页通道 | 无任何通道；派生状态（运行点/未读/标题计数）各页自算 | **新建 `tab-sync.ts`（BroadcastChannel，降级 localStorage）** |
| 未读标记 | `st.unread` 由 `finishRun` 置位（001），仅本页可见 | 广播 `unread-cleared`/`run-finished` 让他页收敛 |
| attach 恢复 | B 页切到运行中会话时 `fetchDetail` → run=running → attach（001 已支持） | **收广播后主动 attach 即可**，事件流多订阅互不影响 |
| 系统通知 | 无；仅页内 toast | **新建 `notify.ts`（Notification + WebAudio）** |
| 通知权限 | 无请求逻辑 | **仅用户手势（点开关）中请求**（浏览器已禁止非手势请求，Firefox 72+/Safari） |
| 提示音 | 无 | WebAudio 合成双音（零音频资源） |
| `finishRun` 状态 | task-04 已加 `status` 参数（通知逻辑未变） | **本任务消费：按 status/前后台分流** |

### 1.3 任务目标

1. 新建 `webui/src/tab-sync.ts`：`postTab` / `onTab`；四类消息（run-started / run-finished / unread-cleared / session-dropped）。
2. `chat-stream.ts` 四个发送点接线；接收处理（唤醒 + reconcile / markRead / drop）。
3. 新建 `webui/src/notify.ts`：设置持久化（system/sound/asked）、权限请求、`notifyRunDone`、`playChime`。
4. `finishRun` 分流：后台（hidden/无焦点）→ 系统通知 + 提示音；前台 → 页内 toast（001 现状）。
5. `ChatView` 工具条加 🔔 开关（两项：系统通知 / 提示音）；`App.vue` 订阅广播并反注册。

### 1.4 设计约束

- 广播**只传派生状态，不传消息体**（方案 D8）：内容永远以服务端为准，接收方只做"唤醒 + 对齐"。
- 不重复打扰：前台完成不弹系统通知；声音/系统通知各一个开关且持久化（localStorage）。
- 权限请求只发生在用户点击开关时；未授权时给一次性页内引导条。
- 零新依赖；非安全上下文（局域网 IP + http）下系统通知静默降级并给出说明。

## 二、方案设计

### 2.1 总体思路

```
标签页 A                                    标签页 B
  sendMessage 成功起跑
    └─ postTab(run-started) ──────────────▶ B：若本端 idle → status='running' + attach(id)
  finishRun(id, st, status)
    ├─ 后台？→ notifyRunDone + playChime
    ├─ postTab(run-finished) ─────────────▶ B：reconcile(id)；非活跃会话置 unread；刷新侧栏
    └─ 前台 → showToast（001 现状）
  setActiveSession → markRead（此前 unread）
    └─ postTab(unread-cleared) ───────────▶ B：markRead（不回播，防乒乓）
  drop(id) ─ postTab(session-dropped) ────▶ B：drop(id) + 移出列表
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D1** | 通道首选 `BroadcastChannel('loop-agent')`，缺失降级 localStorage+storage 事件 | BroadcastChannel 同源、不回到发送者、无持久化副作用；降级写随机键 + 500ms 清理 + 按 `at` 去重，社区标准做法 |
| **D2** | 广播只传状态事件，接收方 `reconcile()` 全量对齐（方案 D8：lastSeq 是每连接游标，跨页无意义） | 传消息体会重复且失序风险；reconcile 幂等且内容一致不替换（防闪烁） |
| **D3** | 通知仅在 `document.hidden \|\| !document.hasFocus()` 时发 | 前台已有页内反馈，双通道重复打扰 |
| **D4** | 权限在用户点开 🔔 面板勾选"系统通知"时请求；`asked` 标记防止重复引导 | 页面加载即请求已被浏览器禁止；`asked` 持久化避免每次烦扰 |
| **D5** | 声音用 WebAudio 合成（880→1320Hz 各 80ms，gain 0.05），AudioContext 在开关手势中创建并 resume | 自动播放策略要求手势解锁；零音频文件依赖 |
| **D6** | Notification `tag=sessionId`、`silent:true` | 同会话通知互相替换防刷屏；避免系统声与 WebAudio 双响 |
| **D7** | 通知点击：`window.focus()` + 路由到对应会话 + close | Notification click 默认行为在多窗口下不可靠，显式处理 |
| **D8** | `unread-cleared` 接收端不回播广播 | 两页同看一会话时乒乓清零 |

## 三、任务详细设计

### 3.1 `tab-sync.ts`（新建）

```ts
export type TabMsg =
  | { t: 'run-started'; id: string; runId?: string; at: number }
  | { t: 'run-finished'; id: string; status: 'done' | 'failed' | 'aborted'; durationMs?: number; at: number }
  | { t: 'unread-cleared'; id: string; at: number }
  | { t: 'session-dropped'; id: string; at: number };

export function postTab(msg: Omit<TabMsg, 'at'>): void;      // at 自动补
export function onTab(fn: (m: TabMsg) => void): () => void;  // 返回反注册
```

- 实现：`BroadcastChannel` 存在则用之；否则 localStorage 随机键 `__la__<ts>_<rand>` 写入后 500ms 删除；接收方 `JSON.parse` + `at` 去重（300ms 窗口）。

### 3.2 `chat-stream.ts` 接线

发送点（4 处）：
- `sendMessage` 起跑后：`postTab({ t:'run-started', id, runId })`
- `finishRun(id, st, status)`：`postTab({ t:'run-finished', id, status, durationMs })`
- `markRead`（由 `setActiveSession` 调用且此前 unread）：`postTab({ t:'unread-cleared', id })`
- `drop(id)`：`postTab({ t:'session-dropped', id })`

接收处理（在 `App.vue` `onMounted` 中注册 `onTab`）：

| 收到 | 行为 |
|---|---|
| `run-started` | 本端该会话 idle → `states.get(id).status='running'` + `attach(id)` |
| `run-finished` | 本端 running → `reconcile(id)`；`!chatViewMounted || activeSessionId!==id` → `st.unread=true`；触发 finishHandlers（侧栏刷新） |
| `unread-cleared` | `markRead(id)`（不再广播） |
| `session-dropped` | `drop(id)` |

### 3.3 `notify.ts`（新建）

```ts
export interface NotifySettings { system: boolean; sound: boolean; asked: boolean }
const KEY = 'loop-agent.notify';

export function getNotifySettings(): NotifySettings;               // localStorage 读取+默认
export function setNotifySettings(patch: Partial<NotifySettings>): void;
export async function requestNotifyPermission(): Promise<NotificationPermission>;  // 仅开关手势中调用
export function notifyRunDone(n: { sessionId; title; status; durationMs? }): void;
export function playChime(): void;
```

要点：
- `notifyRunDone`：`Notification.permission==='granted'` 才发；`title='会话已完成：<标题>'`、`body='耗时 X.Xs · N 轮'`、`tag=sessionId`、`silent:true`、onclick 聚焦回跳。
- 未授权且 `!asked`：一次性页内引导条「后台完成提醒可开启系统通知 → 开启」（点击才请求权限，`asked=true`）。
- 非安全上下文（`!window.isSecureContext`，即局域网 IP+http）：跳过 Notification，仅提示音+toast；🔔 面板显示一行说明。
- `playChime`：AudioContext 懒创建（首次开关手势），双音 880/1320Hz 各 80ms，gain 0.05。

### 3.4 `finishRun` 分流（`chat-stream.ts`）

```ts
const background = document.hidden || !document.hasFocus();
if (status !== 'aborted' || true) { /* aborted 也提示？ */ }
```

分流规则：
- `background === true` → `notifyRunDone(...)`（status: done/failed/aborted 均提示，title 区分「已完成/已失败/已停止」）+ `settings.sound && playChime()`；
- 否则 → 保持 001 的页内 toast 文案。

### 3.5 UI（`ChatView.vue`）

- 输入区工具条（与「流式」勾选同级）加 🔔 按钮：点击弹小面板，两个开关（系统通知 / 提示音）写 `setNotifySettings`；
- 勾选"系统通知"时若 `Notification.permission!=='granted'` → `await requestNotifyPermission()`，denied 则开关回退并 toast 说明。

### 3.6 边界与错误处理

| 场景 | 行为 |
|---|---|
| B 页该会话未加载过（states 无 entry） | `run-started`/`run-finished`：仅当侧栏会话存在时更新；否则忽略（等用户点开时 fetchDetail 自然对齐） |
| 同源多端口（不同 port 即不同源） | 广播天然隔离（BroadcastChannel 同源限定），符合预期 |
| localStorage 降级下收自己刚写的键 | `at` 去重窗口 + 排除自身随机键（记录 lastWrittenKey） |
| 通知权限被拒（denied） | 开关回退为关；此后仅提示音/页内提示，不再请求 |
| 标签页长时间后台被浏览器冻结 | BroadcastChannel 消息在解冻后不补发（可接受：切回时 reconcile 兜底） |

### 3.7 演进项（本任务不做）

- Service Worker Notification（后台关闭标签页也能通知）——需 PWA 化，超范围。
- 自定义提示音文件/音量设置。
- 广播消息签名/防伪造（本机单用户场景无威胁模型）。
