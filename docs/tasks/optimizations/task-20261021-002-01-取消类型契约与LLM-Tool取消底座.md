## 一、任务目标需求

### 1.1 背景

服务端取消（本批次核心）要求一条从 API 层贯穿到 LLM SDK 与子进程的**单一取消通道**。现状该通道在四处断开：`AgentOptions` 无 signal、`ToolRunner.withTimeout` 只 reject 不取消、`commandRun` 的 `exec` 无 signal、LLM 客户端无取消。本任务为后续所有任务（检查点、停止端点、池化并发）打地基。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| run 级取消信号入口 | `AgentOptions`（[types.ts](file:///d:/trae_workspace/loop-agent-command/src/types.ts)）仅有 model/temperature/messages/spinner/onSnapshot 等 | **需新增 `signal?: AbortSignal`** |
| 工具拿到取消信号 | `Tool.execute(args)` 单参（[types.ts](file:///d:/trae_workspace/loop-agent-command/src/types.ts)）；`runner.run(tool, args, {timeout})`（[runner.ts](file:///d:/trae_workspace/loop-agent-command/src/tools/runner.ts)） | **需新增可选 `ToolContext` 第二参** |
| LLM 请求取消 | `chatStream` 无 signal；openai SDK 支持 `create(params, { signal })` | **需透传 + 处理 abort 后行为** |
| 取消不进重试 | `chatStream` 失败进 `retry()`（网络/429/5xx 重试，[client.ts:223](file:///d:/trae_workspace/loop-agent-command/src/llm/client.ts#L223)） | **需在 retry 前短路 AbortError** |

| 子进程树终止 | `commandRun` 用 `exec`，仅传 timeout（[commandRun.ts:18-38](file:///d:/trae_workspace/loop-agent-command/src/tools/commandRun.ts#L18-L38)）；Node 无内置 killTree | **需自实现 `process-tree.ts`（taskkill /T /F）** |

### 1.3 任务目标

1. `src/types.ts`：新增 `ToolContext`、`AgentOptions.signal`、`AgentPartialResult`、`AgentAbortedError`；`Tool.execute` 增可选第二参（对既有 10 个内置工具 + MCP 适配器零改动）。

### 1.4 设计约束

- 零新依赖：进程树 kill 用系统 `taskkill` / POSIX 进程组信号。
- 向后兼容：不传 signal 时所有路径行为与现状完全一致（CLI 模式零改动）。

## 二、方案设计

### 2.1 总体思路

```
AgentOptions.signal（由 task-03 的 RunHub 注入）
  ├─▶ streamLLM(messages, tools, {model, temperature, signal})
  │      └─ client.chatStream(..., {signal})
  │            ├─ create(params, { signal })          ← openai SDK 官方取消
  │            ├─ for await 结束后：signal.aborted → throw AgentAbortedError
  │            └─ catch：AbortError/APIUserAbortError → 短路 return（不进 retry）
  └─▶ ToolRunner.run(tool, args, { timeout, signal })
         ├─ raceAbort(tool.execute(args, {signal}), signal)
         ├─ commandRun：exec({signal}) + abort→killProcessTree(child.pid)
         └─ abort → reject(AgentAbortedError)  ← 唯一冒泡例外（D10）
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D1** | `AgentAbortedError` / `AgentPartialResult` 定义在 `src/types.ts` | 全部层已依赖 `types.js`，放这里无循环依赖；不选：新建 `errors.ts` —— 为单个类增加导入路径分叉，收益为零 |
| **D2** | `ToolRunner` 抛出的 `AgentAbortedError` 携带**空 partial**，由 agent 层（task-02）catch 后换带完整 partial 的实例再抛 | `ToolRunner` 不掌握 messages/steps，无法构造 partial；用 `aborted===true` 标记位识别，agent 层统一补全 |
| **D3** | openai SDK abort 后 `for await` **正常 return 而非抛错**——必须在循环结束后显式判 `signal.aborted` 并抛错 | 已核对 openai-node `src/core/streaming.ts`（SDK 吞掉传输层 abort 错误）；不判会出现"abort 了但空响应继续往下走"的静默错误 |
| **D4** | `AbortError` / `APIUserAbortError` 在进入 `retry()` 前**短路 return** | 否则取消被当网络抖动重试 3 次 = 没取消；单测断言 `chat.completions.create` 调用次数 |
| **D5** | `commandRun` 的默认 cwd 本期仍为 `undefined`（`exec` 默认 process.cwd()） | `ctx.workspaceRoot` 是 2b 接口位，本期只透传不启用（方案 D11） |
| **D6** | 进程树终止：win32 用 `taskkill /pid <pid> /T /F`，POSIX 优先 `process.kill(-pid)` 进程组、退化单 pid | 已检索：Windows 无 POSIX 进程组，`child.kill()` 只打直接子进程，子树需 taskkill（execa/pnpm 同款做法）；**必须趁树完整时执行**（先杀直接子进程会让后代孤儿化）。Node 未内置 killTree（nodejs/node#64406 open） |
| **D7** | `killProcessTree` 失败一律静默（catch 后 debug 日志） | 取消路径的清理失败不应改变用户可见结果（停止已生效，残留进程由系统/超时兜底） |

### 3.3 工具取消（`src/tools/runner.ts`）

```ts
export interface RunOptions {
  timeout?: number;
  signal?: AbortSignal;   // 新增
}

async run(tool, args, options = {}): Promise<string> {
  const timeout = options.timeout ?? tool.timeoutMs ?? 30000;
  const signal = options.signal;
  try {
    const exec$ = tool.execute(args, { signal });       // ctx 注入
    const raced = signal ? this.raceAbort(exec$, signal) : exec$;
    const result = await this.withTimeout(raced, timeout);
    // ...既有归一化不变
  } catch (e) {
    if ((e as { aborted?: boolean }).aborted === true) throw e;  // D2：唯一冒泡例外
    // ...既有"工具执行失败/超时"归一化不变
  }
}

/** abort 与工具完成竞速；abort 先到则 reject AgentAbortedError（工具 Promise 仍会跑完，结果被丢弃） */
private raceAbort<T>(p: Promise<T>, signal: AbortSignal): Promise<T> {
  if (signal.aborted) return Promise.reject(new AgentAbortedError(空 partial));
  return new Promise<T>((resolve, reject) => {
    const onAbort = (): void => reject(new AgentAbortedError(空 partial));
    signal.addEventListener('abort', onAbort, { once: true });
    p.then(
      (v) => { signal.removeEventListener('abort', onAbort); resolve(v); },
      (e) => { signal.removeEventListener('abort', onAbort); reject(e); },
    );
  });
}
```

> 注释必须写明：取消冒泡是"异常不抛出"契约的**唯一例外**——若归一化为 Observation，ReAct 会把"用户取消了"当"工具失败"再重试一轮（设计方案 D10）。

### 3.4 进程树终止（新建 `src/tools/process-tree.ts`）

```ts
import { execFile } from 'node:child_process';
import { promisify } from 'node:util';
const execFileAsync = promisify(execFile);

/**
 * 尽力终止进程树（失败静默，见 D7）。
 * - Windows：taskkill /pid <pid> /T /F（系统无 POSIX 进程组）
 * - POSIX：优先负 pid 杀进程组（需 spawn 时 detached:true），退化单 pid
 */
export async function killProcessTree(pid?: number, signal: NodeJS.Signals = 'SIGKILL'): Promise<void> {
  if (!pid || pid <= 0) return;
  if (process.platform === 'win32') {
    await execFileAsync('taskkill', ['/pid', String(pid), '/T', '/F']).catch(() => {});
    return;
  }
  try { process.kill(-pid, signal); }
  catch { try { process.kill(pid, signal); } catch { /* 已退出 */ } }
}
```

### 3.5 `commandRun` 取消（`src/tools/commandRun.ts`）

```ts
async execute(args, ctx) {
  const cmd = String(args.command);
  const cwd = args.cwd ? String(args.cwd) : undefined;   // D5：workspaceRoot 本期不启用
  const timeout = Number(args.timeout ?? 30000);

  return new Promise((resolve) => {
    const child = exec(
      cmd,
      { cwd, timeout, maxBuffer: 1024 * 1024, signal: ctx?.signal },
      (err, stdout, stderr) => { /* 既有归一化不变：abort 触发的 err 也走 [exit=...] 汇编 */ },
    );
    // Windows：exec 走 cmd.exe，signal 只杀 shell，孙进程残留 → 进程树兜底（趁树完整时执行）
    ctx?.signal?.addEventListener('abort', () => { void killProcessTree(child.pid); }, { once: true });
  });
}
```

> `exec` 收到 signal abort 后回调会带 `err`（`ExecException`，`killed=true`）——既有回调把 err 汇编为 `[exit=...]` 文本返回，此返回值会被 `raceAbort` 的 reject 丢弃，无需特判。
