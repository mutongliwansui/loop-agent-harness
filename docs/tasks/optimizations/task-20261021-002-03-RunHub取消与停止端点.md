## 一、任务目标需求

### 1.1 背景

Agent 层已具备可取消能力（task-01/02），但取消的"扳机"还缺三块：RunHub 没有 per-run 的 `AbortController` 与 `aborted` 状态；HTTP 层没有停止端点；`handleMessage` 收到中止错误后不知道如何收尾（封口、落盘、发终态）。本任务把三者接通，形成服务端取消的完整闭环。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| per-run 取消句柄 | `RunHub`（[run-hub.ts](file:///d:/trae_workspace/loop-agent-command/src/api/run-hub.ts)）只有 runs Map + 编号环形缓冲 + fan-out；`RunStatus = 'running'|'done'|'failed'` | **需 +controller/+aborting/+`'aborted'` 状态 + `signal()`/`abort()`** |
| 停止入口 | 路由表（[router.ts:81-95](file:///d:/trae_workspace/loop-agent-command/src/api/router.ts#L81-L95)）无 stop 路由 | **新增 `POST /sessions/:id/stop`** |
| 中止收尾 | `handleMessage`（[messages.ts:92-151](file:///d:/trae_workspace/loop-agent-command/src/api/handlers/messages.ts#L92-L151)）catch 只处理普通失败 | **需 aborted 分支：封口 + 部分落盘 + finish('aborted')** |
| tool_calls 序列自洽 | 中止时 `assistant(tool_calls)` 可能缺对应 tool 响应 → 下一轮报 `tool must be response to preceding tool_calls`；既有 `repairMessageSequence`（[context.ts:35](file:///d:/trae_workspace/loop-agent-command/src/memory/context.ts#L35)）只删不补、且仅在 restore 路径 | **新增 `sealPendingToolCalls`（补合成 tool 消息）** |
| attach 终态关流 | [stream.ts:69](file:///d:/trae_workspace/loop-agent-command/src/api/handlers/stream.ts#L69) 只对 `done`/`fatal` 关流 | **终态集合加入 `aborted`，否则 attach 悬挂到 keep-alive** |
| 终态事件下发 | `RunHub.publish` 在 `status!=='running'` 时返回 0；`finish` 先 publish 再置状态 | **`aborted` 复用该顺序，publish 无需改** |

### 1.3 任务目标

1. `RunHub`：`RunStatus` 增 `'aborted'`；每 run 一个 `AbortController`；新增 `signal(id)` / `abort(id)`（幂等）；`dispose()`/`drop()` 时 abort。
2. 新端点 `POST /sessions/:id/stop`：404 / 204 / 202 三态响应，立即返回不等 run。
3. `handleMessage`：注入 `runOptions.signal`；catch 中 aborted 分支完成"封口 → 部分落盘 → warning + aborted 终态 → 响应"。
4. 新建 `sealPendingToolCalls`（`src/api/abort-utils.ts`）。
5. attach 流终态集合扩展。

### 1.4 设计约束

- 不传 signal（如 CLI 路径）行为零变化。
- `/stop` 幂等：重复请求、停止已停会话都不报错。
- 部分落盘失败不抛出（降级为 warning，内存 history 照常更新）。
- 鉴权与跨工作空间校验沿用 `handleAttachStream` 的只读校验方式，不切换空间。

## 二、方案设计

### 2.1 总体思路

```
POST /sessions/:id/stop
  └─ handleStop：会话存在？（404）→ runs.snapshot？（无 run: 204）→ runs.abort(id)（202 {runId, status:'aborting'}）
       └─ RunHub.abort：status==='running' 且未 aborting → controller.abort + 置 aborting
            └─（agent 主循环感知）→ AgentAbortedError(partial) 抛回 handleMessage
                 ├─ sealPendingToolCalls(partial.messages)        ← 封口
                 ├─ updateSession(id, sealed, message, {transcript}) ← 部分落盘（失败降级 warning）
                 ├─ entry.history = stored 过滤视图
                 ├─ publish 'warning'（已被用户停止）
                 ├─ finish(id, 'aborted', {event:'aborted', data:{sessionId,durationMs,iterations,steps,partial:true}})
                 │     └─ SSE：attach 订阅者收到 aborted 后关流（终态集合已扩展）
                 └─ stream ? res.end() : sendJson(200, {aborted:true, partial:true, ...})
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D1** | `/stop` **202 立即返回**，不等 `entry.inFlight` | 取消耗时取决于在跑工具，同步等待会让停止按钮转圈数秒；前端靠 SSE `aborted` 终态感知完成 |
| **D2** | 无 run 返回 **204** 而非 404/409 | 幂等语义：停止一个已停的会话不算错；前端提示"当前无运行" |
| **D3** | 封口策略：**补**合成 tool 消息（内容标明取消），而非删除孤立 tool_calls | 保留"当时确实发起过该工具"的信息，历史可读；且 `messages` 与 `transcript` 保持一致。既有 `repairMessageSequence`（删孤立）保留为 restore 兜底，二者互补不冲突 |
| **D4** | 中断标记**不进消息数组**（D3 已确认）：只写前端灰条 +（task-06 起）`run.json` | 合成 assistant 消息会进 LLM 上下文、参与压缩摘要、被归档去重反复匹配（react-agent.ts:648 同类坑） |
| **D5** | `abort()` 只置位 + controller.abort，**不发布终态** | 终态由持有 run 的 `handleMessage` 统一 finish——避免 abort 与真实完成竞争时出现双重终态 |
| **D6** | `aborted` 终态事件 data 携带 `partial:true` 标记 | 前端据此渲染"部分输出"灰条而非失败态；与 fatal 区分 |
| **D7** | 非流式请求被取消：返回 `200 {aborted:true, partial:true, iterations}` 而非 4xx/5xx | 用户主动行为不算错误；前端（task-04）回滚乐观消息并提示"已停止（未产生输出）" |
| **D8** | `handleMessage` 的 signal 取自 `runs.signal(id)`（start 之后取） | signal 生命周期与 run 注册同源，避免自建 controller 与 Hub 状态分叉 |

## 三、任务详细设计

### 3.1 RunHub 扩展（`src/api/run-hub.ts`）

```ts
export type RunStatus = 'running' | 'done' | 'failed' | 'aborted';

interface RunState {
  // ...既有字段
  controller: AbortController;   // 新增（start() 内创建）
  aborting: boolean;             // 新增：幂等标记
}

/** 供 handleMessage 注入 AgentOptions.signal */
signal(sessionId: string): AbortSignal | null {
  return this.runs.get(sessionId)?.controller.signal ?? null;
}

/** 请求取消：无 run/非 running/已在取消中 → null（幂等）。只置位，不发终态（D5） */
abort(sessionId: string): { runId: string; alreadyAborting: boolean } | null {
  const state = this.runs.get(sessionId);
  if (!state || state.status !== 'running') return null;
  const alreadyAborting = state.aborting;
  state.aborting = true;
  if (!alreadyAborting) state.controller.abort(new Error('aborted by user'));
  return { runId: state.runId, alreadyAborting };
}
```

- `dispose()` / `drop(id)`：对仍 running 的 run 先 `controller.abort()`。
- `publish` 的 `status!=='running'` 短路**不改**；`finish` 保持"先 publish 终态再置状态"——`aborted` 事件可下发且晚到订阅者可回放。

### 3.2 停止端点（新建 `src/api/handlers/stop.ts` + 路由）

| 场景 | 状态码 | 响应体 |
|---|---|---|
| 会话不存在（`listAllWorkspaces` 扫描） | 404 `not_found` | `{error:{code,message}}` |
| 无 running run（从未跑/已结束/过保留期） | **204** | 空 |
| 有 running run，首次 | **202** | `{ runId, status:'aborting' }` |
| 重复请求 | **202** | 同上 + `alreadyAborting:true` |

路由（`router.ts`）：`{ method:'POST', path:'/sessions/:id/stop', handler: (ctx,req,res,p)=>handleStop(ctx,req,res,p.id) }`。

### 3.3 封口工具（新建 `src/api/abort-utils.ts`）

```ts
/** 为未被响应的 tool_call 补合成 tool 消息（内容标明取消），保证消息序自洽（D3） */
export function sealPendingToolCalls(messages: ChatMessage[]): ChatMessage[] {
  const answered = new Set(messages.filter((m) => m.role === 'tool').map((m) => m.tool_call_id!));
  const out = [...messages];
  for (const m of messages) {
    if (m.role !== 'assistant' || !m.tool_calls?.length) continue;
    for (const tc of m.tool_calls) {
      if (!answered.has(tc.id)) {
        out.push({ role: 'tool', tool_call_id: tc.id, content: '（运行已被用户停止，该工具调用未完成）' });
      }
    }
  }
  return out;
}
```

### 3.4 `handleMessage` aborted 分支（`src/api/handlers/messages.ts`）

```ts
ctx.runs.start(id);
runOptions.signal = ctx.runs.signal(id);   // D8

// runOptions.events / onSnapshot 既有逻辑不变

entry.inFlight = (async () => {
  try {
    // ...既有成功路径
  } catch (e) {
    if ((e as { aborted?: boolean }).aborted === true) {
      const partial = (e as AgentAbortedError).partial;
      const sealed = sealPendingToolCalls(partial.messages);
      const abortedWarnings: string[] = [];
      let stored = sealed;
      try {
        stored = await deps.sessionStore.updateSession(id, sealed, message, { transcript: partial.transcript });
      } catch (err) {
        abortedWarnings.push(`会话持久化失败（已停止，部分输出仅存内存）: ${msg(err)}`);
      }
      entry.history = stored.filter((m) => m.role !== 'system' && m.is_compact !== true);
      for (const w of abortedWarnings) ctx.runs.publish(id, 'warning', { level: 'warning', message: w });
      ctx.runs.publish(id, 'warning', { level: 'warning', message: '已被用户停止（以上为已生成的部分输出）' });
      ctx.runs.finish(id, 'aborted', { event: 'aborted', data: {
        sessionId: id, durationMs: Date.now() - startedAt,
        iterations: partial.iterations, steps: partial.steps.length, partial: true,
      }});
      if (stream) res.end();
      else sendJson(res, 200, { sessionId: id, aborted: true, partial: true, iterations: partial.iterations });
      return;
    }
    // ...既有 failed 分支不变
  } finally { entry.inFlight = null; }
})();
```

### 3.6 边界与错误处理

| 场景 | 行为 |
|---|---|
| abort 与 done 竞争（最后一 token 刚产出） | 先到先得：`finish` 后 `status!=='running'`，后到的 `publish` 返回 0、`abort()` 返回 null |
| 停止时 entry.inFlight 已为 null（run 刚结束） | `runs.abort` 返回 null → 204 |
| partial 落盘失败 | warning 下发；`entry.history` 用内存 sealed 消息（本轮不丢，重启后丢） |
| 会话在跨工作空间被停止 | 与 attach 同策略：run 只存在于其所属空间；`hasInFlight()` 已禁止运行中切空间，实际只命中当前空间 run |
| 服务关停时仍有 run | `dispose()` 全部 abort（run 日志归 task-06） |
