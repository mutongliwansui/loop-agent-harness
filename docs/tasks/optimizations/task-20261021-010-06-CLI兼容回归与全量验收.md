## 一、任务目标需求

### 1.1 背景

本需求是**纯内部重构**，产品可见收益只有一个（跨空间并行），但风险面覆盖几乎所有模块。CLI 与 HTTP 服务共享 4 个进程级单例（`configLoader`、`configWriter`、`skillLoader`、`agent`，见 [runtime/init.ts:8-12](file:///d:/trae_workspace/loop-agent-command/src/runtime/init.ts#L8-L12)）——任何"为 serve 按空间实例化"的改动都可能顺手改到 CLI 路径。因此 **CLI 零回退不是"顺便验一下"，而是 P1 的出口闸门**：不通过就不许进入 task-05/07。

### 1.2 现状梳理

| 验收对象 | 依据 | 现状 |
|---|---|---|
| CLI 入口 | `src/cli/**`、`src/commands/**` 与 serve 分支解耦（[index.ts](file:///d:/trae_workspace/loop-agent-command/src/index.ts) → `initRuntime` → 二选一） | 无 `--serve` 时不加载 `api/*`、`agent-pool` |
| CLI 的 cwd 语义 | `cli/start.ts`、`commands/skill-command.ts`、`commands/session-command.ts` 共 8 处 `process.cwd()` | **红线保留**（D11） |
| 技能层双语义 | `skillLoader.scan(cwd)` 的 cwd 既是"工作空间技能目录"也是"结果集" | 需证明"serve 传 root" 与 "CLI 传 process.cwd()" 对同一 root 结果一致（A7.2） |
| 全仓 cwd 分布 | 空间资源 29 处 / 14 文件（D16 口径），应用自身资源 4 处 | task-03 收口后需 grep 断言（A4） |
| 测试基线 | Vitest 串行执行（避免 API 限速），集成用例约 7 个 | 全量必须零放宽 |

### 1.3 任务目标

1. **A7.1 代码零改动**：`git diff --stat -- src/cli src/commands` 为空。
2. **A7 CLI 七项冒烟**：横幅/`/config`/`/skill`/`/session`/其余命令/普通对话 cwd/退出 Dreaming。
3. **A7.2 技能层双语义**：新增单测证明 `scan(root)` 对同一 root 与 `scan(process.cwd())` 等价。
4. **A4 cwd 收口断言**：grep `process.chdir` = 0；剩余 `process.cwd()` 全部落在允许集合且带注释。
5. **A5 路径书写归一**：三种书写形式 → 同一 `workspaceId`；存量目录未迁移可见。
6. **A6 跨空间 id 不重复**：同秒两空间创建 id 不同、老 id 可解析。
7. **A8 全量回归**：`npx tsc --noEmit` + `npx vitest run` 全绿，不放宽既有断言。

### 1.4 约束

- 本任务**只做验证与补测**，不夹带功能改动；发现缺陷回退到对应任务修复后重跑。
- 断言脚本使用 Node 内置能力实现（零新依赖），可重复执行。

## 二、方案设计

### 2.1 总体思路

```
① 静态断言（快，先跑）
   - grep process.chdir            → 必须 0
   - grep process.cwd()            → 白名单比对（29+4 分类）
   - git diff --stat src/cli src/commands → 必须为空
                    │
② 单测补强（VM 级）
   - scan(root) vs scan(cwd) 双语义
   - canonical 三种书写 → 同一 workspaceId
   - 同秒两空间 id 唯一性
                    │
③ 全量回归
   - npx tsc --noEmit
   - npx vitest run（串行）
                    │
④ 人工冒烟（真实进程）
   - CLI 七项 + serve 两空间并行（A1/A2/A3）
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D13** | CLI 兼容策略 **additive 只增不改**：为新需求新增可选参数/方法，`CommandContext` 与既有方法签名一律不动 | 让 CLI 也传 root：触发 `src/commands/**` 大面积 diff，违反 A7.1，且 CLI 单空间无收益 |
| **D11** | CLI 仍是"启动目录 = 唯一空间"，**不引入 registry** | CLI 也走 registry：内存/句柄开销与启动复杂度上升，用户无感知 |
| **D16** | cwd 白名单口径以 **29 空间资源 + 4 应用资源/默认值 + 8 CLI 保留** 为准（合计 41 处，含 2 处 sqlite 已改 `import.meta.url`） | 以方案原"33 处全改"为准：会把 `static.ts`/`.env`/sqlite 定位改坏 |

### 3.3 A7.2 技能双语义单测

```ts
// 同一 root 下，两条调用路径结果必须一致
const a = new SkillLoader().scan(root);
const prev = process.cwd();
process.chdir(root);                    // 仅测试内允许，用于证明等价性
const b = new SkillLoader().scan(process.cwd());
process.chdir(prev);
expect(a.map(s => s.name)).toEqual(b.map(s => s.name));
```

> 该用例**允许**在测试中使用 `chdir`（生产代码不允许），并在用例注释中说明目的。
