> 目标：让 Agent 具备开箱即用的首次体验——启动时自动检测必备目录与配置：齐备则直接进入对话界面；核心模型配置缺失时进入初次加载引导界面，分步引导用户完成初始化（仅主模型三元组需用户输入，其余使用默认值自动生成），消除"手动创建配置文件与目录"的使用门槛。
>

## 一、任务目标需求

### 1.1 背景

当前首次使用 Agent 需要用户手动创建全局配置文件（`~/.loop-agent/config.json`）、workspace 配置（`.loop-agent/.agent-config.json`）及 skills 等目录，并自行摸索配置格式。由于 [loader.ts:262-269](file:///d:/trae_workspace/loop-agent-command/src/config/loader.ts#L262-L269) 对缺失/损坏文件静默返回 `{}`，启动过程**不会报错也不会提示**，用户直到第一次对话模型调用失败（apiKey 未配置）才意识到问题，首次体验断裂。

### 1.2 现状梳理（框架契合度）

| 引导需要的能力 | 当前框架现状 | 结论 |
|---|---|---|
| 分层配置合并 | `configLoader.load()` 五层合并（CLI > workspace > global > env > default），缺文件静默跳过（[loader.ts:72-99](file:///d:/trae_workspace/loop-agent-command/src/config/loader.ts#L72-L99)） | 检测基于**合并后生效值**即可，env/.env 配置的用户天然免引导 |
| 配置写盘 | `configWriter.updateScope(scope, partial)` 点分写入，global → `~/.loop-agent/config.json`、workspace → `.loop-agent/.agent-config.json`（[writer.ts:17-26](file:///d:/trae_workspace/loop-agent-command/src/config/writer.ts#L17-L26)），写入自动建目录 | 直接复用，来源标记/`/config list` 零改动 |
| 默认配置 | `DEFAULT_CONFIG` 已含全部字段默认值（[schema.ts:101+](file:///d:/trae_workspace/loop-agent-command/src/config/schema.ts#L101-L103)，如 `model.baseUrl` 默认 `https://api.openai.com/v1`） | 向导"其余使用默认配置"= 不落盘、运行时回退，无需生成全量骨架 |
| 连通性校验 | `llm.chat()` 非流式调用自带 retry（网络/429）与 4xx 中文错误提示（[client.ts:80](file:///d:/trae_workspace/loop-agent-command/src/llm/client.ts#L80)） | 发一次极小请求即可验证三元组 |
| 交互输入 | REPL 已用 `node:readline`；Spinner 可复用 | 向导交互无需新依赖 |
| 目录自动创建（已存在，勿重复建设） | `~/.loop-agent/logs`（llm-logger/debug 写入时）、`.keyfile`（[keychain.ts:78](file:///d:/trae_workspace/loop-agent-command/src/session/keychain.ts#L78)）、记忆目录（[react-agent.ts:190-219](file:///d:/trae_workspace/loop-agent-command/src/agent/react-agent.ts#L190-L219)） | 引导范围收敛为：全局 config、workspace 配置、两级 skills 目录 |

**关键结论**：

1. **必备项检测面很小**：真正阻断使用的是合并后 `model.apiKey` 与 `model.name` 为空；目录/文件缺失多数有默认兜底，可静默补建。
2. **无需新增协议或命令框架**：向导是启动期的一段交互流程 + 一个独立模块；复用 `ConfigWriter` 写盘保证 `/config list` 来源标记正确。
3. **唯一挂接点**：[index.ts:90-92](file:///d:/trae_workspace/loop-agent-command/src/index.ts#L90-L92) step 0（配置加载）之后、会话初始化之前；向导写盘后需重新 `load()` 刷新合并结果。

### 1.3 任务目标

- 全新环境启动 → 进入**初次加载引导界面**：分步输入 `model.baseUrl`（带默认值回车跳过）、`model.apiKey`（必填）、`model.name`（必填），实时连通性校验，随后自动生成目录与配置文件，进入正常对话界面。
- 配置齐备 → 启动**零打扰**直接进入对话界面。
- 仅目录/文件缺失但 model 已配置（如 env 用户、新 workspace）→ **静默幂等补建**并打印一行 ✓ 提示，不进向导。
- 其余配置项（vision、session、memory、tools 等）不询问、不落盘，按 `DEFAULT_CONFIG` 运行时生效。
- 非 TTY（管道/CI）与 `--no-setup` 场景不阻塞、不挂起。
- **零新依赖**：仅 `node:readline`、`node:fs`。

### 1.4 设计约束

- **不破坏既有启动路径**：`index.ts` 仅插入单点调用 `ensureBootstrap()`；检测/向导逻辑全部收敛在 `src/bootstrap/` 模块内。
- **向后兼容**：已有用户配置齐备时行为与现状完全一致（仅多一次毫秒级文件存在性检查）。
- **密钥安全**：apiKey 只经内存与 `ConfigWriter` 落盘，日志/摘要仅显示尾 4 位；不写入任何调试输出。
- **写入层语义正确**：model 三元组默认写全局（用户级资产，跨 workspace 复用），向导允许改选写入层。
- **可独立验证**：doctor/scaffold/wizard 均为纯逻辑或可注入 IO 的模块，单测不依赖真实终端与真实 API。

## 二、方案设计

### 2.1 总体思路

```
启动 main()
   │ configLoader.load()          ← step 0（现有）
   ▼
┌──────────────────────────────┐
│ ensureBootstrap()            │
│  ① doctor.check(cfg)         │ 检测合并后 model.apiKey/name + 目录文件存在性
│  ② 分流                       │
│    ├─ 阻断（model 缺失）→ wizard │ ③ 分步输入 → 连通性校验 → ConfigWriter 写盘
│    ├─ 非阻断（文件/目录缺失）→ scaffold 幂等补建 + ✓ 提示
│    └─ 齐备 → 直接通过           │
│  ④ configLoader.load() 重新加载 │ 向导写盘后刷新
└──────────────────────────────┘
   ▼
会话初始化 → MCP → Skills → Banner → REPL（现有流程不变）
```

### 2.2 关键设计决策

1. **D1 检测看生效值，不看文件**：`model.apiKey/name` 经五层合并后非空即视为已配置——env/`.env` 用户免引导；反之全局 config.json 存在但字段为空仍进引导。
2. **D2 两级分流**：阻断级（model 三元组缺失）→ 向导；非阻断级（目录/文件缺失）→ 静默幂等补建。避免"只差一个 skills 目录"也弹向导的过度打扰。
3. **D3 默认值不落盘**：配置文件只承载用户显式配置（workspace `.agent-config.json` 写 `{}` 骨架仅作存在标记与编辑锚点），避免把 `DEFAULT_CONFIG` 全量钉死在文件里阻碍默认值升级。
4. **D4 model 三元组默认写全局**：`~/.loop-agent/config.json`（用户级资产）；向导最后一步允许改选写入工作空间。
5. **D5 连通性校验复用 `llm.chat()`**：`chat([{role:'user',content:'ping'}], undefined, { maxTokens: 16 })` + 15s 外层超时；成功显示模型名/回复/耗时，失败给分类错误，允许【重试 / 重新输入 / 仍保存（标注未验证）】。
6. **D6 非 TTY 保护**：`process.stdin.isTTY === false` 时不进向导，打印缺失项与两条手动配置指引（`/config set` 与环境变量）后继续原有流程。
7. **D7 模块独立 + 单点挂接**：`src/bootstrap/`（doctor/scaffold/wizard/index），`index.ts` 仅在 step 0 后调用 `ensureBootstrap()`；CLI `--no-setup` 可整体跳过。
8. **D8 写盘统一走 `ConfigWriter`**：保证来源标记、点分写入、目录创建与 `/config` 命令语义完全一致。

## 三、任务详细设计

### 3.1 检测模块 `src/bootstrap/doctor.ts`（P0）

```typescript
export type BootstrapIssueId =
  | 'model-apiKey' | 'model-name'            // 阻断级：进向导
  | 'global-config' | 'workspace-config'     // 非阻断：静默补建
  | 'skills-global' | 'skills-workspace';

export interface BootstrapIssue {
  id: BootstrapIssueId;
  level: 'blocker' | 'missing';
  message: string;   // 面向用户的中文描述
  path?: string;     // 相关文件/目录绝对路径
}

export interface BootstrapReport {
  ok: boolean;                       // 无 blocker 即 true
  issues: BootstrapIssue[];
}

/** 纯函数（IO 通过注入的 exists 探针），便于单测 */
export function checkBootstrap(cfg: AgentConfig, paths: BootstrapPaths): BootstrapReport
```

- 判定规则：`cfg.model.apiKey === ''` 或 `cfg.model.name === ''` → blocker；`globalConfigPath`/`workspaceConfigPath`/两级 skills 目录不存在 → missing（`~/` 路径经 `os.homedir()` 解析后展示）。
- 检测不含 `logs/`、memory、`.keyfile`（各模块按需自建，见 1.2）。

### 3.2 幂等补建模块 `src/bootstrap/scaffold.ts`（P0）

- `ensureDirs(paths)`：`mkdir -p` 两级 skills 目录与 workspace `.loop-agent/`，返回新建项列表。
- `ensureConfigFiles(paths)`：仅当文件**不存在**时写入——workspace `.agent-config.json` 写 `{}`；全局 config.json 缺失时**不写空文件**（留待向导写入，避免"存在但无 model"的半配置态干扰下次检测）。
- 全部操作幂等、不覆盖已有内容。

### 3.3 引导向导 `src/bootstrap/wizard.ts`（P0）

交互步骤（readline，逐题即答即校验）：

1. 欢迎语 + 缺失项清单（来自 doctor report）。
2. `model.baseUrl`：显示默认值，回车跳过采用；输入合法性仅做 URL 前缀检查。
3. `model.apiKey`：必填，空输入重新提示（P1 改为遮蔽回显）。
4. `model.name`：必填，提示常用示例（如 `deepseek-chat` / `gpt-4o-mini`）。
5. 连通性校验（D5）：Spinner「正在验证模型连通性…」→ 成功显示 `✓ 连接成功（模型 xxx，N ms）`；失败按 D5 三选项处理。
6. 写入层确认：全局（默认，回车）/ 工作空间。
7. `scaffold` 补建 + `configWriter.updateScope(scope, { model: {...} })` 写盘 → 重新 `configLoader.load()`。
8. 摘要：写入路径、baseUrl、model、apiKey 尾 4 位、校验结果/未验证标注；随后继续正常启动。

- 向导中 `Ctrl+C`：打印「初始化未完成，已输入内容未保存」后退出进程（`process.exit(1)`），下次启动重新引导。
- 所有提问函数通过注入的 `ask` 接口实现，单测可模拟输入序列。

### 3.4 入口 `src/bootstrap/index.ts`（P0）

```typescript
export async function ensureBootstrap(opts: { noSetup?: boolean }): Promise<void>
```

- `noSetup` 为 true → 直接返回（`--no-setup`）。
- `!process.stdin.isTTY` → 打印缺失项与手动指引（D6），仅执行 `scaffold`，不进向导。
- 有 blocker → 执行向导；仅 missing → 执行 `scaffold` 后逐项打印 `✓ 已创建: <path>`。
- 完成后**由调用方重新 `load()`**（index.ts 内刷新 `cfg`）。

### 3.5 启动挂接（P0）

[index.ts](file:///d:/trae_workspace/loop-agent-command/src/index.ts) `main()` step 0 之后插入：

```typescript
await ensureBootstrap({ noSetup: /* 解析 --no-setup */ });
const { config: cfg } = configLoader.load(); // 向导可能已写盘，重新加载
```

后续 step 1（会话初始化）及全部流程不变；CLI 参数解析处增加 `--no-setup`。

### 3.6 `/setup` 与 `/doctor` 命令（P1）

- `/setup`：REPL 内随时重跑向导（写盘后调用 `registerBuiltinTools` 重载工具，提示重启或自动刷新）；subcommand 预留 `--global/--workspace` 选层。
- `/doctor`：输出 BootstrapReport 逐项状态（✓/✗、路径、是否阻断），不修改任何文件。
- 两命令加入 `BUILTIN_SLASH_COMMANDS` 与 [index.ts](file:///d:/trae_workspace/loop-agent-command/src/index.ts) 注册，Tab 补全自动生效。

### 3.7 apiKey 遮蔽输入（P1）

readline 无原生密码模式：监听 `keypress` 逐字符替换为 `*` 回显、退格支持；实现收敛在 wizard 内部小工具函数并单测。P0 先明文回显（仅本地终端场景），P1 收口。

### 3.8 边界与错误处理

| 场景 | 处理 |
|---|---|
| 全局 config.json 存在但 JSON 损坏 | loader 静默返回 `{}` → 视为未配置进向导；向导写入前将损坏文件重命名 `<name>.json.bak-<ts>` 并提示 |
| 用户跳过连通性校验仍保存 | 摘要标注「⚠ 未验证」，首次对话失败时现有错误提示兜底 |
| 校验超时（15s） | 按校验失败处理，提示检查 baseUrl/网络/代理 |
| 磁盘不可写 | `ConfigWriter` 抛错原样展示，引导退出后排查权限 |
| 非 TTY 且缺配置 | 打印手动配置指引（`/config set model.apiKey ...` 或 `OPENAI_API_KEY` 环境变量），不阻塞 |
| `--no-setup` 且缺配置 | 与现状一致：首次对话报模型未配置错误 |
| env/.env 已配置 | 免引导；仅补建缺失目录并打印 ✓ |
