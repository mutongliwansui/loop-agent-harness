## 一、任务目标需求

### 1.1 背景

现状"并发"靠三层互斥兜底：`entry.inFlight`（同会话）、`hasInFlight()`（切空间前全局空闲）、前端"另一会话在跑"拦截。根因是 `deps.runAgent` 闭包捕获**单例 agent**（[bootstrap.ts:36](file:///d:/trae_workspace/loop-agent-command/src/api/bootstrap.ts#L36)），其 `_chatHistory/_currentSessionId/_workingMemory/_episodicMemory/_curatedMemory` 均为实例字段，两个会话并发会互相覆盖。本任务以"每个 run 一份 agent 实例"替代单例假设，从而放开同工作空间内多会话并发。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| 多实例 agent | `export const agent` 单例（[react-agent.ts:939](file:///d:/trae_workspace/loop-agent-command/src/agent/react-agent.ts#L939)），`deps.runAgent: (input, options) => agent.run(...)` | **新建 `AgentPool`，按 sessionId 租用** |
| 记忆子系统共享 | `cachedKit` 进程级单例（[memory-kit.ts:92-103](file:///d:/trae_workspace/loop-agent-command/src/api/memory-kit.ts#L92-L103)）；kit 内 Episodic/Curated 指向 `~/.loop-agent/memory/<workspaceId>/` 同一磁盘目录 | **Map 化为按 `workspaceId` 复用**（多 agent 实例共享同一 kit 实例，避免双实例写同一索引） |
| agent 记忆注入 | `initMemory(cwd)` 内部自建 kit 并装配 promotionGate/contextAssembler/memoryCallback（react-agent.ts:227-290） | **新增 `attachMemory(kit, cwd)` 注入入口** |
| per-run signal | task-01 后 `runOptions.signal = runs.signal(id)` 每次独立 | 天然支持，池化后无需改 |
| 会话间事件隔离 | `events`/`onSnapshot` 按次注入（messages.ts:59-90），RunHub 按 sessionId fan-out | **已隔离，无需改（001 红利）** |
| 前端发送拦截 | `ChatView.vue:298-323` `otherRunningSession` 拦截跨会话发送 | **移除**；保留同会话 streaming 拦截（服务端 409 兜底） |
| 切换空间互斥 | `hasInFlight()` 全局空闲才许 `switchWorkspace`（messages.ts:31-35、sessions.ts:131） | **保留**（2b 前提），但语义随池化自然兼容 |

### 1.3 任务目标

1. 新建 `src/agent/agent-pool.ts`：按 sessionId 租用/归还 ReActAgent，LRU 容量 4（可配），busy 实例不淘汰。
2. `memory-kit.ts`：`cachedKit` 单例 → `Map<workspaceId, Promise<MemoryKit>>`；`resetMemoryKitCache()` 清空 Map。
3. `ReActAgent.attachMemory(kit, cwd)`：外部注入已初始化记忆（与 `initMemory` 互斥，后调用者生效）；CLI 路径保持自建不变。
4. `deps.runAgent` 签名改为 `(sessionId, input, options)`；bootstrap/server/messages 三处接线。
5. 前端移除跨会话发送拦截。

### 1.4 设计约束

- 单会话仍串行（`entry.inFlight` 语义不变，池只保证"空闲实例不被两个会话同时拿到"）。
- 记忆写并发安全依赖"同空间共享同一 kit 实例"——**禁止**按 sessionId 各建 kit。
- 零新依赖；池容量可配（`config.api` 或常量，倾向常量 + 环境变量）。
- CLI 模式（非 --serve）完全不走池，行为零变化。

## 二、方案设计

### 2.1 总体思路

```
handleMessage(id, message)
  └─ deps.runAgent(id, message, runOptions)
       └─ AgentPool.withAgent(id, (a) => a.run(message, runOptions))
            ├─ acquire(id)：同 id 空闲实例复用；否则取最久未用空闲实例；
            │                否则新建（超容量先淘汰最久未用空闲实例；busy 永不淘汰）
            │                └─ attachMemory(getMemoryKit(cwd), cwd)（首次）
            ├─ a.run(...)            ← signal/onSnapshot/events 按次注入，天然隔离
            └─ finally release(id)   ← 回空闲池，刷新 lastUsed
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D1** | 池容量默认 **4**（含 busy），可配 | 同空间并发需求 2~3 已覆盖 + 切换余量；8+ 徒增内存与记忆句柄。容量 2 拒绝感明显 |
| **D2** | 记忆按 `workspaceId` 共享 kit 实例（而非每 agent 一套） | kit 内 Episodic/Curated 写**同一目录**的 index/state 文件，双实例并发写必互相覆盖；共享单实例由其内部串行写保证一致（现状 CLI 即单实例） |
| **D3** | 池淘汰只针对**空闲**实例，busy 实例不可淘汰 | 淘汰 busy 等于杀死运行中 run 的宿主；容量含 busy 的语义下不会发生 |
| **D4** | 会话粘性：同 sessionId 优先复用同一实例 | 复用已装配的记忆上下文/热身状态；且会话历史经 `entry.history` 显式传入，粘性非正确性依赖而是性能优化 |
| **D5** | `attachMemory` 与 `initMemory` 互斥、后调用者生效 | 不新增状态位区分来源，避免"哪个生效"的二义性；文档注明 API 模式用 attach、CLI 用 init |
| **D6** | `reset()` 触发时机：配置变更 / `switchWorkspace`（沿用现 `resetMemoryKitCache()` 调用点） | 切空间后 cwd 变化，池内实例的 `process.cwd()` 感知失效（记忆绑定 workspaceId），整体重建最稳妥 |
| **D7** | 2b（跨空间并发）本期**不做**，仅留 `ToolContext.workspaceRoot` 接口位（方案 D11） | `process.chdir` 是进程级状态：skill/config/store/工具相对路径全绑定 cwd，改造范围远超本建议 |

## 三、任务详细设计

### 3.1 `AgentPool`（新建 `src/agent/agent-pool.ts`）

```ts
export interface AgentPoolOptions {
  capacity?: number;                    // 默认 4
  create?: () => ReActAgent;            // 默认 new ReActAgent()（测试注入）
}

interface IdleEntry { agent: ReActAgent; lastUsed: number }

export class AgentPool {
  private readonly idle = new Map<string, IdleEntry>();
  private readonly busy = new Set<string>();

  constructor(private readonly opts: AgentPoolOptions = {},
              private readonly initAgent: (a: ReActAgent) => Promise<void> = async () => {}) {}

  /** 取/建实例并标记 busy；initAgent 仅对新建实例执行（attachMemory） */
  async acquire(sessionId: string): Promise<ReActAgent>;

  /** 用完归还：busy 移除；池超容量时淘汰最久未用空闲实例（dispose） */
  release(sessionId: string): void;

  /** withAgent：acquire → run → finally release */
  async withAgent<T>(sessionId: string, fn: (a: ReActAgent) => Promise<T>): Promise<T>;

  /** 切空间/改配置：全部 dispose 重建 */
  reset(): void;

  get size(): number;      // 诊断：idle + busy
}
```

不变量：
- `busy` 中任意时刻无重复 sessionId（由 `entry.inFlight` 保证同会话串行）；
- `idle` 中任意 sessionId 最多一个实例；
- `idle.size + busy.size <= capacity`（acquire 超容量时先淘汰）。

### 3.2 记忆 Map 化（`src/api/memory-kit.ts`）

```ts
// 旧：let cachedKit: Promise<MemoryKit> | null = null;
const kits = new Map<string, Promise<MemoryKit>>();

export function getMemoryKit(cwd: string): Promise<MemoryKit> {
  const key = workspaceId(cwd);
  let p = kits.get(key);
  if (!p) { p = createMemoryKit(cwd, configLoader); kits.set(key, p); }
  return p;
}

export function resetMemoryKitCache(): void { kits.clear(); }
```

- `workspaceId(cwd)` 已有实现（kit 内部用它分目录），导出复用即可。
- 调用点迁移：`bootstrap.ts` 的 `reinitMemory` 改为 `resetMemoryKitCache()` + `pool.reset()`。

### 3.3 `attachMemory`（`src/agent/react-agent.ts`）

```ts
/** 外部注入已初始化的记忆子系统（AgentPool 用）；与 initMemory 互斥，后调用者生效 */
async attachMemory(kit: MemoryKit | null, cwd: string): Promise<void>
```

实现要点：
- 以注入 kit 组装 `promotionGate`/`contextAssembler`/`memoryCallback`（复用 `initMemory` 的装配段，抽私有方法 `bindMemory(kit)`）；
- `initMemory(cwd)` 改为：serve 模式经 `getMemoryKit(cwd)` 拿共享 kit 后走 `bindMemory`；CLI 模式自建（`process.cwd()` 唯一）。**实现上让 `initMemory` 内部调用 `getMemoryKit`，`attachMemory` 只是显式注入入口**，两条路径最终都汇到 `bindMemory`。

### 3.6 边界与错误处理

| 场景 | 行为 |
|---|---|
| 同会话并发 POST | `entry.inFlight` 命中 → 409 `busy`（不变） |
| 容量打满（4 个 busy）第 5 个会话发起 | 池无空闲可淘汰 → acquire 排队等待 release（withAgent 内 await 空闲位），或直接 409？**决策：排队**（ fairness：先到先得），排队上限由 HTTP 层无超时保护，与现有 run 无时限一致 |
| agent 实例 run 抛错 | release 照常执行（finally）；出错实例**不复用**——release 时若 run 失败则 dispose 重建（防脏状态），通过 withAgent 包装结果判定 |
| 切换工作空间（运行中） | 仍被 `hasInFlight()` 拒绝；空闲后切换走 `resetMemoryKitCache + pool.reset` |
| 双空间会话交替运行（2b 前置限制内） | 同一时间仅一个空间活跃，kit Map 最多 2 项，无害 |

### 3.7 演进项（本任务不做）

- 跨工作空间并发（2b：移除 chdir、store 按空间实例化、`commandRun` 默认 cwd 接 `workspaceRoot`）。
- 池容量热更新（改配置需重启，与项目"配置变更需重启生效"现状一致）。
- 池指标暴露（`/status` 加 pool 字段，可 P2 顺手）。
