## 一、需求背景

20261021-001 让 run 与 HTTP 连接解耦（RunHub + attach 续传），解决了"切页面/刷新即丢流"。但留下副作用：**前端"停止"只是断开自己那条 SSE，服务端 run 完全不受影响**——用户点停止后 token 继续烧、工具继续跑（可能还在写文件）、侧栏运行点仍在转。本批次把 001 标记为"P2 可选增强"的五项补齐：

1. 服务端真正取消（P0，其余项的安全前提）
2. 同工作空间多会话并发（P1）
3. 多标签页状态同步（P2-1）
4. 系统通知与声音提醒（P2-2）
5. 运行态持久化与中断诊断（P2-3）

## 二、总体设计（摘要）

详细设计见设计方案第 3/4 章，此处仅列与任务边界相关的骨架：

```
用户点击「■ 停止」
  └─ POST /sessions/:id/stop（新端点）
       └─ RunHub.abort(id)：置位 + controller.abort（幂等）
            └─ AgentOptions.signal 贯穿：
                 ReAct 五类检查点（迭代/LLM前/工具前/压缩前后/记忆写前）
                   ├─ streamLLM({signal}) → openai create(params,{signal})
                   └─ ToolRunner.raceAbort → commandRun exec({signal}) → taskkill /T /F
                        └─ throw AgentAbortedError(partial)
                             └─ sealPendingToolCalls + 部分结果落盘
                                  └─ RunHub.finish('aborted') → SSE event: aborted
                                       └─ 前端灰条「已停止」+ reconcile
```

并发：`AgentPool`（LRU 4，busy 不淘汰）按 sessionId 租用 ReActAgent；记忆 kit 按 workspaceId 共享（Map 化）；前端放开跨会话发送拦截。跨工作空间并发（2b）**本期不做**，仅留 `ToolContext.workspaceRoot` 接口位。

多标签页：`tab-sync.ts`（BroadcastChannel，降级 localStorage），只传派生状态（run-started/finished、unread-cleared、session-dropped），接收方 reconcile 对齐。

通知：`notify.ts`（系统通知 + WebAudio 双音），仅后台（hidden/无焦点）触发，权限仅用户手势中请求。

持久化：`run-journal.ts` 写 `<store.path>/runs/<id>.json`（bootId 判中断），`run-log.ts` 写 `~/.loop-agent/logs/runs-YYYY-MM-DD.jsonl`。

## 六、风险与注意事项

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| openai SDK abort 后 `for await` 正常 return 而非抛错 | "abort 了但空响应继续往下走"的静默错误 | task-01 在循环后显式判 `signal.aborted` 并抛 `AgentAbortedError`；单测固定 |
| 取消异常被 `retry()` 当网络错误重试 | 取消变成重试 3 次，等于没取消 | task-01 在 retry 前短路 AbortError/APIUserAbortError；单测断言调用次数 |
| `ToolRunner` 取消被归一化为 Observation | ReAct"换个思路重试"白烧一轮 token | 取消冒泡为异常是 `ToolRunner` 唯一例外，注释 + 单测固定（D10） |
| Windows `taskkill` 不存在（极简环境） | 进程树残留 | 静默降级为只杀直接子进程，日志可诊断 |
| `deps.runAgent` 签名变更 | 影响 server/bootstrap/messages 及既有单测 | task-05 一次性改完，全仓 grep `runAgent:` 同步 mock 签名 |
| 记忆 kit Map 化影响 `/memory` 端点用例 | 既有测试失败 | task-05 检查 `tests/memory-*.test.ts` 的 `resetMemoryKitCache()` 断言 |
| D1 移除侧栏"停止查看"后用户误触 | 误以为丢失后台 run | 侧栏运行点保留展示语义；聊天页停止按钮 title 明确"服务端将中断" |
| 非流式请求被取消 | 无中间输出可保留 | 回滚乐观消息 + 提示「已停止（未产生输出）」 |

## 七、全局工程约束

1. **零新依赖**：进程树 kill 用系统 `taskkill`；跨标签页用 `BroadcastChannel`/`localStorage`；提示音用 WebAudio 合成。
2. **跨平台**：`process-tree.ts` 覆盖 win32（taskkill /T /F）与 POSIX（负 pid 进程组，退化单 pid）两分支。
3. **写盘 best-effort**：`run.json`、`runs-*.jsonl` 全部失败静默（记 debug 日志），不阻塞主流程。
4. **状态单向**：服务端是唯一事实源；前端运行态一律由事件或 GET 详情派生。
5. **不污染 LLM 上下文**：中断标记只进 `run.json` 与前端渲染，绝不进消息数组（D3 已确认）。
6. 每个任务完成：打勾验收项 + 追加完成记录 + `npx tsc --noEmit` + `npx vitest run` 全绿 + 中文提交。
