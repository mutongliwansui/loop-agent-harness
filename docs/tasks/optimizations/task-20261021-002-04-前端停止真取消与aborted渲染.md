## 一、任务目标需求

### 1.1 背景

服务端取消闭环已就绪（task-01~03），前端"停止"仍是旧语义：`stop()` 只 abort 本地两条读流（POST 与 attach），toast 提示"服务端将照常完成并保存"。本任务把停止按钮切到 `/stop` 端点、消费新的 `aborted` 终态事件，并按已确认的 D1 **移除侧栏"停止查看"**，让"停止"只有一个语义：真取消。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| 调用停止端点 | `chat-stream.ts` 只有 `stop()` 本地断流（[chat-stream.ts:679-684](file:///d:/trae_workspace/loop-agent-command/webui/src/chat-stream.ts#L679-L684)） | **新增 `abortRun(id)`** |
| 消费 `aborted` 事件 | `applyEvent` 无此 case（未知事件落入 default 被忽略） | **新增 case：置灰条、撤状态行、finishRun、reconcile** |
| 停止按钮 | `ChatView.vue:354` `stopGen()` 调 `stop(activeId)`，toast 文案为旧语义 | **改调 `abortRun`，文案更新** |
| 侧栏"停止查看" | `App.vue:47` `stopSession` 仅断流（D1 确认移除） | **删除入口，运行点保留展示** |
| 消息渲染标记 | `ChatMsg` 无 aborted 字段；`failed`/`failedText` 仅服务 fatal | **`ChatMsg` + `aborted?: boolean`，灰条样式** |
| 非流式被取消 | `sendMessage` 非流式分支无中间事件 | **catch aborted 响应：回滚乐观消息 + 提示** |
| `finishRun` 状态 | `finishRun(id, st)` 无 status 参数（task-07 的 tab 广播需要） | **本任务先加参数（'done'\|'failed'\|'aborted'），通知逻辑仍走 001 的 toast** |

### 1.3 任务目标

1. `abortRun(id)`：POST `/stop`，202/204 均视为受理；失败回退纯本地 detach（保持 001 行为，不让用户卡死）。
2. `applyEvent` 新增 `aborted` case：助手消息置 `aborted`、`meta` 标"已停止"、`finishRun(id, st, 'aborted')`、`reconcile`。
3. `ChatView` 停止按钮改走 `abortRun`；消息卡片 aborted 灰条；非流式取消回滚提示。
4. `App.vue` 移除侧栏"停止查看"；`ChatMsg`/`SessionStreamState` 类型补齐。
5. `finishRun` 增加 status 参数（为 task-07 的 tab 广播铺路）。

### 1.4 设计约束

- 不改 SSE 连接管理/重连/缓冲逻辑（001 已稳定）。
- `abortRun` 网络失败不得阻塞用户：降级为本地 detach + toast。
- 灰条为纯前端态（`note`/字段渲染），不进消息持久化内容（D3）。
- `reconcile` 逻辑不变：以落盘结果为准，内容一致不替换（防闪烁）。

## 二、方案设计

### 2.1 总体思路

```
「■ 停止」点击
  └─ ChatView.stopGen(activeId)
       └─ abortRun(id)
            ├─ POST /sessions/:id/stop
            │    ├─ 202 {runId, status:'aborting'} → toast「已请求停止（服务端正在收尾）」
            │    ├─ 204 → toast「当前无正在运行的任务」
            │    └─ 网络/其他错误 → stop(id) 本地 detach + toast「停止请求失败，已断开本页连接」
            └─（稍后）SSE event: aborted
                 └─ applyEvent case 'aborted'
                      ├─ asst.aborted = true; streaming=false; live=null
                      ├─ asst.meta = `已停止 · X.Xs · N 轮`
                      ├─ finishRun(id, st, 'aborted')   ← 未读/toast 逻辑复用 001
                      └─ void reconcile(id)             ← 与落盘部分结果对齐
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D1** | `abortRun` 失败回退**本地 detach**（001 语义）而非报错阻塞 | 服务端照常跑完并落盘，用户至少"眼不见"；卡死的按钮更糟。回退 toast 明示降级 |
| **D2** | 204（无运行）也要给 toast | 静默无反馈会让用户以为点了没生效 |
| **D3** | aborted 渲染**复用** `meta` 标注位（前缀"已停止 ·"）+ 新增 `aborted` 布尔驱动灰条，不新建独立消息条 | 独立消息条会进 `messages` 数组，与 `reconcile` 的磁盘对齐、`sameTimeline` 比对产生额外耦合；灰条由渲染层按 `aborted` 追加显示即可 |
| **D4** | 移除侧栏 stopSession（D1 已确认）而非保留改文案 | 两个"停止"必然引发误触；detach 需求仍可通过"切换会话/离开页面"自然满足（attach 流由组件卸载/切换断开） |
| **D5** | `finishRun` 本任务就加 status 参数，但通知行为不变（仅页内 toast） | task-07 的 tab 广播/系统通知直接复用该参数，避免二次改签名 |
| **D6** | 非流式取消：回滚乐观消息 + toast「已停止（未产生输出）」 | 非流式无中间事件可渲染，部分结果已落盘但界面无增量；回滚输入避免"空泡"困惑 |

## 三、任务详细设计

### 3.1 `chat-stream.ts` 新增/修改

```ts
export interface ChatMsg {
  // ...既有
  aborted?: boolean;      // 被用户停止（灰条渲染依据）
}

export type AbortOutcome = 'aborting' | 'none' | 'error';

/** 请求服务端取消当前 run（202/204 均视为受理；终态由 SSE aborted 驱动） */
export async function abortRun(id: string): Promise<AbortOutcome> {
  try {
    await api<unknown>(`/sessions/${encodeURIComponent(id)}/stop`, { method: 'POST' });
    return 'aborting';          // 202（api() 对 2xx 均成功；204 由 client 层视作成功空体）
  } catch (e) {
    if ((e as { status?: number }).status === 204) return 'none';
    stop(id);                   // 本地兜底
    return 'error';
  }
}
```

> 注：若 `webui/src/api/client.ts` 对 204 抛错（视实现而定），在 `abortRun` 内按 `status===204` 归一为 `'none'`；实施时先确认 client 行为再定写法。

`applyEvent` 新增：

```ts
case 'aborted': {
  const asst = currentAssistant(st);
  asst.lastEventAt = now;
  asst.streaming = false;
  asst.live = null;
  asst.aborted = true;
  asst.meta = `已停止 · ${(Number(d.durationMs ?? 0) / 1000).toFixed(1)}s · ${String(d.iterations ?? '?')} 轮`;
  finishRun(id, st, 'aborted');
  void reconcile(id);
  break;
}
```

`finishRun` 签名：`finishRun(id: string, st: SessionStreamState, status: 'done' | 'failed' | 'aborted' = 'done')`；内部逻辑不变（D5，task-07 复用）。

非流式分支（`sendMessage`）：响应体含 `aborted:true` 时 → 回滚乐观消息（`st.messages.splice(baseLen)`）、`st.status='idle'`、toast「已停止（未产生输出）」、返回 `'aborted'`（`SendOutcome` 联合类型扩充）。

### 3.2 `ChatView.vue`

- `stopGen()`：
  ```ts
  const outcome = await abortRun(activeId);
  if (outcome === 'aborting') showToast('已请求停止（服务端正在收尾）');
  else if (outcome === 'none') showToast('当前无正在运行的任务');
  else showToast('停止请求失败，已断开本页连接', 'error');
  ```

- `case 'compaction'` 事件中 `fallback==='aborted'` 的 toast 文案改「压缩已随停止终止」（可选，P1）。

### 3.3 `App.vue`

- 删除侧栏"停止查看"按钮与 `stopSession` 逻辑（D1 确认）；运行点保留（仅展示）。
- 若侧栏有 hover 操作条，删除对应按钮位。

### 3.4 边界与错误处理

| 场景 | 行为 |
|---|---|
| 停止后 202，但 aborted 事件迟迟未到（工具收尾慢） | 界面保持 streaming 态；用户可再点（`abortRun` 幂等）；attach 重连逻辑兜底 |
| abortRun 网络失败但 run 实际已被取消 | 本地 detach 后，用户刷新/切回会话时 `fetchDetail` 按 run=running 走 attach → 收到 aborted 终态，状态收敛 |
| 非流式 + aborted | 回滚乐观气泡；服务端已落盘的部分输出在下次进入会话时由历史渲染呈现 |
| 同一会话双标签页都点了停止 | 第二次 202（alreadyAborting）→ 前端同样提示"已请求停止"，无副作用 |
| aborted 事件与 done 竞争 | 服务端保证只发布一个终态（task-03 D5）；前端 `finishRun` 有 `status!=='running'` 守卫 |
