## 一、任务目标需求

> 这些子命令目前只写在 `description` 的括号里（如「配置管理（list/get/set/delete/path）」），是**展示文本**、不是结构化数据，无法直接用于补全，需要显式声明为候选。

### 1.3 任务目标

- 输入以 `/` 开头时，Tab 触发**一级补全**：`/con` → `/config`；`/` → 列出全部命令。
- 一级补全命中后，继续输入空格，Tab 触发**二级补全**子命令：`/config l` → `/config list`。
- 多候选时展示候选列表（依赖 readline 内置行为），不产生报错、不吞掉用户输入。
- **不干扰普通提问**：非 `/` 开头的 Agent 提问，Tab 保持原样（不插入字符、不报错）。
- **零新依赖**：仅用 Node 内置 `readline`，不引入 `inquirer`/`omelette` 等包。
- **可单元测试**：补全逻辑抽成纯函数/注册器方法，便于断言，不依赖真实 TTY。

### 1.4 设计约束

- **不改动命令语义**：只新增"候选来源"，不改变任何 `match` / `execute` 行为。
- **不破坏 `running` 守卫**：补全发生在输入阶段，不得与运行期 Spinner / readline 交互冲突。
- **向后兼容**：新增字段与 API 均可选；不传即行为与现状完全一致。
- **跨终端**：Windows / macOS / Linux 下 Tab 补全行为一致（Node readline 内置支持）。
- **可独立验证**：分 P0/P1/P2 落地，每阶段可单独验收。

## 二、方案设计

### 2.1 总体思路

```
用户在 readline 中按 Tab
  └─ readline 调用注册的 completer(line)
       ├─ line 不以 '/' 开头 ──▶ 返回 [[], line]（不做任何补全，Tab 无副作用）
       └─ line 以 '/' 开头
            ├─ 仅一个 token（如 "/con"）
            │     └─ 候选 = 注册命令名 ∪ 内联斜杠命令名
            │          过滤 startsWith("/con") ──▶ ["/config"]
            └─ 已有两个 token（如 "/config l"）
                  └─ 按 token[0] 找到 handler 的 subcommands
                       过滤 startsWith("l") ──▶ ["/config list"]
```

核心：**只提供候选列表，补全动作交给 readline 内置逻辑**（单候选自动替换；多候选补公共前缀并列出）。

### 2.2 关键设计决策

1. **候选交由 `CommandRegistry` 统一提供，而非在 `index.ts` 硬编码**
   新增 `listNames()` / `completeCommands(prefix)` 方法（[registry.ts](file:///d:/trae_workspace/loop-agent-command/src/commands/registry.ts)）。CLI 只负责"读候选 + 回填"，命令清单未来新增时**无需再改 `index.ts`**，避免两处维护。

2. **内联命令单独维护一个常量并集**
   `/help` `/reset` `/clear` `/status` 不走注册器（[index.ts:254-278](file:///d:/trae_workspace/loop-agent-command/src/index.ts#L254-L278)），必须在补全候选里以常量并集补齐；否则用户可输入却补不出，体验割裂。**P1 可进一步把内联命令迁入注册器**，从根上统一，但属可选重构。

3. **子命令候选显式声明为结构化字段 `subcommands`**
   在 [CommandHandler](file:///d:/trae_workspace/loop-agent-command/src/commands/registry.ts#L28-L37) 新增可选 `subcommands?: string[]`，各命令文件补一行即可。**不从 `description` 正则解析**（易碎、且 description 会变）。属于 P1。

4. **`completer` 返回的候选项是"整行替换串"，`completeOn` 恒为 `line`**
   Node readline 的 `completer(line)` 需返回 `[completions, completeOn]`；返回 `completeOn = line` 时，Node 用候选**整体替换当前行**——这正是我们要的效果（`/con` → `/config`）。二级补全时候选同样返回**整行**形式（如 `/config list`），避免依赖 Node 内部对 `completeOn` 的切片细节，最稳。

5. **非 `/` 输入返回空候选**
   普通提问（`帮我读一下 package.json`）按 Tab 时返回 `[[], line]`，readline 不做任何替换、不插入制表符，保证零副作用。

6. **补全逻辑与 I/O 解耦**
   `completer` 主体为纯函数（输入 `line` + 候选来源 → 输出候选），便于 `tests/command-completion.test.ts` 直接断言，无需伪 TTY。readline 接线只做"注册函数"。

### 2.3 补全规则映射

| 输入（按 Tab 前） | 候选来源 | 返回候选 | readline 表现 |
|------------------|---------|---------|--------------|
| `（非 / 开头）` | — | `[]` | 无动作（不插入 Tab） |
| `/` | 全部命令名 | `/config` `/help` `/mcp` … | 补公共前缀 `/`，再次 Tab 列出全部 |
| `/con` | 全部命令名 | `/config` | 单候选 → 替换为 `/config` |
| `/re` | 全部命令名 | `/reset` | 单候选 → 替换为 `/reset` |
| `/s` | 全部命令名 | `/session` `/skill` `/status` | 多候选 → 补公共前缀 `/s`，再次 Tab 列出 |
| `/config l` | `subcommands` | `/config list` | 单候选 → 替换整行为 `/config list` |
| `/config ` | `subcommands` | `/config list` `/config get` … | 多候选 → 补公共前缀 `/config `，列出子命令 |
| `/config list x` | — | `[]` | 无动作（已到最深层） |

### 2.4 与现有交互的协作

- **与 Spinner / `running` 守卫无关**：补全只发生在用户输入阶段，`running` 为真时会话内重复提交仍由守卫拦截（[index.ts:244-249](file:///d:/trae_workspace/loop-agent-command/src/index.ts#L244-L249)），二者无交集。
- **与 readline prompt 无冲突**：`completer` 由 readline 在 Tab 键处理中内部调用，不改 `prompt`、不改 `rl.pause()`/`resume()` 语义。
- **多候选列表输出**：readline 会把候选项打印到 `output`（即 `process.stdout`），需确认其打印时机不会与 `Spinner` 混行——补全只可能在**未运行**时发生（运行时无 prompt），故不冲突。

## 三、任务详细设计

### 3.1 `CommandRegistry` 增加补全 API（P0）

[registry.ts](file:///d:/trae_workspace/loop-agent-command/src/commands/registry.ts)：

```typescript
export interface CommandHandler {
  name: string;
  description: string;
  match: (input: string) => boolean;
  execute: (input: string, ctx: CommandContext) => Promise<void>;
  /** 子命令候选（用于二级补全，如 /config 的 list/get/set…）；可选 */
  subcommands?: string[];                                   // ← 新增（P1 使用）
}

export class CommandRegistry {
  // ...原有 register / dispatch 不变

  /** 全部已注册命令名，用于补全候选（含前导 /） */
  listNames(): string[] {
    return this.handlers.map((h) => h.name);
  }

  /** 按前缀过滤一级命令候选 */
  completeCommands(prefix: string): string[] {
    return this.listNames().filter((n) => n.startsWith(prefix));
  }
}
```

### 3.3 `index.ts` 注册 `completer`（P0 一级 / P1 二级）

关键片段示意：

```typescript
// 内联命令（未走注册器，需单独并入候选）
const BUILTIN_SLASH_COMMANDS = ['/help', '/reset', '/clear', '/status'];

/** 补全候选来源：注册命令 ∪ 内联命令；候选项为"整行替换串"，completeOn 恒为 line */
function completer(line: string): [string[], string] {
  const trimmed = line.trimStart();
  if (!trimmed.startsWith('/')) return [[], line];          // 普通提问：零副作用

  const tokens = trimmed.split(/\s+/).filter(Boolean);

  // 一级：补命令名
  if (tokens.length <= 1) {
    const names = [...new Set([...commandRegistry.listNames(), ...BUILTIN_SLASH_COMMANDS])];
    return [names.filter((n) => n.startsWith(trimmed)), line];
  }

  // 二级：补子命令（P1）
  if (tokens.length === 2) {
    const handler = commandRegistry.list().find((h) => h.name === tokens[0]);
    const subs = handler?.subcommands ?? [];
    return [subs.filter((s) => s.startsWith(tokens[1])).map((s) => `${tokens[0]} ${s}`), line];
  }

  return [[], line];                                        // 更深层不补全
}

const rl = readline.createInterface({
  input: process.stdin,
  output: process.stdout,
  prompt: `${C.bold}${C.cyan}Agent>${C.reset} `,
  completer,                                                 // ← 新增
});
```

### 3.4 边界处理

| 场景 | 处理 |
|------|------|
| 空行按 Tab | `trimmed === ''`，不以 `/` 开头 → 返回 `[]`，无动作 |
| 前导空格 `/con` | 用 `trimStart()` 判定，候选按 `trimmed` 过滤 |
| 已完整输入 `/config` 按 Tab | 候选含 `/config` 自身，单候选且等于当前行 → readline 无变化（幂等） |
| 大小写 | 命令名均小写；`startsWith` 区分大小写，与既有 `match`（部分命令内部 `toLowerCase`）保持"输入即所写"的一致预期 |
| 不存在的命令 `/xyz` 按 Tab | 候选为空 → 无动作、无报错 |
| Tab 与 Agent 提问混用 | 非 `/` 开头恒不补全，杜绝误替换用户自然语言 |
