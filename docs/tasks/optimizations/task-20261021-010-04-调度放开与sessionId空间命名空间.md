## 一、任务目标需求

### 1.1 背景

task-03 完成后，每个空间已拥有独立的 store/config/skill/kit/pool，`process.chdir` 也已消失。但**调度层仍是串行语义**，产品仍然"不能跨空间并行"：

```ts
// src/api/session-manager.ts:49-54 —— 全局互斥：任一会话在跑 → 任何空间都不能切/建
hasInFlight(): boolean {
  for (const entry of this.sessions.values()) if (entry.inFlight) return true;
  return false;
}
```
```ts
// src/api/handlers/sessions.ts:94-97 —— 于是"新建会话到别的空间"必然被 busy 拒绝
if (ctx.sessions.hasInFlight()) throw new ApiHttpError('busy', '存在正在处理的会话，暂不能切换工作空间');
await switchWorkspace(ctx, target);
```
```ts
// src/api/handlers/sessions.ts:205-212 —— 打开跨空间会话还会"偷偷换掉当前空间"
if (!owner.current && !ctx.sessions.hasInFlight()) { await switchWorkspace(ctx, owner.path); switched = true; }
```

要放开并行，必须先解决**全局键冲突**：`sessionId` 是秒级时间戳（[store.ts:335](file:///d:/trae_workspace/loop-agent-command/src/session/store.ts#L335)），而它同时是 `SessionManager.sessions`、`RunHub.runs`、`RunJournal` 文件名、前端 `chat-stream` 状态的**全局键**——两空间同秒创建会互相覆盖（文件名同为 `sess_20261021_143000.json`，且分属不同目录时虽不冲突，但 `RunHub` 的内存键会撞）。

### 1.2 现状梳理

| 所需能力 | 现状 | 结论 |
|---|---|---|
| 空间级互斥 | `SessionManager` 单例 + 全局 `hasInFlight()`（[session-manager.ts:29-54](file:///d:/trae_workspace/loop-agent-command/src/api/session-manager.ts#L29-L54)） | task-03 后每 runtime 已各持一个 `SessionManager` → **天然 per-space**；本任务只需把 handler 的 `ctx.sessions` 换成"当前/归属 runtime 的 sessions" |
| 会话创建串行化 | 全局 `createChain` + `lastCreateAt` + 1050ms 间隔（[:77-93](file:///d:/trae_workspace/loop-agent-command/src/api/session-manager.ts#L77-L93)） | 保留**同空间**串行（秒级 id 粒度不变），**跨空间不再互相等待** |
| `sessionId` 唯一性 | `sess_${formatDate()}` 秒级，**`sess_` 前缀在全仓无解析点**（仅 [store.ts:335](file:///d:/trae_workspace/loop-agent-command/src/session/store.ts#L335) 生成，作为文件名 `<id>.json`） | 加空间段 `sess_<wsId8>_<ts>` **完全兼容**（无解析方依赖格式） |
| 跨空间会话定位 | `GET/DELETE /sessions/:id` 靠 `listAllWorkspaces()` 全扫找 owner（[:196-199](file:///d:/trae_workspace/loop-agent-command/src/api/handlers/sessions.ts#L196-L199)、[:234-237](file:///d:/trae_workspace/loop-agent-command/src/api/handlers/sessions.ts#L234-L237)） | 新 id 段解析 O(1)；老 id 走映射缓存 + 全扫回退（D17） |
| 打开跨空间会话 | 自动 `switchWorkspace()` 改变全局当前空间（[:203-212](file:///d:/trae_workspace/loop-agent-command/src/api/handlers/sessions.ts#L203-L212)） | **删除自动切换**（D10 前置）：只读/续聊都在会话所属 runtime 内完成 |
| "当前空间" | `/workspaces` 用 `dir === this.workspaceId` 标 `current`（[store.ts:665](file:///d:/trae_workspace/loop-agent-command/src/session/store.ts#L665)） | 改为 registry 的"最近使用指针"（D9） |
| 全局并发上限 | 无 | 新增进程级 `Semaphore`（D18） |
| 残留原地重绑 | `rebindWorkspace`（[store.ts:304](file:///d:/trae_workspace/loop-agent-command/src/session/store.ts#L304)）、`setWorkspacePath`（[loader.ts:65](file:///d:/trae_workspace/loop-agent-command/src/config/loader.ts#L65)、[writer.ts:30](file:///d:/trae_workspace/loop-agent-command/src/config/writer.ts#L30)） | **删除**（P1 已无生产调用） |

### 1.3 任务目标

1. **per-workspace 互斥**：`busy` 判定只看"该空间内是否有 in-flight"，A 空间运行中可在 B 空间新建/切换/删除会话。
2. **`sessionId` 空间命名空间**：`sess_<wsId8>_<YYYYMMDD_HHMMSS>`，兼容老 id。
3. **跨空间会话按 id 定位归属 runtime**（D17），`GET/POST messages/stop/stream/DELETE /sessions/:id` 全部按 sessionId 路由到对应 runtime。
4. **删除自动切换空间**：打开跨空间会话不再 `switchWorkspace`；响应 `switched` 字段恒 `false`（字段保留，task-05 前端移除依赖）。
5. **`POST /sessions { workspacePath }` 直接建在目标空间**，不改变任何"当前空间"状态。
6. **全局并发信号量**（D18）：`min(maxRuntimes × poolCapacity, LOOP_AGENT_MAX_CONCURRENCY=8)`。
7. 删除 `rebindWorkspace` / `setWorkspacePath`；`/workspaces` 的 `current` 改由"最近使用指针"决定（D9）。

### 1.4 设计约束

- **向后兼容**：老格式 `sess_YYYYMMDD_HHMMSS` 会话在 `/workspaces`、`GET /sessions/:id`、续聊、删除、run journal 上全部照常。
- **`RunHub` 仍为进程级单例**（不按空间分），靠 sessionId 全局唯一；`runs.isRunning(id)` 语义不变。
- CLI 零 diff（A7.1）；`/workspaces` 响应结构不删字段（只改 `current` 的来源）。
- 本任务**不改前端**（task-05）。

## 二、方案设计

### 2.1 总体思路

```
请求 → 解析 sessionId（若带）
   │
   ├─ 新格式 sess_<wsId8>_<ts> ──► 按 wsId8 前缀在 registry.list() 中精准匹配 → runtime
   │                                （未装载则扫描 <userDir>/sessions/*/meta.json 反查 root 后 registry.get）
   └─ 老格式 sess_<ts> ─────────► 映射缓存 id→wsId（miss：全扫一次并缓存）→ runtime
                                       │
                                       ▼
                          rt.sessions.ensureEntry(id)   ← per-space 缓存与锁
                          rt.store.loadSession(id)      ← per-space 存储
                          rt.pool.withAgent(id, ...)    ← per-space 池
                                       │
                                全局 Semaphore（D18）夹在外层：同时最多 8 个 run

POST /sessions { workspacePath }
   └─ registry.get(canonical(path)) → rt.sessions.createSessionSafe(...) → rt.store 写盘
      ✗ 不 chdir  ✗ 不改其他 runtime  ✗ 不 reset 任何池
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D5** | 新 id 格式 `sess_<wsId8>_<ts>`，**老 id 永久兼容读取** | 换成 UUID：存量会话 id 与前端/文档/日志全变，兼容成本高；仅加时间戳精度（毫秒）：同毫秒仍可能撞，且不解决"不知道归属空间" |
| **D9** | "当前工作空间"退化为 **"最近使用"指针**（registry 维护），`/workspaces.current` 由它决定 | 保留"全局当前空间"：与并行语义冲突，多标签页场景必然误标 |
| **D10 前置** | 打开跨空间会话**不再切空间**，直接在该会话所属 runtime 内读/写 | 保留自动切换：会把用户界面共享状态改掉，且与并行语义矛盾 |
| **D17** | 会话归属定位：**新 id 段解析 O(1)** + **老 id 映射缓存 + 全扫回退** | 全部走全扫：每次消息/停止都扫一遍所有空间目录，长跑进程下 IO 放大；只支持新 id：老会话直接不可用 |
| **D18** | 进程级 `Semaphore`（零依赖、FIFO），上限 `min(maxRuntimes × poolCapacity, LOOP_AGENT_MAX_CONCURRENCY=8)`，包在 `pool.withAgent` 外层 | 只靠各池 capacity：总并发 = 空间数 × 4，空间多时打爆 LLM 限速；引入 `p-limit` 依赖：违反零新依赖 |
| **L1** | `createSessionSafe` 保留"同空间串行 + 1050ms 间隔"，但**链按 runtime 独立** | 去掉间隔：同空间同秒仍会覆盖（`sessionId` 秒级粒度未变）；改为毫秒 id：改动面扩散到 store 全部读写路径 |
| **L2** | `switched` 字段**保留但恒 false**，留给前端 task-05 移除 | 直接删字段：前端仍读 `r.workspace?.switched`（[ChatView.vue:197](file:///d:/trae_workspace/loop-agent-command/webui/src/views/ChatView.vue#L197)），会 TypeError 风险 |

## 三、任务详细设计

### 3.1 `sessionId` 命名空间（`src/session/store.ts:335`）

```ts
// 旧：sess_20261021_143000
// 新：sess_1a2b3c4d_20261021_143000   （wsId8 = workspaceId 前 8 位）
const id = `sess_${this.workspaceId.slice(0, 8)}_${formatDate(new Date())}`;
```

- `${id}.json` / `${id}.enc` 文件名规则不变；
- `sessions.json` 索引结构不变；
- run journal（`runs/<id>.json`）不变；
- 老 id 只读兼容，**不迁移**。

### 3.2 归属定位（新增 `src/api/session-locator.ts`）

```ts
/** 解析 sessionId → 归属 runtime；找不到 → ApiHttpError('not_found') */
export async function locateSession(ctx: HandlerContext, id: string): Promise<WorkspaceRuntime>;
```

三级策略（D17）：

1. **段解析**：`/^sess_([0-9a-f]{8})_/` → 与 `registry.list()` 中 `rt.id.slice(0,8)` 比对；命中直接返回。
2. **映射缓存**：`Map<sessionId, wsId>`（进程内，`locate` 成功即写入）。
3. **全扫回退**：`listAllWorkspaces()` 找 owner（现逻辑），命中后 `registry.get(owner.path)` 并写缓存。

> 未装载的空间需**按 `meta.json` 反查 root**：扫描 `<userDir>/sessions/<wsId>/meta.json` 得到 `workspacePath`（已有结构，见 [store.ts:636-665](file:///d:/trae_workspace/loop-agent-command/src/session/store.ts#L636-L665)）。

### 3.3 handler 改造矩阵

| 端点 | 现状 | 改为 |
|---|---|---|
| `POST /sessions`（无 `workspacePath`） | `ctx.sessions.createSessionSafe` | 建在**最近使用空间**（或显式 `X-Workspace` 缺失时取 `currentRoot`） |
| `POST /sessions`（带 `workspacePath`） | `hasInFlight` → `switchWorkspace` → 创建 | `registry.get(root)` 后**直接在该 runtime 创建**；不 chdir、不改其他 runtime；响应 `switched:false` |
| `GET /sessions` | `ctx.deps.sessionStore.listSessions()` | 当前空间 runtime 的 `store.listSessions()` |
| `GET /workspaces` | `listAllWorkspaces()` + `runs.isRunning` | 不变（`current` 改由最近使用指针标注，D9） |
| `GET /sessions/:id` | 全扫 + 可能 `switchWorkspace` | `locateSession(id)` → `rt.store.loadSession` + `rt.runs.snapshot`；**不切空间** |
| `POST /sessions/:id/messages` | 用当前 `store`/`pool` | `locateSession(id)` → `rt.pool.withAgent(id, ...)`（外层过 Semaphore） |
| `GET /sessions/:id/stream`、`POST /sessions/:id/stop` | `RunHub` 全局 | 只依赖 `RunHub`（全局键唯一），**无需定位 runtime** |
| `DELETE /sessions/:id` | `ctx.sessions.get(id)?.inFlight` + 全扫 | `locateSession(id)` → 该 runtime 的 `entry.inFlight` 判定 → 删该空间文件 |
| `switchWorkspace` | 六步 | **退化为指针刷新**：`ensureRoot` + `registry.get` + `ensureScaffold` + 更新最近使用指针；**不再有 busy 判定** |

### 3.4 全局并发信号量（D18）

```ts
// src/api/semaphore.ts（新建，零依赖 FIFO）
export class Semaphore {
  constructor(private readonly max: number) {}
  async run<T>(fn: () => Promise<T>): Promise<T>;   // 排队，先到先得
  get pending(): number; get active(): number;
}
```

接入点（`bootstrap.ts`）：

```ts
const limit = Math.min(maxRuntimes * poolCapacity, Number(process.env.LOOP_AGENT_MAX_CONCURRENCY ?? 8) || 8);
const gate = new Semaphore(limit);
runAgent: (sid, input, opts) => gate.run(() => rt.pool.withAgent(sid, (a) => a.run(input, opts)))
```

> 排队**不设超时**（与现有 run 无时限一致）；`/status` 可选暴露 `{active, pending}` 便于观测。

### 3.5 `current` 语义与最近使用指针（D9）

- `WorkspaceRegistry` 增 `currentRoot: string | null` + `touch(root)`；
- `switchWorkspace` 与"在空间内创建会话/发消息"都会 `touch(root)`；
- `listAllWorkspaces()` 结果的 `current` 不再由 `dir === this.workspaceId` 判定，改由 handler 按 `registry.currentRoot` 覆写。

### 3.6 删除原地重绑 API

- 删 `SessionStore.rebindWorkspace()`（[store.ts:304-307](file:///d:/trae_workspace/loop-agent-command/src/session/store.ts#L304-L307)）及其单测；
- 删 `ConfigLoader.setWorkspacePath()`（[loader.ts:64-67](file:///d:/trae_workspace/loop-agent-command/src/config/loader.ts#L64-L67)）与 `ConfigWriter.setWorkspacePath()`（[writer.ts:29-32](file:///d:/trae_workspace/loop-agent-command/src/config/writer.ts#L29-L32)）；
- `HandlerContext` 中 `configLoader/configWriter` 改为 `currentRuntime().configLoader` 访问器（或保留字段指向最近使用 runtime，P2 内保持最小改动）。

### 3.7 边界与错误处理

| 场景 | 行为 |
|---|---|
| 两空间同秒创建会话 | id 含不同 `wsId8` → 不撞；`RunHub` 键唯一 |
| 老会话 id（无空间段） | 全扫定位一次后缓存；缓存随 runtime 淘汰清理 |
| 会话所在目录被移走/删除 | `locateSession` 抛 `not_found`（与现状 `SessionNotFoundError` 语义一致） |
| 目标空间已淘汰（LRU evict） | `registry.get` 重建 runtime；会话历史从磁盘恢复 |
| 并发 run 超过上限 | 排队（FIFO），`/status` 可见 `pending` |
| 同一 sessionId 并发发消息 | 仍由 `entry.inFlight` 拒绝（现状语义不变） |
| `POST /sessions` 带不存在目录 | `ensureRoot` 抛 `not_found`（原语义） |

### 3.8 演进项

- `RunHub` 是否也按空间分片（当前不必：全局键已唯一）。
- `/status` 暴露 `{workspaces, active, pending}` 的完整观测面板（另立建议）。
