## 一、任务目标需求

### 1.1 背景

后端的"跨空间只读"约束源自一个已经消失的前提：**服务端只有一个工作空间是活动的**，打开别的空间的会话必须先把服务端整体切过去，于是前端做了三件事来配合：

1. 给跨空间会话打 **"只读"** 徽标，并禁用输入框/附件/发送（`foreignActive`）；
2. `send()` 里直接拦截并 toast "跨空间会话仅支持查看与删除"；
3. 打开跨空间会话时靠后端 **自动切换**，前端收到 `switched: true` 后刷新列表并弹 "已切换工作空间" toast。

task-04 之后：打开跨空间会话不再切换任何服务端状态、会话可原地续聊、两空间可并行。前端这三处遗留逻辑就从"约束"变成了**错误限制**——用户明明能聊，界面却禁用输入。

### 1.3 任务目标

- 只改 `webui/src`，不碰 `src/`（除编译产物）。

## 二、方案设计

### 2.1 总体思路

```
改造前                                   改造后
activeWs.current === false               （删除该概念）
   → foreignActive = true                  每个会话都能直接续聊
   → 输入禁用 / 只读徽标                    → 输入可用
   → send() 拦截                            → 正常发送（后端按会话归属空间路由）
GET /sessions/:id → switched:true        → switched 恒 false，前端不再分支
   → loadSessions() + toast                 → 静默
FilesView :ws-path="currentWsPath"       → :ws-path="activeWsPath"（活跃会话所属空间）
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与被否决项 |
|---|---|---|
| **D10** | 撤 `foreignActive`：跨空间会话**完全可写**（可续聊） | 保留只读：与 task-04 的服务端能力矛盾，用户体验倒退 |
| **D9** | 保留 `current` 标记用于"最近使用"提示，但**不承担禁用语义** | 彻底移除 `current` 展示：`/workspaces` 契约与用户认知都要变，收益低 |
| **L1** | `FilesView` 用**活跃会话所属空间**根 | 继续用 `currentWsPath`：跨空间会话看文件会打开别的空间目录（功能性错误） |
| **L2** | 前端保留 `workspace ?.switched` 的类型定义但**不作分支**，下批次统一下线 | 立即删类型：与后端字段生命周期不同步，容易在后端未发版时崩 |
