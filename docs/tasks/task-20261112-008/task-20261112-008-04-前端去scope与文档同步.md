## 一、任务目标需求

### 1.1 背景（痛点）

后端全局化后，前端仍有五处 scope 选择器与若干「工作空间/全局」徽标文案。用户所见与后端语义不一致，会出现「选了工作空间却写进全局」的错觉，且 `?scope=workspace` 会得到 400 而界面无提示。

### 1.2 现状梳理

| 文件 | 现状 |
|---|---|
`ConfigView.vue:25,185-186,280` | 「写入 scope」下拉 + 来源徽标（`StatusBadge kind="brand">来源 {{ keyResult.scope }}`） |
`McpView.vue:136,141,176-177,390,448-463` | `regScope`/`cfmScope` 两个 ref + `.gl/.ws` 徽标 + 删除确认层选择 |
`ModelsView.vue:69,131,433,458,482,522,659-663,994-998,1231-1238,1257` | `scope` ref + 四处切换 UI + `scopeText` 文案 |
`ToolsView.vue:35,132,294,391,474` | 「写入范围」下拉 + 元信息与抽屉展示 |
`SkillsView.vue:35,67,222,293,438-440,641-648` | `scopeTab` 筛选（all/workspace/global）+ `installScope` 单选 |
`DreamScheduleCard.vue:175,181` | 硬编码 `scope:'workspace'` |
`skills-ui.ts` | `scopeLabel()` / `scopePath()` |
`DevView.vue:342` | 开发者文档写「默认 workspace」 |

### 1.3 任务目标

- 五个管理页面移除 scope 选择器、scope 徽标与「工作空间/全局」文案
- 请求体/查询参数不再发送 `scope`
- `DreamScheduleCard` 去掉 `scope:'workspace'`
- `skills-ui.ts` 的 `scopeLabel`/`scopePath` 删除或改为常量
- `DevView` 开发者文档同步为新语义（`scope` 仅 `global`，传 `workspace` → 400）
- 中英双语 README 同步（若无相关章节则补「配置均为全局」说明）

### 1.4 设计约束

- 布局不得因删除下拉而错位（`tl-scope`、`mv-scope-wrap` 等类名需一并清理）
- 暗色/浅色主题、窄屏（≤900px）均需回归
- 不引入新依赖；不改变页面其它交互

## 二、方案设计

### 2.1 总体思路

```
请求构造：删除 scope 字段        ──► 后端只按全局处理
界面展示：删除 scope UI 与徽标    ──► 不再暗示存在分层
文档：    改写 DevView 与 README ──► 与新语义一致
```

### 2.2 关键设计决策

- **D5/D9 延伸**：前端仍保留对响应中 `scope` 字段的**类型兼容**（后端恒返回 `'global'`），但不渲染。避免后端回滚或灰度时前端崩溃。
  - 被否决：前端类型里删掉 `scope`（与后端过渡期不匹配）
- **文案决策**：不新增「全局配置」大标题，仅在原本显示 scope 的位置留空或改为一句话提示（避免版面膨胀）。
  - 被否决：显眼横幅提示「所有配置为全局」（冗余，用户已明确要求）

### 2.3 交互影响

| 页面 | 删除后影响 |
|---|---|
`ConfigView` | 「来源」徽标删除；单键读取结果只显示值 |
`McpView` | 登记不再选范围；删除确认不再选范围 |
`ModelsView` | 四处切换删除，登记/保存/切换/删除均写全局 |
`ToolsView` | 「写入范围」下拉删除，启停直接生效 |
`SkillsView` | `scopeTab` 筛选保留 `all` 语义（或整体删除筛选行）；安装不再选范围 |
