## 一、需求背景

`fileRead` 与 `grep` 目前只支持「可直接按 UTF-8 逐行读取」的文本文件，前 8000 字节含 NUL 即判定二进制并拒绝/跳过。用户需要 Agent 能直接读取和检索 doc、docx、pdf 等文档，而不是依赖本机不一定存在的 `pdftotext` 或 Office。

总体方案：新增独立文档层负责「识别 + 提取为纯文本」，两个工具只在二进制嗅探前加识别分支，行号、区间、截断、匹配、落盘等既有逻辑全部复用。文本文件路径零行为变化。

## 四、统一设计约束（三个任务共同遵守）

- 零新增 npm 依赖；zip 解析复用 [`readZipEntries()`](file:///d:/trae_workspace/loop-agent-command/src/skill/zip.ts#L68-L138)。
- 纯文本路径字节级不变：检测只多读文件头，且与现有 NUL 嗅探共用缓冲区。
- 文档行号为**提取文本行号**，输出首行必须显式说明。
- 资源上限：源文件 50MB、提取文本 5M 字符、PDF 500 页、单文档 15s、目录文档提取合计 20s。
- 不新增工具名、不改 `ToolContext`、不改 SSE/前端协议、不改 runner 默认 30s 超时。
- 所有错误消息为中文且可纠正；目录检索单文件失败不得中断整体。
