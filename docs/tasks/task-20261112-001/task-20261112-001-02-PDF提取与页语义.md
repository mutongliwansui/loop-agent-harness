## 一、任务目标需求

### 1.1 背景（痛点）

任务 01 已让 doc/docx 可读可搜，但 PDF 仍被识别后提示「待启用」。PDF 是用户最常需要 Agent 阅读的文档类型，且其「页」语义与文本行完全不同：用户与模型都按页定位，`startLine/endLine` 单独不够用。

### 1.3 任务目标

1. 新增 `src/documents/pdf.ts`，零依赖提取文本层 PDF 的正文字；
2. PDF 输出插入 `=== 第 N 页 ===` 页标记，并建立「页 ↔ 提取文本行」映射；
3. `grep` 在 PDF 中的命中带 `[p.N]` 页码；
4. `fileRead` 新增可选 `pages` 参数（`"3"`/`"3-7"`/`"3-"`/`"1,4,9"`），与 `startLine/endLine` 互斥，仅对 PDF 生效；
5. 加密、扫描件、损坏、超页数/超时/超字符数均有可纠正提示；
6. 提取文本超限时落盘完整提取文本（非原始二进制），并更新提示文案；
7. `/fs/doc2md` 改为复用 `extractWordBody()`，响应与内容零变化；
8. 工具描述预算测试同步更新后全绿。

### 1.4 设计约束

- **零新增 npm 依赖**；不引入 pdfjs-dist / unpdf / pdf-parse；
- 源文件 ≤50MB、PDF ≤500 页、提取文本 ≤5M 字符、单文档 ≤15s；
- 每页至少检查一次超时与取消信号，保证在 runner 30s 超时前返回；
- 扫描件不尝试 OCR，返回 `scanned` 并给出替代路径；
- `pages` 参数只影响返回范围，不改变行号口径（行号始终基于完整提取文本）；
- 不改变 `grep` 既有输出前缀结构（`path:line:` 不变），只改 content 前缀。

## 二、方案设计

### 2.1 总体思路

```
Buffer(≤50MB)
   │
   ├─ 1. 对象扫描（正则扫 "N 0 obj"，不依赖 xref）
   │        └─ ObjStm 解压 → 合并内部对象
   │
   ├─ 2. trailer /Encrypt? ── 是 ──▶ encrypted
   │
   ├─ 3. /Root → /Pages → /Kids 递归 ──▶ 页序 + /Resources 继承
   │
   ├─ 4. 每页 /Contents 解码（Flate/ASCIIHex/ASCII85）
   │
   ├─ 5. 内容流解析：BT/ET、Tf/Td/TD/T*/Tm、Tj/TJ/'/"
   │        └─ Tf → /ToUnicode CMap 或简单编码表 → Unicode
   │
   ├─ 6. 页聚合：=== 第 N 页 === + PageRange
   │
   └─ 7. 预算检查（页数/字符数/耗时/取消）
        │
        ▼
   ExtractResult { text, pages, pageCount, warnings, truncated }
        │
        ├─ fileRead：pages 过滤 → 行号/maxBytes → 超限落盘
        └─ grep：逐行正则 + 行→页映射 → [p.N]
```

图中 D 编号对应设计方案 D3/D6/D7/D9/D10/D12。

### 2.2 关键设计决策

| 编号 | 决策 | 推荐 | 被否决项与理由 |
| --- | --- | --- | --- |
| **T2-D1** | 自研最小 PDF 解析器，零依赖 | ✅ | 否决 pdfjs-dist/unpdf：体积、worker、SEA 打包风险；否决 pdf-parse：维护与 CJK 支持弱 |
| **T2-D2** | 不依赖 xref：暴力扫描 `N 0 obj`，并解压 `ObjStm` | ✅ | 否决只读 xref 表：大量真实 PDF 的 xref 损坏或为压缩流 |
| **T2-D3** | 只处理文本层；`/Encrypt` → `encrypted`，无可读字符 → `scanned` | ✅ | 否决尝试解密/OCR：超出范围且不可靠 |
| **T2-D4** | 字体解码优先 `/ToUnicode`，其次简单编码表；`�` 占比 >20% 告警 | ✅ | 否决无映射直接丢弃：中文文档会整段丢失；否决全部回退 UTF-16 猜测：误码率更高 |
| **T2-D5** | `pages` 为字符串区间，与 `startLine/endLine` 互斥，仅 PDF 生效 | ✅ | 否决 `pageStart/pageEnd`：schema 更长且不支持离散页 |
| **T2-D6** | 页标记使用独立行 `=== 第 N 页 ===`，行号全局连续 | ✅ | 否决每页重置行号：后续 `startLine` 续读会歧义 |
| **T2-D7** | `grep` 保持 `path:line: content`，PDF 命中在 content 前加 `[p.N] ` | ✅ | 否决改动路径段结构：破坏既有输出契约 |
| **T2-D8** | 超限落盘完整提取文本，提示明确「非原始二进制文档」 | ✅ | 否决复制原始字节：对模型无用；否决不落盘：截断后无法续读 |
| **T2-D9** | `/fs/doc2md` 改用 `extractWordBody()`，`textToMd()` 与响应结构不变 | ✅ | 否决保留两份 Word 解析：易漂移 |

## 三、任务详细设计

### 3.1 模块接口

```ts
// src/documents/pdf.ts
export interface PdfExtractOptions {
  maxBytes: number;        // 源文件上限（50MB）
  maxPages?: number;       // 默认 500
  maxChars?: number;       // 默认 5_000_000
  timeBudgetMs?: number;   // 默认 15000
  signal?: AbortSignal;
}

export function extractPdf(
  absPath: string,
  opts: PdfExtractOptions,
): Promise<ExtractResult>;   // pages 必填
```

内部拆分（均可单测）：

| 函数 | 职责 |
| --- | --- |
| `scanObjects(buf)` | 扫 `N 0 obj`，返回 `Map<objNum, objBody>` |
| `expandObjectStreams(objects)` | 解压 `ObjStm` 并合并内部对象 |
| `decodeStream(dict, raw)` | 按 `/Filter` 解码，`maxOutputLength` 防炸弹 |
| `walkPageTree(objects)` | 返回页对象数组与继承后的 `/Resources` |
| `parseContentStream(stream, fonts)` | 产出文本片段与换行/空格事件 |
| `buildFontDecoder(fontObj)` | 解析 `/ToUnicode` CMap 或简单编码表 |
| `assemblePages(pageTexts)` | 生成 `text` 与 `PageRange[]` |

### 3.2 内容流支持范围

| 类别 | 支持 | 说明 |
| --- | --- | --- |
| 文本显示 | `Tj`、`TJ`、`'`、`"` | `TJ` 数组中的数字按 kerning 处理 |
| 定位 | `Td`、`TD`、`T*`、`Tm`、`BT`、`ET` | Y 变化换行；X 间距过大补空格 |
| 字体 | `Tf` | 资源名 → 字体对象 |
| 忽略 | `q/Q/cm/Do/re/f/S/...` | 图形、图片 XObject 不参与文本 |
| 流过滤器 | `FlateDecode`、`ASCIIHexDecode`、`ASCII85Decode` | LZW/RunLength 跳过并告警 |

### 3.3 字体解码

1. `/ToUnicode` CMap：解析 `beginbfchar/endbfchar`、`beginbfrange/endbfrange`；
2. 无 ToUnicode：
   - 简单字体（`/Subtype /TrueType`/`/Type1`）按 WinAnsi/StandardEncoding 单字节映射；
   - `Type0 + Identity-H` 按 2 字节码解析，未映射输出 `�`；
3. 统计 `�` 占非空白字符比例，>20% 追加告警「字体编码未完全解析，文本可能乱码」；
4. 字体缓存按对象号去重，避免重复解析 CMap。

### 3.4 `fileRead.pages` 参数

- 类型：`string`，可选；示例 `"3"`、`"3-7"`、`"3-"`、`"1,4,9"`；
- 解析为页号集合；非法格式、页号 <1、起止倒置 → 抛参数错误；
- 与 `startLine/endLine` 同时出现 → 抛「pages 与 startLine/endLine 互斥」；
- 仅 PDF 生效；非 PDF 文档传 `pages` → 抛「pages 仅对 PDF 生效」；
- 返回所选页的文本，但行号仍为完整提取文本行号，便于后续 `startLine` 续读；
- `maxBytes` 仍生效；超出所选页范围 → 提示实际页数。

工具描述示例（≤200 字符）：

```
读取文本或文档（doc/docx/pdf），默认带行号。大文件用 startLine/endLine 分段；PDF 可传 pages（如 "3-7"）。扫描件/加密件会提示。
```

参数 schema 新增：

```json
"pages": { "type": "string", "description": "PDF 页码，如 3 / 3-7 / 3- / 1,4,9；与 startLine/endLine 互斥" }
```

### 3.5 `grep` 页标注

- 提取结果带 `PageRange[]`，逐行匹配时维护页指针；
- 命中格式：`/abs/a.pdf:123: [p.3] 命中内容`；
- 跨页命中不会出现（按行匹配，行不跨页）；
- 目录汇总中 PDF 失败原因取 `DocumentExtractError.code` 映射中文。

### 3.6 超限落盘

- 触发条件：返回行数/字节超过 `DEFAULT_MAX_LINES` / `DEFAULT_MAX_BYTES`；
- 用 `TmpFileWriter` 写入完整 `ExtractResult.text`；
- 提示文案：

  ```
  ── 完整输出已保存 ──
  路径: ~/.loop-agent/tmp/.../fileRead-a.pdf-<ts>.txt
  文件大小: 320.4 KB
  文件行数: 8123
  完整性: 完整（该文件为提取出的全文文本，非原始二进制文档）
  建议: 用 fileRead 的 startLine/endLine 分段读取，如 startLine: 2001, endLine: 2200
  ```

### 3.7 错误与边界

| 场景 | code | 行为 |
| --- | --- | --- |
| `/Encrypt` | `encrypted` | 直接返回，不尝试解密 |
| 全篇无可读字符 | `scanned` | 提示可能是扫描件，建议 analyzeImage/转文本 PDF |
| 对象/页树损坏 | `corrupt` | 返回「PDF 结构损坏，无法定位页面」 |
| 页数 >500 | — | 提取前 500 页，`truncated=true`，末尾说明 |
| 字符数 >5M | — | 停止并标记，末尾说明 |
| 超过 15s | `timeout` | 返回已完成页的文本，末尾说明剩余页未处理 |
| 取消信号 | — | 抛出 `AgentAbortedError`（由 runner/agent 处理） |
| `pages` 越界 | 参数错误 | 提示实际页数并给出合法范围 |

### 3.8 `fs/doc2md` 共享

- `handleDoc2Md` 改为 `const raw = await extractWordBody(abs)`；
- `textToMd()` 与响应字段（`path/name/bytes/truncated/content`）不变；
- 现有 `fs-endpoints.test.ts` 应零改动通过；如测试依赖 `WordExtractor` mock，改为 mock 共享模块。

### 3.9 演进项（本任务不做）

- OCR；
- 版面/表格还原；
- 外部 `pdftotext` 兜底（任务 03）；
- 提取缓存。
