## 一、任务目标需求

### 1.1 背景（痛点）

当前 WebUI 的回答区没有任何消息级操作：想再问一遍只能手动重新输入；想复用回答内容只能手动划选；上下文快满时只能等下一轮自动触发 L1 压缩，用户既看不到「还剩多少上下文」，也无法主动腾空间。

期望形态（参考截图）：每条回答下方一排轻量图标——复制、重试、…，最右侧是环形百分比（如 `63%`）；鼠标悬浮百分比弹出卡片：`上下文使用率`、`63% of 200K`、下方「压缩」按钮。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| 上下文用量数据 | SSE 已有 `llm_stats`，含 `contextTokens` / `contextMaxTokens`（[types.ts#L165-L178](../../../src/types.ts#L165-L178)、[react-agent.ts#L855-L867](../../../src/agent/react-agent.ts#L855-L867)） | 数据已有，**前端未消费**（[chat-stream.ts](../../../webui/src/chat-stream.ts) 的 switch 无 `llm_stats` 分支） |
| 会话级用量查询 | `ReactAgent.getContextUsage()` 仅 CLI `/status` 使用（[start.ts#L76](../../../src/cli/start.ts#L76)） | **无 API**，历史会话打开后拿不到 |
| 手动压缩 | 压缩只在 run 内按阈值自动触发（[react-agent.ts#L601-L757](../../../src/agent/react-agent.ts#L601-L757)），无公开方法 | **无方法、无端点** |
| 压缩过程反馈 | `compaction_start` / `compaction` 事件已驱动消息末尾 loading（[ChatView.vue#L967-L970](../../../webui/src/views/ChatView.vue#L967-L970)） | 仅 run 内可用；手动压缩需前端本地态 |
| 消息级操作 | ChatView 仅输入区有按钮，消息区无复制/重试 | **缺失** |
| 重试所需的截断能力 | `SessionStore.updateSession` 是**增量合并**（含压缩轨迹重建，[store.ts#L406-L560](../../../src/session/store.ts#L406-L560)），无「按消息截断」入口 | 需新增 `rewriteMessages`（仅重试用） |
| 历史会话用量 | 历史消息不带统计 | 需估算兜底并标注 |

### 1.3 任务目标

1. **每条 assistant 回答**下方新增操作栏：复制、重试，最右侧上下文百分比环。
2. 百分比悬浮卡片展示：百分比、已用/上限 token、压缩阈值、数据来源（真实 / 估算），并提供**压缩**按钮。
3. 新增 `GET /sessions/:id/context`：会话用量查询（真实统计优先，回退估算）。
4. 新增 `POST /sessions/:id/compact`：空闲时强制 L1 压缩，返回压缩前后 token 与保留条数；**执行前弹二次确认**。
5. 新增 `POST /sessions/:id/retry`：**替换式重试**——截断该轮及之后的对话，重新发送该轮用户文本。
6. 前端消费 `llm_stats` 实时刷新百分比；压缩期间按钮禁用 + 消息末尾显示「正在压缩对话历史…」。
7. 复制取该条回答纯文本。

### 1.4 设计约束

- **不改自动压缩策略**（阈值、`planCompaction` 切轮规则、`flushFailure` 语义全部沿用）。
- 压缩与重试都是破坏性操作：必须空闲可触发、有明确确认与 loading、禁止与 run 并发。
- 重试的截断**只允许从「某轮 user 消息」开始**，不允许从任意 assistant/tool 中间切断（避免非法 tool 序列）。
- 用量数据是**展示态**，不落盘、不进会话文件。
- 零新依赖；前端不引入图标库，沿用内联 SVG。
- 跨平台一致；窄屏操作栏不换行、浮层不超出视口。
- 本阶段**只出原型与设计**，不改代码。

## 二、方案设计

### 2.1 总体思路

```
run 期间
  Agent onLLMStats ──SSE llm_stats──▶ messages.ts 转发时记 entry.lastContext（内存）
                                   └▶ chat-stream 更新 state.context ──▶ 各条操作栏百分比环实时刷新

会话打开 / 空闲
  ChatView ──GET /sessions/:id/context──▶ sessions.ts
                                        ├ entry.lastContext（有 → source='stats'）
                                        └ 无 → 按 entry.history 估算（source='estimate'）

点击「压缩」→ 确认框 → POST /sessions/:id/compact
  ├ entry.inFlight → 409
  └ rt.pool.withAgent(id, a => a.compactNow())
        ├ 计划无丢弃 → {ok:false, reason:'nothing_to_compact'}（不调 LLM）
        ├ flush 失败 → 按 flushFailure 策略 skip / archive
        └ 成功 → 写 L2(scope=session,tag=compaction) + 裁历史 + 落盘

点击「重试」→（中间轮次弹确认）→ POST /sessions/:id/retry { seq }
  ├ entry.inFlight → 409
  ├ 校验 history[seq] 为 assistant 且上一轮 user 可取文本 → 400
  ├ 截断：store.rewriteMessages(prefix) + entry.history = prefix 视图
  └ 以该轮 user 文本重新 run ──SSE 流──────────────────▶ 前端从 seq 处重建消息
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍 / 被否决项 |
| --- | --- | --- |
| D1 | **每条 assistant 回答下方都挂操作栏**；会话 streaming 时全部隐藏（避免与生成中状态冲突） | 否决**仅最后一条**（用户已明确要求每条）。代价：长会话视觉噪音，用 hover 才显色、默认低对比度缓解 |
| D2 | **重试 = 替换旧回答**：截断到该轮 user 之前，重新发送该 user 文本，其后的所有轮次一并删除 | 否决**追加重发**（用户已否决）。替换语义依赖 D12/D13 的锚点与确认 |
| D3 | **百分比口径 = `contextTokens / contextMaxTokens`**（最近一次 `llm_stats`，真实 usage 优先）；历史/未运行会话回退估算，浮层标「估算」 | 否决**纯前端字符估算**：与真实 `prompt_tokens` 偏差大；也否决**只显示真实值**：旧会话看不到占用 |
| D4 | **新增 `GET /sessions/:id/context`**；`llm_stats` 转发时写 `SessionEntry.lastContext`（仅内存） | 否决**每次查询重建 Agent**：池租借有成本且会干扰在跑会话 |
| D5 | **手动压缩走同步 HTTP**，前端本地 loading，不复用 SSE | 否决**为压缩单独开 SSE 流**：空闲会话没有 run 流可挂，需新增续传通道，收益不值当 |
| D6 | **强制压缩预算 = `max(floor(threshold*0.2), threshold - 固定开销)`**（与自动压缩同口径）；`droppedCount===0` → `nothing_to_compact`，不调 LLM | 否决**无条件调 LLM 生成摘要**：没有可丢弃消息时纯烧 token |
| D7 | **复制 = 该条回答纯文本段拼接**（保留 Markdown 原文，不含工具卡片） | 否决**复制渲染 HTML**：粘贴带样式垃圾；否决**复制整轮含工具输出**：体积不可控 |
| D8 | **配色阈值**：<60% 常态、60–85% 琥珀、≥85% 红 | 否决**两态**：无法提前预警 |
| D9 | **压缩按钮只放在悬浮卡片内**，不常驻操作栏 | 与参考截图一致；否决**常驻**：破坏性操作易误触 |
| D10 | **禁用条件**：`streaming`、`manualCompacting`、无 `activeId`、无用量数据 | 否决**仅按百分比判断**：低占用也允许手动精简 |
| D11 | **压缩必须二次确认**：通用确认框说明「将丢弃 N 条历史（写入 L2 可召回）」，确认后执行 | 用户明确要求。否决**直接执行**、否决**复用 hover 浮层做两步确认**（鼠标移出即消失，不可靠） |
| D12 | **重试锚点 = `ChatMsg.seq`（会话恢复视图下标）**；接口只接受 `seq` 且必须指向 assistant，后端向前找最近 user 作为重发文本 | 否决**用文本匹配定位**：重复提问无法区分；否决**只传 user 文本**：中间轮次无法定位 |
| D13 | **重试的破坏性分级**：重试**最后一条**回答直接执行；重试**中间回答**先弹确认「将删除其后 N 条消息」 | 中间重试会丢掉后续对话，必须有确认；最新一条重试等价于重新生成，无需二次确认 |
| D14 | **存储截断用新方法 `SessionStore.rewriteMessages(id, messages)`**：直接覆盖消息数组（保留 system 与被折叠归档前缀），不复用 `updateSession` 的增量/轨迹合并逻辑 | 否决**复用 `updateSession`**：其压缩轨迹重建会与「人为截断」冲突，可能把已删消息补回 |

### 2.3 参考与已知坑

- 参考形态来自用户提供的 Trae 截图：操作栏为浅灰图标组，右侧「由 AI 生成」+ 环形百分比；悬浮卡片右对齐、底部小箭头、内含单行「压缩」按钮。
- 本项目已知坑：
  1. `_lastContextTokens` 是 **run 内实例字段**，池非粘性复用时不会跨会话保留 → 必须由 API 层按 `sessionId` 记录。
  2. `getContextUsage()` 的估算基于实例 `_chatHistory`，而 API 的 `entry.history` 才是权威视图 → 估算必须基于 `entry.history`。
  3. 压缩会物理删除内存消息并落 `is_compact=true` 标记；`compactNow()` 必须复用 `persistSnapshot(true)`。
  4. 会话存储中 `is_compact=true` 的归档消息不进入恢复视图，但仍在文件里；重试截断必须按「恢复视图下标 → 存储下标」映射后**保留前缀**，不能丢归档。
  5. 前端 `messages` 是流式拼接视图（含历史 + 本轮），`ChatMsg.seq` 只对历史消息有值；重试前以服务端 `history` 为准重新对齐。

## 三、任务详细设计

### 3.1 后端：`SessionEntry` 增加内存态用量

```ts
// src/api/session-manager.ts
export interface SessionContextUsage {
  contextTokens: number;
  maxTokens: number;
  threshold: number;
  source: 'stats' | 'estimate';
  at: number;
}
export interface SessionEntry {
  history: ChatMessage[];
  inFlight: Promise<void> | null;
  lastContext?: SessionContextUsage; // 新增
}
```

### 3.2 后端：`GET /sessions/:id/context`

```ts
{
  contextTokens: number;
  maxTokens: number;   // memory.working.maxTokens
  threshold: number;   // round(maxTokens * compactionThreshold)
  percent: number;     // 0–100，1 位小数；maxTokens<=0 → 0
  source: 'stats' | 'estimate';
  updatedAt?: string;  // source='stats' 的采集时间
}
```

| 情况 | 取值 |
| --- | --- |
| `lastContext.source==='stats'` | 直接返回 |
| 无统计 | `estimateMessageTokens(entry.history) + 固定开销`，`source='estimate'` |
| 会话不存在 | 404（复用 `ensureEntry`） |
| `maxTokens<=0` | `percent=0`，不除零 |

估算复用 [working.ts](../../../src/memory/working.ts) 的 `estimateMessageTokens`（未导出则仅补 `export`）。

### 3.3 后端：`ReactAgent.compactNow()`

```ts
export interface CompactNowResult {
  ok: boolean;
  reason?: 'memory_disabled' | 'nothing_to_compact' | 'flush_failed';
  fallback?: 'skip' | 'archive';
  beforeTokens?: number;
  afterTokens?: number;
  droppedCount?: number;
  keptMessages?: number;
  contextTokens?: number;
  maxTokens?: number;
  threshold?: number;
}
async compactNow(): Promise<CompactNowResult>;
```

步骤（与自动压缩同口径）：`_workingMemory` 判空 → 取视图消息 → 算 `threshold/messageBudget` → `planCompaction`（空计划即返回）→ `persistSnapshot(true)` → `preCompactionFlush`（成功写 L2 `tag:'compaction'`；失败按 `flushFailure`）→ `compact()` 替换 `_chatHistory` → 回写 `_lastContextTokens` → 返回前后 token。

### 3.4 后端：`POST /sessions/:id/compact`

- `entry.inFlight` → `409 { code:'conflict', message:'会话正在生成，无法压缩' }`。
- 否则 `rt.pool.withAgent(id, (a) => a.compactNow())`，200 + 上述结果（`ok:false` 也是 200）。
- 登记 [api-docs.ts](../../../src/api/api-docs.ts) 与 [router.ts](../../../src/api/router.ts#L126-L142)。

### 3.5 后端：`POST /sessions/:id/retry`

```ts
// body
{ seq: number }  // 目标 assistant 在会话恢复视图（entry.history）中的下标
// 200: SSE 流（与 POST /messages 同格式）；错误：400 / 404 / 409
```

校验与流程：

1. `entry.inFlight` → 409。
2. `entry.history[seq]` 必须存在且 `role==='assistant'` → 否则 400 `invalid_target`。
3. 从 `seq` 向前找最近 `role==='user'`，取其 `show_content ?? content` 作为重发文本（含上传 contextNote 时原样重发）；找不到 → 400。
4. **视图下标 → 存储下标**：遍历 `store.getSessionMessages(id)`（含 system 与归档），统计「非 system 且 `is_compact!==true`」的可见消息，使第 `k` 条可见消息对应 `seq` 前一条 user；取该 user 在存储数组中的位置 `p`。
5. `SessionStore.rewriteMessages(id, stored.slice(0, p))`：保留 system 与前序归档，删除该 user 及之后全部消息；同步更新 `messageCount`/`title`（首条 user 被删且无更早 user 时重置标题）。
6. `entry.history = rewritten.filter(m => m.role!=='system' && m.is_compact!==true)`；`entry.lastContext` 清空（本轮将重算）。
7. 复用 `handleMessage` 的「启动 run + SSE 转发」段（抽公共函数），以第 3 步文本重新执行一轮；`sessionId` 正常注入。

`SessionStore.rewriteMessages`：

```ts
/** 直接用 messages 覆盖会话文件（仅用于重试截断；保留调用方传入的完整数组语义） */
async rewriteMessages(id: string, messages: ChatMessage[]): Promise<void>;
```

实现复用 `readSession` + `writeSessionFile`（或现有写盘私有方法），更新 `updatedAt/messageCount`，不做增量合并。

### 3.6 后端：`messages.ts` 采集 `llm_stats`

SSE 转发器外包一层：`onLLMStats(stats)` 时写 `entry.lastContext = { contextTokens, maxTokens: stats.contextMaxTokens, threshold, source:'stats', at: Date.now() }`，再原样转发（事件格式不变）。

### 3.7 前端：`chat-stream.ts`

- `SessionStreamState.context`：`{contextTokens,maxTokens,threshold,percent,source}`。
- `ChatMsg.seq?: number`：`loadHistory` 构建消息时按 `entry.history` 下标赋值（仅历史 assistant/user）；流式新增消息无 seq。
- `case 'llm_stats'`：更新 `state.context`；`refreshContext(sessionId)` 调 `GET /context`，供历史加载与压缩完成时使用。
- `resetFromSeq(seq)`：重试确认后清空 `messages` 中 `seq` 及之后（或直接整段 `loadHistory` 重建），避免旧回答残留。

### 3.8 前端：`ChatView.vue` 操作栏

每条 assistant 消息下（`v-for` 内，`v-if="m.role==='assistant' && !streaming"`）：

```
<div class="msg-actions">
  <button @click="copy(m)">复制</button>
  <button @click="retry(m)">重试</button>
  <span class="gen-hint">· 由 AI 生成</span>
  <div class="ctx-wrap" v-if="isLastAssistant(m)">   <!-- 百分比只在最后一条显示，避免重复 -->
    <button class="ctx-ring">环 + {{ pct }}%</button>
    <div class="ctx-pop">
      <div>上下文使用率</div>
      <div>{{ pct }}% of {{ fmtK(max) }}</div>
      <div>已用 … · 阈值 …（估算标记）</div>
      <button :disabled="compactDisabled" @click="askCompact">压缩</button>
    </div>
  </div>
</div>
```

> 操作栏每条都有；**百分比环只在最后一条显示**（上下文用量是会话级指标，每行都放会误导）。

交互与边界：

| 场景 | 行为 |
| --- | --- |
| 复制 | `navigator.clipboard.writeText(plainText)`；失败回退 textarea + `execCommand`；Toast「已复制」/「复制失败」 |
| 重试（最后一条） | 直接 `POST /retry {seq}`；成功后从 `seq` 重建流式消息 |
| 重试（中间条） | 先弹确认：「重试将删除该回答之后的 N 条消息，并重新生成」。取消 → 无请求 |
| 重试按钮禁用 | `streaming` / `manualCompacting` / 历史消息无 `seq` |
| 悬浮/聚焦 | 显示浮层；`mouseleave`/`blur` 关闭；右对齐 + 底部箭头；窄屏 `max-width:min(240px,80vw)` |
| 压缩点击 | 先弹确认框（D11），确认后按钮 disabled、文案「压缩中…」，消息末尾显示 `.compact-loading` |
| 压缩成功 | Toast「已压缩：丢弃 N 条，before → after tokens」；刷新百分比 |
| `nothing_to_compact` | Toast「暂无可压缩的历史（最近 N 轮会保留）」 |
| `flush_failed` | 按 fallback：`skip`→「压缩失败，已保留全部历史」；`archive`→「已降级存档后压缩」 |
| 409 | Toast「会话正在生成，请稍后再试」 |
| 无用量数据 | 环显示 `—`，浮层提示「暂无统计」 |

新增通用组件 `webui/src/components/ConfirmDialog.vue`（标题 / 说明 / 取消 / 确认，Esc 关闭，确认按钮危险色），压缩与中间重试共用。

### 3.9 演进项（本任务不做）

- 重试时保留/编辑原用户输入的草稿回填（当前直接重发原文）。
- 压缩进度 SSE 化（长会话压缩耗时可见）。
- 百分比按模型上下文窗口区分（当前用 `memory.working.maxTokens`）。
- 每条消息的分支（fork）能力。
- 移动端专用操作栏布局。
