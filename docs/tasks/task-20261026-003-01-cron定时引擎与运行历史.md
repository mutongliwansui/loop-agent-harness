## 一、任务目标需求

### 1.1 背景（痛点）

`memory.dreaming.schedule` 现状只有 `intervalHours`(24) + `startupDelayMin`(5)，语义是「启动后 5 分钟首轮、之后每 24h 一次」。这表达不了用户真正想说的「每天凌晨 3 点、我睡觉时跑」——间隔语义会随服务重启时间漂移，且无法回答「到底几点跑」。同时 `POST /memory/dream` 与定时轮的结果只沉淀一条 `lastRunAt` + `lastSummary`（每次覆盖），失败原因只进日志，用户看不到历史。

### 1.2 现状梳理

| 能力 | 现状 | 结论 |
| --- | --- | --- |
| 节奏表达 | `schedule.intervalHours / startupDelayMin` | 只能表达「每 N 小时」，无墙钟时刻 |
| 热生效 | 定时器一旦挂上不受配置变化影响 | 改 cron 必须主动重排 |
| 运行历史 | `.dreaming-state.json` 单条 `lastRunAt/lastSummary` | 无列表、无耗时、无失败原因 |
| 单次可观测字段 | `DreamRunSummary` 已含 `reason/ok/daysBack/promoted/skipped/errors/durationMs/skippedBecause` | 字段够用，只是没沉淀 |

### 1.3 任务目标

1. 新增零依赖 5 字段 cron 引擎（解析 / 下一次触发 / 中文描述），支持 `*` `,` `-` `/` 与 `@daily` 等宏。
2. 调度器支持 cron 模式：分片等待（≤6h，规避 `setTimeout` 24.8 天溢出）+ 整分对齐 + 墙钟分钟键去重（应对 DST 回拨）+ 错过补跑宽限。
3. 运行历史独立文件 `.dreaming-runs.json`（环形，默认 20 条）。
4. 4 个专用端点 + `GET /memory/status.dreaming` 扩展，保存 cron **立即生效免重启**。

### 1.4 设计约束

- 零新依赖（不引 `croner` / `cron-parser` / `node-cron`，见方案 §三 联网调研）。
- 时区一律服务器本地时区，不引 IANA 库。
- 历史文件损坏 / 不可写**绝不影响晋升主链路**。
- 旧字段 `intervalHours / startupDelayMin` 保留一版（`cron` 为空时回落）。
- 代码注释中文；不改 DreamingPipeline 提取算法与 Curated 格式。

## 二、方案设计

### 2.1 总体思路

```
配置 schedule.{cron,misfireGraceMin} ──► DreamScheduler.applySchedule()
                                            │ parseCron
                                            ▼
                             scheduleNextByCron()  delay = min(next-now, 6h)
                                            │ 到点
                                            ▼
                     onTimer()  分片?→重排 / 墙钟键重复?→重排 / late>grace?→记 missed
                                            │ 否则
                                            ▼
                          tick({catchup}) → runFor() → DreamingPipeline（不改）
                                            │ 结束
                                            ▼
                          DreamRunLog.append() → .dreaming-runs.json（环形 20）
```

## 三、任务详细设计

### 3.1 `src/api/cron.ts`（新增）

```ts
export interface CronFields {
  minute: number[]; hour: number[]; dayOfMonth: number[]; month: number[];
  dayOfWeek: number[];            // 0-6，7 已归一化为 0
  domRestricted: boolean; dowRestricted: boolean;
  expr: string;                   // 归一化后表达式（宏已展开）
}
export type ParseResult = { ok: true; fields: CronFields } | { ok: false; error: string; fieldIndex?: number };
export function parseCron(expr: string): ParseResult;
export function nextFireTime(fields: CronFields, fromMs: number): number | null;
export function nextFireTimes(fields: CronFields, fromMs: number, count: number): number[];
export function describeCron(fields: CronFields): string;
export function localMinuteKey(ms: number): string;  // 本地墙钟 YYYY-MM-DDTHH:mm
```

- 字段范围：分 0-59、时 0-23、日 1-31、月 1-12（`JAN`…）、周 0-7（`SUN`…，7→0）。
- 语法：`*` `N` `a-b` `a,b,c` `*/n` `a-b/n` `a/n`；宏 `@hourly/@daily/@weekly/@monthly/@yearly`。
- 拒绝：`L/W/#/?`、6 字段；错误文案含字段序号与期望范围。
- `nextFireTimes` 按「天 → 时 → 分」跳跃：月不匹配跳下月 1 日、日不匹配跳次日、时/分不匹配在当日候选集内挑；候选构造后**回读校验**（DST 前拨不存在的墙钟时刻自然跳过）。搜索上限 1461 天，超出返回 `null`（永不触发）。

### 3.2 `src/memory/dream-runs.ts`（新增）

```ts
export type DreamRunReason = 'schedule' | 'shutdown' | 'manual';
export type DreamRunSkipReason = 'disabled' | 'busy' | 'already-running' | 'no-runtime' | 'missed';
export interface DreamRunRecord {
  startedAt: string; finishedAt: string; durationMs: number;
  reason: DreamRunReason; catchup?: boolean; ok: boolean;
  skippedBecause?: DreamRunSkipReason;
  daysBack: number; promoted: number; skipped: number; errors: number;
  errorMessage?: string;   // 截断 200 字符
}
export class DreamRunLog {
  constructor(opts: { file: string; limit: number });
  list(limit?: number): DreamRunRecord[];   // 新→旧，容错（损坏 → []）
  append(rec: DreamRunRecord): void;        // 环形裁剪 + tmp→rename 原子写
  clear(): number;                          // 返回删除条数
}
```

同步 IO（`readFileSync/writeFileSync/renameSync`）：单文件几十 KB，避免给晋升主链路引入额外异步时序；一切异常 catch 后 `debug.log`，不抛出。

### 3.4 `src/api/dream-scheduler.ts`（改）

| 成员 | 说明 |
| --- | --- |
| `private mode: 'cron' \| 'interval'` | 由 `schedule.cron` 是否非空且可解析决定 |
| `private fields?: CronFields` | 解析结果缓存 |
| `private cronError?: string` | 解析失败原因（status 暴露） |
| `private lastFireKey?: string` | 墙钟分钟键去重 |
| `start()` | `stopped=false` → `applySchedule()` |
| `applySchedule()` | 清定时器 → 重读配置 → 按 mode 分派；`enabled:false` 置空 `nextRunAt` |
| `reschedule()` | 公开热重排入口（`PUT` 成功后调用） |
| `scheduleNextByCron()` | `next = nextFireTime(fields, now)`；`delay = min(next-now, 6h)` |
| `onTimer()` | 分片未到期 → 重排；墙钟键重复 → 重排；`late > grace` → `recordMissed()`；否则 `tick({catchup})`；结束再 `applySchedule()` |
| `statusFor()` | 追加 `cron/cronValid/cronError/describe/timezoneOffsetMin/misfireGraceMin/intervalMode/nextRunTimes` |
| `historyFor(root, limit?)` / `clearHistory(root)` | 供 handler 读写历史，路径与 limit 由 runtime 配置决定 |
| `finishSummary()/skipSummary()/recordMissed()` | 末尾 `recordHistory()`（fire-and-forget，异常静默） |

`DreamRunSummary` 追加 `catchup?: boolean`；`DreamSkipReason` 追加 `'missed'`；`runFor()` 透传 `errorMessage`（catch 到的异常 message）。

### 3.5 `src/api/handlers/memory-dream.ts`（新增）

| 端点 | 语义 |
| --- | --- |
| `PUT /memory/dream/schedule` | body `{enabled?, cron?, misfireGraceMin?}`；先校验（非法 400，**不写盘、不动现有排期**）→ 写 workspace 配置 → `scheduler.reschedule()` → `{ok, enabled, cron, describe, nextRunAt, nextRunTimes[3], misfireGraceMin}` |
| `GET /memory/dream/preview?cron=` | 只算不存 → `{ok:true, describe, next:string[5]}` / `{ok:false, error, fieldIndex}`（均 200） |
| `GET /memory/dream/history?limit=` | `{runs: DreamRunRecord[]}`（新→旧） |
| `DELETE /memory/dream/history` | `{deleted: n}` |

校验规则：`cron` 空串允许（= 回落 interval 模式）；非空必须 `parseCron` 通过且 `nextFireTimes(...,1).length>0`（否则「该表达式不会触发」）；`misfireGraceMin` 整数 0–1440；`enabled` 布尔。

### 3.6 错误与边界

| 场景 | 行为 | 用户可见 |
| --- | --- | --- |
| cron 语法错 / 越界 | 400，不写盘 | 中文错误含字段序号与范围 |
| cron 永不触发 | 400「该表达式不会触发」 | 同上 |
| 配置被外部改坏 | `applySchedule()` 回落 interval + `cronError` | status `cronValid:false` |
| 历史文件损坏 | `list()` → `[]` | 列表空态 |
| 历史写失败 | 只 debug 日志 | 无感 |
| 撞 in-flight | `skippedBecause='already-running'` 入历史 | 列表「跳过（进行中）」 |
| 休眠越过 grace | `skippedBecause='missed'` 入历史、不跑 | 列表「错过」 |
