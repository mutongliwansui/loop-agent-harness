## 一、任务目标需求

### 1.1 背景（痛点）

用户反馈「模型配置页面太丑了，重新设计下」并给出真实截图。页面 `webui/src/views/ModelsView.vue` 自 20261027-003 加入测速能力后，一直沿用最初的「技术直出」形态：页头挂 HTTP 端点徽标、主体是 7 列表格、操作列 4 个同权重文字按钮、登记表单靠 placeholder 承载字段名、版尾常驻两行长技术说明。功能齐备但可读性差，且模型数量增长后难以快速定位与比较。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| 一屏看清「谁在生效」 | 独立「当前生效」卡片 + 表格内 `active` 徽标，同一事实两处 | 需合并 |
| 承载 7 类信息（含 baseUrl/apiKey 长串） | `table.tbl` 7 列，操作列硬编码 290px | 表格必溢出 |
| 状态呈现（激活 / 连通 / 性能） | `StatusBadge` 三类混排，未测试用 warn 黄 | 需收口配色 |
| 登记入口 | 内联卡片，5 个 input 仅 placeholder | 需显式 label + 校验 |
| 图标语言 | `＋ 登记模型`、`⟳ 刷新` 字符图标 | 与项目 SVG 体系冲突 |
| 窄屏 | 无适配，表格横向溢出 | 需换行堆叠 |
| 三态（加载 / 空 / 无匹配） | 仅一行灰字「暂无登记模型」 | 需骨架与引导 |
| 可测不变量 | `.vue` 无 jsdom，纯逻辑埋在组件里 | 下沉纯函数模块 |

### 1.3 任务目标

把该页从「端点 + 表格 + 表单」改为「模型清单」：页头（标题 / 说明 / 写入位置分段 / 主操作）→ 工具行（过滤 + 计数）→ 行卡列表（生效置顶高亮 + 状态胶囊 + 图标操作）→ 折叠说明 → 右侧登记抽屉。零新增依赖与令牌。

### 1.4 设计约束

- 不改任何后端端点语义与响应结构。
- `webui/src/style.css` 令牌复用优先，新样式统一 `.mv-` 前缀，不覆盖既有全局类。
- `.vue` 内无可测逻辑：所有判定下沉 `webui/src/models-ui.ts` 并用 vitest 覆盖。
- 用户运行中的服务是 SEA 单文件版（内嵌旧 WebUI 资源），验证须另起临时端口服务，不重启用户进程。

## 二、方案设计

### 2.1 总体思路

```
GET /models ─┬─> sortActiveFirst()  ─> filterProfiles(q) ─> 行卡渲染
             │                                                 │
GET /model  ─┴─> snapshotNotice（active=null 时）              ├─ 状态胶囊 ← modelPills(test, perf)  [D4]
                                                               ├─ 操作区   ← D5/D6
GET /models/bench/history ──> perf[alias] ─────────────────────┘

添加模型 ─> 抽屉（D7）─> validateModelForm（D12）─> POST /models（scope 来自 D8）
```

### 2.2 关键设计决策

见设计方案第四节 D1–D13。实施中新增两条实测修正：

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| **D14**（实施新增） | `.pill.brand` 底色用 `--panel` 而非 `--brand-weak` | 原型用 `--brand-weak`，但产品里生效行整卡就是 `--brand-weak` 底，同色会让胶囊"消失"。改 `--panel` 后深色 `rgb(27,31,38)` / 浅色 `#fff`，与行底形成层次（CDP 实测通过） |
| **D15**（实施新增） | 窄屏 `.mv-head-acts` 用 `flex: 1 0 100%` 而非 `width: 100%` | `width:100%` 在 flex 行内被 `flex-shrink` 压窄（实测 291px / 应为 347px）；`flex-basis:100% + flex-shrink:0` 才稳定占满一行 |

### 6.4.1 线上样式事故修复（20261103-001）

**用户反馈**：重打包后「模型配置页面样式不对」，截图为页头下方一个巨大黑色放大镜，工具行被撑到约 150px，行卡与胶囊均正常。

**根因（两层）**：

| 层 | 问题 | 说明 |
| --- | --- | --- |
| ① 选择器失配 | `.mv-filter > svg` 匹配不到 | 模板是 `<span v-html="icon('search')">`，真实 DOM 为 `.mv-filter > span > svg`，`>` 直接子级跨不过 `<span>` |
| ② 无尺寸兜底（共性） | `modelIconSvg()` 只出 `viewBox`，无 `width`/`height` | SVG 尺寸 100% 依赖 CSS；一旦失配，替换元素退化为浏览器默认 **300×150** |

**为何只有这一处炸**：`style.css` 其余 17 处 SVG 规则全是后代选择器（`.pill svg`、`.mv-ico svg`、`.icon-btn svg` 等），能穿透 `<span>`；只有用了 `>` 的过滤图标中招。但根因②是共性缺陷，任何后续改动都可能重演，所以从**生成侧**兜底而非只改选择器。

**修复内容**：

- `webui/src/models-ui.ts`：`modelIconSvg(key, strokeWidth = 1.6, size = 16)` 输出内联 `width`/`height`（presentation attribute 优先级低于 CSS，既有各处 CSS 覆盖尺寸的行为完全不变），新增第三参数供大图标场合显式指定。
- `webui/src/style.css`：`.mv-filter > svg` → `.mv-filter > span`（承载 absolute 定位与 14×14）+ `.mv-filter > span svg { display:block; width:100%; height:100% }`。
- `tests/webui-models-ui.test.ts`：+2 例——每个图标恒带内联宽高、第三参数可覆盖（共 36 例）。

**验证结果**：CDP 图标尺寸回归 **13/13**——全页 28 个 SVG 全部 ≤64px（最大 16px）、过滤图标精确 14×14 / `absolute` / 落在输入框内 / 不遮挡占位文字、工具行 32px、抽屉 SVG 受控、深色主题取色 `rgb(154,161,171)` 正常、375 窄屏同样通过；视觉模型复核确认巨图消失、布局紧凑。`tsc --noEmit` 0 错误、单测 36/36、全量回归通过、`vite build` 成功。

**验证教训（已固化为常设检查）**：上一轮 34/34 全绿却漏掉此缺陷，原因是几何不变量只覆盖 `.mv-row` 内部子块，**没覆盖工具行**，也没设「全页 SVG 尺寸上限」这条与类名无关的通用断言。本轮起固定加入「扫描全页 `svg`，任一 >64px 即失败」。
