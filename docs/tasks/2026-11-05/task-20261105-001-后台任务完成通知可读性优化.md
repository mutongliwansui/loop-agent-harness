## 一、任务目标需求

### 1.1 背景（痛点）

需求 20261104-004 落地后，后台任务完成通知以 **user 角色消息**原文注入并落盘，WebUI 对话流把它当用户气泡纯文本渲染，实测界面问题（用户截图反馈）：

1. `<background_task_notification>` 伪 XML 标签整块裸显，普通用户看不懂、视觉上像「系统内部数据泄漏到聊天里」；
2. `logTail` 从 npm/vitest 彩色输出原样截取，ANSI 转义序列（`ESC[31m`、`ESC[41m` 等）在界面上显示为 `□[31m□□…` 的乱码块；
3. 这些转义序列同样进入模型上下文，浪费 token、干扰阅读（模型侧虽能容忍，但属无意义噪音）；
4. `\r` 行内覆写（进度条输出）在日志里形成「一行内多段覆盖」的长行，进一步拉长气泡。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| ANSI 剥离 | [background-notice.ts](../../../src/agent/background-notice.ts) `readLogTail`/`renderNotice`（L52-104）原样透传日志尾部，无任何净化 | 缺失，需新增 |
| `\r` 覆写收敛 | 同上，按 `\n` split 后直接截尾 | 缺失，需新增 |
| 通知消息识别 | [ChatView.vue](../../../webui/src/views/ChatView.vue)（L917-948）user 消息一律 `.bubble` + `.plain` 纯文本渲染 | 需加分支 |
| 系统通知卡片 | 无对应组件；[BackgroundTaskCard.vue](../../../webui/src/components/BackgroundTaskCard.vue) 是「任务详情卡」（轮询/停止），不适用于「一次性完成通知」 | 新建轻量组件 |
| 状态→色调映射 | [background-task-card.ts](../../../webui/src/background-task-card.ts) `statusTone/statusLabel` 输入是结构化 status 枚举；通知里是文本 `exited (exitCode=1)`/`killed（用户停止）` | 需新增文本解析版 |
| CSS 令牌 | [style.css](../../../webui/src/style.css) 已有 `--ok/--warn/--danger/--brand` 及 `-weak` 变体、`--code-bg`、`--mono`、双主题 | 直接复用，零新增令牌 |

### 1.3 任务目标

1. 后端：注入文本生成前剥离 ANSI/OSC 转义序列、收敛 `\r` 行内覆写；**标签结构与字段格式不变**（模型行为不回退）；
2. WebUI：user 消息整体为 `<background_task_notification>` 块时渲染为**系统通知卡片**（图标 + 状态 pill + command + 耗时 + 默认折叠的日志尾部），不再用用户气泡；
3. 历史已落盘的含 ANSI 通知：前端解析层兜底剥离，旧会话回看同样干净；
4. 混合文本（通知块前后有其他文字）保持原纯文本渲染，不吞用户正常消息。

### 1.4 设计约束

- 零新依赖（ANSI 剥离用正则，不引 `strip-ansi` 包）；
- 注入给模型的文本格式（标签名、字段名、字段顺序）保持不变，仅内容净化（D8）；
- 通知的注入时机、队列、去重、补投机制（004 D1-D6）不在本任务改动范围；
- 卡片样式只用现有 CSS 变量令牌，亮/暗主题自适应。

## 二、方案设计

### 2.1 总体思路

```
日志文件(含 ANSI)                       runs/<taskId>.json
     │                                       │
     ▼ readLogTail                           ▼ finish/kill
┌─────────────────────────────────────────────────────┐
│ renderNotice：① stripAnsi ② \r 覆写收敛 ③ 截尾 (D1/D2)│  ← 模型可见文本在此净化
└─────────────────────────────────────────────────────┘
     │ <background_task_notification>…</…>（结构不变 D8）
     ▼ 注入 user 消息 → 落盘 → WebUI 加载
┌─────────────────────────────────────────────────────┐
│ ChatView：整体匹配通知块？(D3)                        │
│   是 → parseBackgroundNotice（容错 D4，兜底再剥 ANSI）│
│       → BackgroundNoticeCard（D5 层级 / D6 布局）     │
│   否 → 原 .bubble 纯文本                              │
└─────────────────────────────────────────────────────┘
```

### 2.2 关键设计决策

- **D1 剥离位置在后端 `renderNotice`**（推荐）：注入模型的文本同步净化，一处改动两头受益。否决「仅 WebUI 剥离」：模型输入仍脏、token 浪费依旧。
- **D2 剥离范围 = ANSI 全序列 + `\r` 收敛**（推荐）：正则覆盖 CSI（`ESC[…字母`，颜色/光标）、OSC（`ESC]…BEL/ESC\`，标题/超链接）、单字符序列（`ESC` + `@-Z\-_`）与字符集选择（`ESC(0` 等）；`\r` 收敛按行处理——行内存在 `\r` 时取最后一个 `\r` 之后的内容（进度条最终态）。**不**清理 U+FFFD 等其他字符（可能来自日志原文，误伤风险）。截图中的 `□` 即 ESC 字符的字体缺字渲染，剥离后自然消失。
- **D3 识别方式 = user 消息整体精确匹配**（推荐）：segments 仅一个 text 段，且 `trim()` 后以 `<background_task_notification>` 开头、以 `</background_task_notification>` 结尾，才走卡片；混有任何其他文本保持纯文本。保守识别，不吞正常消息；注入侧本任务就是独立 user 消息，覆盖率无损。
- **D4 解析容错**（推荐）：逐行 `key: value` 解析头部字段（taskId/command/status/duration），`logTail:` 之后原样多行保留；`taskId` 或 `status` 缺失/格式不认识 → 整体降级纯文本；command/duration/logTail 可缺省显示「-」/隐藏日志区。前端解析时对 logTail 再执行一次 stripAnsi（历史脏数据兜底，D1 只覆盖新数据）。
- **D5 卡片信息层级**（推荐）：单行紧凑头（🔔 图标 + 「后台任务」+ 状态 pill + 耗时），第二行 command（mono、单行省略、title 悬停全文）；日志**默认折叠**为「查看日志尾部（N 行）」按钮，展开后 `pre-wrap` mono、限高 220px 内滚动。pill 三态：`已完成`（ok 绿）/ `失败（退出码 N）`（danger 红）/ `已停止`（warn 黄）；解析不出退出码显示 `已结束`（dim）。截图痛点即日志摊开，故所有状态默认折叠（不区别对待失败态，保持简单一致）。
- **D6 布局 = 系统卡片，非用户气泡**（推荐）：`.msg.user` 分支内命中通知时改渲染独占一行的系统卡（`justify-self: stretch`，max-width 与 `.msg-wrap` 内容区对齐），左侧 3px 状态色竖条 + 浅底圆角卡，不用右对齐绿色气泡。全部样式走 style.css 令牌，暗色主题自动适配。
- **D7 代码组织**（推荐）：新增 `webui/src/background-notice.ts`（parse/tone/label 纯函数，可单测）+ `webui/src/components/BackgroundNoticeCard.vue`（仅渲染与折叠交互，无轮询无定时器）；ChatView.vue 只加一个 `v-if` 分支与少量样式；**不改** `background-task-card.ts` 与 BackgroundTaskCard.vue（职责不同：详情卡 vs 通知条）。
- **D8 模型可见文本结构不变**（推荐）：标签名、字段名、字段顺序、`logTail:` 标记全部保持，仅字段值内容被净化；004 既有 7 例测试除新增 ANSI 用例外不改动断言。
- **D9 通知不进入 LLM 历史前缀**（2026-11-05 追加，用户实测反馈）：原先 `pushMessage` 把通知当普通 user 消息，导致 ① 同一 run 后续每轮请求都重复携带（llm 日志第 86 行可见通知滞留在请求中段）；② 落盘后成为历史，下一轮/重启后被当作正常历史注入；③ 被 L2 记忆注入误当作「最后一条 user 消息」，记忆前缀挂到通知上。改为：通知仍 `pushMessage` 保留在 `messages`/`transcript`（前端卡片与落盘不受影响），但构建 LLM 视图时一律剔除通知消息，**只在 drain 的那一轮作为尾部消息投递一次**；`SessionStore.getRestoreMessages` 同步过滤（含旧版被记忆前缀包裹的遗留通知）。否决「完全不落盘、仅 SSE 实时展示」：会丢失历史可见性，且需要新增事件通道与前端合并规则，改动面更大。

## 三、任务详细设计

### 3.1 后端：ANSI/`\r` 净化（`src/agent/background-notice.ts`）

```ts
// 模块级常量
const ANSI_RE = /\x1B(?:\[[0-9;?]*[ -/]*[@-~]|\][^\x07\x1B]*(?:\x07|\x1B\\)|\([0-9A-B]|[@-_])/g;

/** 剥离 ANSI 转义；行内 \r 覆写取最终态 */
export function sanitizeLogText(text: string): string;
```

- `renderNotice` 内 `logTail` 先经 `sanitizeLogText` 再做行数/字符截断（截断基于净化后文本，额度不被转义序列挤占）；
- 导出函数以便单测直接覆盖；不改 `readLogTail`（读文件逻辑不动）。

### 3.2 WebUI：解析纯函数（`webui/src/background-notice.ts`，新建）

```ts
export interface BackgroundNoticeInfo {
  taskId: string;
  command: string;      // 可 ''
  statusText: string;   // 原始 status 行，如 'exited (exitCode=1)'
  exitCode: number | null; // 从 statusText 解析；killed → null
  killed: boolean;
  durationSec: number | null;
  logTail: string;      // 已兜底 stripAnsi；可 ''
}
export function parseBackgroundNotice(text: string): BackgroundNoticeInfo | undefined;
export function noticeTone(n: BackgroundNoticeInfo): Tone;       // 复用 background-task-card.ts 的 Tone
export function noticeLabel(n: BackgroundNoticeInfo): string;    // 已完成/失败（退出码 N）/已停止/已结束
```

- `parseBackgroundNotice` 实现 D3 整体匹配 + D4 逐行容错；内部含一份与后端同源的 `stripAnsi`（webui 侧独立实现，不跨端 import）；
- `Tone` 类型从 `background-task-card.ts` import（类型复用，无运行时耦合问题）。

### 3.3 WebUI：通知卡片组件（`webui/src/components/BackgroundNoticeCard.vue`，新建）

- props：`info: BackgroundNoticeInfo`；
- 结构：`.bnc`（状态色左竖条 + `--panel` 底、`--radius-card`）→ 头行（图标 SVG + 「后台任务」+ `.pill.<tone>` + 耗时 `mm:ss`）→ command 行（mono 省略）→ 折叠区（`<button>查看日志尾部（N 行）</button>` ↔ `<pre>`）；
- 折叠状态组件内 `ref`，默认 `false`；`logTail` 为空时不渲染折叠区；
- scoped 样式，全部引用 style.css 令牌；≤720px 时头行允许换行（pill 不挤压）。

### 3.4 WebUI：ChatView 接入（`webui/src/views/ChatView.vue`，修改）

- 新增 `bgNotice(m: ChatMsg)`：`m.role==='user'` 且单 text 段时调 `parseBackgroundNotice`（结果可 `computed` 缓存按 `m.id`）；
- 模板：`v-for` 内若 `bgNotice(m)` 命中 → 渲染 `<BackgroundNoticeCard :info="…" class="notice-in-chat" />`，跳过 `.m-head`/`.bubble`；`.msg.user:has(.notice-in-chat)` 覆盖 `justify-content: flex-end` 为 `stretch`（或命中时给 `.msg` 加 `notice` class 控制）；
- 纯文本降级路径（D3 未命中/D4 降级）走原渲染，零影响。

### 3.5 错误与边界处理表

| 场景 | 行为 |
| --- | --- |
| 日志含 OSC 超链接/标题序列 | 完整剥离（D2 正则覆盖） |
| 进度条单行多次 `\r` 覆写 | 取最终态，行数统计基于收敛后 |
| 通知块缺 taskId 或 status | 整体降级纯文本（不猜） |
| 通知块缺 command/duration/logTail | 卡片渲染，对应区域省略 |
| 历史含 ANSI 的旧通知 | 前端 parse 兜底剥离，显示干净 |
| 通知块前后混入其他文字 | 不识别为通知，纯文本原样 |
| WebUI 端 strip 正则与后端漂移 | 两侧正则同形；各配单测锚定行为 |

### 3.6 通知与 LLM 历史隔离（D9，2026-11-05 追加）

- `src/types.ts` 增加 `BACKGROUND_NOTICE_OPEN/CLOSE` 与 `isBackgroundNoticeContent(content)`（容忍记忆前缀的遗留形态）；
- [react-agent.ts](../../../src/agent/react-agent.ts) 每轮：`llmMessages = messages.filter(非通知)` → 记忆组装 → 再追加本轮 `freshNotices`（仅此一轮，下一轮 drain 为空即不再出现）；
- [store.ts](../../../src/session/store.ts) `getRestoreMessages` 跳过通知消息（跨进程/下一轮恢复同样干净）；
- 前端 `parseBackgroundNotice` 兼容旧版「记忆前缀 + 通知」形态，历史脏数据仍渲染为卡片。

### 3.7 演进项（本任务不做）

- SSE 实时弹出通知（不等下一轮注入）；
- 通知卡片点击跳转任务详情/日志全文视图；
- 通知聚合（多任务同时完成合并为一条）。
