## 一、任务目标需求

### 1.1 背景

20261023-001 上线后（对话流与文件预览已支持 KaTeX 公式、```mermaid、```echarts 图表），真机实测暴露三处体验断点：

1. **渲染时机滞后**。`ChatView.vue` 的图表后处理统一入口 `postRenderMsgs()` 只在 `send()` 中 `await sendMessage(...)` **整条 SSE 流结束之后**调用一次（`ChatView.vue:407`），历史加载同理（`:352`、`:497`）。因此流式输出中，```echarts 的 JSON 报文早已闭合完整，界面上却仍是一段代码文本，必须等整条回复结束才变成图表；长回答时"图表迟到"非常明显。
2. **生成过程不友好**。流式期间 `seg.text` 逐 chunk 增长、`v-html` 整段重渲，图表源码以裸代码块一字一字刷屏（hljs 对 `language-echarts` 已跳过高亮，视觉上就是原始 JSON），极易被误读为"回复出错了 / 在输出代码"。
3. **交互缺口**。`chart-box.ts` 工具栏只有 放大 `＋` / 缩小 `－` / 适应宽度 `100%` / 全屏 `⛶`，缺「预览 ⇄ 源代码」切换。用户想复制图表源码、微调参数后重发、或排查"为什么没渲染出来"时，无任何入口（渲染成功后源码 DOM 已被替换，历史不可见）。

### 1.3 任务目标

1. **流式增量渲染**：对话流文本段改为「稳定块 + 可变尾部」结构，```mermaid / ```echarts 围栏**闭合即渲染**，且后续 chunk 到来时已渲染图表**不被销毁重建**（无闪烁、无实例泄漏、缩放状态保留）。
2. **生成中 loading 占位**：围栏已开头未闭合期间，该处显示「正在生成 mermaid/echarts 图表…」占位，不再裸刷源码。
3. **源码/预览切换**：chart-box 工具栏新增切换按钮，源码态显示原始 mermaid/JSON 文本（可选中复制），切回预览不重建实例。
4. FilesView md 预览复用同一渲染路径，自动获得上述能力；渲染失败仍保留代码块标红降级。

### 1.4 设计约束

- **不替换现有渲染管线**：marked + DOMPurify + hljs + KaTeX 与自研 chart-box 保持不变，只改「何时渲、渲到哪、怎样不被覆盖」。
- **不破坏 Vue 管理的 DOM**：禁止对流式渲染中的 Vue 元素做 `replaceWith`/`remove`（会与 vnode 失联），改用"槽位内 append"。
- **零新增依赖**：不引入流式 markdown 第三方库。
- **安全基线不动**：DOMPurify 仍在 `renderMarkdown` 末尾统一消毒；图表仍只接受 JSON 声明式 option。
- 缩进/引用块内的围栏不参与流式渲染（保守切分，避免破坏 markdown 上下文语义）。

## 二、方案设计

### 2.1 总体思路

```
一条 assistant 消息的 segments（text 段逐 chunk 增长）
   │
   ▼  stream-blocks.ts（新增，纯逻辑）
splitStreamBlocks(text, {streaming, isTail})
   │  按【顶层】围栏边界保守切分（D2）
   ├─ md 块      { kind:'md',    k, html }   → html 由 renderMarkdown 生成并缓存（D8）
   ├─ 图表块    { kind:'chart', k, lang, src } → 渲染为空槽位 div（D3）
   └─ 待完成块  { kind:'pending', k, lang, partial } → 仅当 streaming && isTail（D5）
   │
   ▼  ChatView / FilesView 模板（D1）
<div class="md">
  <template v-for="blk in blocks" :key="blk.k">
    <div v-if="blk.kind==='md'" v-html="blk.html"></div>          ← Vue 管理
    <div v-else-if="blk.kind==='chart'" class="chart-slot"
         :data-lang="blk.lang" :data-src="blk.src"></div>          ← 空元素，Vue 不碰内部
    <div v-else class="chart-pending">⟳ 正在生成图表…</div>
  </template>
</div>
   │  稳定 key → 已渲染块 DOM 原地保留，仅尾部重渲（D1）
   ▼  postRenderMsgs()（流式节流调用 + 结束时全量，D4）
扫描 .chart-slot:not([data-done]) → renderMermaidIn / renderEChartsIn
   │  渲染成功：slot.appendChild(box.el) + data-done（D3，不 replaceWith）
   │  渲染失败：slot 内 append <pre><code class="language-x xxx-err"> 源码标红（D7）
   ▼
chart-box.ts 工具栏（D6）
  ＋ － 100% ⛶ ｜ </> 源码/预览切换 → .mmd-view ⇄ .mmd-source（不 dispose 实例）
```

### 2.2 关键设计决策

- **D1 采用「稳定块 + 可变尾部」增量渲染，替换单元素 `v-html`**
  把文本段按围栏边界切成块数组用 `v-for` 渲染，`key = 块序号 + 内容指纹`：内容未变的块 Vue 复用 DOM 且 props 相同不再赋值 `innerHTML`，故**文本段内手动 append 的图表容器得以原地保留**；每次 chunk 只重渲尾部块。
  否决 ①「整段 `v-html` + 节流重渲全部图表」：每次 chunk 都会销毁重建图表，造成闪烁、echarts `dispose/init` 抖动、缩放与滚动位置丢失，正是当前"只能等流结束"的根因；否决 ②「引入 markstream-vue / vue-stream-markdown / incremark-renderer」：会替换 marked+DOMPurify+hljs+KaTeX 整条管线，丢掉 20261023-001 的 DOMPurify MathML 白名单结论与自研 chart-box 交互，回归面与依赖面都过大。
  依据：业界流式 markdown 渲染的通行范式即 "stable blocks + mutable tail，unchanged blocks remain mounted"（incremark-renderer / @copse/streaming-markdown / markstream-vue 均如此描述：只 patch 已稳定块与尾部，避免整篇重渲）。

- **D2 切分边界保守：只在「顶层围栏」处切**
  仅当 ```` ```mermaid ```` / ```` ```echarts ```` 起始行**行首无缩进**（不属于列表项/引用块/嵌套代码）时才作为切分点；块级别结构不跨围栏，切分不改语义。
  缩进或引用内的围栏不切分，留在 md 块里由 marked 正常渲染为代码块，流式期间**不**做图表渲染（流结束后同样不特殊处理），记入演进项。

- **D3 图表块渲染成"空槽位 + `data-src`"，渲染时 `append` 而不替换元素**
  槽位 `<div class="chart-slot" data-lang data-src>`：`data-src` 用 `setAttribute` 语义写入（Vue 自动转义 `"`/`<`/`&`，`getAttribute` 原样还原，含换行安全）。渲染时 `slot.appendChild(box.el)` 并打 `data-done`，**绝不 `replaceWith`/`remove` Vue 管理的槽位**（否则 vnode.el 与真实 DOM 失联，下次 patch 会异常）。
  否决 ①「模块级 `Map<hash, code>` 传源码」：需配清理策略、且 hash 碰撞即静默错配；否决 ②「按 DOM 顺序配对」：槽位渲染后已非 `.chart-slot`，顺序配对必然错位。
  代价：HTML 体积随 option 增大（长 option 数十 KB），记入演进项（必要时改 `ref` 传递）。

- **D4 流式触发：watch 文本长度 + 节流合并 + 幂等标记**
  ChatView 以「当前会话消息文本总长度」为信号（长度变化必意味着有新 chunk），节流 300ms 触发 `postRenderMsgs()`；尾块内的图表**首次闭合立即渲**（不等待下一次节流窗口：哨兵值判断）。
  幂等：`data-done` 跳过已渲槽位；失败块打 `xxx-err` 且在扫描时排除，避免每个 tick 重复失败重渲。历史加载与结束仍走一次全量后处理（兜底）。

- **D5 待完成围栏显示 loading 占位**
  仅当 `streaming` 且该文本段是消息的**最后一个 segment** 时，把末尾已开头未闭合的图表围栏渲染为 `<div class="chart-pending">⟳ 正在生成 mermaid/echarts 图表…</div>`（可附已生成字符数）；其前的 md 部分正常渲染。
  流被停止（`aborted`）/失败/结束后 `streaming=false`，pending 消失，该处回退为普通代码块（marked 对未闭合围栏按代码块处理），源码可见可复制。

- **D6 源码/预览切换由 chart-box 承载，切换不重建实例**
  `buildChartBox(content, caption, source?)` 增第三参数；传入 `source` 时工具栏追加 `</>` 按钮。切换仅切 `.mmd-view` / `.mmd-source` 的 `display`，**不 dispose** echarts 实例；切回预览时调 `fit()` 并触发 `resizers`（`chart.resize()`），避免隐藏期间 `clientWidth=0` 导致的错误尺寸。源码态禁用缩放类按钮（`＋/－/100%/⛶`）。
  源码区为等宽 `pre`（可横向滚动、`max-height` 限高），不接 hljs（避免额外开销），记入演进项。

- **D7 失败降级改为"槽位内保留源码"，不再依赖 `pre.replaceWith`**
  JSON 非法 / mermaid 解析失败：在槽位内 `append` 一个 `<pre><code class="language-xxx xxx-err">` 承载源码并标红。相比现状的"保留原代码块"，语义等价且与 D3 的"不替换 Vue 元素"约束一致。
  mermaid / echarts 动态 import 失败：现状是"静默保留代码块"，改为同样落源码（否则槽位空白，用户以为内容丢了）。

- **D8 md 块 HTML 缓存**
  切分函数内部即调用 `renderMarkdown(text)` 生成 `html` 并做文本→HTML 的 LRU 缓存（上限 50 条），避免"每个 chunk 把前面所有 md 块重新 marked+DOMPurify 解析一遍"。这是 D1 拆分后新增的必要优化（原实现每 chunk 只解析整段一次）。

- **D9 FilesView 复用同一渲染路径**
  md 预览也走 `splitStreamBlocks(text, { streaming:false })` + 同一块渲染模板（`streaming:false` 时无 pending 分支），两视图逻辑不分叉；`pre > code.language-xxx` 旧扫描路径保留为兼容兜底（一旦某处仍输出代码块形态）。

- **D10 测试策略**
  纯逻辑抽为可导出纯函数放主工程 `tests/`：`splitStreamBlocks`（围栏闭合/未闭合/多图表/缩进围栏/无围栏/内容指纹稳定性）、`data-src` 转义与还原、pending 判定、md 缓存命中。DOM 交互（渲染、切换、节流）列入人工验证清单，不引入 jsdom。

## 三、任务详细设计

### 3.1 `webui/src/stream-blocks.ts`（新建，纯逻辑）

```ts
export interface MdBlock    { kind:'md';      k:string; text:string; html:string }
export interface ChartBlock { kind:'chart';   k:string; lang:'mermaid'|'echarts'; src:string }
export interface PendingBlock { kind:'pending'; k:string; lang:'mermaid'|'echarts'; partial:string; chars:number }
export type Block = MdBlock | ChartBlock | PendingBlock;

export interface SplitOptions { streaming?: boolean; isTail?: boolean }

/** 把文本段切分为稳定块序列；k = 块序号 + ':' + 内容指纹（D1） */
export function splitStreamBlocks(text: string, opts?: SplitOptions): Block[];

/** 内容指纹（djb2 + 长度），供 key 稳定与 md 缓存使用（导出供单测） */
export function contentKey(s: string): string;

/** md 渲染缓存（LRU 50）：splitStreamBlocks 内部使用（D8） */
```

切分规则：
1. 逐行扫描，维护"是否在顶层围栏内"状态；仅行首无缩进且以 ```` ```mermaid ```` / ```` ```echarts ```` 开头的行进入候选。
2. 遇到同语言闭合围栏 → 产出一个 `chart` 块（`src` 为围栏内原始文本，原样保留换行）。
3. 扫描至结尾仍未闭合 → 若 `streaming && isTail` 产出 `pending` 块；否则整体并入 md 块。
4. 其余连续文本合并为一个 `md` 块，内部调用 `renderMarkdown` 得到 `html`（走 D8 缓存）。
5. 空文本 → 返回 `[]`（模板不渲染空块）。

### 3.3 mermaid.ts / echarts.ts（渲染入口扩展）

```ts
// 统一"取待渲染项"：槽位优先，兼容旧代码块形态
interface ChartTarget {
  el: HTMLElement;            // 挂载点：槽位本身 or 旧 pre
  lang: 'mermaid' | 'echarts';
  src: string;
  legacy: boolean;            // true：旧 pre>code 路径（渲染后 replaceWith 仍可用，因其非 Vue 管理）
}
function collectTargets(root: HTMLElement): ChartTarget[];
```

- **槽位路径**：`slot.appendChild(box.el)` → `slot.dataset.done = '1'`；失败 → slot 内 append `<pre><code class="language-x xxx-err">`，并置 `data-done`（同时排除 err 重试，D4）。
- **兼容路径**：沿用现有 `pre.replaceWith(box.el)`，仅用于 FilesView 旧分支或未来其他调用点。
- 扫描选择器加排除：`.chart-slot:not([data-done])`、`pre:not(.mermaid-err):not(.echarts-err) > code.language-x`。
- echarts 尺寸计算与 `onResize` 接线不变；`rendered` Map 的孤儿清理逻辑保留（槽位被 Vue 移除时 `host.isConnected === false` → dispose）。

- md 预览的 `mdHtml` 由「整段 v-html」改为与 ChatView 相同的块渲染（`streaming:false`，无 pending 分支）；`highlightIn` 仅对源码模式与 doc 分支保留。
- 切回预览（`:1049`）仍调用两个 render 函数，走槽位路径。

### 3.7 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| 围栏已闭合，流仍在继续 | 立即渲染；后续 chunk 只重渲尾部，图表 DOM 不被触碰（D1） |
| 围栏未闭合 | 显示 `chart-pending` 占位，不裸刷源码（D5） |
| 流被停止 / 失败 / 结束 | pending 消失，回退代码块形态，源码可见可复制 |
| mermaid 解析失败 / echarts JSON 非法 | 槽位内保留源码并标红（`.mermaid-err` / `.echarts-err`），不参与重试（D7） |
| mermaid / echarts 动态 import 失败 | 同上落源码，避免槽位空白（D7 修订现状"静默保留"） |
| 同一消息多图表 | 切分天然产生多个槽位，按序渲染；共享串行队列 |
| 缩进 / 引用块内围栏 | 不切分、不流式渲染（D2，演进项） |
| 内容被整体替换（非追加） | `key` 含内容指纹 → 该块 Vue 重建，不残留旧图表 |
| 会话切换 / 视图卸载 | 槽位脱离文档 → `rendered` Map 孤儿清理 dispose（现状逻辑） |
| 超长 option（>50KB） | `data-src` 属性体积偏大，记入演进项（必要时改 ref 传递） |

### 3.8 实施偏差记录（相对 3.1~3.6 的落地差异）

| 项 | 设计 | 落地 | 原因 |
| --- | --- | --- | --- |
| 目标收集 | 抽 `collectTargets()` 统一抽象 | `mermaid.ts` / `echarts.ts` 各自内联两段循环（槽位路径 + optional legacy） | 两语言失败降级文案/类名不同，抽取反而增加间接层；各自 20 行内可读性更好 |
| 兼容路径 | "保留 `pre > code` 兼容" | 改为 `renderXxxIn(root, { legacy?: boolean })`，**默认关闭** | 默认开启会在 FilesView/ChatView 的 Vue 管理 DOM 上做 `replaceWith`，与 D3 结论冲突；仅显式传入时才走旧路径 |
| `pending` 块 key | 序号 + 内容指纹 | 仅 `p<序号>:<lang>`（不含指纹） | 含指纹时每个 chunk key 都变 → Vue 重建占位 div → `cp-spin` 动画每次从头播放（看起来像卡住）；占位内无状态，复用 DOM 只更新字符数更合适 |
| 图表 `src` 换行 | 原样保留 | 统一剔除行尾 `\r`（CRLF → LF） | `\r` 会进入 `data-src` 并传给 mermaid / `JSON.parse`，无收益且是不必要的噪声源 |
| `.md` 首尾样式 | "CSS 为后代选择器，不受影响" | `.md :first-child/:last-child` 收窄为 `.md > .md-blk:first-child :deep(:first-child)` 等 | 分块后每条规则命中每个块的首尾元素，块间 margin 被清零导致段落粘连；块 div 无 padding/border，子元素 margin 仍可正常 collapse 穿过块边界 |
| 触发节流 | 长度 watch + 300ms 节流 | 追加 `FENCE_TAIL_RE` 快速预判 | 避免每个 chunk 都对尾段做一次完整切分（含 md 渲染），只在"文本以围栏行结尾"时才深入判断 |
| `.chart-pending` 外观 | 实底 `--code-bg` 圆角块 | 虚线边框 + 转圈 spinner + 右侧字符数 | 实底占位在流式中反复出现/消失时视觉跳动明显；虚线边框更轻，且字符数让"仍在推进"可感知 |
