## 一、任务目标需求

### 1.1 背景（痛点）

WebUI 对话流里，`commandRun({background:true})` 的结果目前只是一段 JSON 文本（`{taskId,pid,logPath}`）。用户看不到任务是否还在跑、退出码是多少、最近输出了什么，只能让 Agent 调 `commandStatus`/`commandLogs`，又把本可直接展示的状态塞回了对话上下文。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
| --- | --- | --- |
| 工具卡片渲染 | [ToolCard.vue](../../../webui/src/components/ToolCard.vue) 已有头部 + 参数表 + 结果区，`commandRun` 在 [tool-meta.ts](../../../webui/src/tool-meta.ts#L219) 已有中文名/图标/摘要 | 复用卡片骨架，结果区特殊化为任务卡 |
| 后台任务数据 | 后端 `BackgroundTaskRegistry` 已有 `get/list/log/stop` | 需新增只读 HTTP 端点供前端轮询 |
| API 路由 | [router.ts](../../../src/api/router.ts) 60+ 条，按 `createRoutes()` 组装 | 新增 `/api/background/*` 三条，不动既有路由 |
| SSE 事件 | 会话流 `GET /sessions/:id/stream` 只承载 Agent 事件 | 卡片不占用主事件流（见 D1） |
| 状态持久化 | `~/.loop-agent/runs/{taskId}.json` 保存状态/退出码；会话历史保存工具结果 JSON | 历史重载可从工具结果恢复卡片 |
| 视觉体系 | 线性 SVG 图标 + `.badge/.pill` 令牌 + 亮暗主题 | 零新增令牌，状态色复用 `--ok/--warn/--danger` |

### 1.3 任务目标

在对话流中把后台 `commandRun` 结果渲染为卡片：

1. 头部：图标 + 命令（单行截断，`title` 全文）+ 状态 pill（运行中/成功/失败/已停止/失联）。
2. 摘要行：taskId、耗时、退出码、日志大小；运行中显示动态耗时。
3. 日志区：默认收起，展开显示最后 20 行（等宽字体、可滚动、自动到底）；运行中每 2s 刷新。
4. 操作：运行中显示「停止」按钮（二次确认），结束态显示「查看完整日志」入口。
5. 状态收敛：终态后停止轮询；页面刷新/会话重载后卡片按工具结果 JSON 直接渲染，不丢卡片。
6. 适配亮/暗主题与 ≤720px 窄屏。

### 1.4 设计约束

- 不改变 `commandRun` 工具结果 JSON 结构。
- 不新增 npm 依赖；不新增 CSS 令牌。
- 轮询必须可停止、可并发安全（同一 taskId 单飞）；页面后台标签页降频。
- 不干扰 ToolCard 其余工具（含 MCP）的渲染路径。
- 所有请求沿用既有 token 鉴权。

## 二、方案设计

### 2.1 总体思路

```
会话历史/实时流
  └─ tool result (commandRun background) ──解析 taskId──▶ BackgroundTaskCard.vue
                                                              │
                         ┌────────────────────────────────────┼───────────────────────┐
                         ▼                                    ▼                       ▼
              初始快照（来自 result JSON）          轮询 GET /api/background/:id   展开时 GET /api/background/:id/logs?tail=1
                         │                          （running 时 2s，终态停）             │
                         └──────────────▶ 状态 pill / 耗时 / 退出码 ◀─────────────────────┘
                                                              │
                                                      停止 → POST /api/background/:id/stop
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍 / 被否决项 |
| --- | --- | --- |
| D1 | **前端轮询**（运行中 2s，页面隐藏时 15s），不使用 SSE 推送 | 否决 SSE：需给会话流加新事件类型并处理多标签页回放，改动大于收益；轮询只在卡片可见且运行中发生 |
| D2 | **识别方式 = 解析工具结果 JSON 的 `taskId`**，不改工具返回 | 否决新增 `toolKind` 字段：会让历史结果格式分叉；否决按参数 `background:true` 判断：停止后仍要能看结果 |
| D3 | 卡片作为 ToolCard 的**结果区替换**，不新开消息气泡 | 否决独立消息：会打乱「一次工具调用 = 一张卡」的现有流 |
| D4 | 终态停止轮询；`running` 每 2s，`orphaned-*` 每 10s | 否决固定 2s 全生命周期：浪费请求 |
| D5 | 日志默认收起，展开取 `tail`（最后 2KB/20 行） | 否决默认展开：长日志撑高对话流；否决全量下载：频繁且无必要 |
| D6 | 停止按钮放在卡片右上角，二次确认复用既有 ConfirmButton | 否决无确认直接停：误点会杀长任务 |
| D7 | 新增后端端点 `GET /api/background/:taskId`、`GET .../logs`、`POST .../stop` | 否决复用 `/sessions/:id`：后台任务是进程级、不绑会话路径；端点仍走统一 token 鉴权 |
| D8 | 会话历史重载时按工具结果静态渲染，**不主动补拉**；仅在 running 时启动轮询 | 否决重载即全量刷新：历史卡过多会放大请求 |

### 2.3 联网检索结论

- 主流 IDE Agent（Cursor/VS Code Copilot）的后台任务卡均采用「状态 pill + 可展开终端输出 + 停止按钮」三件套，默认收起日志，符合本方案。
- 已知坑：轮询在页面隐藏/多标签页时并发叠加，需 `visibilitychange` 降频 + 单飞；终态后必须清理 timer，否则内存泄漏。
- 来源：VS Code Task API 文档、Cursor 后台任务交互说明（2026-11 检索）。

## 三、任务详细设计

### 3.1 组件契约

```ts
// webui/src/components/BackgroundTaskCard.vue
props: {
  taskId: string;
  command: string;
  initial?: { status: string; exitCode?: number | null; startedAt?: number; finishedAt?: number };
}
state: { status, exitCode, durationMs, logTail, expanded, polling, error }
```

暴露纯函数便于单测：

```ts
parseBackgroundResult(resultJson: string): { taskId, command, startedAt } | undefined
statusTone(status): 'run' | 'ok' | 'warn' | 'danger' | 'dim'
pollDelay(status, hidden: boolean): number
```

### 3.2 后端端点

| 方法 | 路径 | 响应 |
| --- | --- | --- |
| GET | `/api/background/:taskId` | `{ taskId, command, status, exitCode, startedAt, finishedAt, durationMs, logSize, cursor }` |
| GET | `/api/background/:taskId/logs?tail=1` | `{ taskId, tail: string, size, truncated }` |
| POST | `/api/background/:taskId/stop` | `{ taskId, stopped: boolean, alreadyStopped: boolean }`（幂等，参考 commandStop） |

任务不存在：`404`；日志已清理：`200 + tail:"" + cleaned:true`；非回环无 token：沿用既有 401 语义。

### 3.3 状态映射

| status | pill 文案 | 色调 | 轮询 |
| --- | --- | --- | --- |
| `running` | 运行中 | 品牌色 | 2s |
| `exited` exitCode=0 | 已完成 | ok | 停 |
| `exited` exitCode≠0 | 失败（退出码 N） | danger | 停 |
| `killed` | 已停止 | warn | 停 |
| `orphaned-running` | 失联（可能仍在运行） | warn | 10s |
| `orphaned-exited` | 失联（已结束） | dim | 停 |

### 3.4 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| 结果 JSON 非法/无 taskId | 回退为普通文本结果区，绝不报错 |
| 轮询 404（日志被清理/任务丢失） | 卡片转「记录已清理」dim 态，停止轮询 |
| 停止请求失败 | 按钮恢复可点，显示一行行内错误 |
| 同时展开多个卡片 | 各卡独立 timer，同 taskId 单飞 |
| 页面隐藏 | 轮询间隔 15s，恢复可见立即拉一次 |
| 亮/暗主题切换 | 全部使用 CSS 变量，无硬编码颜色 |

### 3.5 演进项（本任务不做）

- 终端式全屏日志（复用预览区终端）。
- 任务完成桌面通知/铃铛。
- 按 taskId 跨会话检索任务卡。
