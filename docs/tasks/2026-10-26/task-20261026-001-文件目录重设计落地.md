## 一、任务目标需求

### 1.1 背景（痛点）

对话右侧「工作空间文件目录」面板是 WebUI 中使用频次最高的常驻区域之一（`ChatView` 默认 `filesOpen = true`），但它仍是早期「功能直出」形态，与已经完成重设计的工具调用卡片（20261024-001）、图表容器（20261023-003）在设计语言上明显脱节：

| # | 症状 | 实测 |
| --- | --- | --- |
| 1 | 头部三行堆叠 | 搜索行 + 常驻复选框行（隐藏目录 / 自动刷新）+「＋目录 / ↑文件 / ↑目录」按钮行 ≈ **115px**，在 264px 宽面板里吃掉近 1/5 可列表高度 |

### 1.3 任务目标

按原型 v2 重做 `.files-side`（右栏目录）的**视觉与交互**，让它与已重设计的工具卡片、图表容器共用同一套设计语言；布局位置、后端端点、props 契约全部不动。

验收口径：在 1600×1000 与 264/204/320px 三种面板宽度下，头部**≤64px**、树行 26px、四层缩进有引导线、选中行有 3px 色条、搜索按文件分组并高亮、四态齐备、窄面板占位不截断。

### 1.4 设计约束

1. **位置不动**：`.files-viewer` 在左、`.files-side` 在右（实测 663 / 5 / 240@1600 视口），本次只重做右栏内部。
2. **零新增依赖**：图标一律内联 SVG（跟随 `currentColor`），不引 icon 库；不使用 `@vueuse` 等工具库。
3. **零新增全局令牌**：颜色全部取自 `style.css` 现有令牌，组件内不硬编码色值（`mark` 复用 `--warn-weak`）。
4. **后端零改动**：`/fs/tree`、`/fs/search`、`/fs/fingerprint` 等端点契约不变，`FsNode` / `SearchResult` 字段不变。
5. **props 契约不变**：`FilesView` 仍只接收 `wsPath: string` + `v-model:open`，`ChatView` 不改。
6. **功能不倒退**：现有 12 项能力（懒加载展开、自动刷新轮询、隐藏项、上传文件 / 上传目录、新建目录、重命名 / 移动、下载（含目录 zip）、删除、右键菜单、拖拽上传、文件内搜索、面板与内部分割条拖拽）必须全部保留。
7. **跨平台**：路径分隔统一用 `/`（后端已归一），不引入 `\\` 假设。
8. **深浅主题**：所有颜色走令牌，`prefers-color-scheme` 与强制暗色两套都要可读。

### 2.2 关键设计决策

> 以下每条为一句可确认的判断。**推荐项加粗**，括号内为被否决项；用户逐条确认后进入实施。

**D1 · 面板位置与宽度**
沿用「预览左 / 目录右」不动；目录默认宽 **240 → 264px**，可拖最小值 **160 → 204px**，上限仍为 `min(420, 总宽 − 320)`。
（否决：改为目录在左——与现状不符且预览是主区；否决：保持 240——原型 note 02 已定为 264，且 264px 才能容下「搜索框 + 3 个 26px 图标按钮」不换行）

**D2 · 头部三行合一行**
搜索框（放大镜图标 + `Ctrl K` 聚焦）与三个 26px 图标按钮同排：`＋ 新建目录`、`↑ 上传`、`↻ 刷新`。原「↑文件 / ↑目录」两个入口**合并为一个「↑ 上传」按钮，点击弹二级小菜单**（上传文件 / 上传文件夹），复用现有 `.fs-menu` 组件。
（否决：并排放 4 个图标按钮——264px 内搜索框会被压到 <120px；否决：去掉上传入口——功能倒退）

**D3 · 树行视觉重写**
emoji + 字符三角 → **内联 SVG**：目录 `folder`（`--brand`）、文件 `file`（`--muted`），twisty 用 `chevron` 并 `rotate(90deg)` 表示展开；行高 **26px**、缩进 **14px**、层级用 `--line-strong` 画 1px 引导线；选中行加 **3px 左侧色条**（`--brand`）+ 名称 `600`；目录名 `500` / 文件名 `400`。
（否决：保留 emoji——彩色图标无法跟随主题，且与项目 SVG 体系冲突；否决：按扩展名给图标上色——原型 note 04 明确「绿底里蹦出紫红蓝」，只留两档）

**D4 · 行内操作收敛**
每行只留 **2 个高频动作 + `⋯`**：目录 = `＋`（新建子目录）/ `↑`（上传到此）/ `⋯`；文件 = `⤓`（下载）/ `✎`（重命名）/ `⋯`。`⋯` 复用右键菜单（同一份 `openMenu()`，删除等危险项只在菜单里）。
（否决：保留 4 个直排——正是当前挤爆文件名的原因；否决：全部收进 `⋯`——下载/重命名是高频，多一次点击不划算）

**D5 · meta 口径**
**目录显示已加载子项数**（未展开时无数据则不显示）；**文件保留大小显示**，并在 hover / focus 时淡出让位给操作按钮。
（否决：完全照原型去掉文件大小——现网已有该信息，去掉属功能倒退；否决：目录显示「项」字后缀——264px 太挤，纯数字即可）

**D6 · 搜索结果结构化**
平铺列表 → **按文件分组**：顶部「N 处命中 · M 个文件」+ 清除；每组一行文件头（文件图标 + 目录灰字 + 文件名粗体 + 命中数徽标），组内命中行行号右对齐 + **关键词 `<mark>` 高亮**（`--warn-weak` 底）。
（否决：保持平铺——一行里路径与正文混排，多命中时无法扫读；否决：后端改成分组返回——后端零改动是本次约束）

**D7 · 四态齐备**
骨架屏（12 行 shimmer，按 `--row-h` 节奏）、空态卡片（图标 + 「没有匹配的文件」+ 说明 + 清除按钮）、错误态卡片（⚠ + 原因 + 重试按钮）、拖拽浮层（整块虚线覆盖 + 「松开即上传 / 目标：<路径>」）。
（否决：只做空态——加载与错误是当前最容易被误读为「卡住了」的两态）

**D8 · 底部状态条**
新增 30px 状态条：左侧 **项数**（「N 项」，搜索态显示命中数）、中间 **隐藏项开关**（视觉开关，`role="switch"`，逻辑复用 `showHidden`）、右侧 **自动刷新指示灯**（`--ok` 呼吸点）。
**自动刷新保留可点切换**（关闭时点变灰、`localStorage` 仍持久化）；上传中状态条左侧改显 `上传 3/10`。
（否决：自动刷新改为纯指示灯不可点——会丢掉现有「临时关掉轮询」的能力；否决：状态条再加密度切换——264px 内三组控件会挤，见 D9）

**D9 · 面包屑与密度**
新增面包屑（根名 › … › 当前目录）仅显示**选中文件所在目录链**，点击某段 = 展开该目录并滚动定位；未选中文件时只显示根名。
**暂不提供密度切换 UI**（固定 26px 紧凑档），但 CSS 保留 `[data-density="cozy"] → 30px` 钩子以便后续开启。
（否决：本期就做密度切换按钮——底部状态条已 3 组控件，再加会溢出；否决：不做面包屑——深目录定位是实际痛点，且纯函数 `crumbOf` 成本低）

**D10 · 令牌映射与依赖**
**零新增全局令牌、零新增依赖**。原型变量按 1:1 映射到 `style.css` 现有令牌：

| `--panel-2` | `--bar-bg` | 状态条底色，取同值 |
| `--guide` | `--line-strong` | 引导线（`#d3d8de` / `#3a424d`，与原型同值） |
| `--mark` | `--warn-weak` | 搜索高亮底，同值复用 |

## 三、任务详细设计

### 3.1 新建 `webui/src/fs-tree.ts`（纯函数，可单测）

```ts
/** 与后端 /fs/tree 一致的节点结构（由 FilesView 内联接口迁出并导出） */
export interface FsNode {
  name: string;
  path: string;      // 相对工作空间，'/'-分隔，根为 ''
  type: 'dir' | 'file';
  size?: number;
  children?: FsNode[];
}

/** 与后端 /fs/search 一致的命中结构 */
export interface SearchResult {
  path: string;
  name: string;
  line: number;
  text: string;
}

/** 树行：depth 用于缩进，guides 为各层是否续画的位图（true = 该层需画引导线） */
export interface FsRow {
  node: FsNode;
  depth: number;
  guides: boolean[];
}

/** 摊平展开中的树；guides[k] = 第 k 层祖先是否还有后续兄弟 */
export function flattenRows(tree: FsNode[], expanded: ReadonlySet<string>): FsRow[];

/** 搜索结果按文件分组；组按 path 首次出现顺序，组内按 line 升序 */
export interface HitGroup {
  path: string;
  dir: string;    // 'docs/tasks/'，根级文件为 ''
  name: string;   // 文件名
  hits: SearchResult[];
}
export function groupHits(results: SearchResult[]): HitGroup[];

/** 关键词高亮切片（大小写不敏感匹配，保留原文大小写） */
export interface HiPart { t: string; hit: boolean }
export function highlightParts(text: string, kw: string): HiPart[];

/** 面包屑：根标签 + 选中文件所在目录链；每段带可点击的相对路径 */
export interface Crumb { label: string; path: string }
export function crumbOf(filePath: string, rootLabel: string): Crumb[];

/** 字节格式化（自 FilesView L1190 迁入） */
export function fmtBytes(n: number): string;
```

### 3.2 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| `flattenRows` 遇未展开目录 | 只出该目录行，不递归；`guides` 长度 = `depth` |
| `flattenRows` 空树 | 返回 `[]`，由空态卡片接管渲染 |
| `highlightParts` 空 / 全空白关键词 | 返回 `[{ t: text, hit: false }]`，不产生空切片 |
| `highlightParts` 关键词长于文本 | 单段非命中，不抛错 |
| `highlightParts` 文本含正则元字符 | 用 `indexOf` 而非 `RegExp`，天然安全 |
| `groupHits` 收到重复 `path+line` | 保留全部（后端可能同文件多行命中同文本），不去重 |
| `groupHits` 根级文件（path 无 `/`） | `dir = ''`，前端渲染时不显示目录段 |
| `crumbOf` 未选中文件（`filePath=''`） | 返回 `[{ label: rootLabel, path: '' }]` |
| `crumbOf` 路径超过 3 层 | 全部返回，前端用 `max-width:96px` + ellipsis 截断（原型一致） |
| `/fs/tree` 请求失败 | `treeError` 非空 → 错误态卡片 + 「重试」按钮（调 `loadTree()`） |
| 搜索无命中 | 空态卡片 + 「清除搜索」（调 `clearSearch()`） |
| 上传中切换会话 | `uploading` 归零、进度线淡出（沿用现有 `afterMutation` 收口） |
| 拖拽落到文件行 | 不高亮（仅 dir 行与根区接收），沿用 `onDragOverRow` 现有判定 |
| 面板宽 < 246px | 容器查询生效：隐藏放大镜、图标按钮 24px；文件名仍 ellipsis |
| 深色主题 | 全部走令牌；`mark` 用 `--warn-weak`（深色 `#3a2e10`）+ `--text` 前景，对比度 ≥ 4.5:1 |
