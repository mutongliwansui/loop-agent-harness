## 一、需求背景

当前 LoopAgent 的图形界面必须由用户手动执行 `loop-agent --serve` 常驻进程，再在浏览器输入 `http://127.0.0.1:3000`。对现场（Windows 10 神州网信政府版 19044，无源码 / 无 node_modules / 无 npm、**无管理员权限**）的非技术用户有三个硬门槛：要记命令、要记地址、端口冲突看不懂报错。目标是提供**安装后双击即用**的桌面端。

## 二、总体设计（摘要）

```text
LoopAgent.exe（Electron 壳）
  ① requestSingleInstanceLock → 二次启动聚焦已有窗口
  ② 探测空闲端口（从配置端口起顺延，不用 --port 0）
  ③ spawn resources/loop-agent-core.exe --serve --port <p>
  ④ 轮询 GET /health 就绪（实测约 2.5s，上限 60s）
  ⑤ BrowserWindow.loadURL(http://127.0.0.1:<p>)
  ⑥ 关窗 → POST /admin/shutdown → 等退出 → 超时 taskkill /T /F
        │
        ▼ HTTP/SSE（回环，无 token）
loop-agent-core.exe（既有 SEA 产物，除新增关停端点外零改动）
```

**两项已实测证伪、必须正面处理的关键结论**：

1. `--port 0` **不可用**——`parsePort` 只接受 `1..65535`，0 被静默丢弃后回落到 3000。端口必须由壳探测。
2. Windows 下 `kill('SIGINT')` 是**无条件强杀**，handler 不执行（本机实测 `handler-ran=false`）。Dreaming 只挂在信号处理上且无 HTTP 端点，故**必须新增 `POST /admin/shutdown`** 才能「关窗不丢记忆」。

## 四、跨任务共通约束

- **不改前端**：WebUI 一行不动（同源相对路径已就绪）。
- **不改既有 `--serve` 行为**：浏览器访问路径必须原样可用。
- **后端改动只允许一处**：`POST /admin/shutdown`（任务 02）。除此之外后端不动。
- **零新依赖优先**：壳侧仅新增 Electron / electron-builder 为 devDependencies，不进运行时依赖树。
- **提交信息、代码注释用中文**；文档中英双语同步（`docs/readme/zh` + `docs/readme/en`）。

## 六、验收总纲

1. 全新机器（非管理员账户）运行 `LoopAgent-Setup-*.exe`，一路下一步装完，**全程无 UAC 弹窗**
2. 双击快捷方式出窗口，能正常对话、能看到既有会话
3. 重复双击只有一份后端进程，窗口聚焦
4. 3000 被占用时仍能启动，用户无感
5. 关窗口后任务管理器无残留 `loop-agent-core.exe`，且日志有 Dreaming 完成记录
6. `loop-agent.exe --serve` + 浏览器访问**行为与改动前完全一致**
