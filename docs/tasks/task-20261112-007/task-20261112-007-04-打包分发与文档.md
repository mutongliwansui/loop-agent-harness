## 一、任务目标需求

### 1.1 背景（痛点）

前三个任务只在开发机跑得起来。现场用户要的是「拿到一个 exe，双击装上，桌面有图标」。本任务把三条既有构建链（`build:webui` → `build:sea`）接上新的一环 `build:desktop`，产出可交付安装包。

**核心风险不在代码，在「安装」这个动作本身**：现场是**非管理员账户**，任何需要 UAC 提权的安装器都会让交付失败。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| WebUI 构建 | `npm run build:webui` → `webui/dist` | 复用，作为 SEA 的输入 |
| 后端单文件 | `npm run build:sea` → `dist-sea/loop-agent.exe`（实测 102.2MB） | 复用，原样作为 `extraResources` |
| 桌面打包 | 无 | **新增 electron-builder** |
| 应用图标 | 无 `.ico`（任务 03 提供 PNG 源） | 需 ico 生成步骤 |
| 双语文档 | `docs/readme/zh` + `docs/readme/en` | 需新增桌面端章节 |
| 非管理员安装验证 | 无自动化 | 本机非管理员账户手工验证 |

### 1.3 任务目标

1. `npm run build:desktop` 一条命令产出**安装包 exe** 与 **portable 兜底包**
2. 安装过程**全程无 UAC 弹窗**，装到用户目录，创建桌面与开始菜单快捷方式
3. 卸载干净（不留残留进程与注册表污染）
4. 中英文档说明安装、首次使用（含 SmartScreen 提示）、卸载
5. `--serve` 浏览器路径回归不受影响

### 1.4 设计约束

- 后端 exe 必须走 `extraResources`，**不得打进 asar**（asar 内文件无法直接执行）
- 不在主工程 `package.json` 增加 electron-builder 到运行时依赖
- 安装包与 portable 必须用**同一份**壳产物，避免两条构建路径漂移
- 产物目录 `dist-desktop/` 不入库

## 二、方案设计

### 2.1 总体思路

```text
npm run build:desktop
   │
   ├─ 1) build:webui → webui/dist
   ├─ 2) build:sea   → dist-sea/loop-agent.exe        （既有，不改）
   ├─ 3) tsup 壳     → desktop/dist/main.cjs + preload（任务 01 的产物）
   ├─ 4) 准备资源    → resources/loop-agent-core.exe（重命名拷贝）
   │                   build/icon.ico（由 icon.png 生成）
   └─ 5) electron-builder
          ├─ target: nsis     → LoopAgent-Setup-0.1.0.exe   ← 主交付物
          └─ target: portable → LoopAgent-0.1.0.exe         ← 兜底

安装后布局（%LOCALAPPDATA%\Programs\LoopAgent）：
   LoopAgent.exe                 ← 壳
   resources/loop-agent-core.exe ← 后端（extraResources）
   resources/app.asar            ← 壳代码
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与理由 |
|---|---|---|
| **D4-1** | **NSIS 安装包，`oneClick: true` + `perMachine: false`（静默按用户装到 `%LOCALAPPDATA%\Programs\LoopAgent`）** | 对齐设计方案 D10 已确认结论。`perMachine:false` 是**无 UAC 的关键**——装到用户目录不请求提权，这是现场非管理员账户能装上的唯一途径。`oneClick:true` 则消除误操作面：assisted 模式会出「安装模式选择页」，用户选了 per-machine 就会撞 UAC 失败，对非技术用户是纯粹的失败入口。**否决 `oneClick:false`**（同 D10）。代价是不能自选安装盘 → **由 portable 版兜底**：确需装到非 C 盘的用户直接用 portable 放任意目录。 |
| **D4-2** | **同时产出 portable 单 exe 作为兜底** | 若现场安全策略禁止安装任何软件，portable 解压即用；两者共用同一壳产物，成本几乎为零。**这是 D10 修订后保留的退路**。 |
| **D4-3** | **后端 exe 走 `extraResources` 并重命名为 `loop-agent-core.exe`，不打进 asar** | asar 是归档文件，内部文件无法被 `spawn` 执行（需先解包）。重命名让「壳 vs 后端」在安装目录里一眼可辨。SEA 产物不依赖自身文件名（资源内嵌于 `src/sea-assets.ts`），重命名安全，但需实测确认（见验收）。 |
| **D4-4** | **图标以任务 03 的 `icon.png` 为唯一源，构建设置 `win.icon` 指向 PNG（≥256×256），不手工维护 `.ico`** | electron-builder 会从 PNG 自动生成 ico，避免多源不一致。若该版本不支持，则回退脚本生成（构建期报错即暴露，不会静默用默认图标）。 |
| **D4-5** | **不做代码签名，但必须在文档与首次运行提示中说明 SmartScreen** | 现场无签名证书采购流程，签名属演进项。未签名 exe 首次运行会弹「Windows 已保护你的电脑」，用户点「更多信息 → 仍要运行」即可。**必须在 README 中给出图示化步骤**，否则现场会判定「装不上」。 |
| **D4-6** | **卸载前后需确认：无残留 `loop-agent-core.exe` 进程；用户数据（`~/.loop-agent`）默认保留** | 卸载程序不应删用户会话与记忆（数据与程序分离）。文档需明确「卸载不删数据，如需彻底清除请手动删 `%USERPROFILE%\.loop-agent`」。 |
| **D4-7** | **构建前置用脚本串联（`scripts/build-desktop.mjs`）而非 npm 链式 `&&`** | Windows 下 npm script 的 `&&` 与跨平台 shell 差异易出错；脚本文件可打印阶段耗时、校验前置产物存在性，并在缺 `dist-sea` 时给出明确指引。 |

### 2.3 检索依据

- electron-builder Windows 目标（nsis / portable）与 perMachine、allowToChangeInstallationDirectory 选项：官方文档 `win` / `nsis` 配置项
- SmartScreen 对未签名 exe 的拦截行为：Microsoft 官方说明（用户需「仍要运行」）

## 三、任务详细设计

### 3.1 electron-builder 配置要点

```jsonc
// desktop/package.json 的 build 字段
{
  "appId": "com.loopagent.desktop",
  "productName": "LoopAgent",
  "directories": { "output": "../dist-desktop", "buildResources": "build" },
  "files": ["dist/**/*", "package.json"],          // 只含壳产物，不含源码
  "extraResources": [
    { "from": "../dist-sea/loop-agent.exe", "to": "loop-agent-core.exe" }
  ],
  "win": {
    "target": [
      { "target": "nsis", "arch": ["x64"] },
      { "target": "portable", "arch": ["x64"] }
    ],
    "icon": "assets/icon.png",
    "artifactName": "LoopAgent-${version}-${arch}.${ext}"
  },
  "nsis": {
    "oneClick": true,
    "perMachine": false,
    "allowElevation": false,
    "createDesktopShortcut": true,
    "createStartMenuShortcut": true,
    "shortcutName": "LoopAgent",
    "artifactName": "LoopAgent-Setup-${version}-${arch}.${ext}",
    "deleteAppDataOnUninstall": false
  }
}
```

### 3.2 构建脚本

| 后端 SEA exe | 102MB（已知） |
| 安装包压缩后 | 约 130–180MB |
| **安装后总占用** | **约 300–380MB** |

### 3.4 边界与错误处理

| 场景 | 现象 | 处理 |
|---|---|---|
| 未先跑 `build:sea` | 打包缺后端 | 构建脚本前置校验，缺则报错并提示命令，不产出半成品 |
| 后端 exe 重命名后无法启动 | 壳起来后端崩 | 验收必测项；SEA 资源内嵌不依赖文件名，若实测失败则改用启动参数传递原路径 |
| electron-builder 首次下载 Electron 二进制慢/失败 | 构建卡住 | 文档给出 `ELECTRON_MIRROR` 环境变量设置方法 |
| 现场安全软件隔离安装包 | 双击无反应 | README 说明「先加入信任/白名单」；portable 兜底 |
| 安装后目录含中文/空格（用户自选目录） | 路径解析异常 | 壳内路径拼接统一用 `path.join`，无手拼字符串 |
| 卸载时后端仍在运行 | 文件占用删不掉 | 壳关停已保证退出（任务 02）；NSIS 卸载前不强杀，文档提示先退出应用 |
| 安装包版本号不一致 | 混淆 | 版本号单一来源：根 `package.json` 的 `version`，构建时同步 |
