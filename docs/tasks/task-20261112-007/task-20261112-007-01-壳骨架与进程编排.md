## 一、任务目标需求

### 1.1 背景（痛点）

壳这一层当前不存在。用户要的是「双击出窗口」，本任务负责把这个链路**第一次打通**：双击 → 选端口 → 拉起后端 → 等就绪 → 出窗口。没有这一步，后续任务（生命周期、窗口体验、打包）都无从谈起。

### 1.2 现状梳理

| 所需能力 | 框架现状 | 结论 |
|---|---|---|
| 后端可执行文件 | `scripts/build-sea.mjs` 产出 `dist-sea/loop-agent.exe`（实测 102.2MB，内嵌 WebUI + PTY） | 可直接被 spawn，**无需二次打包** |
| 端口可指定 | `--port` 支持 `--port N` / `--port=N`（`src/config/cli-overrides.ts:15-35`） | 可用，但**只接受 1..65535**，`0` 被静默丢弃 |
| 监听实际端口 | `start()` 返回 `{ port }`（`src/api/server.ts:286-302`） | 壳不依赖它（端口由壳先定） |
| 就绪探针 | `GET /health` → `{status,version,model}`（`src/api/router.ts:114-118`） | 用它做就绪判定 |
| 前端托管 | `resolveStaticHandler()`：磁盘 → SEA 内嵌 → 纯 API（`src/api/server.ts:249-250`） | 壳只要 loadURL 根路径 |
| 前端网络层 | `webui/src/api/client.ts` 全同源相对路径 | **前端零改动** |
| 鉴权 | 无 token 仅放行回环（`src/api/http-utils.ts:89-94`） | 绑 127.0.0.1 即零配置可用 |
| 项目模块格式 | `package.json` 为 `"type": "module"`（ESM） | 影响壳主进程打包格式（见 D1-2） |

### 1.3 任务目标

1. `desktop/` 子包可独立启动（开发期 `npm run dev` 直出窗口）
2. 双击/启动后自动定端口、拉起后端、等 `/health` 就绪、加载界面
3. 后端找不到 / 起不来 / 超时，**给可读错误**而不是白屏
4. 不修改主工程运行时依赖与前端代码

### 1.4 设计约束

- 壳的 Electron 依赖**不得**进入主工程 `dependencies`
- 不改 `webui/`、不改 `src/`（本任务后端零改动）
- 不假定构建机已跑过 `build:sea`（开发期允许回落到 tsx 启动后端）
- 不做单实例、不做优雅关停（属任务 02）

## 二、方案设计

### 2.1 总体思路

```text
desktop/main.ts（Electron 主进程）
   │
   ├─ resolveBackendPath()                    [D1-5] app.isPackaged 分支
   │     ├─ 打包后：process.resourcesPath/loop-agent-core.exe
   │     ├─ 便携：  <exeDir>/loop-agent-core.exe
   │     ├─ 开发期： ../dist-sea/loop-agent.exe
   │     └─ 都没有 → <dist-sea 不存在> → 回落 tsx src/index.ts --serve（仅开发）
   │
   ├─ pickPort(preferred)                     [D1-3] net 试绑 + 顺延
   │
   ├─ spawn(backend, ['--serve','--port',String(port)], { cwd, stdio:'pipe' })
   │     └─ stderr/stdout 环形缓冲最后 N KB（供错误提示用）
   │
   ├─ waitForHealth(port)                     [D1-4] fetch /health，200ms × 60s
   │     └─ 失败 → 带 stderr 尾部弹错误窗，退出
   │
   └─ new BrowserWindow().loadURL(`http://127.0.0.1:${port}`)   [D1-6]
```

### 2.2 关键设计决策

| 编号 | 决策 | 取舍与理由 |
|---|---|---|
| **D1-1** | **`desktop/` 作为独立子包**，有自己的 `package.json`，Electron 只装在这里 | 主工程 `dependencies` 只有 6 个运行时包，把 Electron（安装体积 200MB+）塞进去会污染主工程与 SEA 构建。与既有 `webui/` 独立子包的做法一致。 |
| **D1-2** | **壳主进程用 tsup 打包成 CJS（`format: cjs`），desktop 子包不设 `type: module`** | 主工程是 ESM，但 Electron 的 ESM 主进程有额外限制（须 `.mjs`/type:module、部分特性不可用）。壳不需要原生模块、不需要顶层 await 之外的 ESM 特性，**打成 CJS 是零风险路径**。否决「直接 ESM 主进程」（会引入 Electron 版本相关的隐性坑）。 |
| **D1-3** | **端口探测用 `net.createServer().listen()` 试绑**，从配置端口起向上顺延最多 20 个，失败抛明确错误 | `--port 0` 实测不可用（`parsePort` 丢弃 0 后静默回落 3000，见设计方案 D3）。顺延而非随机：保证多数情况下仍是 3000，老书签继续可用。**注意探测与 spawn 之间存在竞态**，见 3.2 错误表兜底。 |
| **D1-4** | **就绪判定 `fetch('http://127.0.0.1:p/health')`，200ms 间隔、60s 上限** | 实测 SEA spawn → 200 约 2.5s，60s 留足冷启动余量（MCP 后台监测、记忆初始化）。否决固定 sleep（慢机不够、快机白等）。否决「先开窗口让页面自己重试」（退化为白屏干等）。 |
| **D1-5** | **后端路径按 `app.isPackaged` 分支解析**，开发期允许回落 tsx | 安装包形态下后端在 `resources/`，与 exe **不同级**（D11）。开发期回落 tsx 让壳可独立迭代，不必每次 `build:sea`。 |
| **D1-6** | **窗口绑 `127.0.0.1`、不配 token**；若用户已配 `api.token` 则预置 localStorage `loop_agent_token` | 回环免鉴权是既有策略（`http-utils.ts:89-94`）。已配 token 时前端只读 localStorage（`webui/src/api/client.ts:27-38`），故由壳 `executeJavaScript` 预置，**前端仍零改动**（不走 URL 参数）。 |
| **D1-7** | **本任务用 `BrowserWindow` 默认原生边框、默认尺寸 1440×900、`show:false` 待 `ready-to-show` 再显示** | 避免「白屏闪一下」。原生边框是 D8 既定结论（自绘标题栏放 P2）。 |
| **D1-8** | **spawn 后端时 cwd 显式设为用户主目录（`os.homedir()`），不继承壳的安装目录**（P2 顺手项，不再是 P0 必须项） | **原立论已失效，但结论仍成立（2026-11-13 复核）**：本条原以「`defaultRoot()` 的 cwd 兜底是有意保留」为立论，而需求 **20261113-001 D9** 已把该兜底整条退场——`defaultRoot` / `cwdFallback` 全仓零引用，兜底改用 `homedir()`（`recent-workspace.ts:11-13`）。原点名的三处「写坏」也已不再依赖 cwd：`terminal.ts:37` 取 `ctx.deps.sessionStore.path`（会话所属空间根）、Skill 落点为 `~/.loop-agent/skills`（`skill/loader.ts:20`）、文件面板兜底为 `currentWorkspaceRoot() \|\| homedir()`（`sessions.ts:71`）。**现存 cwd 代码级依赖共三处**（均在 `tests/no-chdir.test.ts` 白名单内，见 2.3）：`config/mcp-manager.ts:18`（stdio MCP 缺省 cwd）、`config/loader.ts:27`（`<cwd>/.env`）、**`api/static.ts:53`（`<cwd>/webui/dist` 磁盘探测兜底）**。前两者设 `homedir()` 纯属改善；**第三处是本条唯一的实质风险点**——SEA 产物 `import.meta.url` 被 esbuild 置空会走该兜底，若 exe 未内嵌 WebUI 且依赖「exe 同目录放 webui/dist」的部署方式，改 cwd 后磁盘探测落空 → `createEmbeddedStaticHandler()` 也返回 null → 降级纯 API → **窗口白屏**。故**默认不做处理，靠 SEA 内嵌**（`build:sea` 正常内嵌 WebUI，最终安装布局 `resources/loop-agent-core.exe` 下压根没有 `webui/dist` 目录，磁盘兜底本就不可用）；`--web-root` 仅作**应急手段**——用于开发期免重建、或遇未内嵌的纯后端 exe 时由壳补传绝对路径指向磁盘 dist，且传了即不回退内嵌（`static.ts:206`），须先 `existsSync(join(dir,'index.html'))` 再传。真正的防线放在任务 04：打包脚本强制校验 SEA 已内嵌 WebUI。**否决「继承壳的 cwd」与「用安装目录」**。 |

### 2.3 检索依据

- `--port 0` 失效：源码事实（`cli-overrides.ts:30-35` 要求 `1..65535`）
- Windows 信号强杀：Node 官方文档 + 本机实测（见设计方案第六章）
- Electron ESM 主进程限制：Electron 官方文档「ESM support」要求 `.mjs` 或 `type:module`，且部分 API 在 ESM 主进程不可用 → 选 CJS 规避（D1-2）
- cwd 依赖现状（D1-8）：源码事实——`grep -r "process.cwd()" src/` 的**代码行**（排除注释）全部落在 `tests/no-chdir.test.ts` 的 `CWD_ALLOWLIST`（共 13 个文件，其中仍有代码级调用的约 10 个：`agent/react-agent.ts`、`runtime/init.ts`、`session/store.ts`、`tools/runner.ts`、`tools/workspace-fs.ts`、`config/loader.ts`、`config/mcp-manager.ts`、`api/static.ts`、`cli/start.ts` 等）；`defaultRoot` / `cwdFallback` 全仓零引用（需求 20261113-001 D9 退场后复核）。其中真正影响桌面端的只有 `api/static.ts:53`：`resolveWebRoot('')` 在 `import.meta.url` 不可用（CJS/SEA）时回落 `<cwd>/webui/dist`，而 `resolveStaticHandler` 是「磁盘 → SEA 内嵌 → 降级纯 API」三级（`static.ts:210-215`），磁盘落空且未内嵌即白屏

### 3.2 边界与错误处理

| 场景 | 现象 | 处理 |
|---|---|---|
| 三种布局都找不到后端 exe 且无 tsx 环境 | 无法启动 | 弹错误窗：「未找到后端程序 loop-agent-core.exe，请重新安装」+ 已查找路径列表 |
| 端口 3000~3020 全被占 | 无法监听 | 抛 `PortUnavailableError`，错误窗列出已尝试端口 |
| 探测成功但 spawn 时被抢占（竞态） | 后端报 `EADDRINUSE` 退出 | **检测到后端提前退出 → 换下一个端口重试一次**；仍失败则报错 |
| 后端启动即崩（配置错误等） | 无 `EADDRINUSE` 但秒退 | 错误窗展示 `tail()` 尾部 8KB，直指原因 |
| 60s 内 `/health` 未 200 | 卡住 | 超时错误窗 + `tail()`；不静默白屏 |
| 用户已配置 `api.token` | 401 | loadURL 前 `executeJavaScript` 写入 localStorage `loop_agent_token` |
| 端口被非本程序占用但健康检查也 200（他例） | 误连到别的服务 | `/health` 校验返回体含 `status:'ok'` 与 `version`，不匹配视为未就绪 |
| 开发期未装 tsx 也无 dist-sea | 起不来 | 错误提示明确「请先 npm run build:sea」 |
| spawn 未设 cwd（落进安装目录） | stdio MCP server 未显式配置 `cwd` 时子进程会开在壳的安装目录（`mcp-manager.ts:18` 的 `startupRoot`）；`.env` 也会在安装目录找 | D1-8：设 `cwd: os.homedir()`，两者都落到用户主目录；单测断言取值 |
| **设 cwd 后 WebUI 静态资源探测落空** | `static.ts:53` 以 `<cwd>/webui/dist` 兜底；cwd 改 homedir 后，若该后端 exe 既未内嵌 WebUI 又靠「exe 同目录放 dist」部署，则磁盘探测与内嵌兜底双双落空 → 降级纯 API → **窗口白屏** | **首选：确认走内嵌**（`build:sea` 正常内嵌，安装布局下不存在 `webui/dist`，本就走内嵌分支，cwd 改了也不影响）；**应急：壳传 `--web-root=<绝对路径>`**（须先校验 `index.html` 存在，传了不回退内嵌）；**根治：任务 04 打包脚本强制校验内嵌**。**P0 验证**：挪开后端 exe 同目录的 webui/dist 后仍能显示页面 |
