## 一、任务目标需求

### 1.1 背景（痛点）

对话正在流式输出时，用户想往上滑回看中间过程（例如刚才某次工具调用的参数、上一段思考），视口会被立刻拽回底部——**必须先等整轮输出结束才能读**。长回答/多轮工具调用（一次 run 可能几分钟）时几乎无法中途阅读，只能被动盯着尾部。

用户体验到的现象是「滚不动 / 滚一下就弹回」，而不是「滚动条坏了」。

### 1.3 任务目标

1. 流式输出期间用户上滑即「解绑跟随」，视口停在用户选择的位置，后续 chunk 不再拽回。
2. 用户滚回底部（距底 ≤ 阈值）自动「重新吸附」，行为与现在一致。
3. 解绑期间露出「回到最新」悬浮按钮，一键回底并恢复跟随；有新 chunk 时给「新内容」提示。
4. 以下场景无论当前状态一律回底：用户发送消息、切换会话、新建会话、点击回底按钮。
5. 后处理（高亮/图表渲染）改变块高度时，阅读位置不漂移。
6. 判定逻辑抽纯函数模块并补 vitest 用例，回归全绿。

### 1.4 设计约束

- **零新依赖**：只用 DOM 事件与既有设计令牌。
- **只改 WebUI 渲染层**：不动 SSE 协议、`chat-stream.ts` 的状态机与消息数据结构；`setActivityHandler` 语义（"有新动静了"）保持不变，只是消费方式变化。
- **不引入全局 store**：滚动是纯视图行为，状态留在 `ChatView.vue` 内，组件重挂载回到 `pinned`。
- 复用 `style.css` 既有令牌（`--panel` / `--line` / `--shadow-pop` / `--brand` / `--muted` / `--radius-card`），不新增色值。
- 图标用内联 SVG，**不使用 emoji / 字符图标**（沿用 20261024-001、20261025-002、20261026-001 的图标规范）。
- 跨浏览器：Chrome / Edge / Firefox / Safari 均需可用；不依赖 `scrollend` 等新事件。

### 2.2 关键设计决策

**D1 跟随策略：采用「贴底才跟随（stick-to-bottom）+ 上滑即解绑」状态机。**
`follow: 'pinned' | 'released'`，初值 `pinned`；`scrollBottom()` 仅在 `pinned` 时写 `scrollTop`。
取舍：被否决的替代方案——(a)「run 结束后才允许上滑」等于把问题推后，长回答依旧不可读；(b)「完全关闭自动滚动」会让主场景（盯最新输出）退化；(c) 「Hover 时暂停」无法覆盖触屏与键盘，且鼠标悬停在正文上是常态（会变成永不跟随）。

**D2 贴底判定口径：`scrollHeight - scrollTop - clientHeight <= 24px` 视为贴底。**
阈值抽常量 `STICK_THRESHOLD_PX = 24`（约 1.5 行正文高度）。取舍：按百分比判定在超长对话下会误吸（几万 px 的 1% 就是几百 px）；按行数需要读计算样式，成本高且随字号漂移。业界同口径：MUI X 的 `buffer`、TanStack Virtual 的 `scrollEndThreshold`。

**D3 用户意图来源：`wheel` / `touchmove` / `pointerdown` 是「解绑」触发；`scroll` 只用于「回吸」判定；程序化写入用 `programmatic` 标志屏蔽。**
理由：`scrollTop` 赋值同样会触发 `scroll` 事件，只靠 `scroll` 无法区分「用户滚的」与「我们滚的」。`pointerdown` 覆盖拖动滚动条与触控板拖拽；键盘 `PageUp/PageDown/Home/End/ArrowUp/ArrowDown` 仅在 `event.target` 不是 `textarea`/`input`/`[contenteditable]` 时才算用户滚动意图（否则与输入框内的光标移动、历史回调冲突）。
取舍：被否决项——用 `scroll` 事件方向判定（同一帧内程序化写入与用户滚动混在一起，误判率高）；用 `scrollend`（Safari 长期不支持，且流式期间永远不触发）。

**D4 解绑后不记录「距底偏移量」补偿，改为显式 `overflow-anchor: auto`。**
理由：流式增长发生在**视口下方**，`scrollTop` 不变时已读内容天然不动，无需补偿；真正会导致漂移的是后处理在上方改高度（图表槽位、代码高亮），这交给浏览器滚动锚定。"记录 `scrollHeight - scrollTop` 再回填"会在上方高度变化时反向抖动，且与锚定打架。故：给 `.msgs` 显式 `overflow-anchor: auto`（显式声明，不依赖默认值随浏览器版本变化）。

**D5 回底入口：`released` 时露出「回到最新」悬浮按钮；解绑期间有新 chunk 时加「新内容」圆点，不做条数计数。**
理由：一条流式消息是**一条**在长大，不是多条新增，计数无意义且会误导。按钮位置：`.msgs` 右下角（`position: sticky/absolute` 于滚动容器内），`--panel` 底 + `--line` 描边 + `--shadow-pop`，内联 SVG 下箭头 + 文案（窄容器只留箭头，`title`/`aria-label` 兜底）。点击 → `pinned` + 回底，并清 `hasPending`。
取舍：被否决项——常驻按钮（`pinned` 时也在，占视觉且点击无效果）；用 toast 提示新内容（流式期间高频，会刷屏）。

**D6 强制回底的例外清单。**
四类场景无论 `follow` 为何值都 `pinned` 并立即到底：用户发送消息（`send()` 第 429/446 行）、切换会话（`selectSession` 第 388 行）、新建会话（`createSession` 第 269 行）、点击回底按钮。run 结束（`onRunFinished` 第 636-641 行）**仅在 `pinned` 时**滚底，`released` 时保持阅读位置只更新按钮提示——用户正在读的内容不该在生成结束时被抢走。
理由：与 MUI「用户发送消息恒激活跟随」一致；切会话属于「进入全新上下文」，保留旧滚动位置反而困惑。

**D7 滚动合帧：保留 rAF 合帧，去掉内层 `nextTick`，并在 `released` 时直接 return。**
现状 `scrollBottom()` 是 `nextTick(() => 写 scrollTop)` 套在 rAF 回调里，等于延迟两帧；改成 rAF 回调内同帧读 `scrollHeight` + 写 `scrollTop`。`released` 时直接 return，连 `scrollHeight` 都不读（读它是强制重排，流式高频下是主要开销之一）。
取舍：被否决项——用 `ResizeObserver` 监听内容高度变化来代替活动事件（会与 v-for 块替换共振，且拿不到「有新内容」语义）。

**D8 滚动动画：流式跟随用瞬时定位；「回到最新」按钮点击用 `smooth`，并在 `prefers-reduced-motion: reduce` 下降级为瞬时。**
理由：流式每秒数十次定位，`smooth` 会互相打断产生粘滞感；一次性回底用平滑更有指向性。被否决项——给 `.msgs` 全局设 `scroll-behavior: smooth`（会把程序化跟随也变平滑，正是上述故障）。

**D9 滚动链微调：`.chart-view` 保留 `overscroll-behavior: contain`；工具卡内层保持浏览器默认（链式）。**
理由：图表容器内的平移/缩放需要独立，落到边界时不该把父容器一起滚走；工具卡结果区默认 `auto` 已经是「内层到底→传父级」，仅在「内层还有余量」时吃掉滚动，这是合理行为。**不为此改动布局**。
取舍：被否决项——把工具卡内层也设 `contain`（会让「滚不动」的感受更严重）；把内层 `max-height` 取消（20261024-001 D6 已定 190px/420px 的口径）。

**D10 判定逻辑抽 `webui/src/scroll-follow.ts` 纯模块。**
导出 `isAtBottom(metrics, threshold)` 与 `createFollowState()`（含 `follow`/`hasPending` 与 `onUserGesture()`/`onScroll()`/`forcePin()`/`onActivity()` 的纯状态迁移）。组件只做 DOM 接线。
理由：webui 无 jsdom（无 vitest/jsdom/@vue-test-utils 配置），纯函数是唯一可单测路径；沿用 `autogrow.ts` / `stream-blocks.ts` / `chart-labels.ts` 先例。

**D11 解绑期间不暂停后处理渲染。**
`postRenderMsgs()` 照旧执行（图表该渲染就渲染），位置稳定靠 D4 的锚定而非"不渲染"。被否决项——暂停后处理：用户滚回时仍需补渲染，且需额外记录脏标记，复杂度换不到收益。

**D12 会话切换记忆滚动位置（回到上次读到的地方）本次不做。**
列为演进项。理由：切会话当前是「进入新上下文」语义（D6 强制回底），与其冲突；且需要按 sessionId 持久化偏移，属独立议题。

## 三、任务详细设计

### 3.1 `webui/src/scroll-follow.ts`（新增，纯函数）

```ts
/** 贴底阈值：约 1.5 行正文（正文 14px / 行高约 22px） */
export const STICK_THRESHOLD_PX = 24;

export interface ScrollMetrics {
  scrollTop: number;
  scrollHeight: number;
  clientHeight: number;
}

/** 距底距离（负数按 0 处理，防 Safari 弹性滚动给出负值） */
export function distanceToBottom(m: ScrollMetrics): number;

/** 是否贴底：distanceToBottom <= threshold */
export function isAtBottom(m: ScrollMetrics, threshold?: number): boolean;

export interface FollowState {
  follow: 'pinned' | 'released';
  /** 解绑期间是否来过新内容（驱动按钮上的「新内容」圆点） */
  hasPending: boolean;
}

export interface FollowController {
  get(): FollowState;
  /** 用户手势（wheel/touchmove/pointerdown/键）→ released */
  onUserGesture(): FollowState;
  /** 容器 scroll（仅在非程序化写入时调用）→ 贴底则回 pinned 并清 hasPending */
  onScroll(m: ScrollMetrics, threshold?: number): FollowState;
  /** 活动事件（新 chunk 到达）→ released 时置 hasPending */
  onActivity(): FollowState;
  /** 强制回底（send/切会话/新建/点按钮）→ pinned 且清 hasPending */
  forcePin(): FollowState;
}

export function createFollowState(init?: Partial<FollowState>): FollowController;
```

纯函数、无 DOM 依赖，可被 vitest 直接覆盖。

| 属性 | 取值 | 说明 |
| --- | --- | --- |
| 定位 | `position: absolute; right: 18px; bottom: 14px` | 父级 `.chat-main` 需 `position: relative`（若无则加） |
| 尺寸 | `32×32`、`border-radius: 999px` | 与发送按钮（32×32）同规格 |
| 底色/描边 | `background: var(--panel)`、`border: 1px solid var(--line)` | 不引入新色 |
| 阴影 | `box-shadow: var(--shadow-pop)` | 与模型选择浮层同层级语言 |
| 悬浮 | `color: var(--brand)`、`border-color: var(--brand-weak)` | 轻微强调 |
| 圆点 | `.pending::after`：`6px` 圆点、`background: var(--brand)`、右上角 | 有新内容时出现 |
| 过渡 | `opacity/transform 120ms`；`@media (prefers-reduced-motion: reduce)` 关闭 | 尊重系统偏好 |

`.msgs` 追加 `overflow-anchor: auto;`（D4）。

### 3.4 边界与错误处理

| 场景 | 期望行为 |
| --- | --- |
| 内容不足一屏（无滚动条） | `scrollHeight ≈ clientHeight` → 恒贴底；按钮永不出现 |
| 用户上滑后内容继续增长 | `scrollTop` 不变，已读内容不移动（增长发生在下方） |
| 用户上滑到底部之上后 run 结束 | 保持位置；按钮带「新内容」圆点直至点击或滚回底部 |
| 用户滚回底部（≤24px） | 自动回 `pinned`，按钮消失，跟随恢复 |
| Safari 弹性滚动给出负 `scrollTop` | `distanceToBottom` clamp 到 ≥0，不会误判为解绑 |
| 图表渲染改变上方高度 | 浏览器滚动锚定校正，阅读位置不漂移；若仍漂移属 `overflow-anchor` 未被支持，退化为「位置可能小幅跳动」（可接受，记入已知限制） |
| 组件卸载（切去其他页面） | 监听全部移除、rAF 取消、`follow` 随组件重建回到 `pinned` |
| 触摸设备 | `touchmove` 解绑；`pointerdown` 覆盖拖动滚动条 |
| 键盘焦点在输入框 | `ArrowUp/PageUp` 不算用户滚动意图（D3 过滤） |
| 会话切换与旧滚动位置 | 强制回底（D6/D12），本次不保留旧位置 |
| 非流式（`stream: false`）一次性返回 | 与流式同路径，`pinned` 时照常到底 |

#### 验证方式与证据

验证均在**真实浏览器（headless Chrome + CDP 9222）**上驱动生产代码路径完成，滚动几何量取自 `scrollTop / scrollHeight / clientHeight` 实测值，不靠视觉判断：

1. **流式增长期间解绑不被拉回**：以注入式缓慢 SSE 流（PostMessage 级 `ReadableStream`，走生产 `sseFetch → parseFrame → consume → onEvent → notifyActivity → setActivityHandler` 全链路，每 60ms 一帧、共 300 帧）复现流式输出。用户上滑解绑后连续采样 10s：`scrollTop` **零位移**（`topMovedPx = 0`），同期内容高度 +7098px、距底由 903px 增至 8001px —— 内容在长，视口不动。
2. **新内容圆点**：上述窗口内每帧采样均读到 `.jump-bottom.pending` ✔。
3. **点「回到最新」恢复跟随**：点击后 `dist = 0`、按钮消失；随后 8 次采样 `dist` 全为 0（持续贴底）。
4. **解绑态 run 结束不回弹**（时序实验，16ms 采样）：`done` 之后 `scrollTop` 始终保持 48779 不变（`firstTopChangeMs = null`），直到 `reconcile` 用磁盘历史替换内容（height 50305 → 49487）视口仍未移动 —— 证明 `onRunFinished` 未抢视口，此前的位移只可能来自内容收缩被 clamp。
5. **贴底阈值**：滚回 ≤24px 自动回吸、>24px 保持解绑（单测 + 页面双覆盖）。
6. **用户意图来源**：`wheel` / `touchmove`（`TouchEvent` 模拟）/ 拖动滚动条 `pointerdown` / `PageUp` 均可解绑；输入框内 `ArrowUp` 与点击消息正文不解绑；内容不足一屏时手势不解绑（避免空会话出现按钮）。
7. **按钮外观与可达性**：32×32、`border-radius: 999px`、内联 `svg` 1 个、无 emoji 字符；浅色 `bg rgb(255,255,255) / border rgb(227,230,234)`，深色 `bg rgb(27,31,38) / border rgb(43,49,58)`（均取自 `--panel` / `--line`）；`document.elementFromPoint(中心)` 命中按钮内 `<path>` → **未被遮挡**；`gapToComposer = 14px`、距容器右缘 18px；对话区被压窄到 401px 时位置与可达性不变。
8. **`prefers-reduced-motion`**：样式表中存在针对 `.jump-bottom` 的 reduced-motion 覆盖规则，`scrollBottom({smooth:true})` 在该偏好下走 `behavior: 'auto'`（代码级）。
9. **阅读位置稳定（D4）**：`.msgs` 计算样式 `overflow-anchor: auto`；等价实验——在视口上方的消息块顶部插入占位块使上方高度 +192px，`scrollTop` 自动 +193px 补偿，移除后精确还原（24744 → 24937 → 24744），说明上方块变高时阅读位置不漂移。
10. **回归**：`npx vitest run` 全绿（119 文件 / 1431 用例）、`npx tsc --noEmit`（webui）exit 0 零错误、`cd webui && npm run build` 成功（25.65s）；构建产物 `webui/dist` 按项目约定不入库（`.gitignore` 第 14 行 `/webui/dist/`），部署侧需本地执行 `npm run build:webui`。
