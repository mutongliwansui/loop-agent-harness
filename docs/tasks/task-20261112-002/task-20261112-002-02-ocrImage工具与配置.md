### 1.3 任务目标

1. 新增 `ocrImage` 工具：参数 `image`（必填）、`lang`、`maxChars`；返回首行带来源标注的文本；
2. 配置段 `ocr.*` 落地并有安全默认值（默认开启，但无引擎时不注册）；
3. 条件注册：`ocr.enabled=true` **且** 本机有可用引擎才注册，保证关掉后 tools 列表与当前版本逐字节一致（保护前缀缓存）；
4. `/tools list|enable|disable` 与 REST/WebUI 工具列表能识别 `ocrImage`；
5. 引擎不可用、格式不支持等「可纠正」错误，以中文说明直接回给主模型，而不是抛裸栈。

### 1.4 设计约束

- 工具层不重复实现校验、缓存、截断——一律走 `src/ocr/`；
- 工具级 `maxChars` 只能**收紧**不能放宽全局上限（`Math.min`）；
- 非 Windows 平台不注册工具，也不在工具列表里出现「不可用」占位；
- 描述文案要让模型分清 `analyzeImage`（看图说话）与 `ocrImage`（只取字、离线、不耗 token）。

## 二、方案设计

### 2.1 总体思路

```
registerBuiltinTools(baseTools)
   ├─ baseTools（10 个始终注册）
   ├─ shouldRegisterVisionTools() → visionTools（4 个）
   └─ shouldRegisterOcrTools()   → ocrTools（1 个）   ← 本任务新增
                                    │
                                    ├─ ocr.enabled === false → 不注册
                                    └─ winrtOcrLikelyAvailable() 为 false 且未配 http 端点 → 不注册
```

`ocrImage.execute()` 流程：取参 → 读配置（热更新）→ 用 `Math.min` 收敛 `maxChars` → `runOcrOnSource()` → 再截一次 → `buildOcrResultText()` 加标注头 → `OcrError` 转成 `OCR 失败（code）：中文说明`。

### 2.2 关键设计决策

| 编号 | 决策 | 被否决项与理由 |
| --- | --- | --- |
| **T2-D1** | `ocr.enabled` 默认 `true`，但注册还要求「本机有可用引擎」 | 否决「仅看开关」：非 Windows 或没装语言包时会挂一个每次必失败的工具，污染模型选择 |
| **T2-D2** | 工具 `maxChars` 用 `Math.min(arg, cfg.maxChars)` | 否决「参数直接覆盖」：模型传个 100000 就能突破全局上限，把上下文打爆 |
| **T2-D3** | `OcrError` 在工具层转 `throw new Error('OCR 失败（code）：…')` | 否决原样抛出：`OcrError` 的 `code` 对模型有价值，裸栈对模型无意义 |
| **T2-D4** | 不新增 `/ocr` 命令行入口，诊断走 `describeOcrStatus()` 的 API/设置页 | 否决加命令：现场用不上高频诊断，避免命令面板膨胀 |
| **T2-D5** | `OcrDocConfig` 默认值在本任务一并定义（`enabled/ocrImages/maxImagesPerDoc/…`） | 让任务 04 只消费配置，不改 schema 形状 |

## 三、任务详细设计

### 3.1 工具契约

```ts
name: 'ocrImage'
parameters: {
  type: 'object',
  properties: {
    image:    { type: 'string', description: '图片路径（工作空间内或绝对路径）、file:// 或 dataURI；不支持 http(s) 地址' },
    lang:     { type: 'string', description: '识别语言标签，如 zh-Hans-CN / en-US；省略用配置值' },
    maxChars: { type: 'number', description: '本次结果字符上限（覆盖配置 ocr.maxChars）' },
  },
  required: ['image'],
}
timeoutMs: 60000   // 20s 配置上限之外再留 powershell 冷启动开销
```

返回示例：

```
[OCR 引擎: winrt-ocr | 语言: zh-Hans-CN | 耗时: 0.1s]
苏智问答系统 V1.0
操作手册
```

### 3.2 配置结构（`config.ocr`）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关；关掉后工具不注册 |
| `engine` | `'auto'` | `auto` / `winrt-ocr` / `http` |
| `enginePriority` | `['winrt-ocr']` | auto 下的探测顺序 |
| `lang` | `'auto'` | Windows 上 auto 优先中文 |
| `maxImageBytes` | 10MB | 单图上限 |
| `maxChars` | 20000 | 结果字符上限 |
| `timeoutMs` | 20000 | 引擎超时 |
| `cacheEnabled` / `cacheTtlMs` / `cacheMaxEntries` | `true` / 10min / 100 | 结果缓存 |
| `http.endpoint` / `http.timeoutMs` / `http.headers` | 空 / 20s / `{}` | 可选自建 OCR 服务（P1） |
| `doc.enabled` / `doc.ocrImages` / `doc.maxImagesPerDoc` / `doc.maxCharsPerImage` / `doc.timeBudgetMs` | `true` / `true` / 20 / 2000 / 8000 | 任务 04 消费 |

### 3.3 边界与约束

- `ocr.enabled=false` 时不注册，`/tools list` 不出现该条目；`/tools enable ocrImage` 在未注册时给出「本机无可用 OCR 引擎」而非静默成功。
- 工具描述中明确「不支持 http(s) 地址」，让模型提前改走下载或 `analyzeImage`。
- WebUI 图标须为 16×16 内联线性 SVG（项目图标规范），不用 emoji。

### 3.4 演进项（本任务不做）

- `/ocr status` 类命令行诊断。
- WebUI 设置页的 OCR 独立面板（当前只随配置项暴露）。
- 多语言自动切换与语言包检测提示的前端引导。
