## 一、任务目标需求

### 1.1 背景（痛点）

Loop-Agent 以 `--serve` 常驻对外提供 60+ 个 REST 端点（`/sessions`、`/fs/*`、`/memory/*`、`/models/bench/*` 等），是二次开发与外部集成的唯一入口。但：

1. **接口文档在 WebUI 里看不见**：文档只以 Markdown 存在于 `docs/readme/zh/http-api.md`（62 条端点表格行）与英文版，开发者要接接口得离开界面去翻仓库文件，或凭记忆写请求。
2. **代码与文档会漂移且漂移不可观测**：端点真源是 `src/api/router.ts` 的 `createRoutes()`（含 22 个 `xxxRoutes()` 工厂），md 是手写副本；新增端点忘了写文档时没有任何机制报警，用户侧也发现不了。
3. **左下角「设置与管理」没有面向开发者的入口**：现有 3 组 7 项全是「配置/运维」视角（配置、模型、工具、MCP 服务器、技能、记忆、诊断），缺少「把本服务当平台来用」的视角。

用户诉求原话：**在左下角的设置与管理里新增一个菜单，就叫「开发者中心」，开发者中心里第一个展示模块就是 API 接口文档。**

### 1.2 现状梳理

| 关注点 | 现状（已核实） | 结论 |
| --- | --- | --- |
| 侧边栏菜单 | `webui/src/nav-menu.ts` `ADMIN_GROUPS`：3 组 7 项（配置/模型/工具 · MCP 服务器/技能 · 记忆/诊断），`NavItem = {path,label,short,icon}`，图标为自绘 16×16 线性 SVG（`NAV_ICON_PATHS`，stroke 1.6 / currentColor） | 需新增第 8 项 + 1 个图标 |
| 前端路由 | `webui/src/router.ts` 自管理 hash 路由，8 条（`#/chat` + 7 管理视图），支持 hash query（`?tab=`） | 需新增 `#/dev` |
| 页面范式 | `MemoryView.vue` 用 `.tabs/.tab` 标签页 + `replaceHashQuery({tab})` 还原（D1 范式），`FilesView/ModelsView` 同族 | 直接复用，不造新样式体系 |
| 后端端点真源 | `src/api/router.ts` `createRoutes(deps)` 返回 `Route[] = {method,path,handler}[]`，含 22 个工厂展开，共 60+ 条 | **可运行时反射，无需手工登记路径** |
| 端点语义（中文说明） | 仅存在于 `docs/readme/zh/http-api.md` 表格（62 行）与各 handler 的代码注释 | 需结构化到代码内 |
| 鉴权 | `src/api/server.ts` `isAuthorized`：token 为空→仅本机（403）；token 非空→强制 `Authorization: Bearer`（401）；绑非回环 + 无 token→拒启动 | 文档需展示，`/dev/*` 沿用同一策略 |
| 错误语义 | `matchRoute` 返回 `not_found`/`method_not_allowed`（404/405），`ApiHttpError` 统一 JSON 错误体 | 文档需展示 |
| SSE | `messages` 默认 SSE 流式（`"stream": false` 切 JSON），帧格式见 docs「SSE 流式事件」节 | 文档需展示 |
| 依赖约束 | 项目「零新增依赖」原则（`node:http` 手写 REST）；`webui/dist` 不入库 | 不得引入 swagger-ui/openapi 库 |
| SEA 分发 | 单文件可执行，运行时工作目录无 `docs/` | 文档内容**不能运行时读 md** |

### 1.3 任务目标

1. **菜单入口**：左下角「设置与管理」新增第 8 项「开发者中心」（`short` 取「开发」），沿用现有图标体系、单列竖排与键盘可达性，不改面板分组标题数量（避免面板高度再涨）。
2. **页面模块化**：「开发者中心」页 `#/dev` 用 tabs 组织多个模块，**第一个模块 =「API 接口文档」**（默认激活），为后续新增开发者向模块（如 Webhook、SDK 示例）留插槽。
3. **API 接口文档模块**：
   - 按分组列出全部端点，每条显示 `method` 徽标 + `path`（`:param` 高亮）+ 中文说明；
   - 顶部搜索框（方法 / 路径 / 说明三路匹配）+ 方法筛选；
   - 点击条目展开详情：参数表（名称/位置/类型/必填/说明）、请求体字段、响应结构、curl 示例、鉴权要求；
   - 顶部显示统计「共 N 个端点，已登记说明 M 个」与当前服务地址（`location.origin`）。
4. **数据来源**：后端新增只读端点 `GET /dev/api-docs`，**运行时反射 `createRoutes()`** 得到端点全集，叠加 `src/api/api-docs.ts` 元数据（分组 / 中文说明 / 参数 / 示例）**合并**输出；元数据缺口显式标记 `documented:false`，前端灰标「说明待补」，并由单测列出缺口清单 → **漂移可观测，不静默**。
5. **第二、三模块**（内容均来自既有真实实现，不臆造）：「鉴权与通用约定」（token 三态、404/405/409 语义、错误体结构）、「SSE 事件」（帧类型与字段、接入建议）。
6. **零新增依赖**；中英双语文档同步（`docs/readme/zh|en`）；单测覆盖「元数据 ↔ 路由表」一致性与前端过滤纯函数。

### 1.4 设计约束

- 不修改任何既有 REST 端点语义（只**新增** `GET /dev/api-docs`）；不改 `matchRoute` 匹配规则。
- `webui` 不引入 swagger-ui / openapi 运行时；不新增 npm 依赖（前后端皆然）。
- 页面样式复用 `webui/src/style.css` 既有令牌（`--ok/--danger/--warn/--muted/--line-strong` 等），不新增色值。
- 图标遵循项目规范：16×16 内联线性 SVG、`stroke-width:1.6`、`currentColor`、圆头圆角，不用 emoji/字符。
- 文档内容不得运行时读 `docs/`（SEA 分发后不存在），必须是代码内数据。
- 验收项不预先打勾，真机（CDP 截图 + DOM/像素校验）通过后才勾。

## 二、方案设计

### 2.1 总体思路

```
                       ┌──────────────────────────────────────────┐
 浏览器 #/dev          │  后端（--serve，运行时）                  │
 ┌───────────────┐     │                                          │
 │ DevView.vue   │ GET │  handlers/dev.ts                         │
 │  ├ tab=api ───┼─────►  GET /dev/api-docs                      │
 │  ├ tab=auth   │     │      │                                   │
 │  └ tab=sse    │◄────┤      ├─ createRoutes()  ← 唯一真源（反射）│
 └───────────────┘     │      │      method+path 全集              │
   api-docs-ui.ts      │      └─ api-docs.ts（元数据）             │
   （纯函数：过滤/     │             分组/中文说明/参数/示例       │
     分组/统计）        │             ↓ 合并                       │
                       │        {groups:[{items:[...]}], stats}   │
                       └──────────────────────────────────────────┘
```

三层职责：

1. **真源层（反射）**：`createRoutes()` 决定「有哪些端点」，新端点自动出现在文档页，不可能漏。
2. **语义层（元数据）**：`api-docs.ts` 决定「端点什么意思」，以 `METHOD path` 为键；缺失时输出 `documented:false` + 分组兜底。
3. **呈现层（前端纯函数 + 视图）**：`api-docs-ui.ts` 做过滤/分组/统计（Node 下可直测），`DevView.vue` 只做渲染与交互。

### 2.2 关键设计决策

| 编号 | 决策点 | 备选 | 推荐 | 理由 |
| --- | --- | --- | --- | --- |
| D1 | 文档数据来源 | A 前端静态清单（手写）／B 后端反射 + 元数据合并／C 运行时读 `docs/*.md` | **B** | A 必然随路由表漂移且无法告警；C 在 SEA 单文件分发下 `docs/` 不存在，运行时读文件必崩 |
| D2 | 元数据单一真源位置 | A `src/api/api-docs.ts` 代码内常量／B 由脚本从 md 生成产物入库 | **A** | 项目已有多处「数据 + 纯函数」模块先例（`nav-menu.ts`、`tool-meta.ts`），代码内常量可被 tsc 与单测直接覆盖；脚本生成会多一步构建流水线且产物同样会漂移 |
| D3 | 元数据缺口的处理 | A 静默用路径代替说明／B 输出 `documented:false` + 前端灰标 + 单测列缺口 | **B** | 用户要求「修根因、兜底也要可观测」，缺口必须能被 CI/单测看见 |
| D4 | 端点路径与鉴权 | A `GET /api-docs`／B `GET /dev/api-docs` | **B** | `/dev/*` 为开发者向命名空间，后续 Webhook/SDK 模块可聚合；且与既有组命名风格一致（`/mcp/*`、`/memory/*`），不占用根级短路径 |
| D5 | 页面模块组织 | A 单页长滚动／B tabs + hash `?tab=` 还原 | **B** | 复用 `MemoryView` 已验收范式；「第一个展示模块」的措辞本身要求可扩展多模块 |
| D6 | 第一版模块清单 | A 只有 API 接口文档／B 接口文档 + 鉴权与约定 + SSE 事件 | **B** | 三者是「接接口」的完整闭环，且内容均有既有实现依据；不额外造「SDK/变更日志」等无来源模块 |
| D7 | 菜单项位置 | A 新增第 4 组「开发」／B 追加到「扩展」组末尾 | **B** | 面板已 3 组 7 项，新增分组标题会让浮层高度再涨约 25px（贴近视口上限）；「扩展」组语义（MCP/技能）与「开发者中心」同为扩展能力，归入自然 |
| D8 | 图标 | A `book`（文档）／B `code`（尖括号） | **B** | 「开发者中心」是容器（内含多模块），尖括号表达「代码/接口」比书本更贴合，且与 `wrench/link/puzzle` 视觉重量一致 |
| D9 | curl 示例的 base URL | A 后端返回配置里的 `host:port`／B 前端用 `location.origin` | **B** | 用户可能通过反代/局域网地址访问，后端配置值不一定等于用户实际地址；`location.origin` 恒为可用地址 |
| D10 | 搜索/筛选实现位置 | A 后端查询参数过滤／B 前端纯函数过滤 | **B** | 端点数仅 60+ 量级，一次性返回更简单；纯函数易在 Node 下直测，且离线可用 |
| D11 | 是否做在线试调（Try it out） | A 做／B 不做（列为演进） | **B** | 会引入写请求副作用、token 管理、CSRF 与误操作风险，超出「文档」范围；演进项留档 |
| D12 | 参数/响应详情的覆盖度 | A 一次补齐 60+ 端点全字段／B 结构支持全字段 + 首版只对高频写接口补齐，其余先给中文说明 | **B** | 全字段表单靠人工核对易出错；结构先支持（`params/body/response/example` 均可选），P1 内按组补齐高频项 |

## 三、任务详细设计

### 3.1 后端 `src/api/api-docs.ts`（新增）

```ts
// 纯数据 + 纯函数，无 IO，可在 Node 下直测
export interface ApiDocParam {
  name: string;
  in: 'path' | 'query' | 'body';
  type: string;         // 'string' | 'number' | 'boolean' | 'object' | 'string[]' ...
  required?: boolean;
  desc: string;
}
export interface ApiDocEntry {
  summary: string;                    // 中文一句话说明（非空）
  params?: ApiDocParam[];
  body?: string;                      // 请求体结构说明（代码片段文本）
  response?: string;                  // 响应结构说明（代码片段文本）
  example?: string;                   // curl 示例（不含 base URL，前端拼接）
  stream?: boolean;                   // 是否 SSE 流式
  scope?: 'read' | 'write';           // 只读/写操作（前端标签与排序用）
}
/** 键为 `METHOD /path`，如 'GET /sessions/:id' */
export const API_DOC_ENTRIES: Record<string, ApiDocEntry>;

/** 分组定义（顺序即展示顺序） */
export interface ApiDocGroup { key: string; title: string; desc: string; prefixes: string[]; }
export const API_DOC_GROUPS: ApiDocGroup[];
//   1 sessions  会话与系统        /health /status /sessions* /workspaces /fs/dirs
//   2 files     上传与文件        /uploads* /userdir/* /fs/*（除 /fs/dirs）
//   3 config    配置              /config*
//   4 models    模型与测速        /model* /models*
//   5 tools    工具              /tools*
//   6 extensions MCP 与技能       /mcp* /skills*
//   7 memory    记忆与 Dreaming   /memory*
//   8 system    诊断与视觉        /doctor /vision* /terminal/*
//   9 dev       开发者            /dev/*

/** 反射 + 合并：端点全集来自 routes，分组按 prefixes 最长匹配，未命中归 'other' 并 documented:false */
export function collectApiDocs(routes: { method: string; path: string }[]): ApiDocsPayload;
export interface ApiDocsPayload {
  version: string;
  groups: { key: string; title: string; desc: string; items: ApiDocItem[] }[];
  stats: { total: number; documented: number; undocumented: string[] };  // undocumented = 'METHOD /path' 列表
}
```

要点：

- 分组归属用 **prefix 最长匹配**（`/fs/dirs` 归 sessions、`/fs/tree` 归 files 由注册顺序 + 显式 `overrides` 处理，避免歧义）；
- `undocumented` 数组直接暴露缺口，前端展示 + 单测断言；
- 模块内**不 import** `router.ts`（避免循环依赖：`router.ts` → `handlers/dev.ts` → `api-docs.ts`），由 `dev.ts` 把 `createRoutes()` 结果传进来。

### 3.2 后端 `src/api/handlers/dev.ts`（新增）

```ts
export function devRoutes(): Route[] {
  return [{ method: 'GET', path: '/dev/api-docs', handler: handleApiDocs }];
}
```

- `handleApiDocs`：`collectApiDocs(createRoutes(ctx.deps, ...))` → `sendJson`；结果可按 `version` 做进程内缓存（一次构建、多次命中），`/dev/reload` 不做（文档随代码变化，重启即最新）。
- 在 `router.ts` 末尾 `...devRoutes()` 注册（静态段，无 `:param`，无冲突）。
- 错误处理：无输入 → 无 400；内部异常走既有 `ApiHttpError` → 500 JSON。

### 3.3 前端 `webui/src/api-docs-ui.ts`（新增，纯函数）

```ts
export type MethodFilter = 'all' | 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';
export function matchDocItem(item, kw: string): boolean;          // 方法/路径/说明三路小写匹配
export function filterDocs(payload, {kw, method}): ApiDocsPayload; // 保留有命中项的分组，组内按 path 稳定排序
export function docCounts(payload): { total: number; documented: number; byMethod: Record<string, number> };

```

### 3.4 前端 `webui/src/views/DevView.vue`（新增）

- 结构：页头（标题「开发者中心」+ 副标题「本服务对外开放的接口与约定」）+ tabs（`api`｜`auth`｜`sse`，`role=tablist/tab/tabpanel`，hash `?tab=` 还原，非法值回落 `api`）+ 三个 `<section v-show>`。
- `tab=api`：统计条（共 N 个端点 / 已登记 M / 服务地址）+ 搜索框 + 方法下拉 + 分组列表（组标题 + 条数）+ 条目（method 徽标着色：GET 绿 / POST 蓝 / PUT 橙 / PATCH 紫 / DELETE 红，取既有令牌）+ 展开详情（参数表 / body / response / curl，一键复制）。
- `tab=auth`：鉴权三态卡（含「当前：仅本机 / Bearer」状态位，数据来自 `GET /config/api`? → **不从 config 读 token 明文**，仅显示 mode 与是否已配置）+ 错误码表（400/401/403/404/405/409/500）。
- `tab=sse`：事件帧表（`meta`/`delta`/`tool`/`done`/`error` 等，以 `src/api/sse.ts` 的实际帧类型为准，实现前逐一核对）+ 接入片段（`EventSource` 与 `fetch` 两种）。
- 空态/错误态：请求失败 → 卡片内「加载失败 + 重试」，不弹全局错误。
- 样式：全部走既有 class 命名与令牌，不新增色值；`prefers-reduced-motion` 下禁用展开动画。
