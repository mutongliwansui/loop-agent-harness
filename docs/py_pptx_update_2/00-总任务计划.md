# py-pptx 技能改进任务计划（第二期：总览）

> 本文档为 py-pptx 技能改进工作的**第二期总任务计划**，汇总问题清单、任务拆分、优先级、依赖关系与整体验收标准。
> 每个任务的详细文档见本目录下 `task-XX-*.md`。
>
> **技能源码根目录**：`.loop-agent/skills/py-pptx/`
> **复盘来源**：使用 py-pptx 从零生成《AI 赋能办公 · 提质增效》（13 页，国网深绿风格）的真实制作过程，全程经历多轮 lint 报错与修复，共暴露 10 个改进点（相对第一期新增/加深）。
> **前置说明**：第一期（`docs/py_pptx_update/`，9 个任务）已修复"样例不过门禁、溢出检查前置、SVG 预览 Shape、卡片/toc 判定、中性色豁免、错误 hint 兜底"等问题，本期为**第二期迭代**，聚焦真实项目暴露的**更深层摩擦点**。

---

## 一、项目背景

在制作《AI 赋能办公 · 提质增效》PPT 的过程中，即使第一期修复已落地（validate 0 错误通过），仍暴露出一批影响**交付效率**与**排版自由度**的问题，归纳为 10 项，按严重度分为三类：

1. **正确性问题（P0）**：富文本 span 测量与渲染不一致导致溢出误报；溢出报错无法定位"padding/border 叠加"类根因；卡片判定不可预期导致 2×2 功能卡片页被迫改版；
2. **约束冲突问题（P1）**：嵌套深度 ≤5 与标准内容页结构冲突、需扁平化牺牲可读性；正文字数下限对流程/图表页机械、被迫"凑字"；样例定义未使用的 ACCENT 误导新手；字号阶梯缺中间档导致排版僵硬；
3. **体验增强问题（P2）**：内置样例覆盖不足缺内容页高频骨架；调试手段单一（layout --debug 输出重定向失败）；富文本能力偏弱（不支持 lineHeight / 嵌套 span）。

本次改进以"**报错可定位、规则可预期、骨架可复用、排版有弹性**"为目标，共拆分 **7 个任务**。

## 五、全局验收标准

1. **测量一致**：同一段含 span 的富文本，layout 测量高度与 SVG 渲染高度**偏差 ≤ 1px**，不再出现"测量 381px vs 渲染实际"级差异；
2. **报错可定位**：所有溢出 error 给出"溢出方向 + 超出值 + 根因类别 + 1-2 条修法"，padding/border-box 叠加场景有专属提示；
3. **规则可预期**：2×2/3×N 功能卡片页不再误触 `card_row_max_pages`；纯色装饰元素不再误判为卡片导致填充率虚低；
4. **约束不冲突**：标准内容页结构（标题区+卡片+卡片文字）不触发嵌套深度警告；流程/图表页正文统计口径与页面形态匹配；
5. **样例无误导**：内置样例不定义未使用的主题色常量；字号阶梯区间连续无断裂；
6. **骨架可复用**：每个风格包提供 ≥3 种内容页骨架，全部通过 lint 门禁，可直接套用改内容；
7. **调试可靠**：`layout --debug` 输出在 Windows 可重定向保存，含节点层级与 rect 明细；
8. **回归验证**：用《AI 赋能办公 · 提质增效》13 页重跑 validate/build/preview，0 错误；第一期样例 `state-grid-template` 不产生新错误；
9. **全量测试**：`pytest tests/` 全绿（或仅保留有明确说明的既有失败），新增用例覆盖上述全部修复点。

## 六、风险与注意事项

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 富文本测量模型复杂度上升 | 引入新的测量偏差 | 测量与渲染共用同一"run 解析"函数，杜绝两套逻辑；用快照测试锁定 |
| 卡片判定放宽过度 | 真卡片横排页漏检 | 判定分层：形态判定 + 内容判定 + 尺寸判定，任何一层不满足即排除；保留调试日志 |
| 字数统计纳入卡片文字后口径混乱 | 不同页面统计方式不一致 | 统计口径写入 rules.json 与文档，单一数据源；测试锁定 |
| 骨架库样例与规则冲突反复 | 任务延后 | 骨架库仅用已验证规则内能力；每个骨架过 lint 后入库 |
| `layout --debug` 重定向修复涉及编码 | Windows 环境兼容问题 | 输出统一 UTF-8，重定向时显式写文件而非仅 stdout |
