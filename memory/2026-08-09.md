| 🧠 **三层记忆管理** | L1 工作记忆 / L2 情景记忆 / L3 核心记忆，上下文自动压缩，跨会话知识积累 |
| 🔧 **分层配置系统** | CLI > 工作空间 > 全局 > .env > 默认值，多层覆盖，来源可追溯 |
| 🎛️ **运行时配置管理** | CLI 内置 `/config`、`/mcp`、`/tools` 命令，支持热修改 |
| 💾 **会话持久化** | 对话历史 AES-256-GCM 加密存储，跨进程自动保存 / 手动恢复 |
| 📝 **调试日志** | 文件日志记录 LLM 请求/响应、工具调用、Agent 迭代，自动轮转 |
| 🎯 **事件监听** | 参考 LangChain callbacks 设计，9 个生命周期钩子便于扩展 |
| 💬 **多轮对话** | 跨 `run()` 调用持久化消息历史，支持上下文续接 |
| ⚡ **同轮多工具** | 支持 LLM 单轮返回多个 `tool_calls`，`Promise.all` 并发执行 |
| 🛡️ **失败隔离** | 单个工具失败不影响其他工具，工具不存在时返回错误 Observation 让 Agent 继续推理 |
| 🔁 **自动重试** | LLM 调用对网络错误与 429 速率限制自动重试（指数退避） |
| 🗣️ **错误友好** | 401/403/404 等错误抛出明确中文提示，便于快速定位问题 |

## 💻 编程式调用

### 基础单轮调用

```typescript
import { agent } from './src/agent/react-agent.js';
import { registerBuiltinTools } from './src/tools/index.js';

// 注册内置工具（每个进程只需调用一次）
registerBuiltinTools();

// 单次调用
const result = await agent.run('帮我读取 package.json 的版本号', {
  verbose: true,       // 输出 Thought/Action/Observation 日志
  resetHistory: true,  // 清空历史，开始新会话
});

console.log(result.answer);
console.log(`迭代: ${result.iterations}, 步骤: ${result.steps.length}`);
```

### 多轮对话

```typescript
// 第一轮：读取 package.json
const r1 = await agent.run('package.json 里项目叫什么名字？', {
  resetHistory: true,
  verbose: false,
});
console.log(r1.answer);

// 第二轮 —— 自动复用历史上下文，无需显式传 messages
const r2 = await agent.run('那它的版本号是多少？');
// Agent 已经知道 package.json 的内容，可以直接回答，无需再次调用工具
console.log(r2.answer);
```

### 会话持久化

```typescript
import { agent } from './src/agent/react-agent.js';
import { SessionStore } from './src/session/index.js';
import { registerBuiltinTools } from './src/tools/index.js';

registerBuiltinTools();

// 初始化会话存储（按当前工作空间路径隔离）
const sessionStore = new SessionStore(process.cwd());
await sessionStore.init();
agent.setSessionStore(sessionStore);

// run() 结束后若配置 session.autoSave=true，会自动创建/更新会话
const result = await agent.run('帮我读取 package.json', {
  resetHistory: true,

console.log(`会话 ID: ${agent.currentSessionId}`);
```

```typescript
import { agent } from './src/agent/react-agent.js';
```

### ReAct 循环流程

```
  ┌─────────────────────────────────────────────────────┐
  │  1. 构造 messages（system + user，或复用历史）       │
  └────────────────────┬────────────────────────────────┘
                       │
                       ▼
  ┌─────────────────────────────────────────────────────┐
  │  2. 流式调用 LLM（chatStream）                       │
  │     实时通过 events.onLLMStream 输出 Thought         │
  └────────────────────┬────────────────────────────────┘
                       │
                       ▼
  ┌─────────────────────────────────────────────────────┐
  │  3. 流结束后得到完整 LLMResponse                     │
  └────────────────────┬────────────────────────────────┘
                       │
                       ▼
          ┌────────────────────────────┐
          │  4. 检查 tool_calls        │
          │                            │
          │   ┌─── 无 tool_calls ──┐   │
          │   │ 返回 content 作为  │   │
          │   │   Final Answer     │   │
          │   └────────────────────┘   │
          │                            │
          │   ┌─── 有 tool_calls ──┐   │
          │   │ 并发执行所有工具   │   │
          │   │ 拼接 Observation   │   │
          │   │ 回 messages        │   │
          │   └────────┬───────────┘   │
          └────────────┼───────────────┘
                       │
                       ▼
          ┌────────────────────────────┐
          │  5. 回到步骤 2，继续迭代   │
          └────────────────────────────┘
                       │
          ┌────────────┴────────────┐
          │  6. 达到最大迭代次数    │
          │  → 抛出错误，优雅退出   │
          └─────────────────────────┘
```

> `run()` 结束后，若启用了会话存储（`session.autoSave=true`），当前 messages 与 steps 会自动加密保存到磁盘。若启用了记忆系统，工具调用结果与关键信息还会写入 L2 情景记忆。

## 🧩 工具扩展

### 新增自定义工具

```typescript
import type { Tool } from './src/types.js';
import { registry } from './src/tools/registry.js';

const myTool: Tool = {
  name: 'myTool',
  description: '我的自定义工具',
  parameters: {
    type: 'object',
    properties: {
      input: { type: 'string', description: '输入内容' },
    },
    required: ['input'],
  },
  async execute(args) {
    const input = String(args.input);
    return `处理结果: ${input}`;
  },
};

// 注册到全局注册表
registry.register(myTool);
```

### 接入 MCP 外部工具

MCP（Model Context Protocol）是一种标准化的工具接入协议，支持 stdio 和 SSE 两种传输方式。

#### 方式一：配置文件（推荐）

创建 `.mcp.json` 或通过 CLI 的 `/mcp add` 命令交互式添加：

```json
{
  "mcpServers": {
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]
    },
    "fetch": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-fetch"]
    }
  }
}
```

项目启动时会自动加载配置并注册所有 MCP server 的工具。工具名规则：`{serverName}__{toolName}`（如 `filesystem__read_file`）。

#### 方式二：CLI 交互式添加

启动后输入 `mcp add my-server`，按提示输入传输类型、命令/URL 等，自动测试连接后写入配置。

#### 方式三：编程式接入

```typescript
import { registry } from './src/tools/registry.js';

await registry.registerMCPServer('filesystem', {
  type: 'stdio',
  command: 'npx',
  args: ['-y', '@modelcontextprotocol/server-filesystem', '.'],
});

// 注册成功后，可通过 registry.list() 查看所有工具
// MCP 工具名示例：filesystem__read_file, filesystem__write_file
```

#### 方式四：SSE 协议接入

```typescript
await registry.registerMCPServer('my-server', {
  type: 'sse',
  url: 'http://localhost:3000/mcp',
});
```

> **注意**：单个 MCP server 连接失败不影响其他 server 或内置工具（失败隔离）。

## 🎯 Skill 技能包

基于 **Claude Code Skills** 与 **DeepAgents Skills** 规范设计，支持将领域技能（如 PDF 处理、网页调研、部署流程等）打包为 `SKILL.md`，让 Agent 按需渐进式加载执行。

### 目录结构

```
~/.loop-agent/                    # 用户目录
├── skills/                       # 全局 Skill（所有项目可用）
│   ├── pdf-processing/
│   │   └── SKILL.md
│   └── web-research/
│       └── SKILL.md
│
<current-workspace>/              # 当前项目
├── skills/                       # 工作空间 Skill（仅当前项目可用，优先）
│   └── example-skill/
│       ├── SKILL.md
│       ├── scripts/              # 可选：执行脚本
│       ├── references/          # 可选：参考文档
│       └── assets/               # 可选：模板/资源
```

### SKILL.md 格式规范

```markdown
---
name: pdf-processing
description: Extract text and tables from PDF files, fill forms, merge documents.
---

# PDF Processing

## When to use this skill
Use this skill when the user needs to work with PDF files...

## How to extract text
1. Use pdfplumber for text extraction...
```

**YAML Frontmatter 字段**：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | Skill 唯一标识，用于 LLM 匹配和调用 |
| `description` | ✅ | 简短描述，LLM 据此判断何时使用该 Skill |

### 工作流程

```
启动时：
  1. 扫描 ~/.loop-agent/skills/  → 全局 Skill 元信息
  2. 扫描 <cwd>/skills/         → 工作空间 Skill 元信息
  3. 合并去重（工作空间优先）
  4. 将所有 SkillMetadata 注入 System Prompt

运行时：
  1. LLM 根据用户意图选择 Skill
  2. Agent 调用 activate_skill(name) 工具
  3. 读取 SKILL.md 完整正文并追加到上下文
  4. LLM 基于 Skill 详细说明继续推理
```

### 配置

```jsonc
{
  "skill": {
    "enabled": true,                        // 是否启用 Skill 功能
    "globalDir": "~/.loop-agent/skills",    // 全局 Skill 目录
    "workspaceDir": "skills",               // 工作空间 Skill 目录
    "autoLoad": true                        // 启动时自动扫描
  }
}
```

> **命名冲突**：同名 Skill 同时存在于全局与工作空间时，**工作空间版本优先**。

## 🧠 记忆管理

基于 **OpenClaw Tier Model** 设计的三层记忆架构。核心思想：**文件是真相源，索引只做加速；写读路径分离；晋升有闸门。**

### 三层架构

| 层级 | 存储形态 | 生命周期 | 自动进 context | 写入触发者 |
|---|---|---|---|---|
| **L1 工作记忆** | RAM 中 `_chatHistory` 数组 | 单次会话 | ✅ 始终在 | ReAct 循环自身 |
| **L2 情景记忆** | `{cwd}/memory/YYYY-MM-DD.md` | 永久存档 | ❌ 按需检索（`/memory search`） | Pre-compaction flush / 工具回调 |
| **L3 核心记忆** | `{cwd}/SOUL.md` / `USER.md` / `MEMORY.md` | 永久常驻 | ✅ 启动注入 system prompt | 人工编辑 / Promise Gate 晋升 |

### 文件分工（L3）

| 文件 | 内容 | 写入权限 |
|---|---|---|
| `SOUL.md` | Agent 人格、核心价值观、行为准则 | 仅系统初始化 / 人工编辑 |
| `USER.md` | 用户画像、稳定偏好、沟通风格 | 人工编辑 / `/memory curated append` |
| `MEMORY.md` | 精炼事实、跨会话关键知识 | 人工编辑 / `/memory curated append` |

### 工作机制

- **L1 工作记忆**：LLM 调用前估算 token 用量，超过阈值（默认 80% × 8000 tokens）时触发 **pre-compaction flush**——先让 LLM 将关键信息提取为结构化笔记写入 L2，再保留最近 3 轮对话完成压缩
- **L2 情景记忆**：按天分文件（`memory/YYYY-MM-DD.md`），追加写 only，保证不可变性；工具调用结果通过 `ToolMemoryCallback` 自动记录，支持关键词检索
- **L3 核心记忆**：每次 LLM 调用时作为 system prompt 常驻注入，token 开销可控（通常 < 1000 token）

### 配置

```jsonc
{
  "memory": {
    "enabled": true,
    "working": {
      "maxTokens": 8000,
      "compactionThreshold": 0.8,
      "keepRecentTurns": 3
    },
    "episodic": {
      "dir": "memory",
      "searchTopK": 3,
      "searchTimeoutMs": 500
    },
    "curated": {
      "files": ["SOUL.md", "USER.md", "MEMORY.md"]
    },
    "dreaming": {
      "enabled": true,
      "daysBack": 3,
      "onExit": true
    }
  }
}
```

### 降级策略

| 组件 | 失败行为 | 恢复方式 |
|---|---|---|
| L2 Episodic 写入 | 静默丢弃，不阻塞主流程 | 日志告警 |
| L2 Episodic 检索 | 返回空结果 | 跳过历史记忆，用 L1 + L3 对话 |
| L3 Curated 读取 | 返回空内容 | 仅用 L1 对话 |

> **原则**：记忆子系统挂了不能拖垮主回复。所有 memory 操作必须带 timeout/fallback。

## ⚙️ 配置管理

支持多层配置系统，优先级从高到低为：**CLI 参数 > 工作空间配置 > 全局配置 > 环境变量 > 默认值**。

### 配置层级

| 层级 | 文件位置 | 说明 |
|---|---|---|
| CLI 参数 | 运行时传入 | 最高优先级，仅内存中生效 |
| 工作空间 (workspace) | `{项目目录}/.agent-config.json` | 项目级配置，随项目分发 |
| 全局 (global) | `~/.loop-agent/config.json` | 用户级配置，跨项目共享 |
| 环境变量 (env) | `.env` 或 `process.env` | 向后兼容，支持原有环境变量 |
| 默认值 (default) | `DEFAULT_CONFIG` | 代码内置的默认值 |

### 配置结构

```json
{
  "model": {
    "name": "gpt-4o-mini",
    "baseUrl": "https://api.openai.com/v1",
    "apiKey": "sk-xxx",
    "temperature": 0,
    "maxIterations": 10

  "tools": {
    "enabled": ["commandRun", "fileRead", "fileWrite", "grep", "activate_skill"],
    "disabled": [],
    "mcpServers": {
      "filesystem": {
        "type": "stdio",
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]
      }
    }
  },
  "skill": {
    "enabled": true,
    "globalDir": "~/.loop-agent/skills",
    "workspaceDir": "skills",
    "autoLoad": true
  },
  "memory": {
    "enabled": true,
    "working": { "maxTokens": 8000, "compactionThreshold": 0.8, "keepRecentTurns": 3 },
    "episodic": { "dir": "memory", "searchTopK": 3, "searchTimeoutMs": 500 },
    "curated": { "files": ["SOUL.md", "USER.md", "MEMORY.md"] },
    "dreaming": { "enabled": true, "daysBack": 3, "onExit": true }

  "agent": {
    "verbose": true,
    "debug": false,
    "systemPrompt": null
  },
  "session": {
    "autoSave": true,
    "autoRestore": true,
    "encryptionEnabled": true
  }

```

| 配置段 | 字段 | 说明 | 默认值 |
|---|---|---|---|
| `model` | `name` / `baseUrl` / `apiKey` / `temperature` / `maxIterations` | LLM 模型配置 | `gpt-4o-mini` 等 |
| `tools` | `enabled` / `disabled` / `mcpServers` | 内置工具开关与 MCP server 配置 | 全部启用 |
| `skill` | `enabled` / `globalDir` / `workspaceDir` / `autoLoad` | Skill 技能包配置 | 启用，全局 `~/.loop-agent/skills`，工作空间 `skills` |
| `memory` | `enabled` / `working` / `episodic` / `curated` / `dreaming` | 三层记忆管理配置 | 启用，L1 阈值 80% |
| `agent` | `verbose` | 是否输出 Thought/Action/Observation 控制台日志 | `true` |
| `agent` | `debug` | 是否开启文件调试日志（见 📝 调试日志） | `false` |
| `agent` | `systemPrompt` | 自定义 system prompt 覆盖 | `null` |
| `session` | `autoSave` | `run()` 结束后自动保存会话到磁盘 | `true` |
| `session` | `autoRestore` | 启动时自动恢复最近会话 | `true` |
| `session` | `encryptionEnabled` | 会话文件是否加密存储（AES-256-GCM） | `true` |

### 环境变量（向后兼容）

| 环境变量 | 必填 | 说明 | 默认值 |
|---|---|---|---|
| `OPENAI_API_KEY` | ✅ | API Key | 无 |
| `OPENAI_BASE_URL` | ❌ | 模型服务地址 | `https://api.openai.com/v1` |
| `MODEL_NAME` | ❌ | 模型名称 | `gpt-4o-mini` |
| `MAX_ITERATIONS` | ❌ | Agent 最大迭代次数 | `10` |

| `DEBUG` | ❌ | 是否开启文件调试日志（`true`/`false`，输出到 `~/.loop-agent/logs`） | `false` |


## 🎧 事件监听器

参考 LangChain callbacks 设计，支持 **9 个生命周期钩子**。可叠加任意数量的监听器。

### 钩子列表

| 钩子 | 触发时机 | 参数 |
|---|---|---|
| `onStart` | Agent 开始执行 | `input: string` |
| `onIterationStart` | 每轮迭代开始 | `iteration: number, maxIterations: number` |
| `onLLMStream` | LLM 流式输出文本片段 | `delta: string` |
| `onLLMEnd` | 每轮 LLM 调用结束 | `response: LLMResponse, iteration: number` |
| `onToolStart` | 工具开始执行 | `tool: string, args: Record<string, unknown>` |
| `onToolEnd` | 工具执行结束 | `tool: string, result: string` |
| `onFinal` | Agent 给出最终答案 | `answer: string` |
| `onError` | 发生错误 | `error: Error` |
| `onEnd` | Agent 执行结束（成功或失败） | `result: AgentResult \| null` |

### 多个监听器叠加

```typescript
import { agent } from './src/agent/react-agent.js';
import type { AgentEvents } from './src/types.js';

// 日志记录器
const auditLogger: AgentEvents = {
  onToolStart: (tool, args) => {
    console.log(`[AUDIT] 调用工具: ${tool}`);
  },
  onFinal: (answer) => {
    console.log(`[AUDIT] 最终答案长度: ${answer.length} 字符`);
  },
};

// 性能监控器
const metricsCollector: AgentEvents = {
  onStart: () => { performance.mark('agent-start'); },
  onEnd: () => {
    performance.measure('agent-duration', 'agent-start');
    const duration = performance.getEntriesByName('agent-duration')[0].duration;
    console.log(`[METRICS] 耗时: ${duration.toFixed(0)}ms`);
  },
};

const result = await agent.run('帮我搜索文件', {
  events: [auditLogger, metricsCollector],
});
```

> **注意**：单个监听器抛错会被捕获，不影响其他监听器与主循环。

## 💬 多轮对话

Agent 实例内部维护 `_chatHistory`，跨 `run()` 调用自动持久化消息历史。

### 行为规则

| 场景 | 行为 |
|---|---|
| 首次调用 `run(input)` | 自动创建新会话（system + user） |
| 连续调用 `run(input)` | 自动复用上次的 `_chatHistory`，追加新的 user 消息 |
| `run(input, { resetHistory: true })` | 清空历史，开始全新会话 |
| `run(input, { messages: [...] })` | 使用外部传入的消息历史（会补上 system prompt） |
| `agent.resetSession()` | 手动清空持久化的历史 |
| `agent.getSessionMessages()` | 获取当前会话的消息历史（只读拷贝） |

### 多轮对话示例

```typescript
// 第一轮：读取文件
const r1 = await agent.run('读取 package.json', { resetHistory: true });
// 第二轮：基于第一轮的结果继续追问
const r2 = await agent.run('这个项目的版本号是多少？');
// 此时 Agent 已知道 package.json 内容，可直接回答
```

> **进程内**多轮由 `_chatHistory` 保证；**跨进程**恢复请使用 `SessionStore` 持久化（见下节）。

## 💾 会话持久化

Agent 内置了基于文件系统的会话持久化能力：对话历史（messages + steps）加密存储到本地磁盘，重启 CLI 后可通过 `/session load <id>` 恢复上下文继续对话。

### 存储结构

```
~/.loop-agent/
├── .keyfile                      # 🔑 主密钥文件（首次自动生成，权限 0600）
├── config.json                   # 全局配置（可选）
├── logs/
│   └── debug-YYYY-MM-DD.log      # 📝 调试日志（见下节）
└── sessions/
    └── {workspaceId}/            # 按工作空间路径隔离（路径 SHA-256 前 16 位）
        ├── meta.json             # 工作空间元信息
        ├── sessions.json         # 会话索引（仅元信息，不含消息内容）
        └── sess_YYYYMMDD_HHMMSS.enc   # 加密的会话数据文件
```

### 加密机制

- **主密钥**：首次使用时自动生成 256-bit 随机密钥，保存于 `~/.loop-agent/.keyfile`（`0600` 权限），无需用户输入密码
- **数据加密**：会话消息通过 **PBKDF2（100,000 次迭代）派生** + **AES-256-GCM** 加密，附带认证标签保证完整性
- **密钥校验**：密钥文件包含校验 token，读取时会验证密钥完整性，损坏则报错
- **索引明文**：`sessions.json` 仅存储会话元信息（ID、标题、消息数、时间），消息内容全部加密

### 自动保存 / 恢复

- **自动保存**：`run()` 结束后，若 `session.autoSave=true` 且已设置 SessionStore，自动创建新会话或更新当前会话
- **自动恢复**：`session.autoRestore=true` 时，CLI 启动会自动加载最近一次会话，无缝续接上次对话
- **手动控制**：可通过 `/session` 子命令随时 list / load / save / new / delete

### 密钥管理（Keychain）

`src/session/keychain.ts` 提供密钥生命周期管理：

| 方法 | 说明 |
|---|---|
| `keychain.ensureUnlocked()` | 确保密钥已加载（首次自动生成密钥文件） |
| `keychain.exportKey()` | 导出主密钥（base64，用于备份） |
| `keychain.importKey(base64)` | 从备份导入主密钥（用于迁移/恢复） |
| `keychain.reset()` | 删除密钥文件（⚠️ 会导致所有加密会话无法解密） |

> ⚠️ **重要**：`.keyfile` 是解密会话的唯一凭证。丢失该文件将导致所有加密会话无法恢复，建议定期 `exportKey()` 备份。

## 📝 调试日志

Agent 内置了文件型调试日志系统（`src/debug.ts`），可将 LLM 请求/响应、工具调用、Agent 迭代过程完整记录到本地文件，便于问题排查。

### 开启方式

```bash
# 方式一：环境变量
DEBUG=true npm start

# 方式二：运行时配置
/config set agent.debug true
```

开启后 CLI 启动会提示：

```
⚠ 调试模式已开启，日志输出到: C:\Users\xxx\.loop-agent\logs
```

### 日志位置与轮转

- **位置**：`~/.loop-agent/logs/debug-YYYY-MM-DD.log`（按日期分文件）
- **轮转**：单文件最大 **10MB**，超出后自动轮转，最多保留 **5** 个历史文件
- **脱敏**：日志中的 API Key 自动脱敏（仅显示首尾各 4 位）

### 日志内容

| 类型 | 触发时机 | 记录内容 |
|---|---|---|
| `llmRequest` | 每次 LLM 请求 | 模型、消息数、工具数、脱敏后的参数 |
| `llmResponse` | LLM 响应返回 | 内容（截断 300 字符）、工具调用、耗时 |
| `llmError` | LLM 调用报错 | 错误信息、耗时 |
| `toolCall` | 每次工具调用 | 工具名、参数、结果（均截断）、耗时 |
| `iteration` | 每轮 Agent 迭代 | Thought / Action / Observation |
| `session` | 每次 `run()` 开始 | 消息数、工具数、会话 ID |

### 编程式读取

```typescript
import { debug } from './src/debug.js';

// 当前日志文件路径
const logPath = debug.getLogPath();

// 读取最近日志内容（默认最多 10000 字符）
const content = debug.readLog(10000);
```

## 🔍 故障排查

### API Key 无效或已过期

```
错误：API Key 无效或已过期，请检查 .env 中的 OPENAI_API_KEY
```

**解决**：检查 `.env` 中 `OPENAI_API_KEY` 是否正确，是否与 `OPENAI_BASE_URL` 对应的服务商匹配。也可通过 `/config set model.apiKey <key>` 运行时修改。

### 模型不存在（404）

```
错误：模型不存在（404），请检查 .env 中的 MODEL_NAME（当前: xxx）
```

**解决**：确认 `MODEL_NAME` 在目标服务商上可用。通过 `/config set model.name <新模型名>` 运行时修改。

### 请求过于频繁（429）

```
错误：请求过于频繁（429），请稍后重试或降低调用频率
```

**解决**：降低调用频率。集成测试默认串行执行（`fileParallelism: false`）避免并发限速。

### 工具执行超时

```
错误：工具执行超时 (30000ms)
```

**解决**：`commandRun` 工具默认 30s 超时，可通过 `timeout` 参数调整。复杂命令建议拆分为多步执行。

### Windows 终端中文乱码

**解决**：CLI 启动时已自动执行 `chcp 65001` 切换到 UTF-8。如仍乱码，手动运行 `chcp 65001` 后再启动。

### 达到最大迭代次数

```
错误：达到最大迭代次数 10，Agent 未能给出最终答案
```

**解决**：增大 `.env` 中 `MAX_ITERATIONS`，或通过 `/config set model.maxIterations 20` 运行时修改。也可以简化问题描述，让 Agent 在更少步骤内完成。

### 工具未注册

```
错误：工具 xxx 未注册
```

**解决**：调用 `registerBuiltinTools()` 注册内置工具，或通过 `registry.register(tool)` 注册自定义工具。也可通过 `/tools reload` 重新加载。

### Skill 未找到

```
错误：Skill "xxx" 未找到
```

**解决**：确认 SKILL.md 存在于 `~/.loop-agent/skills/<name>/` 或 `<cwd>/skills/<name>/`，且 YAML frontmatter 包含 `name` 与 `description`。可通过 `/skill list` 查看已发现的 Skill。

### MCP 连接失败

```
错误：MCP server xxx 连接失败
```

**解决**：检查 MCP 配置是否正确，可执行 `/mcp test <name>` 测试连接。使用 `/mcp remove <name>` 移除后重新 `/mcp add <name>` 添加。

### 会话无法加载 / 解密失败

```
错误：密钥文件损坏，验证失败
错误：密钥未加载，无法读取会话
```

**解决**：
- 检查 `~/.loop-agent/.keyfile` 是否存在且未损坏
- 若误删/损坏，可通过备份的 `exportKey()` 导出的 base64 调用 `keychain.importKey()` 恢复
- 若无法恢复，可删除损坏的会话文件（`/session delete <id>`）后重新开始

### 调试日志未生成

**解决**：确认已通过 `DEBUG=true` 环境变量或 `/config set agent.debug true` 开启调试模式，日志输出到 `~/.loop-agent/logs/debug-YYYY-MM-DD.log`。开启后 CLI 启动 banner 会显示调试日志目录提示。

### 配置来源追踪

当配置未按预期生效时，可通过 `/config list` 查看每个字段的实际来源（cli / workspace / global / env / default），快速定位是哪一层覆盖了配置。

| 特性 | 说明 |
|---|---|
| 🔄 **ReAct 循环** | Thought → Action → Observation 逐步推理，直到得出最终答案 |
| 📡 **流式输出** | LLM 推理过程实时流式输出，支持 `content` 与 `tool_calls` 分片拼接 |

| 🧠 **三层记忆管理** | L1 工作记忆（token 压缩）/ L2 情景记忆（按天 Markdown）/ L3 核心记忆（SOUL/USER/MEMORY 常驻注入） |

### CLI 命令详解

#### `/config` — 配置管理

支持对工作空间（默认）和全局两个层级的配置进行读写：

```
/config list                    # 查看当前生效配置（含每一字段的来源标记）
/config get <key>               # 查看某个配置项（如 model.name）
/config set <key> <value>       # 设置配置项（默认写入工作空间）
/config set <key> <value> --global  # 写入全局配置
/config delete <key>            # 删除某配置项
/config path                    # 查看配置文件路径
```

配置值支持自动识别类型：`true`/`false` 为布尔值，数字自动转为 Number，`{...}` 或 `[...]` 自动解析为 JSON。

#### `/mcp` — MCP 管理

```
/mcp list                       # 列出所有 MCP Server 配置及连接状态
/mcp add <name>                 # 交互式添加新 MCP Server
/mcp remove <name>              # 移除指定 MCP Server
/mcp reload                     # 重新加载全部 MCP 配置
/mcp test <name>                # 测试连接指定 MCP Server
```

#### `/tools` — 工具管理

```
/tools list                     # 列出所有已注册工具（内置 + MCP）
/tools enable <name>            # 启用内置工具
/tools disable <name>           # 禁用内置工具
/tools reload                   # 重新加载所有工具
```

#### `/skill` — Skill 管理

```
/skill list                     # 列出所有可用 Skill（全局 + 工作空间，工作空间优先）
/skill reload                   # 重新扫描 Skill 目录
/skill show <name>              # 显示指定 Skill 的 SKILL.md 完整内容
```

#### `/memory` — 记忆管理

```
/memory status                        # 查看记忆系统状态（启用状态 / L2 天数 / L3 文件 / L1 配置）
/memory curated list                  # 列出 L3 核心记忆文件（SOUL/USER/MEMORY）
/memory curated read <soul|user|memory>  # 读取指定核心记忆文件内容
/memory curated append <soul|user|memory> <内容>  # 向核心记忆文件追加一条事实
/memory episodic list                 # 列出 L2 情景记忆日志（按天摘要）
/memory episodic read <YYYY-MM-DD>    # 读取指定日期的情景记忆
/memory search <关键词>               # 搜索 L2 情景记忆（返回相关片段 + 相关性分数）
```

#### `/session` — 会话管理

```
/session list                   # 列出当前工作空间所有会话（ID / 标题 / 消息数 / 时间）
/session current                # 查看当前会话详情
/session load <id>              # 加载指定会话，恢复历史对话
/session save                   # 手动保存当前会话
/session new                    # 新建会话（旧会话自动保存）
/session delete <id>            # 删除指定会话
/session delete-all             # 删除当前工作空间的所有会话（需二次确认）
```

### ReAct 循环流程

```
  ┌─────────────────────────────────────────────────────┐
  │  1. 构造 messages（system + user，或复用历史）       │
  └────────────────────┬────────────────────────────────┘
                       │
                       ▼
  ┌─────────────────────────────────────────────────────┐
  │  2. 流式调用 LLM（chatStream）                       │
  │     实时通过 events.onLLMStream 输出 Thought         │
  └────────────────────┬────────────────────────────────┘
                       │
                       ▼
  ┌─────────────────────────────────────────────────────┐
  │  3. 流结束后得到完整 LLMResponse                     │
  └────────────────────┬────────────────────────────────┘
                       │
                       ▼
          ┌────────────────────────────┐
          │  4. 检查 tool_calls        │
          │                            │
          │   ┌─── 无 tool_calls ──┐   │
          │   │ 返回 content 作为  │   │
          │   │   Final Answer     │   │
          │   └────────────────────┘   │
          │                            │
          │   ┌─── 有 tool_calls ──┐   │
          │   │ 并发执行所有工具   │   │
          │   │ 拼接 Observation   │   │
          │   │ 回 messages        │   │
          │   └────────┬───────────┘   │
          └────────────┼───────────────┘
                       │
                       ▼
          ┌────────────────────────────┐
          │  5. 回到步骤 2，继续迭代   │
          └────────────────────────────┘
                       │
          ┌────────────┴────────────┐
          │  6. 达到最大迭代次数    │
          │  → 抛出错误，优雅退出   │
          └─────────────────────────┘
```

> `run()` 结束后，若启用了会话存储（`session.autoSave=true`），当前 messages 与 steps 会自动加密保存到磁盘。

## 🔧 内置工具

| 工具 | 名称 | 说明 | 参数 |
|---|---|---|---|
| 🖥️ **命令执行** | `commandRun` | 在本地执行 shell 命令，返回 stdout + stderr | `command`（必填）, `cwd`（可选）, `timeout`（可选，默认 30000ms） |
| 📄 **文件读取** | `fileRead` | 读取文件内容，支持按行范围部分读取 | `path`（必填）, `startLine`（可选）, `endLine`（可选）, `encoding`（可选） |
| ✏️ **文件写入** | `fileWrite` | 写入文件，支持覆盖与追加，自动创建父目录 | `path`（必填）, `content`（必填）, `mode`（可选，`overwrite` / `append`） |
| 🔍 **内容检索** | `grep` | 在文件或目录中检索内容，支持正则、忽略大小写、递归搜索 | `pattern`（必填）, `path`（必填）, `ignoreCase`（可选）, `recursive`（可选）, `maxResults`（可选，默认 50） |
| 🧩 **Skill 激活** | `activate_skill` | 按名称激活指定的 Skill（技能包），返回该 Skill 的完整指令内容，供 Agent 按步骤执行 | `name`（必填） |

### 工具使用示例

```bash
# 命令执行
commandRun({ "command": "dir", "cwd": "." })

# 文件读取（全文）
fileRead({ "path": "package.json" })

# 文件读取（部分行）
fileRead({ "path": "src/agent/react-agent.ts", "startLine": 1, "endLine": 20 })

# 文件写入
fileWrite({ "path": "output.txt", "content": "Hello World", "mode": "overwrite" })

# 内容检索
grep({ "pattern": "config", "path": "src", "ignoreCase": true, "maxResults": 20 })

# Skill 激活（返回 SKILL.md 完整内容）
activate_skill({ "name": "example-skill" })
```

### 接入 MCP 外部工具

MCP（Model Context Protocol）是一种标准化的工具接入协议，支持 stdio 和 SSE 两种传输方式。

#### 方式一：配置文件（推荐）

创建 `.mcp.json` 或通过 CLI 的 `/mcp add` 命令交互式添加：

```json
{
  "mcpServers": {
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]
    },
    "fetch": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-fetch"]
    }
  }
}
```

项目启动时会自动加载配置并注册所有 MCP server 的工具。工具名规则：`{serverName}__{toolName}`（如 `filesystem__read_file`）。

#### 方式二：CLI 交互式添加

启动后输入 `mcp add my-server`，按提示输入传输类型、命令/URL 等，自动测试连接后写入配置。

#### 方式三：编程式接入

```typescript
import { registry } from './src/tools/registry.js';

await registry.registerMCPServer('filesystem', {
  type: 'stdio',
  command: 'npx',
  args: ['-y', '@modelcontextprotocol/server-filesystem', '.'],
});

// 注册成功后，可通过 registry.list() 查看所有工具
// MCP 工具名示例：filesystem__read_file, filesystem__write_file
```

#### 方式四：SSE 协议接入

```typescript
await registry.registerMCPServer('my-server', {
  type: 'sse',
  url: 'http://localhost:3000/mcp',
});
```

> **注意**：单个 MCP server 连接失败不影响其他 server 或内置工具（失败隔离）。

## 🧩 Skill 能力

Skill（技能包）是一种将**特定领域的完整操作指令**封装为可复用资源的能力。Agent 启动时自动扫描全局与工作空间目录下的 Skill，将元信息注入 System Prompt 供 LLM 发现，当用户请求匹配某个 Skill 时，通过 `activate_skill` 工具**渐进式加载**该 Skill 的完整指令（SKILL.md），指导 Agent 按规范执行任务。

### Skill 目录结构

```
~/.loop-agent/                    # 🔗 全局 Skill（所有项目可用）
├── skills/
│   ├── pdf-processing/
│   │   └── SKILL.md
│   └── web-research/
│       └── SKILL.md
│
<current-workspace>/              # 📂 工作空间 Skill（仅当前项目可用，优先级更高）
├── skills/
│   └── custom-deploy/
│       ├── SKILL.md
│       ├── scripts/              # 可选：执行脚本
│       ├── references/           # 可选：参考文档
│       └── assets/               # 可选：模板/资源
```

### SKILL.md 格式

每个 Skill 是一个包含 `SKILL.md` 的目录，文件以 YAML frontmatter 声明元信息，正文编写具体操作指令：

```markdown
---
name: pdf-processing
description: Extract text and tables from PDF files, fill forms, merge documents.
---

# PDF Processing

## When to use this skill
Use this skill when the user needs to work with PDF files...

## How to extract text
1. Use pdfplumber for text extraction...
```

| Frontmatter 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | Skill 唯一标识，用于 LLM 匹配与 `activate_skill` 调用 |
| `description` | ✅ | 简短描述，LLM 据此判断何时使用该 Skill |

### 工作流程

```
启动时：
  1. 扫描 ~/.loop-agent/skills/  → 全局 Skill 元信息
  2. 扫描 <cwd>/skills/          → 工作空间 Skill 元信息
  3. 合并去重（工作空间优先覆盖同名全局 Skill）
  4. 将 SkillMetadata 列表注入 System Prompt

运行时：
  1. LLM 根据用户意图选择合适的 Skill
  2. Agent 调用内置工具 activate_skill({ name: "xxx" })
  3. 返回 SKILL.md 完整正文（含描述、作用域、操作步骤）
  4. LLM 基于 Skill 详细指令继续推理并执行任务
```

### CLI 管理

```
/skill list               → 列出所有可用 Skill（带作用域标记）
/skill reload             → 重新扫描 Skill 目录
/skill show <name>        → 显示指定 SKILL.md 完整内容
```

### 配置

| 配置项 | 说明 | 默认值 |
|---|---|---|
| `skill.enabled` | 是否启用 Skill 功能 | `true` |
| `skill.globalDir` | 全局 Skill 目录 | `~/.loop-agent/skills` |
| `skill.workspaceDir` | 工作空间 Skill 目录 | `./skills` |
| `skill.autoLoad` | 启动时是否自动扫描 | `true` |

## 🧠 记忆管理

Agent 内置了 OpenClaw 风格的三层记忆系统：**文件是真相源，索引只做加速；写读路径分离；晋升有闸门**。与 [💾 会话持久化](#-会话持久化)（解决会话恢复）互补，记忆管理解决的是**跨会话知识积累**。

### 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│              L1 Working Memory（工作记忆）                   │
│              内存中 _chatHistory 数组                       │
│              TTL: 单次会话                                   │
│              超阈值 → pre-compaction flush → L2             │
└──────────────────────┬──────────────────────────────────────┘
                       │ flush（确定性触发）
                       ▼
┌─────────────────────────────────────────────────────────────┐
│              L2 Episodic Memory（情景记忆）                  │
│              {cwd}/memory/YYYY-MM-DD.md 按天分文件          │
│              TTL: 长期留存，不自动注入 context               │
│              访问方式: /memory search 按需召回               │
└──────────────────────┬──────────────────────────────────────┘
                       │ promote（后台异步）
                       ▼
┌─────────────────────────────────────────────────────────────┐
│          L3 Curated Core Memory（核心记忆）                  │
│          {cwd}/SOUL.md / USER.md / MEMORY.md                │
│          TTL: 永久，启动时注入 system prompt                 │
│          内容: Agent 人格、用户画像、精炼事实                │
└─────────────────────────────────────────────────────────────┘
```

| 层级 | 存储形态 | 生命周期 | 自动进 context | 写入触发者 |
|---|---|---|---|---|
| L1 Working | RAM 中 `_chatHistory` 数组 | 单次会话 | ✅ 始终在 | ReAct 循环自身 |
| L2 Episodic | `{cwd}/memory/YYYY-MM-DD.md` | 永久存档 | ❌ 按需检索 | Pre-compaction refresh / 工具回调 |
| L3 Curated | `{cwd}/SOUL.md` / `USER.md` / `MEMORY.md` | 永久常驻 | ✅ 启动注入 | 人工编辑 / CLI 追加 |

### L3 核心记忆文件

| 文件 | 内容 | 说明 |
|---|---|---|
| `SOUL.md` | Agent 人格、核心价值观、行为准则 | 系统初始化生成，通常不自动修改 |
| `USER.md` | 用户画像、稳定偏好、沟通风格、约束 | 通过 `/memory curated append user ...` 追加 |
| `MEMORY.md` | 精炼事实、跨会话关键知识、项目决策 | 通过 `/memory curated append memory ...` 追加 |

### 工作记忆自动压缩（L1）

- 对话历史超过 `memory.working.maxTokens`（默认 8000）的 **80%** 触发压缩
- 压缩前先执行 **pre-compaction flush**：调用 LLM 将对话中的关键信息提取为结构化笔记写入 L2 当日日志，再截断为最近 `keepRecentTurns`（默认 3）轮
- 提取的信息覆盖：用户稳定偏好/约束、已确认事实与决策、未完成任务、工具调用关键结果

### CLI 管理

```
/memory status                                → 查看记忆系统状态
/memory curated list / read <key> / append <key> <内容>   → L3 核心记忆管理
/memory episodic list / read <YYYY-MM-DD>     → L2 情景记忆阅读
/memory search <关键词>                       → 搜索 L2 情景记忆
```

### 配置

```jsonc
{
  "memory": {
    "enabled": true,                    // 是否启用记忆系统
    "working": {                        // L1 工作记忆
      "maxTokens": 8000,                // 最大 token 数（估算）
      "compactionThreshold": 0.8,       // 达到 80% 触发压缩
      "keepRecentTurns": 3              // 压缩后保留最近 3 轮
    },
    "episodic": {                       // L2 情景记忆
      "dir": "memory",                  // 存储目录
      "searchTopK": 3,                  // 检索返回条数
      "searchTimeoutMs": 500            // 检索超时（超时降级不阻塞）
    },
    "curated": {                        // L3 核心记忆
      "files": ["SOUL.md", "USER.md", "MEMORY.md"]
    },
    "dreaming": {                       // 晋升流水线（规划中）
      "enabled": true,
      "daysBack": 3,
      "onExit": true
    }
  }
}
```

> **设计原则**：记忆子系统失败不影响主回复路径 —— 所有 memory 操作带超时/降级；L2 按天追加写入、不可变；L3 内容始终 < 1K token，常驻注入开销可控。

## ⚙️ 配置管理

支持多层配置系统，优先级从高到低为：**CLI 参数 > 工作空间配置 > 全局配置 > 环境变量 > 默认值**。

### 配置层级

| 层级 | 文件位置 | 说明 |
|---|---|---|
| CLI 参数 | 运行时传入 | 最高优先级，仅内存中生效 |
| 工作空间 (workspace) | `{项目目录}/.agent-config.json` | 项目级配置，随项目分发 |

## 🎧 事件监听器

参考 LangChain callbacks 设计，支持 **9 个生命周期钩子**。可叠加任意数量的监听器。

### 钩子列表

| 钩子 | 触发时机 | 参数 |
|---|---|---|
| `onStart` | Agent 开始执行 | `input: string` |
| `onIterationStart` | 每轮迭代开始 | `iteration: number, maxIterations: number` |
| `onLLMStream` | LLM 流式输出文本片段 | `delta: string` |
| `onLLMEnd` | 每轮 LLM 调用结束 | `response: LLMResponse, iteration: number` |
| `onToolStart` | 工具开始执行 | `tool: string, args: Record<string, unknown>` |
| `onToolEnd` | 工具执行结束 | `tool: string, result: string` |
| `onFinal` | Agent 给出最终答案 | `answer: string` |
| `onError` | 发生错误 | `error: Error` |
| `onEnd` | Agent 执行结束（成功或失败） | `result: AgentResult \| null` |

### 多个监听器叠加

```typescript
import { agent } from './src/agent/react-agent.js';
import type { AgentEvents } from './src/types.js';

// 日志记录器
const auditLogger: AgentEvents = {
  onToolStart: (tool, args) => {
    console.log(`[AUDIT] 调用工具: ${tool}`);
  },
  onFinal: (answer) => {
    console.log(`[AUDIT] 最终答案长度: ${answer.length} 字符`);
  },
};

// 性能监控器
const metricsCollector: AgentEvents = {
  onStart: () => { performance.mark('agent-start'); },
  onEnd: () => {
    performance.measure('agent-duration', 'agent-start');
    const duration = performance.getEntriesByName('agent-duration')[0].duration;
    console.log(`[METRICS] 耗时: ${duration.toFixed(0)}ms`);
  },
};

const result = await agent.run('帮我搜索文件', {
  events: [auditLogger, metricsCollector],
});
```

> **注意**：单个监听器抛错会被捕获，不影响其他监听器与主循环。

## 💬 多轮对话

Agent 实例内部维护 `_chatHistory`，跨 `run()` 调用自动持久化消息历史。

### 行为规则

| 场景 | 行为 |
|---|---|
| 首次调用 `run(input)` | 自动创建新会话（system + user） |
| 连续调用 `run(input)` | 自动复用上次的 `_chatHistory`，追加新的 user 消息 |
| `run(input, { resetHistory: true })` | 清空历史，开始全新会话 |
| `run(input, { messages: [...] })` | 使用外部传入的消息历史（会补上 system prompt） |
| `agent.resetSession()` | 手动清空持久化的历史 |
| `agent.getSessionMessages()` | 获取当前会话的消息历史（只读拷贝） |

### 多轮对话示例

```typescript
// 第一轮：读取文件
const r1 = await agent.run('读取 package.json', { resetHistory: true });
// 第二轮：基于第一轮的结果继续追问
const r2 = await agent.run('这个项目的版本号是多少？');
// 此时 Agent 已知道 package.json 内容，可直接回答
```

> **进程内**多轮由 `_chatHistory` 保证；**跨进程**恢复请使用 `SessionStore` 持久化（见下节）。

## 💾 会话持久化

Agent 内置了基于文件系统的会话持久化能力：对话历史（messages + steps）加密存储到本地磁盘，重启 CLI 后可通过 `/session load <id>` 恢复上下文继续对话。

### 存储结构

```
~/.loop-agent/
├── .keyfile                      # 🔑 主密钥文件（首次自动生成，权限 0600）
├── config.json                   # 全局配置（可选）
├── logs/
│   └── debug-YYYY-MM-DD.log      # 📝 调试日志（见下节）
└── sessions/
    └── {workspaceId}/            # 按工作空间路径隔离（路径 SHA-256 前 16 位）
        ├── meta.json             # 工作空间元信息
        ├── sessions.json         # 会话索引（仅元信息，不含消息内容）
        └── sess_YYYYMMDD_HHMMSS.enc   # 加密的会话数据文件
```

### 加密机制

- **主密钥**：首次使用时自动生成 256-bit 随机密钥，保存于 `~/.loop-agent/.keyfile`（`0600` 权限），无需用户输入密码
- **数据加密**：会话消息通过 **PBKDF2（100,000 次迭代）派生** + **AES-256-GCM** 加密，附带认证标签保证完整性
- **密钥校验**：密钥文件包含校验 token，读取时会验证密钥完整性，损坏则报错
- **索引明文**：`sessions.json` 仅存储会话元信息（ID、标题、消息数、时间），消息内容全部加密

### 自动保存 / 恢复

- **自动保存**：`run()` 结束后，若 `session.autoSave=true` 且已设置 SessionStore，自动创建新会话或更新当前会话
- **自动恢复**：`session.autoRestore=true` 时，CLI 启动会自动加载最近一次会话，无缝续接上次对话
- **手动控制**：可通过 `/session` 子命令随时 list / load / save / new / delete

### 密钥管理（Keychain）

`src/session/keychain.ts` 提供密钥生命周期管理：

| 方法 | 说明 |
|---|---|
| `keychain.ensureUnlocked()` | 确保密钥已加载（首次自动生成密钥文件） |
| `keychain.exportKey()` | 导出主密钥（base64，用于备份） |
| `keychain.importKey(base64)` | 从备份导入主密钥（用于迁移/恢复） |
| `keychain.reset()` | 删除密钥文件（⚠️ 会导致所有加密会话无法解密） |

> ⚠️ **重要**：`.keyfile` 是解密会话的唯一凭证。丢失该文件将导致所有加密会话无法恢复，建议定期 `exportKey()` 备份。

## 📝 调试日志

Agent 内置了文件型调试日志系统（`src/debug.ts`），可将 LLM 请求/响应、工具调用、Agent 迭代过程完整记录到本地文件，便于问题排查。

### 开启方式

```bash
# 方式一：环境变量
DEBUG=true npm start

# 方式二：运行时配置
/config set agent.debug true
```

开启后 CLI 启动会提示：

```
⚠ 调试模式已开启，日志输出到: C:\Users\xxx\.loop-agent\logs
```

### 日志位置与轮转

- **位置**：`~/.loop-agent/logs/debug-YYYY-MM-DD.log`（按日期分文件）
- **轮转**：单文件最大 **10MB**，超出后自动轮转，最多保留 **5** 个历史文件
- **脱敏**：日志中的 API Key 自动脱敏（仅显示首尾各 4 位）

### 日志内容

| 类型 | 触发时机 | 记录内容 |
|---|---|---|
| `llmRequest` | 每次 LLM 请求 | 模型、消息数、工具数、脱敏后的参数 |
| `llmResponse` | LLM 响应返回 | 内容（截断 300 字符）、工具调用、耗时 |
| `llmError` | LLM 调用报错 | 错误信息、耗时 |
| `toolCall` | 每次工具调用 | 工具名、参数、结果（均截断）、耗时 |
| `iteration` | 每轮 Agent 迭代 | Thought / Action / Observation |
| `session` | 每次 `run()` 开始 | 消息数、工具数、会话 ID |

### 编程式读取

```typescript
import { debug } from './src/debug.js';

// 当前日志文件路径
const logPath = debug.getLogPath();

// 读取最近日志内容（默认最多 10000 字符）
const content = debug.readLog(10000);
```

## 🔍 故障排查

### API Key 无效或已过期

```
错误：API Key 无效或已过期，请检查 .env 中的 OPENAI_API_KEY
```

**解决**：检查 `.env` 中 `OPENAI_API_KEY` 是否正确，是否与 `OPENAI_BASE_URL` 对应的服务商匹配。也可通过 `/config set model.apiKey <key>` 运行时修改。

### 模型不存在（404）

```
错误：模型不存在（404），请检查 .env 中的 MODEL_NAME（当前: xxx）
```

**解决**：确认 `MODEL_NAME` 在目标服务商上可用。通过 `/config set model.name <新模型名>` 运行时修改。

### 请求过于频繁（429）

```
错误：请求过于频繁（429），请稍后重试或降低调用频率
```

**解决**：降低调用频率。集成测试默认串行执行（`fileParallelism: false`）避免并发限速。

### 工具执行超时

```
错误：工具执行超时 (30000ms)
```

**解决**：`commandRun` 工具默认 30s 超时，可通过 `timeout` 参数调整。复杂命令建议拆分为多步执行。

### Windows 终端中文乱码

**解决**：CLI 启动时已自动执行 `chcp 65001` 切换到 UTF-8。如仍乱码，手动运行 `chcp 65001` 后再启动。

### 达到最大迭代次数

```
错误：达到最大迭代次数 10，Agent 未能给出最终答案
```

**解决**：增大 `.env` 中 `MAX_ITERATIONS`，或通过 `/config set model.maxIterations 20` 运行时修改。也可以简化问题描述，让 Agent 在更少步骤内完成。

### 工具未注册

```
错误：工具 xxx 未注册
```

**解决**：调用 `registerBuiltinTools()` 注册内置工具，或通过 `registry.register(tool)` 注册自定义工具。也可通过 `/tools reload` 重新加载。

### MCP 连接失败

```
错误：MCP server xxx 连接失败
```

**解决**：检查 MCP 配置是否正确，可执行 `/mcp test <name>` 测试连接。使用 `/mcp remove <name>` 移除后重新 `/mcp add <name>` 添加。

### Skill 未找到

```
Skill "xxx" 未找到。可用的 Skill: example-skill
```

**解决**：确认 Skill 目录存在于 `~/.loop-agent/skills/`（全局）或 `<cwd>/skills/`（工作空间），且包含合法的 `SKILL.md`（YAML frontmatter 含 `name` + `description`）。执行 `/skill reload` 重新扫描，通过 `/skill list` 查看已发现的 Skill。

### 会话无法加载 / 解密失败

```
错误：密钥文件损坏，验证失败
错误：密钥未加载，无法读取会话
```

**解决**：
- 检查 `~/.loop-agent/.keyfile` 是否存在且未损坏
- 若误删/损坏，可通过备份的 `exportKey()` 导出的 base64 调用 `keychain.importKey()` 恢复
- 若无法恢复，可删除损坏的会话文件（`/session delete <id>`）后重新开始

### 调试日志未生成

**解决**：确认已通过 `DEBUG=true` 环境变量或 `/config set agent.debug true` 开启调试模式，日志输出到 `~/.loop-agent/logs/debug-YYYY-MM-DD.log`。开启后 CLI 启动 banner 会显示调试日志目录提示。

### 配置来源追踪

当配置未按预期生效时，可通过 `/config list` 查看每个字段的实际来源（cli / workspace / global / env / default），快速定位是哪一层覆盖了配置。

load <id>` 恢复上下文继续对话。\n\n### 存储结构\n\n```\n~/.loop-agent/\n├── .keyfile                      # 🔑 主密钥文件（首次自动生成，权限 0600）\n├── config.json                   # 全局配置（可选）\n├── logs/\n│   └── debug-YYYY-MM-DD.log      # 📝 调试日志（见下节）\n└── sessions/\n    └── {workspaceId}/            # 按工作空间路径隔离（路径 SHA-256 前 16 位）\n        ├── meta.json             # 工作空间元信息\n        ├── sessions.json         # 会话索引（仅元信息，不含消息内容）\n        └── sess_YYYYMMDD_HHMMSS.enc   # 加密的会话数据文件\n```\n\n### 加密机制\n\n- **主密钥**：首次使用时自动生成 256-bit 随机密钥，保存于 `~/.loop-agent/.keyfile`（`0600` 权限），无需用户输入密码\n- **数据加密**：会话消息通过 **PBKDF2（100,000 次迭代）派生** + **AES-256-GCM** 加密，附带认证标签保证完整性\n- **密钥校验**：密钥文件包含校验 token，读取时会验证密钥完整性，损坏则报错\n- **索引明文**：`sessions.json` 仅存储会话元信息（ID、标题、消息数、时间），消息内容全部加密\n\n### 自动保存 / 恢复\n\n- **自动保存**：`run()` 结束后，若 `session.autoSave=true` 且已设置 SessionStore，自动创建新会话或更新当前会话\n- **自动恢复**：`session.autoRestore=true` 时，CLI 启动会自动加载最近一次会话，无缝续接上次对话\n- **手动控制**：可通过 `/session` 子命令随时 list / load / save / new / delete\n\n### 密钥管理（Keychain）\n\n`src/session/keychain.ts` 提供密钥生命周期管理：\n\n| 方法 | 说明 |\n|---|---|\n| `keychain.ensureUnlocked()` | 确保密钥已加载（首次自动生成密钥文件） |\n| `keychain.exportKey()` | 导出主密钥（base64，用于备份） |\n| `keychain.importKey(base64)` | 从备份导入主密钥（用于迁移/恢复） |\n| `keychain.reset()` | 删除密钥文件（⚠️ 会导致所有加密会话无法解密） |\n\n> ⚠️ **重要**：`.keyfile` 是解密会话的唯一凭证。丢失该文件将导致所有加密会话无法恢复，建议定期 `exportKey()` 备份。\n\n---\n\n## 🧠 记忆管理\n\n基于 OpenClaw 风格的三层记忆架构（Tier Model），核心思想：**文件是真相源，索引只做加速；写读路径分离；晋升有闸门。** 记忆系统与会话持久化（Task-11）互补：会话持久化解决\"恢复上次对话\"，记忆管理解决\"跨会话知识积累\"。\n\n### 三层架构\n\n| 层级 | 存储形态 | 生命周期 | 自动进
