# 视觉设计原则（Design Principle）· 通用法则

## 文件层级声明

- 本文件是设计的**通用法则**——所有项目必读，所有硬门禁（密度、容器填充率、视觉锚点、色彩面积分配等）默认生效；未命中领域分支时即为本项目的最终边界。
- `designs/` 是本文件的**领域特化分支**——每一份 `design-principle.<id>.md` 是某一种成熟视觉文化（academic / consulting / redgold）的"风格知识包"。每份分支文件内容**分两层**：
  - **结构层**：版式分类、字号阶梯比例、色彩面积分配比例、装饰白名单**结构**、自检与返工触发条件、留白/密度上下限框架——这是该视觉文化的工程化骨架，**对内容相似的项目仍具普遍指导价值**；
  - **常量值层**：默认色板 hex、默认字体家族名、默认装饰具体项、默认场景标签语义引用——这是该视觉文化在"标准场景"下的填空答案，可被用户需求改写。
- Step 3 进入设计阶段后，先用 [create-from-scratch.md](create-from-scratch.md) Step3 §风格路由 做关键词路由，结果分**三态**：
  - **matched（完全命中）**：命中某风格包硬关键词 ≥ 1 → 分支**结构层 + 常量值层**与本文件**共同构成本项目设计宪法**，两份均需完整加载、整体执行；
  - **soft_match（软降级）**：仅命中软关键词 → 分支**结构层继续生效**（视为本项目结构宪法），**常量值层失效**，由用户需求 / `STORY.md` 推导改写填空；
  - **no_match（无命中）**：无任何命中 → 仅基于本文件与 `STORY.md` 原创设计稿（通用路径）。
- 通用法则与命中分支冲突时的解决规则（优先级链：**用户显式指令 ≻ 命中分支结构层 ≻ 通用法则**）：
  - **① 用户显式指令优先**——用户以具体值/具体名称给出的工程化指令（hex 码、命名色、字体家族、页数、比例、装饰增减、量化密度偏好）覆盖分支常量值层与通用法则的对应缺省值；覆盖**仅作用于被显式指定的常量值**，分支的结构层继续生效。
  - **② 同向冲突（同维度紧/松对比）以更严格者为准**（例：通用强调色 ≤ 10% vs 分支 ≤ 5% → 取 5%）。
  - **③ 正交冲突（一边上限、一边下限）以领域分支为准**。
  - **④ 兜底覆盖**：本文件颜色与字体的"参考表"是无分支命中时的兜底；完全命中分支若给出具体色彩 hex / 字号阶梯按命中分支执行；软降级时分支常量值层失效，回退到本文件参考表 + 用户需求改写。
  - **关键厘清**：命中分支**结构层是本项目设计宪法的一部分**，应像执行本文件那样完整执行；**常量值层在完全命中态下整体执行，在软降级态下由用户需求 / `STORY.md` 改写填空**——"为本项目改造常量值"是允许且必要的，但结构性约束（比例、阶梯、版式分类、装饰白名单结构、自检条件）禁止改造。

## 设计总则（生成时不要复述，只检查是否落实）

- **一致性优先**：母版骨架、配色、字体、配图风格全程统一，禁止"个别页特殊处理"。
- **密度优先**：极简风的前提是单元素信息密度足够大；空 ≠ 极简。任何一页内容稀薄都是失败。
- **配图骨架化**：配图必须承担叙事功能（占有效面积，与正文耦合），禁止 200×70 的"装饰小贴片"塞在标题栏。
- **大胆对比**：好设计的核心是尺度跳跃和刻意不对称——每页至少一个"视觉锚点"（超大字号/超大图/超大色块），其余元素围绕锚点组织。禁止所有元素趋近中间大小。
- **视觉节奏**：10 页以上的 PPT 必须有 2–3 页"视觉高潮页"（hero 页），其余为"支撑页"（supporting 页）。每页视觉重量必须不同，禁止"流水线感"。

## 1. 画布与全局母版

> 画布尺寸固定 16:9、1280×720（rules: `canvas`）。同类内容页之间的标题位置、页码位置必须保持稳定，禁止逐页随机发挥。封面 / 章节过渡 / 结束页允许有自定义版式。

### 默认母版（A/B/C 三区）

| 母版区 | 垂直位置 | 高度 | 内容规则 |
| :--- | :--- | :--- | :--- |
| **A · 标题块** | 0–120px | 120px | 主标题 32–40px bold |
| **B · 内容区** | 120–660px | 540px 可用 | 一切正文、图表、配图、卡片；禁止挤占 A/C 区 |
| **C · 页脚条** | 660–720px | 60px | 左侧项目名（可选）+ 右侧页码 `NN / TOTAL`，统一 12–16px 弱化灰字 |
| 页面 padding | 上下 20px、左右 60–80px | — | A/B/C 在 padding 之内排布 |

- 内容禁止溢出画布（rules: `layout` 溢出即 `LAYOUT_OVERFLOW` 错误）；
- 页脚条不是装饰：标题块与页脚之外的区域才算内容区面积（色彩/密度计算都以 B 区为基准）；
- 项目根目录 `DESIGN.md` 必须把上面三区**写成具体 px 值**，并在每个页面文件中以注释或固定结构复用；
- 封面 / 章节过渡 / 结束页可省略 C 区或采用自定义版式；其余内容页之间应严格保持母版一致。

## 2. 颜色系统（实例化为具体 hex）

全篇主题色 ≤ 4 个 hex（rules: `color.max_theme_colors`）。依据 PPT 的受众和用户的实际需求，从 4 类角色中选取并实例化，如下是一些常用的参考色系：

| 主题领域 | 背景 | 主色 | 辅色 | 文本主色 |
| :--- | :--- | :--- | :--- | :--- |
| 科技 / 金融 | `#FFFFFF` 或 `#0F172A` | `#3B82F6` | `#06B6D4` | `#1A1A1A` / `#F7F4EC` |
| 人文 / 哲学 / 文化 | `#F7F4EC`（宣纸米） | `#1A1A1A`（松烟墨） | `#A8351A`（朱砂） | `#3F4A55`（青墨） |
| 教育 / 消费 | `#FAF7F2` | `#F97316` | `#EC4899` | `#1A1A1A` |
| 政务 / 党建 | `#FFFFFF` | `#C8102E` | `#D4AF37` | `#1A1A1A` |

### 2.1 色彩面积分配

在 `DESIGN.md` 中必须声明每页的色彩面积分配（rules: `color.primary_ratio` / `color.secondary_ratio` / `color.accent_ratio`）：

| 色彩角色 | 面积占比上限（B 区） | 说明 |
| :--- | :--- | :--- |
| **主色** | ≤ 60% | 背景、大色块、标题栏底色 |
| **辅色** | ≤ 30% | 卡片背景、图表第二系列、分隔线 |
| **强调色** | ≤ 10% | 只出现在需要视觉焦点的元素上——巨型数字、CTA 按钮、核心数据标注 |
| **中性色** | 剩余 | 文字、页脚、边框，不计入彩色面积 |

**色彩节奏规则**：
- **Hero 页（视觉高潮页）**：强调色占比可放宽到 20%（rules: `color.accent_ratio_hero`），但仍是硬上限；
- **Supporting 页（信息承载页）**：强调色 ≤ 5%、辅色 ≤ 20%（视觉上收敛）；
- **禁止全篇每页色彩比例雷同**：至少 2 页的色彩比例应与其他页显著不同；
- 图表系列色从辅色 + 强调色中取，禁止额外引入第 5 色。

### 2.2 渐变与半透明

引擎支持（`Box` / `Slide` 的 `background` 与 `opacity`）：
- `linear-gradient(135deg, #3B82F6 0%, #0F172A 100%)`：卡片头部、标题栏渐变（`background` 键，语法 `linear-gradient(Ndeg, #hex, #hex)`）；
- `opacity` 0–1：大面积浅色半透明覆盖、背景蒙版、底层元素弱化（0.15–0.3）；
- 背景图上叠加深色蒙版（`rgba(0,0,0,0.4)`），让白色文字清晰可读；
- 卡片容器使用 `boxShadow: '0 4px 20px rgba(0,0,0,0.08)'` 创造浮起感。

**项目 `DESIGN.md` 必须声明**：本项目的渐变方案（角度、起止色、使用位置）和半透明策略（哪些元素叠在什么之上、opacity 值）。

### 通用禁忌

- 同一页面出现 ≥ 2 套主色板；
- 高饱和撞色铺满 ≥ 1/3 页面；
- 全篇每页颜色分配比例雷同（差异 < 10%）。

## 3. 字体系统（按层级给出具体 px + 字体个性）

项目 `DESIGN.md` 必须列出每个层级的字号、字重、行高与字距，禁止只写"标题大字、正文小字"。

### 3.1 字号阶梯

字号不是任意值，必须落在 4 级阶梯上（rules: `typography.size_ladder`）：

| 层级 | 字号范围（px） | 用途 | 权限 |
| :--- | :--- | :--- | :--- |
| Hero 标题 | 56–72 | 仅 cover / section / ending 页 | 每页 ≤ 1 个 |
| 标题 | 32–40 | 页内主标题（A 区标题块） | 每页 ≤ 1 个 |
| 正文 | 18–24 | 段落、列表、说明 | 主体 |
| 辅助 | 12–16 | 图注、页脚、角标 | 弱化处理（灰字） |

**规则**：
- 全篇字体家族 ≤ 2 个（rules: `typography.max_font_families`）；
- 行高 ≥ 1.3 倍字号（rules: `typography.line_height_multiplier`）；
- 禁止出现 25px、31px 这类阶梯外的字号（这是"AI 味"重灾区）。

### 3.2 字体个性策略

如下是一些参考推荐，请结合用户的主题和页面内容，分配合适字体：

| 气质方向 | 推荐中文字体 | 推荐西文搭配 | 适合主题 |
| :--- | :--- | :--- | :--- |
| 商务现代 | 思源黑体 / 苹方-简 | Helvetica Neue / Inter | 科技、金融、SaaS |
| 人文质感 | 思源宋体 / 方正书宋 | Georgia / Merriweather | 文化、学术、哲学 |
| 活力亲和 | 阿里普惠体 / 站酷快乐体 | Poppins / Nunito | 教育、消费、生活 |
| 政务庄重 | 方正小标宋 / 华文中宋 | Times New Roman | 政务、党建、法律 |
| 科技未来 | 思源黑体 + letterSpacing 加大 | Space Grotesk / JetBrains Mono | AI、芯片、航天 |

**关键规则**：
- 标题与正文允许不同字体个性：标题可用更有表现力的字体，正文用易读字体；
- 巨型数据 / 锚点数字：必须用与正文不同的字重或字体（如正文 regular 18px、数据 bold 56px）；
- 禁止所有页面只用"系统默认无衬线"；项目 `DESIGN.md` 必须写出具体字体名。

## 4. 信息密度门禁

| 规则 | 阈值 | 依据（rules） |
| :--- | :--- | :--- |
| 内容页正文字数下限 | ≥ 180 字 | `typography.min_body_chars` |
| 内容页留白上限 | ≤ 35% | `layout.max_whitespace_ratio` |
| 卡片填充率下限 | ≥ 85% | `layout.card_fill_min_ratio` |
| Hero 页配额区间 | 全篇 20%–30% | `layout.hero_page_ratio` |
| 每页 1 个论点 | 人工评审 | 不可机器检测 |

**留白计算**：B 区中"无任何元素（含文字/图形/图片）覆盖"的面积占比。
**填充率计算**：卡片内内容（文字块 + 图表）面积 / 卡片面积。
**Hero 配额**：10 页以上的 PPT 必须有 2–3 页视觉高潮页（hero），过多节奏失效、过少平淡。

如项目走极简 / 留白风格，需在项目 `DESIGN.md` 显式声明"留白型"并覆盖本节默认值。

### 4.1 容器填充率

- **填充率 ≥ 85%**：卡片/容器内的实际内容垂直占用应 ≥ 容器高度的 85%。卡片越高，要求字数越多——高 ≥ 380px 的卡片，正文应 ≥ 100 字；高 ≥ 480px 的卡片，正文应 ≥ 130 字；
- **底栏锚定**：卡片末尾的引文条 / 标签条 / 行动按钮等"尾部元素"，必须用父容器 `justifyContent: 'space-between'`（或行内 `marginTop` 显式撑开）钉到容器底部；禁止"自然紧跟正文"导致它悬浮在卡片中段；
- **横向兄弟卡对齐**：同一行的多张卡片，其内部"标题块 / 正文块 / 引文条"三段在 y 轴上必须等高对齐。任意两张兄弟卡的尾部元素 y 坐标差 > 16px → 返工。

### 4.2 留白策略

- **焦点留白**：每个视觉锚点元素（巨型数字、核心图片、大标题）周围必须留出 ≥ 40px 的呼吸空间；
- **Hero 页允许更多留白**：视觉高潮页的留白可以达 40–50%，但留白必须围绕核心元素（不是均匀散布的空白）；
- **禁止"均匀稀薄"**：一页的留白不是围绕焦点元素、而是每两个元素之间都有差不多大小的空白 → 需要补内容或合并页面。

## 5. 视觉锚点

每页必须至少 1 个视觉锚点（rules: `anchor.per_page_required`）——第一眼抓住视线的元素：

| 锚点类型 | 标准 | 依据（rules） |
| :--- | :--- | :--- |
| 大文字 | 字号 ≥ 44px | `typography.anchor_min_size` |
| 主视觉 | 图片/图表占 B 区 ≥ 40% | `anchor.min_image_area_ratio` |

**锚点法则**：
- 锚点位于 B 区左上 1/3 或右 1/3 区域（利用视觉 F 型扫视路径），避免正中放置；
- 无锚点页是失败页：如无 → 必须补充巨型数字 / 大图 / 大色块。

## 6. 配图系统

项目 `DESIGN.md` 必须把每张配图归类到下列三级之一，并标明出现位置与最小尺寸：

| 级别 | 定义 | 面积/尺寸 | 依据（rules） |
| :--- | :--- | :--- | :--- |
| **L1 主视觉** | 支撑全页论点的核心图 | B 区 ≥ 40% | `image.l1_area` |
| **L2 支撑图** | 强化某一段落 | ≥ 280×180px | `image.l2_min_size` |
| **L3 角标** | 品牌/装饰性小图标 | ≤ 64×64px | `image.l3_max_size` |

**配图法则**：
- L3 角标全篇位置一致（同页同角），不做随机装饰；严禁把 200×70 等小尺寸图片塞进标题块右侧当装饰；
- 高置信度场景（财务/学术/法律等）必须使用素材原始图表，禁止 AI 生图替代；
- 图片缺失或路径非法是错误，不是警告；素材中没有的图片不要编造路径；
- 全篇 L1 主视觉风格统一（同为摄影 / 同为插画 / 同为 3D，特殊主题需 `DESIGN.md` 显式声明）。

**配图获取规则**：
1. 所有 L1 主视觉、占 B 内容区 ≥ 30% 的大面积背景 / 半屏图 / 一栏铺底图、具象场景（城市、办公室、会议、工厂、实验室、校园、产品使用）、人物 / 群像 / 空间、风格化画面（摄影、插画、3D、国风、水墨、卡通、科技氛围）必须优先使用生图能力，禁止直接用 SVG 代替；
2. 生图产物必须落到 `resources/images/` 后再引用（`Image` 组件按 `resources/images` → `resources` → 当前工作目录依次查找）；不得使用在线 URL 或占位符；
3. **允许 SVG**：流程图、时间轴、矩阵、漏斗、架构图、关系网络、图表底图、巨型数字、趋势箭头、进度环、L3 角标、印章、页脚纹样、背景网格、抽象几何概念页等结构化 / 低语义元素可以用 `SVG` 组件；
4. **SVG 兜底条件**：必须生图的 L1/L2 只有在生图最多 2 次重试仍不符合主题、构图、清晰度或风格时，才允许改用 SVG 兜底。

**生图规则**：
1. 按页面映射表清点所有需要生图的 L1/L2，为每张写出 prompt：主体 + 场景 + 构图 + 风格 + 色彩 + 禁忌；
2. 同一 deck 的生图必须使用同一视觉类型和风格词，禁止摄影 / 插画 / 3D 混用，除非 `DESIGN.md` 显式声明刻意混搭；
3. 生图产物必须保存到 `resources/images/`；文件名使用英文短名，禁止中文、空格、特殊字符；
4. 生图返回顺序常与 prompt 顺序错位：必须逐张核对真实内容、构图、清晰度和风格后再重命名映射，禁止按时间戳盲映射；
5. 对生成的图片进行视觉检查，确认清晰、无水印且符合上下文后方可使用。

## 7. 版式骨架库

定义可复用的版式骨架（相邻页禁用相同骨架）：

| 骨架 | 描述 | 归类 |
| :--- | :--- | :--- |
| `hero-center` | 居中大标题 + 少量正文 | 对称 |
| `hero-split` | 左文右图（或反），对角分割 | 非对称 |
| `bullet-flow` | 标题下左侧编号列表 | 非对称 |
| `chart-led` | 图表为主，右侧文字说明 | 非对称 |
| `card-row` | N 卡片均分横排 | 对称（全篇 ≤ 2 页，rules: `layout.card_row_max_pages`） |
| `two-column` | 左右两栏对比 | 对称 |
| `section-banner` | 全幅色块 + 章节号 | 对称（仅 section 页） |
| `quote-hero` | 大引言 + 弱化背景 | 非对称 |

**选择规则**：相邻两页禁用相同骨架；全篇对称骨架占比 ≤ 60%，等价于非对称 ≥ 40%（rules: `layout.asymmetric_min_ratio`）。

## 8. 页面映射表（项目 `DESIGN.md` 必填）

为每一页给出：序号、文件、类型、**角色（hero/supporting/transition）**、节奏（peak/valley/transition）、版式、主视觉文件、密度估算（字数、图数、留白比例）、**色彩分配**、关键约束。这张表是 `STORY.md` 与 `pages/*.py` 之间的**契约**，逐页生成时严格对照：

