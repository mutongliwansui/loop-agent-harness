# 叙事结构原则（Story Principle）

> 本文件定义一套 PPT 的**叙事骨架**：怎么把内容组织成有节奏、有重点、可被听众跟随的故事。
> 所有量化参数以 `rules.json` 为准，本文标注的数值仅作速查，冲突时以 `rules.json` 为准。

## 1. 叙事金字塔：先对齐，再讲

任何一套 PPT 动手之前，先回答 5 个问题并写入 `STORY.md`：

| 问题 | 落点 |
|---|---|
| 听众是谁？他们关心什么？ | 决定语气、专业深度、信息密度 |
| 听完要做什么？ | 唯一目标：决策 / 认知 / 行动 |
| 时长与页数预算？ | 1 分钟 ≈ 1 页的粗估，可上下浮动 20% |
| 场合与调性？ | 汇报 / 路演 / 培训 / 政务，决定风格包路由 |
| 内容边界？ | 什么必须讲、什么必须不讲 |

**没有 STORY.md 就动手写页面，是最高频的失败原因。**

## 2. 页面角色模型

每一页必须声明一个角色（`role`），角色决定它在叙事中的功能：

| 角色 | 功能 | 配额 |
|---|---|---|
| `hero`（高峰页） | 承载核心论点、关键数据、视觉记忆点 | 占全篇 20%-30%（rules: `layout.hero_page_ratio`） |
| `supporting`（支撑页） | 展开论证、提供证据、解释细节 | 剩余主体 |
| `transition`（过渡页） | 章节切换、方向预告、节奏喘息 | 每 3-5 个 supporting 后至少 1 个 |

## 3. 节奏曲线：peak / valley / transition

叙事不是匀速的。每一页还要声明一个节奏（`rhythm`）：

| 节奏 | 特征 | 用途 |
|---|---|---|
| `peak`（高峰） | 大字号、大视觉、少文字、强对比 | 封面、核心结论、结尾升华 |
| `valley`（低谷） | 高信息密度、多图表、多数据 | 论证、展开、细节页 |
| `transition`（过渡） | 极简、留白大、单一焦点 | 章节过渡、预告 |

**节奏法则**：
- 高峰页之间必须间隔至少 2 页，连续 2 个 peak 等于没有 peak
- 全篇高峰页占 20%-30%（同 `layout.hero_page_ratio`），其余以 valley 为主的 supporting 页填充
- 结尾页必须是 peak，且与倒数第 2 页形成"谷→峰"的收束

## 4. 页面类型与标准顺序

一套标准 deck 的页面类型（`page_type`）与建议顺序：

```
cover（封面·peak）
  → toc（目录·transition，≤8 条，rules: `toc.max_entries`）
    → [section（章节页·transition）
        → content × n（支撑页，peak/valley 混合）] × m
      → ending（结束页·peak，行动号召）
```

- 章节数（m）≤ 5：章节过多说明叙事没收敛
- 目录页可省略（≤6 页的 deck 不需要目录）
- 结束页必须有明确行动号召，不写"谢谢观看"

## 5. 信息预算

- 常规内容页正文 ≥ 180 字（rules: `typography.min_body_chars`），低于即信息空洞
- 每页只讲一个论点：一页一论，页内所有素材服务同一论点
- Hero 页克制字数：标题即论点，正文不超过 1 个短段落

## 6. 版式预算（全篇视角）

- 非对称版式页占比 ≥ 40%（rules: `layout.asymmetric_min_ratio`），防止千篇一律的居中
- "N 卡片横排"这一种版式全篇最多 2 页（rules: `layout.card_row_max_pages`），它是流水线感的最大来源
- 相邻两页禁止使用同一种版式骨架（可被 T3.1 lint 检测）
